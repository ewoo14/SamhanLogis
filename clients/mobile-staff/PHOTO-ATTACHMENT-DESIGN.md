> Designer 산출물 — 2026-05-11

## 0. 설계 원칙

| 원칙 | 상세 |
|---|---|
| UUID 미노출 | 모든 화면에서 UUID 표시 금지. 슬립번호 / 거래처명 / 품목명만 노출 |
| 권한 차단 fallback | 카메라 또는 갤러리 권한 거부 시 해당 기능만 비활성 (GPS 와 달리 앱 전체 차단 X) |
| 자동 압축 의무 | 업로드 전 클라이언트 측 1MB 이내 압축. 원본 미전송 |
| 진행률 표시 | 업로드 중 진행률 bar 표시. 완료 전 화면 이탈 차단 |
| 다중 첨부 | 시나리오별 최대 첨부 수 상이 (검수 5장 / 배송 3장 / 영업 5장) |
| 썸네일 grid | 3열 grid, 각 셀 정사각형 (aspectRatio 1:1), 우상단 X 삭제 버튼 |
| Pretendard | 본문 14px Regular / 헤더 18px SemiBold / 캡션 12px Regular |

### 1.3 썸네일 Grid + 삭제 버튼

첨부된 사진을 3열 grid로 표시. 각 셀 간격 4px.

```
┌─ 전체 너비 (360~390px) ───────────────┐
│                                        │
│ ┌──────┐ ┌──────┐ ┌──────┐           │
│ │      │ │      │ │ [+]  │           │ ← 마지막 셀 = 추가 버튼 (최대 미달 시)
│ │ 사진1│ │ 사진2│ │      │           │
│ │  [×] │ │  [×] │ │      │           │ ← [×] 우상단 24×24 원형 버튼
│ └──────┘ └──────┘ └──────┘           │
│                                        │
│  ※ 최대 N장 / 현재 M장 첨부됨  (12px) │ ← 시나리오별 N 상이
└────────────────────────────────────────┘
```

**셀 spec**

| 항목 | 값 |
|---|---|
| 셀 크기 | `(screenWidth - 32 - 8) / 3` px 정사각형 (padding 16 × 2 + gap 4 × 2) |
| 셀 borderRadius | `radii.md` = 8 |
| 이미지 resizeMode | `cover` |
| 삭제 버튼 위치 | 우상단 오프셋 -8 -8 |
| 삭제 버튼 크기 | 24×24 원형 |
| 삭제 버튼 배경 | `colors.state.danger` = `#EF4444` |
| 삭제 버튼 아이콘 | 흰색 × 12px |
| 추가 버튼 배경 | `colors.surface.subtle` = `#F4F6F8` |
| 추가 버튼 border | `1px dashed` `colors.line.default` |
| 추가 버튼 아이콘 | `+` 20px `colors.ink.tertiary` |
| 최대 달성 시 추가 버튼 | 미표시 (grid 마지막 셀 없음) |

### 1.4 업로드 진행률 (Loading)

사진 선택 확정 후 → 압축 → 업로드 순서. 각 단계별 UI.

```
┌─ 사진 업로드 진행 카드 ───────────────┐
│                                        │
│  ■■■■■■■■■■□□□□□□□□□□  48%           │ ← 진행률 bar 8px 높이
│                                        │
│  사진 2 / 3 업로드 중...  (14px)       │ ← 현재 장수 / 전체 장수
│  자동 압축 완료 → 서버 전송 중         │ ← 단계 안내 (12px secondary)
│                                        │
└────────────────────────────────────────┘
```

**진행 단계**

| 단계 | 상태 표시 |
|---|---|
| 압축 중 | "사진 M장 압축 중..." + 진행률 bar spinner (indeterminate) |
| 압축 완료 | 진행률 bar 즉시 25%로 점프 |
| 업로드 중 (각 파일) | "사진 N / M 업로드 중..." + 진행률 bar 25% → 90% 선형 증가 |
| 전체 완료 | 진행률 bar 100% (green) 0.5초 → 카드 사라짐 + 성공 토스트 |
| 업로드 실패 | 진행률 bar 숨김 + 오류 배너 (state.danger) + [재시도] 버튼 |

**진행률 bar 토큰**

| 상태 | fill 색 |
|---|---|
| 진행 중 | `colors.action.brand` = `#1E40AF` |
| 완료 | `colors.state.success` = `#10B981` |
| 실패 | `colors.state.danger` = `#EF4444` |

**업로드 중 화면 이탈 차단**

업로드 진행 중 뒤로 가기(Android HW) / 탭 전환 시도 시 Alert 노출:

```
제목: 업로드 진행 중
내용: 사진 업로드가 진행 중입니다. 지금 나가면 업로드가 취소됩니다.
버튼: [계속 업로드] (dismiss) | [나가기] (취소 후 이탈)
```

### 1.5 자동 압축 안내 (상세)

| 항목 | 규격 |
|---|---|
| 압축 목표 | 1MB 이내 (1,048,576 bytes) |
| 압축 포맷 | JPEG (quality 0.7 — expo-image-manipulator) |
| 단계 | 1차: quality 0.7 → 2차 (미달 시): quality 0.4 + 해상도 1280px 이내 |
| 원본 보존 | 로컬 미보존. 압축 결과만 메모리 → 업로드 → 즉시 해제 |
| 안내 위치 | Bottom Sheet 하단 배너 + 업로드 진행 카드 sub-text |
| 사용자 표시 원본 크기 | 미표시 (압축 결과 크기도 미표시 — 불필요한 정보 최소화) |

## 2. 시나리오 1 — 검수 사진 첨부 (DriverSignatureScreen 확장)

### 2.1 시나리오 개요

배송기사가 정차 도착 후 검수 증빙 사진 (포장 상태, 수량, 파손 여부) 을 촬영하여 서명과 함께 등록.

| 항목 | 값 |
|---|---|
| 접근 화면 | `tab='signature'` → DriverSignatureScreen |
| 최대 첨부 | 5장 |
| 필수 여부 | 선택 (사진 없이도 서명 등록 가능) |
| 업로드 endpoint | POST `/driver-app/arologis/dispatches/{id}/vehicles/{seq}/stops/{stopSeq}/photos` |
| 연동 흐름 | 서명 등록(`/sign`) 과 별도 call. 사진 먼저 업로드 → photoRef[] 반환 → 서명 payload 에 포함 |

### 2.2 검수 사진 첨부 화면 wireframe

```
┌─ 375px viewport ──────────────────────┐
│ [SafeArea 상단]                        │
│                                        │
│  [←] 정차 서명         (18px SB)       │ ← 정차명 (parsedPartnerName)
│      한국전력 강남지사                 │   UUID 미노출
│                                        │
│ ─── 정차 정보 카드 ───────────────────│
│ ┌───────────────────────────────────┐ │
```

### 2.3 검수 시나리오 UX flow

| step | 사용자 동작 | 시스템 동작 |
|---|---|---|
| 1 | 정차 dashboard 에서 [검수 서명] tap | DriverSignatureScreen 진입 |
| 2 | [사진 추가] tap | Bottom Sheet 노출 (§1.1) |
| 3 | [카메라로 촬영] 또는 [갤러리에서 선택] 선택 | expo-camera / expo-image-picker 호출 |
| 4 | 사진 촬영 또는 선택 완료 | 자동 압축 (§1.5) → 썸네일 grid 에 즉시 표시 |
| 5 | (필요 시) 사진 × 탭 | 해당 썸네일 제거 |
| 6 | (필요 시) 추가 사진 (최대 5장) | step 2~4 반복 |
| 7 | 인수자명 입력 + 서명 | 기존 서명 UX (Signature Slice C 동일) |
| 8 | [서명 + 등록] tap | 1) 사진 업로드 진행률 표시 2) 완료 후 서명 POST |
| 9 | (자동) | 완료 토스트 "검수 사진 N장 + 서명 등록 완료" |

### 2.4 검수 시나리오 실패 케이스

| 실패 | UX |
|---|---|
| 사진 업로드 실패 | 오류 배너 + [재시도] + 서명 입력 내용 보존 |
| 카메라 권한 거부 | Bottom Sheet 내 권한 안내 카드 (§1.2) |
| 갤러리 권한 거부 | 동일 |
| 압축 후 1MB 초과 (극히 드문 경우) | 토스트 "이 사진은 첨부할 수 없습니다 (용량 초과)" |
| 5장 초과 시도 | [사진 추가] 버튼 미표시 (방어) |

## 3. 시나리오 2 — 배송 완료 사진 (배송 증빙)

### 3.1 시나리오 개요

배송기사가 배송 완료 후 수령 확인 사진 (배송 위치 전경) 을 등록.
GPS 위치와 동시에 타임스탬프 기록.

| 항목 | 값 |
|---|---|
| 접근 화면 | DriverDashboardScreen → 정차 카드 [배송 완료] 버튼 |
| 최대 첨부 | 3장 |
| 필수 여부 | 선택 |
| GPS 동반 | 사진 첨부 시 현재 GPS 좌표 자동 태깅 (메타데이터 — UI 미표시) |
| 업로드 endpoint | POST `/driver-app/arologis/dispatches/{id}/vehicles/{seq}/stops/{stopSeq}/delivery-photos` |

### 3.3 배송 완료 사진 UX flow

| step | 사용자 동작 | 시스템 동작 |
|---|---|---|
| 1 | Dashboard 정차 카드 [배송 완료] tap | 배송 완료 처리 화면 진입 + GPS 1회 취득 시작 |
| 2 | [추가] 셀 tap | Bottom Sheet 노출 |
| 3 | 카메라 또는 갤러리 선택 | expo-camera / expo-image-picker |
| 4 | 사진 확정 | 자동 압축 → 썸네일 추가 + GPS 좌표 메모리 태깅 |
| 5 | (선택) 메모 입력 | 100자 이내 자유 입력 |

### 3.4 배송 GPS 태깅 안내

GPS 태깅은 사진 메타데이터에만 기록. 사용자 화면 미노출.
GPS 취득 실패 시 (정확도 불량 / 타임아웃) 태깅 없이 사진만 등록.
안내: "GPS 위치 태깅 실패 — 사진은 정상 등록됩니다." toast 1회.

## 4. 시나리오 3 — 영업 현장 사진 첨부 (영업직원 estimate mode)

### 4.1 시나리오 개요

영업직원이 현장 방문 중 설치 환경 / 제품 상태 사진을 견적서에 첨부.
estimate mode (WebView) 가 아닌 RN native 화면으로 구현 (WebView 외부).

| 항목 | 값 |
|---|---|
| 접근 mode | estimate mode 내 [사진 첨부] 네이티브 브리지 또는 별도 native tab |
| 최대 첨부 | 5장 |
| 필수 여부 | 선택 |
| 사진 참조 | 업로드 URL ref 를 WebView 로 postMessage (slipNo + photoRefs[]) |
| 업로드 endpoint | POST `/api/v1/slips/{slipNo}/attachments` (slip-service) |

## 9. 검증 체크리스트 (QA 인계)

### 9.1 권한 검증

- [ ] 카메라 권한 최초 요청 → 허용 → 카메라 실행 정상
- [ ] 카메라 권한 거부 → Bottom Sheet 내 비활성 + 권한 안내 카드 표시
- [ ] [설정 열기] tap → OS 설정 이동 정상 (iOS / Android 각각)
- [ ] 권한 허용 후 앱 복귀 → 버튼 자동 활성
- [ ] 갤러리 권한 동일 시나리오 반복

### 9.2 압축 검증

- [ ] 5MB 원본 촬영 → 업로드 payload 1MB 이내 (devtools 네트워크 확인)
- [ ] 압축 완료 → 썸네일 즉시 표시 (200ms 이내)
- [ ] 압축 실패 (메모리 부족 극단) → 토스트 오류 안내

### 9.3 썸네일 Grid 검증

- [ ] 0장 → [추가] 버튼 1개 + 빈 셀
- [ ] 1~N-1장 → 썸네일 + [추가] 버튼
- [ ] N장 (최대) → 추가 버튼 미표시
- [ ] [×] 삭제 → 해당 썸네일 즉시 제거 + [추가] 버튼 재노출
- [ ] 3장 이상 시 행 wrap 정상 (3열 grid)

### 9.4 업로드 진행률 검증

- [ ] 진행률 bar 표시 → 100% → 성공 토스트
- [ ] 업로드 중 뒤로가기 → Alert "나가면 취소" 표시
- [ ] [나가기] 선택 → 업로드 cancel + 화면 이탈
- [ ] [계속 업로드] 선택 → 업로드 재개
- [ ] 업로드 실패 (네트워크 끊김) → 오류 배너 + [재시도]

### 9.5 시나리오별 검증

- [ ] Scenario 1 검수: 사진 없이 서명만 등록 가능 확인
- [ ] Scenario 1 검수: 사진 5장 + 서명 동시 등록 정상
- [ ] Scenario 2 배송: 사진 없이 [배송 완료 등록] 활성 확인
