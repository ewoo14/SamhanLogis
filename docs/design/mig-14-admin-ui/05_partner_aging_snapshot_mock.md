# 거래처 잔액 스냅샷 목업

대상 화면: `PartnerAgingSnapshotPage`  
경로: `/accounting/admin/aging-snapshot`

---

├────────────────────────────────────────────────────────────────────────────────────┤
│ [거래처명 ________] [정렬 ▼ 순미수금 높은순] [검색]                    [초기화]     │

스냅샷은 읽기 중심 화면이다. 갱신 버튼은 POST refresh를 호출하고 성공 시 최종 갱신 시각과 표를 다시 조회한다.

---

## 2. 필터와 정렬

| 항목 | 입력 방식 | 동작 |
|---|---|---|
| 거래처명 | 텍스트 | `partnerName` 부분 일치 |
| 정렬 | 선택 | 순미수금 높은순 / 순미지급금 높은순 / 거래처명순 |

갱신 중에는 버튼 라벨을 `갱신 중`으로 바꾸고 중복 클릭을 막는다. 표 조회는 계속 가능하되 갱신 완료 후 최신 데이터로 교체한다.

---

## 3. 컬럼

| 컬럼 | 데이터 | 표시 규칙 |
|---|---|---|
| 거래처 | `partnerName` | 링크 없음, 업무 명칭 |
| 총미수금 | `totalReceivable` | 우정렬 |
| 총미지급금 | `totalPayable` | 우정렬 |
| 총입금액 | `totalReceipt` | 우정렬, CashReceiptKind 집계 금액 |
| 총지출액 | `totalDisbursement` | 우정렬, CashKind 집계 금액 |
| 순미수금 | `netReceivable` | 양수 강조 |
| 순미지급금 | `netPayable` | 양수 경고 |

`netCash`는 기본 표에서는 숨기고, 행 펼침 또는 상세 tooltip에서 `순현금`으로 표시한다. 본 화면은 집계표라 kind/status chip을 직접 표시하지 않으며, CashKind(`EXPENSE_VOUCHER`/`MANUAL_DISBURSEMENT`)와 CashReceiptKind(`DEPOSIT_REPORT`/`MANUAL_RECEIPT`) 라벨은 상세 tooltip 또는 후속 drill-down에서 tokens.md 매핑을 따른다.

---

## 4. 상태

- 빈 결과: `조건에 맞는 거래처 잔액이 없습니다.` + `필터 초기화`
- 오류: `잔액 스냅샷을 불러오지 못했습니다.` + `다시 시도`
- 갱신 실패: 기존 표 유지 + `스냅샷 갱신에 실패했습니다. 잠시 후 다시 시도하세요.`
- 권한 없음: `거래처 잔액 스냅샷을 볼 권한이 없습니다.`
