# 출고전표 작성폼 전면 정비 — RESULTS

> 개발책임자 실 UI 리뷰 반영. eCount 잔재로 비대해진 출고전표 작성폼 정비.

## 변경
| 항목 | 전 | 후 |
|---|---|---|
| 창고 | 출발 창고 + 도착 창고 (2개) | **출고 창고 1개**(입고전표=입고 창고 1개). 도착 창고 제거 |
| 출고구분 | 배송태그(label="배송태그") | **출고구분**(동일 옵션 당일/야적/지방/택배3/대여/반납 리라벨) |
| 거래 명세 정보(eCount 12필드) 카드 | 존재 | **카드 전체 제거** — ioType(출고/입고 토글), 거래처 연락처/주소/대표자 입력, 배송지/검수지/수령자, 결제만기/할인/회수/약정, timeDate |
| 배송 정보(V20) | 배송주소/감리주소 + 프로젝트명/인수자번호/입금예정일 | **배송주소 + 감리주소만** |
| 거래처 snapshot | 카드 입력 | 자동완성 선택 시 채워짐(폼 미표시, 전표 기록·주소복사용 유지) |

- ioType(eCount 10/11)은 사용자 선택이 아니라 내부 코드 → BE 가 slipType 으로 자동 분기(미전송).
- 거래처 자동완성에서 **선택** 시 연락처/주소/대표자 자동 채움(현 동작 유지). 배송주소 "거래처 주소 복사" 버튼 유지.

## 검증
- desktop `npm run typecheck` PASS (제거 state 잔여 참조 0).
- **실 UI 캡처**(실 Docker 스택 :8080 + 실 로그인 dev_master): `form-cleaned.png` — 출고 창고 1개 + 출고구분, eCount 카드 없음, 배송 정보=배송/감리주소만.

## 분리(별도 슬라이스)
- **단가 부가세포함 전환**: 단가=부가세 포함 → 공급가액=round(단가÷1.1)·부가세 분리. 작성폼뿐 아니라 **전표 상세/조회/견적 전반 일관성** 필요하므로 본 구조 정비와 분리해 전용 슬라이스로 진행(반쪽 적용 방지). BE SlipLine 은 이미 unitPrice(공급가)+unitPriceWithVat+supplyAmount 보유 → FE 입력/표시 계층만 전환 예정(BE 계약 무변경).
- **세트 구성품 규격 자동채움**(product_spec) 별도 슬라이스.
