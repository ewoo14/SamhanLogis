## 첫 번째 각도 — 이번 fix가 정상 동작을 막았는가

### 1. 행 분리의 화면·CSV·인쇄 영향

- 백엔드는 `actualUnitPrice`를 `AxisKey`에 넣어 실제 단가가 다르면 별도 `DailyProductLine`을 만든다. 수량·공급가·VAT는 각 key별로 그대로 합산하므로 전체 합계 유실은 확인되지 않았다: `MonthEndCloseService.java:346-357,379-398,429-470,638-665`.
- 데스크톱은 응답 순서대로 모든 `productSummaries`를 `rowIndex`가 포함된 고유 key로 렌더한다. 모델당 1행 가정이나 별도 페이지 제한은 없다: `DailyClosingPage.tsx:621-624,1137-1166`.
- 일마감 상세 자체에는 CSV/인쇄 동작이 없다. 같은 API를 쓰는 매출마감·월마감 CSV는 `productSummaries`가 아니라 `taxInvoices`만 내보내며 합계도 응답의 `totalSupply/totalVat/totalAmount`를 쓴다: `SalesClosingPage.tsx:112-135`, `MonthEndClosingPage.tsx:106-135`.
- targeted UI 테스트 `DailyClosingPage.test.tsx`는 26/26 통과했다. exact-SHA의 `Frontend Desktop` 및 Playwright checks도 통과했다.
- 현재 공유 accounting DB에는 같은 날짜·품목에 서로 다른 단가가 공존하는 화면 도달 묶음이 0개라 실데이터 다행 분리 화면/페이지 나눔은 재현하지 못했다. 후보의 `DailyClosingDetailServiceTest`는 두 실제 단가 25,843,675원과 28,043,675원을 두 행으로 반환했다.

이 범위에서 행 분리로 인한 합계·정렬·CSV·인쇄 기능 차단은 확인하지 못했다.

### 2. `HALF_UP` 기존값 영향 직접 계수

공유 `slip_db`의 활성 `unit_price_domain='VAT_INCLUSIVE'` 라인을 수량까지 포함해 아래 두 산식으로 직접 비교했다.

```text
기존 = TRUNC(ROUND(unit_price_with_vat × quantity) / 1.10)
신규 = ROUND(ROUND(unit_price_with_vat × quantity) / 1.10)
```

```text
existing_lines  11
unchanged_lines  5
changed_lines    6
changed_slips    5
supply_delta    +6원
vat_delta       -6원
total_delta      0원
```

변경 묶음도 보고와 일치했다.

```text
218181→218182 / VAT 21819→21818 : 4라인
401090→401091 / VAT 40110→40109 : 1라인
602363→602364 / VAT 60237→60236 : 1라인
```

따라서 “6라인 5전표, +6/−6/0원”은 **현재 slip DB의 기존 VAT 포함 라인 재계산 영향**으로는 정확하다. 그러나 F-01처럼 공유 계산기의 다른 소비자인 신규 partner-order 주문 경로는 이 숫자에 포함되지 않았다.

## 두 번째 각도 — R-01·R-02 해소 여부

### R-01 전표 단가

읽기 전용 SQL로 화면이 읽는 상태(`ISSUED` 세금계산서, `POSTED` 매출/매입 회계전표)의 각 라인에 대해 다음을 비교했다.

```text
표시 단가 = (supply_amount + vat_amount) / quantity
원천 단가 = line_total / quantity
```

현재 도달 데이터는 `TAX_INVOICE` 13라인뿐이고 수량 0은 0라인이었다. 표시 단가와 원천 단가 차이는 **0라인**, 최대 차이는 **0원**이었다. 현재 DB에는 같은 날짜·품목의 복수 실제 단가 묶음이 0개였다. 따라서 실데이터에서 “표시 ≠ 실제”는 0으로 확인했지만, 복수 단가의 실제 두 행 렌더는 데이터 부재로 확인하지 못했다.

### R-02 110,005원 견적

공개·내부 견적과 단일·병합 주문 발행 테스트에서 모두 다음 저장값을 다시 확인했다.

```text
입력 VAT 포함 단가 110,005원 × 수량 1
공급가액 100,005원
VAT       10,000원
합계     110,005원
```

견적 원천과 slip 발행 저장값은 일치한다. R-02의 목표 경로는 해소됐지만, 같은 공유 변경이 F-01의 partner-order 기존 계약 회귀를 만들었다.
