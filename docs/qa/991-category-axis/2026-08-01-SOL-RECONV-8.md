## (1) main이 확정하던 것을 여전히 확정하는가? — PASS

### 6 대 6은 같은 6건인가

**아니다.** r9 exact 우선 6행은 아래 모델 토큰이다.

| 원천 | snapshot 모델 | main label 결과 | r9 결과 |
|---|---|---|---|
| partner-order | `AR-EH05` | 미확정 | exact 확정 |
| partner-order | `AWR-WE13N` | 미확정 | exact 확정 |
| slip | `AC023CN1DBC1` | 미확정 | exact 확정 |
| slip | `AC023CX1DBC1` | 미확정 | exact 확정 |
| slip | `AR-EC05` | `AMBIGUOUS` | exact 확정 |
| slip | `PC1NWSK3NW` | 같은 제품 확정 | 같은 제품 exact 확정 |

r9 보고서의 `main 6`은 main 코드의 label resolver를 양쪽 원천 라벨에 실제 적용해 얻은 집합이 아니다. 현재 제품 연결과 불변 `modelCode` 조건을 대리 집계한 뒤 이를 “label 결과 6”으로 해석했다. main의 실제 판정 입력은 snapshot `modelName`이 아니라 `productName`이고, 3단 label resolver 결과다.

- main은 `productName`으로만 집계하고 label 해소 결과를 그대로 사용한다: `origin/main:services/accounting-service/src/main/java/com/samhanair/logis/accounting/service/MonthEndCloseService.java:345-400`.
- label resolver는 노출 modelCode exact → alias → unique LIKE 순이며, 후보가 2개 이상이면 `AMBIGUOUS`다: `services/product-service/src/main/java/com/samhanair/logis/product/service/ProductService.java:311-330`.
- r9 exact 6행은 snapshot token 조회 결과의 `modelCode`가 그 token과 같을 때만 채택된다: `services/accounting-service/src/main/java/com/samhanair/logis/accounting/service/MonthEndCloseService.java:513-531`.

### main 확정 결과의 보존 여부

동일한 활성 원천 4,843행에 main label resolver와 r9 `effectiveProductMatch`를 각각 적용하고 `source + line id + resolved product id`를 대조했다.

- main `MATCHED`: 185행, 7개 label 그룹.
- r9 최종 `MATCHED`: 190행.
- 교집합: 185행.
- **main-only: 0행.**
- r9-only: 5행(위 exact 6 중 main과 겹치지 않은 5행).
- 동일 원천 행을 main과 r9가 서로 다른 제품으로 확정: **0행**.

따라서 “6 대 6이 같은 집합”이라는 r9 보고서 설명은 성립하지 않지만, 실제 사용자 결과 기준으로 main이 확정하던 행을 r9가 못 하게 만든 회귀는 없다. r9 코드는 불변코드 일치 exact가 아니면 `byLabel`을 반환하고, exact 자체가 없을 때도 기존 label의 null-code 정상 경로를 보존한다: `services/accounting-service/src/main/java/com/samhanair/logis/accounting/service/MonthEndCloseService.java:523-540`.
