## 조사 입력과 재현 기준

공유 `product_db`는 모든 SQL을 `BEGIN READ ONLY` 트랜잭션으로만 조회했다. DB write, 코드 수정, 빌드, 서버 기동은 하지 않았다. 시트 값은 허용된 추적 스냅샷 `docs/dev-reports/1008-r9-snapshot/single-components-A1-N1737.csv`를 사용했다. Google 자격 키는 읽거나 출력하지 않았다.

### 전환 전(현행)

제시된 네 관측값을 모두 재현하는 기준은 다음과 같다.

```text
remain = setUnit - 현재 DB 기본 고정/예약행 금액 합계
indoor = HALF_UP(remain × allocationWeight / weightSum), 1원 단위
outdoor = remain - indoor
```

이 기준은 제시값 `572,810/859,215`, `346,400/519,600`과 정확히 일치한다. 즉 전환 전 비교값에는 1,000원 반올림이 적용되지 않았다.

### 전환 후(데이터)

HEAD의 `redistributeFromContract`를 그대로 재현했다.

```text
AUTO + INDOOR/OUTDOOR = 비중 배분 대상
그 외 선택 기본행 = 예산 예약행
fixedSum = fixedAllocationAmount, 없으면 현재 전역 deliveryPrice
indoor = HALF_UP(remain × weight / weightSum, allocationRoundUnit)
outdoor = remain - indoor
```

### 레거시 계산값

`tools/legacy-gas/거래처 발송 주문서/index.html:1655`의 `splitIndoorOutdoorToK` 실행 순서를 그대로 재현했다. 고정행 입력은 같은 세트 문맥의 시트 값, 본체 비율은 레거시 분류의 가정 6:4·비가정 4:6이다.

```text
remain = setUnit - sheetFixedSum
indoor = round(remain × ratioIn / total)
indoor = roundK(indoor)
outdoor = remain - indoor
mod = outdoor mod 1000
outdoor > 0이면 indoor -= mod, outdoor += mod
```

마지막 보정은 주석의 “둘 다 천원 단위”와 달리 끝전을 다시 만들 수 있다. 이 보고서는 주석이 아니라 실행 코드를 따랐다.

시트에 본체 값이 없는 3행은 빈칸으로 남겼지만, 해당 세트에는 레거시 고정합 계산에 필요한 값이 모두 있어 레거시 계산 불가 세트는 0건이다.

## 원인 추적

### 1. 추가 기본행 87건 전제는 반대로 기록돼 있었다

실 DB 분포는 다음과 같다.

| 기본 전개행 수 | 세트 수 | 실내·실외 외 예약행 수 |
|---:|---:|---:|
| 2 | 87 | 0 |
| 3 | 89 | 1 |
| 4 | 61 | 2 |
| 5 | 34 | 3 |

따라서 **87세트는 추가 행이 있는 세트가 아니라 실내·실외 1쌍만 있는 세트**다. 추가 기본행이 있는 세트는 **184세트**다.

- 추가행 없는 87세트: 차이 0세트
- 추가행 있는 184세트: 차이 166세트, 무차이 18세트

추가행은 이번 차이와 강하게 관련 있다. 추가 고정액 때문에 `remain`에 천원 미만 끝전이 생기고, 데이터 전환이 `allocationRoundUnit=1000`을 적용하면서 실내·실외 사이 금액이 이동했다.

### 2. allocationWeight 누락·불일치는 원인이 아니다

- AUTO INDOOR 271행, AUTO OUTDOOR 271행
- `allocationWeight IS NULL`: 0행
- 세트별 AUTO 비중 합계 10이 아닌 세트: 0건
- 레거시 가정/비가정 비율과 DB 비중이 다른 세트: 0건

### 3. allocationRoundUnit은 직접 차이 원인이다

- 271세트 모두 `allocationRoundUnit=1000`
- 차이 332행은 전부 INDOOR/OUTDOOR다.
- 고정·예약행은 전환 전후 같은 값이다.
- 행별 이동은 최대 446원, 세트별 실내 증감과 실외 증감이 상쇄된다.

따라서 전환 전후 86,412원의 절대 이동은 1,000원 반올림을 새로 소비한 결과다.

### 4. FIXED 금액이 시트와 다른 세트가 65건이다

| 종류 | 불일치 행 |
|---|---:|
| PANEL | 58 |
| REMOTE | 53 |
| 합계 | 111 |

- 관련 세트: 65
- 현재 고정액은 시트 합계보다 총 1,568,205원 낮다.
- 65세트 모두 이번 차이 세트이며 세트 분류 ㉢이다.
- 대표적으로 시트 128,000원 패널이 현재 104,060원, 시트 16,000원 리모컨이 현재 13,915원이다.

이는 개발책임자의 “멀티의 동일 품목 가격을 쓴 것으로 보인다”는 관측과 일치한다.

### 5. 레거시와 시트 자체가 충돌하는 세트가 66건이다

- 본체 불일치: INDOOR 66행 + OUTDOOR 66행 = 132행
- 이 중 전환 전후도 달라진 세트: 52
- 전환 전후는 같지만 레거시·시트 충돌이 잠복한 세트: 14

예: `AF60F17D11BRS`는 전환 후와 레거시가 649,000/433,000으로 같지만 시트는 769,000/313,000이다. 이 경우 “레거시와 시트를 동시에 따른다”는 조건 자체가 성립하지 않으므로 ㉢이다.

### 6. “추가 행을 예산 예약 행으로 합산” 처리의 영향

이 처리는 차이 발생의 조건이지만 단독 원인은 아니다.

- 전환 전 재현도 같은 현재 고정/예약행 합계를 차감한다.
- 전환 후도 같은 합계를 차감한다.
- 두 값의 차이는 그 뒤 1,000원 반올림에서 생긴다.
- 다만 예약행의 금액이 시트가 아닌 전역/멀티 값이면 레거시 예산과 다른 `remain`을 만들므로 65세트의 ㉢ 원인이 된다.

즉 예약행 합산을 제거하면 합계 보존 계약이 달라지고, 그대로 두되 잘못된 고정액을 유지하면 레거시·시트와 계속 어긋난다.

## 두 의사결정 경로별 필요한 변화

### “271건 게이트”를 통과시키려면

목표는 전환 전후 차이 166세트·332행을 0으로 만드는 것이다.

- 현재 고정/예약행 금액과 AUTO 비중을 유지한다.
- AUTO 배분에서 1,000원 반올림을 적용하지 않고 기존처럼 1원 단위 HALF_UP + 실외 잔차를 보존하거나, 같은 결과가 되도록 반올림 계약 데이터를 바꾼다.
- 이 경로는 현재 운영값을 보존하지만, 65세트의 잘못된 고정액과 66세트의 레거시-시트 충돌을 해결하지 않는다.

### “레거시 정본”을 따르려면

목표는 `splitIndoorOutdoorToK` 실행 결과를 그대로 내는 것이다.

- 65세트의 PANEL·REMOTE 고정액을 전역/멀티 값이 아니라 세트 문맥 시트 값으로 바꾼다.
- 본체는 레거시 가정/비가정 비율과 `roundK` 뒤 실제 mod 보정 순서를 그대로 적용한다.
- 현재 전환 후에서 레거시로 바뀌는 범위는 65세트·237행, 순증감 0원, 절대 이동 3,136,410원이다.
- 단, 66세트는 레거시 결과와 시트 본체 값이 충돌한다. 그 세트에서 “레거시 함수”와 “시트 값” 중 무엇을 최종 정본으로 볼지는 별도 결정이 필요하다.
