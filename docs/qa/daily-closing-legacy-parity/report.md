## ② RED 원문

새 회귀 테스트를 먼저 추가한 뒤 실행했다.

```text
FAIL  DailyClosingPage S3 레거시 단일표 > 금액 편집 뒤 정렬과 열 필터는 화면의 최신 draft 값을 사용한다
expected '...회계 반영 품목...' to contain '편집 품목'
```

원인은 금액 draft를 바꾼 뒤 정렬·필터가 화면 draft가 아닌 API 원본 `productPrice`를 읽고 있었기 때문이다.

## ③ 구현한 것

- `DailyClosingPage.tsx`에 `viewColumnValue`를 추가했다.
- 금액 draft/저장 완료값의 단가·공급가액·부가세·합계·출고가·할인율·총계를 정렬·필터·통합검색에 사용한다.
- 화면 표시와 같은 천 단위 콤마 값을 필터 기준으로 사용한다.
- 기존 셀 선택·TSV 복사·헤더 정렬·열 필터·통합검색·초기화 구현은 변경하지 않고 최신 draft 연동만 보강했다.
- 새 테스트: 금액 편집 후 출고가 정렬 및 `20,000` 열 필터가 최신 draft를 찾는지 검증한다.

사용자는 셀을 여러 개 선택하고 선택 합계를 확인한 뒤 복사할 수 있으며, 각 헤더의 정렬·필터와 통합검색을 적용할 수 있다. 금액 편집 후에도 같은 화면에서 새 금액을 즉시 정렬·검색할 수 있다.

공유 API는 인증 방식(`POST /auth/login`, `dev_master`)으로 확인했고 공유 DB·컨테이너는 변경하지 않았다.

- `docs/qa/1270-daily-closing-parity-real-qa/01-2026-08-03-multi-select-copy.png`: 2026-08-03, 4행. 공급가액·부가세 2셀 선택, 선택 합계 641,480 표시.
- `docs/qa/1270-daily-closing-parity-real-qa/03-2026-08-03-sort.png`: 2026-08-03, 4행. 번호 오름차순 헤더 동작.
- `docs/qa/1270-daily-closing-parity-real-qa/05-2026-08-03-filter.png`: 2026-08-03, 4행 기준. 품목명 필터 팝업 및 검색.
- 2026-08-14 라이브 API/기존 화면 확인: 결과 1행 + 선발행 12행 = 13행. 기존 #1250 스펙의 결과 탭을 전체 13행과 비교하는 단정은 잘못되어 실패했다.

8/14에 생성된 보조 캡처 02/04/06은 네트워크 경고가 표시된 상태에서 선발행 탭 전환이 안정적으로 끝나지 않아 증거로 승격하지 않았다. 8/14 행 수는 API 응답 13건과 결과 1건 화면으로 대조했고, 기능 동작 증거는 4행이 안정적으로 표시된 8/03 캡처를 사용한다.

복사 문자열 자체는 Vitest에서 `text/plain` TSV로 확인했다. 스크린샷은 선택 합계와 선택 셀 강조를 포함한다.
