## ② 설정값 변경 → 화면 반영 확인

격리 PostgreSQL `product_clone`에서만 `AWR-WG00N` 연결 65행의 `context_delivery_price`를 `91,000 → 123,456`으로 바꾸고 브랜치 백엔드와 양쪽 renderer를 다시 읽혔다. 공유 DB에는 쓰지 않았다.

| 화면 | 변경 전 컬러 상세 단가 | 변경 후 컬러 상세 단가 | 변경 전 세트가 | 변경 후 세트가 | 결과 |
|---|---:|---:|---:|---:|---|
| 종합견적서 | 91,000 | 123,456 | 1,607,000 | 1,639,456 | 설정 변경 32,456원이 상세·세트가에 그대로 반영 |

따라서 현재 `컬러` variant의 모델·납품가는 코드 상수가 아니라 `bundle_component_estimate_setting → bundle_component.context_delivery_price` 경로에서 온다. 변경 후 컬러 차액도 `123,456 - 16,000 = 107,456`으로 양쪽이 동일했다. 검증 뒤 격리 DB는 `컬러`, `91,000`으로 원복했다.

다만 설정 원천성의 추가 적대검증에서 실사용자 결함을 재현했다. 격리 DB의 컬러 variant 명칭만 `컬러 → 특수`로 바꾸면 양쪽 셀렉트 목록에는 실제로 `특수`가 나타나지만, 사용자가 이를 선택해도 `AWR-WG00N 91,000`이 아니라 기본 `AR-EH05 16,000`이 유지되고 세트가도 1,532,000원에서 오르지 않는다. 즉 **목록은 설정 기반이지만 소비 분기는 `유선|컬러`에 하드코딩**되어 있다.
