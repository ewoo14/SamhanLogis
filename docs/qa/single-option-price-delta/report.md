# 싱글중대형 옵션 가격 차액 검증 보고서

## 1. RED 원문 3축

지정된 `docs/dev-reports/2026-08-17-option-price-impact/report.md`는 이 워크트리에 존재하지 않아 읽을 수 없었다. 대신 `origin/main`의 동일 함수 원문을 메모리에서 실행했다.

```text
remote: { ok: true, value: null }
panel: { ok: true, value: null }
material: { ok: true, value: 0 }
```

재현 조건은 AC060CS6PBH1SY, 구성품 정본 `component_variant` 직접 입력이다.

- 리모컨: 기본→유선 후보가 해석되지 않아 1,660,000원에 40,000원이 더해지지 않음
- 판넬: 기본→블랙 후보가 해석되지 않음
- 자재: `component_variant=자재`를 읽지 못해 포함액 0원

## 2. 판넬·자재 싱글 실측 표

| 축 | 기본가 | 선택가/포함액 | 차액 | 세트가 before | 세트가 after | 일치 여부 |
|---|---:|---:|---:|---:|---:|---|
| 판넬 기본→블랙 | 30,000 | 50,000 | 20,000 | 1,660,000 | 1,680,000 | 일치 |
| 자재 별도→포함 | 0 | 25,000 | 25,000 | 1,660,000 | 1,685,000 | 일치 |

위 표는 RED/GREEN 단위 테스트의 고정 실측이다. 라이브 AC060 구성품에는 `MATERIAL` 행이 없어서 라이브 자재 전환은 `0 → 0`으로 관찰되었다. 따라서 기존 조사에서 “세 화면 모두 반영”이라고 판정한 것은 AC060의 자재 원천 행 부재를 반영 동작으로 잘못 읽은 것으로 판정한다.

라이브 AC060 구성품은 판넬 10행, 리모컨 3행이며 자재 행 0행이다. 라이브 데이터의 리모컨 원가 필드는 무선 13,915원, 유선 45,375원이지만, 레거시 싱글 차액 설정은 유선 40,000원이다.

## 3. 원인

싱글중대형 옵션 후보를 표시 문자열과 `feat`에만 의존했다. PR #1263 이후 정본 축인 `component_variant`를 직접 받은 구성품은 리모컨·판넬·자재 모두 후보/금액 계산에서 누락될 수 있었다. 또한 레거시 싱글 옵션 차액 설정(`singleMatPrices`)을 구성품 원가 치환값으로 사용하지 않았다.

## 4. 고친 내용

- `component_variant → componentVariant → feat` 순서의 정본 해석 helper 추가
- 리모컨 유선/컬러유선 후보를 정본 변형값으로 탐색
- 판넬 기본·선택 후보와 변형값을 정본으로 탐색
- 자재 포함액을 정본 변형값 `자재`로 합산
- 유선·컬러유선·블랙·승강·공청 선택은 `singleMatPrices`의 레거시 차액을 우선 사용하고, 설정이 없으면 구성품 가격 차액으로 fallback
- `변동단가` 명칭은 변경하지 않음

## 6. 라이브 캡처와 금액

estimate-app는 이 워크트리에서 포트 5183으로 기동했고 `/healthz=200`, `/=200`을 확인했다. 그러나 현재 Codex 세션에는 사용 가능한 브라우저가 없어(`agent.browsers.list()=[]`) `resolveQaShotsDir()` 경유 실화면 캡처를 생성하지 못했다. 따라서 라이브 캡처 파일은 게시하지 않는다.

## 7. 회귀 없음 확인

- 홈멀티·상업멀티의 기존 표시 문자열 후보 계약 테스트 유지
- 기본 구성품의 `isDefault=true` 우선 및 legacy `feat=기본` fallback 테스트 통과
- `component_variant` 해석은 싱글 helper에만 추가했고 홈멀티·상업멀티 계산 흐름을 변경하지 않음
- `변동단가` UI 명칭과 의미는 변경하지 않음

## 8. 프로세스 회수

공유 스택 컨테이너는 변경·중지하지 않았다. 이 워크트리의 estimate-app 기동 프로세스는 최종 검증 후 회수하며, 잔여 수를 마지막 보고에 기록한다.
