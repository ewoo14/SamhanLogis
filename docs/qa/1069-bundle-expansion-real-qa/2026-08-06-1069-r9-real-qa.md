```text

360 정액 30,000원 → 관찰 불가
```

`AC060CN6PBH1`의 실 DB `selling_price=935000.00`, `has_variable_discount=true`는 확인했지만, 화면 단가가 생성되지 않았으므로 B의 PASS/FAIL 근거로 사용하지 않았다.

## 5. 결함·실 사용자 도달성

### 발견한 차단 상태

실 사용자가 판매전표 신규 화면에서 `AC060CN6PBH1` 또는 `AC060BN6PBH1`을 입력하면 품목 검색 결과가 없다. 따라서 R9가 확인하려는 정액 할인 로직의 실제 도달 전제부터 성립하지 않는다.

### 재현 절차

1. `http://localhost:5199` 접속
2. `dev_manager`로 로그인
3. 판매 → 새 판매전표
4. 거래처 검색에 `1060818309` 입력 후 `랜드유통(최경호)` 선택
5. 출고 창고에 실 데이터 `1 · 서초창고` 선택
6. 품목 1행에 `AC060CN6PBH1` 입력
7. `검색 결과 없음` 확인
8. 같은 방식으로 `AC060BN6PBH1` 입력해도 `검색 결과 없음`

### 사용자 도달성 판정

**도달 가능하며 재현됨.** 이는 실 UI·실 API에서 발생한다. 다만 R9 할인 계산 결함으로 단정하지 않는다. 실 DB에는 두 품목이 존재하지만 `usage_scope=NONE`, 판매전표 검색 요청은 `usageScope=PARTNER_ORDER`이므로 사용범위 불일치가 직접 원인 후보다. 개발책임자 지시대로 `products` 데이터와 코드는 변경하지 않았다.

### 저장·DB

저장하지 않았으므로 `<id>`가 없다. `slip_lines` 원문 조회는 허위 ID를 만들지 않기 위해 실행하지 않았다. DB 쓰기·전표 생성은 0건이다.

참고로 로그인/화면 기동 중 콘솔에는 기존 인증 전 초기화 요청의 `401 Unauthorized`와 `503 Service Unavailable`이 관찰됐으나, 로그인은 `POST /auth/login -> 200`으로 성공했고 이번 중단 사유는 해당 콘솔 메시지가 아니다.
