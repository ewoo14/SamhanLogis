# PR #1077 / Issue #1069 라이브 QA R2

## 결론

**C: FAIL**

전역DC API는 재배포 후 정상적으로 200을 반환했고 세트 구성품도 4행으로 전개됐다. 그러나 가격은 기대한 **자격 있음 2행 할인 / 자격 없음 2행 정가**로 갈리지 않았다. 현재 관측은 자격 없는 PANEL·REMOTE가 할인되고, 자격 있는 INDOOR·OUTDOOR는 기대한 할인 상태가 아니다.

## 사전 전제 확인

거래처 선택 직후 브라우저의 실제 API 호출이 다음과 같이 성공했다.

```text
GET /api/v1/partner-dc-configs/1012555999  →  200
```

응답에서 확인한 값:

```text
partnerCode       1012555999
companyName       동영 온라인점-송아름
homeMultiDc       45%
commercialMultiDc 46%
unitProcess       No
```

따라서 R1의 500은 현재 배포본에서 재현되지 않았다. 인증 전 직접 호출이 401인 것은 로그인 전 정상 응답이며 결함으로 세지 않았다.

## C-1. 4행 전개와 전역DC 공존

품목 입력 후 다음 호출이 모두 성공했다.

```text
GET  /api/products?q=AC072CS6PBH1SY&size=20&usageScope=PARTNER_ORDER  →  200
POST /slips/expand-line                                           →  200
```

전개 결과는 정확히 4행이었다.

| 행 | 구성품 | has_variable_discount | 화면 단가 | 화면 공급가액 | 화면 부가세 |
|---:|---|:---:|---:|---:|---:|
| 1 | `AC072CN6PBH1` / INDOOR | true | 1,053,775 | 957,977 | 95,798 |
| 2 | `AC072CXAPBH1` / OUTDOOR | true | 1,580,450 | 1,436,772 | 143,678 |
| 3 | `PC6NUNK1NW` / PANEL | false | 104,060 | 94,600 | 9,460 |
| 4 | `AR-EH05` / REMOTE | false | 13,915 | 12,650 | 1,265 |

화면은 `전표 라인단가는 부가세 포함 단가`라고 명시한다. 따라서 화면 `단가`를 VAT 포함 금액으로 판정했다. 세트 부모 품목 API의 `sellingPrice=2,752,200`도 네 행 화면 단가 합계 `2,752,200`과 일치한다.

PM이 제공한 구성품 `selling_price`와 비교하면:

| 구성품 | 정가 기준 | 관측 | 판정 |
|---|---:|---:|---|
| INDOOR | 990,000 | 1,053,775 | 자격 있음인데 정가보다 낮아지지 않음 |
| OUTDOOR | 1,540,000 | 1,580,450 | 자격 있음인데 정가보다 낮아지지 않음 |
| PANEL | 189,200 | 104,060 | 자격 없음인데 55%로 할인됨 |
| REMOTE | 25,300 | 13,915 | 자격 없음인데 55%로 할인됨 |

REMOTE는 같은 실사용 세션의 상품 검색 응답에서도 `sellingPrice=25,300`, `deliveryPrice=13,915`, `hasVariableDiscount=false`로 확인됐다. 화면 단가는 이 `deliveryPrice`를 사용하고 있었다.

따라서 결과는 기대한 **할인 2행 / 정가 2행이 아니다.** 정가를 VAT 포함으로 해석하면 자격 있는 2행은 할인되지 않고 자격 없는 2행만 할인되어 사실상 반대 방향이다. `selling_price`를 공급가로 해석하더라도 네 행 모두 어떤 형태로든 가격 조정이 발생하므로 2/2가 아니다. 즉, 단순히 “전부 정가” 또는 “전부 할인”의 두 갈래가 아니라 **자격 축과 가격 도메인이 엇갈린 셋째 상태**가 관측됐다.

## C-2. 옵션 교체

화면에는 판넬 옵션 교체 경로가 실제 사용자에게 노출되어 있었다.

```text
판넬 모델코드 (미입력=기본)
```

자격 있는 `PC6NUCK1NW`를 입력하고 Enter를 누르자 브라우저 요청에는 다음 값이 포함됐다.

```json
{"parentModelCode":"AC072CS6PBH1SY","setOptions":{"panelOption":"PC6NUCK1NW"}}
```

서버 응답은 200이었지만 PANEL은 계속 기본값이었다.

```text
응답 PANEL: PC6NUNK1NW
응답 단가: 104,060
화면 3행: PC6NUNK1NW / 104,060
```

화면 하단에는 다음 상태가 남았고 저장 버튼은 비활성 상태였다.

```text
세트 구성품 반영 중... 저장할 수 없습니다.
```

이후 자격 없는 `PC6EUCK1NW`로 교체해도 화면의 4행과 단가는 기본값에서 변하지 않았다. 따라서 옵션 교체는 “경로 없음”은 아니지만, 현재 실사용 경로에서 입력한 옵션이 구성품과 가격에 반영되지 않고 저장도 진행할 수 없다.

REMOTE 교체용 별도 입력 컨트롤은 이 화면에 보이지 않았다. 다만 PANEL 교체 경로 자체는 존재하므로 “옵션 교체 경로가 전혀 없음”으로 판정하지 않았다.

## 콘솔 및 환경 관찰

- C 관련 API의 401/500/503은 최종 경로에서 발생하지 않았다.
- 개발 서버에서 폰트 디코드 경고가 반복됐다.
- 앱 부팅 중 활성 공지 조회와 메뉴 접근 기록 요청이 503을 반환했다. 판매전표 핵심 API와 C 판정에는 영향을 주지 않았으며 이번 C 결함 수에는 포함하지 않았다.
