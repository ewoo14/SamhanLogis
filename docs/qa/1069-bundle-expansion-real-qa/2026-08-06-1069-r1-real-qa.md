## 1. 네트워크 및 실환경 확인

renderer는 이 워크트리의 `clients/desktop`에서 `VITE_APP_VERSION=2026/08/06-1`, Vite `localhost:5199`로 기동했다. `VITE_MOCK_MODE`는 설정하지 않았다. 로그인 후 네트워크에서 확인한 실제 경로는 다음과 같다.

사용자가 안내한 로그인 URL `/api/v1/auth/login`과 달리 renderer가 실제 호출한 로그인 경로는 `/auth/login`이며 200이었다. 로그인 응답 원문과 JWT는 저장·기록하지 않았다.

부가적으로 이 환경에서 로그인 후 `GET /app/notices/active`, `POST /logs/front`가 각각 503으로 관찰됐다. 판매전표 핵심 API의 200/201과는 별도 경로다.

## 3. 선택 시나리오

E(세트품목 직접 API 저장)와 F(구성품 단독 입력)는 A/C의 필수 전제가 이미 깨져 있고, 추가 실 DB 변이를 늘리지 않기 위해 미실시했다. 가짜 데이터나 mock으로 대체하지 않았다.

`자재 포함` 옵션은 진단 목적으로 한 번 실제 클릭했다. 실 `POST /slips/expand-line`은 여전히 4행을 반환했으며 화면 하단에 `세트 구성품 반영 중... 저장할 수 없습니다.`가 남았다: [`07-bundle-material-included.png`](screenshots/07-bundle-material-included.png). 이 옵션 토글 자체는 E/F 판정에 포함하지 않았다.

## 4. 발견한 결함 및 실 사용자 도달성

1. **세트 전개 행 수가 기대 13행이 아니라 4행**
   - 재현: 로그인 → 새 판매전표 → `서초창고` → 거래처 코드 `1012555999` → `AC072CS6PBH1SY` 입력.
   - 실 사용자 도달 가능: 가능. 화면 입력만으로 재현된다.
   - 결과: 부모 세트 라인은 숨겨지지만 9개 구성품이 누락된다. 저장·상세에도 4행만 남는다.

2. **전역DC 조회 API 500**
   - 재현: 같은 거래처를 선택하면 `/api/v1/partner-dc-configs/1012555999`가 500.
   - 실 사용자 도달 가능: 가능. 거래처 선택 즉시 발생하며 콘솔에도 500이 기록된다.
   - 결과: C의 6/7 할인 분류를 수행할 수 없다. D의 고정DC는 독립적으로 적용됐다.

3. **`자재 포함` 선택 뒤 저장 잠금 상태 잔류 관찰**
   - 재현: 번들 4행 전개 후 `자재 포함` 체크.
   - 실 사용자 도달 가능: 가능.
   - 결과: expand-line은 200이지만 화면에 `세트 구성품 반영 중... 저장할 수 없습니다.`가 남았다. 필수 A~D의 기본 입력 흐름과 별도 옵션 경로다.
