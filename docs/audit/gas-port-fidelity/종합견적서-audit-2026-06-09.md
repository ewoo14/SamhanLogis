## 1. P0 — 치명적 갭 (운영/정확성 직접 훼손)

### P0-A. 견적 저장/불러오기 엔드포인트 부재 ★사용자 지적 직결★
- 웹: `code.js:1686 saveQuoteSnapshot → POST {ESTIMATE}/api/v1/estimates/snapshots`, `code.js:1704 getQuoteHistory → GET .../snapshots`.
- BE: slip-service 에 `estimates/snapshots` **매칭 0건**. 존재하는 건 `/slips/estimates`(CRUD), `/slips/estimates/{id}/revisions`(리비전) — path·스키마 다름.
- 결과: **종합견적서에서 견적 저장·불러오기 호출 시 404 → 사용자 흐름 차단.** GAS 가 노션에 blob(base64 전체상태) 저장/복원하던 기능이 우리 쪽엔 없음.
- → 사용자 요구("견적 데이터 그대로 불러오기, GAS 노션 복원처럼")의 정확한 미구현 지점. **신규 `quote_snapshot` 테이블+엔드포인트 필요**(blob 그대로 저장/복원).

### P0-B. 출고전표 발행 — 잘못된 엔드포인트·스키마
- `slip-bridge.js:130` 이 `POST /api/v1/slips`(=`CreateSlipRequest`) 호출 → `slipType`/`productId(UUID)` 미송신으로 **400 확정**.
- 정작 1:1 매핑용으로 만든 `POST /api/v1/slips/from-estimate`(`PublishFromEstimateRequest`, `SlipPublishController`)는 **미사용**. 이 DTO 필드는 slip-bridge `buildSlipRequest` 출력과 거의 완전 일치(Javadoc 에 "호출자: lib/slip-bridge.js" 명시).
- → **URL 1줄 + line 필드명 정합**으로 해소(근본은 이식 시 연결 누락). 라인 필드: `productCode/qty/unitPriceExVat/unitPriceVat/supplyAmount/vatAmount/remarks` 대조 필요.

### P0-C. 비즈니스 로직 전면 재작성/축약 (carbon-copy 아님)
1. `getSpecDetailMap_` (code.js:1052) — GAS ~360줄(냉난방 kcal/kW·소비전력·효율등급·배관길이·중량/포장·ERV 레이아웃) → **6필드 골격만**. 견적서 상세 스펙표 대부분 공란. 주석에 "후속 PR" 자인.
2. `classifyHome_` (code.js:316) — GAS 8단계 분류(받침대/전열교환기/인테리어핏/제습기/실외기 단·다배관/실내기 1·4way·360·평형·무풍/판넬/부자재) → GAS 에 없는 키워드로 5분기 재작성. catM/catS·평형·무풍·HP 상실.
3. `classifyCommercial_` (code.js:383) — catS 소분류(소·중·대형/덕트정압/전열/ECO) + inKeys 상세 **전부 누락**.
4. `decideWarehouseCode_` (code.js:1502) — 창고결정 조건·매핑·**기본값 반전**. 잘못된 창고로 출고 위험.
5. `buildDefaultDcConfig_` (code.js:303) — 반환 shape flat→중첩 불일치. `bootstrap` config(flat)와 어긋나 DC 소비부 undefined.
6. `getFormulas()` shim 한계 (apps-script-shim.js:292) — 항상 빈문자 → `isDisc`/`useK2`/`matKey` 수식분기 전부 기본값 붕괴(구형할인/단가인상/자재키). **구조적**(Sheets readonly 가 수식 미제공) → 시드/DB 컬럼화 필요.

## 2. P1 — 표기/금액/스펙 보강 훼손
- `sanitizeKoreanParen_`/`trimSymbols_`/`sanitizeDisp_` 정제 깡통화(code.js:222~) → 표시명 노이즈 노출.
- `hpFromText_` string→number + `마력` 키워드 누락.
- `sendOrderFromUi` 가 `getSpecMap_` 미사용(SIZE_DES 보강 누락) + 거래처 `*` isStar 분기 누락.
- `formatWonDiscountLabel_`/`formatPercentLabel_` 출력 포맷 상이("-3만5천"→"(35,000원 할인)").
- `initDcConfigFromNotion` 10자리 가드+필드별 머지 안전로직 상실 → 통짜 Object.assign.
- DC설정 endpoint path 불일치(`/api/v1/partners/{bizno}/dc-config` 없음; 실제 dc-config-service `/api/v1/partner-dc-configs/{code}`) → 거래처 DC 항상 default(45%) silent.
- MS 치환 함수 응답 shape 일치 미보장: `checkUserAuth`(authorized), `getNotionHistory`(date), `getQuoteHistory`(created/createdAt), `getManagersForInput`, `searchCustomerByBizno`.
- 재고조회 `getInventoryTableHtml` stub("미구현" HTML) → 재고 화면에 미구현 문구 노출(silent).
- 로고/게이트 이미지 `getLogoImage`/`getGateImages` 빈값(files-service 미연동) → 인쇄 로고 누락 가능.

## 3. RPC 계약 함정
- `sendOrderFromUi` 등이 실패를 throw 대신 `{ok:false}` **정상 result 로 반환** → shim 이 successHandler 로 흘림 → 전표 생성 실패가 성공 UI 로 위장. (successHandler 에 `res.ok===false` 검사 또는 throw 전환 필요)
- dispatch 에러 표기에 `Error:` 접두 부착(경미).
