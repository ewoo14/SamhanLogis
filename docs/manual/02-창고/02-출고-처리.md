# 02. 출고 처리

> **Stage 안내**: Stage 2 ✅ — Phase 12 step-6 본 PR 에서 7-section 패턴으로 재작성.

---

## 1. 구현 상태

| 항목 | 상태 | 비고 |
| --- | --- | --- |
| Backend (slip-service OUTBOUND) | ✅ 운영 | 11 status (PR-G1: 12 컬럼) |
| Backend (inventory-service 자동 동기) | ✅ 운영 | reserve / release / deduct |
| 출고 list 화면 | ✅ 운영 | desktop electron-vite |
| 모바일 서명 (DELIVERED) | ✅ 운영 | mobile-staff |
| 인쇄 (거래명세표) | ✅ 운영 | 브라우저 인쇄 |

(주)삼한공조시스템 출고 처리는 전표 결재 후 창고에서 물품을 피킹하고 배송하기까지의 흐름을 안내합니다.

---

## 2. 대상 독자

- 전표을 피킹하는 창고 직원 (WAREHOUSE)
- 재고 lot 을 추적하는 재고 관리자 (INVENTORY)
- 출고 진행을 모니터링하는 영업 부장 (MANAGER)

---

## 3. 학습 내용

- 9 transition 출고 흐름 (APPROVED → CLOSED)
- 피킹 / 출고 / 배송 / 서명 단계 책임자
- 재고 reserve / release / deduct 의미
- DPS (Digital Picking System) 비교 활용

---

## 4. 본문

### 4-1. 출고 메뉴 진입

좌측 사이드바 **[창고]** > **[출고]** 클릭.

### 4-2. 9 transition 흐름

| # | Status 전환 | 책임자 | 트리거 |
| --- | --- | --- | --- |
| 1 | DRAFT → SUBMITTED | SALES | 결재요청 |
| 2 | SUBMITTED → APPROVED | MANAGER | 승인 |
| 3 | APPROVED → PICKING | WAREHOUSE | 피킹 시작 (재고 reserve) |
| 4 | PICKING → PICKED | WAREHOUSE | 피킹 완료 |
| 5 | PICKED → SHIPPING | DISPATCH/DRIVER | 배송 시작 (재고 deduct) |
| 6 | SHIPPING → DELIVERED | DRIVER | 도착 + 서명 수신 |
| 7 | DELIVERED → INVOICED | ACCOUNTANT | 세금계산서 발행 |
| 8 | INVOICED → CLOSED | ACCOUNTANT | 월말 마감 |
| 9 | * → CANCELED | MANAGER 승인 | 역분개 / 재고 release |

### 4-3. 피킹 시작

APPROVED 전표 list 에서 전표 클릭 → **[피킹 시작]** 버튼.

- inventory-service `/inventory/reserve` 호출 → 재고 가용량에서 차감 (예약)
- status: APPROVED → PICKING
- 창고 직원이 모바일 또는 desktop 으로 피킹 작업

### 4-4. DPS 비교

피킹 중 DPS (Digital Picking System) 와 시스템 데이터를 비교합니다.

- 시스템 표시 수량 vs 실제 피킹 수량
- 차이 발생 시 사유 입력 + 재고 실사 PR 권고

### 4-5. 피킹 완료 / 배송 시작

피킹 완료 후 **[피킹 완료]** → status: PICKING → PICKED.

배송 담당이 **[배송 시작]** 클릭 → status: PICKED → SHIPPING.

- inventory-service `/inventory/deduct` 호출 → 재고 영구 차감

### 4-6. 도착 + 서명

기사가 mobile-staff 앱에서 도착 확인 + 받는 사람 서명 수신.

- 자세한 절차는 [04-모바일 / 02. 전자 서명](../04-모바일/02-전자-서명.md) 참조
- 서명 수신 시 status: SHIPPING → DELIVERED
- DELIVERED 트리거로 자동 분개 발행 ([03-회계 / 01. 분개 입력](../03-회계/01-분개-입력.md))

### 4-7. 창고 이동 (Transfer)

창고간 재고 이동은 별도 transfer 화면 사용.

- 본사창고 → 지점창고
- inventory-service `/inventory/transfers`

### 4-8. 월말 마감

DELIVERED → INVOICED → CLOSED 흐름은 회계 단계. [03-회계 / 04. 월말 마감](../03-회계/04-월말-마감.md) 참조.

### 4-9. Stage 4 실시간 협업

출고 list / 상세에 [수정 횟수 chip](../08-실시간-협업/03-수정-횟수-카운트.md) + [audit overlay](../08-실시간-협업/02-수정-이력-보기.md). 피킹 진행 중 영업 직원이 전표 라인 수정 요청 시 [창고 직원 수락](../08-실시간-협업/07-창고-직원-수락.md) 흐름으로 처리.

## 6. FAQ

**Q1. 피킹 중 재고 부족 발생 시?**
A. 시스템에 부족 표시. WAREHOUSE 가 사유 입력 후 영업 직원에게 통지. 영업 직원이 전표 수정 또는 취소 결정.

**Q2. 부분 출고 (5개 중 3개만 출고) 가능?**
A. 미구현. 임시 우회로 전표 라인 수정 후 재결재.

**Q3. 배송 중 파손 발생 시?**
A. 기사가 모바일에서 사진 첨부 (P1 미구현 안내) + 사유 입력. 회사 도착 후 영업 부장 / 회계 협의.

**Q4. 출고 취소 시 재고는?**
A. CANCELED 처리 시 inventory-service `/release` 자동 호출 → 재고 복구.

**Q5. 묶음 출고 (10건 한 번에 배송)?**
A. 기사가 모바일에서 다수 전표 동시 수령. 각 전표 별도 서명 수신.
