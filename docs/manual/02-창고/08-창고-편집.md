# 08. 창고 편집 (관리자)

> **Stage**: Quick win — 데스크탑 관리자 화면에서 창고 마스터 정보를 목록 row 에서 바로 편집할 수 있도록 한 작업의 사용 매뉴얼.

---

## 1. 개요

관리자 → **창고 관리** 화면(`/admin/warehouses`)에서 row 의 **편집** 버튼을 클릭하면, 별도 페이지 이동 없이 모달이 열려 창고 정보를 수정할 수 있습니다.

변경된 필드만 PATCH payload 에 포함되므로 (diff-only), 다른 사용자가 동시에 수정한 필드는 보존됩니다.

---

## 2. 접근 경로

| 단계 | 위치 |
|---|---|
| 1 | 데스크탑 앱 사이드바 → "관리자" 그룹 → "창고 관리" |
| 2 | 목록의 각 row 우측 **편집** 버튼 (`data-testid=admin-warehouses-edit-{code}`) |

---

## 3. 편집 가능 필드

| 필드 | 타입 | 제약 | 비고 |
|---|---|---|---|
| 창고명 | text | 최대 100자, 필수 | 비울 수 없음 (저장 버튼 disabled) |
| 분류 | select | HEADQUARTERS / VEHICLE / CONSIGNMENT / VIRTUAL | 라벨: 본사 / 차량 / 위탁 / 가상 |
| 표시 순서 | number | 0 이상 | 사이드바 / 드롭다운 정렬 기준 |
| 주소 | text | 최대 255자 | 빈 값 허용 (null 저장) |
| 설명 | textarea | 최대 500자 | 빈 값 허용 (null 저장) |

> **코드(code)는 편집 불가**입니다. 코드 변경이 필요한 경우 별도 마이그레이션 절차를 거쳐야 합니다.

---

## 4. 동작 흐름

1. **편집** 버튼 클릭 → 모달 열림 (기존 값 채워짐)
2. 필드 수정 → **저장** 클릭
3. 변경된 필드만 `PATCH /inventory/warehouses/{id}` 로 전송
4. 응답 성공 시 모달 닫힘 + 목록 즉시 invalidate (Tanstack Query)
5. 응답 실패 시 모달 하단에 빨간색 에러 메시지 표시 (모달 유지)

변경 없이 저장 시: API 호출 없이 모달만 닫힘.

---

## 5. 권한

backend `@PreAuthorize("@hr.isExecutiveOffice() and hasAnyRole('MASTER','MANAGER','DEVELOPER')")` 가드:

- 대표실 소속이면서
- MASTER / MANAGER / DEVELOPER 중 하나의 역할

권한 미달 시 403 응답 → 모달 에러 영역에 "권한 없음" 표시.

---

## 6. 실시간 갱신

- 목록 화면은 **30초 polling** 으로 다른 사용자의 변경을 자동 반영
- 본인의 편집은 저장 즉시 invalidate 로 반영 (polling 대기 불필요)

---

## 7. 창고 코드 자동 부여 (1a — 진행 완료)

신규 창고 등록 모달은 **코드 입력 필드를 노출하지 않는다**. 등록 시 backend 가 자동으로 `WH-XXXXXX` 패턴(0/1/O/I/L 제외 6자 alphanumeric)을 생성하여 부여한다.

| 항목 | 값 |
|---|---|
| 형식 | `WH-` prefix + 6자 (예: `WH-7K2P9X`) |
| Charset | `23456789ABCDEFGHJKMNPQRSTUVWXYZ` (헷갈리는 글자 제외) |
| 충돌 검증 | `existsByCodeAndIsDeletedFalse` |
| 재시도 한도 | 5회 (CHARSET^6 ≈ 7.3억 → 5회 안에 거의 확정) |
| 재시도 초과 | INTERNAL_ERROR (사실상 발생 X) |

**Legacy 호환**: API 측 `CreateWarehouseRequest.code` 는 optional. 명시적으로 채워서 보내면 그 값을 사용 (마이그레이션/시드 시 활용). 데스크탑 UI 는 입력 필드 제거 → 항상 자동 생성 경로.

**관련 코드:**
- Backend: [`WarehouseService.create` / `generateUniqueCode`](../../../services/inventory-service/src/main/java/com/samhanair/logis/inventory/service/WarehouseService.java)
- Frontend: [`WarehousesPage.CreateWarehouseModal`](../../../clients/desktop/src/renderer/routes/WarehousesPage.tsx) — 코드 입력 필드 → "자동 부여 안내 banner" 로 교체

## 8. 창고 비활성화 (soft-delete)

`/admin/warehouses` 화면 각 row 의 **비활성화** 버튼(`data-testid=admin-warehouses-delete-{code}`) 클릭 → 확인 모달 → 확정 시 `DELETE /inventory/warehouses/{id}` 호출.

| 항목 | 동작 |
|---|---|
| Backend | `WarehouseService.delete` 가 `is_deleted=true` 마킹 (BaseEntity.markDeleted) |
| 데이터 영향 | 실제 row 보존 — `@SQLRestriction("is_deleted = false")` 가드로 활성 목록에서만 자동 제외 |
| UI 영향 | 활성 창고 목록 / 사이드바 / 드롭다운에서 즉시 제외 (Tanstack Query invalidate 2종) |
| 기존 전표/이동 이력 | 영향 없음 (UUID 참조 보존) |
| 복구 | UI 미노출 — backend 데이터 직접 수정 또는 별도 마이그레이션 필요 |
| 권한 | `MASTER / MANAGER / DEVELOPER` (backend `@PreAuthorize` 가드) |

확인 모달 노출 항목 3가지: 활성 목록 제외 / 데이터 보존 / 복구 경로 — 사용자가 의도치 않은 클릭을 방지.

---

## 9. 변경 이력 (audit log)

각 창고의 모든 PATCH / soft-delete 변경은 `InventoryAuditLogRecorder` (PR-H4b 인프라) 가 자동으로 audit overlay 1행 INSERT + SSE broadcast 한다.

| 항목 | 동작 |
|---|---|
| Backend | `WarehouseService.update / delete` 가 변경된 필드별 `ChangeEntry` 수집 → `recordBatch(warehouseId, actorId, actorName, changes)` 호출 |
| Actor 결정 | `X-User-Id` 헤더 (UUID) → actorId. 미공급/형식 오류 시 system sentinel (`00000000-0000-0000-0000-000000000000`) |
| revision_no 채번 | `countByEntityId + 1` 단조 증가 (Slip / DcConfig 패턴과 동일) |
| 다중 필드 | 같은 mutation 의 N개 필드 변경은 **같은 revisionNo 공유** |
| 실패 정책 | audit 실패 시 graceful fallback (도메인 진행). WARN 로그만 |
| 조회 endpoint | `GET /inventory/warehouses/{id}/audit-logs` — 모든 인증 사용자 |
| UI | EditWarehouseModal 하단의 **▸ 변경 이력 보기** 토글 (lazy fetch, `data-testid=edit-warehouse-audit-toggle`) |
| Timeline | revision 별 그룹 + 필드별 row (필드명 한국어 라벨, 이전값 strikethrough → 새값) |

### 추적되는 필드

`name`, `type`, `address`, `displayOrder`, `description`, `isDeleted` (soft-delete 도 audit 1행).

> Slip / DcConfig 의 audit overlay 와 동일한 인프라 — SSE 이벤트 `inventory:edit` 로 실시간 협업 가능 (구독 코드 추가 시).
