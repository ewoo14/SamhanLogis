# 08. 거래처 DC 설정

> **Stage**: 4b ✅ — 데스크탑 영업 → "거래처 DC 설정" 화면(`/sales/partner-dc-config`)의 backend endpoint GET + PATCH 모두 활성화 완료.

---

## 1. 개요

거래처별로 적용되는 11종 DC율 + 1종 특이사항을 행 단위로 조회. 본 매뉴얼은 데스크탑 영업 화면 사용 + backend API 명세.

접근 경로: 데스크탑 → 사이드바 "영업" 그룹 → "거래처 DC 설정" (sub-nav)

---

## 3. Backend endpoint

| 메서드 | 경로 | 상태 |
|---|---|---|
| GET | `/api/v1/partner-dc-configs?page=&size=&keyword=` | ✅ 활성 |
| PATCH | `/api/v1/partner-dc-configs/{partnerCode}` | ✅ 활성 — 4b 완료 |

GET keyword 는 `partner.name` 또는 `partner.partner_code` 부분 일치 (대소문자 무시). pagination 은 Spring Data `Pageable` 그대로.

backend 위치: **dc-config-service** ([PartnerDcConfigsController.java](../../../services/dc-config-service/src/main/java/com/samhanair/logis/dcconfig/web/PartnerDcConfigsController.java))

내부 BigDecimal (0~1 비율, 원 단위) ↔ 외부 표시 문자열 (`%`, `₩`, `Yes/No`) 변환:
- **응답 (GET)**: `PartnerDcConfigResponse.from()`
- **요청 (PATCH)**: `DcConfigService.updatePartnerDcConfig()` 내 `parsePercent / parseWon / parseYesNo` 헬퍼

### PATCH 시맨틱

| 입력 | 동작 |
|---|---|
| 필드 = `null` | no-op (변경 없음) |
| 필드 = `""` | remark 만 null clear, 그 외는 no-op |
| 필드 = `"—"` | no-op |
| 필드 = `"46%"` | `0.46` BigDecimal 로 저장 |
| 필드 = `"₩70,000"` / `"70000"` | `70000` BigDecimal 로 저장 |
| 필드 = `"Yes"` / `"No"` (case-insensitive) | Boolean 토글 |
| 필드 = `"abc"` (잘못된 형식) | 400 BAD_REQUEST + 메시지 |
| Partner 미존재 | 404 NOT_FOUND |
| DC config 미설정 거래처 | 자동 생성 후 적용 (source=`ADMIN_EDIT`) |

회귀 테스트: [`DcConfigServiceUpdateTest`](../../../services/dc-config-service/src/test/java/com/samhanair/logis/dcconfig/service/DcConfigServiceUpdateTest.java) (8건).

## 4. DC 노출 5겹 가드 — 외부 endpoint 추가 영향

본 endpoint 는 `/api/v1/...` 외부 path 라서 gateway 가 일반 사용자에게 라우팅한다. 기존의 가드 구조는 그대로 유지:

| 가드 | 위치 | 본 endpoint 영향 |
|---|---|---|
| 1. partner-public 응답 DTO 분리 | `PartnerPublicResponse` (DC 미포함) | 영향 없음 — 본 endpoint 는 영업자(내부) 용도 |
| 2. DcConfig.*Rate / *Amount → 응답 DTO 분리 | `DcConfigResponse` (internal) vs `PartnerDcConfigResponse` (external) | 본 PR — 영업자 화면 용 DTO 신규 추가 |
| 3. Gateway 의 `/internal/**` 외부 라우팅 차단 | api-gateway | 영향 없음 — `/api/v1/...` 별도 라우트 |
| 4. X-Internal-Token 인증 | `InternalTokenFilter` | 본 endpoint 는 일반 사용자(영업) 인증 |
| 5. X-User-Id audit logging | (도메인별 audit log) | 다음 PR 에서 dc-config-service audit log 통합 |

→ 5겹 가드의 본질(거래처 자가 화면에는 DC 미노출)은 보존된다.

## 5. PATCH 인라인 편집 (Backlog)

frontend 의 인라인 편집(셀 더블클릭 → 저장)은 본 PR 에 미포함. PATCH 호출 시 501 응답.

다음 PR 예정 작업:
- 외부 형식(`"46%"`, `"₩70,000"`, `"Yes"/"No"`) ↔ 내부 BigDecimal/Boolean 역변환 유틸
- DcConfigEditRequest 발동 — 변경 이력 audit
- 권한 검증 (MASTER / MANAGER / DEVELOPER)

운영 우회: `internal/partner-dc-configs/{partnerCode}` (internal 경로) 활용 또는 dc-config-service 의 admin import 흐름 (`/admin/dc-configs/import`) 활용 가능.
