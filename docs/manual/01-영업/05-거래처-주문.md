# 05. 거래처 주문 자동 변환

> **Stage 안내**: Stage 2 ✅ (정식 본문) — Phase 12 step-6 본 PR 에서 7-section 패턴으로 재작성.

---

## 1. 구현 상태

| 항목 | 상태 | 비고 |
| --- | --- | --- |
| 거래처 주문 등록 | ✅ 운영 | partner-order-service `/api/v1/partner-orders/**` |
| draft → confirm → slip 자동 발행 | ✅ 운영 | idempotency 보장 |
| 거래처 자가 등록 PWA | ⏳ 부분 | 일부 라우트만 |
| 영업 직원 native 앱 (모바일 주문) | ✅ 운영 (P1-4) | Expo EAS Build 정식 배포 (PR #144) |
| 거래처 등록 4 탭 (선행) | ✅ 운영 (P0-6) | 정식 운영 중 (PR #141 P0-6 머지) |
| 장바구니 / 즐겨찾기 / 결제 PG | ⛔ 미구현 | 장기 backlog |

(주)삼한공조시스템 거래처 주문은 거래처가 직접 또는 영업 직원이 대리 등록한 주문을 자동으로 전표으로 변환하는 기능입니다.

## 2. 대상 독자

- 거래처 측 발주 담당자 (PWA 운영 중)
- 거래처 주문을 대리 등록하는 영업 직원 (SALES)
- 주문 → 전표 변환 흐름을 검토하는 영업 부장 (MANAGER)

## 3. 학습 내용

- 거래처 주문 신규 등록
- draft → confirm 단계 분리 의미
- 자동 전표 발행 흐름
- idempotency-key 의 역할
- 주문 source 필터 사용

## 4. 본문

### 4-1. 거래처 주문 list 진입

좌측 사이드바 **[영업]** > **[거래처 주문]** 클릭.

### 4-2. 신규 주문 등록 (draft)

list 상단 **[신규 등록]** 클릭.

| 필드 | 필수 | 설명 |
| --- | :-: | --- |
| 거래처 | ✅ | 검색 후 선택 |
| 희망 납기일 | ✅ | YYYY-MM-DD |
| 출고 창고 | — | 자동 결정 가능 |
| 라인 (품목/수량/단가) | ✅ | 다중 입력 |
| 비고 | — | |

[임시저장] → status: DRAFT.

### 4-3. confirm (확정)

거래처 / 영업 직원이 주문 내용을 검토 후 [확정] 클릭. status: DRAFT → CONFIRMED. 자동으로 전표 발행 트리거.

### 4-4. 자동 전표 발행

CONFIRMED 시 partner-order-service 가 slip-service 로 전표 등록 API 호출. 전표이 자동 생성되며, 주문 list 에 전표번호가 표시됩니다.

- 주문 1건 → 전표 1건 매핑
- 전표 status: DRAFT (영업 부장 결재 대기)
- 이후 흐름은 [03. 전표 발행](03-전표-발행.md) 동일

### 4-5. idempotency-key

동일 주문이 중복 발행되지 않도록 backend 에서 idempotency-key 로 보호합니다.

- 동일 거래처 + 동일 희망 납기일 + 동일 라인 조합 시 동일 key
- 중복 클릭 시 첫 번째 전표만 발행되고 두 번째는 기존 전표번호 회신
- key UI 노출은 미구현 (장기 backlog)

### 4-6. 주문 source 필터

list 상단 필터에서 주문 source 별 조회 가능.

- 거래처 PWA 자가 등록
- 영업 직원 대리 등록
- 카카오톡 자동 파싱 (P1-5 운영 중, PR #145 — [05-arologis / 01. 카카오톡 배차](../05-arologis/01-카카오톡-배차.md) 참조)
- vendor 업로드 (Excel 일괄)

### 4-7. 영업 직원 native 모바일 (P1-4 ✅)

영업 직원이 외근 중 모바일에서 주문을 직접 등록하는 native 앱은 P1-4 에서 Expo EAS Build 정식 배포되었습니다 (PR #144). [04-모바일 / 03. 영업 앱](../04-모바일/03-영업-앱.md) 을 참조하세요.

### 4-8. Stage 4 실시간 협업

거래처 주문 list / 상세 화면에 [수정 횟수 chip](../08-실시간-협업/03-수정-횟수-카운트.md) + [audit overlay](../08-실시간-협업/02-수정-이력-보기.md) 표시. 거래처가 자가 등록 후 수정하면 영업 직원 화면에 1초 이내 반영됩니다.

## 6. FAQ

**Q1. 거래처가 직접 PWA 로 주문할 수 있나요?**
A. 일부 라우트는 운영 중. 거래처 자가 등록(P0-6)은 정식 운영 중 (PR #141). 신규 거래처는 영업 직원이 4탭 UI 로 먼저 등록 후 PWA 주문 진행하세요.

**Q2. 같은 주문을 두 번 클릭해도 되나요?**
A. idempotency-key 보호로 첫 번째만 전표 발행. 두 번째는 기존 전표번호 회신. 안전합니다.

**Q3. 주문을 전표으로 변환 안 하고 취소하려면?**
A. CONFIRMED 전 (DRAFT 상태) 에서 [취소] 가능. CONFIRMED 후는 전표을 별도 [취소] 처리해야 합니다.

**Q4. Excel 일괄 업로드는 어디서?**
A. list 상단 **[Excel 업로드]** 클릭. 양식 다운로드 → 데이터 입력 → 업로드. vendor 측 외부 시스템 통합 시 활용.

**Q5. 카카오톡 주문 자동 파싱은?**
A. P1-5 운영 중 (PR #145 ✅). `/arologis/admin/auto-dispatch` 에서 메시지 붙여넣기 후 자동 파싱. [05-arologis / 01. 카카오톡 배차](../05-arologis/01-카카오톡-배차.md) 참조.

**Q6. 주문번호 형식?**
A. `PO-2026-0001` 형태. UUID 는 사용자에게 노출되지 않습니다.
