## 2. 대상 독자

- 잠금 해제 권한자 (MASTER/MANAGER)
- 잠금 정책을 인수인계 받는 신규 IT 관리자

## 3. 학습 내용

- 4단계 잠금 임계 (0 / 1 / 2 / 영구)
- 잠금 자동 / 수동 발생 시점
- 잠금 해제 권한 매트릭스
- 잠금 banner 색상 의미

---

## 4. 본문

### 4-1. 4단계 잠금 임계

| 단계 | 발생 조건 | 해제 권한 | banner 색상 |
| --- | --- | --- | --- |
| **0 (없음)** | 변경 0회 | — | 없음 |
| **1 (소프트)** | 다른 직원이 편집 중 (자동) | 본인 종료 시 자동 | 노랑 |
| **2 (하드)** | 결재 / POSTED / DELIVERED 등 status 변경 | 권한자 (MANAGER+) | 주황 |
| **영구** | CLOSED / 마감 / 외부 감사 후 | MASTER only | 빨강 |

### 4-2. 잠금 자동 발생

- 다른 직원 편집 (1 단계) — 자동
- 결재 / POSTED 전환 (2 단계) — 자동
- 마감 / CLOSED (영구) — 자동

### 4-3. 잠금 수동 발생

- 외부 감사 시 회계 부장이 강제 영구 잠금 (MASTER 협의)
- 분쟁 발생 데이터 동결 (MASTER)

### 4-4. 잠금 해제 권한

| 단계 | 해제 권한 |
| --- | --- |
| 1 (소프트) | 편집 중인 직원이 종료 또는 30분 자동 |
| 2 (하드) | MANAGER 이상 |
| 영구 | MASTER only |

### 4-5. Banner 노출 위치 + 색상

| 색상 | 의미 |
| --- | --- |
| **노랑 banner** | 1 단계 — 다른 직원 편집 중 |
| **주황 banner** | 2 단계 — 결재/POSTED — 권한자 해제 필요 |
| **빨강 banner** | 영구 — MASTER 만 해제 |

화면 상단 fixed 위치. 항상 노출.

### 4-6. 수정 요청 흐름

잠금 banner 우측 [수정 요청] 클릭 → [05. 수정 요청 워크플로우](05-수정-요청-워크플로우.md).

### 4-7. 잠금 우회 절대 금지

backend 가 강제 검증. 우회 시도 시 거부 + IT 관리자 알림. MASTER 임의 강제 해제 시 audit history 영구 기록.

## 6. FAQ

**Q1. 본인이 편집 중인데 banner 가 떠요.**
A. 다른 탭/창에서 본인이 같은 데이터 열었을 가능. 다른 탭 닫기.

**Q2. 30분 자동 해제는?**
A. 1 단계 (소프트) 만 자동. 2 / 영구는 권한자 수동.

**Q3. MASTER 가 영구 잠금을 해제하면?**
A. audit history 에 영구 기록 + 외부 감사 시 추적. 신중 처리.

**Q4. 잠금 우회 가능?**
A. 불가. backend 강제 검증. 시도 시 IT 관리자 알림.

**Q5. 결재 후 자동 잠금되면 어떻게 수정?**
A. [수정 요청 워크플로우](05-수정-요청-워크플로우.md) 사용. 영업 부장 수락 후 수정.

**Q6. 모바일에서도 잠금 banner?**
A. 동일. mobile-staff 화면 상단.
