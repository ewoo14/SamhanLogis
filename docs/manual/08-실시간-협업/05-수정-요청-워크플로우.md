# 05. 수정 요청 워크플로우

> **Stage 안내**: Stage 4 ✅ — Phase 12 step-6 본 PR 에서 7-section 패턴으로 재작성.

---

## 1. 구현 상태

| 항목 | 상태 | 비고 |
| --- | --- | --- |
| `SlipEditRequestDialog` (PR-H3) | ✅ | |
| 잠금 정책 + SSE 알림 5채널 | ✅ | PR-H3 |
| 13 service 일괄 (PR-H4b/4c) | ✅ | |
| 알림 5채널 | ✅ | 요청 / 수락 / 거절 / 만료 / 삭제 |

(주)삼한공조시스템 다른 직원이 잠금한 데이터를 수정해야 할 때 사용하는 표준 워크플로우입니다.

---

## 2. 대상 독자

- 다른 직원의 잠금 데이터를 수정하려는 모든 ROLE
- 수정 요청을 받아 수락/거절하는 잠금 해제 권한자 (MASTER/MANAGER)
- 수정 요청 흐름을 인수인계 받는 신규 IT 관리자

---

## 3. 학습 내용

- 잠금 banner 인지
- 수정 요청 dialog 진입
- 사유 입력 + 요청 발송
- 수락 / 거절 / 만료 / 삭제 5채널 알림

---

## 4. 본문

### 4-1. 잠금 banner 인지

다른 직원이 데이터 편집 중일 때 화면 상단에 빨간/노란 banner.

> "이 전표은 김미선 님이 편집 중입니다. 수정하려면 [수정 요청] 클릭."

자세한 잠금 4단계는 [06. 잠금 정책](06-잠금-정책.md) 참조.

### 4-2. 수정 요청 진입

#### 단계 1 — [수정 요청] 클릭

banner 우측 [수정 요청] 버튼 클릭.

#### 단계 2 — 사유 입력 dialog

`SlipEditRequestDialog` 표시.

- 사유: 필수 (자유 입력)
- 변경 의도 항목 (선택)
- 긴급도 (낮음 / 보통 / 높음)
- [요청] / [취소]

#### 단계 3 — 요청 발송

[요청] 클릭 시.

- 잠금 해제 권한자 (MASTER + MANAGER) 에게 SSE 알림
- 요청자 화면: 대기 status 표시
- 요청자 본인은 잠금 해제까지 편집 불가

### 4-3. 수락 / 거절

잠금 해제 권한자 화면.

#### 알림 수신

헤더 종 아이콘 배지 + 토스트.

> "[수정 요청] 박철수 님이 SLIP-2026-0001 수정을 요청합니다. 사유: 단가 보정"

#### 수락

[수락] 클릭.

- 잠금 해제
- 요청자 알림 + 잠금 해제 → 요청자 편집 가능
- audit history 에 "[수정 요청 수락] 김미선 → 박철수" 기록

#### 거절

[거절] + 사유 입력.

- 잠금 유지
- 요청자 알림 + 거절 사유 표시

### 4-4. 5채널 SSE 알림

| 채널 | 발신 시점 | 수신자 |
| --- | --- | --- |
| 요청 | 요청 시 | 잠금 해제 권한자 |
| 수락 | 수락 시 | 요청자 |
| 거절 | 거절 시 | 요청자 |
| 만료 | 30분 무응답 | 요청자 + 권한자 |
| 삭제 | 요청자 취소 | 권한자 |

### 4-5. 만료 / 취소

#### 30분 무응답 시 만료

- 요청 자동 삭제
- 양측 알림

#### 요청자 취소

- 요청 dialog 에서 [취소]
- 잠금 해제 권한자 알림

### 4-6. 적용 service

audit 13 service 모두. 전표 / 거래처 / 재고 / 세금계산서 / 배차 / 사용자 등 ([09. 적용 범위](09-적용-범위.md)).

## 6. FAQ

**Q1. 사유 입력이 필수인가요?**
A. 네. 외부 감사 추적용. 빈 사유는 거부.

**Q2. 수락된 후 잠금이 즉시 해제되나요?**
A. 네. SSE 1초 이내 요청자 화면 갱신. 즉시 편집 가능.

**Q3. 권한자가 자리 비웠을 때?**
A. 30분 후 자동 만료. 다른 권한자에게 재요청.

**Q4. 같은 데이터에 다수 요청 가능?**
A. 1건만 가능. 기존 요청 만료/처리 후 신규.

**Q5. 본인이 잠금한 데이터 수정 요청 받을 수 있나요?**
A. 권한자 본인이 잠금한 경우 본인이 [잠금 해제] 직접 가능. 요청 불필요.

**Q6. 모바일에서?**
A. 가능. mobile-staff 에서 동일 dialog. [08. 모바일 실시간 알림](08-모바일-실시간-알림.md).
