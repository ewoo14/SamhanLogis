## 4. 본문

### 4-1. SSE 동작 원리

본인이 desktop 화면을 열어두면 backend 가 SSE 연결을 자동 생성하여 변경 사항을 push.

- 연결 유지: 헤더 또는 페이지 측 indicator (있는 경우 녹색 / 빨간 dot)
- 변경 감지: 다른 직원이 같은 데이터 수정 시 1초 이내 push
- 본인 화면: 자동 갱신 + 토스트 알림

### 4-2. 토스트 알림 형식

화면 우측 상단에 4 ~ 6초간 토스트 표시.

```
[수정 알림] 김미선 님이 전표 SLIP-2026-0001 의 라인 1 수량을 5 → 8 로 변경하였습니다.
```

- 수정자 풀네임 (UUID 비공개)
- 변경 항목 (필드명)
- 이전 값 → 새 값
- 전표번호 / 비즈니스 식별자 (UUID 비공개)

### 4-3. 자동 갱신 vs 수동 새로고침

자동 갱신은 SSE 가 push 한 변경만 적용. 광범위 변경 (예: 1000건 일괄 import) 또는 SSE 끊김 시 수동 새로고침 (F5).

### 4-4. SSE 연결 끊김

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| 토스트가 안 옴 | SSE 연결 끊김 | 새로고침 (F5) |
| indicator 빨간 dot | 서버 측 push 중단 | 재로그인 |
| 다른 직원 변경 미반영 | 새로고침 필요 | F5 |
| 30분 지나면 끊김 | 세션 만료 | 재로그인 |

## 6. FAQ

**Q1. SSE 가 무엇인가요?**
A. Server-Sent Events. 서버가 클라이언트에게 단방향 push. WebSocket 보다 가벼움.

**Q2. 토스트가 너무 자주 떠요.**
A. 본인이 보고 있는 화면 관련만 토스트 표시. 다른 화면 변경은 미표시.

**Q3. 토스트를 끌 수 있나요?**
A. 미구현. 사용자 설정 장기 backlog.

**Q4. 1초 이내가 정확히?**
A. 평균 200ms ~ 500ms. 네트워크 지연 시 1초 이내.

**Q5. 인터넷 끊긴 상태에서 변경?**
A. 본인 측 미적용. 재연결 시 새로고침으로 최신 동기화.

**Q6. 변경 알림이 누구에게?**
A. 같은 데이터 (예: 같은 전표) 를 보고 있는 모든 직원. 데이터 단위.
