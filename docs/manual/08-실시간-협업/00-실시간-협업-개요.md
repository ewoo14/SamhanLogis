## 4. 본문

### 4-1. 5종 패턴 한눈에

| # | 패턴 | 시각 표시 | 진입 매뉴얼 |
| --- | --- | --- | --- |
| 1 | **실시간 동기화** (SSE) | 토스트 + 자동 갱신 | [01. 실시간 동기화](01-실시간-동기화.md) |
| 2 | **수정 이력 보기** (audit overlay) | 호버 popover (취소선 + 풀네임 + 색상 dot) | [02. 수정 이력 보기](02-수정-이력-보기.md) |
| 3 | **수정 횟수 카운트** (chip) | 0=회색 / 1~4=파랑 / 5~9=주황 / 10+=빨강 | [03. 수정 횟수 카운트](03-수정-횟수-카운트.md) |
| 4 | **수정 복원** (revert) | 드롭다운 → 이전 값 복구 | [04. 수정 복원](04-수정-복원.md) |
| 5 | **잠금 + 수정 요청** | 잠금 banner + 요청 dialog | [05. 수정 요청 워크플로우](05-수정-요청-워크플로우.md) + [06. 잠금 정책](06-잠금-정책.md) |

### 4-2. Phase 12 시리즈 흐름

```
PR-H1 (SSE infra)
  ↓
PR-H2 (audit overlay + 수정 횟수 + 복원)
  ↓
PR-H3 (수정 요청 + 잠금 정책 + 창고 수락)
  ↓
PR-H4a (shared-realtime module 추출)
  ↓
PR-H4b (BE 13 service 일괄 적용)
  ↓
PR-H4c (FE 50+ desktop page + mobile-staff 일괄)
  ↓
[Phase 12 종결]
```

### 4-3. 적용 범위

자세한 매트릭스는 [09. 적용 범위](09-적용-범위.md) 참조.

| 영역 | 적용 |
| --- | --- |
| BE 17 service 중 audit 대상 | 13 service ✅ |
| FE desktop page | 50+ ✅ |
| FE mobile-staff | ✅ (driver mode) |
| 적용 안 됨 | 회계 보고서 (read-only), legacy v2 WebView |

### 4-4. 운영자가 인지할 변화

Phase 12 적용 전 ↔ 후 비교.

| 항목 | 적용 전 | 적용 후 |
| --- | --- | --- |
| 다른 직원 변경 | F5 새로고침 필요 | 1초 이내 자동 갱신 |
| 수정 이력 | DB 직접 조회 | 호버 popover |
| 수정 횟수 | 미표시 | chip 색상 |
| 복원 | 불가 | 드롭다운 (MASTER/MANAGER) |
| 동시 편집 | 충돌 | 잠금 banner + 요청 |

### 4-5. 모든 ROLE 1회 통독 권장 이유

본 카테고리는 ROLE 별 차이가 작고, 모든 화면 공통 노출되므로 1회 통독으로 평생 사용 가능합니다.

## 6. FAQ

**Q1. 5종 패턴이 헷갈려요.**
A. 5종 모두 1번 [01. 실시간 동기화](01-실시간-동기화.md) → 2번 [02. 수정 이력 보기](02-수정-이력-보기.md) 순서로 학습 권장.

**Q2. 모든 화면에 적용되나요?**
A. audit 대상 13 service 의 50+ page + mobile-staff. 회계 보고서 (read-only) / legacy v2 WebView 는 미적용. [09. 적용 범위](09-적용-범위.md).

**Q3. 다른 직원 변경이 안 보이면?**
A. SSE 연결 확인 → 새로고침 → 재로그인. [01. 실시간 동기화](01-실시간-동기화.md) 트러블슈팅.

**Q4. 잠금 banner 가 떴어요.**
A. 다른 직원이 편집 중. [수정 요청](05-수정-요청-워크플로우.md) 흐름 사용.

**Q5. 모바일에서도?**
A. mobile-staff 푸시 + 토스트로 동일 적용. [08. 모바일 실시간 알림](08-모바일-실시간-알림.md).
