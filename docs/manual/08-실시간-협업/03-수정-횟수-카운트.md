# 03. 수정 횟수 카운트 (Revision Chip)

> **Stage 안내**: Stage 4 ✅ — Phase 12 step-6 본 PR 에서 7-section 패턴으로 재작성.

---

## 1. 구현 상태

| 항목 | 상태 | 비고 |
| --- | --- | --- |
| Revision chip | ✅ | PR-H2 |
| 4단계 색상 임계 | ✅ | 0/1~4/5~9/10+ |
| 50+ page + mobile-staff | ✅ | PR-H4c |
| 클릭 시 audit overlay 자동 표시 | ✅ | |

(주)삼한공조시스템 모든 화면에서 데이터 옆에 수정 횟수를 색상 chip 으로 표시합니다.

---

## 2. 대상 독자

- 변경이 잦은 전표 / 분개를 모니터링하는 모든 ROLE
- 외부 감사 / 외주 회계 — 변경 회수 검토
- 영업 부장 — 영업 직원의 잦은 전표 변경 감지

---

## 3. 학습 내용

- 4단계 색상 임계 (0 / 1~4 / 5~9 / 10+)
- chip 클릭 시 audit overlay 진입
- 색상 의미 + 운영 정책
- 영업 부장 / 회계 외부 감사 활용

---

## 4. 본문

### 4-1. 4단계 색상 임계

| 임계 | 색상 | 의미 |
| --- | --- | --- |
| 0 | 회색 | 변경 없음 (초안 / 신규) |
| 1 ~ 4 | 파랑 | 정상 변경 (조정) |
| 5 ~ 9 | 주황 | 잦은 변경 (검토 권장) |
| 10+ | 빨강 | 비정상적으로 많은 변경 (조사 필요) |

### 4-2. 표시 위치

데이터 옆 또는 위 — 작은 chip 형태.

```
SLIP-2026-0001  [3]   [DRAFT]
                ↑
              파랑 chip = 3회 변경
```

### 4-3. Chip 클릭 시 동작

chip 클릭 시 audit overlay popover 자동 표시 ([02. 수정 이력 보기](02-수정-이력-보기.md)).

### 4-4. 운영 정책

#### 영업 부장 / MANAGER

- 빨강 chip 전표 → 영업 직원 코칭 (단가 / 수량 잦은 변경 사유 확인)
- 주황 chip 전표 → 정기 회의 시 검토

#### 회계 / 외주 회계

- 빨강 chip 분개 → 분개 사유 / 외부 감사 시 사전 점검
- 주황 chip 분개 → 결산 시 우선 검토

#### MASTER / IT 관리자

- 빨강 chip 거래처 / 사용자 → 보안 의심 (권한 변경 등) 즉시 점검

### 4-5. 모바일 표시

mobile-staff 에서도 동일 chip 표시. 다만 화면 좁아 약식 표시 가능.

## 6. FAQ

**Q1. 임계 기준 (5/10) 변경 가능?**
A. 미구현. 시스템 표준. 장기 backlog.

**Q2. chip 이 너무 많아 화면이 복잡해요.**
A. 회색 (0회) 은 약하게 표시. 빨강 / 주황만 시각 강조.

**Q3. chip 클릭 시 popover 가 안 떠요.**
A. audit overlay 가 적용 안 된 항목일 가능. [09. 적용 범위](09-적용-범위.md) 확인.

**Q4. 변경 횟수가 줄어들 수 있나요?**
A. 누적 only. 줄지 않음. 단, 데이터 삭제 (Soft Delete) 시 chip 표시 종료.

**Q5. 빨강 chip 처리 정책은?**
A. ROLE 별 다름. 4-4 운영 정책 참조.
