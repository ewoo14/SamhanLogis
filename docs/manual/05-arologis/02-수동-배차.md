## 3. 학습 내용

## 4. 본문

### 4-0. 지역 관리 메뉴

좌측 사이드바 **[arologis]** > **[지역 관리]** 클릭 → `/admin/regions` 진입 (DISPATCH/MANAGER/MASTER).
지역 마스터(지역 코드 / 배차 권역 / 우선순위)를 등록·수정합니다. 동일 화면은 **[관리자]** > **[지역 분류]** 에서도 접근 가능합니다.

### 4-1. 수동 배차 메뉴 진입

좌측 사이드바 **[arologis]** > **[배차 관리]** 클릭 → `/arologis/admin/manual-dispatch` 진입.

배차 일자 + 상태 필터로 배차 목록을 조회하고, 각 행의 **[기사 직접 선택]** 버튼으로 기사를 변경한다.

### 4-2. 신규 배차 등록

#### 4-2-1. 차량 선택

| 필드 | 필수 | 설명 |
| --- | :-: | --- |
| 차량 번호 | ✅ | 12가3456 |
| 차종 | ✅ | 1톤 / 2.5톤 / 11톤 등 |
| 운수사 | ✅ | 인성데이타 vendor 또는 자체 |

#### 4-2-2. 기사 배정

[03. 기사 배정](03-기사-배정.md) 흐름 참조. 자동 (Mock + Insung) 또는 수동.

#### 4-2-3. 정차 (VehicleStop) 등록

| 3 | 정차 2 | B거래처 |

### 4-3. 등록 + 알림

[등록] 클릭 시.

- 배차 status: PENDING → ASSIGNED
- 기사 mobile-staff 앱에 푸시 알림 ([08-실시간-협업 / 08. 모바일 실시간 알림](../08-실시간-협업/08-모바일-실시간-알림.md))
- 전표 status: PICKED → SHIPPING (해당 전표 자동 갱신)

### 4-4. 배차 list 조회

배차 list 화면에서 진행중 / 완료 / 취소 배차 확인.

- 차량 / 기사 / 정차 수 / 전표 수 / status
- 클릭 시 상세 진입

### 4-5. 인성데이타 vendor 협력

인성데이타 퀵프로그램과 데이터 동기화.

- DriverMatcher Insung 모드 사용
- backend 가 인성데이타 API 호출하여 차량/기사 정보 동기화
- 자세한 흐름은 [03. 기사 배정](03-기사-배정.md) 참조

### 4-6. Stage 4 실시간 협업

배차 list / 상세에 [수정 횟수 chip](../08-실시간-협업/03-수정-횟수-카운트.md) + [audit overlay](../08-실시간-협업/02-수정-이력-보기.md) 표시. 배차 변경 시 기사에게 실시간 푸시. 자세한 절차는 [08-실시간-협업 / 08. 모바일 실시간 알림](../08-실시간-협업/08-모바일-실시간-알림.md) 참조.

## 6. FAQ

**Q1. 정차 순서를 변경하려면?**
A. 배차 상세에서 정차 행 드래그 / 위/아래 화살표로 순서 변경 가능합니다 (P1-5 운영 중, PR #145 ✅).

**Q2. 같은 차량에 다수 전표 묶음 가능?**
A. 네. 단, 차량 적재 한도 / 정차 효율 검토 권장.

**Q3. 기사가 거부 시?**
A. 기사 mobile-staff 에서 [거부] + 사유 입력. 배차 담당이 알림 수신 후 다른 기사 재배정.

**Q4. 배차 취소 시 전표은?**
A. 전표 status: SHIPPING → PICKED 복구. 재고는 영향 없음.

**Q5. 인성데이타 차량/기사가 시스템에 없으면?**
A. IT 관리자가 backend 에 차량/기사 추가 등록 후 재시도.
