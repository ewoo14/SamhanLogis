## 4. 본문

### 4-1. 기사 list

좌측 사이드바 **[arologis]** > **[기사 배정]** 클릭 → `/arologis/admin/driver-assignment` 진입.

화면은 좌측 (가용 기사 list) + 우측 (미배정 배차 list) 2-panel 구조. 좌측에서 기사를 클릭하여 선택한 후, 우측 배차 항목의 [배정] 버튼을 눌러 배정한다.

기사 정보 구성.

| 필드 | 설명 |
| --- | --- |
| 기사명 | 풀네임 |
| 휴대전화 | 010-0000-0000 |
| 운수사 | 인성데이타 vendor 또는 자체 |
| 차량 (1대 또는 다수) | 12가3456 |
| 운행 region | 서울 / 경기 / 인천 등 |
| 활성 여부 | 휴직 / 퇴사 표시 |

### 4-2. autoMatch (자동 배정)

backend `autoMatch` API 가 다음 기준으로 자동 매칭.

1. 운행 region 일치
2. 차종 / 적재 한도 일치
3. 시간대 가용 (다른 배차 진행 여부)
4. DriverMatcher (Mock + Insung) 호출
5. 결과: 1명 또는 다수 후보

#### 정식 UI 운영 (P1-5)

1. **[자동 매칭]** (`/arologis/admin/auto-dispatch`) 에서 **[자동 매칭 실행]** 버튼 클릭
2. DriverMatcher 호출 후 매칭 결과 표 확인
3. 미매칭 건 → [배차 관리] 에서 수동 보정

### 4-3. assignDriverManual (수동 배정)

배차 담당이 직접 기사 선택.

1. 기사 list 에서 후보 기사 확인
2. backend `assignDriverManual` API (정식 UI 운영 중 — P1-5, PR #145)
3. 배차 status: PENDING → ASSIGNED
4. 기사 mobile-staff 푸시 알림 ([08-실시간-협업 / 08. 모바일 실시간 알림](../08-실시간-협업/08-모바일-실시간-알림.md))

#### 정식 UI 운영 (P1-5)

1. **[기사 배정]** (`/arologis/admin/driver-assignment`) 진입
2. 좌측 가용 기사 list 에서 기사 클릭 (선택 표시)
3. 우측 미배정 배차 항목의 **[{기사코드} 배정]** 버튼 클릭
4. 배차 status: PENDING → ASSIGNED, 기사 mobile-staff 푸시 알림 발송

### 4-4. 인성데이타 vendor Insung 모드

DriverMatcher Insung 모드.

- 인성데이타 퀵프로그램 API 호출
- 인성데이타 보유 차량/기사 풀에서 매칭
- 매칭 성공 시 인성데이타 측에도 동기화

### 4-5. 정식 UI 운영 (P1-5 완료)

본 docs 는 P1-5 PR 머지로 정식 본문으로 교체되었습니다.

**운영 중 기능:**
- 가용 기사 list + 미배정 배차 2-panel 배정 UI
- 기사 선택 → 배차 [배정] 버튼 1-click 배정
- 배정 즉시 기사 mobile-staff 푸시 알림
- 기사 현재 배차 건수 실시간 표시 (과부하 방지)
- 수동 배차 화면에서 기사 직접 선택 modal 지원

## 6. FAQ

**Q1. autoMatch 결과가 만족스럽지 않으면?**
A. assignDriverManual 로 수동 변경. 자동 결과는 추천일 뿐 강제 아님.

**Q2. 인성데이타 vendor 와 자체 운수사 동시 활용 가능?**
A. 네. DriverMatcher 가 양쪽 풀 모두 검토. 가용 우선 매칭.

**Q3. 기사 거부 시 자동 재배정?**
A. 정식 출시 후 가능. 현재는 배차 담당이 수동 재배정.

**Q4. 배정 시 기사 동의 없이 가능?**
A. backend assignDriverManual 은 강제 배정. 사후 기사 거부 시 [02. 수동 배차](02-수동-배차.md) 흐름 참조.

**Q5. 정식 UI 출시는 언제?**
A. P1-5 슬라이스로 출시 완료. `/arologis/admin/driver-assignment` 에서 바로 사용 가능.
