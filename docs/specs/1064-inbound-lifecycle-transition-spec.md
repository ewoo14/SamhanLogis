# #1064 입고 전표 lifecycle 버튼과 API 전이 역전 — 기획

> 작성 2026-08-05 (집PC PM) · 이슈 `#1064`

## 1. 무엇이 문제인가

입고 전표 상세의 **하단 "완료" 버튼이 부르는 API 와 백엔드가 요구하는 전이가 어긋나** 실 사용자가 GUI 만으로 입고를 끝낼 수 없다.

이슈 재현 원문:

```text
완료 (검수 시작) → /inspect   →  409  전이 가능한 상태가 아닙니다: 현재 처리중, 필요 검수중
완료 (처리 완료) → /complete  →  409  전이 가능한 상태가 아닙니다: 현재 검수중, 필요 처리중
```

입고가 막히면 재고가 생기지 않고, 재고가 없으면 출고 수락이 `409 재고 부족` 으로 막힌다. `#1057` 라이브QA 가 실제로 이 연쇄에 걸렸다.

## 2. 좌표 (PM 이 코드에서 확인)

| 층 | 위치 | 무엇 |
|---|---|---|
| FE | `clients/desktop/src/renderer/routes/SlipDetailPage.tsx:1882` | `actionsForStatus(slip.status, mode)` — 상태별 노출 액션 목록의 출처 |
| FE | 같은 파일 `:2059` | `possibleActions.find((a) => a !== 'reject' && a !== 'cancel')` — **"완료" 버튼이 부르는 액션은 이 목록의 첫 원소**다 |
| FE | 같은 파일 `:312` `ACTION_LABEL` · `:4361` | 버튼 라벨 `완료 (…)` 생성 |
| BE | `services/slip-service/src/main/java/com/samhanair/logis/slip/domain/Slip.java:1774` | 전이 거부 시 409 문구 |

⟹ 화면이 노출·선택하는 액션과 도메인이 허용하는 전이가 **입고(INBOUND) 경로에서 어긋나 있다.**

## 3. 불변식 — 무엇이 참이어야 하는가

1. **입고 전표를 GUI 만으로 끝까지 진행할 수 있다.** 수락 이후 완료까지 사용자가 버튼만 눌러 도달한다.
2. **버튼 라벨이 실제로 일어나는 일과 같다.** `완료 (검수 시작)` 을 눌렀는데 처리 완료가 일어나면 안 된다.
3. **화면이 노출하는 액션 ⊆ 도메인이 그 상태에서 허용하는 액션.** 어떤 상태에서도 화면이 부르는 전이가 409 가 되면 안 된다.
4. **출고(OUTBOUND) 경로가 회귀하면 안 된다.** 반려·취소 버튼을 포함해 지금 되는 것이 그대로 되어야 한다.
5. 권한이 없는 사용자에게 그 액션이 노출되지 않는다(현행 권한 게이트 유지).

## 4. 🚨 축을 하나만 주지 않는다

`#1057` R22 에서 *"상태 → 다음 전이"* 만 물었더니 **반려 버튼이 통째로 사라진 채** 통과한 전례가 있다. 이번에는 **두 축을 함께** 대조한다.

```
축 A   도메인이 각 상태에서 허용하는 액션 전부   (Slip.java 전이 규칙에서 뽑는다)
축 B   화면이 각 상태에서 노출하는 액션 전부     (actionsForStatus 에서 뽑는다)
```

**전표 유형(INBOUND / OUTBOUND) × 상태 전부**에 대해 A 와 B 를 표로 만들고 차이를 전수 열거한다. 차이가 0 이 되어야 한다.

## 5. 양방향 RED

- **RED-A (되돌리면 안 되는 것)** — 출고 전표의 기존 전이·반려·취소가 그대로 동작한다. 권한 없는 사용자에게 액션이 노출되지 않는다.
- **RED-B (재발하면 안 되는 것)** — 입고 전표에서 화면이 부른 전이가 409 가 되면 RED. 버튼 라벨과 실제 전이가 다르면 RED.
