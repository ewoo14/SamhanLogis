## 1. 8모드 실행 결과

PM이 제시한 사전 실측 기대값과 최초 실행 결과가 일치했다. `사전`은 화면 저장 전, `STACK 저장 후`는 위 전표를 실 사용자 화면에서 저장한 뒤의 결과다. REGION 저장 시도는 409로 거절되어 `현재 최종`은 STACK 저장 후와 같다.

| 모드 | 화면 명칭 | 모드 값 | 사전 | PM 예상 | STACK 저장 후 / 현재 최종 | 대조 |
|---:|---|---|---:|---:|---:|---|
| 1 | 상일+초월 (지방 제외) | `SANGIL_AND_CHOWOL_REGION_EXCLUDED` | 1 | 1 | 2 | PASS, 저장 전표 +1 |
| 2 | 초월 (지방 제외) | `CHOWOL_REGION_EXCLUDED` | 1 | 1 | 2 | PASS, 저장 전표 +1 |
| 3 | 상일 (지방 제외) | `SANGIL_REGION_EXCLUDED` | 1 | 1 | 2 | PASS, 저장 전표 +1 |
| 4 | 야적 only | `STACK_ONLY` | 0 | 0 | 1 | PASS, UI 저장 STACK 1건 |
| 5 | 지방 only | `REGION_ONLY` | 0 | 0 | 0 | REGION 저장 차단으로 양성 표본 없음 |
| 6 | 상일+초월 (지방 포함) | `SANGIL_AND_CHOWOL_REGION_INCLUDED` | 1 | 1 | 2 | PASS, 저장 전표 +1 |
| 7 | 초월 (지방 포함) | `CHOWOL_REGION_INCLUDED` | 1 | 1 | 2 | PASS, 저장 전표 +1 |
| 8 | 상일 (지방 포함) | `SANGIL_REGION_INCLUDED` | 1 | 1 | 2 | PASS, 저장 전표 +1 |

사전 8회와 STACK 저장 후 8회 모두 화면에서 시작일·종료일·실행 모드를 선택하고 `조회`를 눌렀다. 사전 mode 1 캡처에는 기존 `2026/08/04-4` 1건이, 저장 후 mode 1 캡처에는 `2026/08/05-1`과 기존 전표 2건이 보인다. 저장 후 mode 4에는 새 전표 1건만 보이고 mode 5는 0건이다.

## 2. 발화 조건을 실 사용자 화면에서 만들 수 있는가

### 출고창고 코드 `2` · STACK

판매 화면에서 다음 순서로 만들었다.

1. `판매 → 판매관리 → 신규 판매전표` 진입
2. 출고창고 검색에 `2` 입력
3. 화면 옵션 `2 상일물류` 선택. 입력값은 `2 · 상일물류`로 표시됨
4. 거래처 `한울냉열시스템`, 품목, 주소를 화면에서 선택·입력
5. 출고구분 `야적 (자동 메모)` 선택. 값은 `STACK`
6. `저장` 클릭

실 응답은 다음과 같다.

```text
POST http://localhost:8080/slips → 201 Created
slipNo=2026/08/05-1
status=DRAFT
deliveryTag=STACK
```

화면 저장 응답에는 raw `source_warehouse_code`가 노출되지 않고 `sourceWarehouseId`만 있었다. 이후 화면 재조회에서 `2026/08/05-1`이 나타났고, 읽기 전용 SQL로 다음을 확인했다.

```text
2026/08/03-1  source_warehouse_code='1'      delivery_tag=NULL
2026/08/05-1  source_warehouse_code='2'      delivery_tag='STACK'
```

따라서 출고창고 선택·저장으로 `source_warehouse_code='2'` 발화 조건을 실 화면에서 만들 수 있다. 저장 후 8모드 재실행에서 mode 4가 0→1, mode 1·2·3·6·7·8이 각각 1→2가 된 것이 화면 동작 근거다.

### 출고창고 코드 `00003` · REGION

화면에서 출고창고 검색 `00003` 후 `00003 · 삼성창고 (초월 무갑)`을 선택할 수 있었고, 출고구분 `지방 (자동 메모)`도 선택됐다. 그러나 저장 시 다음 실 응답으로 거절됐다.

```text
POST http://localhost:8080/slips → 409 Conflict
지방 당일 마감(12:00) 초과 — 익일 출고로 생성하세요
```

화면의 `출고일(상차일)`은 읽기 전용으로 2026-08-05에 고정되어 있었고, `하차일`만 2026-08-06으로 편집 가능했다. 현재 시각이 마감 이후이므로 UI에서 저장 가능한 익일 출고 전표를 만들지 못했다. 저장 실패 뒤 `source_warehouse_code='00003'` 및 `delivery_tag='REGION'` 전표는 생성되지 않았다.

판정: `2/STACK` 발화는 PASS. `00003/REGION`은 태그 선택까지 PASS, 저장·양성 mode 5 검증은 **BLOCKED**.

## 3. REGION 태그 화면 도달성

`신규 판매전표`의 출고구분 콤보에는 다음 항목이 실제로 있었다.

```text
지방 (자동 메모) → REGION
```

따라서 지방은 주소 접두가 아니라 태그로 화면에서 선택할 수 있다. 다만 이번 세션에서는 위의 지방 당일 마감 409 때문에 저장 표본을 만들 수 없었다.

현재 active 전표의 태그 읽기 결과는 다음과 같다. 빈 값은 NULL이다.

```text
NULL 115 · DAY 6 · STACK 2 · REGION 0
```

## 4. 주소 제외 규칙

읽기 전용 SQL로 active 전표의 `shipping_address`, `delivery_address`, `customer_address`, `inspection_address`, `supervision_address` 각각의 앞 10자를 검사했다.

```text
active_count=123
marker_prefix_count=0
```

`회수·회차·차용·대여·반납·자가` 중 하나가 주소 앞 10자 안에 있는 전표는 0건이었다. 따라서 이번 실 데이터에는 주소 제외 분기를 밟을 표본이 없었고, 화면에서 제외 결과를 확인할 수 없었다. 해당 문자열을 임의로 입력해 표본을 만들거나 DB를 직접 수정하지 않았다.
