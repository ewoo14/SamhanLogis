FROM accounts a JOIN account_page_permissions p ON p.account_id=a.id
WHERE p.page_code='notification.dispatch-sms.display' AND p.is_deleted=false

SELECT DISTINCT a.login_id, a.display_name
FROM accounts a JOIN account_groups ag ON ag.account_id=a.id AND ag.is_deleted=false

### 2. 로그인 규약

`services/auth-service/src/main/resources/db/migration/V48__seed_driver_staff_dispatch_dev_accounts.sql:10-14` 및 V5/V49 주석에 개발 시드 공통 비밀번호가 `${QA_DEV_DEFAULT_PASSWORD}`로 명시되어 있다. 이는 저장소상 시드 규약일 뿐 현재 DB의 로그인 성공을 보장하지 않는다. `janyeonggu`는 개발 시드가 아니며, R23에서 `${QA_DEV_DEFAULT_PASSWORD}` 로그인 시도 원문은 `아이디 또는 비밀번호가 올바르지 않습니다`였다. DB 비밀번호/권한 변경은 하지 않는다.

### 3. 로그인 시도 및 중단

- 시도 계정: `dev_manager`, `dev_dispatch`, `dev_accountant`, `janyeonggu`
- 시도 방법: 실제 UI 로그인 폼 및 게이트웨이 `POST /auth/admin/login`, 비밀번호는 저장소에 명시된 `${QA_DEV_DEFAULT_PASSWORD}`만 사용
- 현재 게이트웨이 응답: 네 계정 모두 HTTP `401 Unauthorized`
- UI에서 확인된 원문(R23 및 이번 동일 규약 시도): `아이디 또는 비밀번호가 올바르지 않습니다`
- 브라우저 스킬은 `No browser is available`로 연결 실패했고, 로컬 Playwright Chromium 직접 실행도 로그인 클릭 단계에서 120초 timeout되어 중단했다. 인증 HTTP 401은 별도로 확인했다.
- DB 비밀번호 변경, 권한 변경, 잠금 해제는 하지 않았다.

따라서 이번 R24에서 사용할 수 있는 로그인 성공 계정을 찾지 못했다. 사용자 지시대로 V93 GUI 진입/렌더/preview와 V92 차단 GUI 판정을 결함 없음으로 처리하지 않고 여기서 중단한다. 새 R24 GUI 캡처는 로그인 성공 화면이 없어 생성하지 않았다. R23의 기존 실 GUI 캡처는 이번 라운드 증거로 재사용하지 않는다.

### 4. R23 별건 — 2026-03-10 partner code 없는 전표

코드 판정: 현재 구현에서 연락처 입력 매칭은 의도적으로 `partnerCode`가 아니라 다음 두 기준이다.

- 입력의 `slipNo`가 전표번호와 정확히 일치
- 또는 입력의 `companyName`이 전표번호를 포함하거나 전표의 `partnerName`과 정확히 일치

근거: `services/notification-service/src/main/java/com/samhanair/logis/notification/service/DispatchBatchPreviewService.java`의 `resolveDriverPhone()`에서 `slipMatches || companyMatches`로 판단하며 `partnerCode`는 사용하지 않는다. 따라서 `partner code` 없는 `2026-03-10` 전표에 연락처를 입력한 뒤에도 fallback이 유지된 것은 **전표번호·업체명 기준 매칭을 의도한 현재 계약과 일치하는 결과**로 판정한다. 수정은 하지 않았다.
