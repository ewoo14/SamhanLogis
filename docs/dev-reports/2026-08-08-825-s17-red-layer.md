## §2. 단위 테스트와 Playwright의 차이

### 실제 부모 경로

- `clients/desktop/src/renderer/routes/SalesPartnerOrderListPage.tsx:640-645`
  - 실제 화면이 `<MergeConvertDialog />`를 렌더링한다.
- `clients/desktop/src/renderer/routes/components/MergeConvertDialog.tsx:704-717`
  - `MergeConvertDialog`가 `WarehouseAutocomplete`를 사용한다.
- `MergeConvertDialog.tsx:706-707`
  - `value={selectedWarehouse?.id ?? null}`인 controlled 입력이다.
  - `onChange={(_id, warehouse) => setSelectedWarehouse(warehouse)}`로 부모 상태를 갱신한다.

### 확정 후 값이 사라지는 데이터 흐름

- `WarehouseAutocomplete.tsx:278-283`
  - `pick()`은 부모 `onChange`를 호출하고 내부 `draft`에 선택 레이블을 쓴 뒤 dropdown을 닫는다.
- `WarehouseAutocomplete.tsx:402-407`
  - 모달 확정 callback은 `pick()` 후 `selectionOpen`을 닫는다.
- `Modal.tsx:104-131`
  - 모달 open 시 이전 active element를 저장하고, close cleanup에서 그 element에 `focus()`를 복원한다.
- `WarehouseAutocomplete.tsx:188-201`
  - 복원된 input focus가 `handleFocus()`를 다시 호출한다.
  - 기존 구현은 `preserveDraftOnNextFocusRef`가 false인 일반 focus로 판단해 `setDraft('')`, `setOpen(true)`를 수행했다.
- `WarehouseAutocomplete.tsx:297-298`, `317-343`
  - 결국 controlled 부모 선택 상태는 남아도 input 표시값은 빈 draft가 되고 기존 dropdown이 다시 열린다.

### 단위와 브라우저의 순서 차이

단위 테스트의 기존 흐름은 `WarehouseAutocomplete.test.tsx:80-109`, `111-138`처럼 컴포넌트와 실제 `Modal`을 렌더링하지만, 브라우저에서 발생하는 모달 close cleanup 이후 input focus 복원 순서를 결정적으로 재현하지 못했다. 따라서 확정 callback 직후의 `pick()` 상태까지만 관찰하고, 실제 브라우저의 `Modal` cleanup → input `onFocus` 재진입을 놓쳤다. 이 차이는 코드에서 확인되었고 추측이 아니다.
