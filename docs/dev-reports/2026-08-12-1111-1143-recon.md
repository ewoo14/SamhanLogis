## 2. #1093이 남긴 비중·반올림 데이터 모델과 현재 사용처

## 4. 견적품목에 남길 것과 뺄 것

### 현재 견적품목에서 세트에 대해 할 수 있는 일

모든 활성 BUNDLE 343건은 `usage_scope=BOTH`이고 견적 노출도 `SINGLE_SET 271 / COMMERCIAL_MULTI 72`로 잡혀 있다. 현재 `EstimateItemsCatalogPage`에서 세트 행도 일반 품목과 같은 다음 기능을 탄다.

1. 모델명/품목명 검색 (`EstimateItemsCatalogPage.tsx:1662-1673`)
2. 기초품목 검색 후 현재 견적 카테고리에 추가 (`:1718-1734`)
3. 분류 조회·설정 모달 (`:1498-1508`)
4. 견적 카테고리 추가/제거와 수량 동기화 규칙 편집 (`:1512-1527`, `:775-938`)
5. 견적/주문 노출 설정 (`:1530-1542`)
6. 상품/비상품 변경 (`:1544-1556`)
7. 변동DC 변경 (`:1558-1570`)
8. 고정DC%와 출처 변경 (`:1572-1584`)
9. 카테고리별 표시순서 변경 (`:1586-1597`, 저장 `:1427-1449`)
10. `세트 · 구성품수` 배지 조회 (`:1599-1614`)

현재 **할 수 없는 것**:

- 구성품 조회/추가/수정/삭제: 이미 제거됨
- 세트 대표 납품가 편집: 컬럼과 mutation이 없음
- 자동/고정·비중·반올림 편집: 데이터 모델 자체가 없음

`ProductCatalogRow.deliveryPrice`는 DTO에만 있다(`productCatalogApi.ts:102-105`). 테이블 columns `:1470-1616`에는 이를 렌더하는 열이 없다. 기초품목 상세에는 `ProductFormPage.tsx:836-844`의 `deliveryPrice` 입력이 있지만 라벨이 업무용어 `납품가`가 아니라 `배송가`다.

### 정정에 따라 남길 것

- BUNDLE 검색 및 기초품목에서 선택해 견적 카테고리에 노출
- 세트 **대표** `products.delivery_price` 조회·편집(현재 빠진 부분)
- 세트 여부/모델명/품목명 같은 식별 표시

### 정정에 따라 빼야 할 것

- 구성품 CRUD: **이미 빠졌으므로 추가 작업 0**
- 구성품별 자동/고정, 비중, 반올림 단위 편집: 견적품목에 새로 넣지 말고 기초품목 세트 상세에만 둔다
- 구성품별 납품가 편집 또는 구성 모달 진입: 현재 0건 상태를 유지한다

분류·노출·상품구분·DC·표시순서·수량 동기화는 세트 전용 구성 편집이 아니라 기존 견적 카탈로그 공통 기능이다. #1111/#1143 댓글은 이 공통 기능을 삭제하라고 결정하지 않았다. 이 트랙에서 함께 제거하면 범위 확장이므로 건드리지 않는다. “세트 검색·납품가만”은 **세트 구성/가격 내부 소관의 경계**로 적용하고, 공통 카탈로그 기능 삭제로 확대 해석하지 않는다.
