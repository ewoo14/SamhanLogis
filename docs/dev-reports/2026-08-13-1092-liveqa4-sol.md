## 실행 경계와 증거 무결성

인앱 Browser 런타임은 실제로 `[]`였으며 연결 복구 절차 후에도 동일했다. 지시대로 저장소의 Playwright Chromium을 사용했다. 현재 작업 트리 renderer와 공유 gateway·서비스의 실제 응답만 사용했고 fixture·mock·응답 대체는 사용하지 않았다.

로그인은 `last_login_at`을 갱신하므로 호출하지 않았다. 공유 환경의 JWT 서명 구성과 활성 MASTER 계정을 조회해 1시간짜리 로컬 QA 쿠키를 만들었다. 브라우저 route는 gateway의 `GET`/`HEAD`/`OPTIONS`만 허용하고 나머지는 전부 브라우저에서 중단했다. 최종 감사 세션에서 `POST /logs/front` 3회, 협업 presence join/leave 19회, 합계 22회를 차단했다. 저장·편집·발송·전표 변환·등록 버튼은 누르지 않았다.

DB 확인 SQL은 모두 `BEGIN TRANSACTION READ ONLY` 안에서 실행했다.

```text
공유 DB INSERT/UPDATE/DELETE/DDL: 0건
로그인 호출: 0회
저장 버튼 클릭: 0회
브라우저 gateway 비-GET 허용: 0건
```

## 도달 가능한 결함

### 1. 견적 상세의 협업 조회가 슬래시 문서번호에서 HTTP 400

세 번째 fix의 본문 상세 API는 하이픈 path id로 정상화됐지만, 같은 상세 화면이 자동 호출하는 협업 조회는 여전히 슬래시 문서번호를 `%2F`로 보낸다.

```text

GET /api/v1/slips/estimates/2026%2F08%2F10-9/collab/comments?limit=20 HTTP 400
GET /api/v1/slips/estimates/2026%2F08%2F10-9/collab/stream         HTTP 400

```

그 결과 본문 데이터는 열리지만 코멘트/협업 조회는 실제 사용자 상세 화면에서 실패한다. 같은 path 계약 경계의 한 결함으로 집계했다.
