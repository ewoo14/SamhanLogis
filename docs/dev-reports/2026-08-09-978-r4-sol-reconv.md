## 결함 1 — `nameDrift`가 품목 수를 520건 과대 계수한다

실 사용자 경로는 `MANAGER/MASTER → 설정 → 구글 시트 동기화 → 지금 동기화 → summary/log 확인`이다. `TabSyncResult.nameDrift` 주석은 “품목 수”라고 하지만 구현은 탭별 row occurrence마다 증가시키고 전체 summary에서 단순 합산한다. 같은 modelCode가 여러 탭에 있으면 한 품목을 반복 계수한다.

2026-08-09 08:12:58.420 KST에 Google Sheets API v4를 readonly로 읽고 같은 시각의 `product_db.products`와 readonly SQL CTE로 결합한 원문:

```text
GOOGLE_SHEETS_HTTP=200
RANGES=6
sheet_valid_occurrences=3120
sheet_distinct_models=1121
db_missing_occurrences=2
name_drift_occurrences=1012
name_drift_distinct_models=492
name_equal_occurrences=2106
ecount_name_drift_occurrences=0
```

재현 절차: 위 6개 sync 탭을 현재 DB에 대해 동기화하면 `nameDrift` 합계는 1,012가 된다. 실제 고유 품목은 492개이므로 사용자에게 “품목 수”로 해석되는 값은 520건 과대다. 이름 제외 자체는 정상 갱신을 막지 않는다. 일반 SHEET/MANUAL 행은 DB 이름을 보존하면서 `nameDrift++` 후 다른 writer가 만든 Hibernate dirty가 없으면 `unchanged++` 된다. ECOUNT 승격 행은 `rename()`·lineage·productCategory 변경이 dirty로 잡혀 정상 `updated++` 된다. 실 데이터의 ECOUNT name drift는 0건이었다.

## 결함 2 — `priceHistoryExposureSpecWrites`가 실제 외부 엔티티 변경 행 수를 접어 센다

실 사용자 경로는 동일하다. 한 품목의 PriceHistory·Exposure·여러 ProductSpec이 동시에 바뀌면 `ExternalWriteTracker`의 boolean 하나로 모두 접은 뒤 카운터를 한 번만 증가시킨다. 필드명과 `TabSyncResult` 주석의 “실제로 변경된 ... 행 수” 계약과 다르다.

격리 PostgreSQL에 임시 IT를 넣어 Product는 불변으로 두고 ProductSpec `배관경`, `냉매가스` 2행을 동시에 변경했다. DB에서 변경값 2개를 확인하면서 counter 1을 단정한 fresh 원문은 다음과 같다.

```text
XML_FILES=1 TESTS=1 FAILURES=0 ERRORS=0 SKIPPED=0
TEST=reconv_probe_외부엔티티_두행변경도_카운터는_한번만_증가한다
[ProductSheetSync] tab '홈멀티': inserted=0, updated=0, unchanged=1,
nameDrift=0, priceHistoryExposureSpecWrites=1, softDeleted=0, skipped=0
[ProductSheetSync] sync 완료: ... 사양 linked=2, priceHistoryExposureSpecWrites=1
```

재현 절차: 기존 품목의 Product 값과 가격은 유지하고 같은 sync에서 ProductSpec 두 개의 값만 바꾼다. 실제 변경 엔티티 행은 2개지만 counter는 1이다. 임시 IT는 실행 직후 삭제했고 제품/테스트 소스 diff가 0임을 최종 확인한다.

## ② dirty detection 양방향 변화

R2 필드 열거 대비 **새로 감지하는 현재 writer 변경**:

- ECOUNT → SHEET 승격의 `lineage`
- ECOUNT → SHEET 승격의 `productCategory`
- ECOUNT → SHEET 승격의 `name`
- 앞으로 writer가 변경하는 Hibernate dirty-checkable Product 영속 속성 전부(별도 열거 추가 불필요)

R2가 감지했지만 R3부터 **이제 감지하지 않는 것**은 실제 writer가 막힌 가짜 변경이다.

- 다른 productCategory 탭에서 writer guard가 막는 `panelType`, `remoteType`, 조건부 `pyongSize`, `usageScope`, `hasVariableDiscount`, `setMaterialKey`, `legacyDiscountFlag`, `discountFlags`, `fixedDiscountRate`, `catL`, `catM`, `catS`
- `variableDiscountManual=true && fixedDiscountManual=false`에서 보존되는 `fixedDiscountRate`
- 활성 수량규칙이 `usageScope → NONE` 전환을 차단한 경우의 `usageScope`

Product의 현재 scalar/enum/BigDecimal/ManyToOne writer 중 dirty detection이 놓치는 실제 변경은 찾지 못했다. PriceHistory·Exposure·Spec은 Product dirty detection 대상이 아니라 별도 tracker 대상이며, 그 tracker의 계수 결함은 결함 2로 분리했다.
