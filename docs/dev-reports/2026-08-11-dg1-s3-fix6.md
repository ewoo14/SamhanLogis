## 1. 결론

fix5 rollback을 잡는 first-rAF gate의 관측을 실제 mouse click 뒤에서 click 전에 옮겼다.
페이지에 관측 promise를 먼저 설치하되 `page.evaluate()`가 끝나기를 기다리지 않고 즉시 반환하게
한 뒤, 실제 `page.mouse.click()`을 수행하고 그 promise의 결과를 읽는다. 관측 callback은 같은
`scroll` dispatch에서 앱 listener 뒤에 rAF를 예약한다.

같은 순서 오류가 있던 `window scroll 중 option click` first-paint 검사도 동일하게 수정했다.
그 외 검사는 최종 상태를 보는 검사이거나, 하나의 browser task 안에서 조작 후 rAF 관측을 예약하는
구조라 false-green 순서 문제는 확인되지 않았다.

## 3. Playwright 전수표 — 관측을 조작보다 먼저 걸었는가

대상 범위는 PR #1168 S3 live spec의 9개 검사와 그 내부 first-paint surface다.
최종 상태를 확인하는 검사는 결과 상태를 조작 뒤에 읽는 것이 의도된 순서이므로 O로 판정했다.

| 검사 | 관측 순서 | O/X | 비고 |
|---|---|---:|---|
| 정산서 검색·선택 | visible/hit 관측 후 option click, 선택 결과 후행 관측 | O | 최종 선택 계약 검사 |
| 선택 정산서 상세·인쇄 | submit/print 조작 후 해당 화면 결과 관측 | O | 최종 화면 검사 |
| 문서 참조 7유형 | 각 option visible/hit 관측 후 선택 | O | 자동 스크롤 click 아님 |
| 0건·flip-up·container scroll·resize | scroll task 안에서 rAF 관측 예약, 이후 frame 확인 | O | first-paint frame 포함 |
| window scroll first-paint | window scroll과 같은 task의 rAF 관측 | O | frame1 close/aligned 검사 |
| window scroll 중 option click | click 전에 scroll→rAF promise 설치 | O | fix6에서 수정 |
| scroll 0→3 input 재클릭 first-rAF | click 전에 scroll→rAF promise 설치 | O | fix6 핵심 수정 |
| 480px visible/hit | 검색 후 visible/hit 관측 | O | 최종 visible surface |
| wheel·keyboard·large scroll·결과변경·resize | 각 조작 후 count/좌표/scroll 상태 관측 | O | 낡은 first-rAF gate 없음 |

수정 전 X였던 두 좌표는 다음과 같다.

```text
page.mouse.click() → page.evaluate(requestAnimationFrame)       X
clickOption.click() → page.evaluate(requestAnimationFrame)       X
observer promise 설치 → 실제 mouse click → promise 결과 읽기     O
```
