# PR #1050 — #1049 재수렴 2차 적대적 검증

- 검증 범위는 `resetDraft: false`의 도달 가능한 사용자 경로와 `product-catalog.spec.ts` 계약 보존 여부 두 축으로 한정한다.
- fix2 보고서는 모달 취소 시 검색어 `AJ` 보존과 `검색 중…` 잔재 0건까지만 자동 검증했다고 기록하며, 취소 후 재검색·필드 왕복·연속 취소는 검증했다고 기록하지 않는다.
- 스펙 갱신 diff는 시나리오 0b의 후보 `option` 가시성 단언 1개와 `option.click()` 동작 1개를 제거하고, 선택 칩 `1개 선택됨` 단언 1개를 추가했다.
- 갱신 전후 모두 추가 버튼 활성·클릭, 추가된 품목의 견적 토글 가시성·checked, 현재 카테고리 칩 가시성 단언을 그대로 유지하므로 “실제 추가” 결과 불변식은 삭제되지 않았다.
- `closeSearchSurface`는 debounce·blur 타이머를 취소하고 요청 sequence를 증가시키며 후보·resolved query·loading/error를 초기화하므로, 취소 전 in-flight 응답은 이후 상태에 반영될 수 없다.
- 새 입력은 다시 sequence를 증가시키고 검색 실행 시 후보를 먼저 비우므로, 취소 후 검색어를 편집해 재검색하는 경로에서 이전 후보가 새 후보에 섞이는 상태 전이는 보이지 않는다.
- 도달 결함: `preserveDraftOnNextFocusRef`는 모달 취소 뒤 입력 focus에서 읽히지만 `false`로 소비되지 않아, 다른 필드로 이동할 때 blur도 계속 “모달 이동”으로 오인하고 검색어를 복원하지 않는다.
- 실 사용자 경로는 다건 검색 → 모달 취소 → 페이지 검색 필드 클릭 → 기초품목 필드 재진입이며, 이 왕복 뒤에도 취소 검색어가 남는다.
- 이 컴포넌트의 기존 focus 계약은 새 진입 시 draft를 비워 전체 검색을 시작하는 것이므로, 모달의 즉시 포커스 복원 1회만 보존하고 실제 필드 이탈·재진입에서는 검색어가 사라지는 쪽이 맞다.
- 연속 취소는 첫 취소 뒤 검색어를 한 글자 편집했다 되돌려 재검색하면 두 번째 모달이 열리고 다시 취소되며, 후보·모달 후보는 매회 초기화되어 stale 혼합은 없다.

## 판정

### 결함 1 — 모달 취소용 draft 보존 플래그가 실제 필드 이탈 뒤에도 소비되지 않는다

1. **실 사용자 경로 재현 여부: 도달 가능.** 다건 검색 → 모달 취소 → 페이지의 다른 검색 필드 클릭 → 기초품목 검색 필드 재진입이라는 일반 사용자 경로다. 현재 로컬 서버는 인증 화면으로 전환되어 브라우저 실행 재현은 완료하지 못했으며, 아래 이벤트 상태 전이로 도달성을 확정했다.
2. **재현 근거:** `AsyncAutocomplete.tsx:158-160`의 `preserveDraftOnNextFocusRef`는 “다음 focus” 보존용이다. 그러나 `:198-202`의 focus 처리에서 값만 읽고 `false`로 소비하지 않는다. 이어 `:247-252`의 blur는 플래그가 참이면 모달 이동으로 간주해 draft 복원을 건너뛴다. 따라서 모달이 이미 닫힌 뒤 실제 다른 필드로 이탈해도 같은 예외가 반복 적용된다.
3. **영향 범위:** 결과 선택 모달을 사용하는 기초품목 선택 추가 입력의 취소 경로. 확정 칩과 서버 저장에는 영향이 없지만, 취소한 미확정 검색어가 필드 왕복 뒤에도 남아 해당 컴포넌트의 기존 “재진입 시 새 검색 시작” 계약과 충돌한다. 올바른 경계는 모달이 입력으로 돌려주는 즉시 focus 1회만 보존하고, 그 뒤 실제 필드 이탈·재진입에서는 draft를 지우는 것이다.

## 각도 1 — 나머지 경로

- **취소 후 재검색:** 사용자가 남은 검색어를 편집하면 `handleChange`가 보존 플래그를 해제하고 기존 요청을 무효화한 뒤 새 검색을 예약한다. 검색 실행도 후보를 먼저 비우므로 stale 후보 혼합은 도달하지 않는다. 단, 취소 직후 변경하지 않은 동일 문자열은 focus나 Enter만으로 재요청되지 않으며, 모달을 다시 열려면 한 글자 이상 편집해야 한다.
- **연속 취소:** 첫 취소 뒤 검색어를 편집해 다건 검색을 다시 발생시키면 두 번째 모달과 두 번째 취소에 도달한다. 각 취소가 모달 후보·dropdown 후보·loading/error를 비우므로 stale 혼합이나 임시 체크 잔존은 없다. 다만 결함 1의 sticky 보존은 두 번째 취소 뒤에도 반복된다.

## 각도 2 — 스펙 계약 전후 대조

| 구분 | 갱신 전 | 갱신 후 | 계약 판정 |
|---|---|---|---|
| 검색 입력 | 특정 모델코드를 입력 | 동일 | 유지 |
| 선택 표현 | dropdown의 해당 option 가시성 단언 후 클릭 | dropdown 없이 `1개 선택됨` 칩 단언 | 새 1건 즉시 확정 계약에 맞춘 표현 교체 |
| 추가 가능 | 추가 버튼 enabled 단언 | 동일 | 유지 |
| 추가 실행 | 추가 버튼 클릭 | 동일 | 유지 |
| 추가 결과 | 특정 모델의 견적 토글 visible·checked | 동일 | 유지 |
| 카테고리 결과 | 특정 모델의 현재 카테고리 칩 visible | 동일 | 유지 |

- **계약을 낮췄는가:** 아니다. dropdown 클릭이라는 옛 표현을 즉시 선택 칩이라는 새 표현으로 교체했고, “기초품목이 실제 현재 카테고리에 추가된다”는 결과 불변식은 그대로 남았다.
- **삭제된 단언:** **1개** — 특정 모델코드를 포함하는 dropdown option이 보인다는 단언. 함께 삭제된 `option.click()`은 단언이 아니라 옛 선택 동작 1개다.
- **추가된 단언:** **1개** — 선택 칩이 `1개 선택됨`임을 확인한다.
- **결과 단언:** 추가 버튼 활성, 특정 모델의 토글 생성·checked, 현재 카테고리 칩 생성이 모두 유지된다. 따라서 클릭 경로만 바뀌었고 추가 결과 검증은 약화되지 않았다.

## 최종 결론

- **BLOCK 1건:** 모달 취소 보존 플래그가 즉시 focus 1회 뒤 소비되지 않아 실제 필드 왕복에도 검색어를 남긴다.
- **스펙 저하 0건:** 삭제 단언 1개는 옛 dropdown 표현이며, 토글·카테고리 칩이라는 기능 결과 불변식은 유지된다.
