## 1. 라이브 도달성 확인 — 전제가 틀렸다

현재 HEAD renderer를 `http://127.0.0.1:51135`에 별도로 띄우고 Playwright 1.62.1 Chromium을 **headless**로 실행했다. API는 공유 게이트웨이 `http://localhost:8080`을 사용했다. 캡처 목적지는 저장소 `resolveQaShotsDir`를 호출해 얻은 아래 `_local` 경로다.

`docs/qa/2026-08-08-1135-s2-live-qa/_local/01-sales-slips-no-driver-phone-filter.png`

실제 `/sales/slips` 화면에서 발견된 입력 컨트롤은 다음 두 개뿐이었다.

1. `select[aria-label="배송태그 필터"]`
2. `input[type="checkbox"][data-testid="slip-list-include-deleted"]`

`driverPhone`, 기사 전화, 지역그룹 검색창은 없었다. 페이지가 실제 발행한 `/slips` 요청 3회도 모두 다음과 같았다.

```text
http://localhost:8080/slips?page=0&size=20&slipType=OUTBOUND
```

즉 GUI 요청에서 `driverPhone` 0회, `regionGroup` 0회다. native 분기는 `regionGroup` 미지정 상태라도 `driverPhone` 자체가 미지정이므로 검색 predicate에 도달하지 않는다. Criteria 분기는 `regionGroup`을 보낼 UI가 없어 진입할 수 없다.

셋째 가능성은 **백엔드 API에 두 분기가 존재하지만 현재 실 GUI에는 그 필터를 전달하는 호출자가 없다**는 것이다. 임의 테스트 UI를 만들거나 브라우저에서 API를 직접 조립하면 백엔드 분기를 호출할 수는 있으나, 그것은 개발책임자가 지정한 “실 화면에서 `driverPhone` 검색”이 아니다.

개발책임자의 “전제가 틀렸다면 고치지 말고 중단·보고” 지시에 따라 여기서 중단했다. 제품 코드나 GUI를 보완하지 않았고, 직접 API 호출로 화면 도달성을 대체하지 않았다.

## 2. 1번 각도 — 정상 검색 차단 여부

**판정 불가.** 도달성 선행조건 불충족으로 평범한 한글·영문·숫자 검색의 실데이터 건수 비교, 부분 일치, 앞뒤 공백, 대소문자 비교를 실행하지 않았다.

## 3. 2번 각도 — 결함 실제 폐쇄 여부

**판정 불가.** 같은 중단 사유로 `%` 단독, `_` 단독, 이름에 `%`·`_`가 실제 포함된 데이터의 리터럴 검색, 백슬래시 검색을 실행하지 않았다.

발화 데이터를 관리자 화면/API로 생성할 수 있는지 조사하거나 `S2-1135` 데이터를 만들기 전에 전제 불일치가 확정됐다. 따라서 이 라운드가 생성한 QA 데이터는 0건이며 DB 쓰기도 0건이다.

## 4. 3번 각도 — `driverPhone` 두 분기

**실 화면 기준 둘 다 미도달 · 판정 불가.** 근거는 다음과 같다.

| 분기 | 필요한 요청 | 실 GUI 결과 | 도달 여부 |
|---|---|---|---:|
| native | `/slips?...&driverPhone=<검색어>` + `regionGroup` 없음 | `driverPhone` 미전송 | 미도달 |
| Criteria | `/slips?...&driverPhone=<검색어>&regionGroup=<값>` | 두 파라미터 모두 미전송 | 미도달 |

따라서 `%`·`_`에 대한 방어가 런타임에서 맞는지/틀린지 판정하지 않았다. “울타리가 가짜인가”라는 검증 품질 판정도 이 보고서에 포함하지 않는다.
