## 1. 새로 가능해진 상태·역할 조합과 결과

정책의 기준은 서버 `checkOutboundPostInspectionPermission`과 FE `canInspect`의
동일 capability다. `CONFIRMED`는 검수 결재선 개인의 조회 capability에 포함했다.

| 역할/조건 | INSPECTING | COMPLETED | SHIPPING | DELIVERED | CONFIRMED |
|---|---|---|---|---|---|
| 시스템 마스터 | 기존 정적 권한 정책대로 통과 | 기존 정적 권한 정책대로 통과 | `ship` 200, 화면 활성 | `deliver` 200, 화면 활성 | `confirm` 200, 화면 활성 및 재조회 |
| 정적 `slip.transfer.process` 권한자 | 기존 정적 권한 정책대로 통과 | 기존 정적 권한 정책대로 통과 | `ship` 200, 화면 활성 | `deliver` 200, 화면 활성 | `confirm`은 기존 `sales.slip.confirm` 정적 권한 판정 유지 |
| 결재선 개인 SALES | `inspect` capability가 있으면 200, 버튼 활성 | 후속 `ship` 가능, 버튼 활성 | `deliver` 가능, 버튼 활성 | `confirm` 가능, 버튼 활성 | 재조회 가능 |
| 결재선 개인 ACCOUNTANT | `inspect` capability가 있으면 200, 버튼 활성 | 후속 `ship` 가능, 버튼 활성 | `deliver` 가능, 버튼 활성 | `confirm` 가능, 버튼 활성 | 재조회 가능 |
| 결재선 밖·비권한 계정 | 서버 403, 화면 비활성 | 서버 403 또는 기존 정적 권한만 허용 | 서버 403 또는 기존 정적 권한만 허용 | 서버 403 또는 기존 정적 권한만 허용 | 서버 403, 조회 불가 |

핵심 완주 경로는 결재선 개인의 `INSPECTING → COMPLETED → SHIPPING →
DELIVERED → CONFIRMED`이며 서버와 화면 모두 같은 capability를 사용한다.
시스템 마스터는 R9 회귀였던 `ship`·`deliver`·`confirm`에서
`X-Is-System-Master: true` 우회가 복원됐다. INBOUND 및 `inspect` 이외 액션의
정적 판정은 변경하지 않았다. R9의 `slipDetailErrorMessage` 403 안내도 유지했다.

## 2. 제거·이동·개명한 식별자 grep 전수

- 제거/개명한 식별자는 없다.
- R9에서 이동된 `ship`·`deliver`·OUTBOUND `confirm`의 동적 판정 식별자
  `checkOutboundPostInspectionPermission`는 `SlipController`의 세 endpoint가
  계속 사용한다.
- `SYSTEM_MASTER_HEADER`와 `isSystemMaster`를 세 endpoint/helper에 연결했다.
  시스템 마스터 판정은 `X-Is-System-Master=true`만 사용한다.
- `isOutboundInspectionApprovalStage`는 다음 두 좌표를 함께 갱신했다.
  - `services/slip-service/src/main/java/com/samhanair/logis/slip/service/SlipService.java`
  - `services/slip-service/src/main/java/com/samhanair/logis/slip/web/SlipSalesAccessGuard.java`
  두 곳 모두 `INSPECTING`, `COMPLETED`, `SHIPPING`, `DELIVERED`, `CONFIRMED`를
  가진다.
- FE `canInspect`는 `inspect`만 보완하던 상태에서 `ship`, `deliver`, `confirm`까지
  보완하도록 확장했다. INBOUND에는 적용하지 않는다.
- R9 이전 정적 `@RequirePermission`은 `process`·`complete`에 남아 있으며,
  `ship`·`deliver`·OUTBOUND `confirm`에는 중복 정적 annotation을 복원하지 않았다.
  대신 원래 annotation의 시스템 마스터 우회만 동적 helper에 복원했다.

중복 상태 집합은 현재 두 판정 표면의 동작을 맞추기 위해 동시 갱신했다. 같은
상태 집합을 각자 보유하는 구조는 향후 한쪽만 수정될 수 있는 결함 씨앗이므로,
후속 작업에서는 공유 정책 상수/공통 판정으로 통합하는 것이 안전하다. 이번 R10의
범위를 넘는 구조 변경은 하지 않았다.
