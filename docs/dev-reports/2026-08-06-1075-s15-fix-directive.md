## 1. 좌표 · 판정 · 재현

**판정: 실 사용자 경로 재현 결함 1건 · BLOCK · 재현 난이도 쉬움(매회 재현). 머지 권고하지 않는다.**

## 2. 불변식

- 사용자가 직접 입력한 규격은 저장·재조회·페이지 재개방·coedit 재접속 뒤에도 사용자 값으로 취급되어야 하며, 품목 해제만으로 사라져서는 안 된다.
- 품목에서 자동 반영된 규격은 같은 경계를 지난 뒤에도 자동 값으로 취급되어야 하며, 품목 해제 시 로컬 화면과 coedit 문서 양쪽에서 회수되어야 한다.
- 비어 있지 않다는 사실만으로 저장 규격을 자동 값으로 단정해서는 안 된다.
- 자동 규격을 한 글자라도 직접 고친 뒤에는 사용자 입력이다. 원래 문자열로 되돌려도 그 사용자 행위가 저장·재개방 또는 coedit 동기화 때문에 자동 값으로 되돌아가서는 안 된다.
- 품목을 다른 품목으로 재확정하면 이전 품목의 자동 규격이 남아서는 안 된다. 새 품목의 규격이 없는 경우에도 이전 자동 규격이 잔존해서는 안 된다.
- 사용자 직접 규격·사용자 직접 단가·다른 라인의 규격과 단가는 품목 해제나 재확정의 부수 효과로 조용히 사라져서는 안 된다.
- 두 coedit 사용자는 같은 규격 provenance 결과를 보아야 한다. 어느 한쪽에서 품목을 해제해도 상대 화면과 문서가 자동 규격 제거/사용자 규격 보존에 대해 갈라져서는 안 된다.
- 판매전표 공용 `ProductAutocomplete`, 값 변경 허용, 라인 추가·삭제 잠금, 신규 작성 자동 빈행, 후보 모달 취소·선택, F1 모달 전환 blur 차단, UUID 비노출 계약을 유지한다.
- provenance의 표현·저장 위치·API/상태 구조는 구현 수단이므로 본 지시서가 정하지 않는다.

## 3. 양방향 RED · 동시 GREEN

다음 양방향 묶음이 동시에 GREEN이어야 한다.

### RED-A — 사용자 규격 보존

1. 품목 확정 후 규격을 사용자가 다른 문자열로 고치고 사용자 단가도 입력한다.
2. 실제 저장 경계를 통과시켜 저장 요청을 단정하고, 저장 결과와 같은 상세 응답으로 페이지를 다시 연다.
3. 품목을 삭제하고 blur한다.
4. 모델명·품목명·품목 식별자는 해제되되 사용자 규격과 사용자 단가는 로컬 라인과 coedit 문서에 모두 남아야 한다.
5. 규격을 한 글자 수정한 경우와 카탈로그 원문으로 되돌린 경우를 각각 저장→재개방해 같은 보존을 단정한다.

### RED-B — 자동 규격 회수와 반대급부

1. 품목에서 자동 반영된 규격을 사용자가 건드리지 않은 채 저장하고 다시 연다.
2. 품목 삭제 뒤 자동 규격만 로컬과 coedit에서 제거되고 사용자 단가 및 다른 라인 값은 유지되어야 한다.
3. 두 coedit 소비자를 연결해 한쪽의 자동 규격 반영과 다른 쪽의 수신을 거친 뒤, 어느 쪽에서 품목을 삭제해도 양쪽 자동 규격이 함께 제거되어야 한다.
4. 같은 두 소비자 경로에서 어느 한쪽이 규격을 직접 고친 뒤 품목을 삭제하면 양쪽 사용자 규격은 보존되어야 한다.
5. 다른 품목으로 재확정할 때 새 품목 규격이 있으면 새 값으로 수렴하고, 없으면 이전 자동 규격이 남지 않아야 한다.
6. 판매전표의 후보 다건 모달·단건 자동확정·규격/단가 반영·삭제 후 공란·UUID 비노출을 함께 회귀 단정한다.

## 4. 이번에 하지 말 것

- 모든 규격을 무조건 지우거나, 반대로 저장본 규격을 전부 사용자 입력으로 간주하지 않는다.
- 단순 문자열 비교만으로 사용자 행위를 소거하지 않는다. 사용자가 자동 원문으로 되돌린 경우도 RED-A 대상이다.
- 사용자 규격을 살리기 위해 자동 규격 회수를 포기하지 않는다.
- 사용자 직접 단가 정책, 가격기억, 수량·금액 권위, 라인 구조, 저장 유효성 규칙을 함께 재설계하지 않는다.
- 판매전표의 독립 규격 정책을 견적에 맞추는 리팩터링을 하지 않는다.
- 백엔드 DB, Docker, 배포, 실제 vendor, 다른 트랙 `#1057`·`#1066`·`#1069`를 조작하지 않는다.
- 기존 테스트 단정을 삭제·완화하거나 timeout 증가로 통과시키지 않는다.
