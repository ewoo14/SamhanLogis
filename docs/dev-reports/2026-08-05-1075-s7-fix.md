# PR #1078 · 이슈 #1075 — S7 fix 보고서

## 판정

S7 BLOCK을 수정했다. coedit 연결 시점에 이미 존재하던 유효 라인만 품목 교체를 허용하고, trailing 빈행은 데스크톱·모바일 모두 품목 자동완성을 잠갔다. 선택 핸들러와 입력 커밋 경계에도 동일한 구조 잠금 가드를 두어 프로그램적 선택으로도 라인이 추가되지 않는다.

## RED-first 원문

수정 전 RED 테스트 실행 결과:

```text
FAIL src/renderer/routes/EstimateFormPage.coedit.test.tsx
S7 RED-B: coedit 중 기존 행 품목은 열고 trailing 빈행 품목 선택은 잠근다
AssertionError: expected false to be true // Object.is equality
  expect(trailingLineModel.disabled).toBe(true)
  Received: false
Tests: 1 failed, 37 skipped
```

초기 테스트 작성 때 `toBeDisabled` matcher가 설치되지 않아 발생한 matcher 오류는 테스트 단정식을 native `disabled` 속성 검사로 교정한 뒤, 위의 실제 결함 RED를 확인했다.

## 원인 및 수정

- `EstimateFormPage.tsx`에 coedit 연결 시점의 유효 라인 `uid` 스냅샷을 추가했다. 스냅샷은 최초 provider 상태 적용 때 한 번만 생성되므로 trailing 빈행이 품목을 얻어도 편집 대상 자격으로 승격되지 않는다.
- 모바일·데스크톱 `ProductAutocomplete`의 `disabled` 조건에 행 단위 coedit 자격을 반영했다.
- `handleProductSelection()`과 `onInputCommitChange()`에 같은 가드를 추가했다. UI 외부에서 구조 추가 대상 행에 선택 이벤트가 들어와도 무시한다.
- 기존 라인 삭제 잠금(`coeditActive`)과 `lineStructureLocked`는 유지했다.
- 신규 작성/비coedit 편집 경로와 `origin/main` 계승 단정은 변경하지 않았다.
- `1062-line-input-ux.spec.ts` 편집 시나리오를 기존 라인 교체·행 수 유지·trailing 잠금·삭제 잠금·발송 확인 경계로 갱신했다. 기존 신규 작성 trailing 빈행 규약은 유지했다.
