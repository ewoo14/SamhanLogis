# #1049 부분 검색 모달 복수선택 구현 보고서

## 범위 고정 — 기존 동작을 유지하는 40곳

이번 차수의 옵트인 대상은 `EstimateItemsCatalogPage.tsx`의 기초품목 선택 추가 입력 1곳이다. 아래 40곳에는 결과 선택 모달/복수 선택 플래그를 전달하지 않는다.

합계: **40곳**. 대상 외 입력은 기존 자동완성 dropdown, 단수 확정, 칩 동작을 그대로 유지한다.

## 설계

- `SearchResultSelectionModal<T>`: `design-system` 공유 generic 컴포넌트. `single`은 라디오 1개, `multiple`은 체크박스와 선택 칩으로 동작한다.
- `AsyncAutocomplete`: 기본 `legacy` 모드는 행위를 변경하지 않는다. 옵트인 모드에서 검색 결과 1건은 즉시 확정하고 2건 이상은 모달로 넘긴다.
- `ProductMultiSelectAutocomplete`: 기존 품목 표시 renderer와 모델코드/품목명 표시를 재사용하며 UUID는 DOM에 렌더링하지 않는다.
- 품목 적용: `EstimateItemsCatalogPage`의 기초품목 추가만 복수 선택으로 전환하고 선택된 품목을 기존 단건 mutation 계약에 맞춰 순차 추가한다.

## 구현 로그

- RED: 신규 모달 테스트를 먼저 추가했다. 최초 실행은 의존 패키지 미설치로 `vitest is not recognized`가 발생했다.
- GREEN: 구현 후 design-system 단위 테스트와 타입체크를 통과했다.
- 기존 40곳은 `resultSelectionMode`를 전달하지 않아 legacy dropdown 경로를 유지한다.
- `EstimateItemsCatalogPage`의 기초품목 입력만 `ProductMultiSelectAutocomplete`를 사용한다. 검색 결과 1건은 칩 즉시 추가, 다건은 모달 확정 후 칩 누적이다.
