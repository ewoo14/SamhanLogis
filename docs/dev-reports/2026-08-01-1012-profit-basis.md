## 거래로 인정할 상태 기준

- 전표 상태전이는 `DRAFT → SAVED → SENT → ACCEPTED → PROCESSING → INSPECTING → COMPLETED`이며, 입고는 `COMPLETED → CONFIRMED`, 출고는 `COMPLETED → SHIPPING → DELIVERED → CONFIRMED`다 (`services/slip-service/src/main/java/com/samhanair/logis/slip/domain/Slip.java:40-44`, `:1079-1141`; 상태 한글명은 `SlipStatus.java:18-29`).
- 따라서 아직 가격을 고칠 수 있는 `DRAFT/SAVED`, 미처리 `SENT/ACCEPTED/PROCESSING/INSPECTING`, 실패한 `REJECTED/CANCELED`를 실현 이익 계산에서 제외한다. **입고 기록 = INBOUND의 `COMPLETED/CONFIRMED`; 판매 기록 = OUTBOUND의 `DELIVERED/CONFIRMED`**로 확정한다.
- 이 기준의 실데이터는 입고 20라인·20품목·122개, 판매 45라인·40품목·258개다. 입고와 판매 양쪽에 있는 품목은 정확히 5개다.

```sql
BEGIN READ ONLY;
WITH eligible AS (
  SELECT s.slip_type, sl.product_id, sl.model_name, sl.product_name, sl.quantity,
         ROUND(sl.supply_amount / sl.quantity, 2) AS supply_unit
  FROM slip_lines sl
  JOIN slips s ON s.id = sl.slip_id
  WHERE sl.is_deleted = FALSE AND s.is_deleted = FALSE
    AND ((s.slip_type = 'INBOUND'  AND s.status IN ('COMPLETED','CONFIRMED'))
      OR (s.slip_type = 'OUTBOUND' AND s.status IN ('DELIVERED','CONFIRMED')))
)
SELECT slip_type, COUNT(*) AS lines, COUNT(DISTINCT product_id) AS products,
       SUM(quantity) AS quantity, MIN(supply_unit), MAX(supply_unit)
FROM eligible GROUP BY slip_type ORDER BY slip_type;

WITH i AS (
  SELECT DISTINCT sl.product_id FROM slip_lines sl JOIN slips s ON s.id=sl.slip_id
  WHERE sl.is_deleted=FALSE AND s.is_deleted=FALSE AND s.slip_type='INBOUND'
    AND s.status IN ('COMPLETED','CONFIRMED')
), o AS (
  SELECT DISTINCT sl.product_id FROM slip_lines sl JOIN slips s ON s.id=sl.slip_id
  WHERE sl.is_deleted=FALSE AND s.is_deleted=FALSE AND s.slip_type='OUTBOUND'
    AND s.status IN ('DELIVERED','CONFIRMED')
)
SELECT (SELECT COUNT(*) FROM i) AS inbound_products,
       (SELECT COUNT(*) FROM o) AS sold_products,
       (SELECT COUNT(*) FROM o LEFT JOIN i USING(product_id) WHERE i.product_id IS NULL)
         AS sold_without_inbound,
       (SELECT COUNT(*) FROM o JOIN i USING(product_id)) AS overlap_products;
COMMIT;
```

```text
-----------+-------+----------+----------+------------+------------

 OUTBOUND  |    45 |       40 |      258 |  109000.00 | 1097000.00
(2 rows)
```

## 같은 품목의 서로 다른 입고가 건수

- 위 확정 상태 기준에서는 **서로 다른 입고가가 있는 품목 0건**이다. 진행 중 상태까지 포함하되 실패 상태만 제외한 전체 활성 전표에서도 0건이다.
- 삭제되지 않은 취소·반려까지 억지로 포함하면 1품목·4라인·2가격이 나오지만, 전부 `CANCELED`인 `QA797-GEN-01 / QA797 일반 상업멀티 품목(회귀비교용)` QA 데이터다. 실제 입고가 아니므로 이익 기준에서 제외한다.
- 따라서 현재 유효 실데이터에서는 가중평균·FIFO·최근 입고가가 달라지는 대표 품목이 **없다**. 세 방식 결과 차이는 모두 0원이며, 취소 QA 데이터를 넣어 차이를 만드는 계산은 실현 이익을 왜곡하므로 하지 않는다.

```sql
BEGIN READ ONLY;
WITH inbound AS (
  SELECT sl.product_id,
         ROUND(sl.supply_amount / sl.quantity, 2) AS supply_unit
  FROM slip_lines sl JOIN slips s ON s.id=sl.slip_id
  WHERE sl.is_deleted=FALSE AND s.is_deleted=FALSE AND s.slip_type='INBOUND'
    AND s.status IN ('COMPLETED','CONFIRMED')
), varied AS (
  SELECT product_id, COUNT(*) AS inbound_lines,
         COUNT(DISTINCT supply_unit) AS distinct_prices
  FROM inbound GROUP BY product_id
  HAVING COUNT(DISTINCT supply_unit) > 1
)
SELECT COUNT(*) AS varied_products,
       COALESCE(SUM(inbound_lines),0) AS affected_inbound_lines
FROM varied;
COMMIT;
```

출력 원문:

```text

(1 row)
```

### 재고 시리얼 원가까지 포함한 최종 정정

- 위 전표 라인 집계와 별도로 `inventory_db.stock_instances`에는 구매 입고 시리얼 3건·1품목이 있고 원가는 840,000원과 850,000원 두 값이다. 따라서 질문의 최종 답은 **서로 다른 가격 입고 사례 = 1품목, 3개 시리얼, 2개 가격**이다.

### 가중평균·FIFO·최근 입고가 민감도

- 실제 출고된 앞의 두 시리얼 시점(2026-06-02)까지의 원가는 840,000원·850,000원이다. 1개 판매를 대표로 보면 가중평균 845,000원, FIFO 840,000원, 최근 입고가 850,000원으로 **최대 10,000원 차이**다.
- 해당 두 시리얼의 `outbound_slip_no`(`S3-QA-1`, `S4Q-OUT-1`)는 현재 `slip_db`에서 0행이라 실제 판매금액은 **확인불가**다. 아래 이익 비교는 실 DB의 현재 상품 기준 판매가 600,000원(VAT 포함)을 VAT 제외 545,454.55원으로 맞춘 **민감도 예시**이지 실현 판매 이익이 아니다.
- 이 조건에서 이익은 가중평균 −299,545.45원(−54.92%), FIFO −294,545.45원(−54.00%), 최근 입고가 −304,545.45원(−55.83%)이다. 방식 선택만으로 이익 10,000원, 이익률 1.83%p가 달라진다.

```sql
-- inventory_db; 600,000은 위 product_db 출력의 VAT 포함 상품 기준가
BEGIN READ ONLY;
WITH pre_sale AS (
  SELECT unit_cost, received_at
  FROM stock_instances
  WHERE is_deleted=FALSE AND product_code='010001'
    AND received_at <= TIMESTAMP '2026-06-02 23:59:59'
), basis AS (
  SELECT ROUND(SUM(unit_cost)/COUNT(*),2) AS weighted_average,
         (ARRAY_AGG(unit_cost ORDER BY received_at ASC))[1] AS fifo,
         (ARRAY_AGG(unit_cost ORDER BY received_at DESC))[1] AS latest
  FROM pre_sale
), methods AS (
  SELECT '가중평균' AS method, weighted_average AS cost FROM basis
  UNION ALL SELECT '선입선출', fifo FROM basis
  UNION ALL SELECT '최근입고가', latest FROM basis
), catalog AS (
  SELECT 600000.00::numeric AS vat_inclusive_sale,
         ROUND(600000.00/1.1,2) AS supply_sale
)
SELECT method, cost, vat_inclusive_sale, supply_sale,
       ROUND(supply_sale-cost,2) AS profit,
       ROUND((supply_sale-cost)/supply_sale*100,2) AS margin_pct
FROM methods CROSS JOIN catalog
ORDER BY CASE method WHEN '가중평균' THEN 1 WHEN '선입선출' THEN 2 ELSE 3 END;
COMMIT;
```

```text
   method   |   cost    | vat_inclusive_sale | supply_sale |   profit   | margin_pct
------------+-----------+--------------------+-------------+------------+-----------
 가중평균   | 845000.00 |          600000.00 |   545454.55 | -299545.45 |     -54.92
 선입선출   | 840000.00 |          600000.00 |   545454.55 | -294545.45 |     -54.00
 최근입고가 | 850000.00 |          600000.00 |   545454.55 | -304545.45 |     -55.83
(3 rows)
```

### VAT 기준 확정

- 이익 기준값은 양쪽 모두 **VAT 제외 공급가액**으로 통일한다: `입고단가 = INBOUND supply_amount/quantity`, `판매단가 = OUTBOUND supply_amount/quantity`.
- VAT 포함 비교도 `(supply_amount+vat_amount)/quantity`를 양쪽에 동일 적용하면 가능하지만, VAT는 회사 이익이 아니므로 기본 이익 지표에는 제외한다.
- 확정 집합의 입고 20/20라인·판매 45/45라인 모두 `line_total=supply_amount`, `unit_price×quantity=supply_amount`, `unit_price_with_vat×quantity=supply_amount+vat_amount`가 일치했다. 양쪽 모두 VAT가 0이 아닌 행뿐이었다. 다만 모두 legacy라 `unit_price_domain IS NULL`이므로 단가 컬럼 하나만 믿지 않고 S/V 스냅샷을 사용한다 (`V59__add_slip_line_unit_price_domain.sql:4-33`).

```sql
BEGIN READ ONLY;
SELECT s.slip_type, COUNT(*) AS lines,
 COUNT(*) FILTER(WHERE sl.line_total=sl.supply_amount) AS line_total_is_supply,
 COUNT(*) FILTER(WHERE ABS(sl.unit_price*sl.quantity-sl.supply_amount)<=0.01) AS supply_unit_identity,
 COUNT(*) FILTER(WHERE ABS(sl.unit_price_with_vat*sl.quantity-(sl.supply_amount+sl.vat_amount))<=0.01) AS vat_unit_identity,
 COUNT(*) FILTER(WHERE sl.vat_amount=0) AS vat_zero,
 COUNT(*) FILTER(WHERE sl.unit_price_domain IS NULL) AS domain_unknown
FROM slip_lines sl JOIN slips s ON s.id=sl.slip_id
WHERE sl.is_deleted=FALSE AND s.is_deleted=FALSE
  AND ((s.slip_type='INBOUND' AND s.status IN ('COMPLETED','CONFIRMED'))
    OR (s.slip_type='OUTBOUND' AND s.status IN ('DELIVERED','CONFIRMED')))
GROUP BY s.slip_type ORDER BY s.slip_type;
COMMIT;
```

## 입고 기록 없는 판매 품목

- 확정 판매 40품목 중 확정 입고가 전혀 없는 품목은 **35품목**, 입고·판매 공통은 5품목이다. 집계 SQL과 출력은 위 「거래로 인정할 상태 기준」에 원문으로 수록했다.
- 이 35품목의 이익은 **0원 원가로 계산하면 안 된다.** `입고단가=NULL`, `이익=NULL`, `이익률=NULL`, 상태=`입고원가 없음`으로 표시하고 합계 이익에서도 제외해야 한다. 상품 기준 매입가를 쓰는 경우에는 실현 이익과 섞지 말고 `기준가 추정`이라는 별도 지표로만 제공해야 한다.

```sql
BEGIN READ ONLY;
WITH inbound AS (
  SELECT sl.product_id, MIN(sl.model_name) AS model_code,
         MIN(sl.product_name) AS product_name,
         SUM(sl.quantity) AS inbound_qty,
         ROUND(SUM(sl.supply_amount)/SUM(sl.quantity),2) AS inbound_unit
  FROM slip_lines sl JOIN slips s ON s.id=sl.slip_id
  WHERE sl.is_deleted=FALSE AND s.is_deleted=FALSE AND s.slip_type='INBOUND'
    AND s.status IN ('COMPLETED','CONFIRMED')
  GROUP BY sl.product_id
), outbound AS (
  SELECT sl.product_id, MIN(sl.model_name) AS model_code,
         MIN(sl.product_name) AS product_name,
         SUM(sl.quantity) AS sold_qty, SUM(sl.supply_amount) AS sales_supply,
         ROUND(SUM(sl.supply_amount)/SUM(sl.quantity),2) AS sales_unit
  FROM slip_lines sl JOIN slips s ON s.id=sl.slip_id
  WHERE sl.is_deleted=FALSE AND s.is_deleted=FALSE AND s.slip_type='OUTBOUND'
    AND s.status IN ('DELIVERED','CONFIRMED')
  GROUP BY sl.product_id
)
SELECT COALESCE(o.model_code,i.model_code) AS model_code,
       COALESCE(o.product_name,i.product_name) AS product_name,
       i.inbound_qty, o.sold_qty, i.inbound_unit, o.sales_unit,
       ROUND(o.sales_unit-i.inbound_unit,2) AS profit_unit,
       ROUND((o.sales_unit-i.inbound_unit)/NULLIF(o.sales_unit,0)*100,2) AS margin_pct,
       ROUND(i.inbound_unit*o.sold_qty,2) AS matched_cost,
       o.sales_supply,
       ROUND(o.sales_supply-i.inbound_unit*o.sold_qty,2) AS total_profit
FROM outbound o JOIN inbound i USING(product_id)
ORDER BY model_code;
COMMIT;
```

## 기준값 최종 확정

1. **금액 축**: 입고·판매 모두 VAT 제외 공급가액을 사용한다. `입고단가=INBOUND supply_amount/quantity`, `판매단가=OUTBOUND supply_amount/quantity`.
2. **거래 상태**: 입고 `COMPLETED/CONFIRMED`, 판매 `DELIVERED/CONFIRMED`만 실현 계산에 포함한다.
3. **원가 흐름**: 시리얼 품목은 `stock_instances.unit_cost`와 실제 출고 연결을 우선한다. 일반 품목은 유효 입고전표가 여러 가격이면 정책 선택이 필요하다. 현재 실데이터는 1품목에서 최대 10,000원/1.83%p 차이를 보이며, 저장 구조의 FIFO 키가 이미 존재하므로 **FIFO를 1순위 권고**한다. 가중평균을 선택하면 월중 입고 시점별 재계산 정의가 추가로 필요하고, 최근 입고가는 과거 판매 원가를 미래 가격으로 바꿀 위험이 있다.
4. **원가 없음**: 0원 처리 금지. 이익·이익률은 NULL/`입고원가 없음`; 집계에서 제외한다.
5. **단위**: 거래 라인에 단위와 환산계수가 없으므로 단위 일치 검증은 현재 확인불가다. 상품/묶음 정본을 전표 라인에 스냅샷하지 않는 한 BOX↔EA 이익은 안전하게 계산할 수 없다.

## 조사 준수

- 보고서 파일 하나만 생성·append했다. git 명령, Docker 재빌드·재기동, DB 쓰기, 코드 수정, 빌드, 테스트는 수행하지 않았다.
- 모든 DB 쿼리는 `BEGIN READ ONLY`로 실행했다. 품목 표시는 모델코드와 품목명만 사용했고 UUID 값은 보고서에 노출하지 않았다.
