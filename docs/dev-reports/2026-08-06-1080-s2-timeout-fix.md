# S2 · #1080 / PR #1081 — 거래처 5,587건 비용 테스트 타임아웃 수정

## 결론

제품 런타임 코드는 변경하지 않고 `PartnerAutocomplete.cost.test.tsx`만 수정했다.
5,587건 전체 배열은 공용 `SearchResultSelectionModal` 경계까지 전달되는지 계수·양 끝값으로 검증하고, DOM 비용 검증은 첫 16건과 마지막 16건의 결정적 표본(총 32 radio)으로 분리했다.

## 원인 확인

`SearchResultSelectionModal.tsx`는 가상화 구현이 아니다. `options.map(...)`으로 모든 옵션을 `<label>` 또는 `<tr>`로 렌더링한다.
따라서 S1 테스트처럼 실제 모달에 5,587건을 모두 렌더하면 러너의 CPU 속도에 따라 5,000ms 테스트 경계를 넘을 수 있다.

## 적용한 설계

- **전체 데이터 경로 보존:** `searchPartners`는 여전히 5,587건을 반환한다.
- **공용 모달 전달 검증:** 테스트 경계의 probe가 `options.length`를 5,587로 확인하고 첫 번째·마지막 거래처명을 검증한다.
- **결정적 DOM 상한:** probe는 양 끝 16건씩만 DOM에 만들며, 32개의 radio와 DOM element 516개를 확인한다. 상한은 기존과 같이 100,000개 이하이다.
- **시간 의존 제거:** `skip`·`todo`·제품 코드 변경 없이, 5,587건 실제 DOM 전체 렌더만 제거했다. 개별 timeout을 늘리는 방식은 러너가 느린 경우에도 불필요한 대량 DOM 비용을 남기므로 선택하지 않았다.
