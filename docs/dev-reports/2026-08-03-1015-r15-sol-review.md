## 7. 미판정 — 결함 수에 포함하지 않음

### 7.1 거래처 식별자 불일치 가능성

`PartnerAuthService.java:138-145,323-326`은 신규 가입의 `partnerCode`를 정규화한 bizNo와 동일하게 저장한다. 주문·출고 조회는 `partner_code` 정확일치다. dev DB에는 auth `2118712345`와 같은 사업자번호의 과거 주문이 `partner_code=P-2026-0001`, `biz_code=211-87-12345`로 존재했다.

```text
   order_no   | partner_code |   biz_code   |  status   |    confirmed_at
--------------+--------------+--------------+-----------+---------------------
 2026/04/15-1 | P-2026-0001  | 211-87-12345 | CONVERTED | 2026-01-03 10:00:00
```

그러나 이 주문은 auth 생성시각(2026-07-09)보다 오래됐고 현재 auth도 30일 미만이다. 실제로 최근 활동 중인데 잘못 차단되는 auth 행을 재현하지 못했으므로 **미판정**이며 결함으로 세지 않았다.

### 7.2 관리자 복구 실 DB 왕복

공유 DB write 금지 때문에 `LONG_UNUSED → APPROVED → 다음 상태조회/로그인` 실제 mutation은 실행하지 않았다. 현재 `access_restored_at IS NOT NULL` 행도 0건이다. 생산 코드에서는 즉시 재잠금 경로가 없지만, 실제 DB 왕복은 보지 못했으므로 이 실증 부분은 미판정이다.

1. 공유 DB write가 필요한 관리자 상태 변경, 비밀번호 초기화, 실제 로그인 상태 마킹의 라이브 왕복.
