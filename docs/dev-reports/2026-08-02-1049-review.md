### 각도 2 — 실 DB 최대 매치 검색어 선정(읽기 조회)

활성 품목의 실제 검색 대상 컬럼(`name`, `model_name`)을 글자 단위로 분해해 한 글자 검색 시 매치 행 수를 집계했다.

명령 요지:

```sql
WITH base AS (
  SELECT id, lower(coalesce(name,'') || coalesce(model_name,'')) AS txt
  FROM products WHERE is_deleted=false
), chars AS (... 제품별 중복 글자 제거 ...)
SELECT ch, count(*) FROM chars
WHERE ch ~ '[A-Za-z0-9가-힣]'
GROUP BY ch ORDER BY count(*) DESC LIMIT 20;
```

출력 원문:

```text
a 1175 | 1 1086 | 0 1016 | h 751 | d 647 | s 612 | 2 609
b 577 | p 567 | n 558 | 기 526 | c 523 | 풍 503 | 실 495 | 무 483
```

판정: 실 DB 최다 매치 검색어는 **`a`(활성 1,175행)**다. 이 값으로 100건 이상 경로를 실제 UI에서 이어서 검증한다.

### 각도 2 — 0건·1건·대량 결과 분기

실 DB 읽기 조회:

```text
search_term=AJ040RXH4BC1  matches=1
search_term=1049-no-result zero_matches=0
search_term=a             matches=1,175
```

- **1건:** 신규 Playwright가 `AJ040RXH4BC1` 입력 사용자 경로를 실제 실행했고 `2 passed` 중 A 시나리오에서 dialog 0건과 칩 즉시 확정을 통과했다.
- **0건:** `performSearch`는 `results.length`가 0이면 모달 분기에 진입하지 않고 기존 `done + candidates=[]` 경로로 내려가 `검색 결과 없음`을 표시한다. design-system의 기존 empty-state 회귀도 전체 테스트에서 통과했다. 빈 모달 도달성은 없다.
- **100건 이상:** FE `searchProducts`가 `/api/products?q=...&size=20`으로 고정 호출하고 응답 `content`만 반환한다. 따라서 실 DB에서 1,175행이 매치돼도 모달 DOM 후보 상한은 20개다. 모달 list는 `max-height: min(55vh, 420px); overflow-y:auto`다. 100개 이상을 한 번에 그리는 성능 경로는 도달하지 않는다.
- 단, FE가 `totalElements`를 버리므로 `a` 검색 시 사용자는 전체 1,175건 중 첫 20건만 보고 총 건수·추가 페이지를 알 수 없다. 더 구체적으로 재검색해야 하는 기존 20건 자동완성 계약과 동일하다.

### 각도 2 — 키보드·취소 상태 정적 도달성

- 다건 모달의 실제 Playwright 경로에서 checkbox 두 개를 각각 `Space`, 확정 버튼을 `Enter`로 조작해 `2개 선택됨`까지 통과했다.
- 공용 `Modal`은 document-level `Escape`에서 `onClose`를 호출하고, Tab focus trap 및 닫기 후 이전 포커스 복원을 구현한다. `SearchResultSelectionModal.onCancel`은 `closeSelection`으로 연결된다.
- 취소/ESC/X/배경 닫기는 `selectionOpen=false`, 후보 배열 비움, `draft=''`, committed 복원으로 동일 수렴한다. 기존 선택 칩 배열은 건드리지 않으므로 선택 중간 상태가 남지 않는다.

### 각도 3 — 복수선택 경계 정적 도달성

- **동일 품목 재선택:** `searchUnselected`가 기존 `selectedKeys`를 후보에서 제거하고 `add`도 같은 key를 재차 차단한다. API의 활성 품목 한 행도 하나의 key만 가지므로 중복 칩 도달성은 없다.
- **칩 제거:** 품목 칩의 제거 버튼은 `onRemove(product)`를 거쳐 대상 id를 제외한 새 배열로 갱신한다. `MultiSelectAutocomplete`/`TagChip` 전체 테스트에서 기존 칩 제거 계약이 통과했다.
- **빈 선택 확정:** `selectedKeys.size === 0`이면 `선택 확정` 버튼이 disabled이므로 빈 확정 호출은 도달하지 않는다. 취소만 가능하다.
- **저장 후 재진입:** 실 DB 쓰기 금지 조건 때문에 실 저장은 실행하지 않았다. 현재 신규 Playwright 2건도 칩 확정까지만 검증하며 `현재 카테고리에 추가` 저장·재진입은 보지 않는다. 이 축은 미검증으로 남긴다.

### 각도 4 — UUID DOM 경로

정적 렌더 경로 전체를 역추적했다.

```text
ProductOption.id → getOptionKey/getSelectedKey/getKey → Set 비교 및 React key
DOM id → ds-aac-list-<React useId>-opt-<index>
modal input aria-label → modelCode ?? modelName
chip title/value → productName
data-* → 고정 testid/state만 사용
```

- UUID는 후보 동등성·React key·모달 remount key에만 쓰이며 React key는 DOM 속성으로 출력되지 않는다.
- 모달 checkbox에는 `value`, UUID 기반 `id`, `data-*`, tooltip이 없다. 표시·접근성 이름은 모델 식별자이며, 칩 tooltip은 품목명이다.
- 실행된 신규 Playwright는 dialog `textContent`와 확정 후 body `textContent`의 UUID 정규식 0건을 재현했다.
- 브라우저 연결 부재로 런타임 `outerHTML` 전체 속성 정규식 스캔은 수행하지 못했다. 정적 렌더 경로상 UUID 속성 도달점은 발견되지 않았다.
