# 문서 자동 저장·이력 공통 계약 구현 보고서

## 확인 1 — 재사용 계약과 첫 적용

- 재사용할 기존 계약: `services/accounting-service/src/main/java/com/samhanair/logis/accounting/domain/TaxInvoiceBatch.java:21-35, 88-107`의 RDB 배치 스냅샷(`dataSnapshotJson`, gzip+base64, `BaseEntity` 7 audit + Soft Delete), `services/accounting-service/src/main/java/com/samhanair/logis/accounting/service/HometaxExportService.java:246-317`의 생성 시 스냅샷 저장, `:324-367`의 스냅샷 재생성, `services/accounting-service/src/main/java/com/samhanair/logis/accounting/web/AccountingReportController.java:323-369`의 날짜 범위 이력 목록·상세 조회를 재사용한다.
- 첫 적용: 거래처별 원장. 세 대상 중 인쇄 양식 revision 고정이 필요한 거래명세서와 입력 보조 상태까지 복원해야 하는 내일자 전표보다 저장 payload가 단순한 조회 결과 스냅샷이며, 기존 조회·인쇄 API를 유지한 채 저장/이력 계약을 검증할 수 있다.
- Flyway 확인: 저장소 전체 migration 최대 버전은 `V90__seed_accounting...sql` 계열이므로 신규 migration은 동시 트랙 충돌 여유를 둔 `V95`로 계획한다. 적용된 migration은 수정하지 않는다.

실제 구현 전에 기존 거래처별 원장 단위 테스트에 자동 저장 요구를 추가하고 실행했다.

실패 원인은 기존 `LedgerImageService`가 조회 응답만 만들고 `TaxInvoiceBatchRepository.save(...)`를 호출하지 않았기 때문이다.

## 구현 내용

- 기존 `tax_invoice_batches` 테이블과 `TaxInvoiceBatch`의 gzip+base64 스냅샷 저장 방식을 재사용했다. `document_type`/`document_key`만 신규 컬럼으로 추가해 홈택스(`HOMETAX`)와 원장(`PARTNER_LEDGER`) 이력을 분리했다.
- `SnapshotCompression`으로 홈택스 계약과 동일한 gzip+base64 JSON 코덱을 공통 사용했다.
- 거래처별 원장 조회가 기존 응답을 반환한 직후 자동 저장한다. 기존 조회·인쇄 응답 형식과 쿼리 경로는 변경하지 않았다.
- `/accounting/journals/ledger-history` 날짜별 목록과 `/accounting/journals/ledger-history/{batchNo}/restore` 복원 조회를 추가했다. 사용자 응답에는 UUID를 넣지 않고 batchNo/partnerCode만 사용한다.
- 신규 migration은 `services/accounting-service/src/main/resources/db/migration/V95__add_document_snapshot_type.sql`이며 기존 migration은 수정하지 않았다.
- 이번 슬라이스에서는 거래명세서·내일자 전표 화면/서비스를 변경하지 않았다. 거래명세서 양식 revision pin은 다음 적용 슬라이스의 계약 입력으로 남겼다.

## 확인 5 — 변경 모듈 전체 테스트 원문

전체 모듈 명령은 두 차례 시도했다. 첫 시도는 120초, stale Gradle test worker가 남은 뒤 정리하고 재시도한 두 번째 시도는 300초 timeout으로 테스트 종료 전에 중단됐다. 따라서 전체 모듈 PASS는 주장하지 않는다.

```text
.\gradlew :services:accounting-service:test --no-daemon --console=plain
command timed out after 304023 milliseconds
```

timeout 원인은 Docker/공유 DB를 재기동하지 않고 확인할 수 있는 범위를 넘어선 모듈 전체 통합 테스트 실행 지연이며, 테스트 실패 assertion 원문은 생성되지 않았다. stale worker가 잡은 `build/test-results/test/binary/output.bin`은 작업 프로세스만 종료해 해제했다.

변경 대상 테스트와 compile/testClasses는 마지막 실행에서 다시 확인했다.

```text
.\gradlew :services:accounting-service:test --tests 'com.samhanair.logis.accounting.service.LedgerImageServiceTest' --tests 'com.samhanair.logis.accounting.service.LedgerSnapshotServiceTest' --rerun-tasks --no-daemon --console=plain
BUILD SUCCESSFUL in 42s
21 actionable tasks: 21 executed
```

데스크톱 모듈 파일은 변경하지 않았으므로 `npm run typecheck`는 실행 대상이 아니다.

## 확인 7 — 권한 회귀 수정 및 신규 API 권한 검증

`AccountingPermissionControllerIT`에 `@MockBean LedgerSnapshotService`를 추가했다. 또한 신규 API를 동일한 parameterized 403·deny-counter 계약에 추가했다.

- `GET /accounting/journals/ledger-history` — `accounting.partner-ledger / VIEW`
- `GET /accounting/journals/ledger-history/{batchNo}/restore` — `accounting.partner-ledger / VIEW`

두 컨트롤러 메서드 모두 실제로 `@RequirePermission(page = "accounting.partner-ledger", action = VIEW)`가 붙어 있음을 확인했다. 응답 식별자는 `partnerCode`·`batchNo`이며 UUID를 사용자 응답에 노출하지 않는다. `V95__add_document_snapshot_type.sql`은 유지했다.
