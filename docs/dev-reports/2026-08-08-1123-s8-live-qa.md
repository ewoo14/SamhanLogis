## 결론

**판정 불가. 결함 0으로 세지 않는다. 머지 차단.**

주 기능의 발화 조건인 활성 기준선 또는 날짜 규칙을 실 관리자 화면·API로 만들 수 없다. 실 slip-service OpenAPI 188개 path 중 관련 path는 `/admin/slip-cutoffs`, `/admin/slip-cutoffs/{id}`, `/admin/slip-cutoffs/delivery-tags`뿐이며, 전표 날짜 기준선/날짜 규칙 관리 path는 0개다. desktop에도 기준선 관리 route가 없고 `/#/admin/slip-closing`은 404가 표시됐다.

따라서 DB 직접 INSERT 금지 조건에서 날짜 마감 가드를 발화시킬 수 없으며, ③ 마감 날짜 차단·④ 예외 권한 통과·결합 2·3·SlipType 상호 격리는 실행할 수 없다.

별도로 V95가 심은 예외 권한도 실 소비 경로에 도달하지 않는다. `dev_manager`(V95 기본 대상, account `…0003`, MANAGER group `…0101`)를 대상으로 실 auth 내부 API를 호출한 결과는 HTTP 200이지만 `data.allowed=false`였다. 같은 계정을 desktop 권한설정에서 선택하고 `마감일 예외 생성`을 검색하면 페이지 0행·`검색 결과가 없습니다`였고 `slip.closed-date-exception` CREATE cell도 0개였다.

## 2. 차단되면 안 되는 것

날짜 마감 정책이 열린 상태에서 실 생성된 데이터는 4건이다.

| 종류 | 날짜 | 전표번호 | 경로 |
|---|---|---|---|
| OUTBOUND | 2026-08-08 | `2026/08/08-19` | 기준선 0 API |
| INBOUND | 2026-08-08 | `2026/08/08-1` | 기준선 0 API |
| OUTBOUND | 2026-08-09 | `2026/08/09-7` | 컷오프 안내 추종 API |
| OUTBOUND | 2026-08-09 | `2026/08/09-8` | 컷오프 안내 추종 desktop |

날짜 마감 가드에 의해 잘못 차단된 열린 날짜 생성은 **0건**이다. 2026-08-08 DAY 출고 2회가 409였으나 이는 활성 시각 컷오프 `00:01`의 의도된 차단이며 날짜 마감 가드의 오차단으로 세지 않았다.

권한 문자열의 정적 정본은 서버 guard·auth `PageCode`·V95 SQL·desktop type/label map에서 모두 `slip.closed-date-exception`으로 일치한다. 그러나 실 서버는 `allowed=false`, 실 화면은 행 0개이므로 **화면과 서버가 같은 권한을 실제로 소비하는 상태에는 도달하지 않았다.**

## 3. 두 마감 게이트 결합

### 3.1 익일이 열려 있음
