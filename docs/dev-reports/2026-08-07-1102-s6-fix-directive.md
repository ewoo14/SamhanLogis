실사용자 재현 경로는 `거래처 선택 → 최근단가가 있는 품목 선택 → GET /slips/price-memory pending 동안 단가 input 관찰`이다. S6 실 API 반복 측정에서 요청 `t+7ms`의 input은 빈 값이 아니라 `0`이었고 note만 숨겨졌다. 성공·실패 뒤 generation Map 키가 남으며 라인 삭제도 이를 정리하지 않는다.

PM은 새 규칙에 따라 S5를 먼저 되돌리고 원인을 다시 분석한다. LUNA는 PM이 지정한 되돌림 기준점에서 fix하며 S5 위에 증상 patch를 더 쌓지 않는다.

## 2. 불변식(수단 금지)

거래처 기준 자동 가격이 아직 확정되지 않은 동안 단가 input·가격 출처·공급가액·VAT·합계 어느 것도 `0`, 카탈로그 값, 직전 가격을 확정값처럼 보여서는 안 된다. 성공하면 기억 단가/권위 할인값으로 한 번 수렴하고, miss·실패·timeout이면 기존 fallback 계약으로 수렴하며, 조회 중 직접입력은 즉시 pending을 무효화해 늦은 응답보다 우선해야 한다.

가격 조회 수명 bookkeeping은 실제 살아 있는 Promise·라인에만 대응해야 한다. 성공·miss·실패·직접입력·거래처 변경·라인 삭제·페이지 이탈 후 stale generation/pending 키가 남아서는 안 되며, 삭제·추가·정렬로 index가 변해도 다른 lineId에 오귀속되면 안 된다.

구현 수단은 지정하지 않는다. 단, design-system mock의 기대값만 바꾸기, `LineRow` 전역 빈 금액 정책을 이 전표 한 건 때문에 무단 변경하기, pending 동안 `0`을 허용하도록 단언 완화하기, timeout 연장·skip으로 GREEN 처리하기는 금지한다.

## 3. 양방향 RED

### RED-A — 실제 LineRow 통합 표면

1. `@samhan/design-system`의 `LineRow`를 mock하지 않는 최소 통합 렌더를 만든다.
2. 거래처와 품목을 실제 handler 경로로 선택하고 price-memory Promise를 deferred로 둔다.
3. Promise 미해결 동안 실제 단가 input은 빈/미확정 표현이어야 하며 `0`, `판매가`, `거래처 최근단가`, 계산된 공급가액·VAT·합계가 확정값으로 보이면 RED다.
4. Promise를 기억 단가로 resolve하면 input·source·금액이 한 번만 해당 값으로 수렴해야 한다.
5. 204/miss와 failure/timeout은 기존 catalog/DC fallback으로 수렴해야 한다.

### RED-B — 반대급부·수명주기

1. price-memory Promise가 pending인 동안 실제 input 이벤트로 사용자 단가를 넣고, 늦은 응답이 이를 덮으면 RED다.
2. pending 라인을 삭제한 뒤 새 라인을 추가·정렬하고 옛 응답을 resolve한다. 새 라인이 pending으로 보이거나 값이 바뀌면 RED다.
3. 성공·miss·실패·직접입력·거래처 변경·라인 삭제 각각 뒤에 pending ID와 generation bookkeeping이 살아 있는 line/Promise 집합과 일치하지 않으면 RED다.
4. bulk refresh와 단건 lookup을 동시에 deferred로 두고 먼저 끝난 경로가 다른 경로의 표시·저장 gate를 해제하면 RED다.
5. 거래처 선택 직후 DC config를 deferred로 두고 품목을 선택한다. price-memory 호출 전 DC 대기 구간에도 미확정 카탈로그/직전값이 보이면 RED다.
