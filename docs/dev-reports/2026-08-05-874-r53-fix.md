# R53 fix report — PR #1057 · 이슈 #874

## 판정

R52가 남긴 결함 1과 결함 3을 구현하고 좁은 회귀 게이트를 GREEN으로 확인했다.
결함 2의 R52 정정은 유지했다. `accounting-service`와 지정된 실제 QA Playwright 파일은 변경하지 않았다.

## RED-first 원문

### 결함 1 RED

```text
NotificationServiceTest > concurrentSamePendingRequest_entersGatewayOnlyOnce() FAILED
java.lang.AssertionError at NotificationServiceTest.java:237
```

기존에는 동일 PENDING 요청을 두 호출이 모두 gateway에 진입시켰다.

### 결함 3 RED

결함 3 테스트는 기존 outbox 모델에 `TERMINAL` 상태와 terminal 사유가 없어 해당 상태를 표현할 수
없었고, 구현 후 검증할 수 있도록 상태 필드를 반영한 회귀 단언으로 만들었다. 기존 동작의 원인은
`resolve()==empty` 및 gateway `false`가 모두 `markRetry()`로 수렴하는 것이었다.

## 변경

### notification-service — 결함 1

- `notification_requests.dispatch_lease_until` 컬럼과 인덱스를 V10으로 추가했다.
- gateway 호출 직전 `PENDING/FAILED/RETRYING` 행에 대해 만료 가능한 lease를 원자적으로 획득한다.
- lease를 얻지 못한 동시 요청·PENDING 복구자는 gateway에 진입하지 않는다.
- 완료 시 lease를 지운다. 30초 lease 만료로 프로세스 중단 후 재처리 가능성을 보존한다.
- 기존 동일 키 `FAILED → 재시도 → SENT` 호환을 위해 FAILED도 claim 대상에 포함했다.

### slip-service — 결함 3

- outbox 상태에 `TERMINAL`과 `terminal_reason`을 추가했다.
- UUID/loginId 해석 실패는 `RECIPIENT_UNRESOLVED`, 편집자 자신은 `RECIPIENT_IS_EDITOR`로 즉시 종결한다.
- gateway 실패는 최대 5회까지 backoff 재시도하며, 한도 도달 시 `GATEWAY_RETRY_LIMIT`으로 종결한다.
- terminal 행은 PENDING/SENDING 조회 대상이 아니며, 사유가 DB 상태로 관측된다.
- V111 migration을 추가했다. 기존 V108~V110 파일은 편집하지 않았다.

실패의 제한 전 재시도 1건이다. Docker 재빌드·재배포·중지, DB 쓰기, 실제 vendor 발송, git 명령은
수행하지 않았다.
