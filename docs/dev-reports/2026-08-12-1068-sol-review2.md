## 9. fix2 TC-V3

### 인용 위치

현재 HEAD에 인용된 코드 선례가 실제로 있다.

- SlipFormPage.tsx:1995 — 저장 후 /sales/{created.id}
- EstimateFormPage.tsx:1729 — 저장 후 /sales/estimates/{created.id}

- SalesQueryPage.tsx:802 — /sales/{row.id}

SalesQueryPage:480의 변수는 row가 아니라 selectedRow지만 route 계약은 같다.

Issue #1094 원문에는 전표번호를 상세 화면 링크로 만들고 UUID를 숨기는 결정이 있다. 다만 **저장 직후 route를 직접 결정한 문장은 없다.** #1094는 상세 진입 UX의 보조 근거이며 저장 직후 /sales/{id}의 직접 선례는 SlipFormPage:1995와 견적 작성 흐름이다. 최종 route 판단은 코드 선례와 일치하지만 #1094 인용 범위는 이처럼 좁혀야 정확하다.

### payload 단언 뮤테이션

기준 TC-V3 통과 후 제품 코드의 deliveryAddress payload만 일시적으로 TC-V3-MUTATION으로 바꿨다. 같은 테스트는 route 단언을 지난 뒤 payload 단언 407행에서 다음과 같이 RED였다.

~~~text
Error: V20 배송주소 매칭 실패:
기대="서울시 강남구 테헤란로 123"
실제="TC-V3-MUTATION"
~~~

즉 payload 단언이 실제 실행된다. 뮤테이션은 원복했고 제품 파일 diff 없음 확인 후 TC-V3를 다시 통과시켰다.

- 기준: TC-V3 1 passed
- 뮤테이션: 의도한 payload mismatch로 1 failed
- 원복: TC-V3 1 passed

전체 TC-V1~V5 첫 실행에서는 TC-V5 진입 화면이 백지로 남아 edit button timeout 1회(4 passed, 1 failed)가 있었다. 즉시 TC-V5 단독은 1 passed, 이어 전체는 5 passed였다. 추측성 원인은 붙이지 않는다. 최종 반복에서 계보 회귀는 재현되지 않았다.
