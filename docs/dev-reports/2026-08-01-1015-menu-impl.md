# 주문서 앱 접근권한 설정 구현 보고서

## 확인 1 — 기존 구조

- 장기미사용 판정은 거래처 인증의 `lastLoginAt`, 없으면 `passwordChangedAt` 기준으로 30일을 계산한다. 이번 변경에서도 판정 기준은 유지하고 일수만 주입한다.
- 기존 `/sales/order-approvals` 화면은 거래처별 승인·거절·복구와 개별 비밀번호 초기화를 제공하지만, 기간 설정과 대상 미리보기/일괄 실행은 없다.
- 주문서 앱 접근권한 설정은 데스크톱 화면과 `partner-auth-service` 계약 안에서 구현한다. 주문서 웹 앱 및 다른 서비스 모듈은 변경하지 않는다.

### 기간 변경 수치 확인

테스트 입력은 마지막 로그인 45일 전 1건과 20일 전 1건이다. 기간 30일에서는 후보 **1건**, 60일에서는 **0건**으로 바뀌었다. 판정 기준은 마지막 로그인 우선 규칙을 유지했다.

### 미리보기 선행 확인

미리보기 후보가 아닌 거래처 코드는 업데이트 권한이 있어도 초기화 게이트가 `false`이며, 후보 코드이면서 업데이트 권한이 있을 때만 `true`이다. 실제 비밀번호 초기화 API는 실행하지 않았다.

## 변경 범위

- `partner-auth-service`: 기간별 읽기 전용 후보 계산 및 `/api/v1/partner-approvals/access-preview?unusedDays=N` 추가.
- desktop: 기존 주문서 승인현황 화면을 `주문서 앱 접근권한 설정` 단일 메뉴로 명명하고, 기간 입력·후보 수/코드/이름 미리보기·선택 후 확인 실행을 추가.
- 기존 승인·거절·조회 흐름과 권한 코드는 유지했다.
- UUID·비밀번호 값, 실 DB, Docker, 실제 비밀번호 초기화는 사용하지 않았다.

## 2026-08-01 후속 — 옛 메뉴명 보존 및 새 메뉴 연결

### 현재 구조 판정

초기 구현은 기존 `/sales/order-approvals`의 메뉴 라벨을 `주문서 앱 접근권한 설정`으로 교체하여 `주문서 승인` 메뉴 항목을 제거한 상태였다. 화면 컴포넌트와 route 자체는 남아 있었지만, 메뉴 관점에서는 옛 주문서 승인현황 메뉴가 사라진 것이므로 개발책임자 사양 A를 위반했다.

사양의 “장기미발주 거래처 선별은 거래처별 주문서 승인현황 메뉴와 연결”은 기존 메뉴를 유지한 채 같은 업무 화면으로 연결한다는 뜻이다. 따라서 최종 구조는 다음과 같다.

| 메뉴 | 경로 | 연결 화면 |
|---|---|---|
| 주문서 승인 | `/sales/order-approvals` | `SalesOrderApprovalsPage` |
| 주문서 앱 접근권한 설정 | `/sales/order-approvals` | `SalesOrderApprovalsPage` |

두 메뉴는 `AppLayout.tsx`의 `SidebarLink`와 `SalesSubNav.tsx`의 `ITEMS`에 각각 존재하고 동일 경로를 사용한다. 기간 설정(1~365일), 후보 미리보기, 확인 후 실행 및 비밀번호 초기화 안전 게이트는 변경하지 않았다.

### 실패 위치와 기대값

현재 워크트리에서 `주문서 승인`을 직접 `toContain`으로 기대하는 정확한 위치는 다음 두 곳이다.

- `clients/desktop/playwright/purchase-inspection-cta/purchase-inspection-cta.spec.ts:107`: `AppLayout.tsx` 본문에 기존 `주문서 승인` 메뉴 라벨이 있어야 한다.
- `clients/desktop/playwright/purchase-inspection-cta/purchase-inspection-cta.spec.ts:112`: `SalesSubNav.tsx`에 `label: '주문서 승인'` 항목이 있어야 한다.

두 단언은 느슨하게 바꾸지 않고 유지했다. 새 메뉴도 실제 화면에 있어야 하므로 같은 테스트에 `주문서 앱 접근권한 설정` 단언을 추가했다. 전수 검색 결과 별도 `docs/**` 본문을 읽는 `주문서 승인` 단언 스펙은 이 워크트리에 존재하지 않았고, 위 Playwright 정적 mock 스펙이 문서·소스 본문을 읽는 관련 hard gate였다.

### 수정

- `AppLayout.tsx`: 기존 메뉴 라벨 `주문서 승인`을 복원하고 새 메뉴 `주문서 앱 접근권한 설정`을 별도 항목으로 유지했다. 두 항목 모두 `showPartnerOrderList` 권한과 `/sales/order-approvals` 경로를 사용한다.
- `SalesSubNav.tsx`: 동일하게 두 라벨을 각각 `/sales/order-approvals`에 연결했다.
- `purchase-inspection-cta.spec.ts`: 두 메뉴가 모두 존재하는지 단언하도록 보강했다.
- 옛 이름 전수 sweep: `rg`로 저장소 전체를 검색했다. 옛 이름은 복원된 메뉴, API/도메인/보안 문맥, 기존 매뉴얼·결정·QA 기록 등에 남아 있으며, 새 메뉴로 잘못 대체되어야 하는 실행 코드나 별도 낡은 문서 단언은 확인되지 않았다.
