# 주문서 앱 접근권한 설정 구현 보고서

## 확인 1 — 기존 구조

- 장기미사용 판정은 거래처 인증의 `lastLoginAt`, 없으면 `passwordChangedAt` 기준으로 30일을 계산한다. 이번 변경에서도 판정 기준은 유지하고 일수만 주입한다.
- 기존 `/sales/order-approvals` 화면은 거래처별 승인·거절·복구와 개별 비밀번호 초기화를 제공하지만, 기간 설정과 대상 미리보기/일괄 실행은 없다.
- 주문서 앱 접근권한 설정은 데스크톱 화면과 `partner-auth-service` 계약 안에서 구현한다. 주문서 웹 앱 및 다른 서비스 모듈은 변경하지 않는다.

### 기간 변경 수치 확인

테스트 입력은 마지막 로그인 45일 전 1건과 20일 전 1건이다. 기간 30일에서는 후보 **1건**, 60일에서는 **0건**으로 바뀌었다. 판정 기준은 마지막 로그인 우선 규칙을 유지했다.

### 미리보기 선행 확인

미리보기 후보가 아닌 거래처 코드는 업데이트 권한이 있어도 초기화 게이트가 `false`이며, 후보 코드이면서 업데이트 권한이 있을 때만 `true`이다. 실제 비밀번호 초기화 API는 실행하지 않았다.

## 변경 범위

- `partner-auth-service`: 기간별 읽기 전용 후보 계산 및 `/api/v1/partner-approvals/access-preview?unusedDays=N` 추가.
- desktop: 기존 주문서 승인현황 화면을 `주문서 앱 접근권한 설정` 단일 메뉴로 명명하고, 기간 입력·후보 수/코드/이름 미리보기·선택 후 확인 실행을 추가.
- 기존 승인·거절·조회 흐름과 권한 코드는 유지했다.
- UUID·비밀번호 값, 실 DB, Docker, 실제 비밀번호 초기화는 사용하지 않았다.
