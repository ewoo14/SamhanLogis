## 캡처·프로세스 회수

Browser 플러그인의 연결 가능한 브라우저 목록은 빈 배열이라 해당 표면은 사용할 수 없었다. 사용자가 지정한 headless Playwright를 저장소의 `playwright.real-qa.config.ts`로 실행했고, `resolveQaShotsDir(path.resolve(here, '../../../../docs/qa/1123-s14-live-qa/screenshots'))`로 상대경로를 계산했다. 절대 캡처 경로를 하드코딩하지 않았다.

첫 실행은 미추적 로컬 스펙 안전 가드가 mutation 전에 차단했다. 가드가 지시한 `REAL_QA_ALLOW_UNTRACKED=1`과 명시 스펙 경로로 실행했으며 최종 결과는 `1 passed (3.0s)`, exit 0이다.

실행 전후 `Win32_Process`의 `node/chrome/chromium/headless_shell` PID와 command line을 비교했다. 성공 실행 뒤 새 프로세스는 0건이었다. 앞선 실패 실행 직후 보인 `node.exe` PID 32664는 재확인 시 이미 종료돼 있었다. 따라서 다른 트랙 프로세스를 죽이지 않았고 `Stop-Process`도 실행하지 않았다.
