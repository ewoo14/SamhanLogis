## 확인 1 — 결함 경로와 영향 범위

- `GET /accounting/closings/daily`의 `MonthEndCloseService.revalidateProductLines()`가 `PartnerDcConfigClient`를 호출한다.
- 일마감 실행 `POST /accounting/daily-closings` 경로와는 분리되어 있어 실행 자체는 외부 조회 장애의 직접 영향을 받지 않는다.
- 현재 FE에는 `MISSING_GLOBAL_DISCOUNT` 사유 라벨이 없어 API 상태만으로는 사용자에게 전역DC 미조회의 원인이 충분히 드러나지 않는다.

## 확인 5 — accounting 전체 테스트 1차 결과

원인은 `PartnerDcConfigClient`에 생성자가 2개인데 운영 생성자에 `@Autowired`가 없어 Spring이
