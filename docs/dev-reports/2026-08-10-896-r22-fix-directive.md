# PR #1126 R22 fix 지시서 — 중립 계열 재수렴 순서에 따른 규칙값 소실

## ① 좌표

### 지금 고칠 것

- `clients/web/estimate-app/views/index.ejs:8475-8491` — `legacyHomeQuantitiesWithoutRuleSources`가 계열별 단독 기여를 계산한 뒤 해당 계열만이 아니라 `homeQty` 전체를 공통 `legacyHomeQuantities` snapshot으로 되돌린다.
- `clients/web/estimate-app/views/index.ejs:8503-8553` — 각 `reconcileHomeFamily`는 진입 시점의 `homeQty`에서 `ruleQuantities`를 다시 읽으므로, 앞 계열의 규칙값이 위 전체 복원으로 지워진 뒤에는 복원된 legacy 값을 규칙값으로 오인한다.
- `clients/web/estimate-app/views/index.ejs:8556-8589` — 분기관→발통→호스→리모컨→판넬의 고정 호출 순서 때문에 둘 이상의 중립 계열이 동시에 규칙 target을 소유하면 뒤 계열의 단독 기여 계산이 앞 계열 결과를 되돌린다.
- `clients/desktop/src/renderer/routes/EstimateItemsCatalogPage.tsx:1004-1032` — 사용자는 각 source 행에서 서로 다른 HOME_MULTI target 규칙을 저장할 수 있다.
- `services/product-service/src/main/java/com/samhanair/logis/product/quantitysync/QuantitySyncRuleValidator.java:293-318` — 같은 조건의 REPLACE 규칙도 target이 서로 다르면 허용된다. 따라서 아래 두 규칙은 현재 사용자 저장 경로로 도달 가능하다.
- `clients/web/estimate-app/test/legacy-quantity-golden.test.js:483-623` — R22 교차계열 RED를 둘 좌표다.

`2026-08-10 13:03:06 KST` 회사 PC의 활성 HOME_MULTI 119행을 그대로 VM 경계에 주입했다. 아래 source·target 네 모델은 모두 `ACTIVE`이고 활성 `HOME_MULTI` 노출 1행이다. DB의 `quantity_sync_rule`은 0행이므로 write 없이 데스크톱 UI와 같은 `conflictPolicy=REPLACE`, factor/multiplier 1 규칙을 주입했다.

```text
입력
  AJ020BN1PBC1=5 -> AXJ-YA1509N
  AJ060MXHNBC1=1 -> PC1NWSK3NW
  옵션: 분기관 비제외 · 판넬 기본('') · 나머지 기본

evaluator
  AXJ-YA1509N=5 · PC1NWSK3NW=1

최종 계약
  AXJ-YA1509N=5 · AXJ-YA2512N=1 · PC1NWSK3NW=1

현재 최종
  AXJ-YA1509N=3 · AXJ-YA2512N=1 · PC1NWSK3NW=5

반복 3회
  [3,1,5] · [3,1,5] · [3,1,5]
```

첫 분기관 재수렴이 만든 규칙값 5는 뒤 판넬 재수렴의 전체 snapshot 복원에서 legacy 3으로 돌아간다. 판넬 재수렴은 이미 legacy 5로 돌아간 값을 `ruleQuantities`로 다시 snapshot하여 evaluator 값 1 대신 5를 최종 보존한다. 반복 안정성은 있으나 안정적으로 잘못된 값이다.

### 분리할 것

- 이번에 분리할 도달 결함은 없다. 교차계열 규칙값 소실은 현재 UI와 활성 카탈로그만으로 재현되므로 이 fix에서 닫는다.
- 분기관의 비선형 교차항 귀속은 별도 계약 판단 대상이다. 현재 production 주석과 R20 불변식은 규칙 source와 다른 source가 함께 만든 `AXJ-YA2512N=1`을 보존하도록 명시하므로, 이번 지시서는 그 값을 0으로 바꾸지 않는다.

## ② 불변식

1. 서로 다른 파생 계열이 동시에 유효한 규칙 target을 소유하면 모든 소유 target의 최종 수량은 evaluator 결과와 같아야 한다.
2. 한 계열의 재수렴 결과는 뒤에 재수렴하는 다른 계열의 중립 계산 여부나 호출 순서에 따라 바뀌지 않아야 한다.
3. 규칙이 소유하지 않은 source의 유효한 legacy 파생 수량과 source 간 legacy 교차 결과는 보존되어야 한다.
4. 제외·치환 옵션과 다섯 계열 수동 잠금은 규칙값보다 우선하는 기존 화면 계약을 유지해야 한다.
5. 규칙 0건은 순수 legacy exact 결과와 같아야 하고, 같은 입력의 반복 재계산은 누적·소실 없이 같은 결과여야 한다.

## ③ 양방향 RED

### RED-A — 교차계열 소유 target 보존

- 위 실 카탈로그 입력과 두 UI 규칙에서 evaluator와 최종 `AXJ-YA1509N=5`, `PC1NWSK3NW=1`이 일치해야 한다.
- 같은 입력의 비소유 분기관 `AXJ-YA2512N=1`은 남아야 한다.
- 규칙 배열 순서를 뒤집거나 재계산을 3회 실행해도 최종 `{AXJ-YA1509N:5, AXJ-YA2512N:1, PC1NWSK3NW:1}`이 같아야 한다.

### RED-B — RED-A의 반대급부

- R21 부분 source 소유 다섯 표본의 비소유 legacy 수량은 사라지지 않아야 한다.
- source 하나가 한 중립 계열 target만 소유할 때 같은 source의 legacy 대체품이 다시 중복되어서는 안 된다.
- 서로 다른 두 source가 각각 소유한 리모컨 target은 `AWR-WE13N=2`, `AWR-WG00N=3`, 비소유 기본 리모컨 `AR-EC05=0`을 유지해야 한다.
- 호스·판넬·리모컨 치환과 분기관·발통 제외에서 기존 옵션 결과가 유지되어야 한다.
- 호스·판넬·리모컨·분기관·발통의 수동 잠금 77과 규칙 0건 golden exact 결과가 유지되어야 한다.
