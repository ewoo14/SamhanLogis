# 2026-08-01 T1009 판정 방식 실제 품목 데이터 불일치 조사

## 1. 조사 범위와 판정식

- 출발점: `docs/dev-reports/2026-08-01-1009-estimate-recon-r2.md` §4.
- 방식 1은 `clients/web/estimate-app/views/index.ejs:2334-2360`의 `getModelFlags()`를 그대로 적용한다. 모델코드를 대문자로 바꾼 뒤 AC의 8·9번째 문자로 360/4way/1way, AP의 9·11번째 문자로 stand/deluxe, AC/AP의 9번째 `F`로 1등급을 판정하며, `AP230`/`AP290` 접두는 stand=true·deluxe=false로 덮어쓴다.
- 방식 2는 `services/product-service/src/main/java/com/samhanair/logis/product/service/VariableDiscountDetector.java:40-46,111-122`를 그대로 적용한다. 모델 문자열 전체에서 대소문자 무시 `360`, `4way`, `1way`, `stand|스탠드`, `deluxe|디럭스`, `1등급|grade.?1|G1` 포함 여부를 판정한다.
- 집계 단위는 `product_db.products`의 실제 행이다. 동일 모델코드가 여러 행이면 품목 행 수대로 센다.

## 2. 데이터 출처와 모집단

- 2026-08-01 조사 시점에 실행 중인 `samhan-postgres`의 로컬 `product_db`에 `products` 테이블이 실제로 존재해, 모든 SQL을 `BEGIN TRANSACTION READ ONLY`로 감싸 조회했다. Docker 재빌드·재기동 및 DB 쓰기는 하지 않았다.
- `products`는 전체 1,226행, 활성(`is_deleted=false`) 1,220행이다. 현행 품목을 비교하기 위해 아래 표의 모집단은 **활성 1,220행**으로 고정했다.
- 활성 1,220행 중 `model_code IS NULL`은 100행, 빈 문자열은 0행, non-null 고유 모델코드는 1,120개다. NULL 모델코드는 두 방식 모두 여섯 축 전부 false로 판정한다.

## 5. `AP230`·`AP290` 실제 예외 품목

- 활성 품목은 총 **6건**이다: `AP230DAPDHH1S`, `AP230DNPDHH1`, `AP230DXPDHH1`, `AP290DAPDHH1S`, `AP290DNPDHH1`, `AP290DXPDHH1`.
- 방식 1은 예외 덮어쓰기로 6건 모두 `stand=true`, `deluxe=false`로 판정한다.
- 방식 2의 현행 문자열 detector는 여섯 코드 어디에도 `stand|스탠드` 또는 `deluxe|디럭스`가 없으므로 6건 모두 stand=false·deluxe=false다. DB에 저장된 `discount_flags`도 여섯 건 모두 `000000`이다.
- 따라서 이 예외 6건은 stand 축에서 전부 `방식1만 참`이며, deluxe 축에서는 둘 다 거짓이다. 특히 코드의 9번째가 `D`, 11번째가 `H`여도 AP230/AP290 덮어쓰기 때문에 방식 1의 deluxe는 false다.

## 6. 금액 영향 경로

### 6.1 정액 설정의 실재 여부

- 로컬 `dc_config_db.dc_configs`의 활성 설정은 210건이다. 6종 정액이 0보다 큰 설정 수/실제 범위는 360 **45건/20,000~70,000원**, 4way **46건/20,000~80,000원**, 1way **45건/20,000~60,000원**, stand **45건/20,000~70,000원**, deluxe **15건/10,000~30,000원**, 1등급 **10건/20,000~40,000원**이다. 즉 판정 차이는 0원 설정에만 머무는 이론적 문제가 아니다.

### 6.2 코드상 금액 경로

1. web 종합견적서는 `singleUnitPrice()`와 `adjustSingleSetBasePrice()`에서 `getModelFlags(model)` 결과를 읽고, 참인 축의 정액을 순서대로 차감한다 (`clients/web/estimate-app/views/index.ejs:3250-3277,4388-4412`). 따라서 방식 1 판정이 화면 단가에 직접 들어간다.
2. product-service의 `VariableDiscountDetector.detectDiscountFlags()` 결과는 seed/sheet sync 때 `products.discount_flags`에 저장된다 (`ProductSeedRunner.java:218`, `ProductSheetSyncService.java:1236,1257`). product summary가 이 값을 내보내고 (`ProductSummaryResponse.java:118-140`), partner-order 확정은 여섯 비트를 `DcConfigClient.PriceLine`으로 전달한다 (`PartnerOrderConfirmService.java:187-209`).
3. dc-config-service는 `OTHER` 라인에서 참인 축의 설정액을 합산해 기준가에서 빼고 반올림한다 (`PriceCalculationService.java:59-67,120-143`). `HOMEMULTI`/`COMMERCIAL_MULTI`에는 6종 정액을 적용하지 않으므로, 멀티 품목의 플래그 불일치는 이 서버 계산 경로에서는 0원 차이다.
4. 중요한 현행 완충 장치가 있다. `PartnerOrderConfirmService.resolveDiscountFlags()`는 저장 비트가 `000000`이면 방식 1의 위치 규칙을 다시 계산한다 (`PartnerOrderConfirmService.java:355-411`). 그러므로 **방식 1만 참인 품목은 현재 partner-order 확정 경로에서 대체로 복구된다.** 반대로 non-zero 저장 비트는 우선하므로 방식 2만 참인 `AM360...` 8건은 비트가 유지되지만, 이들은 멀티 계열이라 위 3번의 멀티 정액 제외로 금액 차가 0원이다.
   - DB 재확인: `AM360...` 8건은 모두 `discount_flags=100000`, `product_category=COMMERCIAL_MULTI`다(7 BUNDLE, 1 SINGLE). 따라서 “저장 비트 유지”와 “멀티 정액 제외”는 실제 행에도 그대로 해당한다.

### 6.3 대표 실제 품목 계산

- 실제 품목: `AC060CS4PBH2SY`(무풍 4way 냉난방 프레스티지), 활성 `SINGLE_SET`/`BUNDLE`, 실제 `delivery_price=1,510,000원`, 저장 `discount_flags=000000`.
- 실제 설정 사례: 활성 거래처 코드 `2148720659`의 `discount_4way_amount=80,000원`, `unit_round_to=NULL`, 반올림 모드 `ROUND`.
- 방식 1: 모델 8·9번째가 `4P`이므로 4way=true. `1,510,000 - 80,000 = **1,430,000원**`.
- 방식 2를 독립 적용: 코드에 `4way` 문자열이 없으므로 4way=false. `1,510,000 - 0 = **1,510,000원**`.
- 판정 방식만 바꿨을 때 대표 차이는 **80,000원/대**이며, 수량 `q`이면 **80,000×q원**이다. 다만 현재 partner-order 실제 실행은 위 완충 로직이 `000000`을 방식 1로 재판정하므로 이 사례의 서버 확정액도 1,430,000원으로 복구된다. 즉 80,000원은 “두 detector를 각각 그대로 가격식에 넣은 차이”이고, 현재 partner-order의 최종 관측 차이는 이 사례에서 0원이다. web 화면은 방식 1이므로 1,430,000원이다.

## 7. 최종 재검증

- 완료 직전 동일한 read-only 집계를 다시 실행해 `360 1220|17|8|0|1195`, `4way 1220|50|0|0|1170`, `1way 1220|33|0|0|1187`, `stand 1220|73|0|0|1147`, `deluxe 1220|8|0|0|1212`, `1등급 1220|39|0|0|1181`을 재확인했다.
- AP 예외는 `6건/discount_flags=000000 6건`, 대표 품목은 `delivery_price=1,510,000원`, 대표 설정은 `discount_4way_amount=80,000원`, `unit_round_to=NULL`, `ROUND`로 재확인했다.
- 문서 예시 개수 검증: 360 18개, 4way 10개, 1way 10개, stand 10개, deluxe 8개(전체가 8건), 1등급 10개.
