### 저장·조회 경로 전수 확인

- `SalesAggregateService.aggregate(..., partnerCode)`에서 선택 거래처 경로는 기존 `find(from, to, null, partnerId)` 1회 호출을 유지한다.
- 같은 메서드의 무필터 경로는 기존 `byPartner.keySet()`별 호출을 제거하고 `find(from, to, null, null)` 기간 전체 조회 1회로 바꾼다. 이후 `partnerCode`로 journal 후보와 내부 조인하고, 미매칭/공백 전표를 code-only 행으로 보존한다.
- `PartnerLedgerReadService`의 상세 원장 경로는 변경하지 않았다. 기존처럼 선택 시 UUID, 무필터 시 null partnerId를 `PartnerLedgerSalesClient`에 전달한다.
- 저장 API, slip-service, `PartnerLedgerSalesClient`의 JSON 외부 계약은 변경하지 않았다. 따라서 slip-service 테스트 실행 대상 변경은 없다.

### 이번 fix가 새로 만든 표면

1. 무필터 집계 원천을 `journal 후보 집합`에서 `journal 후보 ∪ 기간 내 원장 대상 판매전표 집합`으로 확장했다.
2. journal 후보와 전표가 모두 있는 경우 `partnerCode`를 내부 조인 키로 사용해 기존 UUID aggregate 한 행의 매출만 교체한다. 같은 거래처를 두 번 출력하지 않는다.
3. partner master에서 해소되지 않는 `partnerCode`는 code-only 행으로, `partnerCode`가 비어 있는 전표는 전표번호를 내부 그룹 키로만 사용한 `-` 표시 행으로 남긴다. 화면 응답 `SalesAggregateRow`에는 UUID나 전표번호를 추가하지 않았다.

### 값이 바뀌거나 새로 나타나는 거래처

실 DB `2026-06-24`에는 journal 후보가 0건이므로 기존 journal aggregate의 값이 바뀐 거래처는 **0건**이다. 이번 fix로 다음 두 legacy code-only 행이 새로 나타난다.

| 거래처 표시 키 | fix 전 | fix 후 | 근거 |
|---|---:|---:|---|
| `QA-GATE-A` | 집계 행 없음 | 활성 1라인·2,400,000원 | 실 DB COMPLETED 전표 `2026/06/24-901`, `partner_id` NULL, `partner_code` 존재 |
| `QA-GATE-B` | 집계 행 없음 | 0원 | 실 DB COMPLETED 전표 `2026/06/24-902`, `partner_id` NULL, 활성 line 0 |

두 code는 partner master active 대응이 0/2=0%이므로 master UUID로 억지 조인하지 않고 code-only로 표시한다. 기존 journal+slip 중복 방지는 단위 fixture `P-001`에서 journal 20,000,000원과 slip 12,276,000원을 **한 행**으로 12,276,000원에 교체하는 테스트로 확인했다. 이 `P-001` 수치는 실 DB 변경 수치가 아니라 중복 방지 회귀 fixture다.

### Linux 판정

- 이 단정이 Linux(`ubuntu-latest`)에서도 참인가: **참이어야 한다.** 변경 Java 코드는 JDK 표준 `LocalDate`, `BigDecimal`, `LinkedHashMap`, `HashSet`만 사용하고 Windows 경로·셸 API·줄바꿈에 의존하지 않는다.
- 이 단정이 Linux에서 참인가: **참이어야 한다.** JUnit/Mockito 회귀 테스트는 Gradle 표준 테스트 경로이며, `SalesAggregateServiceTest` 최종 11건 GREEN은 Windows에서 실행했지만 코드상 OS 종속 요소가 없다.
- 이 단정이 Linux에서 참인가: **PostgreSQL 계약 기준 참이어야 한다.** 실 DB SQL은 PostgreSQL 문법이며 실행 래퍼만 `docker exec -c`이다. Ubuntu CI에서는 동일 SQL을 PostgreSQL 서비스 컨테이너에 전달하는 경로로 재현할 수 있다. 실제 ubuntu-latest 실행 결과는 이 워크트리에서 확보하지 않았고 CI를 권위로 남긴다.
