## 2. 결함 — 새 real-QA 스펙이 BrowserRouter 실배포 하네스 목록에 없다

구현자 설명대로 새 스펙과 config가 Git 추적 상태인지 확인했고, `real-qa-scope.test.cjs`도 **51/51 PASS**했다. 그러나 그것은 디스크/추적 수집 범위 계약이다. 전체 desktop 테스트에는 별도의 BrowserRouter 계약이 있다.

재현:

```text

Test Files  1 failed
Tests       1 failed | 61 passed (62)

1163-fix3-real-qa/1163-fix3-live-real-qa.spec.ts
expected [Array(1)] to deeply equal []
```

원인은 다음과 같다.

- 새 스펙은 `build:web 는 BrowserRouter를 사용한다`고 명시하고 실제로 `history.pushState()`로 route를 전환한다.
- [`harness-false-green-guard.test.ts`](../../clients/desktop/src/renderer/test-utils/harness-false-green-guard.test.ts)의 `WEB_DEPLOY_REAL_QA`에는 `1163-fix3-real-qa/1163-fix3-live-real-qa.spec.ts`가 없다.
- G6는 `BrowserRouter` 자기 진술 파일이 이 목록에 없으면 실패하도록 설계돼 있고, 이번 파일을 정확히 검출했다.
- `origin/main...HEAD`에서 이 guard의 등록 목록 변경은 없다.

즉, “새 real-QA 스펙 미등록은 tracked로 해소됐다”는 설명은 절반만 맞다. Git 추적/공식 수집 계약은 해소됐지만, BrowserRouter 실배포 하네스 계약은 해소되지 않았다.
