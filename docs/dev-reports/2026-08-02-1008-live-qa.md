## ② 실행 방식

- DB: 기존 `accounting_db`에 접속하되 `SPRING_FLYWAY_ENABLED=false`, `SPRING_JPA_HIBERNATE_DDL_AUTO=none`으로 실행하여 공유 DB에 DDL/write를 수행하지 않았다.
- Eureka: 기존 `http://localhost:8761/eureka/`에 standalone 회계 서비스를 등록했다. 이는 별도 jar 인스턴스 증명을 위한 서비스 등록이다.
- 프론트: `clients/web/design-system`에서 `npm install` 및 `npm run build` 후 desktop web dist를 빌드했다. 최초 desktop 빌드는 design-system dist 부재로 실패했으며, design-system 빌드 후 재시도하여 성공했다.
- 실제 화면 서버: `vite.renderer.dev.config.ts`(HashRouter) + `VITE_APP_VERSION=2026/08/02-1008`, `VITE_API_BASE_URL=http://127.0.0.1:18486`, `http://127.0.0.1:5186`.
- 브라우저: in-app Browser는 사용 가능한 브라우저가 없어 연결 실패했다. 저장소의 로컬 Playwright(`clients/desktop/node_modules/.bin`)와 설치된 Chrome 실행 파일로 실제 브라우저 화면을 열어 캡처했다.
- 로그인: 공유 auth login으로 `dev_master` 세션을 얻고, 브라우저 화면의 standalone 요청에는 gateway가 downstream에 주입하는 인증 헤더를 동일하게 전달했다. JSON 응답을 QA 증거로 캡처하거나 보고서에 대체하지 않았다.

standalone의 최초 read-only 기동 시 schema validation 원문:

위 이유로 Flyway와 Hibernate schema validation을 끄고 재기동했다. 이후 jar는 health/listener 기준 정상 기동했다.
