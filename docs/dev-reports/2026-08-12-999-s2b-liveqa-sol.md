# #999 S2b QR·재고수불부 라이브 QA — CODEX SOL

## 결론

**실 사용자 경로에서 재현되는 결함이 있는지는 판정하지 못했다.**

격리 복제본의 QA 표본을 준비한 직후 데이터 자리에 `?`가 확인되어, 개발책임자의 “데이터 자리에 `?`가 보이면 즉시 멈추고 보고” 지시에 따라 GUI 진입 전에 검증을 중단했다. 따라서 통과도 결함 0건도 선언하지 않는다.

## 증거 무결성

- 공유 DB에는 쓰지 않았다.
- 공유 `inventory_db`·`partner_db`·`product_db`를 `pg_dump -Fc` 파일로 덤프한 뒤 격리 PostgreSQL `sol999-s2b-pg-20260812232834`에 `pg_restore`했다.
- 현재 브랜치의 `inventory-service.jar`를 격리 DB에 연결해 실행했고, 제품 조회도 격리 `product_db`를 사용하는 별도 제품 서비스로 구성했다.
- 인앱 Browser 런타임은 `[]`였고 연결 진단까지 완료했다. 지시대로 실행 불가로 판정하지 않았으며 Playwright Chromium 실행 준비 중이었다.
- GUI 검증용 출고 태그 표본을 PowerShell 표준입력으로 격리 DB에 넣은 직후 한글이 `?`로 변형됐다. 이 표본은 신뢰할 수 없으므로 이후 검증 증거로 사용하지 않았다.

복제 직후 한글 확인 원문:

```text
(주)한국냉동물류
(주)서울택배
대한화물서비스(주)
```
