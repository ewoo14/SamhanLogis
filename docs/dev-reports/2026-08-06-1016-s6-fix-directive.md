## ② 불변식 — 사용자에게 참이어야 하는 결과만 고정하며 구현 수단은 지정하지 않음

1. 페이지가 유지되는 모든 상태에서 현재 `VIEW=true`, `UPDATE=false`이면 sync 버튼은 비활성화되고 sync POST는 발생하지 않아야 한다.
2. 현재 `UPDATE=false`이면 마지막 mutation이 idle·200·403·500·네트워크 오류·null 중 무엇이든 동기화 또는 재시도를 지시해서는 안 된다. 사용자는 현재 권한이 없다는 원인과 권한 요청이라는 다음 행동을 즉시 볼 수 있어야 한다.
3. 이전 결과 chip·실패 목록을 보존하더라도 현재 권한 설명과 충돌해서는 안 된다. 과거 결과가 현재 실행 권한을 의미한다고 오해하게 만들면 안 된다.
4. 현재 `UPDATE=true`이고 마지막 오류가 5xx·네트워크·null이면 기존 재시도 경로가 유지되어야 한다. 권한 전환 처리가 정상 재시도를 막거나 권한 오류로 오표시하면 안 된다.
5. 서버가 403을 확정한 상태에서는 현재 FE 권한 캐시가 UPDATE를 허용해도 버튼이 잠겨야 하며, 권한 요청 후 화면 새로고침 안내가 유지되어야 한다.
6. 403 뒤 실제 권한이 부여되고 화면을 새로고침하면 이전 403 상태가 남지 않아야 한다. 버튼이 다시 활성화되고 다음 POST가 정상 결과를 표시해야 한다.
7. `NOT_DELIVERED`는 mock 미전달 문구와 신규·변경 0건, `DELIVERED`·`PARTIALLY_DELIVERED`는 mock 미전달 문구 숨김과 실제 건수 표시를 유지해야 한다.
8. CSV 다운로드가 알리고 전달 완료의 증거가 아니라는 고지는 권한·응답·전달 상태 전 조합에서 유지되어야 한다.

## ③ 양방향 RED — 반대급부 필수

### RED-A — 5xx 뒤 UPDATE 회수와 재부여

- 같은 mount에서 `VIEW=true`, `UPDATE=true`로 sync POST를 1회 보내 HTTP 500을 받는다.
- 500 직후에는 버튼 enabled, 일반 재시도 안내, 권한 오류 없음이어야 한다.
- 페이지를 remount하지 않고 권한만 `VIEW=true`, `UPDATE=false`로 갱신한다.
- 버튼 disabled, 권한 부재 원인 표시, 일반 재시도 안내 숨김, sync POST 호출 수 1회 유지가 아니면 RED다.
- 반대급부: 같은 mount에서 UPDATE를 다시 부여하면 403 lock이 아닌 이상 버튼과 재시도 경로가 회복되고, 두 번째 클릭이 기존 POST를 호출해야 한다.

### RED-B — null·200 결과 뒤 UPDATE 회수

- HTTP 200 + `data=null` 뒤 UPDATE를 회수하면 버튼은 disabled이고 권한 부재 원인이 보여야 하며 “잠시 후 다시 시도”만 남으면 RED다.
- `NOT_DELIVERED`, `DELIVERED`, `PARTIALLY_DELIVERED` 200 결과를 각각 표시한 뒤 UPDATE를 회수해도 현재 권한 부재 원인이 보여야 한다. 기존 결과 chip·실패 목록·CSV 고지는 남아야 한다.
- 반대급부: UPDATE가 계속 있는 null 경로에서는 버튼 enabled와 재시도 가능 상태가 유지되고, 다음 200 정상 응답으로 회복해야 한다.

### RED-C — 403 전용 잠금과 정상 오류 반대급부

- UPDATE 표시 상태에서 서버 403을 받으면 권한 원인·새로고침 안내·버튼 disabled가 유지되어야 한다.
- 실제 권한 부여 후 전체 화면 새로고침으로 버튼 enabled가 되고, 다음 200 응답 결과가 표시되지 않으면 RED다.
- 반대급부: 403이 아닌 500·네트워크 오류·null을 받은 안정된 UPDATE 사용자의 버튼까지 잠기거나 권한 오류가 보이면 RED다.
- 전달 상태 3종과 CSV 고지는 S1·S3 행렬 그대로 다시 통과해야 한다.
