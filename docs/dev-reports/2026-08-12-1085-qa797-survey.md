1. 전표/견적/최근단가는 반드시 QA797 전용 상품 UUID에서 시작한다.
2. 이미 `is_deleted=true`인 행, 특히 `deleted_by='qa-residue-softdelete-2026-08-12'`인 333라인·192전표는 재처리하지 않는다.
3. 전표 헤더는 현재 활성 0건이다. 후속 대상은 우선 활성 자식 라인 10행이며, 감사/리비전 보존 정책을 별도로 정해야 한다.
4. 견적은 활성 부모 25건과 활성 라인 53행을 같은 단위로 검토해야 한다.
5. 최근단가는 활성 8행이다.
6. 회계는 `slip_no`만으로 삭제하지 않는다. 물리 FK 부재, 선행 생성, 거래처 불일치, 동일 번호 INBOUND 전표 존재 때문에 별도 판별식 승인이 필요하다.

## 9. 무삭제 확인

- DB: 실행한 DB 문장은 모두 `SELECT` 또는 `psql` 메타데이터 조회였다. `DELETE`, `UPDATE`, `INSERT`, `TRUNCATE`, DDL은 0회다.
- 서비스: 서비스/컨테이너 재시작 0회, 로그인 0회, 화면 접근 0회다.
- 파일: 이 보고서 1개만 신규 작성했다. `Remove-Item`, 파일 삭제, 이동, 덮어쓰기 명령은 0회다.
- git: 사용자 금지에 따라 git 명령을 실행하지 않았다. 따라서 git 기반 삭제 추적 검사는 하지 않았으며, 실행 명령 검토상 삭제된 추적 파일은 없다.
