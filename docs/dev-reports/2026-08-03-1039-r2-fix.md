# #1039 가배차 8개 실행 모드 — R2 fix

## 범위와 결론

PR #1045 (`feat/1039-provisional-dispatch`, HEAD `5afc31178`)의 적대검증 R1에서 확정된 7건을 모두 수정했다. 이번 수정은 warehouse 업무 구분, inventory 장애, 야적 우선, 공통 제외, 저장·복원 화면 상태를 다룬다.

공유 DB write/DDL, git 쓰기 명령, Docker image rebuild는 수행하지 않았다. 공유 Docker는 PR 이전 이미지이므로 실제 HTTP 화면 E2E는 실행하지 않았다.

## 업무 구분의 권위와 provenance 판정 (A/B)

권위 출처는 표시명이나 UUID가 아니라 legacy warehouse code다.

- legacy 원문: `tools/legacy-gas/*/Code.js:1829-1833` — `00003=초월창고`, `2=상일물류` 업무 구분.
- 현행 발행 원천: `services/slip-service/src/main/resources/application.yml:187-191`(기본) 및 `:230-234`(local)의 `app.publish.warehouse-code-map` — legacy code를 내부 UUID로 바꾸는 설정. 이 설정은 표시명 재분석에 사용하지 않는다.
- 수정 후 판정: `services/slip-service/src/main/java/com/samhanair/logis/slip/publish/WarehouseCodeMapper.java:101-106`의 `businessType(String)`이 원천 code `00003`=CHOWOL, `2`=SANGIL만 판정하고 나머지는 `UNKNOWN`으로 둔다.
- 신규 저장: `services/slip-service/src/main/java/com/samhanair/logis/slip/domain/Slip.java:165-169`의 `source_warehouse_code`와 `SlipPublishService.java:150,230,329`의 세 발행 경로. UUID와 inventory 표시명은 업무 구분의 출처가 아니다.

기존 2,303행은 현재 DB에서 `source_warehouse_id`만 보유하고 발행 당시 warehouse code가 저장되어 있지 않다. UUID가 현재 설정의 네 UUID 중 2,299건에 매칭되고 inventory 표시명도 조회되지만, 그것은 발행 당시 code provenance를 복원하는 증거가 아니다. 따라서 V62 적용 후 기존 2,303행의 `source_warehouse_code`는 모두 NULL이고 업무 구분은 전부 `UNKNOWN`이다. 추측 backfill은 하지 않았다. 4건의 미매칭 UUID도 별도 확정 대상에 합산하지 않았다.
