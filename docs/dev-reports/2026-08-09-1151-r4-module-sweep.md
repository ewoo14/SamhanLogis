## ② slip-it-core

R3의 304초 제한은 통과가 아니라 timeout이었다. 이번에는 범위를 나눴다.

| 분할 범위 | 결과 원문 |
|---|---|
| comment + estimate + estimate collab + estimate snapshot | `BUILD SUCCESSFUL in 1m 55s` |
| `slip.it` 직속 52개 IT | 최초 `471 tests completed, 1 failed`; `SlipControllerIT.complete_outbound_callsInventoryDeduct_withFromReservationTrue`의 6→7번째 `sourceContext` matcher 누락을 보완한 뒤 재실행 `BUILD SUCCESSFUL in 7m 12s` |
| dispatch + collab + cutoff + schedule + repository.dispatch | `BUILD SUCCESSFUL in 3m 9s` |

첫 base 실행에서 발견된 matcher 1건도 기존 단정은 유지하고 `any(SourceOperationContext.class)`만 추가했다. 따라서 slip-it-core는 timeout으로 넘기지 않고 분할 범위 전체에서 실패 0으로 판정했다.
