판정: 테스트의 기대값(200과 45%)이 낡은 것이 아니다. 구현 변경으로 `MonthEndCloseService`가 새 `PartnerDcConfigClient`를 호출하게 되었는데 `DailyClosingRevalidationIT`에는 이 외부 client의 `@MockBean`/stub이 없어 실제 서비스 탐색으로 빠지고 500이 발생했다. 즉 실패 원인은 구현-IT fixture 계약 누락이며, 실패를 느슨하게 만들거나 500을 기대하도록 바꾸지 않는다.

### 단일 가설

`PartnerDcConfigClient.findByPartnerCode()`를 IT에서 `LookupResult.notFound()`로 격리하면, 고정DC 45%가 있는 세 경로는 기존 기대값 45%/VERIFIED를 그대로 만족할 것이다. 이는 전역DC 미존재를 45%로 대체하는 수정이 아니라, 고정DC 우선 순서와 C 불변식을 동시에 검증하는 fixture이다.

## 확인 5 — 전체 모듈 첫 실행

실행 명령:

```text
.\gradlew.bat :services:accounting-service:test --no-daemon --console=plain
```

120초 제한으로 프로세스가 종료되어 결과는 `command timed out after 124042 milliseconds`이다. 이 실행은 전체 통과 증거가 아니며, 아직 전체 모듈 결과를 통과로 판정하지 않는다.

재시도는 이전 제한 종료 시 남은 Gradle/JUnit 프로세스가 `build/test-results/test/binary/output.bin`을 잠가 `Unable to delete directory`로 즉시 실패했다. 해당 실행에서 생성된 이 워크트리의 Gradle/JUnit 프로세스만 종료하고 재실행한다.

## 확인 7 — 불변식 C

`DiscountRevalidatorTest.missingGlobalDiscountIsVisible`를 포함한 대상 단위 테스트를 별도 실행했다.

```text
.\gradlew.bat :services:accounting-service:test --tests 'com.samhanair.logis.accounting.service.DiscountRevalidatorTest' --no-daemon --max-workers=1 --console=plain

BUILD SUCCESSFUL in 12s
```

구현 경로는 전역DC 조회 결과가 `NOT_FOUND`이면 `GlobalDiscount.unavailable()`로 전달하고, 고정DC도 없을 때 `expectedRate=null`, `status=MISSING_GLOBAL_DISCOUNT`를 반환한다. 따라서 전역DC 미조회가 조용히 45%로 흘러가지 않는다. 이번 IT fixture는 고정DC 45%가 있는 상품에만 전역DC `NOT_FOUND`를 주므로 고정DC 우선 순서로 45%가 유지되는 C와 A를 함께 검증한다.
