## 0. 🚨 "완전계승" 의 정의 (개발책임자 확정, 2026-07-31)

> **기능 및 표현 데이터를 그대로 복사한다는 뜻이다. 다만 반드시 같은 디자인을 유지할 필요는 없다. 우리 프로그램에 맞는 디자인 사용도 가능하다.**

| 반드시 같아야 하는 것 | 달라도 되는 것 |
|---|---|
| **기능** — 원본이 하는 일, 계산 규칙, 처리 흐름 | 레이아웃 · 색 · 컴포넌트 · 화면 구성 |
| **표현 데이터** — 화면에 나오는 **항목·값·집계 결과** | 그 항목을 **어떻게 보여줄지** |

### 이 정의가 판정에 미치는 영향

- **"화면이 다르게 생겼다" 는 미계승 근거가 아니다.** 같은 데이터를 우리 디자인 시스템으로 보여주면 계승이다.
- **"항목이 빠졌다 · 값이 다르다 · 집계 결과가 다르다" 는 미계승이다.** 실행 대조는 **숫자와 항목**을 본다.
- 우리 디자인 시스템(`design-system`) 컴포넌트를 쓰는 것이 **권장**된다. 레거시 GAS 의 HTML 을 그대로 옮기지 않는다.

⚠️ **예외** — **인쇄 양식**(전표·거래명세서·세금계산서)은 이 저장소의 기존 규율대로 **legacy 100% 매칭**이 유지된다. 위 디자인 자유는 **조회·분석·관리 화면**에 적용된다.

## 2-A. 🚨 종합견적서(22) — "완전계승" 이 원본 복제를 뜻하지 않는다

**개발책임자 추가 사양 (2026-07-31)**

> `견적서` 메뉴는 종합견적서에서 **`견적저장`** 시의 **DB 역할**을 한다(레거시는 **Notion 에 base64 형태로 저장**).
> **현 GAS 와 달리** 그 견적서 목록에서 **내 것은 수정 가능**하고, **다른 사람 것도 조회 가능**하다.

즉 우리 `견적서` 메뉴는 원본의 저장 기능을 **그대로 옮긴 것이 아니라 개선한 것**이다. 레거시는 저장만 하고 수정이 안 됐다.

### 이것이 판정에 미치는 영향

판정표는 live `Code.js` 앞부분의 **구형 helper 12개 중 8개 미대응**을 근거로 22 를 판정불가로 내렸다. 그런데 그 helper 중 상당수가 **Notion 저장·이력 계열**이다 — `saveFilterWordsToNotion` · `getFilterWordsFromNotion` · `saveClientCodesToNotion` · `getClientCodesFromNotion` · `compressString` · `decompressString` · `autoSaveResultToNotion` · `getHistoryFromNotion` · `getSpecificHistory` · `getLatestHistoryFromNotion`.

⟹ **`compressString`/`decompressString` 은 base64 압축 저장을 위한 수단**이고, `*Notion*` 계열은 **저장소가 Notion 이었기 때문에 필요했던 것**이다. 우리는 저장소를 DB 로 바꾸고 수정·조회까지 얹었으므로, **그 helper 들을 다시 만드는 것은 계승이 아니라 퇴행**이다.

### 그래서 착수 전에 갈라야 할 것

| 분류 | 처리 |
|---|---|
| **저장소가 Notion 이라서 필요했던 helper** (압축·Notion 저장/조회) | **계승 대상 아님** — 우리 DB + 수정/조회가 이미 상위 대체 |
| **업무 규칙을 담은 helper** (필터 단어 · 거래처 코드 집합 등 **무엇을** 저장했는지) | **계승 대상** — 그 데이터가 지금 어디에 있는지 확인 필요 |
| **`getUserAuth` · `getChatMapData`** | 별도 판단 — 현행 대응물 존재 여부 확인 |

**helper 8개를 "미대응" 이라는 이유만으로 전부 만들면 안 된다.** 실행 대조 라운드에서 **각 helper 가 담은 업무 규칙**을 기준으로 다시 갈라야 한다.

### 계승 완료의 정의 (22)

1. 종합견적서의 **견적 계산·가격 규칙**이 원본과 같은 결과를 낸다
2. `견적저장` 이 **DB 에 저장**되고, 목록에서 **본인 것 수정 · 타인 것 조회**가 된다
3. 원본 helper 중 **업무 규칙을 담은 것**의 데이터가 우리 쪽에 존재한다
4. ~~Notion 저장·base64 압축 재현~~ ← **하지 않는다**

## 3. 일마감(18) 실행 대조 결과 — 이미 나온 갭

실행 대조 1호가 **부분계승** 으로 판정했다.

| 대조 | 결과 |
|---|---|
| 멀티 품목 **고정DC** 검증 | ✅ **계승** — 숫자 차이 0 |
| 거래처 **전역DC 48%** | ❌ 현행은 거래처를 입력받지 않고 항상 **45%** 를 기대율로 사용 → **3%p 차이**, 판정이 정상(`true`) ↔ 불일치(`false`) 로 **반대** |
| 싱글 1way **옵션 정액 DC 50,000원** | ❌ 현행은 `AC\|AP\|AR\|AF\|PC\|AWR\|ARR` 접두를 `OUT_OF_SCOPE` 로 즉시 반환 → 산출 자체가 없음 |

### 🔑 이 갭은 PR #991 이 지금 다루는 결함과 같은 것이다

PR #991 의 적대검증이 낸 **B-05**(싱글 옵션 정액 DC 50,000원 미독)와 **B-06**(멀티 전역DC 48% 대신 45% 상수)이 **정확히 같은 지점**이다. 서로 다른 두 경로(레거시 실행 대조 / 적대검증)가 같은 결함을 가리켰다.

⟹ **일마감 완전계승은 #991 의 B-05·B-06 을 흡수하는 형태로 설계한다.** 별도 트랙으로 중복 구현하지 않는다.

### 확인하지 못한 것

- 원격 GAS 실행은 **Execution API 미배포 + 브라우저 부재**로 불가능했다. 대조는 **원본 코드 공식 + 실제 전역DC DB 값**을 결합한 결정론적 대조이며 **원격 실행값이 아니다.**
- `accounting_db` 에 해당 거래처 행이 0건이라 현행 라이브 API 호출로는 재현하지 못했다.
