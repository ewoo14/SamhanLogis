# #903 문서 양식 저작 방식 선택 — 워드 방식 / 엑셀 방식 (조기 PR)

- 작성일: 2026-07-30 (집PC 세션)
- 브랜치: `feat/903-template-authoring-mode`

## 1. 이 트랙이 답해야 할 것

이슈는 *"문서 양식 저작 방식 선택 — 워드 문서 방식 / 엑셀 방식(엑셀 라이브러리)"* 입니다.
**무엇을 만드는지가 아직 정해져 있지 않습니다.**

지금 이 저장소에는 **밴드 캔버스 기반 편집기**가 이미 있습니다 — `DocumentTemplateEditorPage` ·
`ElementInspector` · `DocumentRenderer` · `templateSchema`. 방금 #990 에서 이미지 표면을
적대검증까지 마쳤습니다.

⟹ **기존 편집기를 대체하려는 것인지, 나란히 두려는 것인지**가 먼저입니다.

## 2. 정찰 질문 (구현 전에 답한다)

1. **현재 편집기가 무엇을 할 수 있고 무엇을 못 하는가.** 밴드·요소 타입·좌표 배치·이미지·인쇄
   경로를 실제 코드로 정리한다. **못 하는 것이 이 이슈의 동기**일 가능성이 높다.
2. **"워드 방식" 과 "엑셀 방식" 이 각각 무엇을 뜻하는가.** 이 저장소의 기존 인쇄 양식
   (전표·거래명세서·세금계산서·결재 문서)이 어떤 형태로 저작되는지 보고, 두 방식이 그것과
   어떻게 다른지 정리한다.
3. **엑셀 라이브러리를 쓴다면 무엇이 필요한가.** 파싱·렌더·인쇄 각각. 기존 의존성으로 되는지,
   새로 들여야 하는지. 🚨 새 의존성은 라이선스와 번들 크기를 함께 적는다.
4. **기존 양식 데이터와의 호환**은 어떻게 되는가. 이미 저장된 양식이 있으면 그것을 어떻게 다루는가.
5. #845(문서 양식 디자이너 에픽) · #869(DS4) 와의 관계를 정리한다. **중복 설계를 피한다.**

## 3. 불변식 (수단 미지시)

1. **이미 저장된 양식이 깨지면 안 된다.** 기존 양식으로 인쇄되던 문서가 그대로 나와야 한다.
2. 저작 방식을 바꿔도 **인쇄 결과의 법적 형태**(전표·세금계산서 등)가 달라지면 안 된다.
3. 새 의존성을 들이면 **왜 기존 것으로 안 되는지**를 근거로 남긴다.
4. UUID 를 화면에 노출하지 않는다.
