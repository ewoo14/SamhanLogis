# #1052 창고 UUID 실재성·대응 검증 — 정찰 (조기 PR · 코드 무변경)

## 이 트랙이 무엇인가

`#1035` 가 **여섯 라운드에 기동 실패 세 번**을 겪고 개발책임자 결정으로 범위를 축소했다. 축소된 트랙은 값 자체로 판정 가능한 검증(placeholder 미치환·UUID 형식·빈 값)만 남기고 머지했다. **이 이슈는 거기서 떼어 낸 부분** — 외부 창고 서비스 조회가 필요한 검증이다.

## 남은 검증 대상

| | |
|---|---|
| **실재성** | 형식은 맞으나 **실재하지 않는** 창고 UUID |
| **대응** | 실재하지만 **자리가 바뀐** UUID (창고 A 의 UUID 가 창고 B 자리에) |

## 🚨 `#1035` 의 실패 기록 — 착수 전 반드시 읽는다

| 라운드 | 실패 |
|---|---|
| 2 | 정상 창고 4개가 다 있어도 **legacy 코드 조회 4/4 `404`** → 기동 실패 |
| 2 | 일시 장애·늦은 기동·미실재를 **구분하지 않아** context 영구 종료 |
| 4 | **식별자가 뒤바뀌어도 `FOUND`** 로 통과 |

| 4 | 느린 서비스가 **timeout 없이** 기동 스레드 블록 |
| 6 | **legacy 역조회 4/4 `404`** 재발 → 기동 실패 |
| 6 | 재검증이 불일치를 찾아도 **ERROR 로그만** · health/readiness 무변화 |

🔑 **매번 외부 조회에서 무너졌다.** 조회 경로 설계부터 다시 한다.

## 이 정찰이 답할 것 — 구현 전에 먼저 실행으로 확인한다

1. 🚨 **어느 엔드포인트가 실제로 동작하는가** — `#1035` 는 legacy 코드 조회와 UUID 조회 사이를 오갔고 둘 다 `404` 였다. **실행해서 확인**한다. 무엇이 200 을 주는지, 어떤 입력에 404 인지.
2. 🚨 **기동 시점 조회가 맞는가** — 기동을 막으면 배포 순서에 묶인다. 헬스체크 / 기동 후 비동기 / 주기 검증 중 무엇이 맞는가.
3. 🚨 **발견하면 무엇을 하는가** — 로그만 남기면 아무도 안 본다. health·readiness 반영이나 경보가 필요하다.
4. **실 데이터에 대상이 몇 건인가** — 표본 0 이면 "결함 0" 이 아니라 "판정 불가" 다.
