# PR #1063 구현 보고서 — 전표 라인 입력 UX

## 2026-08-03 구현 시작

- 기획 문서 `docs/dev-reports/2026-08-03-1062-plan.md`와 최신 핸드오프를 읽었다.
- 개발책임자 정정 사양을 우선한다. 빈행은 **품목코드가 확정되지 않은 행**이며, 신규·수정 저장 시 모두 제외한다. 수정 모드에서는 열자마자 트레일링 빈행을 유지하고, 채워지면 다시 아래에 빈행을 둔다.
- 자동완성은 내용에 맞게 넓은 드롭다운을 제공하고, 후보가 2건 이상이면 모델명·품목명·규격·단가를 표로 고르는 모달 경로를 추가한다.
- 이 보고서는 작업 항목을 확인할 때마다 즉시 append한다. 최종 보고서에 RED 원문, GREEN 원문, 화면 전수 표, 품목코드 확정 판정, 범위 판단, 변경 파일을 누적한다.
- 범위는 먼저 `AsyncAutocomplete` 사용 화면을 전수 조사한 뒤 결정한다. 견적·분개는 자동 빈행 및 저장 필터의 현재 상태와 수정 난이도를 확인하여 포함 여부를 근거와 함께 기록한다.

### 원인 확정

- `AsyncAutocomplete.module.css`의 `.dropdown`/`.empty`/`.hint`가 `left: 0; right: 0`으로 wrapper 폭을 그대로 사용한다.
- portal 경로도 `updateFloatingPosition()`이 `width: rect.width`를 inline으로 고정해 같은 제약이 남는다.
- `ProductAutocomplete`는 단일 선택 자동완성에 `resultSelectionMode`를 전달하지 않아 검색 결과 2건 이상도 dropdown에서만 보여 준다. 기존 모달은 복수 선택 wrapper에만 활성화돼 있었다.
- `ProductOption`/상품 검색 요약에는 현재 `specification` 응답 필드가 없으므로 모달은 값이 있으면 표시하고 없으면 `—`로 표시한다. 단가는 공개된 `sellingPrice`를 사용한다.
- 빈행의 품목코드 확정 판정은 제품 선택 callback으로 채워지는 `productId !== null`이다. 모델명 텍스트·품목명 텍스트·수량 입력만으로는 확정으로 보지 않는다. 분개는 상품 라인이 아니므로 대응 확정 키를 `accountCode`로 둔다.

### 범위 판단

견적·분개를 이번 PR에서 제외하면 수정모드에서 처음부터 새 라인을 입력할 수 없는 동일 UX 결함이 남는다. 두 화면 모두 이미 `appendBlankRowIfLastChanged`와 저장용 필터를 갖고 있어 공용 기준을 적용하는 변경 폭이 작고, 이동 화면도 같은 이유로 포함한다. 따라서 네 화면 모두 ②를 맞추고, `ProductAutocomplete` 사용 화면은 ① 공용 회귀를 확인한다.

## GREEN-1 — 자동완성 2건 모달 표

`AsyncAutocomplete` portal의 폭을 입력칸 고정값에서 내용 기반(`max-content`, 입력 폭 이상, 화면 가장자리 보정)으로 바꾸고, `ProductAutocomplete` 단일 선택도 후보 2건 이상에서 선택 모달을 열도록 연결했다. 모달은 UUID 없이 모델명·품목명·규격·단가 표를 렌더링하며, 규격 미제공 응답은 `—`로 표시한다. 1건은 기존처럼 dropdown에 남는다.

```text

```

이 단정은 Linux에서도 CSS `max-content`/`max-width`와 고정 portal 위치 계산을 Chromium이 지원하므로 동일하다. 후보 폭이 화면을 넘는 경우에는 표 모달로 전환되고, 1건 dropdown은 수평 스크롤 가능한 내용 폭으로 유지된다.

## 통합 보완 — 협업 견적 라인

견적 협업 provider도 수정 화면의 trailing 빈행을 실제 입력 대상으로 쓸 수 있어야 하므로 seed 문서 자체에 확정 라인 뒤 빈행을 하나 포함했다. 이 때문에 기존 coedit 테스트의 “서버 라인만 seed” 기대가 먼저 2건 RED가 되었고, 새 계약(확정 라인 + 빈 입력 라인)에 맞춰 테스트 기대를 갱신했다. 빈행은 `productId: ''`로 provider에만 존재하고 저장 filter에서 제외된다.

### 품목코드 확정 판정

- 판매전표·견적·이동: 제품 선택/blur lookup 성공으로 채워진 `productId`가 `null`이 아닌 경우만 확정이다. 모델명, 품목명, 수량, 규격, 단가만 입력한 행은 미확정으로 저장 filter에서 제외한다.
- 분개: 상품 라인이 없으므로 같은 의미의 라인 확정 키를 `accountCode.trim()`으로 판정한다. 금액만 입력한 행은 저장하지 않는다.
- 수정 hydrate/provider는 기존 라인의 배열 순서와 서버 `line_no`/`lineNo` 매핑을 그대로 순회하고 끝에만 빈행을 append한다. 빈행은 payload filter에서 제거하므로 기존 라인의 순서·내용을 재번호화하지 않는다.
