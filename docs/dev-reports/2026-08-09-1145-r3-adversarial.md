### 왜 R2로 닫히지 않았는가

PR 최초 보고서는 이 13명의 “화면 진입 후 GET 403”과 3명의 저장 403을 RED-A로 선언하고, 변경 후 “화면 진입 및 GET 허용/생성 허용”을 결과로 약속했다. 그러나 R2의 V97은 `SELECT 1`뿐이므로 해당 권한은 그대로 `0000`이다. 현재 FE는 이 계정에게 메뉴와 라우트를 감춘다. 따라서 결과는 “403 해결”이 아니라 “동일 사용자의 기능 접근 제거”다.

행 시각 함정도 확인했다.

- 후보 중 11명의 매출·매입 `.list`/`.accounting` 행은 `2026-05-30`, `v39-account-materialize`가 만든 장기 행이다.
- `dev_sales` 권한 행은 `2026-08-08 22:40`, `manager@samhan.test`는 `2026-08-07 22:06` 생성이라 최근 QA 성격이 있다.
- 따라서 13명 전체를 운영 사용자로 일반화하면 안 되지만, 후보 전부가 이번 R1/R2 직전에 생긴 QA 잔재도 아니다. 직원명 계정 9명은 2026-05-09 생성 계정이고 권한 행은 2026-05-30부터 존재한다.

## 4. (b) V97 `SELECT 1` 파장

### 원래 GET 403 해결 여부

해결되지 않았다. 실 API 원문은 §2와 같이 MANAGER 매출·매입 GET 403이다. FE가 이 계정을 `.accounting` 가드에서 차단하므로 증상이 화면 뒤로 이동했다.
