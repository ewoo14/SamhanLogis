## 1. 개발책임자 확정 범위

> *"리모컨 구성품 변경이나 방진가대 수량 동기화도 모두 해당 메뉴에서 편집이 가능한 범위에 들어가는 게 맞아."*

⟹ 슬4 = **부속 모델 매핑 · 제품군 판별 정규식 · 리모컨 선택 · 용량 구간**을 칩 설정으로 전환한다.

선례가 이미 있다 — `price_change_schedule`(테이블 + 관리 API + FE 화면)이 같은 형태다.

## 2. 정찰 질문 (구현 전에 답한다)

1. **지금 하드코딩된 것이 정확히 무엇인가.** `clients/web/order-app/index.html` 과 관련 계산 경로에서
   수량 동기화에 쓰이는 상수·정규식·매핑을 **전수로** 뽑아 표로 만든다. 파일:줄 인용 필수.
   - 부속 모델 매핑 (개발책임자가 "17곳" 이라 언급 — 실측으로 확인할 것)
   - 제품군 판별 정규식
   - 리모컨 선택 규칙
   - 용량 구간
2. **슬2 가 만든 스키마가 이 값들을 담을 수 있는가.** #958 이 만든 수량 동기화 규칙 스키마를 읽고,
   그대로 쓸 수 있는지 / 확장이 필요한지 판정한다. **새 테이블을 만들기 전에 기존 것을 먼저 본다.**
3. **`price_change_schedule` 의 관리 API·FE 화면 구조**를 읽고 재사용 가능한 형태를 정리한다.
4. 🚨 하드코딩 값을 설정으로 옮길 때 **현재 계산 결과가 바뀌면 안 된다.** 이동 전후 동등성을
   무엇으로 증명할지 방법을 먼저 정한다.

## 3. 불변식 (수단 미지시)

1. **설정으로 옮긴 뒤에도 현재와 같은 수량이 계산돼야 한다.** 값의 이동이지 규칙 변경이 아니다.
2. 설정 화면에서 **편집한 결과가 실제 계산에 반영**돼야 한다 — 저장만 되고 안 쓰이면 안 된다.
3. 잘못된 설정(빈 값·중복·모순)은 **저장 단계에서 막고 사유를 보여준다.**
4. 신규 권한 체계를 만들지 않는다 — 기존 `@RequirePermission` page-code 모델을 쓴다.
5. UUID 를 화면에 노출하지 않는다. 신규 엔티티는 BaseEntity 7 audit + Soft Delete 규약.
