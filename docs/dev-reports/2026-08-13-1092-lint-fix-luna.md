## 수정 범위

### 두 줄 원문

```ts
// before
export interface WebQuoteSnapshotSummary extends WebQuoteSnapshotListSource {}

// after
export type WebQuoteSnapshotSummary = WebQuoteSnapshotListSource
export type WebPartnerOrderDraftSummary = WebPartnerOrderDraftListSource
```

## 타입 의도 확인

두 선언은 새 런타임 객체를 만들거나 opaque token 값을 브랜딩하려던 선언이 아니다. `estimateUnifiedListModel.ts`의 웹 저장분 목록 모델을 API 응답에서 사용할 도메인 이름(`Summary`)으로 재사용하려던 별칭이다.

구분은 유지된다. `WebQuoteSnapshotListSource`는 필수 `snapshotKey`, `custName`, `created`를 가지며, `WebPartnerOrderDraftListSource`는 필수 `draftKey`, `partnerCode`, `createdAt`을 가진다. 따라서 두 Summary 타입은 각각의 원본 목록 타입과 동일한 필드 제약을 유지한다. `type` 별칭 전환은 이 구분을 없애지 않고, lint가 지적한 빈 인터페이스만 제거한다. UUID/payload 노출도 추가하지 않았다.
