# #1110 S16 — 복원 401 도달 가능성 판정

## 결론: A — 도달 불가

복원 API의 401 응답은 `partnerOrderRestoreErrorMessage`까지 도달할 수 없는 것으로 코드상 확정했다. 따라서 화면에 표시될 수 없는 401 전용 문구와 그 단위 테스트를 제거했다. 403·404·409·400·기타 상태의 기존 안내는 유지했다.

## 코드 증거

1. 복원 호출은 `clients/desktop/src/renderer/api/partnerOrderRevision.ts:115-123`의 `restorePartnerOrderRevision`에서 공통 `apiClient.post`를 사용한다. 요청 URL은 `/api/v1/partner-orders/{orderId}/revisions/{revisionNo}/restore`이며, `skipAuth`나 별도 axios 클라이언트를 사용하지 않는다.
2. 공통 401 처리는 `clients/desktop/src/renderer/api/client.ts:103-127`의 응답 인터셉터다. 복원 URL은 `isAuthEndpoint401HandledByCaller`의 예외 대상(`/auth/me`, `/auth/login`, `/auth/logout`, password-reset)이 아니므로 401이면 `clearAuthState()`를 호출하고 웹에서는 `/login`으로 이동시킨다. 이후 원래 오류를 reject한다.
3. 화면의 복원 오류 함수 호출 지점은 `clients/desktop/src/renderer/components/audit/PartnerOrderVersionHistoryPanel.tsx:223-225`의 `restoreMutation.onError`다. 그러나 위 인터셉터가 먼저 세션 정리·로그인 이동을 수행하므로 정상 복원 요청의 401은 이 지점에서 사용자 토스트로 렌더링되지 않는다.
4. 요청 옵션·재시도·특정 클라이언트 우회도 없다. `restorePartnerOrderRevision`은 옵션 없이 `apiClient.post`를 호출하고, desktop 공통 인터셉터에는 401 재시도 경로가 없다. `skipAuth`는 요청 인증 헤더 처리만 건너뛰며 응답 인터셉터를 우회하지 않는다.

## 변경

- `partnerOrderRestoreErrorMessage`에서 401 분기를 제거했다.
- 함수에 전역 인터셉터가 먼저 처리한다는 주석을 남겼다.
- 도달 불가한 401 기대 테스트를 제거했다.
- 401 세션 만료 시 이유가 바로 보이지 않는 전역 인증 UX 문제는 이 PR 범위 밖의 선재 사항으로 남긴다.
