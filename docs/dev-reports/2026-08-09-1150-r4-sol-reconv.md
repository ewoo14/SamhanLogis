### compositionend 직후 첫 Escape

CDP `Input.insertText("본")`으로 실제 `compositionend`를 만들었다. 자동확정 결과와 selection은 아래였다.


그 직후 첫 Escape 원문은 `keydown key=Escape isComposing=false`였고 dialog는 1→0으로 닫혔다. `isComposingRef.current = false` 시점 불일치로 Escape가 한 번 먹히는 상태는 재현되지 않았다.

## 각도 3 — Escape의 다른 소비자(listbox)

단일 후보 `본`을 조합하면 실제 `창고 목록` listbox가 열린다. 이 상태의 조합 Escape 결과:

```json
{
  "listboxBefore":1,
  "listboxAfterCompositionEscape":1,
  "dialogAfterCompositionEscape":1
}
```

즉 조합 중 Escape는 listbox도 닫지 않는다. 그러나 이 키는 원문상 `isComposing=true`이고 값·selection·listbox 후보가 그대로 보존됐다. 바로 한 번 더 보낸 Escape도 CDP 조합을 종료시키지 않은 상태라 원문이 다시 `isComposing=true`였고, 이를 “compositionend 뒤 첫 Escape” 표본으로 오인하지 않았다. 실제 compositionend 뒤 첫 Escape는 각도 2에서 `isComposing=false`, 모달 정상 close로 별도 확인됐다. 조합 중 입력을 보존하고 조합 종료 뒤 정상 소비자가 살아 있으므로 도달 가능한 결함으로 판정하지 않는다.

## 각도 4 — 중첩 모달

발화 조건이 실제로 존재했다. 외부 병합 모달의 WarehouseAutocomplete에 CDP IME `창`을 조합하자 후보 6건의 `출고 창고 검색 결과` 모달이 열려 dialog가 1→2가 됐다.

중첩 모달이 열린 뒤 포커스는 최상위 모달의 `검색 결과 필터`로 이동했다. Escape 원문:

```text
afterDialogs=1
```
