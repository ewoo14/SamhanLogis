## Spring context 및 불변식 확인

실행 원문:

```text
.\gradlew.bat :services:slip-service:test --tests com.samhanair.logis.slip.it.WarehouseValidationApplicationContextIT --tests com.samhanair.logis.slip.it.WarehouseValidationUnavailableApplicationContextIT --no-daemon
BUILD SUCCESSFUL in 46s
```

XML 원문:

```text
<testsuite name="com.samhanair.logis.slip.it.WarehouseValidationApplicationContextIT" tests="1" skipped="0" failures="0" errors="0">
<testsuite name="com.samhanair.logis.slip.it.WarehouseValidationUnavailableApplicationContextIT" tests="1" skipped="0" failures="0" errors="0">
```

- 정상 context는 네 매핑을 각각 창고코드별 UUID 응답으로 판정하고 기동했다.
- `UNAVAILABLE` context는 기동을 막지 않았다. 보류 코드는 메모리 집합에 남고, 스케줄러의 후속 `revalidateUnavailableWarehouses()`가 같은 검증 경로를 다시 호출한다.
- UUID는 로그·예외 메시지에 포함하지 않고 창고코드만 사용한다.
- placeholder는 기존 UUID 파싱 실패 경로에서 계속 기동을 차단한다.
- 창고 client request factory에 connect 2초/read 3초 상한을 설정했다. 따라서 느린 창고 서비스가 무기한 기동 스레드를 붙들 수 없다.
