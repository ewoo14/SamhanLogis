# #1075 S3 fix 보고서 — 견적 품목 후보 확정

## 결론

SOL 지시서의 두 결함을 수정했다. 공용 `ProductOption` 후보 확정 시 `id`를 견적 내부 `productId`로 정규화하고 `specification`을 로컬 라인과 coedit 문서에 함께 반영한다. mock 하드 게이트는 삭제·skip·timeout 연장 없이 현재 견적 신규 화면의 `ProductAutocomplete` combobox와 다건 모달 확정 계약으로 갱신했다.

## 원인

- `EstimateFormPage`가 공용 후보를 레거시 lookup 응답처럼 취급해 `result.productId`를 읽었다. 공용 후보의 키는 `result.id`라 저장용 `productId`가 비어 있었다.
- 같은 경로가 후보의 `specification`을 라인에 쓰지 않았다.
- `1062-line-input-ux`는 현재 화면에 없는 `estimate-form-line-2-model`을 기다렸다. 편집 화면은 coedit 활성 시 모델 combobox를 잠그므로, 게이트는 지시서의 신규 견적 경로를 사용하도록 갱신했다.

## 변경 사항

- `clients/desktop/src/renderer/routes/EstimateFormPage.tsx`
  - 공용 후보(`id`, 숫자 `sellingPrice`, `specification`)와 레거시 lookup 응답을 공통 내부 결과로 정규화.
  - 정규화된 `productId`, 모델명, 품목명, 규격, 단가를 라인에 반영.
  - 규격을 coedit `items.N.specification`에도 동기화.
  - 가격기억, 사용자 단가(`USER`), 자동 빈행, 버전 복원, coedit 구조 잠금, 참조 조회 경로는 변경하지 않음.
- `clients/desktop/src/renderer/routes/EstimateFormPage.coedit.test.tsx`
  - 후보 확정 후 id·모델명·품목명·규격·단가가 저장 payload에 포함되는 RED-A 회귀 단정 추가.
- `clients/desktop/playwright/1062-line-input-ux/1062-line-input-ux.spec.ts`
  - 사라진 test id를 제거하고 거래처 선택 → 견적 신규 combobox → 다건 모달 확정 → trailing 빈행·모델명·규격 surface·단가 계약으로 갱신.
