# PR #1132 — 구성품 기본값 0건 세트 진단

- 조사일: 2026-08-11 KST
- 역할: CODEX SOL 5.6 / 진단자
- 환경: `samhan-product-service` #1126 배포본, `product_db` Flyway V35
- 조사 원칙: 코드·레거시 원문·실 DB 읽기만 수행했다. 모든 DB 질의는 `BEGIN READ ONLY`로 열고 `ROLLBACK`으로 끝냈다. 코드·실 DB·컨테이너·git 조작은 하지 않았고, 요청된 진단 문서만 추가했다.
- 선행 실측값 72세트(71+1), 구성품 137건, 견적 0건, 주문 0건, 판매전표 2건 3라인은 문제 정의의 확정값으로 받아들였다. 아래 수치는 성격·분포·구분 신호·전표 원문을 채우기 위한 상세 조회 결과다.

## 1. 결론

**72세트의 전개 0행은 원래 의도가 아니다. 그렇다고 싱글세트와 같은 의미의 “기본 지정 누락”도 아니다.**

72세트는 `상업멀티 구성_단가인상` 탭에서 만들어진 복합 실외기 세트다. 활성 구성품 137건은 모두 `OUTDOOR`이고, 세트명 괄호의 HP 조합을 실제 실외기 1~3대로 표현한다. 레거시 GAS는 상업멀티 구성행의 `isDefault`를 계산했지만 전개할 때는 그 값을 전혀 보지 않고 해당 세트의 구성행을 **전부** 펼쳤다. 현재 웹 이식본도 같은 동작이다.

반대로 기본 보유 271세트는 전부 `SINGLE_SET`이다. `INDOOR`·`OUTDOOR` 같은 필수 본체는 `is_default=true`, `MATERIAL`은 전부 false, `PANEL`·`REMOTE`는 기본/선택이 섞여 있다. 이 집합에서 `is_default`는 “옵션 후보 중 기본 조합”이라는 실제 의미가 있다.

즉 진자운동의 원인은 데이터 결손이 아니라 **서로 다른 두 도메인의 동일 컬럼 해석 충돌**이다.

```text
상업멀티 세트  is_default=false = 선택품이라는 뜻이 아니었음
                              = 원천 '구분'에 '기본' 문자가 없어서 생긴 값
                              = 레거시는 전 구성품을 필수 조합으로 전개

싱글세트       is_default=true/false = 필수·기본 조합과 선택 옵션을 가르는 신호
```

따라서 “72세트를 0행으로 둘 것인가”는 증거상 선택지가 아니다. 선택할 것은 **상업멀티의 필수 구성 의미를 카테고리 규칙으로 유지할지, 기존 컬럼으로 정비할지, 별도 의미축으로 승격할지**다.

### 2.3 언제, 어떻게 갈렸는가

두 집합은 모두 같은 서비스 계정과 `lineage=SHEET`로 2026-07-28 시트 동기화에서 만들어졌다. 별도의 수기/신규 생성 집합이 아니다.

| 집합 | 부모 생성 시각 범위 | 활성 구성품 원시 적재 시각 | 시드 경로 |
|---|---|---|---|
| 기본 보유 271 | 20:33:38.623~20:33:48.350 | system 1,446건, 20:34:10.247~20:34:14.747 | `싱글 세트_단가인상` + `싱글 구성품_단가인상` |
| 기본 0건 72 | 20:33:58.047~20:34:04.581 | system 135건, 20:34:15.027~20:34:15.343 | `상업멀티_단가인상` + `상업멀티 구성_단가인상` |

분기 지점은 `ProductSheetSyncService`의 구성품 탭 파서다.

- 구성품 탭은 싱글과 상업을 별도 매핑한다: `ProductSheetSyncService.java:137-139`.
- 기본값은 `variant + kindRaw`에 `기본`이라는 문자열이 있는지만 본다: `ProductSheetSyncService.java:397`.
- 상업멀티의 `구분`은 실외기이고 “기본”이 아니므로 137건이 모두 false가 됐다.
- 싱글 구성 탭에는 `기본` 특징이 있어 본체와 기본 옵션은 true, 선택 옵션은 false로 갈렸다.

시간대가 깔끔히 갈리는 것은 별도 정책 표식이 아니라 같은 배치에서 싱글 탭을 먼저, 상업 탭을 나중에 처리한 순서의 흔적이다.

### 2.4 레거시 GAS와 현재 웹 이식본의 원래 동작

레거시 서버 파서는 상업 구성행에 대해 `isDefault = /기본/.test(kind || '')`를 계산한다(`tools/legacy-gas/종합견적서/Code.js:921`). 그러나 실제 상업멀티 전개 함수는 다음 순서다.

1. `COMM_PARTS.filter(p => p.refModel === setRow.model)`로 해당 세트의 구성행 전부를 가져온다.
2. `parts.map(...)`으로 전 행의 수량과 가격을 만든다.
3. `isDefault` 필터는 없다.

좌표는 레거시 `tools/legacy-gas/종합견적서/index.html:6791-6826`, 현재 웹 이식본 `clients/web/estimate-app/views/index.ejs:7221-7258`이다. 둘 다 구성행이 없을 때만 부모 1행 fallback을 쓰며, 구성행이 있으면 전부 펼친다.

또한 커밋된 parity 자료는 상업 구성 골든 170행이 전부 `feature=''`, `isDefault=false`였음을 명시한다(`clients/web/estimate-app/qa-set-expansion-parity-gate.mjs:17-18`). 이 게이트 자체는 상업 레거시 함수를 직접 실행하지 않는다고 범위를 고지하므로 단독 증거로 쓰지 않았고, 위 GAS 원문과 시트 파서의 보조 증거로만 사용했다.

**원래 의도 판정: 상업멀티의 false는 선택 제외 신호가 아니며, 세트 구성 전부가 전개 대상이다.**

### 3.1 부분 전개 1행의 원인

`2026/08/07-9`가 1행인 것은 엔진이 원래 한 행만 전개했기 때문이 아니다.

- 생성 리비전 snapshot부터 `AM140AXVGHC1` 한 행이므로 저장 후 삭제 이력은 없다.
- 같은 QA의 원문 `docs/qa/1069-bundle-expansion-real-qa/2026-08-07-1069-r23-real-qa.md:41-58`은 최초 화면에서 `AM140AXVGHC1 + AM220AXVGHC1`, VAT 포함 `4,418,315 + 6,403,320 = 10,821,635`로 두 행이 전개됐음을 기록한다.
- 같은 문서 `:94-119`는 사용자가 두 번째 구성행을 삭제한 뒤 저장했다고 명시한다.

따라서 전표 증거는 다음과 같이 읽어야 한다.

```text
AM220 세트  전 구성품 2행 그대로 저장
AM360 세트  전 구성품 2행 전개 → 사용자가 1행 삭제 → 남은 자식 1행 저장
공통        부모 1행 저장 아님, 0행 아님
```

### 3.2 `AM220AXVHHR1SY`의 manual=true 정체

이 세트의 판매전표는 12:18에 만들어졌고, 구성품 수기 교체는 같은 날 23:03에 `[DEV-SEED] 개발마스터`가 수행했다. 수기 교체는 기존 두 구성행을 soft-delete하고 새 두 행을 만들면서 `manual=true`로 바꿨다. 현재 첫 구성품 수량도 원시 1.00에서 2.50으로 바뀌어 있다.

따라서 이 한 건의 `manual=true`는 72세트의 원래 분류가 아니라 **QA 이후 사용자 mutation 흔적**이다. R2가 이 값을 레거시 자격의 역표식으로 사용한 것이 실패한 이유를 실데이터가 직접 보여준다.

| 확정 모델코드 72개 allowlist | 72/271을 완전 분리 | 모델코드 유지 중에는 불변 | 목록 제거로 즉시 복귀 | 새 상업 세트 자동 누락, 모델 단종/대체 때 목록 부채. 전환용 임시 표식으로만 유효 |
| 별도 컬럼 `expansion_policy`/`component_role` | 현재 컬럼 없음. backfill 후 의도대로 완전 분리 가능 | UI/API를 노출한 범위에서만 변경 가능하게 설계 가능 | 명시적 정책 변경·rollback migration 필요 | 가장 명확하지만 schema/API/시트 sync/UI를 함께 바꿔야 함. 부분 도입 시 또 다른 이중 진실원 |
| 데이터 정비: 137건을 기본/필수로 지정 | 정비 직후 72/271 모두 현재 expander 계약으로 정상 전개 | 현재 UI는 기본 토글이 없고 기존 값을 보존. 다만 시트 sync는 원천 문자열로 false를 재계산 | 137건 원복 + 원천/시드 원복 | 원천 시트 또는 sync 규칙까지 같이 고치지 않으면 재동기화로 되돌아감. “기본”과 “필수”를 같은 단어로 합침 |

`created_at`·모델 allowlist는 값이 현재 갈린다는 이유만으로 정책 신호가 되지 않는다. 반대로 `product_category`는 사용자 편집 가능하다는 약점이 있지만, 레거시가 실제로 싱글과 상업 전개 함수를 별도로 둔 것과 같은 도메인 축이라는 점에서 다른 기존 컬럼보다 근거가 강하다.

## 6. 개발책임자가 정해야 하는 것

**개발책임자가 정해야 하는 것은 “72세트를 0행으로 둘지”가 아니라, 레거시에서 필수 조합이었던 상업멀티 137개 구성행을 기존 카테고리 규칙·기존 `is_default` 정비·새 명시적 역할축 중 어디에 정본화할지다.**

### 선택지 A — 상업멀티는 등록 구성품 전부, 싱글세트만 기본 구성품 전개

- 무엇을 하는가: 레거시처럼 `COMMERCIAL_MULTI`는 활성 구성품 전부를 필수 조합으로 전개하고, `SINGLE_SET`에서만 `is_default=true`를 기본 조합 필터로 사용한다.
- 대가: 현재 카테고리 값에 동작이 결합된다. 상업멀티에 미래 선택 구성품을 넣어도 기존 `is_default=false`만으로 제외할 수 없고, 먼저 별도 옵션 의미가 필요하다. 사용자가 product category를 잘못 바꾸면 전개 의미도 바뀐다.
- 영향: 72세트·137 구성품의 기존 전개를 유지한다. 역사 증거 2전표·3라인·VAT 포함 15,242,370원은 소급 변경되지 않고, 이후 같은 세트를 선택할 때 0행을 막는다. 미래 금액은 선택 수량·당시 단가에 따라 달라진다.
- 되돌림 비용: 낮음. 카테고리 분기 제거로 코드 동작을 원복할 수 있고 데이터 rollback은 없다.
- 진단자 판단: **단기 수렴 권장**. 레거시 함수 경계 및 현 72/271 구조와 가장 직접적으로 일치한다.

### 선택지 B — 72세트의 137행을 기존 `is_default=true` 의미로 정비

- 무엇을 하는가: 상업멀티 137행을 모두 기본/필수로 정비하고, 원천 시트 또는 sync 변환도 같은 값을 재생성하게 하여 전개기는 보편적인 “기본만” 규칙 하나를 유지한다.
- 대가: 상업의 “필수 구성”을 싱글의 “기본 옵션”과 같은 컬럼에 합친다. 데이터 migration뿐 아니라 시트 원천·sync·관리 UI의 기본 지정 경로를 함께 닫아야 하며, 하나라도 빠지면 다음 sync/편집에서 다시 false가 된다. AM220처럼 이미 수기 보호된 행과 원시 행의 수량 차이도 별도 확인해야 한다.
- 영향: 72세트·137 활성행을 변경한다. 기존 2전표·3라인·VAT 포함 15,242,370원은 snapshot이라 자동 변경되지 않는다. 신규 전개는 A와 같은 구성행을 낸다.
- 되돌림 비용: 중간. 137행과 원천/변환 규칙을 함께 원복해야 하며, 적용 후 새로 편집된 세트의 true/false와 구분해 rollback해야 한다.

### 선택지 C — `REQUIRED/OPTIONAL/DEFAULT` 또는 명시적 expansion policy 신설

- 무엇을 하는가: `is_default`와 별도로 구성품 역할 또는 부모 전개 정책을 신설해 상업 137행은 `REQUIRED`, 싱글 기본 조합은 `DEFAULT`, 선택품은 `OPTIONAL`로 명시한다.
- 대가: schema migration, API DTO, 시트 sync, 관리 UI, 전개기, 기존 343세트/1,584 활성 구성품 backfill을 함께 바꿔야 한다. 부분 배포하면 두 컬럼이 서로 다른 답을 내는 새 진자운동이 생긴다.
- 영향: 데이터 의미상 343세트·1,584 구성품 전체가 새 축의 대상이며, 실제 동작 변경의 핵심은 72세트·137행이다. 기존 2전표·3라인·VAT 포함 15,242,370원은 소급 변경되지 않는다.
- 되돌림 비용: 높음. 새 컬럼과 소비자 제거, backfill 원복, 전환 기간 이중 읽기 제거가 필요하다.
- 진단자 판단: 장기 모델은 가장 명확하지만 PR #1132의 수렴 비용을 크게 키운다.
