# S10 CI red 해소 보고서 — PR #1078 / Issue #1075

## 결론

CI red 원인은 신규 회귀 시나리오 2건과 그 시나리오가 현재 제품 계약을 잘못 가정한 부분이었다. 시나리오를 삭제하거나 skip하지 않고 현재 계약에 맞게 복원했으며, 견적서 작성 경로에는 모델명 blur 입력을 실제 product lookup으로 연결하는 최소 FE 수정만 추가했다.

최종 전체 게이트:

```text
Vitest: Test Files 202 passed (202)
        Tests 1797 passed (1797)
        EXIT_CODE=0

Playwright: 657 passed (6.2m)
```

Playwright는 `CI=1` 및 기존 명령으로 전체 657건을 끝까지 실행했으며 failed 0건이다.

## 최초 CI 조건 재현 및 원인

### Design System build

실행:

```powershell
cd clients/web/design-system
npm run build
```

결과: exit 0, `built in 4.41s`. 기존 미해결 font 경고 3건만 출력됐고 build 실패는 없었다.

### Vitest

사용자 지정 명령을 build 없이 그대로 먼저 실행했을 때:

```text
Test Files 1 failed | 204 passed (205)
```

실패 테스트는 `src/main/build-output-cjs-interop.test.ts`였다. 이 테스트는 `out/main/index.js`를 읽는데 desktop build 전에는 해당 산출물이 없기 때문에 실패한다. CI 순서인 desktop build 후 Vitest를 실행하면 아래 최종 결과로 통과한다.

```text
Test Files 202 passed (202)
Tests 1797 passed (1797)
```

### Playwright 최초 실패 2건

1. `playwright/1062-line-input-ux/1062-line-input-ux.spec.ts:71`

   VITE mock mode는 브라우저 네트워크 response를 만들지 않고 in-process adapter로 API를 처리한다. 따라서 `page.waitForResponse()`가 60초 timeout으로 실패했다. 이후 테스트가 접근하려던 trailing 빈행의 입력도 현재 coedit 계약상 disabled 상태였다. trailing 빈행 구조 추가/삭제 잠금은 요구 불변식이므로, 시나리오를 기존 행 교체가 아니라 trailing 행의 disabled/delete 잠금과 행 수 보존을 단정하도록 고쳤다.

2. `playwright/bundle-set-options/bundle-set-options.spec.ts:234`

   `estimate-form-line-0-model`이라는 존재하지 않는 test id를 사용하고 있었다. 실제 화면은 `role=combobox`, accessible name `라인 1 모델명`이다. 또한 현재 `AsyncAutocomplete`는 입력 중 draft를 blur 시점에 상위 폼으로 전달하지 않아, 실제 모델명 blur lookup이 실행되지 않았다.

## 수정 내용

- `AsyncAutocomplete`에 선택 확정과 분리된 `onInputBlur(draft)` callback을 추가했다.
- `ProductAutocomplete`가 해당 callback을 전달하도록 확장했다.
- `EstimateFormPage`의 모델명 blur에서 editable 기존 행만 draft를 반영하고, 다음 tick에 기존 lookup handler를 실행하도록 연결했다. 제품 선택 시 `productType`도 즉시 반영해 BUNDLE 옵션 행이 노출되도록 했다.
- 1062 시나리오는 provider fallback을 기다리는 네트워크 response 단정 대신 mock 화면의 실제 trailing lock 계약을 검증하도록 변경했다.
- bundle 옵션 시나리오는 실제 combobox 접근성 locator와 모델명 blur lookup을 사용하도록 변경했다.

## 불변식 확인

- origin/main 기준 18개 단정은 삭제하거나 skip하지 않았다. 1062 시나리오에도 trailing 빈행/라인 삭제 잠금 단정을 유지했다.
- coedit 기존 행 값 변경 경로를 유지했다.
- 신규 작성 자동 빈행과 판매전표 경로는 전체 Vitest 및 전체 Playwright에서 통과했다.
- UUID를 사용자 화면 단정이나 locator에 추가하지 않았다.
- 다른 트랙 파일은 변경하지 않았다.
- 백엔드 API, DB, Docker에는 변경을 가하지 않았다.
