## 실행 경계

- 실 GUI: 현재 브랜치 `clients/desktop` renderer와 Playwright Chromium. `VITE_MOCK_MODE=false`, `VITE_USE_MOCK=false`.
- 인앱 Browser 런타임은 `[]`였으며, 지시대로 실행 불가로 판정하지 않고 Playwright Chromium으로 실행했다.
- 현재 브랜치 회계 서비스를 `127.0.0.1:18087`에 별도 기동했다. 공유 `accounting_db` 연결은 JDBC 세션 옵션 `default_transaction_read_only=on`, Flyway 비활성, JPA DDL `none`, seed 비활성, Eureka 등록·조회 비활성으로 고정했다.
- `dev_master`로 실 로그인했다. 로컬 현재-브랜치 서비스 우회에는 실 gateway가 검증된 JWT에서 붙이는 `X-User-Id`, `X-Is-System-Master`, `X-User-Groups`, `X-Is-Partner` 계약을 동일하게 전달했다.
- Playwright에서 `GET`/`HEAD`/`OPTIONS`만 허용했다. 화면이 자동 시도한 프런트 로그, presence join/leave 등 모든 쓰기 요청은 브라우저에서 차단했다. 저장·확정·역분개·등록 버튼은 누르지 않았다.

## 7. 상세 화면 네트워크 요청 전수 관찰

대표 상세 `2026/04/05-1`을 연 뒤 안정화 대기 동안 발생한 회계 상세 관련 응답 원문(식별자는 마스킹):

```text
200 GET /accounting/journals/<opaque-token>
400 GET /accounting/journals/<opaque-token>/collab/comments?limit=20
400 GET /accounting/journals/<opaque-token>/collab/presence
400 GET /accounting/journals/<opaque-token>/collab/edits
403 GET /accounting/journals/<opaque-token>/collab/stream
403 GET /accounting/journals/<opaque-token>/collab/stream
400 GET /accounting/journals/<opaque-token>/collab/edits          (retry)
400 GET /accounting/journals/<opaque-token>/collab/comments?limit=20 (retry)
```

400 응답 body 원문:

```text
comments -> 400 {"success":false,"code":"INVALID_INPUT","message":"요청 파라미터 형식이 올바르지 않습니다."}
presence -> 400 {"success":false,"code":"INVALID_INPUT","message":"요청 파라미터 형식이 올바르지 않습니다."}
edits    -> 400 {"success":false,"code":"INVALID_INPUT","message":"요청 파라미터 형식이 올바르지 않습니다."}
```

- 수치: 상세 관련 응답 **8건 = 200 1건 + 400 5건 + 403 2건**.
- `comments`, `presence`, `edits` 세 GET 경로가 opaque token을 UUID로 복원하지 못한다. 화면에도 `코멘트를 불러오지 못했습니다`, `수정 이력을 불러오지 못했습니다`가 표시된다.
- `collab/stream` 403 2건도 전수 기록했으나, 이번 token 누락 판정은 요구 조건의 400 응답 3경로로 확정했다.
- 캡처: `02-uuid-zero-and-detail-network-all-statuses.png`.

## 도달 가능한 결함

### SOL-1072-LIVE2-01 — 상세 협업 하위 경로 opaque token 복원 누락

- 재현: 회계 → 분개장 → 임의 전표 상세.
- 본 상세 `GET /accounting/journals/{token}`은 200이지만 `collab/comments`, `collab/presence`, `collab/edits`가 모두 400 `INVALID_INPUT`.
- 사용자 화면에서 코멘트와 수정 이력을 불러오지 못한다.
- 같은 상세을 다시 열어도 재현된다. DRAFT와 POSTED 대표 전표 양쪽에서도 재현됐다.
- fix가 상세/게시/역분개 본 경로만 복원하고 상세가 자동 호출하는 협업 하위 경로에는 복원을 적용하지 않은 도달 가능 결함이다.

**도달 가능한 결함 합계: 1건.**

## 판정

- 원 UUID 노출 결함: **해소** — 목록 133행, 상세 133건, 중첩 lines 전수 UUID 0건.
- 회귀 핵심 수치: 확정 2/2, 미정 10/10, 대표 전표 3/3·7/7 라인, API·DB 133/133, `?` 0건.
- 새 도달 가능 결함: 상세 협업 token 복원 누락 1건.
- **머지 불가**. `comments`·`presence`·`edits`의 opaque token 복원 후 동일 실 GUI 네트워크 전수 재검증이 필요하다.

## 미검증

- 게시와 역분개의 실제 성공은 공유 DB 쓰기가 필요하므로 실행하지 않았다. DRAFT/POSTED 상세 복원, 대상 일치, 액션 버튼 노출까지만 확인했다.
- `collab/stream`의 403은 전수 기록했으나 이번 결함의 400 token 복원 누락과 별개 권한 응답이므로 원인 판정을 확장하지 않았다.

## 공유 DB 쓰기 확인

**공유 DB에 쓰지 않았다.** DB 명령은 `BEGIN READ ONLY`, `SELECT`, `ROLLBACK`뿐이다. 애플리케이션 연결도 세션 기본 읽기 전용으로 강제했다. 화면의 저장·확정·역분개·등록 버튼을 누르지 않았으며, 브라우저에서 발생한 모든 비조회 요청은 서버 도달 전에 차단했다.
