## 1. ① R13 결함 재현 시도 — PASS

신규 견적에서 거래처 `주식회사 제이앤피공조`를 선택하고 모델명 `AF17DX738WSN`을 확정했다.

```text
모델명: AF17DX738WSN
품목명: 24년형 가정용 에어컨 무풍갤러리 화이트 실내기
규격:   17평 무풍갤러리 화이트
출처:   CATALOG
```

R13과 같은 순서·형식으로 사용자 규격을 입력했다. 각 시점의 화면 input 값과 렌더된 React 라인 상태를 함께 읽었다.

```text
사용자 규격 입력값: R14 USER SPEC 1
immediate:  R14 USER SPEC 1 · specificationSource=USER
after100ms: R14 USER SPEC 1 · specificationSource=USER
after700ms: R14 USER SPEC 1 · specificationSource=USER
afterBlur:  R14 USER SPEC 1 · specificationSource=USER
```

R13에서는 100ms 안에 `17평 무풍갤러리 화이트`로 되돌아갔지만 R14에서는 네 시점 모두 사용자 값이 유지됐다.

저장 요청 원문 요약:

```text
POST http://localhost:8080/slips/estimates 201
견적번호: 2026/08/07-2
lines[0].modelName=AF17DX738WSN
lines[0].specification=R14 USER SPEC 1
lines[0].specificationSource=USER
lines[0].quantity=1
```

DB는 `R14 USER SPEC 1 | USER`였다. 저장 뒤 견적 `2026/08/07-2` 편집 화면에 다시 들어가도 모델명, 사용자 규격, `USER` 출처가 그대로 복원됐다.

## 2. ② RED-B — 원격 협업 동기화 — PASS

같은 계정이지만 별도 Chromium 브라우저 컨텍스트로 두 번째 세션을 만들고 같은 견적 편집 화면을 열었다.

```text
세션 2 입력:               R14 REMOTE SPEC 1
세션 1 화면 반영:          R14 REMOTE SPEC 1
세션 1 specificationSource USER
원상복구 뒤 세션 1:        R14 USER SPEC 1
원상복구 뒤 세션 2:        R14 USER SPEC 1
```

두 번째 세션의 실제 원격 변경이 첫 번째 세션에 반영됐다. S36의 stale snapshot 무시가 원격 변경까지 먹지 않았다. 원격 관측 뒤 두 세션의 협업 초안은 저장된 사용자 규격으로 원상복구했다.

## 3. ③ RED-C — 카탈로그 계승 — 지정 값 계약 PASS

편집 가능한 기존 라인에서 실제 품목을 교체·해제·재확정했다.

```text
AJ012BN1PBC2 확정: 모델 AJ012BN1PBC2 · 규격 '소형 내장형' · CATALOG
품목 해제:         모델 '' · 품목명 '' · 규격 ''
AF17DX738WSN 재확정: 모델 AF17DX738WSN · 규격 '17평 무풍갤러리 화이트' · CATALOG
```

지정된 세 가지 화면 값 계약은 모두 유지됐다.

다만 제시된 갈래 밖의 관측이 하나 있다. 카탈로그 품목 해제 후 규격 값은 즉시 비었지만 렌더된 라인 상태의 `specificationSource`는 1.3초 뒤에도 `null`이 아니라 `USER`였다.

```text
after clear immediate: specification='' · specificationSource=USER
after clear 1300ms:    specification='' · specificationSource=USER
```

이번 라운드 요구사항은 “품목 지움 → 규격 비워짐”이므로 값 계약은 PASS로 집계했다. 빈 규격의 provenance 잔류는 고치거나 정상으로 간주하지 않고 PM 판단용 관측으로 남긴다. 재확정하면 `CATALOG`로 정상 수렴했다.

## 4. ④ 동일 계열 타 필드 관측 — 화면 되돌림 없음

### 4.1 품목명

```text
사용자 품목명 입력값: R14 USER PRODUCT NAME
immediate:  R14 USER PRODUCT NAME
after100ms: R14 USER PRODUCT NAME
after700ms: R14 USER PRODUCT NAME
afterBlur:  R14 USER PRODUCT NAME
```

화면 값은 네 시점 모두 유지됐다. 내부 라인 draft는 immediate~after700ms 동안 기존 카탈로그 품목명을 유지하고 blur 때 사용자 품목명으로 커밋됐다. 즉 화면 되돌림은 없었고, 품목명 입력은 blur 전 로컬 input buffer / blur 후 라인 draft 반영 방식으로 관측됐다.

### 4.2 수량

```text
사용자 수량 입력값: 7
immediate:  7
after100ms: 7
after700ms: 7
afterBlur:  7
```

화면 값과 내부 라인 draft 모두 네 시점에서 `7`을 유지했다. 품목명·수량은 요청대로 수정하지 않았다. 관측 후 협업 초안의 품목명·규격·수량을 저장된 값으로 원상복구했으며 추가 저장은 하지 않았다.

## 5. DB 확인 SQL 원문

저장 직후 요청된 두 컬럼 확인:

```sql
SELECT specification, specification_source
FROM estimate_lines
WHERE is_deleted=false
  AND estimate_id = (
    SELECT id FROM estimates
    WHERE is_deleted=false AND estimate_no='2026/08/07-2'
  )
ORDER BY line_no;
```

```text
specification     | specification_source
R14 USER SPEC 1   | USER
(1 row)
```

라운드 종료 전 최종 DB 확인:

```sql
SELECT e.estimate_no, e.status, e.version, e.total_amount,
       el.line_no, el.model_name, el.product_name,
       el.specification, el.specification_source, el.quantity
FROM estimate_lines el
JOIN estimates e ON e.id=el.estimate_id
WHERE el.is_deleted=false
  AND e.is_deleted=false
  AND e.estimate_no='2026/08/07-2'
ORDER BY el.line_no;
```
