# #825 S7 CI red 해소 보고서

작성일: 2026-08-08  
기준 SHA: `6a5358822fda7a1146e37adf659311c2dba9dba1`  
범위: 타입 계약 보완 및 Desktop mock Playwright stale assertion 갱신

## 1. 결론

- `PartnerAutocompleteProps`에 `autoSelectSingleResult?: boolean`을 추가했다.
- 기존 `...rest` 전달 경로가 `AsyncAutocomplete`까지 이미 연결되어 있어 런타임 동작은 유지하고, CI 타입 선언만 누락된 상태였다.
- S2에서 opt-in 된 소비처의 옛 dropdown/listbox 단정을 새 결과 모달 또는 단일 후보 즉시 확정 계약에 맞게 갱신했다.
- S6 AC-5 변경은 이번 red의 원인이 아니다. S6은 AC-5 spec 단정만 바꿨고, 이번 실패 표면은 S2 소비처 전환 및 그에 대한 기존 spec이었다.

## 2. autocomplete 소비처 전수

S2 대표 3곳의 직접 컴포넌트는 다음 3종이다.

| 대표 화면 | 소비 컴포넌트 | opt-in |
|---|---|---|
| `/admin/approval-line-config` | `MultiSelectAutocomplete` | `multiple` |
| `/accounting/bank-transactions` | `PartnerAutocomplete` | `single` + 단일 후보 즉시 확정 |
| `/sales/partner-orders` 병합 모달 | `WarehouseAutocomplete` | `single` + 단일 후보 즉시 확정 |

전체 desktop 전수에는 이 외에도 `AsyncAutocomplete`(JournalForm, DocumentReferencePicker), `ProductAutocomplete`(견적/품목), 그리고 다수의 기존 `PartnerAutocomplete`·`WarehouseAutocomplete` 소비처가 있다. 미지정 소비처는 기존 dropdown 경로를 유지한다.

## 3. 결함 원인

### 타입 오류

S2에서 `BankTransactionPage`가 `PartnerAutocomplete`에 아래 props를 전달했다.

```text
resultSelectionMode="single"
autoSelectSingleResult
resultSelectionTitle="거래처 검색 결과"
```

`PartnerAutocompleteProps`에는 `resultSelectionMode`와 `resultSelectionTitle`만 있었고 `autoSelectSingleResult`가 빠져 있었다. `AsyncAutocomplete` 구현과 `WarehouseAutocomplete`에는 이미 해당 계약이 있었다.

초기 재현 원문:

```text
src/renderer/routes/BankTransactionPage.tsx(424,15): error TS2322
Property 'autoSelectSingleResult' does not exist on type 'IntrinsicAttributes & PartnerAutocompleteProps & RefAttributes<HTMLInputElement>'.
```

### 로컬 green 오판

CI 범위는 design-system 선행 build 후 desktop의 다음 명령이다.

```text
npm run typecheck
```

초기 워크트리에서 이 명령을 파이프 없이 재실행하자 위 오류로 exit 1이 재현됐다. `PartnerAutocomplete` source와 당시 `dist/index.d.ts` 모두 해당 prop이 없었으므로 cache가 오류를 숨긴 경우가 아니다. S2 보고서에도 typecheck 실행 기록이 없고, 저장소 핸드오프에는 `npm run typecheck 2>&1 | tail -6; echo $?`가 `tail`의 종료코드를 보고하게 만든 전례가 기록돼 있다. 따라서 보고된 local green은 CI와 동일 범위가 아니었거나 파이프 뒤 종료코드 오판으로 판단한다.

## 4. Playwright 원인 및 수정

격리 조건:

```text
CI=true
VITE_API_BASE_URL=http://127.0.0.1:1
workers=2
```

원래 전체 hard gate는 `667 tests` 중 `660 passed`, `1 flaky`, `6 failed`였다. 실패 원문은 mock endpoint 404가 아니라 다음 stale 기대였다.

- `d2-order-merge` 3건 및 `partner-order-list-badge-refresh` 2건: `HQ` 단일 후보가 즉시 확정되어 `aria-expanded="false"`인데 옛 spec이 listbox를 기대했다.
- `codef-fe-bc3` 1건: BankTransaction의 새 결과 모달 계약인데 옛 spec이 `거래처 목록` listbox를 기대했다.

수정은 앱 동작을 되돌리지 않고 spec helper/단정을 양쪽 계약에 맞췄다. 단일 후보는 즉시 확정을 확인하고, 다건 Bank 검색은 결과 모달의 폭을 확인한다.

대표 S2/S5와 수정된 실패 표면 재검증:

```text
Running 7 tests using 2 workers
7 passed (11.4s)
TARGET_EXIT=0
```

S2/S5 대표만 별도 격리 재검증:

```text
Running 7 tests using 2 workers
7 passed (8.7s)
PLAYWRIGHT_EXIT=0
```

최종 전체 Desktop mock hard gate:

```text
Running 667 tests using 2 workers
667 passed (6.9m)
PLAYWRIGHT_FULL_FINAL_EXIT=0
```

S5 입금자명 케이스는 전체 suite에서 1회 flaky로 분류됐으나 단독, 대표 worker 2, 수정 대상 묶음에서는 통과했다. S6 AC-5 변경과의 직접 관계는 확인되지 않았다.
