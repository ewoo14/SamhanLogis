## 1. 원인

B-01의 원인은 직전 수정이 README의 slip-service 명령에 `--spring.profiles.active=local`을 강제한 것이다. `local`은 PostgreSQL이 아니라 `jdbc:h2:mem:slip_db`를 선택하고, `ddl-auto=create-drop`, Flyway 비활성, Eureka 비활성으로 바꾼다. `SPRING_PROFILES_ACTIVE=dev`가 환경에 있어도 명령행 프로파일이 우선하므로 dev seeder도 실행 대상에서 빠진다.

B-02는 `.env.dev-seed`의 세 UUID가 실재하지 않는 placeholder가 아니라 다른 실재 창고를 가리키는 fallback인데, 그 사실이 파일에 드러나지 않았던 문제다. 값 변경은 기존 전표 1,428건의 참조 의미를 바꾸므로 선택하지 않았다.

각 단정의 Linux 검토:

- Linux `source`는 같은 셸에 `SPRING_PROFILES_ACTIVE=dev`와 UUID를 export한다.
- Spring Boot의 command-line property 우선순위와 profile YAML 병합은 Linux/Windows가 다르지 않다.
- PostgreSQL JDBC URL, Flyway, Eureka 및 `@Profile("dev")` 조건은 OS 경로가 아니라 JVM 설정이므로 CI(`ubuntu-latest`)에서도 같은 판정이다.

## 3. fix와 선택 근거

선택한 수정은 다음 두 가지다.

1. README의 local 강제를 제거하고, 개별 서비스 실행 전에 `source infrastructure/env-templates/.env.dev-seed`를 수행하도록 했다. 따라서 `dev` profile, PostgreSQL 기본 URL, Flyway, Eureka, dev seeder 조건이 의도한 개발 경로에 함께 전달된다.
2. `.env.dev-seed`의 UUID 값은 유지하고, 업무 창고가 없는 세 값이 어떤 실재 fallback 창고인지와 기존 전표 1,428건 보존 이유를 주석으로 명시했다.

버린 대안:

- local 프로파일을 유지: H2/휘발성 DB와 Flyway·Eureka·seeder 비활성이라는 B-01을 보존하므로 폐기했다.
- UUID 3개를 업무 창고 UUID로 교체: 기존 1,428건이 다른 창고로 재해석될 수 있어 폐기했다.
- 가드 삭제·fallback 전면 허용: 축약형/공백/중괄호/하이픈 생략 차단을 약화하므로 폐기했다.

### 5.3 창고 정체성과 전표 보존

`.env.dev-seed`의 실제 대상은 다음과 같이 파일 안에 명시했다.

| 변수 | 실제 창고 | 의미 |
|---|---|---|
| `WAREHOUSE_UUID_HQ` | HQ-001 본사창고 | 일치 |
| `WAREHOUSE_UUID_HUBAL` | VH-001 1호차 차량재고 | 업무 창고 부재에 따른 fallback |
| `WAREHOUSE_UUID_ANSEONG` | CS-001 거래처 위탁창고 | 업무 창고 부재에 따른 fallback |
| `WAREHOUSE_UUID_CHANGWON` | VR-001 가상창고 | 업무 창고 부재에 따른 fallback |

값을 변경하지 않았고, 공유 DB는 write하지 않았다. 직전 실데이터 read-only 계수와 대조해 fallback 세 UUID를 참조하는 기존 전표는 `490 + 502 + 436 = 1,428건`이며, 이번 변경으로 깨지는 전표 수는 **0건**이다.
