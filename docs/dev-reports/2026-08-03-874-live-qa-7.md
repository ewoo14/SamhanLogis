## ① ACCEPTED → CONFIRMED 판정

상태 머신 근거:

- `services/slip-service/.../Slip.java` 도메인 정의: 출고는 `DRAFT → SAVED → SENT → ACCEPTED → PROCESSING → INSPECTING → COMPLETED → SHIPPING → DELIVERED → CONFIRMED`.
- `Slip.confirm()` 가드는 OUTBOUND에서 `DELIVERED`만 허용한다. 따라서 `ACCEPTED → CONFIRMED` 직행은 정의상 불가하다.
- `SlipController`의 실제 전이 endpoint는 `/process`, `/inspect`, `/complete`, `/ship`, `/deliver`, `/confirm` 순서다.

실행 경로:

1. 실 API 조회: `GET /slips?slipType=OUTBOUND&from=2026-08-03&to=2026-08-03`에서 `2026/08/03-6`, UUID `16b96c42-e9f3-4c8c-b899-210427741644`, 상태 `ACCEPTED` 확인.
2. 실 GUI, `dev_manager`로 상세 진입 후 `완료 (처리 시작)` 클릭: `POST /slips/16b96c42-e9f3-4c8c-b899-210427741644/process` → HTTP 200, 상태 `PROCESSING`.
3. 다음 단계 `완료 (검수 시작)` 클릭: HTTP 403, 화면 메시지 `출고 검수 권한이 없습니다 — 검수자 결재자(그룹/개인)만 처리할 수 있습니다`.
4. 실 결재라인 조회: `GET /auth/approval-line-configs/SLIP_OUTBOUND/default-approvers` → 검수자 `김기철(kimgicheol)`, `김은지(kimeunji)`.
5. 지정 검수자 `kimgicheol`로 실 GUI 진입: `완료 (검수 시작)` 버튼이 비활성(`title=다음 단계: 검수 시작`). 실제 클릭 시도는 Playwright가 disabled 상태로 timeout.

판정:

**`ACCEPTED → CONFIRMED` 직행은 불가.** 중간 상태를 거치면 이론상 도달 가능한 상태 머신이지만, 현재 실 사용자 경로는 `PROCESSING`에서 검수 전이 단계가 막혀 `CONFIRMED`에 도달하지 못한다.

재현 절차/관찰:

- `dev_manager` 로그인 → `/sales/{UUID}` → `완료 (처리 시작)` → 성공.
- 동일 화면에서 `완료 (검수 시작)` → HTTP 403 및 위 권한 메시지.
- `kimgicheol` 로그인 → 동일 상세 → 검수 버튼 disabled.
- `kimeunji`도 동일 결재라인 사용자로 확인되지만, 이번 라운드에서는 기존 전표를 더 진행하지 않고 멈췄다.
