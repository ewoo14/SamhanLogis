# 2026-08-02 #1015 CI 실패 — Config Audit Guard

## 원인 조사

- 실행 명령: `./infrastructure/scripts/validate-config-audit.ps1 -Detailed`
- 가드 규칙: 저장소의 다운스트림 URL 기본 포트와 각 compose 파일이 선언한 동일 서비스의 실제 포트가 일치하고, 필수 URL/template 계약이 모두 존재하는지 정적으로 검사한다.
- 실패 원문:

```text
Status   Variable                         Service                   ConfiguredPort ComposePort
MISMATCH SAMHAN_PARTNER_ORDER_SERVICE_URL partner-order-service                8095 8088
MISMATCH SAMHAN_SLIP_SERVICE_URL          slip-service                         8092 8086

config-audit validation failed: 2 issue(s)
At C:\dev\Samhan-Public\.claude\worktrees\t1015b\infrastructure\scripts\validate-config-audit.ps1:331 char:5
    throw "config-audit validation failed: $($failures.Count) issue(s)"
```

원인은 신규 `/internal/partner-activity/{partnerCode}` 라우트의 게이트웨이 노출 누락이 아니다. `infrastructure/scripts/validate-config-audit.ps1`는 내부 라우트 등록을 검사하지 않고, `SAMHAN_*_SERVICE_URL` 및 `samhan.*-service.url`의 포트와 compose 포트 정합을 검사한다. `partner-auth-service`의 `partner-activity` 기본값만 각각 `8095`, `8092`로 잘못 선언되어 있었다. compose의 실제 포트는 partner-order `8088`, slip `8086`이다.

## 수정

`services/partner-auth-service/src/main/resources/application.yml`의 기본 URL을 다음처럼 정정했다.

```yaml
order-url: ${SAMHAN_PARTNER_ORDER_SERVICE_URL:http://partner-order-service:8088}
slip-url: ${SAMHAN_SLIP_SERVICE_URL:http://slip-service:8086}
```

게이트웨이 라우트는 추가하지 않았다. 저장소 확정 계약대로 `/internal/**`는 게이트웨이 비노출이며 호출자가 서비스에 직결한다.

## 재검증 원문

실행 명령: `./infrastructure/scripts/validate-config-audit.ps1 -Detailed`

```text
OK     samhan.partner-order-service.url partner-order-service 8088 8088
OK     samhan.slip-service.url          slip-service           8086 8086
...
config-audit validation passed: 160 URL/template checks
```

전체 결과의 모든 행이 `OK`였고 프로세스 종료 코드는 `0`이었다.

## 직전 라운드 성과 확인

- `PartnerActivityClient`가 주문 서비스와 출고 서비스의 활동 시각을 각각 조회한다.
- `PartnerActivity.lastActivityAt()`가 주문 확정 시각(`lastOrderAt`)과 출고 시각(`lastShipmentAt`) 중 더 최신 값을 선택한다.
- `PartnerApprovalService.previewLongUnused()`가 그 최신 업무 시각이 현재 시각보다 30일 이상 오래된 경우에만 장기미발주 후보로 판정한다.
- 따라서 로그인·비밀번호 시각이 아니라 주문·출고 시각 기준 판정이 유지된다.
- 내부 응답은 거래처코드와 시각만 사용하며 UUID·상세 전표를 노출하지 않는다.
