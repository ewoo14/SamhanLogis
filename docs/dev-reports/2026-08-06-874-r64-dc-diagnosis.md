SELECT p.partner_code, p.name, dc.id AS dc_config_id,
       dc.home_discount_rate, dc.commercial_discount_rate, dc.is_deleted
FROM partners p
LEFT JOIN dc_configs dc
  ON dc.partner_id=p.id AND dc.is_deleted=false

## 3. 서버 계산 경로와 끊김 지점

현재 별도 가격계산기는 존재한다.

```text
POST /internal/price-calculations
  -> InternalDcConfigController.calculate()
  -> PriceCalculationService.calculate()
  -> DcConfigService.findByPartnerCode()
  -> fixedDiscountRate ?? category global rate
```

`PriceCalculationService` 자체는 `fixedDiscountRate != null`이면 고정율을 우선하고, 없으면 품목 category에 따라 전역율을 선택한다. 그러나 이 경로는 전표 생성 서비스에서 호출되지 않는다.

실제 전표 생성은 다음과 같다.

```text
SlipFormPage 품목 선택
  -> product lookup / 거래처 기억단가 조회
  -> 입력된 selling price를 화면 unitPrice로 유지
  -> POST /slips
  -> SlipService.create()
  -> ProductClient.lookup() (존재 검증/상품 snapshot)
  -> addSlipLinesExpanded(... lineReq.unitPrice() ...)
  -> slip 저장
```

따라서 R63의 ① 전역DC FAIL, ② 고정DC 우선 FAIL, ③ `discountInfo=null`은 저장 중 값이 탈락한 것이 아니라 **저장 전에 가격계산 경로 자체가 호출되지 않은 결과**다. ④ DC 없는 거래처 PASS는 이 미구현 경로에서 정가를 그대로 저장하는 기본 동작과 일치한다.
