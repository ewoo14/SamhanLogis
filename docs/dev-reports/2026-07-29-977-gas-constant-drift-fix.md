## 2. 이 슬라이스가 먼저 답해야 하는 것

둘 다 **조건부**입니다. 고치기 전에 **도달성부터** 판정합니다.

- fallback `0.47` — 설정이 실제로 누락될 수 있는가? 누락되면 어느 화면에서 어떤 금액이 나오는가?
- `AXJ-YA1509N` — 이 모델이 실 카탈로그에 있는가? 있다면 DB 납품가는 얼마이고 차액은 얼마인가?

**도달 불가로 판정되면 고치지 않고 근거를 남깁니다.** 도달 가능하면 그때 fix 합니다.

## 3. 불변식

1. 레거시 GAS 정본이 내는 금액과 제품이 내는 금액이 같다 — 같은 입력에 대해
2. 정본과 다르게 가는 곳이 있으면 **그것이 의도된 결정인지 문서에 근거가 있어야 한다**
3. 고칠 때 **다른 5건(기존 불일치)의 현재 동작이 바뀌지 않는다**

## 4. 검증

- **RED-first** — 도달 가능 판정이 난 건에 대해 골든/회귀 테스트를 먼저 RED 로
- 골든 fixture 는 **실 카탈로그가 만들 수 있는 상태**만 (`legacy-quantity-golden/fixtures.js` 의 합성 상업 카탈로그 공백은 별건 이월)
- `estimate-app` 은 로컬에 `node_modules` 가 없어 `npm ci` 선행 — 안 하면 견적 골든 RED 를 CI 에서야 본다

## 5. 다루지 않는 것

## 6. 결론 (2026-07-29 라운드 1)

### ① 에어디자이너 fallback `0.47` — **도달 불가 · 0원 · 코드 변경 없음**

`getPricingConfig_()` 가 매번 `p = { ...DEFAULT_PRICING }` 로 시작하고 스크립트 속성·거래처 설정은 **유효한 숫자일 때만** `HOME_DISCOUNT_RATE` 를 덮습니다. 따라서 `Code.js:326` 조건이 항상 true 이고 **마지막 `0.47` 은 실행되지 않습니다.**

거래처별 설정에 null 은 존재합니다(라이브 `partner-dc-configs` 기준 홈 null **63건** · 상업 null **91건**). 그러나 그 null 은 제품 프론트 `CONFIG` 전역값으로 대체되고 **라이브 전역값은 홈/상업 모두 `0.4500`** 입니다.

### ② `AXJ-YA1509N` — **제이시스템 전용 계약단가** (개발책임자 결정)

사실관계는 확인됐습니다:

```text
product_code | model_name  |       name        | selling_price | purchase_price | status
             | AXJ-YA1509N | Y형 실내기 분기관 |      45100.00 |       45100.00 | ACTIVE
```

GAS 정본은 `제이시스템 전용 주문서 인식/Code.js:492` 에서 `return 45000;`.

> 📌 **개발책임자 결정**: 그 GAS 는 **제이시스템 전용** 인식기이고, `45,000원` 은 **거래처별 계약단가**다. 전체 카탈로그를 바꾸면 안 된다.

⟹ **코드 변경 없음.** 거래처별 단가는 기존 **고정DC / 전역DC**(`dc_configs`) 구조로 다룰 일이며, 카탈로그 상수를 덮어쓰는 문제가 아닙니다.

🚫 라운드 중 구현자가 `db-catalog.js` 에 모델별 리터럴 `45000` 을 넣는 fix 를 제출했으나 **PM 이 반려**했습니다 — ⓐ #896 슬4 가 없애려는 하드코딩을 하나 더 추가하고 ⓑ 가격 정본인 DB 를 코드가 덮으며 ⓒ 같은 성격을 PR #980 은 마이그레이션으로 처리한 전례와 어긋나기 때문입니다. 무엇보다 `45,100` 은 **시트 sync 값**이라 마이그레이션으로 바꿔도 다음 sync 가 되돌립니다.
