## 확인 1 — 구현 대상과 현재 결함

- `RegionalService.classifyBySido()`가 `OutboundSlipSummary.address()`를 17개 시도 prefix와 비교하고 있다. 이는 지방 판정 계약(`delivery_tag = 'REGION'`)과 다르다.
- `PreClassifyService`는 REGION 마스터 기반 가배차 분류를 이미 제공하지만, 지방가배차 응답은 시도 분류 전용이고 배송 태그를 입력으로 받지 않는다.
- `SlipServiceClient.OutboundSlipSummary`에는 현재 `deliveryTag`가 없어 태그 기반 판정을 수행할 데이터 계약이 없다.
- 기존 테스트 `RegionalServiceTest`도 주소 기반 17개 시도 동작을 고정하고 있어, 요구된 RED-first 테스트로 교체/보강해야 한다.
- 확인된 소비처는 `ArologisAdminController`의 regional endpoint, 두 데스크톱의 pre-classify 화면/API, 저장 이력/CSV/복원 경로, 관련 IT·Playwright parity 테스트이다. UUID는 화면 응답에 포함하지 않는 현재 원칙을 유지해야 한다.
