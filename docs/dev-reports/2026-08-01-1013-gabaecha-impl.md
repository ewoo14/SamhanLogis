- 확인된 소비처는 `ArologisAdminController`의 regional endpoint, 두 데스크톱의 pre-classify 화면/API, 저장 이력/CSV/복원 경로, 관련 IT·Playwright parity 테스트이다. UUID는 화면 응답에 포함하지 않는 현재 원칙을 유지해야 한다.

### 실 DB 읽기 전용 판정 원문

공유 Docker 재빌드·재기동 없이 `samhan-postgres/slip_db`에서 `BEGIN; SET TRANSACTION READ ONLY; ...; ROLLBACK;`만 실행했다.

```text
 active_outbound | region | stack | no_tag
-----------------+--------+-------+--------
            2303 |     12 |    11 |   2218
(1 row)

(23 rows)
ROLLBACK
```

실 DB의 새 projection 입력 분포는 `REGION 12건`, `STACK 11건`으로 불변식 B와 일치한다. REGION 12건과 STACK 11건의 slip_no/tag/date 목록도 같은 읽기 전용 조회에서 함께 출력됐다. 현재 컨테이너는 재기동하지 않았으므로 새 artifact 배포 전 live HTTP jar가 교체됐다고 주장하지 않는다.

조회 명령 원문:

```text
docker exec samhan-postgres psql -U samhan -d slip_db -v ON_ERROR_STOP=1 -P pager=off -c "BEGIN; SET TRANSACTION READ ONLY; SELECT COUNT(*) AS active_outbound, COUNT(*) FILTER (WHERE delivery_tag = 'REGION') AS region, COUNT(*) FILTER (WHERE delivery_tag = 'STACK') AS stack, COUNT(*) FILTER (WHERE delivery_tag IS NULL) AS no_tag FROM slips WHERE slip_type = 'OUTBOUND' AND is_deleted = false; SELECT slip_no, delivery_tag, slip_date FROM slips WHERE slip_type = 'OUTBOUND' AND is_deleted = false AND delivery_tag IN ('REGION','STACK') ORDER BY delivery_tag, slip_date, slip_no; ROLLBACK;"
```
