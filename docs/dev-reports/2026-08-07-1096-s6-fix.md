## 1. 새로 가능해진 상태·문서 조합 열거 + 각각 밟은 결과

### RED-first

기존 S5 계약을 provenance 계약으로 바꾼 뒤 먼저 실행했다.

```text
Issue1096S2FixContractTest > s6_cleanupSelectsDocumentsBySeedLineProvenanceNotEstimateNumber() FAILED
Issue1096S2FixContractTest > s6_estimateListCarriesRestoreAvailabilityForDeletedRows() FAILED

```

실패 원인은 V117이 견적번호 집합으로 문서를 골랐고, 목록 응답·화면에 복원 가능 여부가 없었기 때문이다.

### 적용 후 상태

| 상태·문서 조합 | 결과 |
|---|---|
| 같은 견적번호지만 시더 provenance가 없는 정상 업무 `QUOTE_DRAFT`·미전환 견적 | V117의 견적 대상 임시 테이블에 들어가지 않는다. 헤더·라인·합계는 변경되지 않는다. 번호 일치만으로 오삭제되는 D1 경로를 제거했다. |
| 시더 품목 라인이 하나 이상 있는 활성 `QUOTE_DRAFT`·미전환 견적 | 혼합 여부와 관계없이 견적 ID가 문서 성질로 선택된다. 해당 견적의 헤더와 모든 활성 라인이 같은 cleanup actor로 soft-delete되어 C안과 확정 삭제 규모를 유지한다. |
| 시더 품목만 참조하는 순수 시더 견적 | 기존 product provenance 경로를 유지하므로 전량 삭제된다. 삭제 규모를 줄이지 않았다. |
| 이미 삭제된 순수 QA797 문서의 활성 QA 라인 | 헤더의 `is_deleted` 여부와 무관하게 시더 product ID 라인 정리 경로가 적용된다. 기존 삭제 헤더를 덮어쓰지 않으며 재활성화하지 않는다. |
| cleanup actor로 삭제된 순수 시더/QA 잔재 견적 | 목록 응답 `restoreAvailable=false`; FE는 `복원` 버튼을 렌더링하지 않는다. 일반 복원 409가 사용자 화면에 도달하지 않는다. |
| cleanup actor로 삭제된 혼합 4건(C안) | 헤더와 QA·정본 전 라인이 같은 cleanup actor로 삭제된다. 기존 서비스의 mixed QA+canonical 복원 허용 경로와 actor 일치 검사를 유지한다. |
| 정상 사용자가 삭제한 정본 견적 | 라인 그래프가 cleanup/순수 QA 잔재가 아니면 `restoreAvailable=true`이고 기존 삭제→복원 경로를 유지한다. |
| `deleted_by='issue-1096-test-seed-cleanup'` 일괄 되돌리기 | V117이 actor를 계속 동일하게 기록한다. 기존 주석의 actor 기반 SQL로 묶음 식별이 가능하다. 이번 작업에서 DB 복구 SQL은 실행하지 않았다. |

복원 가능 여부 계산은 헤더와 전체 라인의 삭제 actor 일치 여부 및 순수 QA/cleanup 판정을 재사용한다. 삭제행 목록은 soft-delete 상태를 계속 표시하되 복원 불가능한 행에는 액션을 노출하지 않는다.
