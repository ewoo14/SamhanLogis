- #1026 이후에도 남은 완전계승 범위는 판매전표별 원본 행·순서 경계, 싱글 구성품/세트 역매칭과 수량별 소비, 옵션 정액 DC 6종, 할인제외, 레거시의 기타 분기·가격 기준 차이 및 원본 GAS 실제 반환값과의 1:1 oracle 검증이다.

## 2. 현행 일마감 화면·기능 존재 여부

- 현행 데스크톱에는 `clients/desktop/src/renderer/routes/DailyClosingPage.tsx`가 실재하며, `routes/index.tsx`가 `/accounting/daily-closings`와 호환 경로 `/accounting/daily-closing` 양쪽에 `PermissionGuard(accounting.daily-closing:view)`로 등록한다; 사이드바는 `/accounting/daily-closing`으로 연결한다.
- 현행 백엔드에는 `DailyClosingController`의 `GET/POST /accounting/daily-closings`, `PATCH /accounting/daily-closings/{closingDate}/lock`과 `AccountingReportController`의 상세 `GET /accounting/closings/daily`가 실재하므로 화면 자리표시가 아니라 목록·실행/잠금·잠금해제·상세 재검증 기능이 있다.

## 3. 레거시 GAS 일마감의 집계·판정 항목

- 입력은 이카운트 판매전표 행이며 `일자_번호`로 전표별 그룹을 만들고 원본 행 순서를 유지한다(`Code.js:473-481`).
- 각 행은 거래처코드로 거래처별 전역DC를 찾고, 품목명에서 모델 토큰·구형/홈멀티/상업멀티/싱글 zone·구성품 class를 판별하며, 가격표에서 출고가·납품가·고정DC를 찾는다(`Code.js:462-468,483-558`).
- 행별 산출값은 `출고가`, `할인율 = 1 - 정수원 VAT포함 단가 / 출고가`, `총계 = 정수원 VAT포함 단가 × 정수 수량`, `확인`이며 거래처 전역DC 설명도 `DC` 필드에 붙인다(`Code.js:468,551-561`).
- 싱글은 수량 절댓값만큼 구성품 pool을 만들고(수량 0은 1개), 실내기별 후보 세트를 구성품 수 내림차순으로 탐색해 필수 실외기와 실제 존재 옵션을 매칭한다(`Code.js:568-617`).
- 싱글 판정은 `abs(매칭된 전표 구성품 VAT포함 단가 합계) == abs(카탈로그 구성품 납품가 합계 - 적용 옵션 정액 DC)`의 0원 완전일치이며, 성공한 수량 단위를 소비 처리한다(`Code.js:650-666`).
- 싱글 실내기·실외기·보조실내기는 해당 행의 수량 단위가 전부 소비돼야 통과하고, 판넬·리모컨·자재는 싱글 본체 부재/세트 소비/본체 실패/납품가 일치 순으로 판정한다(`Code.js:690-712`).
- 구형 AM·NJ·NS·AVX는 실제 할인율 50%를, 그 밖의 구형과 유연호스·발통세트·일자발·방진가대·AXJ는 VAT포함 단가와 납품가의 0원 완전일치를 검사하되 `isMultiApplied=false`이면 통과시킨다(`Code.js:671-689`).
- 멀티는 반올림 정수 실제 할인율과 기대율을 0%p 완전일치로 비교하며 기대율 우선순위는 `고정DC → 거래처별 상업/홈 전역DC → 45%`다(`Code.js:714-731`).
- 운임·절삭과 나머지 미분류 품목은 무조건 통과하며, 결과는 회계반영일자가 날짜이면 `pre`, 아니면 `main`, 전체는 `sum=main+pre`로 반환한다(`Code.js:668-670,733-744`).

## 4. 옵션 정액 DC 6종의 적용 방식

- 레거시는 거래처별 설정에서 360·4way·1way·스탠드·디럭스·1등급 금액을 읽어 `dc360/dc4way/dc1way/stand/deluxe/grade1`로 보존하고, 싱글 세트 하나를 판정할 때 해당하는 금액 하나의 절댓값을 선택한다(`Code.js:403-415,619-646`).
- 세트코드 분기는 360=`AC` 계열 8번째 `6`+9번째 `P`, 4way=`AC` 계열 `4`+`P|D`, 1way=`AC` 계열 `1`+`P|D`, 스탠드=`AP230*|AP290*` 또는 지정 `AP` 위치 규칙, 디럭스=`AP`의 지정 위치 `D/H`, 1등급=`AC|AP`의 9번째 `F`다(`Code.js:625-645`).
- 거래처 할인제외 품목이 세트 구성품명에 부분일치하거나 세트코드가 `AR...S`/`AF...S`이면 옵션 정액 DC만 0원으로 만들고 세트 금액 비교 자체는 계속한다(`Code.js:603-607,619-624`).
- 적용식은 `기대 판매금액 = 매칭된 카탈로그 구성품 납품가 합계 - 선택된 옵션 정액 DC`이며, 전표 구성품 VAT포함 단가 합계와 절댓값 기준 0원 완전일치할 때만 그 세트의 수량 단위를 소비 처리한다(`Code.js:650-656`).
- 현행 #1026 경로는 홈·상업 전역DC율만 `GlobalDiscount`에 전달하며 옵션 정액 6종이나 싱글 세트 구성품 목록을 `DiscountRevalidator`에 전달하지 않으므로, 옵션 정액 DC의 일마감 반영은 아직 0종이다.

## 5. 실 DB 옵션 정액 DC 보유 거래처 수

- `dc_config_db.dc_configs`를 `BEGIN TRANSACTION READ ONLY`로 직접 집계한 결과 활성 행 210행/거래처 210곳 중 옵션 정액 DC 6종 가운데 하나라도 채워진 거래처는 **46곳**이다; NULL 기준과 0원이 아닌 값 기준이 모두 46곳으로 같았다.
- 종목별 보유 거래처는 `discount_360_amount` **45곳**, `discount_4way_amount` **46곳**, `discount_1way_amount` **45곳**, `discount_stand_amount` **45곳**, `discount_deluxe_amount` **15곳**, `discount_first_grade_amount` **10곳**이며 각 컬럼도 NULL 기준과 0원이 아닌 값 기준이 같았다.
