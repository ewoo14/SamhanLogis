- 다음 확인 순서: 실 DB 읽기 전용 기존 입금보고서 건수 확인 → 실패 테스트 작성/RED 실행 → 최소 구현 → B/D/F 실행 검증 및 전 모듈 테스트.

### 판매전표 기준 판단

`clients/desktop/src/renderer/routes/SlipFormPage.tsx:1640-1714`의 데스크톱 라인은 `lines.map` 안에서 모든 라인에 `ProductAutocomplete`를 렌더한다. 빈행도 `lineProductValue`가 `null`일 뿐 autocomplete 자체는 숨기지 않는다. `SlipFormPage.tsx:585-588`의 초기 빈행과 `:678-687`의 마지막 행 자동 증식도 같은 렌더 경로를 사용한다.

따라서 빈행 autocomplete 렌더는 판매전표 기준과 일치한다. 구현이 과한 것이 아니라, 자동 빈행 추가 후에도 전체 화면 단일 selector를 사용한 테스트가 낡은 것이다. 테스트는 `cash-receipt-line-0` 같은 행 컨테이너 안에서 원래 의도한 입력을 찾아야 한다. `getAllBy...[0]`나 단정 삭제는 사용하지 않는다.

### 선택자 보정 후 추가로 드러난 B 불변식 확인

행 단위 selector 보정 후 재실행 결과는 모델 7/7 통과, 페이지 14/15 통과였다. 남은 신규 저장 테스트는 헤더 `금액=2480000`만 변경하고 행 1 금액은 공란으로 두어, 행 합계 0과 입금 총액 2,480,000이 어긋났다. 실행 원문은 다음과 같다.

이는 구현 오류가 아니라 불변식 B에 따른 정상적인 저장 거부다. 기존 테스트의 “유효한 신규 저장” 의도를 유지하려면 행 1 금액도 `2480000`으로 입력해야 한다.
