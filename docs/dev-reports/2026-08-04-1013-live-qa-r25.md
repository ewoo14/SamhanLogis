## 로그인 경로 규명

- 선행 성공 보고서 확인: R6 보고서(`.claude/worktrees/t874/.../2026-08-03-874-live-qa-6.md`)는 `dev_manager`가 `dev_p05_pass!`로 실제 GUI 로그인 후 토큰을 발급받고 `/auth/admin/permissions/my`를 호출했다고 기록한다. R2~R6 보고서(`.claude/worktrees/t1001b/...`)도 실제 Electron renderer에서 `dev_master`로 로그인했다고 기록한다.
- 선행 성공 경로: 로컬 renderer (`VITE_MOCK_MODE=0`, gateway `http://127.0.0.1:8080`)의 로그인 화면에서 계정 ID와 비밀번호 `dev_p05_pass!`를 입력하고 일반 로그인한다. 별도 비밀번호 변경 화면을 거치지 않았다.
- V5 소스 확인: V5는 `password_change_required=TRUE`를 주석으로 설명하지만, 현재 auth_db의 대상 계정들은 모두 `password_change_required=FALSE`다. 따라서 이번 401의 원인은 현재 DB의 첫 로그인 변경 플래그가 아니다.
- auth_db read-only 조회(2026-08-04): `dev_manager`, `janyeonggu`, `dev_dispatch`, `dev_master`, `dev_accountant`, `dev_staff`, `dev_sales`, `dev_warehouse` 모두 `enabled=true`, `is_deleted=false`, `failed_login_attempts=0`, `locked_at=NULL`, `password_change_required=false`.
- `password_changed_at`: `dev_manager`, `dev_master`, `dev_accountant`, `dev_sales`는 `2026-05-11 23:09:07.578225`, `dev_dispatch`, `dev_staff`, `dev_warehouse`는 `2026-06-07 13:21:32.735312`, `janyeonggu`는 `NULL`이다. `last_login_at`은 오늘 성공 보고서의 계정들에 갱신 기록이 있다.
- 현재 단계 결론: 정상 자격으로 로그인 가능한 상태로 보이며, 비밀번호 변경 흐름으로 인해 일반 로그인이 401인 상태라는 근거는 확인되지 않았다. 실제 GUI 로그인은 다음 단계에서 계정별로 재현한다.

## 접근 회복 실 GUI 판정

### 접근 가능 대상

실행 환경: 로컬 Vite renderer `http://127.0.0.1:5201`, `VITE_MOCK_MODE=0`, `VITE_API_BASE_URL=http://127.0.0.1:8080`, `VITE_APP_VERSION=2026/08/04-1`, Chrome Chromium executable을 Playwright로 구동. 스택 재배포·재기동 없음.

| 계정 | 로그인 | 메뉴 노출 | `#/arologis/dispatch-sms` | preview 호출 | 판정 |
|---|---|---|---|---|---|
| `dev_manager` | 성공 (`dev_p05_pass!`) | `배차안내 SMS` 노출 | 화면 렌더 | `POST /admin/notifications/dispatch-batch/preview` → 200 | 접근 가능 |
| `janyeonggu` | `dev_p05_pass!` → 401 원문 확인 후 `samhan!2026` → 성공 | `배차안내 SMS` 노출 | 화면 렌더 | `POST /admin/notifications/dispatch-batch/preview` → 200 | 접근 가능 |
| `dev_dispatch` | 성공 (`dev_p05_pass!`) | `배차안내 SMS` 노출 | 화면 렌더 | `POST /admin/notifications/dispatch-batch/preview` → 200 | 접근 가능 |

공통 화면 증거: `배차안내문자`, `Step 1. 미리보기`, 배차일 입력, `미리보기`, `배차일: 2026-08-03 · 출고전표 6건`이 실제 GUI에 렌더됐다. 실제 SMS 발송은 하지 않았다.

### 차단 대상

| 계정 | 로그인 | 메뉴 노출 | 직접 진입 결과 | 판정 |
|---|---|---|---|---|
| `dev_accountant` | 성공 (`dev_p05_pass!`) | `배차` 및 `배차안내 SMS` 미노출 | `#/arologis/dispatch-sms` 요청 후 `#/` 대시보드로 리다이렉트 | 차단 |

차단 화면에는 `[DEV-SEED] 개발회계 · ACCOUNTANT`, 대시보드만 렌더됐고 `dispatch-batch/preview` 호출은 없었다.

### 양방향 인원 수 실측

- V93 대상 접근 가능: MANAGER 2명(`dev_manager`, `janyeonggu`) + DISPATCH 1명(`dev_dispatch`) = **3명**, 실 GUI **3/3 접근 가능**.
- V92 회수 대상: `notification.dispatch-sms.send-audit` `is_deleted=true`인 활성 계정 distinct count = **25명**, auth_db read-only 실측.
- 차단 실 GUI 표본: `dev_accountant` **1/1 차단**. R24가 확인한 25개 계정 전체의 메뉴 차단을 GUI로 전수 반복하지는 않았으며, 전체 25명 판정은 DB의 V92 회수 상태와 대표 표본의 실제 화면 판정을 함께 보고한다.
- 참고: 현재 DB에는 MASTER role의 V93 `display` 보유 계정까지 포함하면 display permission 보유 계정 distinct count가 5명이다. 이번 R25의 PM 지정 대상 수 판정은 명시된 MANAGER 2명 + DISPATCH 1명 범위를 사용했다.

### 로그인 실패 원문

- `janyeonggu` / `dev_p05_pass!`: `아이디 또는 비밀번호가 올바르지 않습니다` 및 HTTP 401 `/auth/login`.
- `janyeonggu`는 DB `password_change_required=false`, `password_changed_at=NULL`, 잠금/실패 카운터 정상이다. 저장소의 기존 QA 시나리오에 기록된 `samhan!2026`으로 재시도하여 HTTP 200 및 대시보드 전이를 확인했다.
