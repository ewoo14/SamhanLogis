# S11 — 가드 루트 집합 보강

## 원인과 수정

PR #1107 / Issue #1101의 CI RED는 같은 구조적 원인이었습니다. 증거 writer를 레포 전체에서 내용 기반으로 찾는 G8c와 달리, 두 가드가 일부 하위 디렉터리만 고정 열거했습니다.

- G8c의 RED 원문: `scripts/lib/qa-credentials.test.cjs`가 관할 밖으로 보고됨. 이 파일은 새로 추가된 S10 가드 자체였습니다.
- `GUARD_ROOTS`에 `clients/desktop/src/renderer/test-utils`와 `scripts/lib`를 추가했습니다. G8c를 약화하거나 제외 목록을 추가하지 않았습니다.
- S10의 `SCAN_ROOTS`를 `['.']`로 바꿔 레포 루트 전체를 재귀 스캔하게 했습니다. 기존 `node_modules`/`.git` 건너뛰기와 가드 파일 자체 제외는 유지됩니다.

## 발견 소비자와 예외

루트 전체로 넓힌 뒤 S10이 발견한 자격 소비자는 **231건**이었습니다. 기존 세 루트(`clients/desktop`, `docs/qa`, `scripts`)에서 227건, 새로 스캔된 루트에서 4건이었습니다. 새 루트의 소비자는 `tools/manual-capture/capture-desktop.js`, `tools/manual-capture/capture-mobile.js`, `tools/operational-validation/import-notion-csv.ps1`, `tools/operational-validation/run-smoke-tests.ps1`이며, 직접 옛 키를 읽는 tracked 파일은 0건입니다.

`perf/k6/mixed-load.js`의 `__ENV.LOADTEST_PASSWORD`는 k6 런타임 API입니다. k6는 Node `fs`/module loader를 사용할 수 없고, `scripts/run-load-test.ps1`가 `-e LOADTEST_PASSWORD=$password`로 값을 주입합니다. 따라서 이 파일은 S10이 교정할 Node/PowerShell 직접 소비자가 아니며, 해당 정당한 예외와 fail-fast 성격을 S10 코드 주석에 남겼습니다.
