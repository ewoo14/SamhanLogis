# 2026-08-02 #1032 전표 요약 합계 수정 보고서

## 1. ①/② 계약 판단

판단: **② 불변식이 맞고 구현이 틀렸다.** 실패 테스트 이름이 “파생 단가×수량 drift가 아닌 저장된 공급가액+부가세를 사용한다”로 명시하고 있으며, 이는 기대값을 표현에 맞춰 바꿀 사안이 아니라 요약 합계의 원천을 저장값으로 고정하는 계약이다. 따라서 `displayTotalAmount`도 단가×수량 재계산이 아니라 저장된 공급가액과 부가세에서 파생되어야 한다. `totalAmount` 계약은 유지한다.

## 2. 조사 시작

보고서 작성 직후 코드와 테스트를 읽고, 금액을 읽거나 계산하는 계약 테스트를 전수 검색한다. 검색 결과와 개수는 확인 즉시 추가한다.

### 금액 계약 테스트 전수 조사

`services/slip-service/src/test` 전체에서 `totalAmount`, `displayTotalAmount`, `lineTotal`, `supplyAmount`, `vatAmount`, `unitPriceWithVat`, 단가/공급가액/부가세를 검색했다. 금액을 읽거나 계산하는 테스트 파일은 **46개**였다. `services`와 `clients`의 테스트까지 동일 검색을 확장하면 **169개** 파일이다. 이번 변경의 직접 경계는 `slip-service`의 전표 요약/응답 계약이며, 46개 파일 중 해당 DTO/요약·서비스·복원/조회 회귀 경로를 모두 영향 후보로 추적한다. 기대값만 바꾸지 않고 저장된 공급가액·부가세, legacy null fallback, `totalAmount` 계약을 각각 확인한다.

### 실패 재현 전

현재 구현을 먼저 실행해 CI 실패를 로컬에서 재현한 뒤 수정한다.

실패 재현 결과: `:services:slip-service:test --tests com.samhanair.logis.slip.web.dto.SlipSummaryAuthoritativeAmountsTest` 실행 시 `SlipSummaryAuthoritativeAmountsTest.java:28`에서 1개 실패, `1 test completed, 1 failed`, Gradle `BUILD FAILED`였다. 실패 원인은 `SlipSummary.of`가 저장 공급가액(`lineTotal`)만 요약 라인 합계로 반환하고 저장 부가세를 더하지 않는 것이다.

### TDD 추가 RED 및 원인 확정

`displayTotalAmount`의 legacy 경로가 저장 `lineTotal`보다 `unitPriceWithVat × quantity`를 우선하는 회귀 테스트를 추가했다. 요약 계약 테스트와 함께 실행한 결과 **6 tests completed, 2 failed**였고, 실패는 요약 합계 1건과 legacy 표시 합계 1건이었다. 따라서 기대값 갱신이 아니라 (1) 요약은 `SlipDisplayAmount.vatInclusive(line)`로 저장 공급가액+부가세를 사용하고, (2) 공급가액 null legacy 행도 저장 `lineTotal`을 우선하며 단가×수량은 저장 합계가 없을 때만 최후 fallback 하는 것이 근본 수정이다.

### 구현

`SlipSummary`의 요약 라인 합계를 저장 공급가액+부가세 기반으로 변경하고, `SlipDisplayAmount`의 legacy fallback 우선순위를 저장 `lineTotal`→단가×수량 순서로 수정했다. `totalAmount`와 라인 공급가액 필드는 변경하지 않았다.
