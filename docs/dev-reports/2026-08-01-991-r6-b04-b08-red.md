## B-04

### RED 시도 결과

**RED 재현 불가 — 직전 변경으로 해소됨.**

시도한 입력은 첫 번째 품명 `첫 번째 상품`을 가진 혼합 매출전표 한 라인과, 서로 다른 두 allocation이다.

- 첫 축: `AR80F07D21WS / singleSets / allocatedAmount 110`
- 둘째 축: `AM480AXVHJH1SY / commercialMulti / allocatedAmount 220`
- 라인 자체의 품명은 첫 상품으로 고정하고, 둘째 축에는 둘째 모델의 상품 가격을 주입했다.
- 기대값: 둘째 축의 출고가 `3000`, 납품가 `2500`.

현재 HEAD의 전용 테스트가 이 기대값을 통과했다. 따라서 현재 코드에서 B-04 실패 RED는 나오지 않았다.

### 변경 요지

직전 라운드에 반영된 exact 모델 snapshot 우선 해소가 allocation별 모델에 적용되어, 이번 라운드에는 B-04 코드 변경을 추가하지 않았다.

### 실측 건수(전후)

공유 DB 읽기 전용 집계:

- 활성 혼합 후보 매출전표 라인: `0건`
- 활성 allocation: `1건`, 그중 모델/축 보존 allocation: `0건`
- 축별 가격 어긋남: 변경 전 `0건` / 변경 후 `0건` (활성 혼합 대상 자체가 0건)
- 합성 전용 입력에서는 변경 전 공통 첫 상품 참조 `1건` → 현재 축별 참조 `0건`.
- 기존에 맞던 판정이 틀리게 된 건수: `0건`. 현재 DB에 기존 known 축 매출전표 라인이 없어 변경 대상이 없었다.

참고로 전체 매출전표 테이블은 비삭제 0건·삭제 1건이며, 고아로 보이는 비삭제 allocation 1건은 혼합 전표 실측 대상에 포함하지 않았다.

### 테스트

전용 입력에서 둘째 축 가격이 첫 축으로 오염되는 RED는 현재 HEAD에서 재현되지 않았다. 따라서 수정 전후의 실데이터 차이는 산출할 대상이 없으며, 위 합성 입력에서만 `1건 → 0건`으로 확인했다.

## B-08

### RED 시도 결과

**RED 재현 불가 — 직전 변경으로 해소됨.**

시도한 입력은 위와 같은 혼합 매출전표 1라인, 두 allocation(`singleSets` 공급가 100, `commercialMulti` 공급가 200), line-level 축 `null`이다.

- 기대 세금계산서 라인: 2건
- 기대 축: `singleSets`, `commercialMulti`
- 기대 공급가: 각각 `100.00`, `200.00`
- 기대 `UNKNOWN` 공급가: `0.00`

현재 HEAD의 전용 테스트가 모두 통과하여 B-08 RED는 나오지 않았다.

### 변경 요지

직전 라운드에 반영된 혼합 매출전표 allocation별 세금계산서 라인 snapshot 경로가 이미 축·수량·공급가액·부가세를 보존하고 있었다. 이번 라운드에는 B-08 코드 변경을 추가하지 않았다.

### 실측 건수(전후)

공유 DB 읽기 전용 집계:

- 활성 혼합 매출전표: `0건`
- 따라서 혼합→세금계산서 전환 대상의 `UNKNOWN` 공급가: 변경 전 `0원` / 변경 후 `0원`
- 원 보고 수치 `27,913,674원`: 현재 공유 DB에서 재현되지 않았다.
- 현재 전체 활성 세금계산서 라인은 22건이며, known 0건·`UNKNOWN` 22건·`UNKNOWN` 공급가 합계 `16,082,727원`이다. 이는 활성 혼합 전환 대상이 없고 기존 라인의 축 snapshot이 모두 null인 현재 데이터 상태이므로 B-08의 27,913,674원 증거로 사용하지 않는다.
- 기존에 맞던 판정이 틀리게 된 건수: `0건`. 현재 DB에 known 세금계산서 축이 0건이다.

### 테스트

현재 HEAD 전용 테스트는 혼합 allocation을 2개 세금계산서 라인으로 만들고 `UNKNOWN` 공급가 0원을 확인했다. 실데이터에는 재현 가능한 혼합 전환 행이 없어 실측 변경 건수는 `0건 → 0건`으로만 판정한다.
