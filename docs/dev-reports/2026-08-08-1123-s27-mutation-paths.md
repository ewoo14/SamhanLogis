# PR #1124 / 이슈 #1123 — S27 mutation paths fix

## 판정

코드 기준 S27 수정은 적용했다. 라이브 재배포와 실 gateway 호출은 이번 라운드에서 하지 않았다(개발책임자 규칙: 재배포 금지). 따라서 공개 4경로의 최종 실측 `409`와 Electron 권한 회수 클릭은 PM 재배포 QA에서 확인해야 한다.

이번 라운드에는 기존 전표 mutation과 DB 직접 조작을 하지 않았다. `S27-1123` 확인용 전표도 생성하지 않았다.

## RED-A 원문

S26 실측을 그대로 기준으로 삼았다.

## 근본 원인과 수정

### 결함 1 — direct PUT/DELETE

`SlipUpdateService`, `SalesSlipUpdateService`, `SlipDeleteService`, `SalesSlipDeleteService`에는 중앙 `SlipClosedDateGuard` 의존성과 호출이 없었다. 각 서비스의 전표 조회 직후 다음 판정을 추가했다.

```java
closedDateGuard.assertAllowed(slip.getSlipType(), slip.getSlipDate(), actorId.toString());
```

`SlipService`의 날짜·내용 mutation도 같은 날짜 축을 빠뜨리고 있었다. `editHeader`, `editDriver`, `updateSlip`, `addLine`, `removeLine`, `applyOverlayPatch`, `applyOverlayPatchBatch`, `softDelete` 모두 실제 mutation 전에 `assertAllowed`를 호출하도록 보강했다. 기존 lifecycle 전이는 이미 가드를 호출하고 있었고 변경하지 않았다.

### 결함 2 — 공개 배선

`SlipPublishController`는 `/api/v1/slips/...` 풀패스를 요구하지만 gateway의 generic `/api/v1/slips/**` route가 `StripPrefix=2`를 적용해 `/slips/...`로 전달했다. 발행 3개 경로보다 먼저 no-strip route를 추가했다.

`MobileSalesController`는 `/mobile/sales/**` 풀패스인데 해당 gateway route가 없었다. `slip-service-mobile-sales-noprefix` route를 추가했다.

### 결함 3 — `slip.period-lock`

S23 근거는 옳았다. `2026-07-05-720-month-end-close-lock-by-period-internal.md`에 기록된 대로 월마감 호출은 public `@RequirePermission(slip.period-lock)` 경로가 아니라 `POST /internal/slips/lock-by-period`로 이관되었고, `2026-07-05-27-slip-period-lock-dead-cleanup.md`는 BE 게이트 소비처 0건에 따라 일반 FE matrix row만 제거했다. V36 seed와 `PageCode`는 불변이었다.

따라서 이번 fix는 권한을 새로 부여하거나 보유자를 결정하지 않는다. 일반 `PAGE_GROUPS`에는 계속 노출하지 않되, 실제 활성 grant가 있는 계정을 선택했을 때만 `비노출 권한 회수` 영역에서 `slip.period-lock`의 7 action을 전체 OFF 할 수 있도록 했다. `PageCode` union에는 회수 요청의 타입·API 식별자만 복원했다. 진짜 폐기된 `notification.dispatch-sms.send-audit`는 union과 카탈로그 모두 계속 숨겼다.

## RED-B 원문

이번 라운드는 기존 전표를 바꾸지 않는 규칙 때문에 실 데이터 mutation을 재실행하지 않았다. S26 정상 경로 증거를 보존한다.

```text
OPEN_UNAUTHORIZED|403|전표 변경 권한이 없습니다.
OPEN_AUTHORIZED|200|COMPLETED
CLOSED_UNAUTHORIZED|403|전표 변경 권한이 없습니다.
CLOSED_AUTHORIZED_NO_EXCEPTION|409|마감된 날짜에는 신규 전표를 만들 수 없습니다.
CLOSED_AUTHORIZED_AFTER_EXCEPTION_GRANT|200|COMPLETED
active_slip_closing_baselines=0 -> 수정·삭제·복원·상태 전이 정상
```

S27 코드 테스트는 direct PUT/DELETE 서비스가 guard를 보유하고 호출하는지, `SlipService` 8개 mutation method가 호출하는지, 공개 route가 no-strip인지 각각 검증했다. 라이브에서 실제 몇 건이 차단되는지의 새 수치는 재배포 QA에서 산출해야 한다.

## ③ S23 근거 재확인 결과

제외가 옳았던 이유는 권한 자체가 폐기되어서가 아니라, 사용자 endpoint 권한에서 internal 월마감 호출 권한으로 이관되어 일반 matrix의 기능 행이 dead가 되었기 때문이다. 따라서 `slip.period-lock`을 `notification.dispatch-sms.send-audit`과 같은 V91/V92 폐기 목록으로 분류하면 안 된다. 이번 구현은 일반 카탈로그 비노출은 유지하고, 실제 보유 grant에 대한 회수 수단만 추가했다.
