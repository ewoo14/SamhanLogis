# PR #1078 · 이슈 #1075 — S8 SOL 2차 적대검증 지시서

## 1. 판정

**사용자 도달 결함 0건, 증거 무결성 BLOCK 1건. 머지 비권고.**

S6의 실사용 결함은 닫혔다. coedit 중 기존 확정행의 품목 교체는 데스크톱·모바일에서 가능하고, trailing 빈행의 품목 자동완성과 모든 행 삭제는 잠긴다. 기존행 교체 뒤 행 수는 3개로 유지되며 임시저장·발송 버튼까지 도달한다. 신규 작성에서는 품목 확정 뒤 다음 trailing 빈행이 생성된다.

다만 사용자 지시의 예외인 증거 무결성을 위반했다. `origin/main`의 `1062-line-input-ux.spec.ts` 단정 18개 중 2개가 현재 작업 트리에서 사라졌다. S7 보고서의 “기존 단정 18개 유지”는 재현되지 않는다.

## 2. 재현 및 근거

기준 파일을 아래 읽기 명령으로 직접 대조했다.

```powershell
git show origin/main:clients/desktop/playwright/1062-line-input-ux/1062-line-input-ux.spec.ts
```

`expect(...)` 줄 기준 결과는 기준 18개, 현재 38개이며 기준에서 빠진 단정은 정확히 다음 2개다.

```ts
await expect(page.getByTestId('estimate-form-line-3')).toBeVisible({ timeout: 10_000 })
await expect(page.locator('[data-testid^="estimate-form-line-"][data-price-source]')).toHaveCount(4)
```

두 단정은 비coedit 편집에서 기존 trailing 빈행을 확정하면 다음 빈행이 생기는 규약이다. 현재 coedit 시나리오를 구조 잠금 계약으로 바꾸면서 삭제됐고, S6 지시대로 coedit 비활성/폴백 편집 시나리오에 옮겨 보존하지 않았다.

실사용 경로는 mock 렌더에서 별도 확인했다.

- 데스크톱·모바일: 기존 라인 1 모델명 활성, trailing 라인 3 모델명 비활성, 라인 1·3 삭제 비활성.
- 데스크톱·모바일: 기존 라인 1에서 `AJ` 부분검색 후 `AJ052RXH5BC1` 확정 가능, 행 수 3 유지, 임시저장·발송 활성.
- trailing 수량 입력도 추가 우회로 조사했으나 값을 바꾼 뒤 행 수는 3으로 유지되어 구조 추가는 재현되지 않았다.
- 신규 작성: 후보 확정 뒤 다음 trailing 빈행 생성 시나리오 통과.

## 3. 원인

S7은 기존 coedit 편집 Playwright 시나리오의 의미를 “trailing 빈행 확정 후 다음 빈행 생성”에서 “coedit 구조 잠금”으로 교체했다. 두 계약은 서로 다른 실행 조건인데, 원래 계약을 비coedit 편집 또는 provider 실패 폴백 시나리오로 이전하지 않았다.

그 결과 현재 테스트 총 단정 수는 늘었지만 기준 단정의 부분집합 보존은 깨졌다. 총 개수 비교만으로는 이 삭제를 검출할 수 없다.

## 4. 수정 지시

1. `1062-line-input-ux.spec.ts`에 coedit 비활성 또는 provider 실패 폴백 편집 시나리오를 추가한다.
2. 그 시나리오에서 기존 편집 화면의 trailing 빈행에 품목을 확정하고 위 2개 원 단정을 문장 그대로 복원한다.
3. 현 coedit 시나리오의 기존행 교체·행 수 3 유지·trailing/삭제 잠금 단정은 그대로 보존한다. 상반된 계약을 같은 실행 조건에 섞지 않는다.
4. 기준 단정 검사는 개수뿐 아니라 `origin/main`의 각 단정 문자열이 현재 파일에 존재하는지 부분집합으로 비교한다.
5. 수정 뒤 데스크톱·모바일 coedit 값 교체, coedit 구조 잠금, 비coedit 편집 자동 빈행, 신규 작성 자동 빈행을 함께 재실행한다.
