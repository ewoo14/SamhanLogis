## Fix 1 — 저장 transaction·작성자·배치번호

- `LedgerImageService`의 class-level `@Transactional(readOnly = true)`를 제거하고, 자동저장 메서드를 명시적 쓰기 transaction으로 전환했다.
- 기존 3인자 호출은 유지하되 4인자 `actor` overload를 추가하고, controller의 `X-User-Id`를 `processed_by`로 전달했다.
- 배치번호는 실제 거래처 코드 최대 20자와 결합하지 않고 문서키에 거래처 코드를 보존한다. `LED` + `yyyyMMddHHmmssSSS` 형식으로 20자 이내를 유지해 컬럼 초과·잘림을 피한다.

## 최종 불변식 판정

- A: 실제 PostgreSQL SELECT에서 `has_snapshot=true` 확인.
- B: 실제 SELECT batch_no `LED20260801172203045`는 20자, 코드 자체를 batch_no에서 잘라내지 않고 document_key에 보존.
- C: 실제 SELECT `processed_by=df881e51-b4c5-453e-80f8-1ec24ff63320` 확인.
- D: frontend API 2건 GREEN, 화면에 이력 표·복원 button production code 연결.
- E: 이력 query에 작성자 제외 조건을 추가하지 않았고, 작성자는 snapshot `processed_by`로 보존.
- F: 권한 78건에서 ACCOUNTANT/MANAGER/MASTER 200, SALES 403 baseline 유지.
- G: 기존 3인자 `getLedger` 호출 호환 overload 유지, 기존 endpoint/권한 guard 변경 없음.
