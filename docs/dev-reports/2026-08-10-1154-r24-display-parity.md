# PR #1154 R24 — 응답·화면 표시 정합성

## 판정

결함 1건을 수정했다. `CSV_ENCODING` 보류 행의 페이지 조회 응답이 staging 원문 `����`를 그대로 내보내 화면에 표시하던 누수를 서버 조회 projection에서 차단했다. 화면은 U+FFFD를 판별하지 않으며, 서버가 내려준 `rawName`을 그대로 표시한다.

## 원인 확정

- `services/partner-service/src/main/java/com/samhanair/logis/partner/service/EcountPartnerImporter.java:814-820`
  - `findRejectionPage`가 `staging.ecount_partner_raw.raw_name`을 그대로 DTO `items[].rawName`으로 반환했다.
  - 실제 `reject_reason`은 `CSV_ENCODING` 단독값이 아니라 `CSV_ENCODING: 거래처명에 치환문자(U+FFFD)가 포함됨`이었다.
- `clients/desktop/src/renderer/routes/admin/PartnerImportRejectionPanel.tsx:36`
  - 화면은 페이지 응답의 `row.rawName`을 그대로 렌더링한다. `����`는 빈 문자열이 아니므로 기존 `|| '읽을 수 없음'` fallback도 작동하지 않았다.
- 응답 표본 경로 `EcountPartnerImporter.java:207-209`는 이미 `heldSample.rawName`을 `읽을 수 없음`으로 치환하고 있었다. 따라서 응답 표본과 페이지 응답의 표현이 달랐다.

최종 수정은 페이지 SQL의 `CASE WHEN reject_reason LIKE 'CSV_ENCODING%' THEN '읽을 수 없음' ELSE raw_name END`이다. 서버 정본을 한 곳에서 만들고 화면에는 별도 판별 로직을 넣지 않았다.
