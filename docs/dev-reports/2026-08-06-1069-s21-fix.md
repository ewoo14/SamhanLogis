- 추가 전수 점검에서 직접 생성 엔진의 `BUNDLE + modelCode=null` 분기도 같은 방식으로 저장될 수 있음을 확인했다. `SlipServiceTest.create_bundleWithoutModelCode_isRejectedBeforeParentLinePersistence`가 `Expecting code to raise a throwable.`로 두 번째 RED가 되었고, 모델코드 누락 명시 오류를 추가했다.

## 원인과 수정

`SlipPublishService.resolveLines()`가 모델 조회 결과의 `productType`을 폐기하고 모든 결과를 `SlipLine.create*` 대상으로 넘겼다. 이 resolver는 견적 발행, 거래처 주문 단건 전환, 주문 병합 전환이 공유하므로 BUNDLE 부모 `productId`가 `slip_lines`에 저장될 수 있었다.

모델 조회 직후 `productType == BUNDLE`이면 `INVALID_INPUT`으로 중단하고 다음 안내를 반환하도록 수정했다.

> 세트 품목은 판매전표 라인으로 저장할 수 없습니다. 구성품으로 전개해 주세요.

검증은 전표 생성·저장 전에 끝나므로 resolver를 호출한 거래처 주문 전환의 재고 예약/converted 누적은 실행되지 않는다. 발행 단계에서 실패하는 재시도·병합도 기존 보상 계약을 유지한다.

## 불변식 판정

- 정상 SINGLE: resolver가 기존대로 `ResolvedLines.Entry`를 만들고 저장한다.
- BUNDLE: 저장·전표 채번 전에 명시 오류로 종료한다.
- 주문 전환: BUNDLE은 구성품 전개 안내와 함께 거부되며, 정상 SINGLE은 기존 예약→발행→converted 누적 흐름을 유지한다.
- S19 a11y 및 `#1063` 빈행 규약: 관련 파일을 수정하지 않았다.
- DB 기준선: DB 쓰기/조회 검증은 이번 라운드에서 수행하지 않았다.
