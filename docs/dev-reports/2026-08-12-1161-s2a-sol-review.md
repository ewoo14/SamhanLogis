## 결함 1 — [치명] 공통 publisher가 Rabbit 설정을 무시해 pilot 이벤트가 구성된 중앙 감사 파이프로 가지 않는다

실 사용자 재현 경로:

1. 운영자가 `spring.rabbitmq.host/port/username/password`로 감사 Rabbit을 구성한다.
2. 사용자가 거래처 DC 설정을 저장하거나 거래처 로그인을 시도한다.
3. 업무 응답은 성공하지만 publisher는 구성된 broker가 아니라 로컬 기본 host/5672/기본 자격증명으로 접속한다.
4. 결과적으로 해당 행이 개발자 로그 메뉴에 생기지 않는다.

원인 경계 원문:

```java
@Bean
@ConditionalOnMissingBean
RabbitTemplate auditRabbitTemplate() {
    return new RabbitTemplate(new CachingConnectionFactory());
}
```

`CachingConnectionFactory()`가 Spring Boot의 구성된 connection factory를 사용하지 않는다. 실제 프로세스 명령행에는 `--spring.rabbitmq.host=127.0.0.1 --spring.rabbitmq.port=16572`가 존재했지만 로그는 `DESKTOP-8SO2GTL:5672`를 기록했다. 이는 라이브 사용자 경로에서 재현된 기능 결함이다.

## 결함 2 — [치명] 두 pilot 이벤트가 직렬화 실패로 모두 소실되어 ActivityLogPage에 나타나지 않는다

실 사용자 재현 경로:

1. 사용자가 거래처 DC 설정을 저장한다. 또는 존재하지 않는 거래처/틀린 PIN으로 로그인한다.
2. 업무 응답은 각각 200으로 끝난다.
3. publisher worker가 `IllegalArgumentException`을 내고 이벤트를 버린다.
4. logging-service/ES 조회 건수는 0이고 화면에 행이 없다.

원인은 pilot이 쓰는 `RabbitTemplate`에 `Jackson2JsonMessageConverter`가 설정되지 않아 `AuditEventV2` record를 전송하지 못하는 경계다. 구현 보고서의 “desktop mock에 pilot event 2건 추가”는 실제 pilot→Rabbit→logging 경로를 증명하지 못하며, 실제 경로에서는 0건이다.

## 결함 3 — [높음] security-chain/controller 이전 partner-auth 로그인 실패가 감사되지 않는다

실 사용자 재현 경로:

1. `/api/v1/auth/partner-login`에 비밀번호 형식이 잘못된 요청을 보낸다.
2. 사용자는 기존 `400 INVALID_INPUT`을 받는다.
3. 해당 시점은 controller method 진입 전이므로 controller 본문의 `auditPublisher.publishAfterCommit(...)`에 도달하지 않는다.
4. Rabbit/ES 증가량은 0이다.

실행 원문은 위 `STATUS=400 ... password: 비밀번호는 숫자 4자리 PIN이어야 합니다`와 `COUNT_AFTER=0`이다. 기획 정본의 validation/auth 실패 B_FAILURE 1건 계약을 실제 사용자 경로에서 위반한다.

## 최종 답변

**실 사용자 경로로 재현 가능한 결함이 있다.** 총 3건이다.

1. [치명] publisher가 Spring Rabbit 설정을 무시해 구성된 중앙 broker가 아닌 기본 localhost:5672로 접속한다.
2. [치명] 두 pilot 이벤트가 실제 Rabbit 직렬화에서 `IllegalArgumentException`으로 모두 소실된다.
3. [높음] controller/security-chain 이전 partner-auth validation 실패가 B_FAILURE로 감사되지 않는다.

반면 Rabbit 중단 시 업무 status/DB commit, UUID 비공개, idempotency, 나머지 12개 비활성은 이번 격리 라이브 QA에서 결함을 재현하지 못했다.

## 라운드 종료 확인

격리 java/node 프로세스와 `s2a-sol-*` 컨테이너 6개를 정리했다. 사용 포트 `15161, 16572, 16672, 19280, 18082, 18089, 18091, 15489, 15491`는 전부 `OPEN=False`다.

삭제된 추적 파일 확인: 사용자 금지에 따라 git 명령은 실행하지 않았다. 이번 라운드에서 repo 파일 삭제 명령·삭제 patch는 한 번도 수행하지 않았고, 생성한 보고서 1개와 PNG 3개가 모두 존재한다. 따라서 이번 라운드 작업으로 삭제된 추적 파일은 없다.
