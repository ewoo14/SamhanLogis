## 작업 기록

- 보고서 파일을 제목만으로 생성했습니다.
- 현재 축소 전 구현을 확인했습니다. `WarehouseCodeMapper`의 기동 조회·코드 역조회·3상태·재검증 스케줄, `WarehouseInternalClient`의 HTTP/timeout, `SlipService`·`SlipDuplicateService`의 창고명 조회 및 관련 테스트 격리가 제거 대상입니다.
- 축소된 값 자체 검증 테스트를 먼저 작성했습니다. placeholder·비UUID·빈 값·공백은 실패하고, 미실재 형식 UUID와 client 미주입 정상 UUID는 통과해야 합니다.
- RED 실행 결과: `WarehouseCodeMapperStartupValidationTest` 6건 중 4건 실패. 기존 구현이 client 미주입 정상값도 실패시키고, 새 실패 메시지 계약을 아직 제공하지 않아 기대대로 실패했습니다.
- `WarehouseCodeMapper`를 외부 조회 없는 값 자체 검증으로 축소했습니다. 첫 GREEN 재실행은 빈 문자열 assertion 1건만 남아 테스트 표현 오류를 확인했습니다.
- mapper 대상 테스트가 GREEN(6 tests, 0 failures)으로 통과했습니다. 창고 검증 전용 context 테스트 2개와 3상태/timeout 검증 테스트를 제거하고, 기존 창고명 snapshot client 테스트만 최소 계약으로 남겼습니다.
- 제거 심볼 재검색 결과: `NO_REMOVED_VALIDATION_SYMBOLS`. `warehouse-validation`, 전용 builder/timeout, `FOUND/NOT_FOUND/UNAVAILABLE`, `findWarehouseById/findWarehouseByCode`, 재검증 스케줄이 main/test 소스에 남아 있지 않습니다.
- `application.yml`의 네 매핑 기본값도 제거해 환경변수가 없을 때 `${WAREHOUSE_UUID_...}` 원문이 mapper에 전달되도록 했습니다. 따라서 미치환 placeholder는 실제 기동 실패 대상입니다.
- targeted 재검증 원문: `:services:slip-service:test --tests ...WarehouseCodeMapperStartupValidationTest --tests ...WarehouseInternalClientTest --no-daemon --rerun-tasks` → `BUILD SUCCESSFUL`, 18 actionable tasks executed.
- DB/Docker를 건드리지 않는 `:services:slip-service:test --tests '*Test' --no-daemon --rerun-tasks` 원문: `BUILD SUCCESSFUL in 1m 17s`, XML 집계 `xml_files=117 tests=801 failures=0 errors=0 skipped=0`.
- 사용자 금지사항 때문에 `*IT`를 포함한 slip-service 전체 통합 테스트는 실행하지 않았습니다. 따라서 이 작업에서 보고하는 실패 수는 실행한 단위 테스트 기준 정확히 `0`이며, 전체 `*IT` suite 수치를 성공으로 주장하지 않습니다.
- CI/운영 환경의 환경변수 미주입 시에도 Spring이 원문 placeholder를 조기 해석해 UUID를 노출하지 않도록 YAML 기본값을 escaped literal로 두고, mapper가 창고코드만 포함한 `IllegalStateException`을 생성하게 했습니다.
- 서비스 main 소스에서 `WarehouseInternalClient.findWarehouseName` 호출을 제거했습니다. 남은 client 클래스는 기존 테스트/호환 bean으로만 남고, 기동 경로 및 전표 생성·복사 경로에서는 호출되지 않습니다.

## 제거한 항목

- `WarehouseCodeMapper`: 창고 UUID 실재성 조회, 창고코드 역조회, `FOUND/NOT_FOUND/UNAVAILABLE` 상태, 보류 집합, 주기적 재검증 스케줄, `warehouse-validation` 설정 의존.
- `WarehouseInternalClient`: `findWarehouseById`, `findWarehouseByCode`, `WarehouseLookup`, `LookupStatus` 및 해당 wire 계약 테스트.
- `RestClientConfig`: 창고 전용 builder와 connect/read timeout 설정.
- `SlipService`, `SlipDuplicateService`: 기동·전표 생성·복사 시 창고명 외부 조회 및 snapshot 배선.
- 테스트: `WarehouseValidationApplicationContextIT`, `WarehouseValidationUnavailableApplicationContextIT`, 실재성/대응 검증·3상태·전용 timeout 테스트.
