# PR #1137 / 이슈 #1136 — S14 git baseline fix

## 결론

Flyway `CHECKSUM_MISMATCH`의 자유 텍스트 분류를 더 확장하지 않고, repair 직전에 대상 migration 파일을 현재 `HEAD`의 blob과 비교하도록 바꿨다.

- 동일: `git rev-parse HEAD:<path>`와 `git hash-object -- <working-tree-file>`가 같을 때만 repair 대상이 된다.
- 불일치: repair를 거부하고 저장소 상대경로, HEAD blob, working-tree blob을 출력한다.
- 파일 없음 / untracked: 대응 파일 또는 HEAD blob이 없다고 출력하고 거부한다.
- `-WhatIf`: git baseline 검증은 수행하지만 Docker `repair`만 건너뛴다. 정상 preview는 종료코드 0이다.
- 서비스 target은 배열 위치가 아니라 명시적 객체로 보관해 `-Service` 필터가 조용히 무시되지 않게 했다.

실제 Flyway 10.10.0 컨테이너가 PostgreSQL 16.13 fixture DB에서 낸 validate 출력을 [fixture](../../scripts/fixtures/flyway-validate-checksum-mismatch.txt)에 보존했다. 실제 서비스 `flyway_schema_history`에는 접근하지 않았고, fixture DB는 검증 후 제거했다.

## RED-A 원문

S14 테스트에 git baseline 검증을 `ShouldProcess` 안쪽에 먼저 넣었을 때의 원문이다. 정상 커밋 migration의 `-WhatIf`가 repair preview를 건너뛰며 실패했다.

```text
committed migration repair preview failed: Flyway repair refused because the migration file is not identical to the current HEAD commit.
```

원인: `-WhatIf`가 baseline 검증까지 실행하지 않았다. baseline 검증을 `ShouldProcess` 밖으로 이동한 뒤 정상 커밋 파일 preview가 다음처럼 통과한다.

```text
Environment file: <fixture>/infrastructure/.env
auth-service: checksum mismatch versions = 10
What if: Performing the operation "Flyway repair (checksum metadata only)" on target "auth-service".
```

## 새로 가능해진 상태·환경 조합과 판정

| 상태 | 판정 |
|---|---|
| 대상 파일이 작업 트리에서 삭제됨 | 해당 버전의 로컬 파일 없음으로 거부 |
| 대상 파일이 untracked 신규 파일 | `HEAD:<path>` blob 없음으로 거부 |
| 작업 트리 dirty지만 대상 migration은 미변경 | 대상 파일의 blob이 HEAD와 같으면 허용. unrelated dirty는 근거가 아니다 |
| detached HEAD | 현재 `HEAD` commit을 기준으로 비교. 파일이 HEAD와 같으면 허용 |
| rebase 중 | branch 이름을 보지 않고 현재 `HEAD` commit을 기준으로 비교. 같으면 허용 |
| 다른 branch | 그 branch의 현재 `HEAD`와 파일이 같으면 허용; 다른 branch의 파일을 기준으로 삼지 않음 |
| DB history에는 있으나 저장소 대응 파일이 없음 | 해당 버전 파일 없음으로 거부. 조용히 repair하지 않음 |
| 매핑 없는 서비스 / migration 디렉터리 없는 서비스 | 기존 S13처럼 진단 출력 후 거부 |

## fix 라운드 필수 3절

### ① 새 상태·환경 조합 열거 및 결과

위 표의 경계 케이스를 모두 명시했다. 정상 커밋 파일 + 낡은 DB checksum은 preview 허용, 미커밋 파괴는 blob 불일치로 거부한다. 삭제·untracked·저장소 대응 파일 부재는 fail-closed다.

### ② 제거·이동·개명한 식별자 grep 전수 확인

이번 변경에서 제거·이동·개명한 production 식별자는 없다. 다음 grep으로 새 식별자와 S13 회귀 축을 확인했다.

```text

targetDefinitions (명시적 객체)        scripts/repair-flyway-checksums.ps1:147-186

```
