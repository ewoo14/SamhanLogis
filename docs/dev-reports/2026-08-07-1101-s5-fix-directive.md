# #1101 S5 수정 지시서 — `.env.local`과 QA 실행 경로의 단절

## 1. 결함 판정

**도달 결함 1건(HIGH)** 이다. `infrastructure/.env.local`에 유효한 자격이 있어도 PR이 수정한 QA 실행 파일은 그 파일을 읽지 않는다. 다수 파일은 `DEV_PASSWORD`를 읽고 빈 문자열로 fallback하지만, 새 템플릿과 PC 설정 문서는 `QA_DEV_DEFAULT_PASSWORD`만 정의한다. 따라서 QA 에이전트가 문서대로 파일만 만들면 기존 라이브 QA 실행 경로는 로그인 전에 단절된다.

실 사용자 제품 인증 자체는 정상이다. S5가 `.env.local`을 직접 파싱해 같은 자격을 주입했을 때 `POST /api/v1/auth/login`과 GUI `POST /auth/login`이 모두 200이었고 대시보드에 진입했다. 원인은 서버·계정·비밀번호가 아니라 저장 파일에서 실행 프로세스로 값을 전달하는 어댑터 부재다.

## 2. 재현 절차와 관측 증거

1. `infrastructure/.env.local`이 존재하고 `QA_DEV_DEFAULT_PASSWORD`가 채워진 상태를 확인한다. 값은 출력하지 않는다.
2. 별도 환경변수 `DEV_PASSWORD`를 설정하지 않고 변경된 실행 파일 가운데 `clients/desktop/qa-formula-f1-categories.mjs`를 실행한다.
3. 파일은 `.env.local`을 읽지 않고 `(process.env.DEV_PASSWORD ?? '')`를 전송하며 `Error: login failed`로 종료한다.
4. 같은 body 계약으로 빈 비밀번호를 실 게이트웨이에 보내면 HTTP 400이다.
5. 반대로 S5 harness가 `.env.local`의 `QA_DEV_DEFAULT_PASSWORD`를 직접 읽어 주입하면 API 로그인 200, GUI 로그인 200, 권한 조회 200, 대시보드 진입이다.

영향 표면은 현재 diff 기준 `process.env.DEV_PASSWORD`를 읽는 변경 실행 파일 201개다(Playwright 181, 기타 desktop QA 18, `scripts/`·`perf/` 2). 이 밖에도 `tools/manual-capture/*`, `tools/operational-validation/*.ps1`, `scripts/run-load-test.ps1`은 프로세스 환경변수만 읽고 `.env.local` 로더나 export 절차를 제공하지 않는다.

## 3. 요구 수정

단일 자격 로더를 두고 다음 우선순위를 명시적으로 구현한다.

1. 이미 주입된 표준 환경변수(`QA_DEV_DEFAULT_PASSWORD`, 역할별 `QA_*_PASSWORD`)
2. repo root의 ignored `infrastructure/.env.local`
3. 값이 없으면 빈 문자열 전송 금지, 필요한 파일 경로와 키 이름을 포함한 fail-fast 오류

`DEV_PASSWORD` 같은 과거 alias가 꼭 필요하면 호환 입력으로만 받고 표준 키로 정규화한다. 201개 파일의 중복 표현을 공용 loader/helper 호출로 치환하고, PowerShell·Node·Playwright·k6 진입점이 같은 계약을 사용하게 한다. 비밀번호나 토큰 원문은 로그·JSON·보고서에 남기지 않는다.

`perf/k6/mixed-load.js`의 `(process.env.DEV_PASSWORD ?? '')`도 제거한다. k6에서는 `process`가 아니라 `__ENV`만 사용하며, 값이 없으면 setup 전에 명시적으로 중단해야 한다. 현 PC에는 k6가 없어 이 항목의 실제 k6 실행은 관측 불가였으므로 별도 회귀 위험으로 취급한다.

## 4. 회귀 테스트

- `.env.local`만 있고 프로세스 환경변수가 없는 조건에서 대표 Node QA, Playwright QA, PowerShell QA가 각각 로그인 200에 도달한다.
- `.env.local`이 없고 표준 환경변수만 있는 조건에서도 동일하게 동작한다.
- 둘 다 없으면 네트워크 요청을 보내지 않고 파일 경로와 누락 키를 명시한 오류로 종료한다.
- 빈 비밀번호 fallback(`?? ''`, `|| ''`)이 자격 입력 경로에 남지 않는다.
- `k6 inspect` 또는 최소 smoke가 `LOADTEST_PASSWORD` 유/무 두 조건에서 각각 정상 구성/명시 오류를 낸다.
- S1/S2 credential guard와 `git diff --check`가 통과하고 보고서·JSON·스크린샷 메타데이터에 평문 자격이 없다.

## 5. 완료 기준

다음이 모두 충족되어야 S5 재검증에서 결함 해소로 판정한다.

- 새 PC 문서의 복사·입력 절차만 수행한 뒤 별도 수동 export 없이 대표 라이브 QA가 실 로그인 200 및 GUI 화면 진입에 성공한다.
- 파일 부재 시 QA 실행기가 조용히 빈 값으로 실패하지 않고, 사용자가 바로 조치할 수 있는 안내를 낸다.
- 대표 표본뿐 아니라 이번 PR이 수정한 모든 실행 파일이 공용 계약 또는 명시적 표준 환경변수 계약으로 수렴한다.
- k6의 Node 전용 전역 참조가 제거되고 실제 k6 실행 증거가 남는다.
- 금지 평문 0건과 가드 PASS가 다시 재현된다.
