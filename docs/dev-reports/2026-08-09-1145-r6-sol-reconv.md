## 머지 가부 판정

**머지 불가 — BLOCKING 1건.**

V97의 실 DB 예상 권한 부여 범위와 멱등성은 의도에 맞는다. 그러나 desktop mock의 실 응답은 회계전표 두 PageCode에 대해 MANAGER `1111011`, SALES `1000011`을 반환한다. V97 적용 후 실 모델은 각각 `1111000`, `1000000`이다. 즉 mock이 `download`와 `print`를 의도 밖으로 추가 허용한다. 기존 계약 테스트는 `view/create/update/delete`만 검사하여 이 차이를 놓친다.

비트 순서는 본 보고서 전체에서 `V/C/U/D/R/DL/P`(조회/생성/수정/삭제/복원/다운로드/인쇄)이다. `-------`는 활성 행 없음이다.

## 사용자 요약 선확인

핵심 방향 요약은 사실과 일치한다.

- MANAGER `.list 1111` → `.accounting 1111`
- SALES `.list 1000` → `.accounting 1000`
- 전표별 대상 13계정, 대상 2그룹
- 수신 세금계산서의 새 순증 대상은 실 계정 3명 + 매니저 그룹 + MANAGER 역할
- role 축 안전장치 `src.role_code IN ('MASTER', 'ACCOUNTANT', 'MANAGER', 'SALES')` 존재

다만 “mock 매트릭스가 부여 후 실 모델과 일치한다”는 전제가 있다면 사실이 아니다. 아래 (e)의 BLOCKING 결함이 셋째 가능성이다.
