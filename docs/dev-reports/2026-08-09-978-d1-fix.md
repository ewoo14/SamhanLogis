# #978 D-1 fix — ProductSheetSyncService 롤백 캐시 제거

## 판정

권장 1안을 적용했다. `ProductSheetSyncService.lastKnownRowHash`를 제거하고, `unchanged` 판정을 현재 DB의 `Product` 상태와 시트가 관리하는 값의 직접 비교로 바꿨다. 따라서 커밋되지 않은 DB 쓰기를 인메모리 상태가 다음 실행에서 성공한 것으로 주장할 수 없다.

2안의 성능 실측은 하지 않았다. 캐시를 유지하기 위한 커밋 후 callback보다, 이미 `Product`를 행마다 조회하고 있던 경로에서 직접 비교하는 1안이 불변식과 기존 `#1139` 계열 규약에 맞고 구조가 단순하다. 이번 변경은 추가 DB 조회를 만들지 않는다.

## 변경 내용

- `ProductSheetSyncService`의 JVM 전역 `lastKnownRowHash`와 `ConcurrentHashMap` 의존 제거
- `rowHash get/put/remove` 및 `evictRowHash`, `clearHashCacheForTest` 제거
- `isProductRowUnchanged(...)` 추가
  - 품명, 출고가, 납품가
  - 판넬/리모컨 속성, 싱글 세트 평형
  - 사용범위, 변동DC, 고정DC, 분류
  - 수동 override가 켜진 필드는 기존 보존 규칙에 따라 비교 제외
- 캐시 무효화에 의존하던 `ProductService` 호출부와 관련 테스트 정리
- 롤백 RED 테스트가 남긴 fixture를 `@AfterEach`에서 soft-delete하여 테스트 간 DB 누출 방지

## (a) product-service 인메모리 상태 sweep

축은 “DB 쓰기 결과와 무관하게 갱신되어 다음 실행 판정에 쓰이는 상태”로 잡았다.

| 대상 | 상태 | 판정 |
|---|---|---|
| `ProductSheetSyncService.lastKnownRowHash` | `ConcurrentHashMap`, cross-run unchanged 판정 | **제거 완료** |
| `ProductSheetSyncService`의 `sheetModelCodes`, `seenByParent`, `lockedParents`, `markedBundles`, spec용 Set/Map | `syncTab`/`syncComponentTab` 호출 내부 지역 변수 | 다음 실행에 남지 않음, 범위 밖 |
| `ProductSheetSyncService.FormulaRowResolver`의 rows Map/List | 호출별 불변 입력 파생값 | 다음 실행에 남지 않음, 범위 밖 |
| `ProductLookupSheetSyncService.lastKnownRowHash` | 별도 lookup sync 계층의 JVM 캐시 | 현재 브랜치의 별도 계층, D-1 대상 클래스 밖. 변경하지 않음 |
| `ProductAdminController.lastSnapshot` | `AtomicReference` 최신 실행 결과 | skip/update 판정에 사용되지 않는 운영 상태, 동시 접근 안전 |
| `ProductSheetSyncScheduler.schedulingEnabled`, `cronEnabled` | 설정 주입 플래그 | DB 결과로 갱신되지 않는 설정값, 범위 밖 |
| `Product`의 manual 플래그들 | JPA 엔티티 DB 필드 | 인메모리 cross-run 캐시가 아님. 직접 DB 비교에서 정책대로 반영 |
| `QuantitySyncRuleService`, `EcountProductImporter`의 Map/Set | 메서드 지역 계산 상태 | 다음 실행에 남지 않음, 범위 밖 |

현재 브랜치 전체 grep에서 `ProductLookupSheetSyncService`의 `lastKnownRowHash`는 남아 있다. 이는 사용자 요청에서 명시한 “#1139가 고친 별도 계층”과 분리해 보고하는 항목이며, 이번 ProductSheet 계층 fix에 섞지 않았다.

## 동시 실행 회귀 근거

- 제거한 상태는 `ProductSheetSyncService`의 cross-run `ConcurrentHashMap`뿐이다.
- sync 중 사용하는 Set/Map은 각 호출의 지역 변수라 다른 sync 실행이 공유하지 않는다.
- 기존 `quantitySyncRuleService.lockGraphMutation()`과 sheet sync generation 검사는 유지했다.
- `@Transactional syncTab`과 `syncAll`의 per-tab transaction 경계는 변경하지 않았다.
- 동시 실행을 포함한 `QuantitySyncRuleReconvergenceR6IT`, `QuantitySyncRuleReconvergenceR7IT`, `QuantitySyncRuleScopeReductionRegressionIT`를 전체 product-service 실행에서 통과했다.

따라서 이번 변경은 동시 실행 직렬화·stale generation 보호를 건드리지 않고, 롤백에 따라가지 않던 전역 캐시만 제거한다.
