## ② 불변식 — 반드시 참이어야 하는 것

1. 한 번의 동기화 결과 화면에서 외부 전달 여부에 관한 문장들은 서로 모순되지 않아야 한다.
2. `DELIVERED`이면 실제 전달된 신규·변경·제외 건수를 그대로 보여야 하며, 같은 화면 어디에도 “실행해도 등록·변경되지 않는다”는 단정이 없어야 한다.
3. `PARTIALLY_DELIVERED`이면 실제 전달된 건수와 실패 건수를 함께 보여야 하며, 전체가 미전달이라는 단정이 없어야 한다.
4. `NOT_DELIVERED`이면 신규·변경 양수 응답이 들어와도 성공 건수로 보이지 않아야 하고, 실제 전달 0건임을 사용자가 즉시 알 수 있어야 한다.
5. CSV 다운로드가 알리고 전달 완료의 증거가 아니라는 사실은 모든 상태에서 거짓이 되지 않아야 한다.
6. PR·커밋·추적 보고서가 최종 검증으로 지목하는 명령, 캐시 사용 여부, 실행 수치와 원문은 서로 일치해야 한다. 캐시 실행은 강제 재실행 증거로 제시되어서는 안 된다.

## ③ 양방향 RED

### RED-A — 정상 전달 기능과 미전달 반대급부

- 유효한 5인자 `UploadResult(1, 1, 1, 200, ...)`가 `DELIVERED`로 해석되고, sync 응답과 실제 페이지에서 신규 1·변경 1·제외 1이 보이는 경로를 먼저 RED로 고정한다.
- 같은 DOM에서 “현재 외부 전달 없는 mock 모드” 또는 “실행해도 등록·변경되지 않는다”는 문장이 하나라도 보이면 RED다.
- 반대급부: 같은 입력 건수를 `NOT_DELIVERED`로 바꾸면 신규·변경은 0으로 보이고 실제 전달 0건 안내가 보여야 한다. 이 경로에서 실제 전달 완료 문장이 보이면 RED다.

### RED-B — 부분 전달과 전체 실패 반대급부

- 여러 chunk 중 일부만 전달된 결과는 `PARTIALLY_DELIVERED`이고, 전달된 chunk의 건수와 실패 chunk 수·목록이 한 화면에서 함께 보여야 한다.
- 같은 DOM에서 전체 미전달을 단정하거나 실제 전달 건수를 0으로 덮으면 RED다.
- 반대급부: 모든 chunk가 미전달 또는 실패이면 `NOT_DELIVERED`, 신규·변경 0이어야 한다. 일부 또는 전체 전달 완료 문장이 보이면 RED다.

### RED-C — 증거 무결성

- 보고서가 최종 권위로 제시하는 강제 재실행 명령을 그대로 실행했을 때, 보고서의 명령 문자열·`BUILD SUCCESSFUL`·actionable task 수치가 새 원문과 일치하지 않으면 RED다.
- 반대급부: `--rerun-tasks` 없는 캐시 실행 결과는 첫 실행 또는 참고값으로만 구분되어야 하며 최종 강제 재실행 원문으로 읽히면 RED다.
