### 셋째 가능성 — 격리 gateway 503

최초에는 slip 검증용 `28082`로 거래처 화면까지 밟아 503이 났다. 응답과 gateway 원문은 아래다.

```text
GET http://127.0.0.1:28082/admin/partners/list-realtime -> 503 application/json
No servers available for service: partner-service
```

`28082` 격리망에는 auth/slip/inventory만 등록되어 있어 partner-service가 없다. factory는 요청을 발화했고, 실제 partner-service가 등록된 main gateway `8080`에서 같은 화면·같은 endpoint가 200으로 열렸다. 따라서 이 503은 사용자 경로 결함이 아니라 검증 topology 차이다.
