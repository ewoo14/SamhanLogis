## 결함 1 — `totalPreservedManual`이 서로 다른 두 단위를 합쳐 Javadoc·화면과 다른 값을 낸다

실 사용자 경로는 `MASTER → 설정 → 시트 동기화 → 지금 동기화 → “수동 보존” chip 확인`이다.

운영 원문은 `SyncSummary.totalPreservedManual`을 “`usageScopeManual=true`로 soft-delete 보호된 품목 합계”라고 선언한다(`ProductSheetSyncService.java:2142-2143, 2156-2157`). 그러나 집계는 Product 탭의 해당 품목 수뿐 아니라 구성품 탭의 `bundleComponentsManual` 부모가 막은 **구성품 시트 행 occurrence**도 같은 필드에 더한다(`:253`, `:274`, component 증가 `:375-379`). R5 전수 표도 이를 “해당 Product 탭 보호 행 합”이라고 적어 실제 구현과 다르다.

2026-08-09 12:00:52 KST 공유 DB/시트 readonly 실측:

```text
usage_scope_manual_products=0
bundle_components_manual_products=1
manual_component_preserved_occurrences=2
```

따라서 현재 데이터로 sync하면 문서가 선언한 품목 합계는 `0`인데 공개 summary와 화면 “수동 보존”은 구성품 occurrence를 섞어 최소 `2`가 된다. 이름은 무엇을 세는지 선언하지 않고, 실제 값도 원문 계약과 일치하지 않는다.

## 결함 2 — `totalSkipped`는 “total”인데 현재 도달 가능한 구성품 skip 37건을 제외한다

실 사용자 경로는 같은 화면의 “총 skip” chip이다.

Product 탭은 `summary.totalSkipped += tabResult.skipped`로 합치지만(`:252`), 구성품 탭은 `cr.skipped`를 `byComponentTab`에만 두고 total에 더하지 않는다(`:267-275`). 구성품 경로는 부모 또는 자식 Product가 없으면 `result.skipped++`한다(`:358-363`). 필드와 화면 이름은 `totalSkipped`/“총 skip”이라 제외 단위를 말하지 않는다.

2026-08-09 12:13:20.337 KST Google Sheets readonly + 공유 DB readonly 재계수:

```text
component_valid_occurrences=1639
component_skipped_missing_occurrences=37
```

즉 현재 실 source만으로도 37건이 구성품 tab 결과에는 찍히지만 “총 skip”에는 들어가지 않는다. R5 표 말미가 이 제외를 서술했어도, 카운터 이름과 사용자 표시는 그 사실을 선언하지 않으므로 R4와 같은 이름/단위 결함이다.

## 결함 3 — `linked`/`totalComponentsLinked`가 고유 링크가 아니라 row occurrence를 세지만 이름이 말하지 않는다

실 사용자 경로는 같은 sync 응답 summary 또는 운영 로그의 component linked 확인이다.

구성품 처리 코드는 기존 link 재저장도 매 유효 시트 행마다 `result.linked++`한다(`:441-448`). 전체는 이를 단순 합산해 `totalComponentsLinked`로 노출한다(`:272`). R5 표에는 occurrence라고 적었지만 필드명 `linked`/`totalComponentsLinked` 자체에는 그 단위가 없다.

2026-08-09 12:01:38 KST readonly 재계수:

```text
component_link_eligible_occurrences=1600
component_link_distinct_parent_child=1581
```

현재 실 source에서 동일 `(부모, 자식)` link가 19회 중복 등장한다. 따라서 사용자가 “연결된 구성품 수”로 읽으면 실제 고유 link 1,581보다 19 큰 1,600을 받는다. `nameDrift` 때와 같은 occurrence/고유 객체 단위 미선언이다.

## 검증 정직성

- desktop 정본 typecheck 명령은 루트 tsconfig가 아니라 `clients/desktop`의 `npm run typecheck`를 사용했다. `tsconfig.node.json`과 `tsconfig.web.json` 컴파일은 통과했으나 마지막 real-QA 추적 집합 테스트가 이번 신규 미추적 스펙을 정확히 검출해 전체 종료코드는 1이었다. commit/git add 금지 범위에서 만든 신규 파일이므로 PR 코드 type error로 세지 않았다. 스펙 자체는 Playwright가 실제 로드·실행해 1/1 통과했다.
- 최초 web build는 BrowserRouter라 해시가 홈에 낙착하는 것을 고유 요소 단정이 잡았다. Electron renderer(HashRouter)로 다시 빌드한 뒤 route 도달을 확인했다.
- 두 번째 실행의 중복 heading strict locator 실패는 H3(level 3)로 한정했고, 세 번째 fresh 실행에서 통과했다.
- 모든 preview 프로세스를 `finally`에서 회수했다.
