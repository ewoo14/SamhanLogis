## 1. 판정 근거

1. 판별식은 거래처명·기간·메모를 전혀 사용하지 않고 QA797 전용 상품 UUID 3개(전표/견적) 또는 4개(최근단가)만 사용한다.
2. 공유 DB 읽기 재확인 결과 실행 직전 활성 대상은 `slip_lines 10 · slips 0 · estimate_lines 53 · estimates 25 · price_memory 8`로 가드와 일치했다.
3. 격리 복제본에서 실행 → 되돌림 후 대상 5개 테이블 전체 행의 JSON 해시가 모두 사전값과 일치했다.
4. 정상/가드 실패/연결 실패 종료코드는 각각 `0/3/2`였다.
5. 실행 중 클라이언트를 강제 종료하자 advisory lock이 `1 → 0`이 되었고 신규 표지는 0건이었다.
6. `#1176` 표지 행은 실행 전후 동일했고, 스크립트는 `slip_db` 한 연결만 사용하므로 회계 DB에 닿지 않는다.
7. 이미 실행된 상태에서 재실행하면 사전 가드가 `ROLLBACK`하고 종료코드 `3`을 반환했다.
8. 되돌림 사전 가드를 고의로 깨뜨린 상태에서도 어떤 테이블도 부분 복구되지 않았다.

## 6. 중간 강제 종료와 잠금 해제

격리 DB에만 statement-level `pg_sleep(30)` 트리거를 임시 설치해 실행을 첫 `UPDATE slip_lines`에서 정지시켰다. 원본 SQL 파일은 바꾸지 않았다. `pg_stat_activity`와 잠금 원문:

```text

-----+--------+-----------------+------------+----------------------------------------------------------------------

     |        |                 |            |  deleted_by
(1 row)

 advisory_locks_before_kill
----------------------------
                          1
(1 row)
```

강제 종료 후 원문:

```text
 advisory_locks_after_kill
---------------------------
                         0
(1 row)

 slip_lines | estimate_lines | estimates | price_memory
------------+----------------+-----------+--------------
          0 |              0 |         0 |            0
(1 row)

post_kill_query_exit=0
```

클라이언트 종료로 트랜잭션이 자동 rollback되었고 transaction-level advisory lock도 남지 않았다. 임시 트리거/함수 삭제는 각각 성공했다(`pause_trigger_drop_exit=0`).
