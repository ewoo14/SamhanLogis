## ② 354 → 349와 R8의 340+14

공유 `samhan-postgres/auth_db`에는 SELECT만 실행하고, 11역할 × 122 page의 비교·집계를
SQL에 맡겼다. 종료코드는 파이프 뒤에서 읽지 않았다.

```text
PARSED_CELLS=1342
scope_cells|present_rows|bit_mismatch|missing_rows|missing_nonzero|total_effective_mismatch
1342|1095|340|247|14|354
SQL_EXIT=0
```

따라서 R8의 존재 행 비트 불일치 340셀 + DB 부재·스냅샷 비0 14셀 = R9 동결 354셀은
같은 집합이다. 파일 직접 계수는 R11 부모 354, 현재 349다. R11이 V97 효과 5셀을
projection에 반영했고 그 5셀은 이미 mock과 같았으므로 `354 - 5 = 349`다.

현재 목록은 349항목, 중복 role/page key 0이다. R8 exact 테스트가 실행 시 실제 차이 집합을
재산출해 역할별 목록과 전체 목록을 `toEqual`로 exact 비교하므로 목록과 실제가 다르면 RED다.

## ⑤ refresh 스크립트 독립성·fail-closed

고유 DB명·사용자로 스크립트를 실제 실행했다.

```text
Database: .../r11_projection_db
Successfully validated 97 migrations
Successfully applied 97 migrations ... now at version v97
REFRESH_EXIT=0
SHARED_BEFORE=<동일 container id> running 0
SHARED_AFTER =<동일 container id> running 0
TEMP_LEFT=0
```

스크립트에는 `samhan-postgres` 참조가 없고, GUID 이름의 임시 network/PostgreSQL만
`docker exec`한다. projection SELECT도 같은 임시 컨테이너 hostname을 사용한다. 고유
DB/user로 성공했고 공유 컨테이너 ID·상태·restart count가 전후 동일하므로 공유 DB를
파생 기준으로 읽지 않는다.

fail-closed도 직접 밟았다.

```text
존재하지 않는 Postgres image: exit 1, projection git diff 0, TEMP_LEFT=0
문법 오류 임시 V98 migration: exit 1, projection git diff 0, TEMP_LEFT=0
```

DB 준비·migration 실패에서 기존 projection으로 조용히 통과하거나 출력 파일을 갱신하지 않는다.

## 새로 보인 표면 — 수정 요구 없이 목록만

1. Browser 런타임이 두 차례 연속 `[]`여서 직접 라이브 GUI 증거를 만들 수 없다.
2. 존재하지 않는 Postgres image 시나리오는 exit 1·무쓰기이지만 `finally`의
   `docker rm` 오류가 본래 image 부재 진단보다 앞에 보인다.
3. refresh 성공 실행은 내용상 git diff 0이지만 Windows 작업트리 줄바꿈 때문에 raw byte
   SHA가 달라질 수 있다. 계약 검사는 내용/집합 기준으로 GREEN이었다.
4. `accounting-slip-permission-snapshot.ts` 머리말에는 아직 “V97 remains unapplied”가 남아
   있다. R8 비교 기준 파일 설명이고 R11 projection 정합에는 영향 없지만 후속 독자에게
   혼동을 줄 수 있다.
5. 원격 GitGuardian check fail은 본 라운드에서 원인 원문을 제공하지 않아 false positive
   여부를 확정하지 않았다.
