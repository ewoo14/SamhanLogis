## 4. S1 핵심 불변식 — 판정 전후 아무것도 되돌리지 않음

### 수행 순서

1. 격리 DB에서 전표 상태·전표행·배차 연결·재고·source journal 관련 테이블을 판정 전 dump.
2. 실제 UI에서 대상/구형 완료 전표 상세를 열어 판정 API 호출.
3. 같은 로그인 세션에서 bulk 판정 1회와 opaque single 판정 13회를 호출.
4. 판정 후 같은 테이블을 다시 dump.
5. `pg_dump`가 매 실행마다 만드는 무작위 `\\restrict`/`\\unrestrict` 토큰 두 줄을 제거한 뒤 byte 비교.

13개 완료 전표의 `status`, `completed_at`, `modified_at`도 모두 동일했다. 대상 배차 연결도 그대로였다.

```text

```

판정 후 UI에서도 구형 전표 `2026/08/03-2`가 계속 `검수완료`로 표시됐다. **S1의 “아무것도 되돌리지 않는다” 불변식은 통과했다.**

## 9. 도달 가능한 결함과 범위 밖

### 도달 가능한 결함: 있음

1. **구매 화면의 창고 목록 응답이 UUID를 노출한다.** 로그인 후 구매관리 목록을 열 때 실제 요청되는 `/inventory/warehouses`가 HTTP 200이면서 `$.data[4..7].id`에 UUID 4개를 반환한다.
2. **전표 상세 협업 presence 응답이 UUID를 노출한다.** 대상 및 구형 전표 상세 진입 시 실제 요청되는 `collab/presence`와 `presence/join`이 각각 `sessionId`를 UUID로 반환한다.
3. **완료 전표 목록 UUID 0이라는 구현자 실측이 재현되지 않는다.** `/slips?status=COMPLETED&page=0&size=50`의 `$.data.content[3].salesPersonName`에서 UUID 1개가 검출됐다. 현재 구매관리 화면의 `/slips/query` 응답은 0이지만, 명시된 증거 무결성 예외에 따라 보고한다.

세 항목 모두 화면 표시 텍스트에는 UUID가 보이지 않았지만, 사용자 브라우저가 수신하는 API 응답이라는 불변식 위반이다.

### 통과한 핵심 사항

- S1 판정 전후 전표·재고·배차 데이터: 변경 0.
- 13건 판정: 13/13 이전 결과와 일치.
- 기존 목록·검색·대상 상세·구형 상세: 모두 정상 진입.
- 상세 URL, 화면 텍스트, 전표 상세 응답: UUID 0.
- `comments`, `edits`, `stream`, `revision/revisions`, `realtime`: 요청된 400·403·404·500 없음.
- 머지 충돌 양쪽 기능: 소스·컴파일·실행 근거로 모두 보존 확인.

### 범위 밖으로 남긴 것 — 결함 0에 포함하지 않음

- 실제 되돌림 실행, 권한, 범위, 연결 처리, 이력은 S1 대상이 아니며 호출하지 않았다.
- 최소 격리 스택에 포함하지 않은 app/notification/logging/product 서비스의 503은 제품 판정에서 제외했다.
- 로그인 전 `/auth/me` 401은 정상 초기 세션 확인이다.
- SSE의 화면 이동 시 abort는 연결 종료 동작이며 200 연결 자체는 성공했다.
- slip-service 전량 테스트 59건 실패는 실행 사실만 기록했으며, 본 보고서의 사용자 도달 결함 수에 산입하지 않았다.
