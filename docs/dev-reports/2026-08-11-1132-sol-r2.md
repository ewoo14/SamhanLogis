## 2. 첫 각도 — fallback 제거가 정상 전개를 막았는가

### 2.1 실 DB 전수 집계

```text
status          sets  default=0  partial  all-default  active rows  default  nondefault  deleted-mixed
ACTIVE           276         72      204            0         1302      665         637              2
DISCONTINUED       50          0       50            0          193      125          68              0
NOT_FOR_SALE       14          0       14            0           77       56          21              0
OUT_OF_STOCK        3          0        3            0           12        9           3              0
```

부분 기본 ACTIVE 204세트는 모두 `SINGLE_SET`이다.

```text
기본으로 계속 전개되는 행 665
비기본이라 전개되지 않는 행 500
  MATERIAL 142세트·187행
  PANEL     58세트·192행
  REMOTE    62세트·121행
```

직전 fallback은 기본이 **0건일 때만** 작동했다. 기본이 1건이라도 있는 부분 기본 204세트는 직전 fix 전에도 이미 665행만 전개했다. 따라서 이 204세트·500행은 이번 fallback 제거가 새로 만든 손실이 아니다.

fallback 제거가 직접 건드린 집합은 다음과 같다.

```text
ACTIVE COMMERCIAL_MULTI manual=false  71세트·135행 — 직전 fallback 대상
ACTIVE COMMERCIAL_MULTI manual=true     1세트·  2행 — 직전에도 fallback 비대상
합계                                      72세트·137행
```

V37 후에는 137행 전부 `true`가 되어 최종 전개 137행이다. 이 축만 보면 fallback 제거 자체의 잔여 손실은 없다.

### 2.2 비활성·삭제 혼합

- 비활성 BUNDLE 67세트는 전부 부분 기본이며 기본 0건은 0세트다. fallback 제거 신규 손실은 없다.
- 삭제 구성품 혼합은 2세트다.
  - `AM220AXVHHR1SY`: 활성 2·기본 0·삭제 2. V37은 활성 2행만 지정하고 삭제 2행은 계속 제외한다.
  - `AP110BAPPHH2S`: 활성 3·기본 2·삭제 1. 직전과 현재 모두 활성 기본 2행만 전개한다.
- `BundleComponentRepository.findByBundleProductId`가 처음부터 `isDeleted=false`만 읽으므로 삭제행 관련 신규 회귀는 없다.

### 2.4 증거 무결성 — raw psql 실패 원문

트랜잭션 래퍼 없이 SQL 파일을 그대로 넣은 첫 실행은 다음과 같이 실패했다.

```text
CREATE TABLE
CREATE INDEX
SELECT 137
ERROR:  relation "v37_target_bundle_components" does not exist
LINE 19:   FROM v37_target_bundle_components t
```

원인은 `CREATE TEMP TABLE ... ON COMMIT DROP`과 psql auto-commit의 결합이다. Flyway PostgreSQL migration은 기본적으로 파일 전체를 트랜잭션 처리하므로 배포 경로 실패라고 판정하지 않는다. 단, 수동 검증·rollback runbook에서 SQL 파일 단독 실행을 성공 증거로 쓰면 안 된다.

### 3.2 근본 원인

`ProductSheetSyncService`의 보호 기준은 부모가 아니라 기존 구성행 UUID다.

```java
Set<UUID> v37Defaults = protectedDefaultComponents.computeIfAbsent(parent.getId(),
        bundleComponentRepository::findActiveDefaultBackfillComponentIds);
boolean isDefault = (variant + " " + kindRaw).contains("기본")
        || (match != null && v37Defaults.contains(match.getId()));
```

- 기존 감사 행 `match`만 true를 보존한다.
- 신규 구성행은 `match == null`이라 보호가 절대 적용되지 않는다.
- 시트에서 사라진 기존 감사 행은 462~469의 일반 soft-delete 대상이다.
- 그 뒤 `BundleExpander`는 `is_default=true`만 읽는다.

### 3.3 격리 DB 재현 데이터와 원문

표본은 V37 대상 중 활성 구성품이 1행뿐인 `AM240AXVHHR1SY`다. V37 직후 활성 감사 기본행은 `AM120AXVHHR1` 1행이다.

## 7. LUNA fix 지시서

### Task 1: V37 시트 정책과 관리자 기본 토글 수렴

#### 7.1 불변식

1. V37 감사 이력이 활성이고 `bundle_components_manual=false`인 부모는 시트 관리 세트다. 구성품 tab sync 후 **이번 시트에 남은 모든 활성 상업 구성행**이 기본/필수로 전개돼야 한다. 기존 감사 UUID뿐 아니라 신규·교체 UUID도 포함한다.
2. 관리자가 화면에서 `isDefault`를 바꿔 저장하면 PUT body가 정본이고 부모는 `bundle_components_manual=true`가 된다. 이후 시트 sync가 그 선택을 덮지 않는다.
3. V37 비대상 부분 기본 `SINGLE_SET` 204세트·기본 665행·비기본 500행은 승격하지 않는다. 비기본 패널·리모컨·자재는 계속 옵션이다.
4. 비활성 67세트, 삭제 혼합 2세트, V37 rollback 완료 부모에는 새 정책을 적용하지 않는다.

#### 7.2 권장 최소 수정

1. repository에 “이 부모가 rollback되지 않은 `PR1132-V37` 감사 대상인가”를 부모 ID로 판정하는 query를 추가한다. 활성 component UUID 집합만으로 정책을 판단하지 않는다.
2. `ProductSheetSyncService.syncComponentTab`에서 `manual=false`이고 위 부모 정책이 true이면 기존/신규 시트 구성행 모두 `isDefault=true`로 저장한다. 시트에서 사라진 행의 soft-delete는 유지한다.
3. `ProductFormPage.BundleComponentsEditor` 각 행에 `기본 구성품` checkbox를 추가하고 `updateDraft(index, { isDefault: checked })`로 기존 PUT 계약에 연결한다. GET false/true를 그대로 rehydrate한다.
4. raw API와 서비스 계약은 이미 false를 허용하므로, 별도 강제 true validator를 넣지 않는다.

#### 7.3 RED-A

**RED-A — V37 시트 교체:**

`AM240AXVHHR1SY`와 같은 fixture를 V37 감사 대상·`manual=false`·활성 기본 `AM120AXVHHR1` 1행으로 만든다. 구성품 시트에서 기존 행을 제거하고 `AM100AXVHHR1`, variant/kindRaw에 `기본` 없음으로 교체한 뒤 `syncComponentTab`을 실행한다. 기대값은 기존 행 soft-delete, 새 행 `isDefault=true`, `BundleExpander.expand` 결과 `AM100AXVHHR1` 1행이다. 현재 값 새 행 false·전개 0행이면 RED다.

**RED-A — 관리자 화면 해제:**

V37 기본 true 1행을 GET한 관리자 편집 화면에서 `기본 구성품` checkbox를 해제하고 저장한다. PUT body `isDefault=false`, 응답 false, 재조회 false, 부모 `bundle_components_manual=true`, 후속 시트 sync 후에도 false를 단언한다.

#### 7.4 RED-B — 구체적 반대급부

**RED-B — 좁히면 빠지는 쪽 / 다른 이름 소비자:**

실데이터 구조를 반영한 `SINGLE_SET` 표본 `AC060BS4PBH7SY`를 사용한다. 기본 패널 1행은 true, 옵션 패널 `PC4NBFK1NW`, `PC4NUCK4NW`, `PC4NUXK1NW` 3행은 false로 둔다. 시트 sync fix 후에도 세 옵션 패널이 false이고 기본 전개에는 포함되지 않아야 한다. 부모 단위 V37 정책을 `SINGLE_SET` 전체로 넓혀 옵션 패널 3개를 승격하면 실패다. order-app의 `pickPanelRow` 소비도 각각 블랙/공청/승강 선택 시 해당 1행을 계속 선택해야 한다.

**RED-B — rollback 층:**

`PR1132-V37` audit의 `rolled_back_at`이 채워진 부모는 구성품 시트 신규행을 기존 `(variant + kindRaw).contains("기본")` 규칙으로 저장해야 한다. 부모 감사 이력 존재만 보고 영구 true로 만들면 실패다.

**RED-B — 화면 저장 무변경:**

관리자가 checkbox를 건드리지 않고 수량만 수정하면 기존 true/false가 그대로 PUT·재조회돼야 한다. 새 checkbox 추가가 모든 행을 true 또는 false로 초기화하면 실패다.

#### 7.5 fix가 새로 만드는 조합 — 전부 밟을 것

1. V37 대상 + manual=false + 기존 감사행 유지 + 시트 raw false → true 유지.
2. V37 대상 + manual=false + 새 구성행 추가 + 기존 감사행 유지 → 기존/신규 모두 true, 둘 다 전개.
3. V37 대상 + manual=false + 기존 감사행 제거 + 새 구성행 교체 → 새 행 true, 전개 0행 금지.
4. V37 대상 + manual=true + 화면에서 일부 false → 시트 sync 전체 skip, 사용자 선택 유지.
5. V37 대상 + manual=true + 화면에서 전부 false → raw API 계약대로 0행 허용, fallback 부활 금지.
6. V37 audit rollback 완료 + manual=false → 기존 시트 `기본` 문자열 규칙으로 복귀.
7. V37 비대상 `SINGLE_SET` 부분 기본 → 비기본 패널/리모컨/자재 승격 금지.
8. 비활성 BUNDLE → 정책 확대 금지.
9. 삭제 감사행 + 신규 활성행 → 부모 정책은 유지하되 삭제행 재활성화 금지.
10. 화면 GET true/false 혼합 → checkbox 정확 rehydrate, 수량만 저장해도 값 불변.

#### 7.6 중단 조건

**제 전제가 틀렸다면 고치지 말고 중단·보고하십시오.**

특히 다음 중 하나가 사실이면 즉시 중단한다.

- 개발책임자의 “72개의 기본 구성품 지정”이 현재 137행만 1회 지정하고, 이후 시트 신규·교체 구성행은 의도적으로 비기본이어야 한다.
- 관리자 화면에서 V37 값을 끄는 것이 금지 정책이고 raw PUT의 false 허용이 제거 대상이다.
- 상업멀티 시트 구성행 중 미래 선택품이 존재해 “V37 부모의 시트 구성행 전부 true”가 성립하지 않는다.

이 경우 정책 결정을 다시 받아야 하며, 감사 UUID 보호를 임의로 부모 정책으로 넓히면 안 된다.

## 9. LUNA fix와 SOL 최종 재검증

### 9.1 적용 내용

- `BundleComponentRepository.isActiveDefaultBackfillBundle`: 구성행 UUID가 아니라 부모 ID에 활성 `PR1132-V37` 감사 이력이 있는지 판정한다. `rolled_back_at IS NULL`, `is_deleted=false`를 모두 제한한다.
- `ProductSheetSyncService`: `bundle_components_manual=true` 부모는 정책 조회·upsert·soft-delete 전에 계속 건너뛴다. 그 외 V37 부모의 현재 시트 기존·신규·교체 행은 모두 `isDefault=true`로 수렴한다.
- `ProductFormPage.BundleComponentsEditor`: GET의 true/false를 그대로 표시하는 controlled `기본 구성품` checkbox를 PUT `isDefault`에 연결했다.
- `BundleExpander`, raw API false 허용, V37 migration, 발주 우회 경로는 변경하지 않았다.

독립 리뷰 결과는 `APPROVED`이며 추가 사용자 도달 결함은 없었다.
