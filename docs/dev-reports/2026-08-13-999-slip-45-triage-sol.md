# #999 slip-service 45건 분류 — CODEX SOL

## 판정

45건은 전부 **(a) 이 브랜치 회귀**다. 같은 45건은 `origin/main` 기준 실행 결과 XML에서 45/45 통과했고, 브랜치의 12개 관련 클래스 집중 재실행에서는 45/45가 같은 유형으로 다시 실패했다. 따라서 대상 45건에 (b)는 0건, (c)는 0건이다.

다만 별개의 **테스트 실행 환경 경합**은 실제로 관찰됐다. 브랜치 전량 재실행 하나가 Testcontainers 컨테이너를 종료하려다 이미 사라진 컨테이너를 만나 404로 중단되어 `1837 tests completed, 3 failed, 643 skipped`를 냈다. 이 오염된 전량 결과를 45건 판정 근거로 쓰지 않고, 관련 12개 클래스 집중 실행과 `main` 대상별 XML 대조로 판정했다.

머지 가능 여부: **불가(BLOCK)**. 라이브 QA의 `FINAL_GATE=PASS`와 별개로, branch의 `slip-service` 자동 검증 45건이 재현 가능한 회귀다. 구현은 수정하지 않았다.

## 원인

branch는 `SlipResponse`, `SlipDetailResponse`, `SlipLineResponse`의 UUID 및 UUID 문자열 필드에 `OpaqueUuidSerializer`/`OpaqueUuidStringSerializer`를 새로 적용했다. 그 결과 기존 통합 테스트가 응답 ID를 UUID로 다시 사용하는 경로가 22자 URL-safe opaque token을 받는다.

- `IllegalArgumentException`: `UUID.fromString(...)` 등에 `12i0_H7vSBqfKW-AvtRR8A` 같은 token이 들어감.
- `DataIntegrityViolationException`: 공유 데이터 충돌이 아니라 테스트 SQL의 `?::uuid`에 opaque token이 들어가 PostgreSQL이 `invalid input syntax for type uuid`를 반환함.
- assertion: 기존 기대값은 UUID인데 실제 응답은 opaque token임.

즉 직접 원인은 DB row/unique-key 경합이 아니라 **branch의 응답 직렬화 계약 확대와 기존 내부/통합 테스트 소비 계약의 불일치**다. 이 opaque 전환이 내부 API까지 의도된 것인지, 외부 사용자 응답에만 한정돼야 하는지는 본 판정 범위에서 결정하지 않았다.

## 동시 실행 자원 관찰

- 실행 전 Docker에는 여러 라운드의 PostgreSQL/서비스가 동시에 존재했다. 예: `sol1090-liveqa-pre-pg`(53729→5432), `sol1090-liveqa-post-pg`(50346→5432), `sol1143-liveqa7-pg`(45732→5432), `recon845-pg`(40232→5432), 공유 `samhan-postgres`(5432→5432).
- `main` 실행 중 별도 `w1111 product-service` Gradle test가 04:24부터 실행됐다.
- Testcontainers 세션은 서로 다른 sessionId와 임의 포트를 사용했다: `44fd...`/52059와 `bf5f...`/59297. 같은 컨테이너 이름 또는 같은 host port를 쓴 직접 충돌은 관찰하지 못했다.
- `%USERPROFILE%/.testcontainers.properties`에는 `docker.host=tcp://localhost:2375`와 Npipe strategy가 있었고 `testcontainers.reuse.enable=true`는 없었다. 재사용 모드 증거는 없다.
- 반면 branch 전량 종료 때 자기 컨테이너를 kill하려다 404가 난 원문은 외부 cleanup 간섭 증거다. 어느 프로세스가 삭제했는지는 못 갈랐다.
- 공유 DB에 쓰는 명령은 실행하지 않았다. 테스트 DB는 Testcontainers 임의 포트의 격리 PostgreSQL을 사용했다.

## 못 가른 것

- `main` 전량 프로세스가 1,873개 XML을 남기고도 요약 없이 exit 1한 직접 원인은 못 갈랐다.
- branch 전량에서 Testcontainers 컨테이너를 먼저 삭제한 프로세스의 PID/라운드는 못 갈랐다.
- opaque 전환을 내부 API까지 적용하는 것이 제품 의도인지, 외부 사용자 응답에만 적용해야 하는지는 요구사항 결정이 필요하다.
