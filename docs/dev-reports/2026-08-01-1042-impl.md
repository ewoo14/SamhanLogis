# #1042 재고 현황 조회 400 수정 구현 보고서

## 2026-08-01 조사 및 RED 준비

- 정찰 결과와 현재 코드의 계약을 대조했다. 화면은 `GET /inventory/balances?page=&size=` 또는 `warehouseId`를 보내지만 서버는 `productId`를 필수로 선언해, 조회 버튼마다 Spring 바인딩 단계에서 400이 발생한다.
- PM 결정에 따라 `/balances/batch`가 아닌 전체/창고별 페이지 조회 계약을 구현한다.
- 응답에는 현재 없는 모델코드·품목명·창고유형을 채워야 하며, LAZY 창고 접근과 품목 메타데이터 bulk 조회에서 N+1을 만들지 않아야 한다.

## 2026-08-01 패턴 확인

- `StockExcelExportService`가 이미 `ProductClient.lookup()`를 100건 청크로 호출하는 bulk 병합 패턴을 갖고 있다.
- `StockBalanceQueryLazyIT`는 LAZY 창고 연관을 트랜잭션 밖 DTO 변환에서 터뜨리는 회귀를 겨냥한 기존 증거다.
- 기존 `productId` 필터 호출부는 유지해야 하므로 optional `productId`와 optional `warehouseId` 조합을 repository 메서드로 분기한다.

## 2026-08-01 RED

- 실패 테스트 추가: `StockBalanceQueryLazyIT.balances_withoutProductId_returns200ForWholeInventoryPage`.
- 의도: 화면과 동일하게 `page,size`만 보내는 전체 현황 호출이 200 페이지를 반환해야 한다는 계약을 고정한다.
- 1차 실행 원문: `empty()` Hamcrest matcher를 import하지 않아 테스트 컴파일에서 중단됐다. 단정을 `jsonPath(...).exists()`로 수정했다. 제품 코드와는 무관한 테스트 작성 오류다.
- 2차 RED 실행 원문 요약: `StockBalanceQueryLazyIT > balances_withoutProductId_returns200ForWholeInventoryPage() FAILED`, `java.lang.AssertionError at StockBalanceQueryLazyIT.java:99`, `1 test completed, 1 failed`, Gradle `:services:inventory-service:test FAILED`. 현재 구현이 200 계약을 만족하지 못해 테스트가 실패하는 것을 확인했다.

## 2026-08-01 GREEN 구현

- `GET /inventory/balances`의 `productId`를 선택 파라미터로 바꾸고 `warehouseId`를 추가했다. 기존 품목별 호출은 같은 endpoint에서 계속 동작한다.
- `StockBalanceRepository.findBalancePage()`를 추가했다. 전체/품목별/창고별/복합 필터를 한 페이지 쿼리로 처리하고 `warehouse` EntityGraph 및 `productId, warehouse.code` 안정 정렬을 적용했다.
- `StockService.findBalancePage()`에서 페이지 내 distinct 품목 UUID를 최대 100건씩 bulk lookup해 모델코드(`modelName`)·품목명(`name`)을 응답에 병합했다. LAZY 창고는 fetch graph로 채운다.
- 응답 DTO에 모델코드·품목명·창고유형을 추가했고, V23에서 창고 선두 활성 인덱스를 추가했다. 기존 V1~V21 마이그레이션은 수정하지 않았다.
  (⚠️ PM 정정: 최초 V22 로 작성됐으나 PR #1040 이 inventory-service V22 를 선점해 V23 으로 옮겼다.)
- 데스크톱 API가 `productId` 선택 옵션을 보존하고 mock도 품목/창고 필터를 반영한다. 운영 smoke에 `productId` 없는 전체 balances 호출을 추가했다.
- targeted GREEN 원문: `:services:inventory-service:test`, `StockBalanceQueryLazyIT` 통과, `BUILD SUCCESSFUL`, `18 actionable tasks: 4 executed, 14 up-to-date`.
- GREEN 검증을 확장해 모델코드·품목명·창고유형 응답과 창고 필터(HQ-001)를 테스트한다.
- 확장 GREEN 원문: `StockBalanceQueryLazyIT` 통과, `BUILD SUCCESSFUL`, `18 actionable tasks: 2 executed, 16 up-to-date`. 테스트의 unchecked 경고도 제거했다.

## 2026-08-01 운영 읽기 조회

- 실행 중인 auth-service에서 `dev_master` 로그인은 `LOGIN_STATUS=200 TOKEN_PRESENT=True`였다.
- 변경 코드를 재기동하지 않고 확인한 현재 공유 런타임 응답은 다음과 같다. gateway 전체 조회와 창고 필터 조회 모두 `STATUS=400`, 본문은 `{"success":false,"code":"INVALID_INPUT","message":"필수 요청 파라미터가 누락되었습니다.","data":null,...}`였다. 이는 기존 실행 중인 inventory-service가 아직 `productId` 필수 구현인 증거이며, 사용자 금지사항인 공유 서비스 재기동 없이 새 코드의 실제 HTTP 응답으로 바꿔 검증할 수 없다.
- 같은 토큰의 inventory-service 직접 호출은 `STATUS=403`이었다. 해당 서비스는 gateway 인증 헤더 계약을 요구하므로 직접 URL은 권한 검증 증거로 사용하지 않았다.
