# `#910` + `#935` 잔여 정찰 — 웹 3앱 · Expo 3앱 · 메신저 배너 · 인증서 운영

> 조사일: 2026-08-14  
> 대상: PR `#1217`, 이슈 `#910` · `#935`  
> 범위: 조사와 보고만 수행. 코드, git, 공유 스택, 컨테이너, DB는 건드리지 않았다.

## 0. 결론

- 웹 3앱은 `estimate-app`, `order-app`, `mobile-public`이다. `design-system`은 배포 앱이 아니라 공통 라이브러리다(`docs/dev-reports/2026-08-14-910-935-recon.md:64-68`). 세 앱 모두 공통 버전 resolver를 쓰지만 앱 전용 release wrapper와 릴리스 표식 검증은 없다.
- Expo 3앱은 `mobile-staff`, 제품명 `mobile-public`인 `clients/mobile`, `arologis-mobile`이다. 모두 `expo-updates`와 `runtimeVersion.policy=appVersion` 골격이 있지만 projectId가 placeholder라 OTA는 비활성이다. 활성화하면 현재 helper가 fetch 직후 `reloadAsync()`를 실행한다.
- 사내 메신저는 design-system을 이미 직접 의존하지만 updater 배너를 React 트리 밖의 기본 `aside`와 기본 `button`으로 만든다. 다른 두 Electron 앱의 network/integrity/trust 문구 계층과 심각도 레일을 구현하지 않았다.
- 인증서 결정 6~11 중 publisher 통일, 제품별 prefix, 아로로지스의 승인·거부·실제 Root 재조회, beta prefix 계약은 일부 반영됐다. 장기 정본 인증서, 인증서 저장소 직접 서명, 만료 30일 알림, 앱 설정의 stable/beta 전환은 없다.
- 9앱 모두 어떤 형태의 테스트 자산은 있으나, 이번 잔여 범위를 실제 실행 환경에서 닫는 하네스는 부족하다. 특히 웹 `mobile-public` 전용 Playwright, 웹 3앱 release wrapper E2E, Expo 3앱 실제 OTA 왕복이 없다.

### 4.1 만료 30일 시점을 놓치면

현재 앱은 Root에 **정확히 같은 thumbprint가 존재하는지**만 확인한다. 새 인증서를 미리 배포하지 않고 기존 인증서가 만료되면 다음 두 경로 모두 끊긴다.

1. 만료 인증서로 새 installer를 계속 서명하면 Authenticode 신뢰 판정이 실패할 수 있고 updater가 installer 설치를 거부한다.
2. 만료 후 새 인증서로 급히 교체하면 기존 PC는 새 thumbprint를 Root에서 신뢰하지 않으므로 역시 설치를 거부한다.

결과는 Electron 3앱의 자동 설치 전면 중단이며, 자동 업데이트 자체로 복구 인증서를 배포할 수 없는 bootstrap 교착이다. 수동 `.cer` 배포나 수동 재설치 같은 out-of-band 복구가 필요해진다. 현재 trust 오류는 updater에서 “인증서를 신뢰할 수 없음” 계열로 분류된다. `scripts/electron-update-contract.cjs:45-56`

### 4.2 정본 thumbprint 기록 자리

- 결정 문서에는 “실제 생성 뒤 기록”이라는 **미결 문장**만 있다. `docs/decisions/2026-08-14-client-update-expansion-decisions.md:172-176`
- QA 보고서의 기존 2개 thumbprint는 테스트 당시 관측값이고 정본이 아니라고 명시돼 있다. `docs/qa/2026-08-14-1211-adversarial/REPORT.md:31-39`
- 전용 인증서 registry/runbook, `NotBefore/NotAfter`, subject, thumbprint, 배포 시작일, 폐기일, 두 PC store 설치 확인을 함께 기록할 정형 자리는 현재 없다.

**미결:** 결정 문서를 운영 정본으로 확장할지, 별도 인증서 운영 runbook을 정본으로 만들지 개발책임자 판단이 필요하다. 임의 경로를 정하지 않는다.

## 7. 미결 목록

1. estimate-app의 release artifact 정본: 서버 소스 bundle/manifest인가, Render 런타임 env+배포 revision 계약인가.
2. mobile-public 웹의 실제 publish 주체와 명령. 현재 CI는 build까지만 보인다.
3. EAS project 소유 계정·비용 정책, 세 앱 owner/projectId/branch 정본.
4. arologis-mobile에서 보호할 dirty 범위: 로그인 입력, 메모, 사진, 서명 등 전 화면 inventory 후 결정.
5. 공통 인증서 설치 안내를 세 Electron 앱 모두가 할지, 지정된 한 앱이 PC당 한 번 책임질지.
6. 정본 thumbprint 기록 위치와 만료 알림의 실행 주체·수신 채널.
7. 삼한 데스크톱의 반복 가능한 실제 feed/installer runner를 이 트랙에서 복원할지, `#1211` 완료 증거만 유지할지.
