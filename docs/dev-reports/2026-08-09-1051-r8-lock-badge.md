작성일: 2026-08-09 · 워크트리 `t1051` · 기준 HEAD `e16809fd8`

## 판정

R7 진단은 맞았다. `Slip.lockFlag`/`lock_flag`는 이미 존재했지만 상세 응답 DTO와 데스크톱 계약에 빠져 있었고, `SlipDetailPage`의 잠금 안내 조건은 상태 목록(`SHIPPING/DELIVERED/CANCELED/REJECTED`)만 검사했다.

## 1. 잠금과 상태를 분리한 변경

- `services/slip-service/src/main/java/com/samhanair/logis/slip/web/dto/SlipDetailResponse.java:60-61,211` — `lockFlag`를 상세 응답의 독립 boolean 축으로 추가하고 `Slip.getLockFlag()`에서 전달.
- `clients/desktop/src/renderer/api/slip.ts:117-119` — 상세 API 타입에 `lockFlag` 추가.
- `clients/desktop/src/renderer/routes/SlipDetailPage.tsx:2400` — `isLocked = slip.lockFlag === true || isPhysicalTerminal`; 상태 목록에 lock을 삽입하지 않음.
- `clients/desktop/src/renderer/routes/SlipDetailPage.tsx:3650-3653` — 상태와 무관하게 `lockFlag=true`일 때 `slip-detail-lock-badge`/`마감 잠금` 렌더.
- `clients/desktop/src/renderer/routes/SlipDetailPage.tsx:4137-4139` — 잠금 사유와 취소·반려 409 안내.

## 4. 버튼·안내 정합

`canCancelSlip`에 `slip.lockFlag !== true`를 추가해 잠긴 전표의 취소 버튼을 활성화하지 않는다. 서버/mock에서 직접 취소를 시도하면 409 `회계 마감으로 잠긴 전표는 취소·반려할 수 없습니다.`를 반환하고, 화면 mutation error 영역은 서버 안내 문구를 그대로 표시한다. 기존 상태별 액션·상태 배지는 변경하지 않았다.
