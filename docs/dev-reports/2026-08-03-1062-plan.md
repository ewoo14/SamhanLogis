## 배경

개발책임자께서 실화면에서 두 가지를 지적하셨다. 둘 다 **전표 라인 입력** 표면이고 `design-system` 공용 컴포넌트에 걸려 있어 한 슬라이스로 묶는다.

---

## ① 모델명 자동완성에서 후보를 읽을 수 없다

`ap145` 를 입력하면 드롭다운에 `모델명생`, `모델명|` 같은 글자만 뜬다. **후보를 구분할 수 없다.**

### 원인 (PM 실측)

```css
/* clients/web/design-system/src/components/AsyncAutocomplete/AsyncAutocomplete.module.css:95 */
.dropdown { position: absolute; left: 0; right: 0; }
```

드롭다운 폭이 **입력칸 폭에 묶여** 있다. 전표 라인의 `모델명` 열은 90px 남짓인데, 옵션 한 줄의 구조는

```text
[모델명]배지 + 값 + · + [품목명]배지 + 값
```

라서 **배지가 폭을 거의 다 먹고 실제 값이 한 글자로 잘린다.** 화면에 보이는 `모델명생` 은 값이 아니라 **배지 텍스트 + 값 1글자**다.

`#1046`(순번코드 → 모델명 전환)이 머지되며 이 자동완성이 좁은 테이블 열로 들어가 드러난 것으로 보인다.

### 📌 개발책임자 결정 (2026-08-03)

> **둘 다 — 폭 넓히고 + 모달 병행**

- 평소에는 **내용에 맞게 넓어진 드롭다운**으로 빠르게 고른다.
- **후보가 2건 이상**이면 이카운트처럼 **모달**로 모델명·품목명·규격·단가를 표로 보여주고 고를 수 있게 한다.

## ② 수정 모드에 자동 빈행이 없어 라인을 추가할 수 없다

> *"수정 시 아래 품목 빈행 자동 추가가 없으니까 수정이 어렵다."*

### 원인 (PM 실측)

`SlipFormPage.tsx` 의 증식 규칙은 **`maybeExpandLastLine`** — *"마지막 행이 편집되면 1행 추가"* 다. 신규 작성은 빈행 1개로 시작하므로 자연히 늘어나지만, **수정 모드는 저장된 행만 로드해 트레일링 빈행이 0개**다. 새 품목을 넣으려면 기존 마지막 행을 건드려야 한다.

### 기준

메모리 정본 [`feedback_auto_blank_row_for_all_line_entry`] — **행 입력 화면은 전부 자동 빈행이고 "행 추가" 버튼은 없다.** 기준 구현은 판매전표 `SlipFormPage.tsx:678-698`(증식) · `:1101-1123`(빈행 저장 제외) · `:710-719`(마지막 행 삭제). **재사용할 것, 중복 구현 금지.**

이 규칙이 **신규에만 적용되고 수정에는 빠져 있다.**

## 적용 범위

`design-system` 공용 컴포넌트 변경이라 라인 입력 화면 전체에 걸린다. 최소한 다음을 확인해야 한다.

- 판매전표 `SlipFormPage` (기준 구현)
- 이동 `TransferFormPage`
- 견적 `EstimateFormPage` · 분개 `JournalFormPage` (메모리상 자동 빈행 **미적용** 상태로 기록돼 있음)

## 불변식

- 빈행이 **저장되면 안 된다.**
- 신규·수정 **양쪽 모두** 자동 빈행이 있어야 한다.
- 자동완성 후보는 **값을 읽을 수 있어야** 한다.
- 화면에 **UUID 노출 금지**(모델명·품목코드는 사용자 노출 코드라 표시 대상).

## 주의

`design-system` 변경은 **Playwright mock 스위트가 필수**다(vitest·정적 검증만으로는 부족). 라이브QA 하네스 디렉토리는 **`-real-qa` 접미사** 규약을 지킬 것.
