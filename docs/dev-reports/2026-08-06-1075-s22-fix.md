# PR #1078 · 이슈 #1075 — S22 fix (LUNA)

## 판정

S21-F1을 최소 수정했다. 구 revision/DB의 `specificationSource` 누락(`null`)이 현재 화면 hydrate 저장에서 `USER` 또는 `CATALOG`로 정규화되어도 표시 규격이 같으면 revision `lineModified`에 포함하지 않는다. 양쪽 source가 명시된 `CATALOG↔USER` 전환은 계속 라인 변경으로 집계한다. backfill·마이그레이션·전표 provenance 이식은 하지 않았다.

S21-F2의 누락 세 경계는 현재 코드에서 규격과 출처가 한 쌍으로 이동하는 것을 재확인했다. `shared/collab-core`는 port의 snapshot JSON을 그대로 캡처·저장·restore 소비하고, revision 응답과 데스크톱 버전 이력 화면은 `ChangeSummary`를 소비하며, 실제 `mobile-staff` 진입점은 `EstimateWebViewScreen`이다. 추가 수정은 필요하지 않았다.

## 수정

`EstimateRevisionService#lineDiffers`의 source 비교를 `specificationSourceDiffers`로 분리했다. 두 source가 모두 비어 있지 않을 때만 `CATALOG↔USER` 차이를 modified로 센다. 규격 문자열, 단가, 수량, 금액, 비고 및 나머지 라인 비교는 변경하지 않았다.

추가한 회귀 테스트:

- 평문 legacy `null→USER` + 동일 규격 + 헤더 변경: `lineModified=0`
- 구 marker legacy `null→CATALOG` + 동일 규격 + 헤더 변경: `lineModified=0`
- 명시 `CATALOG→USER` + 동일 규격: `lineModified=1`
