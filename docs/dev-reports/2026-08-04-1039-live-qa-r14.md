### 분류 의미 확인 보류 사유

- 화면에서 만든 표본은 `DAY` 2건(상일 1, 초월 1)과 `STACK` 1건(상일 1)이다. 코드 정의상 일반 모드에서는 `STACK`을 보존하고, 1~3은 `REGION`을 제외하며, 4는 `STACK`만, 5는 `REGION`만 대상으로 한다. 이 표본으로 1·2·3·4·6·7·8의 양성 후보는 준비했지만, 실제 결과 목록이 403으로 반환되지 않아 포함/제외 양방향 검증을 수행할 수 없다.
- `REGION`은 오늘 12:00 이후 UI 저장이 서버에서 409로 차단됐다. 화면의 상차일은 오늘 읽기 전용이고 하차일만 편집 가능하여, UI에서 익일 출고 표본을 만들 경로는 확인하지 못했다. 따라서 모드 5를 데이터 부족으로 PASS 처리하지 않는다.

## 4. 만든 전표 목록

DB 읽기 조회로 저장 반영을 확인한 신규 전표는 다음 3건이다. 이후 집계·분류 판단에서 기존 데이터와 분리해야 한다.

| 전표번호 | 출고창고 | 태그 | 상태 |
|---|---|---|---|
| `2026/08/04-2` | 상일물류 | `DAY` | `DRAFT` |
| `2026/08/04-3` | 삼성창고 (초월 무갑) | `DAY` | `DRAFT` |
| `2026/08/04-4` | 상일물류 | `STACK` | `DRAFT` |

- DB 읽기 확인 시 활성 태그 집계는 `DAY/DRAFT 2`, `STACK/DRAFT 1`이고 `REGION` 행은 0건이었다. 기존 활성 전표는 모두 `delivery_tag=NULL`이었다.
- `REGION` 저장 시도 1건은 409로 전표번호가 없으므로 목록에 넣지 않았다.

## 5. 이 라운드가 보지 않은 것

- `arologis.dispatch.ops` 권한이 `role=UNKNOWN`으로 거부되어 8개 모드의 실제 결과 행, 포함/제외 의미, positive 분류를 보지 못했다.
- 분류 결과의 `발행` 후속 동작, CSV 다운로드, 가배차 분류 결과 저장을 보지 못했다.
- `REGION` 표본은 업무 마감 규칙과 상차일 읽기 전용 때문에 만들지 못했다. `ABANDONED` 조건은 시도하지 않았고, DB 직접 삽입이나 마스터 변경으로 만들지 않았다.
- 실배차/수동배차, 미배차, reconcile 등 PR #1045의 다른 화면은 이번 8모드 라이브QA 범위가 아니어서 보지 않았다.
