## 1. 원인 조사

R21이 지적한 상태 불일치를 소스에서 재확인했다.


`onDateChange={setDate}`는 화면의 배차일만 바꾸고 기존 행의 숨은 `date`를 바꾸지 않는다. 그 결과 서버의 날짜 대조가 정상적으로 다른 날짜 입력을 제외하지만, 사용자가 새 배차일 기준으로 입력한 연락처까지 조용히 제외한다. 날짜 필터는 제거 대상이 아니다.

## 3. 수정 내용

`DispatchSmsPage.tsx`에 `syncDriverContactDates`를 추가하고 날짜 변경 시 다음 두 상태를 함께 갱신한다.

```text
setDate(nextDate)
setDriverContacts((rows) => syncDriverContactDates(rows, nextDate))
```

행의 `slipNo`, `companyName`, `driverPhone`은 유지하고 숨은 `date`만 현재 화면의 배차일로 교체한다. 서버의 `input.date()` 대조는 그대로 남겨 다른 날짜 연락처가 섞이지 않도록 했다.

### 공란 전표 fallback

`DispatchBatchPreviewServiceTest.preview_withoutDriverContactInput_keepsFallback` 및 새 날짜 필터 회귀 테스트에서 모두 `기사번호 없음 확인요망!`을 유지함을 확인했다.

```text

```

새 테스트 `preview_staleDriverContactDate_doesNotOverrideRequestedDate`는 다른 날짜 입력을 서버가 계속 제외하고, 그 경우 공란 fallback을 유지하는지 고정한다. 따라서 날짜 필터를 없애지 않았고 공란 전표 2,290건에 대한 기존 fallback 경로를 보존했다.
