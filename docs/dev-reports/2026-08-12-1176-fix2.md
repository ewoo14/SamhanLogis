## 2. 수정

- `2026-08-12-soft-delete-qa-residue.sql`: partner/slip 양쪽의 대상 건수를 먼저 각각 검증한 뒤, 두 사전 가드가 모두 통과할 때만 실제 UPDATE를 시작하도록 변경했다. 재실행·가드 실패는 `ROLLBACK` 후 `SELECT 1 / 0`으로 비0 종료를 보장한다.
- `2026-08-12-rollback-soft-delete-qa-residue.sql`: 같은 양 DB 사전검사를 rollback에도 적용했다. slip 표지가 295행이 아니면 partner UPDATE/COMMIT이 시작되지 않는다.
- `2026-08-12-fix2-regression.ps1`: 사전검사 순서와 재실행 비0 종료를 자동 검증하는 회귀 하네스를 추가했다.

## 4. fix1 증거 정정

`docs/dev-reports/2026-08-12-1176-fix1-rollback.md`의 재실행 종료 코드 `1`을 실제 값 `3`으로 정정했다. 원인은 PostgreSQL 16 `psql`에서 `ON_ERROR_STOP` 상태로 `SELECT 1 / 0 AS rollback_guard_failure`가 실행되어 SQL 오류가 발생했기 때문이다. `\quit 1`은 psql에서 인자를 무시하므로 종료 코드 전달 수단이 아니다.
