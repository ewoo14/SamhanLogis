# #1012 조회 키 불일치 fix

## 구현 결과

`InOutAnalysisService`의 실제 입력값을 `modelCodes`에서 `modelNames`로 바로잡고, product-service에 모델명 전용 벌크 조회 계보를 추가했다. 기존 `lookupByModelCodes` 계약과 호출자는 변경하지 않았다.

## 1. `lookupByModelCodes` 전수 계보

조회 명령:

```text
rg -n --glob '*.java' 'lookupByModelCodes' services/slip-service/src/main services/slip-service/src/test services/product-service/src/main services/product-service/src/test services/partner-order-service/src/main services/partner-order-service/src/test | Measure-Object
Count: 21
```

분류:

- 수신 계층 2곳: product-service controller / service.
- 클라이언트 정의 2곳: slip-service / partner-order-service.
- 운영 호출자 3곳: `InOutAnalysisService`, `PartnerOrderQueryService`, `PartnerOrderConfirmService`.
- 관련 테스트 5개 파일과 기존 fallback/HTTP 계약 검증.
- 별도 repository model-code 조회 `findByModelCodeInAndIsDeletedFalse`는 유지.

이번 수정에서 `InOutAnalysisService`의 1개 호출자만 `lookupByModelNames`로 전환했다. partner-order의 2개 호출자는 실제 값이 modelCode이므로 기존 계보를 유지한다.

## 3. 수정 내용

- `ProductService.lookupByModelNames(List<String>)`: `model_name IN (...)`만 조회.
- `POST /products/internal/lookup-by-model-names`: `modelNames` request body.
- slip `ProductClient.lookupByModelNames`: 모델명 값과 endpoint 이름을 일치시킴.
- `InOutAnalysisService`: `modelNames` 변수, `lookupByModelNames`, 결과 key `p.modelName()`으로 정렬.
- 기존 `lookupByModelCodes`와 `model_code` repository 조회부는 변경하지 않음.

## 4. A — 이카운트 계보 read-only 실측

Docker 재빌드·재기동 없이 product DB를 읽기 전용 트랜잭션으로 조회했다. 모델코드는 출력하지 않고 모델명만 출력했다.

```text
BEGIN
   model_name    | lookup_matches
----------------+----------------
 AC1000CNCDEH-85 |              1
(1 row)
ROLLBACK
```

즉 `model_code IS NULL`인 활성 품목을 `model_name`으로 조회했을 때 1건이 매칭된다. 기존 model-code 기준만 사용하면 이 계보는 매칭되지 않는다. 실측 전체 기준은 활성 1,220건 중 model-code 보유 1,120건, model-code NULL 100건이며, 이번 경로는 후자도 model_name으로 조회한다. 전표 DB에 아예 없는 판매 46품목은 별도 #1051 범위이며 이번 결과에 섞지 않는다.

## 5. B·D 확인

- B: 기존 `lookupByModelCodes` 운영 호출자 2곳과 product-service model-code endpoint/service/repository는 변경하지 않았다. 기존 `ProductServiceTest.lookupByModelCodes_fallsBackToModelNameWhenModelCodeIsBlank` 및 slip 40건 model-code 계약 테스트가 통과했다.
- D: `SlipQueryController`의 `accounting.sales-slip.list` VIEW 가드와 `GET /slips/query/inout-analysis` 경로는 변경하지 않았다. 기존 실측 원문은 `warehouse_HTTP=403`, `accounting_HTTP=200 rows=61`이며, 변경은 상품 조회 키에만 한정된다. `—` 표시 및 권한 회귀를 유발하는 응답/컨트롤러 코드는 건드리지 않았다.
