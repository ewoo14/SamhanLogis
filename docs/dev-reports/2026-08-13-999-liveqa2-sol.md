# #999 liveQA2 — CODEX SOL

## 결론

**실 사용자 경로에서 재현되는 결함: 1건. 머지 불가.**

전표 검색·상세 API 자체는 현재 브랜치 소스로 다시 만든 slip-service JAR에서 요청 URL과 응답 본문 모두 UUID 0건이고, opaque token으로 조회한 상세도 `2026/08/02-17`을 반환한다. 그러나 재고수불부를 만드는 inventory-service 내부 `SlipClient`가 opaque `id`, `lines[].id`, `lines[].productId`를 `UUID.fromString(...)`으로 파싱하다 실패한다. `StockLedgerService.resolveSlip()`이 그 예외를 삼켜 해당 행의 `slipNo/slipType`을 null로 내리므로, 실제 화면의 `2026/08/02-17`은 클릭 가능한 전표번호가 아니라 평문 적요가 된다. 사용자는 전표 모달에 도달할 수 없다.

`stock_movements`의 `TRANSFER` 계열은 0건이며 사양대로 결함으로 세지 않았다.

## 증거 무결성

- 공유 DB에는 쓰지 않았다. `origin/main:scripts/qa/clone-db-utf8.sh`(#1191)를 작업트리에 쓰지 않고 직접 실행해 `inventory_db`, `partner_db`, `product_db`, `slip_db` 네 DB의 dump/restore 및 데이터·스키마 이중 비교가 모두 PASS한 뒤, 동일 파일 기반 dump/restore 방식으로 격리 PostgreSQL `sol999-liveqa2-pg-202608130244`을 만들었다.
- 브라우저 런타임 목록 원문은 `[]`였다. 실행 불가로 판정하지 않고 저장소 `@playwright/test` Chromium으로 실 GUI를 걸었다.
- 현재 브랜치 소스의 `:services:slip-service:bootJar`를 다시 실행해 `BUILD SUCCESSFUL`을 확인하고 격리 slip-service를 재기동했다. 낡은 JAR 가능성을 제거한 뒤 결함을 재현했다.
- 인증·권한·창고·재고현황 첫 목록만 화면 진입용 고정 응답을 사용했다. 검증 대상인 품목 인스턴스 GET/PATCH, 수불부 GET, 전표 검색/상세 GET, 재고실사 GET/POST는 격리 서비스·DB에 실제 왕복했다.

```text
[clone] PASS partner_db
[clone] PASS product_db
[clone] PASS slip_db
[clone] PASS all databases; isolated container and dump files will be removed
```

## 결함 원인 증거

현재 slip-service 직접 왕복은 정상이다.

```text
GET /slips/query ... → id=coJdouCwR-Gh-4ZZ9EDItQ
GET /slips/coJdouCwR-Gh-4ZZ9EDItQ → 200
상세 slipNo=2026/08/02-17
두 요청 URL UUID=0, 두 응답 UUID=0
```

그러나 `services/inventory-service/.../SlipClient.parseSlipDetail()`은 다음 필드를 여전히 `UUID.fromString(...)`으로 읽는다.

```text
data.id
data.destinationWarehouseId
lines[].id
lines[].productId
```

opaque 응답과 내부 소비자 계약이 불일치하여 `StockLedgerService.resolveSlip()`이 null로 fallback하고, 결과적으로 수불부 링크가 사라진다.

## 못 한 것

- 최종 재빌드 JAR에서는 표적 전표 링크가 사라져 전표 모달을 열 수 없었다. 따라서 모달 오픈 뒤 발생하는 네트워크 요청 전수와 400·404·500 검사는 **못 했다**. 이를 통과로 기록하지 않는다.
- `TRANSFER` 계열은 0건이어서 재고이동 행은 실행 대상이 없었다. 사양대로 결함으로 세지 않았다.

## 머지 판정

**머지 불가.** 전표 API UUID 비공개 fix 자체는 통과했지만, 실 사용자 재고수불부 → 전표 모달 경로가 opaque token 소비자 계약 불일치로 끊겼다.
