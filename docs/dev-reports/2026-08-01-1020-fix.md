## 확인 5 — 실 DB 읽기 전용 매칭 SQL

실행 중인 기존 PostgreSQL 컨테이너를 조회만 했으며 재빌드·재기동하지 않았다. `auth_db`에서
`is_deleted = false AND enabled = true`인 계정의 `(account_id, login_id, full_name)`을 읽어
메모리 CTE로 전달하고, `user_db`에서는 다음과 같은 SELECT만 실행했다. UUID 값은 보고서에 기록하지
않았다.

```sql
WITH auth_candidates(account_id, login_id, full_name) AS (
    -- auth_db의 활성 계정 SELECT 결과를 읽기 전용으로 전달
), matched AS (
    SELECT e.account_id AS employee_account_id,
           c.account_id AS candidate_account_id
      FROM employees e
      JOIN auth_candidates c
        ON c.login_id = e.login_id
       AND c.full_name = e.full_name
     WHERE e.is_deleted = false
       AND e.termination_date IS NULL
), classified AS (
    SELECT *, (employee_account_id = candidate_account_id) AS already_normal
      FROM matched
)
SELECT COUNT(*) AS matched_active_employees,
       COUNT(*) FILTER (WHERE already_normal) AS already_normal_excluded,
       COUNT(*) FILTER (WHERE NOT already_normal) AS broken_references_to_plan
  FROM classified;
```

실행 출력 원문:

```text
 matched_active_employees | already_normal_excluded | broken_references_to_plan
--------------------------+-------------------------+---------------------------
                       24 |                       8 |                        16
(1 row)
```

판정: 고친 조건은 실 DB에서 정상 8건을 제외하고, `id == account_id`이지만 auth 후보 account가
별도로 실재하는 끊어진 16건을 계획 대상으로 집는다. 이 SQL은 BEGIN/COMMIT, INSERT/UPDATE/DELETE
없이 두 DB에 SELECT만 실행했다.
