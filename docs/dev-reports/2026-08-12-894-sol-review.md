### 9. 동시 메시지 적대검증

같은 방에서 두 참여자 세션이 20건을 동시에 발송했다.

```text
CONCURRENT_SEND statuses=200,200,200,200,200,200,200,200,200,200,200,200,200,200,200,200,200,200,200,200 visible=20 duplicateSequenceRows=20

sequence_no 7  -> 2 rows
```

`ChatMessageService.send()`가 `findMaxSequence(roomId) + 1`을 잠금 없이 계산하고, DB에는 `(room_id, sequence_no)` UNIQUE가 아니라 일반 index만 있다. 20건 전부 200이지만 20건 모두 다른 메시지와 sequence를 공유했다. `ChatRoomPage`는 `key={message.sequence}`를 사용하므로 동시 발화 시 React key 충돌과 순서 불확정이 실제 사용자 화면으로 이어진다.

### 10. 데스크톱 사용자 진입·식별 계약

따라서 사용자는 알려진 `roomCode`를 주소에 직접 입력하지 않는 한 방을 만들거나 목록에서 열 수 없다. 또한 실제 메시지 응답은 `roomCode, sequence, body, sentAt`뿐이고 화면도 `body, sentAt`만 렌더하므로 본인과 상대의 발화를 구별할 수 없다. 방 응답도 `roomCode, type, roomName`뿐이며 DIRECT의 `roomName`은 null이라 정본이 요구한 상대 이름·부서·사번 표시가 불가능하다.

UUID는 신규 채팅 REST 응답·오류·room URL 정규식 검사에서 0건이었고 `ChatRoomPage`도 `roomCode`만 화면에 표시한다. 다만 실제 화면 캡처 검증은 Browser 부재로 skipped다.

## 최종 판정

**실 사용자 경로로 재현 가능한 결함이 있다. 총 5건이다.**

1. **방 생성 500:** V20 room code와 재기동 시 1부터 시작하는 `AtomicInteger`가 충돌한다.
2. **동시 메시지 sequence 충돌:** 20/20 요청은 200이지만 sequence가 중복되어 화면 key·순서가 깨진다.
3. **사용자 진입 경로 없음:** 방 목록·새 대화 호출 UI가 없어 roomCode 직접 입력 없이는 채팅에 진입할 수 없다.
4. **발신자 구분 불가:** 메시지 응답·화면에 발신자 식별 정보가 없어 왕복 대화를 구분할 수 없다.
5. **상대 표시 불가:** DIRECT 방 응답에 상대 이름·부서·사번이 없고 `roomName`은 null이다.
