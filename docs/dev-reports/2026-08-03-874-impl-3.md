# PR #1057 / 이슈 #874 — riUsage 확인 판정 구현 보고서

작성일: 2026-08-03 (KST)  
작업 브랜치: `feat/874-set-riusage-global-dc`  
범위: `MonthEndCloseService`의 SINGLE 세트 `확인` 판정에 레거시 `riUsage` 입력 연결

## 1. 레거시 원문 대조와 적용 경계

이번 라운드에서 이전 보고서의 “`parentSetNames` 경로를 사용한다”는 설명을 정정한다. `parentSetNames`는 #1058의 옵션 정액 선택용이며, `riUsage`는 레거시의 `확인` 판정 입력이다. `riUsage`를 응답 필드로 추가하지 않고 내부 재검증 결과의 `verified`에 반영했다.

레거시 원문 `tools/legacy-gas/일마감 프로그램/Code.js:689-710`의 분기는 다음과 같다.

| 레거시 원문 | 현행 대조 | 적용 여부 |
|---|---|---|
| `Code.js:689-690`: `!hasSingleMain`이고 `PANEL/REMOTE/MATERIAL`이면 `확인=true` | `RiUsageDecision`: 같은 scope에 주 품목이 없으면 `true` | 적용 |
| `Code.js:691-706`: 부속은 먼저 자기 `riUsage.used === total`, 그 다음 주 품목 실패 여부, 마지막으로 `unitPrice === _deliveryPrice` fallback | 자기 소비 완료면 `true`, 주 품목 미완전이면 `false`, 주 품목이 모두 완료되고 자기 소비가 미완료이면 `null`을 반환하여 기존 `DiscountRevalidator` 판정 유지 | 적용 |
| `Code.js:695-698`: 실패 주 품목은 `INDOOR/OUTDOOR`이고 `used !== total` | 동일 판정 단위(scope)에서 `INDOOR/OUTDOOR/SUB_INDOOR` 중 usage 미완료를 검사 | `SUB_INDOOR`는 명시적으로 포함. 원문의 `hasFailedMain`에는 없는 확장은 해당 모델 kind가 `SUB_INDOOR`인 경우에만 적용됨 |
| `Code.js:707-708`: `INDOOR/OUTDOOR/SUB_INDOOR`는 `used === total` | 주 품목 행별 `used === total`을 `verified`로 연결 | 적용 |
| `Code.js:709-710`: 그 밖은 `true` | `RiUsageDecision`가 `null`을 반환하고 기존 경로를 유지 | 적용 범위 외 행 보호 |

세트 matcher 자체와 `riUsage` 판정은 중복하지 않는다. `LegacySetMatcher`는 원본 행을 수량 단위로 소비하여 `Match`, `Usage(total, used)`, 부모 세트명을 만든다. `MonthEndCloseService`는 부모 세트명을 #1058 옵션 정액 선택에만 사용하고, 같은 결과의 usage를 `RiUsageDecision`에 전달해 `verified`를 정한다. 따라서 두 matcher가 같은 책임으로 경쟁하지 않는다.

## 2. RED-first

구현 전에 새 판정 테스트를 실행했고, 아직 `RiUsageDecision` production class가 없어 컴파일 RED가 났다. 실행 명령:

```text
./gradlew.bat :services:accounting-service:test --tests '*RiUsageDecisionTest' --no-daemon --console=plain
```

RED 원문 발췌:

```text
error: cannot find symbol
  symbol:   variable RiUsageDecision
  location: class RiUsageDecisionTest
error: package RiUsageDecision does not exist
...
14 errors
BUILD FAILED
```

이 RED는 다음 실패 조건을 먼저 고정했다.

- 수량 2 중 1만 소비된 주 품목은 `false`.
- 수량 2 중 2가 소비된 주 품목은 `true`.
- 주 품목이 미완료인 같은 scope의 부속은 `false`.
- 주 품목이 없는 부속은 `true`.
- 주 품목이 완전 소비됐지만 부속이 미완료인 경우는 `null`로 두어 레거시 fallback을 보존.

## 3. 구현

- `LegacySetMatcher.findMatchesWithUsage`를 추가해 source row별 `(total, used)`를 노출했다. 수량은 기존처럼 unit pool로 확장하며 매칭되지 않은 단위는 used에 포함하지 않는다.
- `MonthEndCloseService`가 전표번호와 행번호를 `sourceKey`로 전달한다. 판정 scope는 거래처와 전표번호로 제한한다.
- `RiUsageDecision`가 SINGLE 및 레거시 kind 분기만 처리한다. 주 품목은 완전 소비 여부를 직접 반환하고, 부속은 “주 품목 없음 / 주 품목 미완료 / 주 품목 완전 완료” 세 갈래를 보존한다.
- `DiscountRevalidator.Revalidation.withVerified`로 할인·금액 계산 결과는 보존하면서 `verified`만 교체한다.
- 고정DC 우선은 기존 경로의 `fixedDc ?? globalRate`를 유지했다. 이번 라운드에는 할인 우선순위 계산을 재작성하지 않았다.

## 5. 불변식 실측

### 5.1 불변식 1 — 주 품목 완전 소비와 반대급부

`[DEV-SEED/단위 fixture]` `RiUsageDecisionTest`에서 주 품목 source `D1#1`의 usage `(total=2, used=1)`은 `false`, `(2,2)`는 `true`이다. 수량 1개가 1개 소비된 케이스는 `LegacySetMatcherTest.exposesRiUsagePerSourceRowForPartialAndCompleteConsumption`의 `D1#2: (1,1)`로 `true` 경로를 검증했다.

`[실데이터/로컬 read-only]` 현재 `accounting_db` 행 수는 tax invoice 22, sales slip 1, purchase slip 0이다. 이 조회 결과만으로는 실제 일마감 응답의 `verified` 변경 행을 재생성할 입력이 확인되지 않았으므로, 실데이터 변경 행 수는 **0행 관측**으로 기록한다. 0은 규칙 정확성의 증거가 아니라 현재 read-only 전표 모집단에서 도달 행이 없다는 뜻이다.

### 5.2 불변식 2 — 부속 교차 행 의존과 세 갈래

`[DEV-SEED/단위 fixture]` 같은 scope의 미완료 주 품목이 있으면 부속은 `false`, 주 품목이 없으면 `true`, 주 품목이 완전 소비됐으나 부속이 미완료이면 `null`이다. 마지막 `null`은 기존 레거시 가격 fallback을 유지하는 값이며 `false`로 평탄화하지 않았다.

`[실데이터/로컬 read-only]` 이번 로컬 전표 23행에서 이 판정이 실제 응답에 도달해 `verified`를 바꾼 행은 **0행**이다. 실전수 증거가 없는 상태에서 GREEN 테스트 결과를 실데이터 전수 통과로 확대하지 않는다.

### 5.3 불변식 3 — 적용 범위와 비적용 범위

`[DEV-SEED/단위 fixture]` 판정은 `SINGLE` 축과 catalog kind `INDOOR/OUTDOOR/SUB_INDOOR/PANEL/REMOTE/MATERIAL`에만 적용한다. 다른 축과 그 밖의 kind는 `null`을 반환해 기존 경로를 탄다. 부속의 “주 품목 없음”은 적용 범위 안에서 `true`이다.

`[실데이터/로컬 read-only]` `product_db` 활성 제품은 1,220개, 그중 `fixed_discount_rate IS NOT NULL`은 167개, 활성 `bundle_component`는 1,588행이다. 현재 전표 23행에서 `verified` 변경 행은 0행이므로, 전역DC 미보유 거래처 및 해당 없는 품목의 금액 변화도 **0원 관측**이다. 이는 실제 전수 금액 비교가 아니라 도달성 0에 따른 관측값이다.

### 5.4 불변식 4 및 #1058 무회귀

`[실데이터/로컬 read-only 기준선]` #1058이 확정한 권위 기준선은 기존 보고서 `docs/dev-reports/2026-08-02-1008-r9-snapshot-baseline.md:32-33` 및 `docs/dev-reports/2026-08-02-1008-r6-set-matching-in-closing.md:154-168`에 있다.

- 확정 과차감: 0행 / 0원.
- 옵션 미보유 거래처: 164곳 / 0원 변화.
- 스냅샷 기준선: 0.

이번 변경은 `parentSetNames`와 global DC 옵션 선택 경로를 바꾸지 않고 `verified`만 조건부 교체한다. 위 세 값은 해당 보고서 기준선으로 유지되며, 이번 라운드에 accounting 전체 스위트와 별도 원본 스냅샷 전수 실행은 하지 않았으므로 새 전수 측정의 통과로 표현하지 않는다. 타깃 테스트에서 #1058의 기존 `DailyClosingDetailServiceTest` 경로는 GREEN이다.

### 5.5 고정DC 우선 관측

`[실데이터/로컬 read-only]` `product_db`에서 고정DC 보유 제품은 167개다. 이번 라운드에는 할인 재계산 모집단을 write 없이 재현하지 않았으므로 `fixedDc`와 `globalRate`가 서로 다른 실건수와 실제 적용 방향은 **미측정**이다. 구현은 기존 `fixedDc ?? globalRate` 경로를 보존했으며, 이 항목을 증상 0으로 통과 판정하지 않는다.
