- 기준 문서상 제거 범위는 외부 창고 실재성·코드 대응·3상태·주기 재검증·timeout이며, 본 라운드에서는 이를 결함 축으로 보지 않는다(`#1052` 분리).
- 브랜치 원문: `fix/1035-warehouse-uuid-boot`.
- 최초 `git status --short` 원문은 본 보고서 하나만 신규 파일로 표시했다: `?? docs/dev-reports/2026-08-02-1035-reconvergence3.md`.
- 코드·git·Docker·실 DB 쓰기는 수행하지 않는다. 보고서만 append한다.

## 1. 각도 1 — `WarehouseInternalClient` 호출부 전수

- 재현 명령: `rg`로 `services/slip-service/src/main`의 Java 전체에서 타입 참조, `.findWarehouseName(` 호출, `findWarehouseName(` 토큰을 각각 집계했다.
- 출력 원문:

```text
TYPE_REF_FILES=1
services/slip-service/src/main\java\com\samhanair\logis\slip\client\WarehouseInternalClient.java
QUALIFIED_CALL_SITES=0
ALL_METHOD_TOKENS=1
services/slip-service/src/main\java\com\samhanair\logis\slip\client\WarehouseInternalClient.java:42:    public Optional<String> findWarehouseName(UUID warehouseId) {
```

- 판정: main 코드의 실제 호출부는 **0곳**이다. 타입 참조 1파일과 메서드 토큰 1건은 모두 client 자체 선언이다.
- 실 사용자 경로 재현 여부: 정적 도달성 전수 확인. 기동 런타임 확인은 아래에 별도 기록한다.
- 영향 범위: slip-service main 코드 전체. 테스트의 mock 선언은 실행 호출부가 아니므로 별도 집계에서 제외했다.

## 2. 각도 1 — `local` 무환경변수 실제 기동

- 실 사용자 경로 재현 여부: **재현 완료**. 네 창고 환경변수를 자식 프로세스에서 제거하고 `local` 프로파일, H2 메모리 DB, 임의 포트로 실제 Spring Boot를 기동했다.
- 재현 명령: `gradlew.bat :services:slip-service:bootRun --no-daemon --args="--spring.profiles.active=local --server.port=0"` (자식 프로세스에서 네 `WAREHOUSE_UUID_*` 제거).
- 출력 원문:

```text
LOCAL_STARTED=True
PROCESS_RUNNING_AT_45S=True
WAREHOUSE_CLIENT_LOG_LINES=0
2026-08-02T12:08:59.373+09:00  INFO 111656 --- [slip-service] [           main] c.s.logis.slip.SlipServiceApplication    : The following 1 profile is active: "local"
2026-08-02T12:09:04.586+09:00  INFO 111656 --- [slip-service] [           main] com.zaxxer.hikari.pool.HikariPool        : HikariPool-1 - Added connection conn0: url=jdbc:h2:mem:slip_db user=SA
2026-08-02T12:09:15.492+09:00  INFO 111656 --- [slip-service] [           main] c.s.logis.slip.SlipServiceApplication    : Started SlipServiceApplication in 18.155 seconds (process running for 18.739)
T1035_RUNTIME_PROCESSES_AFTER_LOCAL=0
```

- 판정: **PASS**. env 없이 `local` 정상 기동에 도달했고, 45초 관찰 시점에도 프로세스가 살아 있었다. 관찰 후 해당 PID 트리만 종료했으며 잔류 프로세스는 0개다.
- 외부 호출 관찰: 창고 서비스를 띄우지 않은 상태였고 `WarehouseInternalClient` 로그는 0줄이었다. 정적 호출부 0곳 결과와 일치한다.
- 영향 범위: 개발자 로컬 기동 경로. 공유 Docker·실 DB는 사용하지 않았다.

## 3. 각도 1 — 운영(default) 프로파일 env 주입 실제 기동

- 실 사용자 경로 재현 여부: **재현 완료**. `local`을 활성화하지 않은 default 프로파일에 네 창고 env를 주입했다. 실 DB 쓰기 방지를 위해 datasource만 H2, JPA `create-drop`, Flyway off로 격리했고 Eureka도 비활성화했다.
- 재현 명령: `gradlew.bat :services:slip-service:bootRun --no-daemon --args="--server.port=0 --spring.datasource.url=jdbc:h2:mem:slip_ops --spring.datasource.driver-class-name=org.h2.Driver --spring.datasource.username=sa --spring.jpa.hibernate.ddl-auto=create-drop --spring.jpa.properties.hibernate.dialect=org.hibernate.dialect.H2Dialect --spring.flyway.enabled=false --eureka.client.enabled=false --eureka.client.register-with-eureka=false --eureka.client.fetch-registry=false"` (자식 프로세스에 네 창고 env 주입).
- 출력 원문:

```text
OPS_STARTED=True
PROCESS_RUNNING_AT_45S=True
WAREHOUSE_CLIENT_LOG_LINES=0
ACTIVE_PROFILE_LOG_LINES=0
2026-08-02T12:10:32.036+09:00  INFO 6784 --- [slip-service] [           main] c.s.logis.slip.SlipServiceApplication    : No active profile set, falling back to 1 default profile: "default"
2026-08-02T12:10:37.688+09:00  INFO 6784 --- [slip-service] [           main] com.zaxxer.hikari.pool.HikariPool        : HikariPool-1 - Added connection conn0: url=jdbc:h2:mem:slip_ops user=SA
2026-08-02T12:10:49.278+09:00  INFO 6784 --- [slip-service] [           main] c.s.logis.slip.SlipServiceApplication    : Started SlipServiceApplication in 19.375 seconds (process running for 20.016)
T1035_RUNTIME_PROCESSES_AFTER_OPS=0
```

- 판정: **PASS**. 운영(default) 설정에서 env를 주면 정상 기동에 도달했다.
- 외부 호출 관찰: 창고 서비스를 띄우지 않았고 `WarehouseInternalClient` 로그는 0줄이었다. 정적 호출부 0곳과 함께 기동 시 외부 창고 호출 0건으로 판정한다.
- 영향 범위: 운영 설정 바인딩 및 기동 경로. 운영 DB 자체의 연결·migration은 안전 제한으로 보지 않았다.
