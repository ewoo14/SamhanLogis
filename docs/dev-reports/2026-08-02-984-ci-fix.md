# PR #984 CI 실패 수정 보고서

## D. 계보별 보존 조건

| 행의 출처 | 품목명 변경 시 | 코드(product_code/model_code) |
|---|---|---|
| 이카운트 직접 생성(ECOUNT) | 따라간다 | CSV 품목코드로 갱신한다. 다만 다른 활성 행이 이미 같은 코드를 사용하면 그 충돌 행을 덮어쓰지 않고 기존 코드 행을 유지하여 `409`를 피한다. |
| 시트 계보 기존 행(SHEET) | 시트 정본을 보존한다 | 기존 `product_code`/`model_code`를 보존한다. 충돌이 없을 때만 이카운트 코드로 채운다. |

근거: ECOUNT 직접 생성 행은 재임포트의 `name`과 품목 메타데이터를 이카운트 CSV 정본으로 갱신해야 한다(A). 반면 SHEET 행은 시트 정본 행을 유실하지 않고 이카운트 데이터를 메타/단가로 병합해야 한다(B). 따라서 기존 `model_name` 병합 SQL은 `lineage = 'SHEET'`인 경우에만 적용해야 하며, 이 조건이 없으면 ECOUNT 행도 병합 경로로 흘러 `name` 갱신을 막는다. 코드 충돌 시에는 조건부 코드 보존을 SHEET 경로에만 남겨 `409`를 방지한다(C).

## 원인과 수정

`UPDATE_ACTIVE_MODEL_NAME_SQL`이 모든 활성 `model_name` 일치 행을 병합 대상으로 삼고 있어, 신규 ECOUNT 행의 재임포트도 해당 SQL에서 종료됐다. 이 경로는 `name`을 갱신하지 않으므로 `변경 품목`이 저장되지 않았다.

병합 SQL의 대상 조건에 `p.lineage = 'SHEET'`를 추가했다. 따라서 ECOUNT 행은 기존 `product_code` upsert 경로로 돌아가 품목명과 메타데이터를 따라가고, SHEET 행만 기존 코드 보존/조건부 코드 채움 병합을 계속한다.
