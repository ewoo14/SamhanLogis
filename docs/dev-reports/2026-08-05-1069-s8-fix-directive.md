# #1069 S8 SOL fix 지시서 — 판매전표 세트 전개

## 판정

**재현 가능한 결함 있음 — 머지 차단.** S6의 “대기 중 부모 규격 삭제 후 과거 규격 부활”은 닫혔다. 그러나 S7 경합 규칙표의 공통 규칙인 “세대가 바뀌면 이전 응답을 버리고 최신 값으로 재전개”가 **실패 응답**에는 구현되어 있지 않다. 전개 대기 중 같은 BUNDLE의 수량·단가·규격·옵션을 바꾸고 이전 요청이 실패하면 최신 값의 전개가 0회가 되고 BUNDLE 부모가 화면에 남는다.

이 트랙은 S3·S5·S7 세 번의 fix 뒤 상한에 도달한 상태에서 새 표면이 나왔다. 네 번째 fix를 바로 진행하지 말고, 아래 결함과 남은 엣지를 개발책임자 판단 대상으로 올려야 한다.

읽기 전용 실 DB 재계수:

- 견적 노출 활성 BUNDLE: `344품목`.
- 활성 `OUTBOUND DRAFT` 중 현재 활성 SINGLE: **`2,107행 / 2,100전표`**, `line_total 2,837,681,781원`.
- 같은 범위의 견적 노출 BUNDLE 라인: **`0행 / 0전표`**.
- 따라서 현재 BUNDLE 가드가 막아서는 안 되는 정상 SINGLE 실데이터 집합은 기준 수치와 일치하고, 기존 BUNDLE 잔존 전표 오차단 표본은 없다.

## ① 좌표

### F1. 중간 변경 뒤 이전 전개가 실패하면 최신 값으로 재전개하지 않는다

- 사용자 변경 세대 증가: `clients/desktop/src/renderer/routes/SlipFormPage.tsx:703-712`
  - 수량·단가·규격·옵션은 모두 `updateLineFromUser`를 거쳐 같은 행의 세대를 증가시킨다.
- 성공 응답: `SlipFormPage.tsx:798-805`
  - 세대가 달라졌고 최신 행이 BUNDLE이면 `expandSelectedBundle(source, latest)`를 재호출한다.
- 실패 응답: `SlipFormPage.tsx:806-812`
  - 최신 BUNDLE·동일 품목이어도 세대가 다르면 `return`만 한다.
  - 성공 분기와 달리 최신 행 재전개가 없다.

협소 재현:

1. 거래처 없이 판매전표의 빈 행에서 BUNDLE을 선택하고 첫 `/slips/expand-line` 응답을 지연한다.
2. 같은 행 수량을 `1 → 3`으로 바꾼다.
3. 첫 전개 요청을 실패시킨다.
4. S7 표대로라면 과거 실패를 폐기하고 `quantity=3`으로 한 번 재전개해야 한다.
5. 실제로는 전개 호출이 과거 `quantity=1` 요청 1회뿐이고, 최신 `quantity=3` 요청은 **0회**다. BUNDLE 부모도 화면에 남는다.

임시 RED 원문:

```text
expected expandBundleLine to be called with quantity: 3
received 1st call quantity: 1
Number of calls: 1
Tests 1 failed | 68 skipped
```

진단 테스트는 실행 직후 원복했고 제품·테스트 파일에는 S8 진단 변경을 남기지 않았다.

## ② 불변식 — 구현 수단 지정 금지

1. 같은 BUNDLE의 전개가 대기 중일 때 수량·단가·규격·옵션이 바뀌면, 이전 요청의 성공/실패와 관계없이 최신 스냅샷이 정확히 한 벌의 구성품으로 수렴해야 한다.
2. 세대가 지난 실패는 최신 BUNDLE 요청의 실패로 취급하면 안 되고, 최신 입력의 재전개를 누락시키거나 BUNDLE 부모를 저장 가능 상태로 남기면 안 된다.
3. 사용자가 일반 SINGLE 또는 다른 품목으로 교체한 경우에는 옛 성공·실패가 새 품목에 귀속되거나 옛 BUNDLE을 재전개하면 안 된다.
4. S6에서 닫힌 부모 규격 삭제, 구성품 자체 규격 우선, 부모 규격 승계와 S2의 BUNDLE 전체수정·모바일 영속 차단을 유지해야 한다.
5. S4에서 닫힌 최근단가 지연 중 최신 수량·직접 단가 반영, 전개 0회 방지와 구성품 한 벌 규약을 유지해야 한다.
6. `#1063` 초기 빈행 5개, 마지막 행 1회 증식, trailing 빈행 1개, 의미 없는 빈행 저장 제외를 유지해야 한다.
7. 정상 OUTBOUND DRAFT SINGLE 2,107행/2,100전표에 해당하는 일반 품목·구성품 경로를 BUNDLE로 오인 차단하면 안 된다.

## ③ 양방향 RED — 반대급부 필수

### RED-B — 재발 금지

- 전개 대기 → 같은 BUNDLE 수량 `1→3` → 이전 요청 실패에서 최신 `quantity=3` 재전개가 0회이거나 BUNDLE 부모가 남으면 RED.
- 위 순서를 직접 단가 입력, 규격 입력/삭제, 옵션 변경 각각으로 바꿨을 때 최신 값 요청이 0회이면 RED.
- 실패 뒤 최신 전개가 성공했는데 구성품이 0벌 또는 2벌 이상이면 RED.
- 과거 실패 안내가 최신 성공 뒤 남거나, 과거 실패가 최신 구성품을 오류행으로 교체하면 RED.

### RED-A — 반대급부 보존

- 중간 변경이 없는 현재 요청의 실패는 BUNDLE 부모를 제거하고 기존 사용자 오류를 계속 표시해야 한다.
- 중간에 일반 SINGLE로 교체한 경우 재전개 호출 0회 적용, 일반 품목 보존이어야 한다.
- 성공 응답 중간 변경 경로의 최신 수량·단가·규격·옵션 재전개와 S6 규격 삭제가 되살아나면 RED.
- 정상 SINGLE 전체수정·모바일 생성이 차단되거나 BUNDLE 전체수정·모바일 생성이 다시 영속되면 RED.
- 전개 전후 `#1063` 빈행 규약과 VAT 포함 금액·구성품 순서가 달라지면 RED.

## ④ 범위 밖·남은 엣지 목록

범위 밖:

- 견적·분개·이동·INBOUND 전체수정, 세트 마스터와 가격 배분 정책.
- 다른 트랙 `#1057`, `#1066`, `#1075`.
- 실제 DB 쓰기를 동반한 PUT/POST, 브라우저·모바일 실기기 라이브QA, 공유 Docker 배포본과 HEAD 동일성 판정.
- 전체 게이트, Docker 재빌드·재배포·중지.

남은 엣지 목록 — fix 상한 판단용:

1. **확정:** 실패 응답과 중간 수량 변경. 협소 RED로 최신 요청 0회 재현.
2. **코드상 동일 도달:** 실패 응답과 중간 직접 단가·규격·옵션 변경. 네 필드가 같은 세대 증가/실패 종료 분기를 공유한다.
3. **별도 RED 미실시:** 짧은 간격의 연속 변경 두 번 이상에서 재귀 재전개가 최종 1벌로 수렴하는지.
4. **별도 RED 미실시:** 성공 응답이 매우 빠를 때 BUNDLE 부모가 즉시 사라져 `BundleOptionRow`의 비기본 옵션을 사용자가 안정적으로 입력할 수 있는지. 옵션 UI는 `productType === 'BUNDLE'`인 동안만 렌더된다(`:1286-1302`).
5. **코드 대조상 보존:** 중간 일반 SINGLE 교체와 다른 품목 선택은 품목/종류 guard가 옛 응답을 폐기한다. 이번 S8에서는 별도 신규 RED를 추가하지 않았다.

증거 무결성 예외:

- S7 보고서의 `## 검증`에는 데스크톱 83/83과 서버 `BUILD SUCCESSFUL` 실행 결과가 기록돼 있으나, 같은 문서의 `## 미검증/잔여 표면`에는 “지시서 ⑤의 전체 좁힌 명령과 서버 검증을 아직 실행하지 않았다”고 적혀 있어 상호 모순이다.
- S8에서 같은 좁은 명령을 새로 실행해 데스크톱 83/83, 서버 `BUILD SUCCESSFUL`을 확인했지만, 이 결과는 위 신규 실패 조합을 포함하지 않으므로 결함을 닫지 않는다.
