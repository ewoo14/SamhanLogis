# #1161 S2a fix4 — partner-auth 공개 라우트 IP 배선

## RED — 실제 라우트 증상 재현

### 확인한 원인

`ForwardedClientIpGatewayFilterFactory`는 정상적인 ingress peer에서 `X-Real-IP`/`X-Forwarded-For`를 읽어 `X-Audit-Client-IP`로 덮어쓰는 로직과, 비신뢰 peer에서 peer 주소만 쓰는 로직을 이미 갖고 있었다. 그러나 `services/api-gateway/src/main/resources/application.yml`의 실제 `partner-auth-public-v1` 라우트에는 `StripInboundIdentityHeaders`만 선언되어 있었다. 따라서 필터 로직 결함이 아니라 공개 라우트 배선 누락이 원인인지 검증하기 위해 라우트 계약 RED를 추가했다.

두 실패 모두 `partner-auth-public-v1` 라우트 블록에 `name: ForwardedClientIp`가 없어서 발생했다. 기존 라우트 계약 테스트 1건은 통과했다.

## GREEN — 실제 라우트 배선

`partner-auth-public-v1`에 다음 순서로 필터를 배선했다.

```yaml
filters:
  - StripInboundIdentityHeaders
  - name: ForwardedClientIp
    args:
      trustedPeerAddresses: ${SAMHAN_AUDIT_TRUSTED_INGRESS_ADDRESSES:private}
```

첫 필터가 외부 identity 헤더를 제거하고, 둘째 필터가 TCP peer가 신뢰된 ingress일 때만 `X-Real-IP`/`X-Forwarded-For`에서 IP를 복원하여 `X-Audit-Client-IP`를 새로 설정한다. 신뢰되지 않은 peer는 peer 주소만 사용한다.

## 불변식 판정

- 정상 게이트웨이 경로: 신뢰된 ingress의 실제 IP를 `X-Audit-Client-IP`로 전달하도록 실제 공개 라우트에 배선됨.
- 위조 경로: 외부 `X-Audit-Client-IP`는 먼저 제거되고, `ForwardedClientIp`가 계산한 값으로만 대체됨. 비신뢰 peer는 전달 헤더를 사용하지 않음.
- `X-Forwarded-For`/`X-Real-IP`는 새 신뢰 헤더로 추가하지 않았고, 기존 gateway 내부 계산에만 사용함.
