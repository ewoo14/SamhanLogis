# 2026-08-01 1009 wiring fix

## 확인 1 — 작업 범위와 설계

- 대상 화면: `clients/web/estimate-app/views/index.ejs`
- CSP는 `script-src-attr 'none'`을 유지해야 하며, 저장/내역을 포함한 inline 이벤트 배선을 DOM 이벤트 리스너로 이전한다.
- RED 테스트를 먼저 실행해 실제 클릭이 핸들러를 호출하지 않는 현상을 고정한 뒤 최소 수정한다.

## 확인 2 — inline 이벤트 전수

`views/index.ejs` 원문 기준 inline 이벤트 속성은 총 **128개**다.

| 속성 | 개수 |
|---|---:|
| `onclick` | 80 |
| `onchange` | 17 |
| `oninput` | 9 |
| `onfocus` | 21 |
| `onkeydown` | 1 |
| 합계 | **128** |

`onblur`, `onkeyup`, `onsubmit`은 0개였다. CSP에서는 위 128개 속성 모두 속성 자체의 실행이 차단된다. `btnHistory`는 inline 속성 없이 기존 `addEventListener('click', ...)` 방식으로 살아 있는 별도 버튼이므로 보존한다. 동적 행/목록도 동일한 배선 방식으로 처리해 새로 생성되는 버튼까지 누락되지 않게 한다.

## RED — 수정 전 실패 원문

이 실패는 저장 버튼의 inline `onclick`이 아직 남아 있어 CSP에서 실제 클릭 배선이 끊긴 상태를 재현한다.

저장/내역 버튼은 명시적인 `addEventListener('click', ...)`로 연결했고, 나머지 동적 inline 이벤트는 DOM 리스너로 이관하는 CSP 배선기가 생성 시점에 처리한다. CSP 헤더는 수정하지 않았다.

## 라이브 Playwright 실제 클릭 검증

`node scripts/qa-1009-csp.mjs` 원문 요약:

```text
CSP 헤더 = ...;script-src-attr 'none';...
버튼 = {"saveAttr":null,"loadAttr":null,"hasSaveFn":"function","hasGoFn":"function"}
클릭 후 호출된 함수 = ["handleSaveSnapshot"]
CSP 위반 = 0
직접 호출 = ok
```

실제 `page.click()` 보조 검증은 저장/조회 RPC를 Playwright route에서 abort하여 실 DB 쓰기를 막고 실행했다.

```text
saveRequests:
POST http://localhost:5183/rpc/saveQuoteSnapshot

loadRequests:
POST http://localhost:5183/rpc/logFrontEvent
POST http://localhost:5183/rpc/getQuoteHistory

quantity: "2"
homeBodyVisible: true
inlineAttributesAfterLoad: 0
CSP: ...;script-src-attr 'none';...
```

이는 `evaluate` 직접 함수 호출이 아니라 승인 계정 URL에서 `page.click('#btnSaveSnapshot')`, `page.click('#btnLoadSnapshot')`로 확인한 결과다. 저장 요청은 실제 서버로 전달하지 않고 route abort하여 DB 쓰기는 발생하지 않았다.
