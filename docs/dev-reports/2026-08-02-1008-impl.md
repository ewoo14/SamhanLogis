## 불변식 검증 및 적용 규칙

### A. 옵션 정액 DC 6종

엔진 입력·선택 필드는 다음 6종이다.

`discount_360_amount`, `discount_4way_amount`, `discount_1way_amount`, `discount_stand_amount`, `discount_deluxe_amount`, `discount_first_grade_amount`

숫자 원문(360 옵션 정액 2,000원 예시):

```text
적용 전 기대 납품금액: 70,000원
옵션 정액 DC:           2,000원
적용 후 기대금액:       68,000원
실제 전표 유효단가:     68,000원
기존 discountAmount:   30,000원
적용 후 discountAmount: 32,000원
판정:                   verified=true
```

### B. 적용 순서

1. 품목의 `products.fixed_discount_rate`가 있으면 고정DC율을 선택한다(`fixedDc ?? globalRate`).
2. 고정DC율이 없을 때만 거래처코드의 `dc_configs` 전역DC율(홈/상업)을 선택한다.
3. 싱글 세트 판정 시 세트코드에 대응하는 옵션 정액 1종을 기대 납품금액에서 차감한다.
4. 전표 실 유효단가와 차감 후 기대금액을 비교한다.

고정DC율/전역DC율 우선순위는 기존 엔진을 재사용했으며 새 우선순위를 만들지 않았다.

### C. 옵션 정액이 없는 거래처

옵션 6종이 모두 null이면 선택 정액은 null이고 기존 기대금액(`납품가`)을 그대로 사용한다. 테스트 원문은 옵션 미보유 경로에서 `discountAmount=50,000`, `verified=true`로 기존 결과를 유지했다. 실 DB read-only 집계 기준 영향 거래처는 46곳, 비보유 거래처는 `210 - 46 = 164곳`이다.

### D. 결과가 바뀌는 경우와 바뀌지 않는 경우

- 바뀜: 옵션 정액이 설정된 거래처의 싱글 세트 중 해당 세트코드(360/4way/1way/스탠드/디럭스/1등급)에 매칭되는 세트. 기대금액과 `discountAmount`가 정액만큼 달라진다.
- 유지: 옵션 정액이 없는 164곳의 모든 결과.
- 유지: 옵션 정액이 설정돼도 해당하지 않는 세트코드, 멀티, 구형 50%, 액세서리, 운임·절삭, 기타 default 분기.
- 유지: 저장된 일마감 원천 금액과 `totalAmount` 계약 필드. 이번 변경은 read-time 재검증 출력만 변경한다.

### E/F

금액 계약 필드와 일마감 snapshot 저장 로직은 건드리지 않았다. 기존 화면/API 계약과 고정DC 우선 동작을 유지했다.
