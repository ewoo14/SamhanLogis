## ② 품목 응답 DTO 전수표

이번 검색/품목 마스터 계열에서 Product를 직접 응답하는 DTO를 전수 확인했다. `ProductByCodeResponse`는 의도적으로 id/modelCode/name만 반환하는 alias 경량 DTO이며, 품목 상태·가격 소비자가 없어 goodsType 대상이 아니다.

| DTO | endpoint | goodsType 포함 | 소비자 |
|---|---|---:|---|
| `ProductSummaryResponse` | `GET /products`, `POST /products/lookup`, `ProductInternalController`의 lookup 계열 | 예 — `@JsonProperty("goodsType")` accessor + `usageScope`, `estimateCategories`, `productCategory` | desktop `productApi.searchProducts`, 견적 품목 검색, Slip/Estimate 내부 lookup, inventory/slip client |
| `ProductCatalogResponse` | `GET /api/v1/products` 및 catalog mutation 응답 | 예 — record component | `EstimateItemsCatalogPage`, `ProductCatalogPage` |
| `ProductResponse` | `GET /products/{id}`, `/products/by-model/{modelName}`, create/update/price/tags 응답 | 예 — record component | `ProductFormPage`, 모델명 정확 조회 소비자 |
| `ProductByCodeResponse` | `GET /products/by-code/{code}` | 아니오 — 의도된 alias 식별자 전용 응답 | code alias 해소 소비자; goodsType/가격/노출 범위 소비 없음 |

`ProductSummaryResponse`의 검색 경로는 페이지 내 product ID를 모아 `ProductEstimateExposureRepository.findByProductIdInAndIsDeletedFalse` 한 번으로 노출 카테고리를 벌크 조회한 뒤 DTO에 주입한다: `services/product-service/src/main/java/com/samhanair/logis/product/service/ProductService.java:127-139`.

### DTO별 직렬화 mutation RED 가드

- `services/product-service/src/test/java/com/samhanair/logis/product/web/dto/ProductSummaryResponseTest.java:59-84`: NON_GOODS, usageScope, 두 estimateCategories, productCategory의 JSON wire 계약.
- `services/product-service/src/test/java/com/samhanair/logis/product/web/dto/ProductResponseGoodsTypeSerializationTest.java:15-31`: `ProductSummaryResponse`, `ProductCatalogResponse`, `ProductResponse` 각각을 reflection으로 생성해 `goodsType=NON_GOODS` 직렬화를 단정한다. 세 DTO 중 goodsType record component가 없어도(요약 DTO의 accessor 방식) JSON field가 없어지면 RED다.
