## 1단계 — RED 재현

`sol1176-pg`의 격리 DB를 `pg_dump -Fc -f` 파일로 덤프한 뒤 `qa1176-fix1-pg`의 별도 `partner_db`, `slip_db`에 `pg_restore`했다. PowerShell 파이프는 사용하지 않았다.

복제 전 표지 확인 SQL:

```sql

WHERE deleted_by='qa-residue-softdelete-2026-08-12' GROUP BY 1,2;
```


```sql
SELECT 'slips',deleted_by,is_deleted,COUNT(*) FROM slips
WHERE deleted_by='qa-residue-softdelete-2026-08-12' GROUP BY 2,3
UNION ALL
SELECT 'lines',deleted_by,is_deleted,COUNT(*) FROM slip_lines
```

판정: `partner_db`에는 `partners`만 있고 `slips`, `slip_lines`는 없다. 오류가 난 동일 트랜잭션에서 partner 복구도 커밋되지 않았다. RED 재현 완료.

## 2단계 — 수정

되돌림 SQL을 두 독립 DB 블록으로 분리했다.

```sql
\connect partner_db
BEGIN;
CREATE TEMP TABLE qa_partner_rollback_targets ON COMMIT DROP AS
SELECT id FROM partners
WHERE is_deleted
  AND deleted_by = 'qa-residue-softdelete-2026-08-12';
SELECT COUNT(*) = 1000 AS partner_before_ok
FROM qa_partner_rollback_targets
\gset
```

```sql
\connect slip_db
BEGIN;
CREATE TEMP TABLE qa_slip_rollback_targets ON COMMIT DROP AS
SELECT id FROM slips
WHERE is_deleted
  AND deleted_by = 'qa-residue-softdelete-2026-08-12';
CREATE TEMP TABLE qa_line_rollback_targets ON COMMIT DROP AS
SELECT id FROM slip_lines
WHERE is_deleted
  AND deleted_by = 'qa-residue-softdelete-2026-08-12';
SELECT (SELECT COUNT(*) FROM qa_slip_rollback_targets) = 295
   AND (SELECT COUNT(*) FROM qa_line_rollback_targets) = 636 AS slip_before_ok
\gset
```

각 UPDATE는 임시 대상 ID와 복구 표지에 동시에 매칭하며, 사전·사후 건수 불일치 시 `ROLLBACK`한다. 가드 실패가 종료 코드 0으로 오인되지 않도록 `ROLLBACK` 뒤 `SELECT 1 / 0 AS rollback_guard_failure`를 사용했다.

## 4단계 — 건수 가드 RED 재검증

GREEN 직후 동일 스크립트를 다시 실행했다.

원문 출력:

```text
You are now connected to database "partner_db" as user "samhan".
BEGIN
SELECT 0
예상치 불일치: partner_db 복구 표지가 1,000행이 아니므로 롤백합니다.
ROLLBACK
psql:/tmp/rollback-fixed.sql:34: ERROR:  division by zero
```

프로세스 종료 코드는 `1`이며, partner 표지와 slip 표지는 각각 `0`건으로 유지됐다. 대상 표지가 없는 상태에서 임의 행을 변경하지 않았다.

## 5단계 — UTF-8 검증

복제는 파일 dump/restore로 수행했다. 원본 QA 데이터의 일부 한글 필드는 복제 전 원본 `sol1176-pg` 자체에 이미 `?` 바이트로 저장돼 있었다. 원본과 복제의 해당 필드 UTF-8 base64가 동일하여 복제 단계에서 추가 변환은 없었다.

복제 DB에서 UTF-8 바이트를 직접 SELECT한 검증 SQL:

```sql
SELECT convert_from(decode('ec9b90ebacb820ed959ceab880','hex'),'UTF8') AS original_text
```

원문 출력:

```text

---------------
 원문 한글
(1 row)
```
