# PR #1154 R17 — 거래처 상호 입력 충실도

## 판정

결함 ④·⑤를 수정했다. CSV는 UTF-8 strict 판별 후 MS949(CP949) strict fallback을 사용하고, 판별 실패 파일·U+FFFD 상호는 `CSV_ENCODING` 보류 채널로 보낸다. OpenCSV escape는 비활성화했다. XLSX 파서는 변경하지 않았다.

커밋·push는 하지 않았다.

## 원인 `파일:줄`

- 결함 ④ 원인: `services/partner-service/src/main/java/com/samhanair/logis/partner/service/EcountPartnerImporter.java:161-165` (R15 기준) — `InputStreamReader(...UTF_8)` 기본 decoder가 malformed byte를 U+FFFD로 치환했다.
- 결함 ⑤ 원인: 같은 파일 `:161-165` (R15 기준) — `new CSVReader(br)`가 OpenCSV 기본 escape `\`를 사용해 quoted field의 역슬래시를 소비했다.
- R17 수정 경로: `:154-160` strict decode, `:173-178` parser 설정, `:207-212` U+FFFD 행 보류, `:301-334` 인코딩 판별·파일 보류.

판별 근거는 먼저 UTF-8 decoder를 `REPORT` 모드로 실행하고, 실패한 경우에만 MS949 decoder를 `REPORT` 모드로 실행하는 것이다. MS949 후보의 이카운트 헤더가 복원되지 않으면 혼합/훼손 파일로 판정해 보류한다. 따라서 R15의 “UTF-8 파일 일부에 CP949 바이트 삽입”도 MS949 전체 fallback으로 오염되지 않는다.

| 파일 형식 | 정상 상호 | 괄호·쉼표·정방향 `/` | 역슬래시 `\` | 빈값 |

| XLSX 정본 | 기존 POI 경로 유지, 7,253건 회귀 통과 | XLSX 파서 영향 없음 | XLSX 파서 영향 없음 | 기존 빈값 분류 유지 |
| CSV UTF-8 | 통과 | 보존 | 보존 | `REJECT_NAME_NULL` 유지 |
