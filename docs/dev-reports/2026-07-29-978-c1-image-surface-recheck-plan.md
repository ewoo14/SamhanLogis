# #978 C-1 문서 양식 이미지 — 다섯 번째 표면 적대검증 (조기 PR)

> 연관 Issue: #978 (항목 C-1)

## 왜 하는가

#965 → PR #968 (main `f2f4c7b7c`) 로 문서 양식 이미지의 **디코드 가능성 계약**이 머지됐다. 이 트랙에는 특이한 이력이 있다.

> **fix 가 4회 연속으로 새 표면을 만들었고, 마지막 fix 이후 SOL 재검증이 실시되지 않았다.**

실제로 이 트랙의 fix 하나는 **애니메이션 WebP 를 거부하는 회귀**를 만들었다 — 저장소 마스코트 자산이 그 형식이었고, fix 전에는 201 로 통과하던 것이다. **다섯 번째 표면이 있을 확률이 낮지 않다.**

## 이 라운드가 답할 단 하나의 질문

> **문서 양식 이미지 처리에서, 실 사용자 경로로 재현 가능한 결함이 있는가?**

심각도는 묻지 않는다. 도달 가능하면 보고하고, 도달 불가능하면 보고하지 않는다.
🚫 **검증 품질은 찾지도 보고하지도 않는다** — 테스트가 약하다·문서가 과장됐다 류는 대상이 아니다.

## 보는 표면

`clients/desktop/src/renderer/print/**` · `clients/desktop/src/renderer/components/documentTemplate/**`
(특히 `DocumentRenderer.tsx`, `templateSchema.ts`, `ElementInspector.tsx`)

물을 것:

1. **실 사용자가 실제로 올리는 형식**이 거부되지 않는가 — 애니메이션 WebP 처럼
2. 거부될 때 **사용자가 이유와 다음 행동을 알 수 있는가**, 아니면 조용히 실패하는가
3. 디코드 예산·크기 한계가 **실 자산에서 걸리지 않는가**
4. **인쇄 경로와 편집 경로가 같은 판정을 하는가** — 한쪽만 통과하면 사용자는 편집에서 되던 것이 인쇄에서 사라지는 것을 본다

## 🚨 회귀 판정은 실재 자산으로

합성 이미지를 지어내지 않는다. **`git ls-files` 로 저장소에 실재하는 이미지 자산을 찾아** 그것으로 판정한다. 합성으로 세운 울타리가 실 자산 형식을 놓친 실측 전례가 바로 마스코트 WebP 건이다.
