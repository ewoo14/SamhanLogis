# PR #1130 (#1064) R3 SOL 적대 재수렴 — 도달성

## 판정

```text
도달 가능한 결함: 1건
머지 불가
```

결함은 **`inbound.inspection` 계약이 11개 역할 전부를 7비트 exact로 감시하지 않는 것**이다. 현재 테스트는 MASTER를 제외한 10역할만 검사한다. 실 `auth_db` role template의 MASTER는 `1111000`인데 mock `/permissions/my`는 system-master bypass로 `1111111`을 반환한다. MASTER를 기대표에 넣으면 즉시 RED지만, 현재 테스트는 이 불일치를 green으로 통과시킨다.

실 사용자/QA 경로는 `MASTER mock GUI 부팅 → GET /auth/admin/permissions/my → inbound.inspection 권한 도출`이다. canonical role template에는 없는 RESTORE/DOWNLOAD/PRINT가 mock 응답에 존재한다. 현재 입고 lifecycle 완료는 UPDATE만 소비하므로 MANAGER 정상 경로 자체를 깨는 생산 결함은 재현하지 않았지만, 개발책임자가 요구한 11역할 exact 계약과 mock 기반 GUI QA의 권한 모델은 불일치한다.

### 2.3 MASTER 감시 공백

MASTER의 mock PRINT만 임시 제거했을 때 기존 계약 테스트는 그대로 1/1 green이었다. 테스트의 `expectedBits`에 실 DB 값 `MASTER: '1111000'`을 임시 추가하면 현재 HEAD 자체가 다음처럼 RED였다.

```text

Test Files  1 failed (1)
Tests       1 failed (1)

```

따라서 “7비트 exact × 11역할”은 아니다. 파일의 테스트명도 `every non-MASTER role`이고 기대표는 10행이다. 두 임시 변경은 모두 역패치했다.

## 3. V98 범위와 실 auth_db 전수 대조

측정 시각: **2026-08-09 09:04:48 KST**. 공유 `auth_db`에는 쓰지 않았다.

현재 실 DB에서 V98 조건에 맞는 표적 수는 다음과 같다.

V98 SQL은 세 UPDATE 모두 `MANAGER` 또는 MANAGER 기본 그룹, `page_code='inbound.inspection'`, `can_update=false`로 한정하고 SET 절도 `can_update`와 audit 필드뿐이다. INSERT도 활성 MANAGER 중 해당 캐시가 없는 계정만, MANAGER template의 현재 7비트를 복제한다. #1145 V97처럼 모든 역할을 복사하는 형태가 아니다. **V98 자체의 확장 결함은 발견하지 않았다.**

다만 실 DB의 `modified_by='v98-manager-inbound-inspection'`는 role/group/account 모두 0행이고 Flyway V98도 0행이다. 실제 적용 후 상태를 관측한 것이 아니라, 실 pre-state에 V98 조건을 SELECT로 투영한 결과다.

## 4. MANAGER 완료 도달성과 차단 역할

검수 완료 GUI/서버 계약은 INBOUND `INSPECTING → COMPLETED`에 다음 두 권한을 동시에 요구한다.

```text
slip.transfer.process:UPDATE
inbound.inspection:UPDATE
```

실 계정 캐시 집계:

| 역할 그룹 | 활성 계정 | 두 권한 모두 보유 |
|---|---:|---:|
| MANAGER | 3 | 0 (V98 미적용) |
| WAREHOUSE | 1 | 1 |
| INVENTORY | 1 | 1 |
| SALES | 10 | 0 |
| ACCOUNTANT | 7 | 0 |
| DISPATCH | 1 | 0 |
| DRIVER | 2 | 0 |
| STAFF | 2 | 0 |
| DEVELOPER | 2 | 0 |

MANAGER 세 계정은 모두 `slip.transfer.process:UPDATE`를 가지고 `inbound.inspection:UPDATE`만 없다. V98 투영 후에는 세 계정 모두 두 권한을 충족하고, 다른 역할의 권한은 변하지 않는다. 현재 실 환경의 MANAGER 차단 3건은 **V98 미적용 환경 차이**이며 V98 SQL 범위 결함으로 세지 않았다.

## 5. 발화 조건과 원 결함

## 7. #1145 checker와 형태 차이

#1145의 `permission-contract-checker.ts`는 다음을 검사한다.

- 역할 카탈로그 11개 exact 대칭
- page-code 카탈로그 122개 exact 대칭
- 11역할 × 122 page code × 7비트 전체 곱
- DB snapshot과 mock account endpoint 비교
- 누락 셀과 frozen divergence 집합까지 검증

이번 `inbound-permission-contract.test.ts`는 다음 형태다.

- 하드코딩한 non-MASTER 10역할
- `inbound.inspection` 한 page code만 검사
- DB snapshot import 없이 기대 비트 문자열을 테스트 안에 직접 기입
- `/permissions/my`를 사용해 MASTER system bypass 때문에 11번째 역할을 넣지 못함
- 역할/page 카탈로그 대칭 검사가 없음

요청대로 통합 수정은 하지 않았지만, 나중에 #1145 checker와 합칠 때 단순 병합으로 수렴하지 않는 구조 차이다.
