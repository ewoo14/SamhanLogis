## 2026-08-03 R14 보완 — ③ 테스트 계약 정렬

③의 최종 정본 page code가 `notification.dispatch-sms.send-audit`이므로 desktop mock에는 이 문자열이 권한 식별자로 남는다. 기존 계약 테스트가 문자열 전체 `send-audit`를 금지해 canonical 권한 등록 자체를 RED로 만들었으므로, 금지 대상을 발송 감사 모드(`SEND_AUDIT`)·생성 endpoint(`/send-audit`) 잔재로 좁혔다. 이는 권한 판정 경로를 되돌린 것이 아니며, canonical 권한 식별자는 허용하는 테스트 계약 수정이다.

```text

Test Files 3 passed (3)
Tests      9 passed (9)
```

추가로 desktop 전체 테스트에서 새로 추가한 전표 fixture의 seq 선행 0(`2026/08/03-001`, `-002`)이 기존 문서번호 계약을 RED로 만들었다. 전표번호 자체는 UUID가 아닌 사용자 노출 business code이므로 저장소 표준(`...-1`, `...-2`)으로 fixture만 고쳤다.

## 최종 판정 — 이 블록이 앞선 초안 기록보다 우선한다

- ③ 최종 fix는 V93 전역 삭제가 아니다. 앞서 기록한 V93 초안은 폐기했고 파일도 남기지 않았다. V92 migration/checksum은 수정하지 않았다.
- 최종 소비 page code는 `notification.dispatch-sms.send-audit` 하나다. 메뉴 1곳, route guard 1곳, 미리보기 API 1곳, 저장내역 API 4곳(저장 1 + 목록/상세/latest 3)을 모두 이 코드로 판정한다.
- V92 회수 계정의 실제 HTTP 권한 check는 `allowed=false`, 격리 Testcontainers에서 새 canonical grant를 가진 계정은 `allowed=true`였다. `dispatch.board` 활성 role grant도 남았다. 따라서 회수 계정 차단·정상 권한 보존 양쪽을 확인했다.
- ① 전표별 key는 `slipNo`이며, 코멘트 편집·checkbox·복사 모두 같은 key를 쓴다. ② 미매핑 전표 각 행은 `[미매핑]`을 표시한다.
- 로컬 변경 기준 auth-service/notification-service 전체 테스트와 `npm run typecheck`는 GREEN이다. desktop 전체는 R14 관련 197개 파일/1746개 테스트가 통과했고, 기존 H-2 하네스 테스트 1건만 실패했다. R14 변경 관련 4개 파일 138개 테스트는 GREEN이다.
- 배포 컨테이너는 이전 빌드이므로 화면에서의 사후 GREEN은 주장하지 않는다. PM 배포 후 시나리오 7을 재실행해야 한다.
