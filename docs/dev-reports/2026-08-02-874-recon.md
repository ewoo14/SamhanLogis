# S1.5 세트 riUsage · 거래처 전역DC 반영 — 정찰

조기 PR 개설용 자리표시. Codex 정찰 결과를 이 파일에 누적한다.

- `riUsage`의 `ri`는 실내기나 사용량이 아니라 원본 전표 행의 row index이며, `riUsage`는 한 전표 안에서 수량 단위로 펼친 세트 후보가 원본 행별로 모두 소비됐는지 `total/used`로 집계하는 레거시 런타임 맵이다 (`tools/legacy-gas/일마감 프로그램/Code.js:661-710`).
- 세트 품목은 `product_db.products`의 `product_type='BUNDLE'` 및 `bundle_mode` 컬럼에 저장되고, 구성품 연결은 `product_db.bundle_component`의 `bundle_product_id`(부모 품목 연결)·`component_product_code`(구성품 모델코드)와 수량/종류 속성 컬럼에 저장된다 (`V3__migration_extension.sql:77-102`, `BundleComponent.java`).
- 실 DB `product_db` 읽기 전용 집계 결과 세트 품목은 활성 344건(삭제 포함 물리 행 345건)이다.
- 실 DB `product_db` 읽기 전용 집계 결과 구성품 연결은 활성 1,588건이며 삭제 포함 물리 행도 1,588건이다.
- 실 DB `product_db.products.fixed_discount_rate`는 활성 품목 1,220건 중 167건이 채워져 있고, 삭제 포함 전체 1,226건 기준으로도 채워진 행은 167건이다.
- 운영 코드에서 `dc_configs`를 직접 조회하는 repository 호출점은 총 8곳이다: 가격 계산용 거래처코드 조회, 전체 prefetch, 단건 강제 조회, 거래처코드 통합 조회, 사업자번호 통합 조회, 수정 전 조회, import upsert 전 존재 조회, 영업 DC설정 목록 검색 (`DcConfigService` 6곳·`DcConfigImportService` 1곳·`PartnerDcConfigsController` 1곳).
- `products.fixed_discount_rate`를 엔티티 getter로 직접 읽는 운영 코드 호출점은 총 8곳이다: seeder native 적재 1, 시트 sync 수동값 보존 1, internal 단건·벌크 조회 2, 견적 카탈로그 projection 1, 일반 카탈로그/상세/요약 projection 3 (`product-service`의 `getFixedDiscountRate()` 호출 기준).
- 고정DC의 다운스트림 가격 판정 소비자는 2개 업무 경로다: `partner-order-service` 주문 확정과 `accounting-service` 일마감 재검증이며, 둘 다 `product-service`가 읽어 준 값을 사용한다.
- `fixedDc ?? globalRate` 우선순위를 실제로 결정하는 위치는 저장소 전체 총 9곳이다: 현행 6곳(`order-app` 홈·상업 2, `estimate-app` 홈·상업 2, `dc-config-service/PriceCalculationService.pickCategoryRate` 1, `accounting-service/DiscountRevalidator.expectedRate` 1)과 레거시 oracle 3곳(`종합견적서` 홈·상업 2, `일마감 프로그램` 멀티 1); 모두 고정DC가 non-null일 때 전역DC보다 먼저 선택한다.
- “`dc-config-service`에 고정DC 개념이 없다”는 현재 워크트리 기준으로는 사실이 아니다: snake_case `fixed_discount_rate` 직접 DB 조회는 0건이지만 camelCase `fixedDiscountRate`는 `src/main`에 11회 있고, 요청 DTO로 받은 고정DC를 `PriceCalculationService`가 전역DC보다 우선 적용한다.
- `dc_configs`의 실제 다운스트림 호출점은 총 6곳이다: 견적 앱의 전체 prefetch와 사업자번호 단건 조회 2곳, 데스크톱 거래처 DC설정 목록 1곳, 거래처 인증의 사업자번호 조회 1곳, 주문 확정 가격 계산 1곳, 회계 일마감 전역DC 조회 1곳.
- 전역DC는 `dc_config_db.dc_configs`에 활성 거래처당 최대 1행(`partner_id` partial unique)으로 저장되며, 홈·상업 할인율, 옵션 정액 6종, 반올림 단위·방식, 단위처리 여부 및 부가 설정을 보존한다 (`V1__init_dc_config.sql:50-79`, `V2__add_unit_processing_flag.sql`).
- 실 DB `dc_config_db.dc_configs`는 활성 210건이며 삭제 포함 물리 행도 210건이다.
- 현대 운영 코드에는 `riUsage` 필드·맵 구현이 없고, 비문서 실행 소스의 해당 식별자는 `tools/legacy-gas/일마감 프로그램/Code.js` 한 파일에서만 발견된다; 즉 세트 저장 구조는 존재하지만 원본 전표 행별 완전소비 판정은 아직 레거시 oracle에만 있다.
