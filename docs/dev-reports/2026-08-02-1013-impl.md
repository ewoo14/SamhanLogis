# #1013 — 배차문자 발송 모집단 불일치 구현

## 1. RED — 모집단 불일치 재현

`clients/desktop/src/renderer/routes/DispatchSmsPage.test.ts`에 매핑 1건, 인수자 번호가 있는 미매핑 1건, 번호가 없는 미매핑 1건을 구성했다. 기대값은 화면 건수와 실제 요청의 partnerCode 집합이 `P-FALLBACK` 하나로 동일한 것이다.

실행 원문:

```text
> @samhan/desktop@0.1.0 pretest
> node scripts/real-qa-scope.cjs --phase=test

[로컬 파생물 신선도 확인 실패]
- electron-updater가 설치된 node_modules에 없습니다.
- file: 의존 design-system dist이(가) 없습니다.
- Electron main 빌드 산출물 out/main/index.js이(가) 없습니다.
```

위 pretest 가드가 의존 산출물 부재로 중단되어 Vitest를 직접 실행했다.

```text
npx vitest run src/renderer/routes/DispatchSmsPage.test.ts

Startup Error: Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'vitest'
```

테스트는 현재 export 되지 않은 `countSendableEntries`를 요구하므로, 의존성 복구 후에는 수정 전 구현에서 컴파일/테스트 실패가 발생하는 RED 계약이다.

## 2. A 방향 및 근거

`미매핑 + 인수자 번호 보유` 집단을 실제 SMS 요청 집단으로 유지하고, 화면 건수도 이 집단을 세도록 선택했다. 단톡방 매핑 건은 현재 직접 전송 API가 없어 기존처럼 수동 복사 전달 대상이며, 미매핑 건의 인수자 번호 fallback은 레거시 배차안내문자의 의도된 fallback 동작이다. 따라서 보내는 쪽을 매핑 건에 맞춰 제거하면 업무상 의도된 인수자 번호 안내를 잃게 되며, 화면이 실제 SMS fallback 집단을 표시하는 것이 옳다.

## 3. 구현

- `buildSendEntries`와 `countSendableEntries`가 동일한 `unmapped` + 유효한 `recipientPhone` 조건을 사용하도록 고쳤다.
- 미매핑 목록 문구를 전표 기준으로 명확히 하고, 인수자 번호 보유 전표가 SMS 대상임을 표시했다.
- 발송 결과 상세를 성공/실패와 무관하게 펼쳐서 실제 요청 대상과 상태를 화면에서 확인할 수 있게 했다.

## 4. 검증

숫자 검증 fixture: 화면 건수 `N=1` · 실제 `entries` 요청 `N=1` · 대상 partnerCode 집합 동일(`[P-FALLBACK]`). 매핑 전표와 번호 없는 미매핑 전표는 두 집합에서 모두 제외된다.

관련 notification-service 테스트 실행:

```text
> Task :services:notification-service:test

BUILD SUCCESSFUL in 17s
18 actionable tasks: 1 executed, 17 up-to-date
```

실행 대상은 `DispatchBatchPreviewServiceTest`, `DispatchBatchSendServiceTest`다.

```text
> @samhan/desktop@0.1.0 typecheck
> node scripts/real-qa-scope.cjs --phase=typecheck && tsc -p tsconfig.node.json --noEmit && tsc -p tsconfig.web.json --noEmit && npm run typecheck:real-qa

[로컬 파생물 신선도 확인 실패]
- electron-updater가 설치된 node_modules에 없습니다. clients/desktop에서 npm ci 를 먼저 실행하십시오.
- file: 의존 design-system dist이(가) 없습니다: ..\\web\\design-system\\dist\\index.d.ts. cd ..\\web\\design-system; npm run build
```

타입체크는 저장소 코드 오류가 아니라 사전 가드의 로컬 파생물 부재로 `tsc` 전에 종료됐다.

## 5. 불변식 재확인

- A: 화면 건수와 실제 요청은 동일한 `unmapped` + `recipientPhone` 보유 전표 집합을 사용한다.
- B: 미리보기 미매핑 전표 목록과 발송 결과 상세/발송 감사 이력에서 대상과 상태를 확인할 수 있다.
- C/D: 알리고 실연결을 추가하지 않았고, placeholder는 기존 `FAILED` 집계 경로를 유지한다.
- E: `room:` 수신번호를 만들거나 보내는 FE 경로를 추가하지 않았으며 서버의 방어적 `FAILED` 차단도 유지된다.
- F: 단톡방 매핑 건의 기존 수동 복사 경로와 기존 화면 흐름은 유지된다.
