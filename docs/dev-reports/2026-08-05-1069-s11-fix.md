# #1069 S11 fix 보고서 — 판매전표 세트 옵션 전개

## 결론

S10 지시서의 결함을 수정했다. 빠른 첫 세트 전개 응답 뒤에도 옵션 입력면을 구성품 행에 임시 계승하고, 사용자가 옵션을 확정하면 최신 옵션·수량·단가·규격으로 다시 전개한다. 최종 성공 응답에서는 옵션 컨텍스트가 제거되어 저장 payload에 BUNDLE 부모가 남지 않는다.

## RED-first 증거

지시서의 협소 RED를 먼저 추가하고 실행했다.

```text
FAIL  SlipFormPage 이카운트식 라인 입력 > 빠른 전개 성공 뒤에도 옵션을 확정하면 최신 옵션 한 벌로 다시 전개한다
Unable to find an element by: [data-testid="bundle-option-change"]
Tests 1 failed | 72 passed (73 total)
```

추가로 빠른 첫 성공 뒤 옵션 연속 변경 RED를 고정했다. 첫 구현에서는 대기 중 요청과 세대 재시도가 중복되어 3회가 기대되는데 4회 호출되는 실패를 확인했고, 대기 컨텍스트의 요청을 한 번으로 수렴하도록 보완했다.

## 원인

`SlipFormPage`는 `productType === 'BUNDLE'`인 동안만 `BundleOptionRow`를 렌더했다. 빠른 `expand-line` 응답이 도착하면 부모 행이 `SINGLE` 구성품 행으로 즉시 교체되므로 옵션 UI도 함께 언마운트됐다. 이후 옵션을 다시 열어 전개할 수 있는 상태 정보도 없었다.

## 수정 내용

- 첫 전개 결과의 첫 구성품에 부모 세트 modelCode·수량·단가·규격·옵션 스냅샷을 임시 컨텍스트로 계승한다.
- 해당 컨텍스트가 있는 동안 구성품 행 아래에 옵션 UI를 유지한다.
- 옵션 변경은 최신 컨텍스트로 재전개하고, 전개 대기 중 연속 변경은 요청을 중복 생성하지 않고 세대만 갱신한다.
- 응답 세대가 오래되면 최신 컨텍스트로 1회 재전개하며, 최종 성공 시 컨텍스트를 제거한다.
- 품목 교체·행 삭제 시 이전 컨텍스트를 제거한다.
- 전개 후 수량·단가·규격 변경값도 다음 옵션 확정 스냅샷에 반영한다.
- 기존 BUNDLE 즉시 전개, 실패 재전개, 일반 품목 교체 보호, 빈행 규약 경로는 유지했다.

서버 변경은 없으며 Docker·DB 쓰기·재배포는 수행하지 않았다. 정상 SINGLE 실 DB 수치와 다른 트랙 범위는 이번 라운드에서 변경하지 않았다.

### 참고: 직접 TypeScript 타입체크

`npx tsc -p tsconfig.web.json --noEmit`은 `@samhan/design-system` 타입 선언을 찾지 못하는 기존 워크트리 환경 오류로 실패했다. 이 누락으로 다수 파일에 연쇄 TS2307/암시적 any 오류가 발생했으며, 이번 변경의 런타임 Vitest·서버 검증 결과와는 별도 환경 제약이다.
