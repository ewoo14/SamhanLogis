# PR #1164 R12 — Desktop Playwright 실 로그인 스펙 스코프 분리

## 1. 결론

PR #1164가 추가한 Playwright 스펙은 1개이며, mock 스펙이 아니라 실제 자격으로 로그인하고 실제 gateway/inventory API를 읽는 real-QA 스펙이다. 저장소의 기존 opt-out 관례인 `*-real-qa.spec.ts` 접미사로 파일명을 바꿔 mock 회귀 hard gate에서는 제외하고 shared real-QA 하네스에는 남겼다. `test.skip`/`describe.skip`, 자격 주입, 스펙 삭제는 사용하지 않았다.

- 작업 기준 HEAD: `5d65c485c20b9700ae0cc41bac92f0450f398f2f`
- PR: `#1164`
- 변경 전: `clients/desktop/playwright/1163-r4-fix-review/1163-r4-readonly-live-ui.spec.ts`
- 변경 후: `clients/desktop/playwright/1163-r4-fix-review/1163-r4-readonly-live-ui-real-qa.spec.ts`
- 본문 보존 검증: 변경 전 HEAD 본문과 변경 후 파일의 스코프 설명 주석 2줄을 제외한 내용을 비교한 결과 `content_diff_lines=0`

## 2. PM 전제 확인과 기존 스코프 장치

PM 전제는 맞다. `clients/desktop/scripts/real-qa-scope.cjs`는 이 용도의 shared real-QA 수집·추적 장치다.

1. `real-qa-scope.cjs`
   - `REAL_QA_ROOT = 'clients/desktop/playwright'`
   - `REAL_QA_SUFFIX = '-real-qa.spec.ts'`
   - 디스크의 해당 접미사 파일과 Git 추적 집합을 각각 수집하고 차집합을 검사한다.
   - `package.json`의 `typecheck:real-qa`가 `node --test scripts/real-qa-scope.test.cjs`를 실행한다.
2. `playwright.config.ts` — mock 회귀 hard gate
   - `testIgnore`의 `**/*-real-qa.spec.ts`, `**/*-real-qa/**`로 real-QA를 제외한다.
3. `playwright.real-qa.config.ts` — shared real-QA
   - `testMatch: ['**/*-real-qa.spec.ts']`로 같은 접미사를 수집한다.
   - config 로드 시 `assertRealQaScope(...)`를 호출해 추적 집합을 검증한다.
4. `clients/desktop/playwright/README.md`
   - 신규 mock 스펙은 기본 게이트에 자동 포함하고, 실서버/실QA 전용 스펙만 `*-real-qa.spec.ts` 등으로 opt-out 하도록 명시한다.

따라서 이번 수정은 allowlist 추가가 아니라 기존 파일명 기반 양방향 계약(mock 제외/real-QA 포함)을 그대로 따른다.

### 5.2 `127.0.0.1:1` 격리 전체 mock gate

`flaky=1`은 이번 스코프 변경과 무관한 기존 `playwright/slip-version-history/slip-version-history.spec.ts` 재시도 통과 건이다. HEAD의 R11 보고에도 동일한 기존 비결정적 flake가 기록돼 있다. `expected + flaky = 666`으로 수집한 666건이 모두 성공 상태이며, `unexpected=0`, `skipped=0`이다.

### 5.3 수치 표현 정정

기존 CI에서 문제 스펙은 성공(`expected`)이 아니라 실패(`unexpected=1`)로 집계됐다. 따라서 수정 전/후의 정확한 비교는 다음과 같다.

| 항목 | 수정 전 CI | R12 로컬 |
|---|---:|---:|
| mock 수집 총계 | 667 (`expected 666 + unexpected 1`) | 666 (`expected 665 + flaky 1`) |
| 문제 스펙 | `unexpected=1` | 수집 0 |
| `skipped` | 0 | 0 |

즉 “문제 스펙 몫만 줄었다”는 것은 mock 수집 총계 667→666에 해당한다. `expected` 자체는 문제 스펙이 원래 실패였으므로 정상 환경에서는 666→666으로 유지되는 것이 맞다. 이번 로컬 실행은 기존 flake 1건이 재시도 통과해 `expected=665, flaky=1`로 나뉘었다.

## 6. RED-B — real-QA 생존 및 증거 보존

PM이 git commit을 대행하므로 git 조작 금지에 따라 신규 파일을 stage하지 않았다. shared scope는 미추적 파일을 공식 수치에 섞지 않도록 의도적으로 막기 때문에, 로컬 narrow 수집만 `REAL_QA_ALLOW_UNTRACKED=1`을 명시했다. 파일을 PM이 stage하면 이 예외 변수 없이 공식 추적 집합으로 검사된다.

실행:

```powershell
$env:REAL_QA_ALLOW_UNTRACKED='1'
npx playwright test --config playwright.real-qa.config.ts --list `
  playwright/1163-r4-fix-review/1163-r4-readonly-live-ui-real-qa.spec.ts `
  --reporter=line
```

원문:

```text
[real-QA 로컬 실행 모드] 위 차집합은 의도 실행으로 허용했으며 공식 수치로 사용하지 마십시오.
Listing tests:
  [renderer] › 1163-r4-fix-review\1163-r4-readonly-live-ui-real-qa.spec.ts:81:1 › PR #1164 R4 — 구배포본 read-only 실 로그인·실 창고 이력 UI
Total: 1 test in 1 file
PLAYWRIGHT_EXIT=0
```

스코프 회귀 단위 테스트:

```text
✔ PR #1164 live-login spec is registered in the shared real-QA disk scope
tests 1
pass 1
fail 0
skipped 0
```

실 로그인 테스트 본문은 삭제하거나 skip하지 않았고, 파일명 분류 설명 주석 2줄 외에는 HEAD 원문과 동일하다(`content_diff_lines=0`). 따라서 라이브QA 증거의 실행 내용은 보존됐다.
