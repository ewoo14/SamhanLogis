# #1035 placeholder 딜레마 결정

## 1. 딜레마 결정 및 원인 확인

운영 기본 매핑은 환경변수 기본값 없이 유지한다. 따라서 운영에서 `WAREHOUSE_UUID_*`가 미주입되거나 빈 값/잘못된 UUID이면 Spring 설정 주입 또는 `WarehouseCodeMapper` 기동 검증이 실패하여 B를 만족한다. CI는 기존 workflow가 네 환경변수를 주입하므로 A를 만족한다. 로컬은 `local` 프로파일에 개발용 고정 UUID를 두어 env 없이 기동 가능하게 한다(C). 운영 env 주입 시의 기존 매핑 동작은 그대로 보존한다(D). Mapper의 placeholder·빈 값·UUID 형식 검증은 변경하지 않는다(E).

현재 워크트리의 `services/slip-service/src/test/resources/application.properties`는 빈 파일이다. 따라서 `app.publish.warehouse-validation.enabled=false`는 이 작업 위치에 존재하지 않는다. 더구나 현재 `WarehouseCodeMapper`에는 해당 프로퍼티를 바인딩하는 필드나 조건이 없어, 그 키가 존재하더라도 UUID 형식 검증을 끄지 않는다. IT는 클래스별 `@TestPropertySource`와 `@DynamicPropertySource`가 매핑·DB 설정을 직접 주입하므로 공통 리소스의 검증 토글로 IT의 기동 검증 범위를 제어하는 구조도 아니다. 테스트에는 테스트용 매핑을 명시적으로 둔다.

## 2. 적용

- 운영 문서의 `app.publish.warehouse-code-map`은 네 환경변수에 기본값 없이 유지했다.
- `local` 프로파일에는 네 개발용 UUID를 추가해 환경변수 없이 설정이 완성되도록 했다.
- 테스트 리소스 `application.properties`에는 네 테스트용 UUID를 명시해 CI 환경변수와 독립시켰다.
- 공유 Docker, 공유 DB, git 명령은 사용하지 않았다.

## 3. `slip-units` 검증

실행 명령은 `.github/workflows/ci.yml`의 `slip-units` test-tasks와 동일하며, 현재 프로세스에서 `WAREHOUSE_UUID_*` 네 값을 제거한 상태로 실행했다.

원문:

```text
BUILD SUCCESSFUL in 1m 19s
18 actionable tasks: 3 executed, 15 up-to-date
```

Gradle XML 집계:

```text
xml_files=116 tests=784 failures=0 errors=0 skipped=0
```

현재 워크트리에서는 요청서의 790건이 아니라 784건이 선택되었지만 실패·오류는 0건이다. 790건으로 허위 보고하지 않는다.

## 4. 로컬 기동 보완

`local` 프로파일 무환경변수 기동의 첫 실행은 `org.h2.Driver`를 찾지 못해 실패했다. `application.yml`이 local에서 H2 메모리 DB를 지정하지만 H2가 `testImplementation`에만 있어 `bootRun` 런타임 classpath에는 없었다. 따라서 H2를 `runtimeOnly`로 추가했다.

## 5. B/C 확인

B 확인 명령은 H2 메모리 DB를 직접 지정한 기본 프로파일 기동이다. 네 `WAREHOUSE_UUID_*`를 제거한 상태에서 실제 Spring context가 다음 원문으로 실패했다.

```text
Caused by: java.lang.IllegalStateException: 창고 매핑 기동 검증 실패: 창고코드 '00003'
at com.samhanair.logis.slip.publish.WarehouseCodeMapper.invalidStartupMapping(WarehouseCodeMapper.java:58)
```

UUID 원문은 예외에 노출되지 않았다.

C 확인은 네 환경변수를 제거한 `--spring.profiles.active=local` 기동이다. 실제 로그에 다음이 출력됐다.

```text
The following 1 profile is active: "local"
HikariPool-1 - Added connection conn0: url=jdbc:h2:mem:slip_db user=SA
warehouse-code-map 로드: 4 entries
```

이 실행은 서버가 계속 실행되는 정상 상태에서 검증 timeout으로 종료했으며, 남은 실행 PID는 종료했다. 공유 Docker와 실 DB는 사용하지 않았다.

## 7. 최종 재검증 정정

최종 변경 후 동일 `slip-units` 명령을 다시 실행했다. Gradle 프로세스 종료코드는 0이었다.

```text
xml_files=116 tests=784 failures=0 errors=0 skipped=1
```

유일한 skip은 `PublicSlipAttachmentControllerIT` 1건이며 Testcontainers Docker 조건 skip이다. 따라서 이 워크트리에서 확인 가능한 사실은 **784건, 실패 0, 오류 0, skip 1**이다. 요청서의 790건/skip 0은 현재 체크아웃의 테스트 inventory와 일치하지 않아 그렇게 보고하지 않는다.
