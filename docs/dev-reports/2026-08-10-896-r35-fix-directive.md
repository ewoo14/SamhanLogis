## 1. 도달 결함 A — 부자재 행에서 나를 호출하는 본체가 사라졌다

### 재현 원문

활성 규칙은 `UI_HOME_MULTI_AM052BN6PBH1`, source 1건 `AM052BN6PBH1`, target 3건이다. 관리자 UI `/products/estimate-items?category=HOME_MULTI`에서 target `PC6NUDK1NW`를 검색했다.

```text
RULE_COUNT total=1 active=1
ACTIVE_RULE key=UI_HOME_MULTI_AM052BN6PBH1 category=HOME_MULTI sources=1 targets=3
B2_TARGET queryHttp=200 code=PC6NUDK1NW row=VISIBLE apiRows=1
  expectedSources=AM052BN6PBH1 visibleSources=NONE
```

화면 증거: `docs/qa/2026-08-10-896-r35-sol/01-b2-accessory-inbound-sources.png`

### 좌표

- `clients/desktop/src/renderer/routes/EstimateItemsCatalogPage.tsx:262-268` — `quantitySyncRuleForSource`는 source 일치만 반환한다.
- 같은 파일 `:783-846` — 셀은 전달받은 단일 source 규칙의 target 칩과 편집기만 렌더한다.
- 같은 파일 `:1442` — 각 행에 `quantitySyncRuleForSource(..., row.modelCode)`만 주입하므로 target 행에서는 inbound source 정보를 잃는다.

### 불변식

활성 규칙 `sources × targets`의 연결은 양쪽 품목 행에서 모두 보인다. source 행은 `target 품목명:수량`을 편집하고, target 행은 `나를 부르는 본체`를 읽기 전용으로 표시한다. target 행을 두 번째 작성 진입점으로 만들지 않는다.

### 양방향 RED

- **RED-A:** 위 실데이터 계약을 fixture로 고정한다. `PC6NUDK1NW` 행에 inbound source `AM052BN6PBH1`과 rule key가 표시되지 않으면 RED다.
- **RED-B:** `AM052BN6PBH1` 행에는 `PC6NUDK1NW:1`, `AWR-WE13N:1`, `FH-LFHLN:1` 세 target 칩과 저장 버튼이 그대로 있어야 한다. `PC6NUDK1NW` 행에는 inbound source가 보여도 수량 input·저장 버튼이 생기면 RED다.

## 2. 도달 결함 B — 백엔드가 인정하는 실 target을 작성 UI가 숨긴다

### 재현 원문

정상 HOME_MULTI 본체 `AJ060MXHNBC1` 행에서 현재 활성 규칙의 target `PC6NUDK1NW`를 검색했다. 서버 검색은 정확히 1건을 반환했지만 UI 후보는 0건이었다.

```text
PICKER_SOURCE code=AJ060MXHNBC1 productCategory=HOME_MULTI
PICKER_TARGET http=200 apiRows=1 code=PC6NUDK1NW
  productCategory=HOME_MULTI goodsType=GOODS status=ACTIVE
PICKER_UI input=PC6NUDK1NW chipCount=0 optionCount=0 dialogCount=0
```

화면 증거: `docs/qa/2026-08-10-896-r35-sol/07-d15-target-picker-excludes-valid-target.png`

`PC6NUDK1NW`는 현재 활성 규칙의 target이며, 실제 target 역할 변경은 409로 차단된다. 즉 서버가 유효 target으로 취급하는 실 품목을 D15 picker만 `productCategory`가 `MATERIAL`이 아니라는 이유로 버린다.

### 좌표

- `clients/desktop/src/renderer/routes/EstimateItemsCatalogPage.tsx:1305-1313` — picker가 `product.productCategory === 'MATERIAL'`로 후보를 축소한다.
- `clients/desktop/src/renderer/api/productApi.ts:27-46,94-118` — 일반 검색 DTO/`ProductOption`에는 백엔드의 실제 target 역할 판정값이 없다.
- `services/product-service/src/main/java/com/samhanair/logis/product/quantitysync/QuantitySyncRuleValidator.java:401-418` — 서버 정본은 `GOODS && catL ∈ {부자재, 판넬, 실외기 받침, 실외기 받침대}`다.
- `services/product-service/src/main/java/com/samhanair/logis/product/service/QuantitySyncRuleService.java:550-561` — 규칙 검증 snapshot은 `product.getCatL().getName()`을 사용한다.

### 불변식

작성 UI의 target 후보 집합은 서버 저장 검증의 역할 집합과 동일해야 한다. `ProductCategory.MATERIAL`은 내부 분류일 뿐 target 역할의 대체 원천이 아니다. 판정 원천을 프런트 문자열 추론으로 복제하지 말고 서버가 제공하는 단일 role/eligibility 값으로 전달한다.

### 양방향 RED

- **RED-A:** `catL=판넬 · goodsType=GOODS · productCategory=HOME_MULTI · HOME_MULTI 노출`인 `PC6NUDK1NW`가 target 후보에 나타나고 칩으로 선택돼야 한다.
- **RED-B:** `catL=실내기 · goodsType=GOODS · productCategory=MATERIAL` fixture는 후보에서 제외돼야 한다. 반대로 `catL=판넬 · goodsType=NON_GOODS`도 제외돼야 한다. 두 축 중 하나라도 `productCategory` 하나로 대체되면 RED다.

## 3. D15 삭제 반대급부

picker 결함을 고친 뒤 규칙 0건 카테고리에서 관리자 UI로 source A·source B·target T를 생성해 다음 순서를 실제로 완주한다.

1. A와 B를 같은 공용 규칙 source로 저장한다.
2. B의 마지막 target 칩을 제거해 저장한다. 규칙·A·T·multiplier가 동일하게 남아야 한다.
3. A의 마지막 target 칩을 제거해 저장한다. 그때에만 규칙이 삭제돼야 한다.

## 5. 반대급부

- target 행의 inbound 표시는 읽기 전용이어야 하며 D15의 source 단일 작성 진입점을 되돌리지 않는다.
- 공용 규칙의 기존 세 target 순서·multiplier와 source 병합 계약을 보존한다.
- target eligibility를 추가하더라도 일반 견적품목 추가 검색(`searchMasterProducts`)의 `MATERIAL` 제외 계약과 혼합하지 않는다. 두 picker는 목적이 다르다.
- MED의 rule key 브리지는 첫 source 행을 검색·포커스해야 하며 target 행 표시를 편집 anchor로 사용하지 않는다.
