기존 `sol1176-pg`는 `product_db`가 V37이고 V42 전 상태였지만 `dc_config_db`와 `partner_order_db`가 없고 `partner_db` 한글 거래처도 0건이라 금액 검증 증거로 사용할 수 없었다. 공유 `samhan-postgres`에서 `product_db`, `partner_db`, `dc_config_db`, `partner_order_db`, `slip_db`를 각각 custom-format 파일 dump로 만들고 `codex1090-sol-pg`에 복원했다. PowerShell 텍스트 파이프는 사용하지 않았다.

복제 직후 한글 원문:


## 2. 금액 전후 대조 방법

V42 적용 전 활성 품목 2,982건을 별도 검증 DB에 고정했다. 레거시 견적은 기존 Desktop `getModelFlags(modelCode)`, 레거시 주문은 `discount_flags` 비영값 우선 후 모델코드 판별을 사용했다. V42 적용 후에는 두 경로 모두 `discount_option`만 사용했다.

금액식은 실제 코드와 동일하게 적용했다.


## 10. 도달 가능한 결함

### 결함 1 — 미분류 113건 중 112건의 옵션 정액 할인 소실 (금액 불변 FAIL)

- 조건: 레거시 모델코드 규칙 발화 + L/M/S 모두 NULL + 해당 옵션 DC가 0보다 큰 거래처 + 판매가가 0보다 큼.
- 도달 경로: Desktop 새 견적/전표 자동 가격 또는 partner-order 미리보기·확정 가격 계산.

- 원인 좌표: V42가 분류 없는 113건을 의도적으로 NULL로 두는 동시에 런타임 모델코드 fallback을 제거했다.
