# #896 시트 ↔ DB 차집합 실측

- 실측일: 2026-08-08 (KST)
- DB 최종 재확인 시각: `2026-08-08 20:32:00.347642+09`
- 범위: 저장된 CSV와 `product_db`의 현재 상태를 읽기 전용으로 비교
- 금지사항 준수: Google 접근 없음, DB 쓰기 없음, Docker 재기동·재배포 없음, 코드·Git 조작 없음

## 1. 결론

시트 접근을 지금 끊으면 최소한 아래 데이터가 DB에 없는 상태로 남는다.

1. 모델 참조 2개: `AP110RNPPHH1`, `PC6NUNK1N`
2. 시트 세트 키 18개: 상업멀티 JHJ 세트 14개와 모델 코드가 아닌 그룹명 4개
3. 구성 관계 33쌍: DB에 없는 세트에 매달린 관계 32쌍, DB에 없는 구성품 모델 관계 1쌍
4. 비어 있지 않은 옵션/특징 5개
5. DB 현재 단가와 다른 시트 단가 셀 1,458개. 이 중 541개는 시트가 0보다 큰데 DB가 0인 경우다. 빈칸·0 행을 모두 제외해도 충돌 917개가 남는다.

따라서 Google 의존성을 끊기 전에 키 매핑, 세트로 볼 행의 범위, 단가 우선순위, 빈칸/0 규칙, 구성 수량 도출 규칙을 먼저 확정해야 한다. 특히 시트의 `수량` 열은 빈칸 또는 0뿐이라 구조 수량을 증명하지 못하므로 바로 이전할 수 없다. 업무 사용 여부는 이번 자료만으로 확정할 수 없으므로 아래에서 모두 `모른다`로 표시한다.

## 12. 1회 이전 전에 먼저 정할 것

1. **모델 키 매핑**
   - 정본 키는 `model_name`으로 고정한다.
   - `product_code`는 87.45%만 채워져 있어 조인 키로 금지한다.
   - `AP110RNPPHH1↔AP110RNPPBH1`, `PC6NUNK1N↔PC6NUNK1NW`를 동일 모델로 합칠지 별도 모델로 만들지 사람이 결정한다.
2. **세트 키 범위**
   - JHJ 14개를 실제 BUNDLE로 이전할지 결정한다.
   - 그룹명 4개를 세트가 아니라 규칙/계산 그룹으로 옮길지 결정한다.
   - 홈멀티 세트 키와 구성 도출 규칙을 별도로 설계한다.
3. **단가 우선순위**
   - 정본 탭, DB 현재가, `price_history`, `_단가인상` 오버레이 중 무엇이 현재가·과거가인지 확정한다.
   - 싱글 구성품의 두 납품가 열이 전역 품목 단가인지 세트/특징별 오버라이드인지 확정한다.
   - 0을 실제 0원으로 볼지 “미등록”으로 볼지 열별로 정한다. 전역 일괄 규칙은 금지한다.
4. **구성 수량 규칙**
   - 시트 반복행, 괄호 HP 표현, DB `default_qty`의 우선순위를 정한다.
   - 원시 `수량` 열은 빈칸/0뿐이므로 구조 수량 원천으로 사용하지 않는다.
   - 수량 충돌 20쌍을 개별 승인한다.
5. **이름·단위 정규화**
   - `대`/`SET`/`세트`→`EA` 매핑을 승인한다.
   - 괄호·공백 차이 42건을 표기 정규화로 볼지 DB/시트 원문을 함께 보존할지 정한다.
6. **Soft delete 범위**
   - 부모 세트가 삭제된 활성 자식 13개를 이전·대조 범위에서 제외할지 정리할지 결정한다.
7. **회귀 대조 단위**
   - 모델 전역 가격만 비교하지 말고 `(세트, 구성품, 특징, 가격열)` 단위 금액을 저장·재계산한 뒤 정본 CSV와 대조한다.
