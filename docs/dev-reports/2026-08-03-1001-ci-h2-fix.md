## 1. 커밋 필요성 판정

### 판정: 네 스크립트 모두 저장소에 커밋되어야 한다

- `git ls-files -- clients/desktop/playwright/1001-partner-ledger-real-qa` 결과 네 파일이 모두 추적 파일이다.
- `git log --follow`에서 `capture.mjs`는 R2/R3 QA 커밋 계보를 가지며, `run-scenario.mjs`도 동일한 라이브 QA 산출물 계보를 가진다.
- `docs/dev-reports/2026-08-03-1001-live-qa-r2.md`가 네 파일을 R2 하네스로 명시하고, R2/R3 보고서가 `docs/qa/1001-partner-ledger-real-qa/` 캡처를 검증 증거로 참조한다.
- `run-scenario.mjs`는 시나리오 1~8과 캡처·검증 JSON을 재현하는 실행 진입점이다. 따라서 네 파일은 일회성 미추적 산출물이 아니라 커밋된 라이브 QA 증거를 재현·검증하는 하네스다.
- 결론적으로 삭제하지 않고, 모든 캡처 출력이 `resolveQaShotsDir()`를 통과하도록 최소 수정한다. 기존 `docs/qa/**` 증거는 삭제하거나 덮어쓰지 않는다.

## 2. RED 재현 및 처리

- 좁은 명령: `npm exec vitest run src/renderer/test-utils/harness-false-green-guard.test.ts`
- 수정 전 원문: `49 tests | 1 failed`, `48 passed`; H-2가 네 대상 파일에서 총 6건의 인라인 목적지와 `run-scenario.mjs → const shots`를 보고했다. 같은 로컬 실행에서 별도 미추적 `1001-live-qa/capture.mjs → const OUT`도 추가 보고되었다.
- 처리: `capture.mjs`, `electron-probe.mjs`, `probe.mjs`, `run-scenario.mjs`에 `resolveQaShotsDir()`와 절대 경로 계산을 추가하고 모든 screenshot 목적지를 반환 디렉터리 하위로 변경했다.
- `1001-live-qa/`는 현재 작업 트리에 이미 존재하는 미추적 사용자 파일이며 이번 PR의 네 추적 파일 범위가 아니므로 수정하지 않는다. CI checkout에는 포함되지 않는다.
