### 실 DB 72세트 분포

활성 `product_type=BUNDLE`, `product_category=COMMERCIAL_MULTI`, 활성 구성품 1건 이상인 집합을 읽기 전용으로 다시 셌다.

| bundle_components_manual | 세트 | 활성 구성품 | 기본 구성품 | 기본 0건 세트 | 기본 보유 세트 |
|---|---:|---:|---:|---:|---:|
| false | 71 | 135 | 0 | 71 | 0 |
| true | 1 | 2 | 0 | 1 | 0 |
| 합계 | 72 | 137 | 0 | 72 | 0 |

유일한 `manual=true` 행은 다음과 같다.

```text
AM220AXVHHR1SY  DVM S2 동시냉난방 22HP (10HP+12HP)
구성품  AM100AXVHHR1:N · AM120AXVHHR1:N
활성 2건 · 기본 0건 · bundle_components_manual=true
```

따라서 R3 코드의 `allowLegacyNoDefaultFallback = !parent.isBundleComponentsManual()` 조건은 배포 즉시 이 실 세트를 전개 0건으로 만든다.

### 실 사용자 경로와 원문

기초품목 세트 구성품 편집기는 기존 행의 `isDefault` 값을 PUT body에 보존하지만 화면에 기본 여부를 표시하거나 바꾸는 조작이 없다. 새 행은 항상 `isDefault=false`다. 레거시 72세트의 모든 활성 행이 이미 `false`이므로 사용자가 71개 미편집 세트 중 하나에서 수량·종류를 바꾸거나 아무 변경 없이 `구성품 저장`만 눌러도 다음 전이가 발생한다.

```text
GET 구성품: 전 행 isDefault=false
→ PUT /api/v1/products/{modelCode}/components: 전 행 isDefault=false
→ 200 성공
→ BundleComponentService.replaceComponents(): parent.markBundleComponentsManual()
→ 다음 expand: manual=true + 기본 0건
→ []
```

격리 Testcontainers에서 실제 `replaceComponents()` mutation을 거친 테스트 결과도 `saved 2건`, `bundleComponentsManual=true`, `expand=[]`을 고정한다. 이 빈 결과의 사용자 표면은 기존 코드와 R1 실증에서 다음과 같이 확정돼 있다.

- 견적 저장: `세트 구성품 일부를 찾을 수 없습니다(미등록/단종): AM220AXVHHR1SY` — 404
- 판매전표 선택: `세트 구성품을 찾을 수 없습니다. 관리자에게 문의해 주세요.` — 화면 라인 0건

현재 실 DB의 `AM220AXVHHR1SY`는 이미 표식이 true이므로 새 편집 없이도 R3 배포만으로 같은 결과에 도달한다. 나머지 71세트는 사용자가 구성품 저장을 한 번 누르는 순간 같은 상태가 된다.

### 표식 복귀 경로

`Product.clearBundleComponentsManual()` 도메인 메서드는 있으나 전 repo에서 호출자가 없다. 서비스·컨트롤러·클라이언트 API·사용자 UI 경로가 모두 없으므로 사용자는 표식을 되돌릴 수 없다. DB 직접 변경은 사용자 경로도 아니고 이번 검증 범위에서도 금지다.

### 불변식

`bundleComponentsManual`은 시트 동기화 덮어쓰기 방지용 소유권 표식이지, V36 이전 레거시 호환 자격의 역표식이 아니다. 다음 세 조건을 동시에 지켜야 한다.

1. 전환 전 레거시 72세트는 수기 편집 여부와 무관하게 구성품 전개가 0건으로 소실되지 않는다.
2. 신규·수기 세트의 `기본 0건`을 레거시와 구분 없이 활성 전체 전개해서는 안 된다.
3. 기본 구성품이 1건 이상이면 `bundleComponentsManual` 값과 무관하게 정확히 기본 행만 전개한다.

### 양방향 RED

- **RED-A — 전개 차단 방지, 실 표적:** 실 DB 복제 `AM220AXVHHR1SY`, `bundleComponentsManual=true`, 활성 구성품 `AM100AXVHHR1`·`AM120AXVHHR1`, 기본 0건에서 두 모델이 기존 수량대로 전개돼야 한다. 견적 저장은 404가 아니고 판매전표 `/slips/expand-line`은 빈 배열이 아니어야 한다.
- **RED-B — 구체 표적, R2 결함 재개방 방지:** 신규 세트 `R3_NEW_MANUAL_ZERO_DEFAULT`에 필수 `R3_REQUIRED`와 선택 `R3_OPTIONAL`을 모두 `isDefault=false`로 PUT한 뒤 선택품까지 활성 전체 전개하면 실패다. 권장 계약은 PUT 400과 기존 집합 불변이며, 다른 설계를 택해도 신규 세트를 레거시 fallback에 포함하면 안 된다.
- **편집 전이 RED:** `bundleComponentsManual=false`, 기본 0건인 실 레거시 복제 세트에서 UI가 GET한 동일 2행을 그대로 PUT한다. PUT 전후 전개 모델·수량·합계가 같아야 하며, `manual=true` 전환만으로 `[]`이 되면 실패다.
- **기본 1건 경계:** `bundleComponentsManual=true`, 기본 1건·비기본 1건이면 기본 1건만 전개해야 한다.

### 수정 범위와 반대급부

- `bundleComponentsManual` 조건을 단순 제거하면 R2의 신규·수기 세트 활성 전체 전개 결함이 되살아난다.
- PUT에서 기본 1건을 무조건 요구하려면 같은 변경에 기본 여부를 지정할 사용자 조작을 제공해야 한다. 현재 UI 그대로 서버만 400을 반환하면 신규 구성품 저장이 막힌다.
- 안전한 구분은 수기 소유권과 독립된 레거시 전환 표식/확정 모델 집합 또는 72세트 기본값 데이터 전환이다. 데이터 전환 전에는 `manual=true`를 레거시 자격 박탈 신호로 쓰면 안 된다.
- `clearBundleComponentsManual()`만 외부에 노출하는 해법은 수기 편집 보호를 풀어 다음 시트 sync가 사용자의 구성을 덮을 수 있으므로 별도 의미 결정 없이 대체 fix가 될 수 없다.

## 다른 검증 각도

### #1090 S 할인 견적

- 격리 프런트 테스트에서 `sellingPrice=495000`, `fixedDiscountRate=15`는 `420750`으로 계산됐다.
- `fixedDiscountRate=null`은 `495000`을 그대로 유지했다.
- `ProductSummaryResponse`의 유효 할인율·출처 wire 계약 테스트 7건이 통과했다.

### 분류값 null · 기존 품목 DC 167건

- 실 DB 활성 `products.fixed_discount_rate IS NOT NULL`은 167건이며 분포는 0%=6, 35%=21, 40%=38, 45%=73, 50%=29다.
- `(model_code, fixed_discount_rate)` 정렬 해시는 `bf5b6434acf64a4171f631e308c1c8cd`다.
- R3 변경은 `Product.resolveFixedDiscount()`의 `PRODUCT > S > M > L > 기존 품목값` 결정을 바꾸지 않는다. 분류 유효값이 null이면 기존 품목값으로 복귀하고, 분류와 품목값이 모두 null이면 견적 helper가 판매가를 유지한다. 판매전표·주문 금액 코드는 이번 R2 fix에서 변경되지 않았다.
- 현재 실 DB는 V35라 `classification.fixed_discount_rate` 컬럼이 아직 없다. 이 축의 PR 백엔드 결과는 격리 복제본으로만 판정했으며 실 배포본으로 가장하지 않았다.

### 가격기억·수동단가 우선순위

- 견적 lookup은 분류 DC가 적용된 카탈로그가를 먼저 만들고, 가격기억 hit가 있으면 `REMEMBERED` 값으로 덮는다.
- 현재 라인이 `USER`면 자동단가 적용 조건이 false라 사용자 단가를 보존한다.
- 견적 coedit/가격 경로 58건이 fresh run에서 통과했다.

### 기본 1건 경계

- 기본 1건·비기본 1건은 기본 모델 1건만 전개하는 `BundleExpanderIT`가 통과했다.
- R3 predicate는 `manual=true`여도 `isDefault=true` 행을 통과시키므로 이 경계는 유지된다.

## 직전 결함 폐쇄 여부

- R2의 직접 결함인 “신규·수기 `manual=true + 기본 0건`에서 활성 전체 전개”는 폐쇄됐다.
- 그러나 구분 신호를 시트 보호용 수기 표식으로 재사용해 R1의 레거시 0행/404를 실 DB 1세트에서 즉시 다시 열고, 나머지 71세트에도 사용자 편집으로 도달 가능하게 만들었다. 따라서 PR #1132는 이 결함이 닫히기 전 수렴하지 않았다.

## 격리·정리
