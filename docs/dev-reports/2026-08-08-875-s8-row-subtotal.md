# PR #1056 (#875) S8 행 소계 표시 수정

## 범위

- 라이브QA 결함 LQ-875-01의 행 소계 표시만 수정했다.
- 본계산, 저장 payload, 복원 계약, 자동 절삭 분리는 변경하지 않았다.
- 스프레드시트·GAS에는 쓰지 않았다. 공유 Docker 스택도 재기동하지 않았다.
- 커밋·push는 수행하지 않았다.

## 원인 확정

특수행은 읽기전용 수량 칸을 사용하고 단가는 `homeCustomPrices` 등 저장용 Map에서 읽는다. 일반행은 DOM의 `data-unit` 단가 셀을 통해 자동 단가를 읽는다.

홈 동기화 함수 `clients/web/estimate-app/views/index.ejs:8688-8757`는 이 구분 없이 모든 행에 대해 `homeUnitPrice(model)`을 `finalUnit`으로 사용한 뒤 `:8755`의 `finalUnit * q`로 소계를 덮어쓴다. 운임·절삭 특수행은 `data-unit` 셀이 없고 일반 자동 단가도 0이므로, 홈 입력 후 `recomputeHomeDerived(true)` 또는 복원 후 `syncHomeUIFromState()`가 소계를 0으로 덮었다. 최종 합계는 별도 `sumHome()`/`buildSendRows()` 계산 경로라 정상인 상태와 일치한다.

레거시 원문은 다음과 같이 확인했다.

- `tools/legacy-gas/종합견적서/index.html:2699-2750`: 특수행 핸들러가 저장·계산용 `val`을 그대로 소계에 표시한다.
- `tools/legacy-gas/종합견적서/index.html:16205-16233`: 자동 절삭행의 `price`와 `sub`를 `-rem`으로 저장한다.
- 따라서 절삭 입력 칸은 S5 계약대로 절댓값이지만, 소계 열은 레거시 관례대로 `-500`이다.

## 수정

`syncHomeUIFromState()`에 `CATALOG_SPECIAL` 분기를 추가했다.

- 홈 특수행은 `homeCustomPrices`의 저장용 단가와 `homeQty`의 읽기전용 수량으로 소계를 갱신한다.
- 운임 `1000 × 1`은 `1000`으로 표시한다.
- 절삭 `-500 × 1`은 `-500`으로 표시한다.
- 일반행 동기화, `syncHomeTotals()`, 본계산·payload 경로는 그대로 둔다.
