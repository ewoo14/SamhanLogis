## 2. 불변식(수단 금지)

거래처가 선택된 라인의 자동 단가 조회가 진행 중일 때, 아직 그 거래처 기준으로 확정되지 않은 카탈로그 값이나 직전 거래처 값을 현재 거래처의 확정 단가처럼 사용자 편집 input에 노출하면 안 된다. 조회가 성공하면 해당 거래처의 기억 단가 또는 권위 있는 할인 단가가 한 번만 확정되어 표시되어야 하고, miss·실패·timeout이면 기존 계약에 따른 카탈로그 fallback 또는 직접 입력 유도가 표시되어야 한다.

구현 수단은 지정하지 않는다. 단, 테스트 timeout 연장, 호출 여부만 기다리기, 단언 완화·삭제·skip으로 이 불변식을 만족한 것으로 처리하는 것은 금지한다.

## 3. 양방향 RED

### RED-A — 중간값 노출 방향

단건 `getPriceMemory`를 deferred 상태로 둔다.

1. 거래처 A를 선택하고 판매가 `1000`인 품목 A를 선택한다.
2. Promise가 미해결인 동안 실제 모바일 단가 input을 관찰한다.
3. `1000`이 거래처 A의 확정 단가처럼 노출되면 RED다. 조회 중 상태와 저장 차단만으로 이 RED를 면제하지 않는다.
4. Promise를 기억 단가 `100000`으로 resolve하면 input과 가격 출처가 `100000`/`REMEMBERED`로 수렴해야 한다.

### RED-B — 반대 방향·stale 응답

거래처 A 단건 응답과 거래처 B bulk 응답을 각각 deferred로 제어한다.

1. A의 확정 단가 `100000`까지 수렴시킨 뒤 B로 변경한다.
2. B 응답 전에는 카탈로그 `1000` 또는 A의 `100000`이 B의 확정 단가로 제시되면 RED다.
3. 늦은 A 응답은 B 상태를 덮지 못해야 한다.
4. B 응답 `200000` 후에는 최종값 `200000`, `REMEMBERED`, `단가 변경` 표지, `[priceStatusId, priceChangedStatusId]` 순서의 두 IDREF가 함께 성립해야 한다.

두 RED는 테스트의 대기 시간을 늘려서가 아니라, deferred의 미해결/해결 경계에서 실제 DOM 상태를 단언해야 한다.
