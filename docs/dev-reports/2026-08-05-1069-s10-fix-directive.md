# #1069 S10 SOL fix 지시서 — 판매전표 세트 전개

## 판정

**실 사용자 경로로 재현 가능한 결함 1건 있음 — 머지 비권고.** 세트 품목을 선택하면 전개 요청이 즉시 시작되고, 정상 응답이 빠르게 도착하면 BUNDLE 부모가 구성품으로 교체되면서 세트 옵션 입력 UI가 사라진다. 사용자는 실외기 제외·교체, 판넬, 360 형상, 자재 포함 옵션을 입력할 수 없고 기본 옵션으로 전개된 결과만 받는다.

재현 난이도는 **매우 낮음**이다. 판매전표 빈 행에서 세트 품목을 한 번 선택하는 정상 조작뿐이며 정교한 타이밍 조작이 필요 없다. 응답이 사람의 다음 클릭보다 빠른 일반적인 저지연 환경에서 발생한다. 응답을 인위적으로 지연해야만 옵션을 입력할 수 있는 현재 동작이 오히려 비정상 조건이다.

S8 결함은 닫혔다. 전개 대기 중 수량 변경 후 이전 요청 실패에서 최신 수량 재전개 1회와 BUNDLE 부모 소멸을 확인했고, 수량 `1→2→3` 연속 변경은 최종 수량 `3` 한 벌로 수렴했다. BUNDLE 대기 중 일반 품목을 연속 교체한 경우에도 옛 응답이 최종 품목을 덮지 않았다.

읽기 전용 실 DB 재계수:

- 견적 노출 활성 BUNDLE: `344품목`.
- 활성 `OUTBOUND DRAFT` 중 현재 활성 SINGLE: **`2,107행 / 2,100전표 / 2,837,681,781원`**.
- 같은 범위의 현재 활성 BUNDLE: `0행 / 0전표`.
- 정상 SINGLE 기준 집합은 차단되지 않았고 지시 기준값과 정확히 일치했다.

## ① 좌표

### F1. 정상 전개 응답이 빠르면 세트 옵션 입력 기회가 사라진다

- 옵션 UI의 계약: `clients/desktop/src/renderer/routes/components/BundleOptionRow.tsx:1-12`
  - 이 UI는 실외기 제외·교체, 판넬, 360 형상, 자재 포함을 **전개 전 선택**하여 BE `BundleSetOptions`로 보내는 입력면이다.
- 세트 선택 즉시 전개: `clients/desktop/src/renderer/routes/SlipFormPage.tsx:853-883`
  - 품목 선택으로 행을 BUNDLE로 만든 직후, 거래처 최근단가 조회가 필요 없으면 `expandSelectedBundle`을 즉시 기다린다.
  - 거래처가 있어도 최근단가 응답 뒤 `:943-945` 또는 실패 뒤 `:969-971`에서 즉시 전개한다.
- 옵션 UI 생존 조건: `SlipFormPage.tsx:1292-1308`
  - `line.productType === 'BUNDLE'`인 동안에만 `BundleOptionRow`가 렌더된다.
- 정상 응답 적용: `SlipFormPage.tsx:798-810`, `:735-780`
  - 요청은 그 순간의 `setOptions`를 보낸 뒤, 응답이 오면 BUNDLE 부모를 전부 `productType: 'SINGLE'`인 구성품 행으로 교체한다.
  - 교체 직후 옵션 UI는 렌더 조건을 잃고 사라진다. 이미 전개된 구성품에서 옵션을 다시 열거나 재전개하는 사용자 경로도 없다.

협소 RED 재현:

1. 거래처를 선택하지 않은 새 판매전표의 첫 빈 행에서 BUNDLE을 선택한다.
2. `/slips/expand-line`이 정상 구성품 1행을 즉시 반환하게 한다.
3. 구성품 반영 완료 뒤 세트 옵션 입력면이 계속 존재해야 한다고 검증한다.
4. 실제로는 구성품은 표시되지만 `BundleOptionRow`가 이미 제거되어 RED가 된다.

```text
FAIL  S10 진단: 초고속 전개 응답 뒤 사용자는 세트 옵션을 입력할 수 없다
Unable to find an element by: [data-testid="bundle-option-change"]
Tests 1 failed | 74 skipped
```

진단 RED는 실행 후 제거했으며 제품·기존 테스트 파일에는 S10 진단 변경을 남기지 않았다.

## ② 불변식 — 구현 수단 지정 금지

1. 사용자는 서버 응답 속도와 관계없이 세트 전개 옵션을 안정적으로 입력하고 확정할 수 있어야 한다.
2. 사용자가 확정한 마지막 옵션·수량·단가·규격 스냅샷으로 정확히 한 벌의 구성품이 전개되어야 한다.
3. 전개 성공 뒤 옵션을 변경할 수 있는 사용자 경로를 제공한다면, 이전 구성품을 누적하지 말고 새 옵션 결과 한 벌로 교체해야 한다.
4. 빠른 응답을 늦추거나 사용자의 초고속 클릭에 의존하는 방식은 허용하지 않는다.
5. S8에서 닫힌 성공·실패 세대 재전개, 일반 품목 교체 보호와 S2·S4·S6의 BUNDLE 영속 차단·최신 가격·규격 권위를 유지해야 한다.
6. `#1063` 초기 5행, 마지막 행 1회 증식, trailing 빈행 1개, 의미 없는 빈행 저장 제외를 유지해야 한다.
7. 정상 OUTBOUND DRAFT SINGLE `2,107행 / 2,100전표 / 2,837,681,781원` 경로를 BUNDLE로 오인 차단하면 안 된다.

## ③ 양방향 RED — 반대급부 필수

### RED-B — 재발 금지

- BUNDLE 선택과 전개 성공이 같은 이벤트 루프에 가까울 정도로 빠르게 끝나도 사용자가 옵션을 입력·확정할 수 없으면 RED.
- 실외기 제외·교체, 판넬 선택, 360 형상, 자재 포함 각각을 변경했는데 최종 전개 요청의 `setOptions`에 마지막 값이 없으면 RED.
- 빠른 첫 성공 뒤 옵션을 바꾼 결과가 기본 옵션 구성품 위에 누적되어 2벌 이상이 되거나 BUNDLE 부모가 저장 가능 상태로 남으면 RED.
- 옵션을 연속 두 번 바꾸었을 때 중간 응답이 최종 옵션 결과를 덮으면 RED.

### RED-A — 반대급부 보존

- 기본 옵션 사용자는 추가 조작 없이 기존처럼 구성품 한 벌로 전개되어야 한다.
- 전개 대기 중 수량 `1→2→3`은 최종 수량 `3` 한 벌, 이전 요청 실패 후 최신 재전개 1회여야 한다.
- 전개 대기 중 일반 SINGLE 또는 다른 품목으로 교체하면 옛 성공·실패가 최종 품목을 덮거나 옛 BUNDLE을 재전개하면 안 된다.
- S4 최근단가 지연 중 최신 수량·직접 단가, S6 규격 입력·삭제와 구성품 자체 규격 우선이 되살아나면 RED.
- 정상 SINGLE 전체수정·모바일 생성이 차단되거나 BUNDLE 전체수정·모바일 생성이 다시 영속되면 RED.
- 초기 빈행 5개, 마지막 행 1회 증식, trailing 빈행 1개, 빈행 저장 제외와 VAT 포함 금액·구성품 순서가 달라지면 RED.
