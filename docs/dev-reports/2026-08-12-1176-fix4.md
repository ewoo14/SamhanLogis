## RED-first — 연결 단절의 정확한 결과

격리 PostgreSQL network namespace에서 실행했다.

```powershell
docker run -d --name fix4-lock-client --network container:sol1176-pg -e PGPASSWORD=sol1176-only postgres:16-alpine psql -X -h 127.0.0.1 -U samhan -d postgres -c "BEGIN; SELECT pg_advisory_xact_lock(hashtext('qa-residue-soft-delete-2026-08-12')); SELECT pg_sleep(60);"
docker kill fix4-lock-client
```

kill 직전 원문:

```text
locktype | mode          | granted
---------+---------------+--------
advisory | ExclusiveLock | t
```

kill 6초 뒤에도 backend가 `PgSleep` 중이라 xact lock 1개가 남았다. backend를 종료한 뒤:

```text
pid  | state  | wait_event_type | wait_event
-----+--------+-----------------+----------
5080 | active | Timeout         | PgSleep

terminated
----------
t

granted_advisory_locks | waiting_advisory_locks
-----------------------+------------------------
0                      | 0
```

판정은 **부분 개선**이다. xact lock은 transaction 종료 즉시 해제되고 기존 세션 unlock 경고도 사라졌다. 그러나 PostgreSQL backend가 TCP 단절을 감지하기 전 active query/행 잠금 대기라면 transaction 자체가 끝나지 않아 xact lock도 즉시 사라지지 않는다. 그러므로 xact lock 전환만으로 연결 단절 차단 결함이 완전히 해소됐다고 보고하지 않는다.
