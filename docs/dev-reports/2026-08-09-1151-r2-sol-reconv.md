## 1. 결론

R2의 production 경로 자체는 수렴했다. 다섯 call site(4 API)는 모두 `sourceContext(slip)`를 전달하며, 각 call site에서 context를 임시 제거했을 때 구계약 fail-fast가 RED가 됐다. 실제 Desktop 입고 완료도 journal에 `slip_id`와 `slip_revision`을 남겼다.

그러나 R2가 변경한 정방향 호출 계약에 맞춰 관련 slip 테스트를 재수렴시키지 않아, 관련 묶음이 **84건 중 21건 실패**한다. 머지 시 검증 게이트가 깨지는 현재 HEAD는 머지할 수 없다.

## 6. 수정 뒤 revision 판본

격리 fixture의 날짜/상태를 테스트 가능한 값으로 준비한 뒤 실제 audit overlay PATCH로 memo를 수정했다.

```text
PATCH /slips/fe24bb02-9e6f-4e41-854f-58d24bbc75c2/audit/overlay -> 200
revision_count: 0 -> 1
POST /slips/fe24bb02-9e6f-4e41-854f-58d24bbc75c2/complete -> 200 (0.078233s)
```

완료 직후 원문:

```text
slip:    fe24bb02-9e6f-4e41-854f-58d24bbc75c2 | INSPECTING | revision_count=1
journal: a449bea9-a0a0-4c2c-a0d4-3a470aff6454 | fe24bb02-9e6f-4e41-854f-58d24bbc75c2 | slip_revision=1 | APPLIED
```

따라서 저장된 revision은 최초 판(0)이나 완료 후 임의 판이 아니라 **재고 작업 시점의 현재 판 1**이다.
