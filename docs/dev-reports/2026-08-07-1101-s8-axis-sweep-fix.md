## RED-A — 고치기 전 원문

수정 전 `DEV_PASSWORD`가 unset인 조건에서 세 Playwright spec을 실제 실행했다. 모두 login 요청까지 도달했다.

```text
dispatch-collab-codex-round.spec.ts
Error: token: {"success":false,"code":"INVALID_INPUT","message":"password: size must be between 8 and 100",...}

dispatch-collab-real-qa.spec.ts
Error: token: {"success":false,"code":"INVALID_INPUT","message":"password: must not be blank",...}

kst-verification.spec.ts
Error: token: {"success":false,"code":"INVALID_INPUT","message":"password: size must be between 8 and 100",...}
```

원인은 세 파일 모두 `process.env.DEV_PASSWORD ?? ''`를 login body에 넣었기 때문이다. `DEV_PASSWORD`는 unset이고 빈 값이 gateway로 전달됐다.

## RED-B — 고치기 전 원문 및 기준

자격 불필요 CI 경로를 loader import만으로 차단하면 안 된다는 기준이다. S7에서 `.env.local` 부재를 주입한 loader 계약 테스트와 desktop CI 등가 실행을 확인했다.

```text
두 입력이 없으면 경로와 누락 키를 포함해 fail-fast한다 — PASS
Error code: QA_CREDENTIAL_MISSING
Error message includes: .env.local, QA_DEV_DEFAULT_PASSWORD

CI 등가: Vitest 212 files / 1,951 tests PASS
web tsc: exit 0
```

즉, RED-B의 실패 조건(자격 불필요 파일이 loader 호출로 막힘)은 수정 전에도 재현되지 않았다. S8에서는 import 자체가 자격을 읽지 않고 호출 시점에만 fail-fast하는 기존 loader 계약을 유지했다.
