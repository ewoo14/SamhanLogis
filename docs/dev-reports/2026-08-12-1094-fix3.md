## ① 금액 유실 원인 확인 및 되돌림

### 확인한 원인

입금보고서 목록 `CashReceiptListPage.tsx`에 다음 fix2 코드가 있었다.

```text
const frame = window.requestAnimationFrame(restore)
const delayed = window.setTimeout(restore, 100)
...
window.clearTimeout(delayed)
```

이 지연 재복원은 목록 복귀 시 같은 anchor를 두 번 쓰는 변경이며, 편집 폼의 DB hydrate 자체(`row.amount -> String(row.amount)`)와 무관한 추가 타이밍 경로였다. 사용자 지시대로 이 변경분만 되돌렸다.

되돌림 diff:

```diff
 const frame = window.requestAnimationFrame(restore)
-const delayed = window.setTimeout(restore, 100)
 return () => {
   window.cancelAnimationFrame(frame)
-  window.clearTimeout(delayed)
 }
```

### 견적 편집 저장 history

다음 계약을 소스·라우팅 테스트로 단정했다.

```text
EstimateFormPage: navigate(..., { replace: true })

✓ 견적 편집 저장은 상세를 replace하고 목록 버튼은 history를 한 칸만 되감는다
```

따라서 목록 → 상세 → 편집 → 저장에서 편집 entry가 별도 history로 남지 않으며, 상세의 `← 목록`은 한 번만 history를 되감는다.
