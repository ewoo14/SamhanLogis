## 2. 금액 및 잔액 불변성

실측 기준선은 활성 분개라인 309건, 차변 `597,211,068원`, 대변 `597,211,068원`, 대차 `0원`이다. 매핑 적용은 `account_code`만 바꾸므로 금액·journal·partner·source·status가 보존되면 차변·대변 합계와 journal별 대차는 바뀌지 않는다. 분할 판정이 생기면 어떤 라인을 어느 계정으로 보낼지 별도 업무 기준이 반드시 필요하지만, 각 원본 라인의 차·대변 금액 자체는 그대로여야 한다.

코드 수준 이카운트 치환이 확정된 141라인과, 이카운트 코드는 알려졌지만 **실제 거래 성격이 미정**인 3라인은 아래와 같다.

| fold | 판정 | 라인 | 차변 | 대변 | 순액(차변-대변) |
|---|---|---:|---:|---:|---:|
| `110 → 1089` | 확정 | 99 | 526,330,034원 | 14,259,034원 | 512,071,000원 |

표준 의미 분할 대상은 `142 건물` 5라인과 `210 미지급금` 1라인이다. 병합 대상은 `220·255 부가세예수금` 41라인이다. 어느 판정이든 **계정코드만 바뀌어야 하고 잔액이 변하면 결함**이다. 모든 조회 경로가 새 코드를 인식하기 전에 데이터 코드만 바꾸면 화면 표시 잔액이 누락될 수 있으므로 구현 단계에는 전후 라인 수·차변·대변·journal별 대차를 동시에 검증해야 한다.

## 3. 실행 SQL과 출력 원문

### 3.1 현재 전 목록별 사용 건수·금액

```sql
WITH active_lines AS (
  SELECT jl.*
  FROM journal_lines jl
  JOIN journals j ON j.id=jl.journal_id
  WHERE jl.is_deleted=false AND j.is_deleted=false
)
SELECT coa.code, coa.name,
       COUNT(al.id) AS usage_count,
       COALESCE(SUM(al.debit_amount),0) AS debit_sum,
       COALESCE(SUM(al.credit_amount),0) AS credit_sum
FROM chart_of_accounts coa
LEFT JOIN active_lines al ON al.account_code=coa.code
WHERE coa.is_deleted=false
GROUP BY coa.code,coa.name,coa.display_order
ORDER BY coa.display_order,coa.code;
```

## 4. 이카운트 체계와 어긋나 PM이 다시 확인할 항목

이번 판정은 개발책임자 지시대로 한국 표준회계를 근거로 닫았다. 다만 이슈 제목의 “이카운트 체계로 전환”과 아래 항목은 아직 목표 코드 수준에서 어긋난다.

1. `201`: 이카운트 `2519 외상매입금`은 알려졌지만 실제 3라인이 유류비·차량임차비라 표준상 외상매입금인지 기타미지급금인지 미정이다.
2. `220·255`: 표준상 같은 부가세예수금이므로 병합 판정했으나 이카운트에서 유지할 단일 목표 코드는 아직 없다.
3. `142`: 표준상 건물과 감가상각누계액-건물을 분리해야 하나 이카운트 누계액 목표 코드가 없다.
4. `210`: 실제 라인은 미지급 법인세이므로 일반 미지급금과 분리해야 하나 이카운트 미지급법인세 목표 코드가 없다.
5. `900`: 표준 표시상 영업외수익과 영업외비용을 분리해야 하나 이카운트 상위계정 구조는 확인되지 않았다.

구현 전 개발책임자 결정이 필요한 것은 맨 앞의 🚩미정 5건과 위 목표 코드 4종(`부가세예수금`, `감가상각누계액-건물`, `미지급법인세`, 영업외수익·비용 상위계정)이다.
