## 0. 🚩 미정 목록 — 개발책임자 결정 게이트

저장소의 `docs/`·`migration/`·시드와 이카운트 importer 자료를 먼저 검색했으나, 운영 정본인 이카운트 `계정상세내역` 전 목록은 없다. `docs/migration/ecount-data/raw/`에는 `.gitkeep`만 있고, `staging.ecount_account_raw`와 `staging.ecount_account_map`도 0건이다. 테스트 fixture `services/accounting-service/src/test/resources/ecount-raw-fixtures/account.csv`에는 importer 형식 검증용 `00010 출자금` 한 행만 있어 운영 전 목록의 근거로 쓸 수 없다.

저장소 결정문으로 이카운트 정본 코드와 명칭이 명시된 것은 세 계정이지만, 현재 코드에서 실제로 치환할 대상으로 정찰 정본이 확정 후보로 닫은 것은 두 대응뿐이다.

- `110 외상매출금 → 1089 외상매출금`
- `401 상품매출 → 4019 상품매출`

`2519 외상매입금`은 이카운트 정본 코드라는 사실만 확정됐다. 그러나 정찰 정본이 현재 `201` 3라인을 “8코드 매핑 대기”로 분류했으므로 `201 → 2519` 치환은 전 목록 대조 전까지 🚩 미정이다.

나머지 현재 계정은 이카운트 코드·명칭, 이카운트에만 있는 신설 계정, 1:N 분할 및 N:1 병합 여부를 판정할 원본이 없어 모두 `🚩 미정`이다. 이 표를 최종 확정하려면 인터넷 추정이 아니라 실제 이카운트 `계정상세내역-Excel다운로드.csv` 또는 동등한 운영 export를 먼저 확보해야 한다.

현재 77개 판정 집계는 `확정 2개 / 🚩 미정 75개`다. 이카운트 원본 자체가 없어 `분할/병합/신설/폐지`를 0개로 확정한 것이 아니라 **판정할 수 없는 상태**다.

### 3.3 목록 완전성

WITH active_lines AS (
  SELECT jl.* FROM journal_lines jl
  JOIN journals j ON j.id=jl.journal_id
  WHERE jl.is_deleted=false AND j.is_deleted=false
)
SELECT COUNT(*) AS active_accounts,
       COUNT(*) FILTER (WHERE EXISTS (SELECT 1 FROM active_lines al WHERE al.account_code=coa.code)) AS used_accounts,
       COUNT(*) FILTER (WHERE NOT EXISTS (SELECT 1 FROM active_lines al WHERE al.account_code=coa.code)) AS unused_accounts
FROM chart_of_accounts coa WHERE coa.is_deleted=false;

WITH active_lines AS (
  SELECT jl.* FROM journal_lines jl

)
SELECT al.account_code,COUNT(*) AS lines,SUM(al.debit_amount) AS debit_sum,SUM(al.credit_amount) AS credit_sum
