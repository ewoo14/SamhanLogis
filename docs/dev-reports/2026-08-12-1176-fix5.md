## 원인과 수정

기존 `verify-and-repair.sql`은 slip 테이블 전체에서 QA 표지 총계만 세어 대상 누락과 대상 외 오표지가 상쇄되면 정상으로 판정했다. 실행 SQL이 확보한 전표 295건·라인 636건의 ID를 `qa_residue_target_snapshot`에 파일 경유 복제본에서 저장하고, 점검은 이 스냅샷과 교집합으로 다음을 별도 집계한다.

- 대상 전표/라인 총수와 대상 내부 QA 표지 수
- 대상 내부 드리프트 수(`is_deleted`이나 QA 표지가 아닌 행)
- 대상 외 QA 표지 수
- 드리프트 전표 번호·`is_deleted`·`deleted_by` 원문 출력

유효 토큰 복구는 partner 대상과 slip 스냅샷 대상만 되살리고, 대상 외 QA 표지는 명시된 QA 표지로만 복구한다. 라인은 스냅샷 636개 ID로 제한했다.

실행 SQL로 정상 삭제 상태를 만들고, 다음 SQL로 대상 전표 1건 표지를 드리프트시키고 대상 외 전표 1건에 QA 표지를 붙였다.

```sql
WITH drift_target AS (
  SELECT id FROM slips
  WHERE is_deleted AND deleted_by = 'qa-residue-softdelete-2026-08-12'
  ORDER BY slip_no LIMIT 1
)
UPDATE slips s
SET deleted_by = 'qa-reconv4-compensated-drift', deleted_by_name = 'reconv4 drift'
FROM drift_target t WHERE s.id = t.id;

WITH replacement AS (
  SELECT s.id FROM slips s
  WHERE NOT s.is_deleted
    AND NOT EXISTS (SELECT 1 FROM slip_lines l WHERE l.slip_id = s.id AND l.is_deleted AND l.deleted_by = 'qa-residue-softdelete-2026-08-12')
  ORDER BY s.slip_no LIMIT 1
)
UPDATE slips s
SET is_deleted = TRUE, deleted_at = clock_timestamp(),
    deleted_by = 'qa-residue-softdelete-2026-08-12', deleted_by_name = 'QA residue soft-delete'
FROM replacement r WHERE s.id = r.id;
```

## 종료 정리

- 공유 `samhan-postgres`에는 쓰지 않았다.
- 복제 직후와 복구 후 UTF8·한글 SELECT를 확인했다.
- `fix5-1176-pg` 격리 컨테이너를 제거하고 `.qa-temp-fix5-1176` dump/재현 파일을 제거했다.
- 격리 advisory lock은 검증 종료 시 사용하지 않는 상태였다.
- TCP 단절 backend의 12,231ms 차단 한계는 이번 fix5에서 변경하지 않았다.
- 삭제된 추적 파일은 확인되지 않았다. git 명령 금지에 따라 복구가 필요한 삭제 파일은 없었으며, 필요 시 복구는 `git add -f` 규율을 따른다.
