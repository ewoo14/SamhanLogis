### 분리할 것

- **무분류 source의 업무 의미론** — R29 계약은 source를 “네 부자재 분류에 속하지 않을 것”이라는 negative로 정의했으므로 `classificationName=null`도 형식상 source 통과가 의도된 결과다. 현재 세 지원 카테고리의 무분류 노출 품목은 0행이라 현 DB 상태에서 직접 선택 가능한 표본도 없다. 무분류를 source에서도 거부하려면 “본체”의 positive 분류 축이 먼저 필요하므로 이번 봉쇄 결함과 분리한다. 단, 기존 규칙 source를 부자재로 바꾸는 사후 변경은 현재 계약상 명백한 위반이므로 지금 고칠 범위다.
- **target 검색 사전 필터** — `clients/desktop/src/renderer/routes/EstimateItemsCatalogPage.tsx:1153-1159`는 전체 품목 검색을 사용하므로 무분류 1,942행도 검색·선택할 수 있다. 그러나 저장은 `QuantitySyncRuleValidator.java:401-408`에서 거부되고, `EstimateItemsCatalogPage.tsx:1039-1041`, `1520-1523`이 서버의 `target은 허용된 부자재 역할이어야 합니다.`를 화면 alert로 표시한다. 잘못 저장되거나 조용히 실패하지 않으므로 이번 도달 결함으로 지시하지 않는다.
- 분류 마스터 중복 정리, legacy 계산기, 직접 SQL·시더·마이그레이션으로 만든 비정상 데이터, 기존 1,942행의 분류 보강은 범위 밖이다.

## ② 불변식

1. 활성 규칙의 source와 target은 규칙 저장 직후뿐 아니라 그 규칙이 활성인 모든 시점에 현재 품목 역할 계약을 만족해야 한다.
2. 활성 규칙 target은 항상 `GOODS`이며 현재 L분류명이 `부자재`, `판넬`, `실외기 받침`, `실외기 받침대` 중 하나여야 한다.
3. 활성 규칙 source는 현재 L분류명이 위 네 이름 중 어느 것도 아니어야 한다.
4. 품목 또는 분류 마스터 변경으로 1~3이 깨지는 상태는 커밋되어서는 안 되며, 실패 시 품목·분류·규칙 모두 변경 전 상태여야 한다.
5. 비활성 규칙과 규칙에 참조되지 않은 품목은 위 봉쇄의 반대급부로 정상적인 분류·상품유형 편집을 잃지 않아야 한다.

## ③ 양방향 RED

### RED-A — 활성 target의 사후 역할 변경

- 실제 모델 `AJ020BN1PBC1 -> AXJ-YA1509N` 활성 규칙을 저장한 뒤 `AXJ-YA1509N.catL=null` 변경을 시도하면 충돌로 거부되고, 품목 분류와 규칙 graph는 변경 전과 exact 같아야 한다.
- 같은 규칙에서 `AXJ-YA1509N.goodsType=NON_GOODS` 변경도 거부되고 원자적으로 원복되어야 한다.
- 허용 L분류 이름 자체를 비허용 이름으로 바꾸어 참조 target의 역할을 깨는 변경도 거부되어야 한다.

**RED-A 반대급부**

- 동일한 분류·상품유형 변경을 규칙에 참조되지 않은 품목에 수행하면 성공해야 한다.
- `enabled=false` 규칙만 참조하는 품목은 정상 편집 가능해야 한다.
- 활성 target을 `GOODS`로 유지하면서 네 허용 이름 중 다른 이름 또는 같은 이름의 다른 L분류로 옮기는 변경은 막히지 않아야 한다. 네 개 `부자재` UUID의 이름 기반 허용 계약도 유지되어야 한다.

### RED-B — R26 두 원형의 저장 후 복원 우회

- 실제 `AJ040MXHNBC1`을 허용 target 상태로 둔 채 `AJ020BN1PBC1 -> AJ040MXHNBC1` 활성 규칙을 저장한 다음, `AJ040MXHNBC1`을 실외기로 복원하려 하면 거부되어야 한다. 거부 후 규칙과 품목은 저장 직후의 유효 상태여야 한다.
- 실제 `AIM-H04N -> AJ020BN1PBC1` 규칙을 저장 가능한 역할 상태로 만든 뒤 활성 규칙을 저장하고, source를 부자재로 또는 target을 실내기로 복원하려 하면 각각 거부되어야 한다.
- create와 replace 모두에서 처음부터 위 두 R26 입력을 보내면 지금처럼 저장 자체가 거부되어야 한다.

**RED-B 반대급부**

- 실제 일곱 target `FH-LFHLN`, `PC1NWSK3NW`, `AWR-WE13N`, `AXJ-YA1509N`, `SI-AL600A`, `발통세트`, `AWR-WV00N`은 현재 분류·`GOODS` 상태에서 create와 replace target으로 계속 통과해야 한다.
- 가정용 에어컨·실내기·실외기 등 비부자재 source와, R29의 negative 계약상 무분류 source는 같은 category·활성·표시 조건을 만족하면 계속 통과해야 한다.
- target 검색에서 무분류 또는 비허용 품목을 선택해 저장하면 규칙은 생성되지 않고 기존 화면 alert 메시지가 유지되어야 한다.

## ④ 범위 밖

- source 역할을 negative에서 positive allowlist로 재설계하는 업무 결정과 본체 분류 마스터 신설.
- 관리자 target 검색의 사전 필터·검색 UX 개선. 서버 거부와 사용자 메시지가 유지되는 한 별도 개선이다.
- 분류 마스터의 동명 UUID 통합·이관, 전체 무분류 1,942행의 데이터 정비.
- legacy 수량 계산기 재검토, Docker 재배포·서비스 재시작·브라우저 라이브 QA.
- DB 직접 INSERT/UPDATE, 테스트 전용 seed·migration을 일반 사용자 저장 경로로 간주하는 확대.
