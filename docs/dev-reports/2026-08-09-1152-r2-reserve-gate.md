# PR #1152 R2 — 예약 단계 NON_GOODS 게이트

## 결론

SOL 진단은 맞았다. `StockService.reserve()`가 상품 선언을 확인하지 않고 balance를 먼저 조회해, 재고 0인 NON_GOODS 라인을 `"가용 재고가 없습니다: 해당 제품의 입고 이력이 없습니다"` CONFLICT(409)로 차단했다.

수정은 기존 `isInventoryExcluded(ProductSummary)` 축을 그대로 사용했다. 이름/카테고리 문자열로 새 판정하지 않았다.

## ① 쓴 게이트와 대조

- 수량 예약: `services/inventory-service/src/main/java/com/samhanair/logis/inventory/service/StockService.java:236-240`에서 기존 `isInventoryExcluded(...)`를 balance 조회보다 먼저 호출한다.
- 같은 클래스의 기존 입고 게이트: `StockService.java:187-191`.
- 같은 클래스의 기존 차감 게이트: `StockService.java:340-342`.
- 같은 클래스의 기존 조정 게이트: `StockService.java:392-395`.
- 인스턴스 단계의 동일 의미 게이트: `StockInstanceService.java:75-76, 110-111, 156-158, 199-201, 225-227, 256-258, 355-357, 386-388`.
- 판정식 자체는 기존 코드 `StockService.java:507-508`, `StockInstanceService.java:452-453`의 `!product.goods() || productType == BUNDLE` 축이다. 이번 변경에서 새 판정식은 추가하지 않았다.

수량 예약의 NON_GOODS 결과는 `ReservationResponse(quantity=0, availableQty=0, reservedQty=0)`이며 balance·movement를 만들지 않는다. 예약 보상 해제도 같은 no-op을 사용해, 수락 중 후속 GOODS 실패 시 NON_GOODS 해제가 다시 404/409를 만들지 않게 했다.

## ③ 양방향 RED → 동시 GREEN

### RED-A

수정 전 `reserve_nonGoods_skipsWithoutBalanceOrMovement`가 다음 기존 예외로 실패했다.

```text
BusinessException: 가용 재고가 없습니다: 해당 제품의 입고 이력이 없습니다
```

이는 실제 경로의 `accept → inventoryClient.reserve() → HTTP 409`와 같은 원인이다. 수정 후 `StockServiceTest.reserve_nonGoods_skipsWithoutBalanceOrMovement`가 GREEN이고, 반환 수량/잔량은 0이며 balance 조회와 movement 저장은 0회다.

### RED-B

기존 GOODS 부족 테스트 `StockServiceTest.reserve_insufficient_throwsConflict`는 수정 전에도 다음 계약을 검증했다.

```text
BusinessException.errorCode == CONFLICT
```

수정 후에도 GREEN이다. `StockServiceTest`/`StockInstanceServiceOutboundTest`와 `*Reserve*/*Stock*` 묶음에서 GOODS 예약 및 부족 차단이 유지됐다. 즉 게이트가 GOODS 경로를 우회시키지 않는다.

### 혼합 라인 실측

`StockServiceTest.reserve_mixedGoodsAndNonGoods_reservesGoodsAndSkipsNonGoods`에서 같은 전표 참조(`SLIP`)로 GOODS 2개와 NON_GOODS 1개를 순서대로 예약했다.

- GOODS: `reservedQty=2`, RESERVE movement 1건.
- NON_GOODS: `quantity=0`, `reservedQty=0`, balance 조회·movement 저장 없음.
- 두 라인이 함께 처리되어 GOODS는 예약되고 NON_GOODS는 건너뛴다. 이 동작이 slip accept의 혼합 라인 계약을 최종 inventory 게이트에서 보장한다.

serial 혼합 호출의 기존 회귀도 `SlipServiceTest.accept_outbound_mixedSerialAndBatch_routesSerialInstancesAndBatchReserve`로 유지했고, slip-service 단위 묶음이 GREEN이다.
