- 화면 결과: 로그인 성공 후 `배차안내 SMS` 메뉴가 노출됐다. 실행 화면 진입도 됐고, `저장내역` 탭도 노출됐다. 탭을 클릭하자 URL 변경 없이 저장내역 조회 화면이 렌더됐으며 `저장내역이 없습니다.`가 표시됐다. 접근 거부/권한 없음 화면은 없었다.
- 판정: **실패**. V92가 DB 권한 정본의 활성 grant를 0건으로 만들었음에도, 권한을 갖고 있던 `dev_dispatch` 계정이 삭제 대상 발송이력 화면에 실제 접근할 수 있다. 실행 화면과 저장내역 탭 모두 메뉴·클릭·렌더가 가능했다.
- 캡처: 로그인 후 메뉴 상태 `docs/qa/1013-dispatch-inherit-real-qa/09-revoked-account-dashboard.png`, 실행 화면 접근 `10-revoked-account-dispatch-attempt.png`, 저장내역 접근 결과 `11-revoked-history-tab.png`.

## 시나리오 8 — 자동 SMS 미발송

- 발화 조건: QA 전표 5건이 미리보기 가능한 상태. 자동 발송을 유발할 수 있는 `미리보기` 클릭만 수행하고, `내역으로 저장`은 클릭하지 않았다.
- 조작: `dev_master` 로그인 → 배차안내 SMS 화면 진입 → 배차일 `2026-08-03` 입력 → `미리보기` 클릭 → 버튼 목록과 브라우저의 실제 gateway 요청을 관찰.
- 화면 결과: 미리보기 전후에 `내역으로 저장`, `미리보기`, `선택 복사`만 있었고 `문자 보내기`·`SMS 발송`·`발송하기` 버튼은 없었다.
- 네트워크 결과: GUI 조작 중 gateway에 `/send`, `/aligo`, `messages/sms` 대상 요청은 0건이었다. 미리보기/저장내역 관련 요청만 관찰됐다. 이는 실제 SMS 외부 발송 성공을 뜻하지 않으며, 자동 발송 트리거가 없다는 범위의 증거다.
- 판정: **성공(자동 SMS 미발송)**.
- 캡처: `docs/qa/1013-dispatch-inherit-real-qa/12-no-auto-sms.png`.

## QA 실행 데이터 후속 확인

- QA throwaway 전표 5건은 모두 남아 있으며 기존 행은 수정·삭제하지 않았다. 최종 활성 OUTBOUND는 115건, 주소 8건, 인수자번호 6건, 하차일 5건, `delivery_tag` 0건이다.
- preview 클릭 과정에서 notification_db에 `AUTO_LATEST` 저장 이력 9건이 생성됐다. 현재 active 1건, soft-deleted 8건이며 `SEND_AUDIT` 행은 없었다. 이는 화면 preview의 저장 이력 동작으로 생성된 QA 산출물이며, SMS 외부 발송은 아니다.
- 생성·관찰한 모든 전표와 이력은 보고서에 식별 정보를 남겼다. 기존 실 전표·마스터·설정·권한은 수정·삭제하지 않았다.
