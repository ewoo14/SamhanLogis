## 결론

fix1의 코드 결함 1~5를 수정했다. 사람에게 보이는 actor 문자열은 `ActorDisplayName`(BE) 또는 `safeActorName`(FE)을 통과하며, UUID의 canonical·32hex·중괄호·URN·zero-width 변형과 앞 8자 절단값을 표시하지 않는다. `system`은 화면에서 기존 표기인 `시스템`으로 통일했다.

6번은 코드 결함이 아니라 라이브QA 전제 오류다. 로그인은 `dev_master.last_login_at`을 갱신하는 write이므로 공유 gateway/DB에 로그인하지 않았다. real-QA 스펙도 격리 API 주소가 없으면 fail-closed 하도록 바꿨다. 이 실행 환경에는 `REAL_QA_ISOLATED_API_BASE_URL`이 없고 공유 gateway `127.0.0.1:8080`만 확인되어, 실제 로그인·스크린샷 QA는 의도적으로 실행하지 않았다. 기존 `last_login_at`은 되돌리지 않았다.

## 수정 내용

- 홈택스 history/exclusion DTO는 표시 component를 `String`으로 반환하고 `ActorDisplayName.resolve`를 사용했다. `TaxInvoiceBatch.processedBy` entity UUID와 BaseEntity audit 키는 변경하지 않았다.
- 6개 협업 controller의 약한 `UUID_SHAPE`를 제거하고 공통 resolver로 통일했다. presence 요청의 displayName도 같은 경계를 통과한다. callerId/actorId 및 soft-delete 역추적 흐름은 원문으로 service/port/entity에 전달한다.
- design-system `safeActorName`에 canonical, raw32, brace canonical/32hex, URN canonical/32hex, zero-width 정규화를 추가했다. `system`은 `시스템`, 정상 이름은 원문 보존, unsafe 값은 호출부에서 `변경자 미상`으로 표시한다.
- desktop의 홈택스 이력, 협업 패널 6종, 공동편집 배지, presence, 배차 코멘트/상세, generic audit, version history, print approval 표시 출구에 safe guard를 연결했다.
- auth-service 권한 변경 로그는 `actorName`만 resolver 결과로 기록한다. `actorId`는 `updatePermission`, `markDeleted`, audit/reverse 경로에 그대로 보존된다.
- real-QA 스펙은 디렉터리와 파일명이 모두 `-real-qa`이고 `resolveQaShotsDir()`를 사용한다. 로그인은 격리 API 환경변수 없이는 실행되지 않으며, login 전에 inventory GET의 HTTP 503을 검사한다. Playwright 자체를 쓰며 Codex 내장 브라우저는 사용하지 않았다.

## 불변식 확인

- 정상 이름은 보존한다: `김감사` 등 known name 테스트 GREEN.
- `변경자 미상` 기존 표현을 유지한다.
- SYSTEM 화면 표기는 `시스템` 하나로 통일했다. BE 내부 토큰 `system`은 내부 계약으로 남고 화면 경계에서 변환된다.
- actorId/callerId/soft-delete 키/역추적 경로를 삭제하거나 마스킹하지 않았다.
- 라이브QA 로그인으로 공유 DB에 새 write를 만들지 않았다. 따라서 기존 `dev_master.last_login_at`을 되돌리는 작업도 하지 않았다.
