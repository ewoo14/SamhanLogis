## 3. 가드 순서 결정

결정: `load → optimistic version → 타입/라이프사이클·완전 잠금 guard → dispatch-group reference guard → mutation`.

두 가드가 함께 걸리면 전표의 현재 상태/마감 잠금 이유를 먼저 반환한다. DELIVERED/INSPECTING/SHIPPING은 사용자가 삭제할 수 없는 더 정확한 원인이며, 그룹 참조 여부를 먼저 반환하면 기존 lock 계약을 깨고 일반적인 그룹 메시지로 원인이 흐려진다. 기존 도메인 삭제 동작은 `validateDeleteForPurchase`/`validateDeleteForSales`로 비변경 사전 검증을 분리했고, 실제 mutation 메서드는 동일 검증을 다시 수행해 기존 단독 호출 계약도 보존했다.

기존 스펙이 지키던 계약은 두 층으로 분리했다.

- `UnassignedPage`와 `DispatchReconcilePage`는 여전히 공통 저장 이력·복원 계약(`dispatchSaveHistoryApi`, `HistoryTab`, `RestoredBanner`, `maskCreatedBy`)을 단언한다.
