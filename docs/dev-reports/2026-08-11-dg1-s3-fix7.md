제약: `playwright.config.ts` 변경 금지, production source 변경 금지, git 조작 금지, 기존 QA 서버 유지

## 1. 수정 내용

기존 live 스펙은 mock 설정의 `testIgnore` 규약인 `**/*-real-qa/**`에 맞지 않는 디렉토리에
있었다. 공유 real-QA 설정은 파일명도 `*-real-qa.spec.ts`로 수집하므로 디렉토리와 파일명을
함께 규약에 맞췄다.

```text
이전
clients/desktop/playwright/2026-08-11-dg1-s3-fix/s3-fix-live.spec.ts

이후
clients/desktop/playwright/2026-08-11-dg1-s3-fix-real-qa/s3-fix-real-qa.spec.ts
```

실행 명령과 경로를 참조하는 계획서·기존 S3 개발/재검토 보고서도 새 경로로 갱신했다.
`clients/desktop/playwright.config.ts`는 변경하지 않았고, production source diff도 없다.

## 2. PR 추가 스펙 전수 확인

PR #1168의 base(`9b804493c`)부터 HEAD까지 Playwright 아래 신규 스펙을 전수 확인한 결과는
다음 1개뿐이다.

```text
A clients/desktop/playwright/2026-08-11-dg1-s3-fix/s3-fix-live.spec.ts
```

따라서 같은 누수 가능성이 있는 다른 신규 스펙·디렉토리는 발견되지 않았다.


이 로컬에는 사용자가 지정한 기존 QA 서버 PID `71632`가 살아 있어 live 스펙 자체는

동일하게 재현할 수 없었다. 다만 mock 설정이 이 파일을 수집한 사실과 guard의 unexpected는
실제로 확인했다.

## 4. RED-A live 원문

공유 real-QA 설정의 파일명 수집 규약까지 맞춘 뒤, 기존 서버를 재사용해 실행했다.

실행 명령:

```powershell
$env:REAL_QA_ALLOW_UNTRACKED='1'
$env:REAL_QA_RENDERER_BASE_URL='http://127.0.0.1:5193'
$env:AUDIT_BASE_URL='http://127.0.0.1:5193'
npx playwright test --config=playwright.real-qa.config.ts `
  'playwright/2026-08-11-dg1-s3-fix-real-qa/s3-fix-real-qa.spec.ts' `
  --workers=1 --project=renderer --reporter=line
```

원문 핵심:

```text
Running 9 tests using 1 worker
...
9 passed (18.5s)
```

`--list` 원문도 다음과 같이 1파일 9개를 확인했다.

```text
Listing tests:
...
Total: 9 tests in 1 file
```

미커밋 워크트리이므로 `REAL_QA_ALLOW_UNTRACKED=1`을 사용했다. PM commit 이후에는 같은
명령에서 해당 환경변수를 제거하면 된다.

mock hard-gate 통과를 주장하지 않는다.
