# 2026-08-02 #1012 입출고 내역·분석 구현 기록

## 착수 및 설계

- 범위: 입출고 내역 화면, 모델별 칩 필터, 매입가·판매가 차액 기반 품목별 이익률.
- 이익률은 판관비 배부 없이 `판매금액 - 매입금액` 기준으로 계산한다.
- 확정 판매는 원가가 없어도 목록에 남기고 이익률은 `—`로 표시한다.
- 구매예측, Notion 저장 계열, Docker 재빌드·재기동, 실 DB 쓰기는 범위에서 제외한다.

## RED 테스트 추가

- `inoutAnalysisModel.test.ts`에 원가 없는 판매 품목 1건이 목록에 남고 이익률 표시가 `—`인 경로를 추가했다.
- 매입금액 100, 판매금액 125에서 이익금액 25, 이익률 25.00%가 되는 차액 기준 테스트를 추가했다.
- 구현 전 Vitest 실행으로 기능 부재에 의한 실패를 확인한다.

## 구현

- slip-service에 `GET /slips/query/inout-analysis`를 추가했다. 확정 입고·출고 전표를 모델코드별로 합산하고, 공급가액 기준으로 `판매금액 - 매입금액`과 이익률을 계산한다.
- 매입 기록이 없는 판매 품목은 `purchaseAmount/profitAmount/profitRate = null`로 유지해 화면 행을 보존한다.
- product-service 요약의 `categoryKey`를 연결해 모델별 칩 판정에 사용한다.
- 데스크톱 `/inventory/inout-analysis` 라우트·사이드바·조회 API·칩 필터·이익률 표를 연결했다. 화면에는 UUID 대신 모델코드만 표시한다.

## 컴파일 보완

- slip-service 테스트 컴파일에서 기존 `ProductSummary` 10-인자 생성자 사용처가 확인되어 `categoryKey` 추가 전 호환 생성자를 복원했다.
- 입출고 전표가 0건인 기간에는 product-service batch 조회를 호출하지 않도록 빈 품목 목록 가드를 추가했다.

## TypeScript 보완

- `filterInOutRows`를 제네릭으로 바꿔 분석 행의 이익률 필드를 보존한다.
