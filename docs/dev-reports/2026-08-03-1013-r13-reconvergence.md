## 7. 판정 전 자문 — “이 라운드가 안 본 것이 있나?”

**있다.** 다음은 결함 0 판정에 포함하지 않은 표면이다.

1. 현재 소스의 notification/slip 서비스를 새로 빌드·배포한 뒤 실제 데스크톱 브라우저/Electron에서 `/arologis/dispatch-sms`를 조작하는 live QA. 이미지 빌드·배포·재기동 금지 때문에 수행하지 않았다.
2. 현재 실 DB에는 mapped OUTBOUND 0건, 인수자번호 보유 OUTBOUND 0건이어서 실제 업무행으로 단톡방/인수자번호 그룹의 rowspan 편집 차이를 조작하지 못했다. 해당 규칙은 레거시 원문·composer 소스·단위 테스트로만 확인했다.
3. 기존 `SEND_AUDIT` 행을 넣은 PostgreSQL에 V7을 실제 적용하는 migration 실험. 공유 notification_db는 이력 0행이고 mutation 금지이며, 기존 Testcontainers IT도 빈 스키마부터 V7을 적용한다. 과거 행 보존은 SQL 순서와 source 계약까지만 확인했다.
4. 공유 auth_db에 V92를 실제 적용한 사후 조회. 공유 DB mutation 금지 때문에 사전 41행 계수 + 격리 Testcontainers 사후 5개 정본 0으로 나눠 확인했다.
5. R11 당시 VIEW 세 번째 보유자의 현재 상태. 공유 DB가 `25/3/1`에서 `10/2/1`로 변해 동일 사용자를 다시 식별할 수 없었다.
6. 실제 Aligo/SMS 외부 발송, 성능·대량 처리, 테스트 강도·문서 과장·가드 구멍. 이번 유일 각도와 사용자 금지 범위라 조사하지 않았다.

또한 현재 `samhan-slip-service`·`samhan-accounting-service`는 다른 PR #1061 브랜치 배포본이므로 **그 두 컨테이너의 응답은 어떤 판정 증거에도 사용하지 않았다.** 실 slip 영향 건수는 `samhan-postgres`의 `slip_db` read-only SQL로만 셌다.
