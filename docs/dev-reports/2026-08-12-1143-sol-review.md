# PR #1187 (#1143) 적대검증 보고서

## 결론

**실 사용자 경로로 재현 가능한 결함이 있다.**

기초품목 세트 구성품 화면에서 V39 적용 후 기존 세트를 열고 구성 내용은 바꾸지 않은 채 저장하면, V39가 백필한 `AUTO 4 + AUTO 6` 가격 계약이 HTTP 200 응답과 함께 `FIXED + 비중 NULL`로 소실된다. 현 `BundleExpander`는 신규 컬럼을 아직 소비하지 않으므로 이번 검증의 즉시 견적/전표 금액은 변하지 않았지만, 개발책임자가 확정한 자동/고정·비중 계약은 실제 편집 한 번으로 파괴된다.

기존 싱글세트 271건의 현재 전개 금액은 직접 전수 비교했고 **변경 0건**이다.

## 발견 결함

### F-1 [HIGH] 기초품목의 무변경 저장이 AUTO 비중 계약을 FIXED로 바꾼다

실 사용자 경로:

1. V37 실데이터를 파일 덤프로 격리 DB에 복원한다.
2. V38(Java) → V39(SQL)를 실제 Flyway 순서로 적용한다.
3. 기초품목 세트 `AC110CAMDHH1SY`의 구성품을 조회한다.
4. 현 데스크톱 `ProductFormPage`가 실제로 보내는 필드만 사용해 그대로 저장한다.
5. HTTP 응답과 DB 값을 확인한다.

V39 직후 값:

```text

AC110BXADHH1 | OUTDOOR | AUTO | 6 | NULL
```

### F-2 [LOW] 비중 합 오류가 사용자 입력 오류가 아니라 HTTP 500으로 노출된다

정상 `AUTO 4 + AUTO 6`은 HTTP 200으로 저장됐고, 명시한 고정금액 `12,345.67`, `23,456.78`도 값 그대로 보존됐다. 반면 `AUTO 4 + AUTO 5`는 검증 메시지까지 도달했지만 HTTP 500이었다.

```text
NORMAL_SUM10_HTTP=200 ROWS=4
BAD_SUM9_HTTP=500

java.lang.IllegalArgumentException: 자동 구성품 비중 합은 10이어야 합니다.
    at com.samhanair.logis.product.service.BundleAllocationPolicy.validate(BundleAllocationPolicy.java:40)
    at com.samhanair.logis.product.service.BundleComponentService.replaceComponents(BundleComponentService.java:298)
```

정책 검증이 `BusinessException(INVALID_INPUT)`이 아니라 처리되지 않는 `IllegalArgumentException`을 던져 잘못된 입력이 400이 아닌 서버 장애로 보인다.

## 나머지 관문

### 비중 합 10과 고정금액

```text
single_sets=271 | auto_sum_10=271 | auto_sum_bad=0 | min_sum=10 | max_sum=10
NORMAL_SUM10_HTTP=200
AUTO 4 + AUTO 6 저장 성공
```

비중은 `Integer` 계약이므로 소수 입력은 정상 입력 범위가 아니다. 정수 합 10은 막히지 않았다.
