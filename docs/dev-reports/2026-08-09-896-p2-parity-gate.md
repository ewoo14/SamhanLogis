# #896 P2 — 세트 전개 상세행 parity 게이트 재검증

작성일: 2026-08-09
대상: PR #1146, `feat/896-p2-parity-gate`

## 결론

`feature`와 `isDefault`는 비교 대상에서 다시 제외했다. 커밋된 골든에서 두 필드가 전 행 기본값이라 비교 신호가 없기 때문이다. 게이트는 `single=226/226`, `commercial=86/86`, 차이 0건으로 다시 통과했다.

다만 이 통과는 비교 대상 필드 범위에 한정된다. 출력에 다음 미검증 축을 명시했다.

```text
uncovered: feature · isDefault — 골든 전 행이 기본값이라 판정 불가
```

PM 측정값을 커밋된 골든에서 독립 재현했으며, PM 수치와 일치했다. 따라서 이번 라운드에서는 측정 오류나 별도 P0 캡처 누락 가설을 확인하지 못했다.

## ① `feature`·`isDefault` 제외 근거

게이트의 `FIELDS` 주석과 비교 목록을 다음 근거로 되돌렸다.

```js
// feature/isDefault 는 골든 전 행이 기본값('' / false)이라 비교 신호가 없다.
//   single 682행 · commercial 170행 모두 feature 비어있음 · isDefault=false
// 게이트 쪽 정규화는 원천 메타데이터에서 값을 채우므로 비교하면 682건이
// 무의미한 차이로 잡힌다. 골든이 이 축을 담게 되면 다시 넣는다.
```

측정 명령:

```powershell
node --input-type=module -e "import fs from 'node:fs'; const g=JSON.parse(fs.readFileSync('docs/qa/896-p0-golden-manifest/golden/02-set-expansion.json','utf8')); for (const [name,sets] of Object.entries(g)) { const parts=sets.flatMap(s=>s.parts||[]); console.log(name, 'sets='+sets.length, 'partRows='+parts.length, 'featureNonEmpty='+parts.filter(p=>p.feature!=='').length, 'isDefaultTrue='+parts.filter(p=>p.isDefault===true).length); }"
```

측정 결과:

```text
single sets=226 partRows=682 featureNonEmpty=0 isDefaultTrue=0
commercial sets=86 partRows=170 featureNonEmpty=0 isDefaultTrue=0
```

정규화 게이트 쪽은 원천 메타데이터에서 `feature`·`isDefault` 값을 채우므로, 이 축을 골든과 비교하면 single 파트행 682건과 정확히 일치하는 무의미한 차이가 발생한다. 골든이 이 정보를 담게 되면 비교 필드를 다시 추가한다.

```text
sets: single=226/226, commercial=86/86
PASS: 전개 상세행 0건 차이
```

범위 밖 21개 탭 출력과 빈칸=0/빈칸≠0 결과 기록은 그대로 유지했다. 이 게이트가 검증하는 것은 정규화 manifest의 싱글·상업 세트 전개 상세행이며, 전체 물리 탭 전수의 parity가 아니다.

## 발견 — P0 골든이 `isDefault` 축을 담지 못했다

열린 이슈 `#1089`는 “삼한 퍼블릭 세트 전개는 기본 구성품만”이다. 구성품이 기본인지가 전개 포함 여부를 가른다. 그런데 커밋된 골든의 `isDefault`는 852행 전부 `false`다.

```text
single 682행 · commercial 170행 · 합계 852행
isDefault=true: 0행
feature 비어있지 않음: 0행
```

따라서 이 게이트는 `#1089`의 기본 구성품 축을 검증하지 못한다. 그 축을 검증하려면 골든이 `isDefault` 정보를 담아야 한다. 현재 게이트의 PASS를 전체 업무 규칙 검증 완료로 읽어서는 안 된다.

## 뮤테이션 RED 원문

비교 대상 필드인 `unitPrice`와 `subtotal`을 커밋된 골든의 복사본에서 각각 1 변경했다. 원본 골든에는 쓰지 않았다.

```text
sets: single=226/226, commercial=86/86
FAIL: 차이 2건
- 세트=AC060CS6PBH1SY 모델=AC060CN6PBH1 필드=unitPrice 기대=606001 실제=606000
MUTATION_EXIT=1
```

테스트 내부의 actual 자기대조도 확인했다.

```text
NORMAL_SELF_COMPARE: differences=0, exit=0
price mutation: unitPrice +1, subtotal +1
RED: unitPrice 차이 감지, exit=1
```
