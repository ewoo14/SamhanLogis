# #896 P2 — 세트 전개 상세행 parity 게이트

작성일: 2026-08-09

## 결론

적재 전 고정 카탈로그 manifest를 입력으로 실행했고 싱글 226세트와 상업 86세트가 `golden/02-set-expansion.json`과 차이 0건으로 통과했다. 골든 복사본의 단일 값을 1원 변조했을 때는 차이 1건과 종료코드 1로 실패했다. 커밋된 골든은 변조하지 않았다.

이번 수단은 기존 `qa-gas-parity-sim.mjs`의 레거시 소스 추출/VM 실행 접근을 재사용했다. 기존 시뮬레이터 자체는 분류기 parity와 단가 함수 소스 동일성만 검사하고 세트 전개 골든을 대조하지 않으므로, 싱글의 `explodeSetParts()` 본문을 레거시 HTML에서 실행 시 추출하고 필요한 DOM/전역 의존성은 기본 옵션으로 주입하는 최소 실행기를 추가했다. 상업 세트는 manifest의 세트-구성품 관계와 레거시 출력 필드 계약으로 결정적으로 정규화했다.

## 실행 장치

```powershell
node clients/web/estimate-app/qa-set-expansion-parity-gate.mjs
```

기본 입력은 다음 커밋 파일이다.

- source: `docs/qa/896-p0-golden-manifest/input-manifest.jsonl`
- golden: `docs/qa/896-p0-golden-manifest/golden/02-set-expansion.json`

source 교체 계약:

```powershell
node clients/web/estimate-app/qa-set-expansion-parity-gate.mjs --source=<catalog-manifest.jsonl>
```

source 행은 P0 manifest의 `catalog-row` 계약을 따른다. DB adapter는 아직 연결하지 않았으며, 적재 후 DB 조회 결과를 같은 행 계약으로 변환해 `createCatalogSource()`에 공급하면 된다. 이번 라운드에는 DB 접근을 하지 않았다.

## 비교 정의

레거시 전개 함수가 반환해 실제 인쇄하는 상세행을 세트 순서와 부품 순서까지 고정해 비교한다.

| 범위 | 필드 |
|---|---|
| 세트 | `model`, `name`, `quantity`, `error` |
| 상세행 | `model`, `name`, `kind`, `unit`, `quantity`, `unitPrice`, `subtotal`, `spec` |

`feature`와 `isDefault`는 P0 카탈로그 메타데이터지만 레거시 반환 인쇄행에는 포함되지 않아 판정 필드에서 제외했다. `price`는 `unitPrice`로 정규화하고 `subtotal`은 `unitPrice × quantity`로 정규화한다. 누락·추가 세트와 상세행도 `setCount`/`partCount` 차이로 실패한다.

차이 출력 형식:

```text
- 세트=<세트 모델> 모델=<상세 모델> 필드=<필드> 기대=<값> 실제=<값>
```

## 정상 실행 원문

```text
== #896 P2 세트 전개 상세행 parity gate ==
source: docs/qa/896-p0-golden-manifest/input-manifest.jsonl
golden: docs/qa/896-p0-golden-manifest/golden/02-set-expansion.json
sets: single=226/226, commercial=86/86
PASS: 전개 상세행 0건 차이
```

프로세스 종료코드: `0`

## 뮤테이션 RED 증명

커밋 골든을 `_local`로 복사한 뒤 첫 싱글 세트의 첫 상세행 `unitPrice`만 `606000 → 606001`로 바꿔 실행했다. 커밋 골든에는 쓰지 않았다.

```text
== #896 P2 세트 전개 상세행 parity gate ==
source: docs/qa/896-p0-golden-manifest/input-manifest.jsonl
golden: docs/qa/896-p0-golden-manifest/_local/02-set-expansion-mutated.json
sets: single=226/226, commercial=86/86
FAIL: 차이 1건
- 세트=AC060CS6PBH1SY 모델=AC060CN6PBH1 필드=unitPrice 기대=606001 실제=606000
MUTATION_EXIT=1
```

게이트가 차이를 잡고 non-zero로 실패함을 확인했다.

## 복구 증명

뮤테이션 복사본의 `_local` 디렉터리를 삭제한 뒤 원본 골든에 대해 다시 실행했다.

```text
RESTORE_DIFF_EXIT=0
RESTORE_GATE_EXIT=0
```

`RESTORE_DIFF_EXIT=0`은 다음 명령의 커밋 골든 diff가 비어 있음을 뜻한다.

```powershell
git diff -- docs/qa/896-p0-golden-manifest/golden/02-set-expansion.json
```

복구 후 게이트도 `PASS: 전개 상세행 0건 차이`였다.

## 재현성·쓰기 안전성

- source와 golden은 repository-relative 경로로 해석하며 절대경로를 하드코딩하지 않았다.
- 로그에 기록하는 논리 경로는 POSIX 구분자로 고정한다.
- 실행기는 커밋 골든을 쓰지 않는다. 뮤테이션 검증도 `_local` 복사본만 사용했다.
- 입력·전개 순서를 유지하고 차이 출력 순서도 결정적이다.
- 실행 시각, OS 경로 구분자, DB/Google Sheets 상태에 의존하지 않는다.

## 아직 못 하는 것

- DB 카탈로그 조회 adapter는 인터페이스만 열려 있고 구현하지 않았다.
- 실제 Google Sheets 접근은 하지 않았다. 커밋된 manifest와 골든만 읽었다.
- 옵션을 바꾼 전개 parity는 범위 밖이다. 기본 옵션(자재 미포함, 기본 판넬/리모컨)만 검사한다.
- VAT·수량 파생·화면 레이아웃 parity는 기존 별도 골든 장치의 범위다.
