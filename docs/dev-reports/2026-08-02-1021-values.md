# #1021 거래처 값 대조 3차

## 실제 컬럼

- `partner_db.partners` 컬럼(49개, 순서대로): `id`, `partner_code`, `biz_no`, `name`, `address`, `phone`, `credit_limit`, `outstanding_balance`, `status`, `created_at`, `created_by`, `modified_at`, `modified_by`, `deleted_at`, `deleted_by`, `is_deleted`, `sub_biz_no`, `representative`, `business_type`, `industry`, `fax`, `email`, `email2`, `mobile`, `zip_code1`, `address1`, `zip_code2`, `address2`, `search_keyword`, `partner_group1`, `partner_group2`, `website`, `currency`, `shipment_target`, `sales_type`, `purchase_type`, `receivable_no_mgmt`, `payable_no_mgmt`, `outbound_adjustment_rate`, `inbound_adjustment_rate`, `sales_price_group`, `purchase_price_group`, `credit_period_days`, `payment_due_days`, `registration_date`, `transfer_info`, `note`, `manager_name`, `deleted_by_name`.
- `dc_config_db.partners` 컬럼(17개, 순서대로): `id`, `partner_code`, `biz_no`, `name`, `address`, `phone`, `manager`, `partner_group`, `credit_limit`, `remark`, `created_at`, `created_by`, `modified_at`, `modified_by`, `deleted_at`, `deleted_by`, `is_deleted`.
- 같은 컬럼명의 공통 필드는 14개다: `id`, `partner_code`, `biz_no`, `name`, `address`, `phone`, `credit_limit`, `created_at`, `created_by`, `modified_at`, `modified_by`, `deleted_at`, `deleted_by`, `is_deleted`.
- 실제 두 `partners` 테이블에는 `default_discount_rate` 등 이름의 기본 할인율 컬럼이 없다. `partner_db`의 기본 할인율은 별도 `partner_price_discounts.basic_discount_rate`에 있고 `dc_config_db.partners`에는 대응 컬럼이 없으므로, 이번 두 `partners` 테이블 사이에서 기본 할인율 값은 대조할 수 없다.
- 공통 `id`는 UUID이므로 사용자 비공개 원칙에 따라 값 대조·표본 표시 대상에서 제외하고, 행 연결에는 `partner_code`만 사용한다.

## 비교 규칙

- 활성 행(`is_deleted = false`) 210건을 저장된 `partner_code` 완전일치로 연결한다.
- 문자열 원문 비교는 DB에서 읽은 값을 그대로 완전일치 비교하고, 문자열 정규화 비교는 `trim → 모든 공백 제거 → 소문자화 → ASCII 하이픈(-) 제거` 순서로 비교한다.
- `NULL` 또는 양끝 공백 제거 후 빈 문자열은 “값 없음”이며, 양쪽 모두 값 없음은 일치, 정확히 한쪽만 값이 있으면 “한쪽만 값 있음”, 양쪽에 값이 있지만 서로 다르면 “불일치”로 센다.
