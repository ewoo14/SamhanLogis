“거래처가 비어 있음”을 어느 컬럼으로 정의할지는 업무 판단이므로 단일 숫자로 추론하지 않았다. 사용자에게 아무 거래처도 보이지 않는 엄격한 교집합은 63건이다.

SQL 원문:

```sql
BEGIN TRANSACTION READ ONLY;

SELECT
  COUNT(*) FILTER (WHERE slip_type = 'OUTBOUND') AS outbound_slip_rows_all,
  COUNT(*) FILTER (WHERE slip_type = 'OUTBOUND' AND is_deleted = FALSE) AS outbound_slip_rows_active,
  COUNT(*) FILTER (
    WHERE slip_type = 'OUTBOUND'
      AND is_deleted = FALSE
      AND status IN ('DRAFT', 'SAVED')
  ) AS outbound_editable_active
FROM slips;

SELECT
  COUNT(*) AS outbound_line_rows_all,
  COUNT(*) FILTER (WHERE s.is_deleted = FALSE AND l.is_deleted = FALSE) AS outbound_line_rows_active
FROM slip_lines l
JOIN slips s ON s.id = l.slip_id
WHERE s.slip_type = 'OUTBOUND';

SELECT
  COUNT(*) AS outbound_active,
  COUNT(*) FILTER (WHERE partner_id IS NULL) AS partner_id_null,
  COUNT(*) FILTER (WHERE partner_code IS NULL OR btrim(partner_code) = '') AS partner_code_blank,
  COUNT(*) FILTER (WHERE partner_name IS NULL OR btrim(partner_name) = '') AS partner_name_blank,
  COUNT(*) FILTER (
    WHERE partner_id IS NULL
      AND (partner_code IS NULL OR btrim(partner_code) = '')
      AND (partner_name IS NULL OR btrim(partner_name) = '')
  ) AS all_partner_fields_blank
FROM slips
WHERE slip_type = 'OUTBOUND' AND is_deleted = FALSE;

SELECT
  COUNT(*) AS outbound_editable_active,
  COUNT(*) FILTER (WHERE partner_id IS NULL) AS partner_id_null,
  COUNT(*) FILTER (WHERE partner_code IS NULL OR btrim(partner_code) = '') AS partner_code_blank,
  COUNT(*) FILTER (WHERE partner_name IS NULL OR btrim(partner_name) = '') AS partner_name_blank,
  COUNT(*) FILTER (
    WHERE partner_id IS NULL
      AND (partner_code IS NULL OR btrim(partner_code) = '')
      AND (partner_name IS NULL OR btrim(partner_name) = '')
  ) AS all_partner_fields_blank
FROM slips
WHERE slip_type = 'OUTBOUND'
  AND is_deleted = FALSE
  AND status IN ('DRAFT', 'SAVED');

ROLLBACK;
```

## 업무 판단이 필요해 추론하지 않은 질문

1. 판매전표 헤더의 **전잔**은 `#1061` 원장의 어느 날짜 범위를 호출해 얻는 값인가. 전표일 직전일 잔액인지, 화면 조회 시점의 현재 잔액인지 명시가 필요하다.
2. **후잔**은 저장된 현재 전표가 이미 원장 집합에 포함된 경우 그 원장 `closingBalance`를 그대로 보이는가, 아니면 저장 응답의 해당 전표 효과를 별도 합성하는가. 중복 합산 금지 기준이 필요하다.
3. 자동채움은 사용자가 이미 입력한 전화번호·주소·대표자·특이사항을 거래처 재선택 시 덮는가. 최초 빈 값만 채우는가.
4. “거래처가 비어 있는 전표”의 업무 기준은 `partner_id`, `partner_code`, `partner_name` 중 무엇인가. 세 필드 모두 빈 63건만을 의미하는가.
5. `partner-service.outstandingBalance`와 accounting 원장 잔액이 다를 때 어느 값을 고치거나 폐기할지. 현재 명시 계약은 accounting이지만 상충 Javadoc/도메인 모델이 남아 있다.
6. 상세의 기존 inline direct-edit를 확장할지, 이슈 제목대로 별도 `/sales/:id/edit` route를 신설할지. 현재 코드는 전자를 이미 제공하지만 이슈는 후자를 명시한다.
7. 신규 trailing draft 행은 이슈에 적힌 대로 Y.Doc 밖 로컬 행으로 유지하되, 다른 사용자가 품목을 확정한 순간 어느 이벤트에서 Y.Doc 행으로 승격할지.

## 착수 시 밟을 지뢰

- 브랜치가 main보다 101커밋 뒤다. `#1156`의 `partnerCode`/사업자번호 분리 결과를 복제하거나 이 브랜치 코드 기준으로 덮으면 식별자 혼재 결함을 되살린다.
- `SlipDetailPage` 품목 셀은 현재 자유 문자열이다. 여기에 선택기 외형만 넣고 `productId`·가격·BUNDLE·VAT·note·lineId 계약을 함께 hydrate하지 않으면 `#1071`에 기록된 6개 도달 결함을 재현한다.
- 자동 빈행은 화면별 배열 append가 아니라 `autoBlankRow.ts` 공통 계약이다. 특히 삭제 후 trailing 행 보존과 최소 1행을 함께 지켜야 한다.
- 저장 제외 공식은 세 곳(합계, payload, 저장 가능 행수)에 반복 고정돼 있다. 한 곳만 바꾸면 화면 합계·전송·버튼 활성화가 갈라진다.
- 협업 draft를 숫자 index로 `setItemValue`하면 로컬 빈행이 Y.Doc에 생길 수 있다. `CollaborativeSlipInput.setProviderValue`의 비정규 lineId no-op 경계를 보존해야 한다.
- 전잔·후잔 산식을 `slip-service`나 프런트에서 다시 만들면 집계·상세·인쇄·snapshot과 숫자가 갈라진다. accounting read model/공통 fold를 소비해야 한다.
- 실 DB의 과거 이슈 수치(수정 가능 2,174건)는 현재 값이 아니다. 현재 활성 DRAFT/SAVED는 281건이며, 삭제된 DRAFT가 2,143건이다.
