# PR #1078 · 이슈 #1075 — S13 SOL fix 지시서

## 1. 좌표

**판정: 사용자 경로 재현 결함 1건 · BLOCK · 재현 난이도 쉬움(매회 재현). 머지 권고하지 않는다.**

견적 편집 화면에서 품목을 삭제하면 제거한 품목의 규격이 같은 라인과 coedit 문서에 남는다.

재현 경로(HEAD `49bc5f084` · Chromium mock):

1. `/sales/estimates/est-001/edit?mockRole=MASTER`로 진입한다.
2. 라인 1의 초기값 `AJ040RXH4BC1 / 시스템에어컨 4Way 4HP / 규격 4HP / 단가 1850000`을 확인한다.
3. 라인 1 모델명을 전체 선택해 삭제하고 blur한다.
4. 모델명과 품목명은 공란이 되지만 규격은 `4HP`로 남는다. 라인 2의 `MWR-WE10N / 220V`는 그대로다.

실측:

```text
before  line1 model=AJ040RXH4BC1 product=시스템에어컨 4Way 4HP spec=4HP price=1850000
        line2 model=MWR-WE10N spec=220V
after   line1 model='' product='' spec=4HP price=1850000
        line2 model=MWR-WE10N spec=220V
```

원인 좌표:

- `clients/desktop/src/renderer/routes/EstimateFormPage.tsx:1483`의 null 선택 해제 patch는 `productId`, `modelName`, `productName`, `productType`, `catalogUnitPrice` 등을 지우지만 `specification`을 다루지 않는다.
- 같은 함수의 coedit write(`EstimateFormPage.tsx:1501`)도 `modelName`, `productName`, `productId`, 조건부 `unitPrice`만 갱신하고 `specification`을 갱신하지 않는다.
- 반대로 품목 확정 경로는 `EstimateFormPage.tsx:1421`에서 규격을 로컬 라인에 쓰고 `EstimateFormPage.tsx:1447`에서 coedit 문서에도 쓴다. 확정 시 생성한 값을 해제 시 회수하지 않는 비대칭이다.
- `clients/desktop/playwright/1062-line-input-ux/1062-line-input-ux.spec.ts:97`의 S12 삭제 회귀 테스트는 모델명·품목명만 확인해 규격 잔존을 놓친다.

## 2. 불변식

- 품목 삭제 뒤 제거한 품목에서 자동 반영된 규격이 화면, 로컬 라인, coedit 문서 어느 곳에도 남아서는 안 된다.
- 해제는 대상 라인 하나에만 적용한다. 다른 라인의 값과 coedit 상태를 바꾸지 않는다.
- 자동가격만 해제하고 사용자가 직접 입력한 단가는 보존한다. 수량·금액 권위·라인 구조·다른 협업 필드까지 넓혀 지우지 않는다.
- 규격은 사용자가 직접 편집할 수도 있으므로, **품목에서 자동 반영된 규격과 사용자 입력 규격의 보존 정책을 구분**해야 한다. 이 구분 없이 모든 규격을 무조건 지우는 방식은 금지한다.
- 기존 coedit 계약인 값 변경 허용, 라인 추가·삭제 잠금, 신규 작성 자동 빈행을 유지한다.
- 해결 수단(상태 구조, provenance 표현, callback/API 형태)은 지시하지 않는다.

## 3. 양방향 RED

### RED-A — 결함 차단

1. 견적 편집 fixture의 확정 라인에 품목에서 자동 반영된 규격과 자동가격을 둔다.
2. 실제 `ProductAutocomplete`에서 확정 모델명을 삭제하고 blur한다.
3. 모델명·품목명·품목 식별자·품목 유형·카탈로그 단가·품목 유래 규격·자동가격 상태가 같은 라인의 로컬 값과 coedit 값에서 해제됐음을 단정한다.
4. Chromium 경로에서도 `라인 1 규격`이 제거 전 `4HP`, 제거 후 공란임을 단정한다.

### RED-B — 반대급부

1. 라인 1을 해제해도 라인 2의 모델명·품목명·규격·단가와 coedit 값이 그대로임을 단정한다.
2. 사용자가 직접 입력한 단가와 사용자 입력으로 판정된 규격은 품목 삭제만으로 사라지지 않음을 단정한다.
3. 모달 없이 정확한 모델명 `AJ040RXH4BC1`을 입력하고 blur하면 정상 확정되는 반대 경로를 유지한다.
4. 부분검색 후보 모달 취소 뒤 품목·단가가 확정되지 않고, 후보 선택 시 실제 규격·단가가 반영되는 기존 경로를 유지한다.
5. 판매전표의 동일 공용 `ProductAutocomplete` 경로와 coedit 구조 잠금·신규 자동 빈행을 함께 회귀 단정한다.

## 4. 범위 밖

- Docker, DB, 백엔드 API, 배포는 조작하지 않는다.
- 다른 트랙 `#1057`, `#1066`, `#1069` 파일은 수정하지 않는다.
- 판매전표의 독립 정책을 견적에 맞추기 위한 별도 리팩터링은 하지 않는다. 공용 컴포넌트 변경이 필요하면 판매전표 반대급부를 먼저 고정한다.
- S13에서 확인한 F1 모달 전환 blur 차단, 정상 exact blur 확정, 후보 1건 자동 확정, 후보 모달·UUID 비노출, 라인 격리, coedit 구조 잠금은 변경 범위를 넓힐 근거가 아니다.

안 본 범위: 실 백엔드·DB, Docker 배포, 모바일 실기기, 다른 트랙. 전체 202-file Vitest와 659-test Playwright는 S13에서 재실행하지 않았고, 관련 좁은 게이트만 실행했다.
