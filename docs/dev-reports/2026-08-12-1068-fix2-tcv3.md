## 결론

구현을 되돌리지 않고 TC-V3의 경로 기대값을 교정했다.

현재 SlipFormPage.tsx는 OUTBOUND 저장 성공 시 생성된 전표 ID로
/sales/{id} 상세 화면에 진입한다. 이는 다음 저장소 선례와 일치한다.

- SlipFormPage.tsx:1995: 신규 판매전표 저장 성공 → /sales/{created.id}
- EstimateFormPage.tsx:1729: 신규 견적 저장 성공 → /sales/estimates/{created.id}
- SalesQueryPage.tsx:330,480,802: 목록의 상세 진입 → /sales/{row.id}
- #1094 결정: 상세 진입은 문서번호 하이퍼링크로 하고 상세에 뒤로 가기를 제공

따라서 사용자가 방금 만든 전표를 바로 보는 흐름이 이 저장소가 이미 선택한
동작이며, /sales 목록 기대는 회귀를 가리는 테스트 드리프트였다.

## 변경

clients/desktop/playwright/slip-form-v20/slip-form-v20-matching.spec.ts

- TC-V3의 저장 후 URL 기대를 /sales에서 /sales/{id}로 변경
- 생성 ID 1개 세그먼트를 검증하는 정규식 사용
- payload의 deliveryAddress·supervisionAddress 단언은 변경하지 않음

금액·전잔·후잔·원장 조회 코드는 변경하지 않았다.

## payload 단언 생존 증명 — mutation RED-B

payload 검증이 실제로 실행되는지 확인하기 위해 SlipFormPage.tsx의
deliveryAddress만 일시적으로 다음 값으로 변조했다.

~~~text
TC-V3 mutation — intentionally wrong payload
~~~

그 상태에서 TC-V3는 라우트를 통과한 뒤 다음 payload 단언에서 실패했다.

~~~text
Expected: 서울시 강남구 테헤란로 123
Received: TC-V3 mutation — intentionally wrong payload
~~~

확인 후 변조 코드는 즉시 원래 구현으로 복구했다. 최종 diff에는 변조가 남아
있지 않다.
