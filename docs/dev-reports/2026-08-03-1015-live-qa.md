첫 standalone 기동에서 저장소 기본 DB 설정으로 Flyway가 실행되어 공유 `partner_auth_db`에 V3(`partner auth access restore at`)를 자동 적용했다. 로그 원문은 다음과 같다.

이는 이번 작업 지시의 공유 DB DDL 금지 조건을 위반한 실행 하네스 부작용이다. 즉시 해당 프로세스를 중단했고, 이후 모든 재기동은 `SPRING_FLYWAY_ENABLED=false`, `SPRING_JPA_HIBERNATE_DDL_AUTO=validate`로 수행하여 추가 DDL을 차단했다. 이 사실은 결함/성공 판정과 별도로 기록한다.

## 3. 시나리오별 실화면 관찰

### 시나리오 1 — 대상 거래처 목록 및 건수

캡처: `docs/qa/1015-order-app-access-real-qa/01-target-and-deferred.png`

- 사이드바 판매 아래 `주문서 앱 접근권한 설정` 메뉴가 표시되고 화면 진입 가능했다.
- 화면 상단에 `전체 2건`이 표시됐다.
- 실제 화면 표에 dev 시드 거래처 2건이 표시됐다: `1068689215`, `2118712345`.
- 두 건 모두 승인 상태로 표시됐다.
- 장기미발주 후보 미리보기는 `현재 대상 0건`이었다.
- 후보가 0건인 것은 데이터가 없어서 단정된 결과가 아니라 주문·출고 원천 조회가 완료되지 않아 보류된 결과다. 따라서 빈 후보 목록 자체는 결함으로 세지 않는다.

### 시나리오 2 — deferred 표시 및 실패 원천

캡처: `docs/qa/1015-order-app-access-real-qa/02-intentional-downstream-failure-deferred.png`

- standalone backend의 다운스트림 URL을 의도적으로 잘못 주입한 뒤 화면을 새로 렌더했다.
- 화면에 `주문·출고 조회 실패로 2건의 판정이 보류되었습니다. (ORDER, SHIPMENT)`가 표시됐다.
- 보류 건수 `2건`과 실패 원천 `ORDER`, `SHIPMENT`가 모두 사용자 화면에 노출됐다.
- 화면 표의 거래처 2건은 유지됐고, 조회 실패를 장기미발주로 오판하여 후보에 넣지 않았다.
- JSON 응답, 브라우저 JSON 탭, 터미널 출력은 캡처하지 않았다.

정상 설정 시도에서도 두 공유 downstream의 활동 endpoint가 HTTP 500을 반환하여 동일한 보류 화면이 확인됐다. 별도로 의도적 URL 오류를 주입하여 보류 계약을 재현했다.

### 시나리오 3 — 관리자 복구

- 미실시.
- 복구/비밀번호 초기화는 공유 dev 시드 DB에 write가 발생하므로, 이번 라이브QA의 `공유 DB write/DDL 금지` 조건에 따라 클릭하지 않았다.

## 4. 판정

- 화면 진입 및 거래처 목록 표시: PASS — dev 시드 2건과 전체 건수가 화면에 표시됨.
- 핵심 보류 UI: PASS — 보류 2건과 실패 원천 `ORDER, SHIPMENT`가 실화면에 표시됨.
- 데이터 부재/배포본 나이 결함: 미판정 — standalone jar는 HEAD 증명이 되었고, 후보 0건은 원천 조회 보류에 의한 결과임.
- 관리자 복구: 미실시 — DB write 금지.
- 전체 라이브QA 게이트 판정: **조건부 PASS / 운영 반영 전 BLOCK**. 핵심 UI 시나리오는 통과했지만, 실행 중 공유 DB에 V3 DDL이 적용된 부작용이 있어 QA 환경 안전성 확인 없이 최종 게이트 통과로 처리하지 않는다.

## 5. 하지 못한 것

1. 관리자 복구/비밀번호 초기화 mutation은 공유 DB write 금지로 실행하지 않았다.
2. downstream 정상 응답 기반의 후보 `현재 대상 N건` 양성 사례는 확보하지 못했다. 정상 URL 설정에서도 공유 downstream 활동 endpoint가 HTTP 500을 반환했고, 실패를 활동 없음으로 세지 않고 deferred로 수렴했다.
3. in-app Browser 연결은 환경상 불가하여 Playwright headless fallback을 사용했다.
4. 첫 standalone 기동에서 Flyway V3가 공유 DB에 적용된 부작용이 발생했다. 이후 기동은 Flyway OFF + Hibernate validate로 중단했다.
