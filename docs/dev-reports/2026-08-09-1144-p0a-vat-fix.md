## 부분 배분 케이스

양수 원천 1,739,100원의 35% 배분인 608,685원을 사용했다.

```text
공급가액 553,350 · 부가세액 55,335 · 총금액 608,685
553,350 + 55,335 = 608,685
```

100% 배분에만 의존하지 않고 부분 배분을 공통 계산 테스트에 포함했다.

## 세율 구분

이 화면에는 `SalesTaxType = TAXABLE | ZERO_RATED | EXEMPT`가 이미 있고, 두 폼의 선택값이 요청의 `taxType`으로 전달된다. 없는 필드나 스키마는 만들지 않았다.

- `TAXABLE`: VAT 포함 총액을 110분의 100으로 공급가 분리
- `ZERO_RATED`, `EXEMPT`: 공급가=총액, VAT=0
- 실 데이터 표본: 진단 당시 활성 회계전표 0건, soft-delete 역사 표본 1건은 `TAXABLE`; `ZERO_RATED` 0건, `EXEMPT` 0건
- 따라서 실 데이터의 면세·영세율 금액별 판정은 **판정 불가**다. 다만 코드상 화면 구분값은 존재하며 해당 규칙을 적용한다.

## (b) 반올림 판단

기존 서버 계약과 같은 0 방향 절사를 사용한다. 과세 공급가액은 `floor toward zero(총액 × 100 ÷ 110)`이고, 부가세액을 `총액 - 공급가액`으로 계산하므로 항상 `공급가액 + 부가세액 = 총액`이다. 1원·10원·11원·100원, 330,000원 및 부분 배분 608,685원을 테스트했고 1원 어긋남은 재현되지 않았다.
