## 집합 분리 구현 확인

`[DEV-SEED/단위 fixture]` `RiUsageDecision`의 존재 집합을 `isPresentMain()`으로 분리하고 `INDOOR/OUTDOOR/SUB_INDOOR`를 포함시켰다. 실패 집합은 별도의 `isFailedMain()`으로 유지해 `INDOOR/OUTDOOR`만 검사한다. Q-only main + 미소비 자재는 `null`로 돌아가 기존 단가 판정을 유지한다.

`[DEV-SEED/단위 fixture]` Q partial + sibling REMOTE complete는 `true`, Q partial + sibling REMOTE incomplete는 `false`, Q 자기 미소비는 `false`를 유지한다. 수정 후 `RiUsageDecisionTest` 단독 패턴은 `BUILD SUCCESSFUL in 17s`로 통과했다.

## 조사 시작 확인

`docs/dev-reports/2026-08-03-874-r5-reconvergence.md` §2와 현행 `RiUsageDecision.java`를 읽었다. R5 결함은 `isFailedMain()`이 `sawMain` 계산에도 재사용되어 `SUB_INDOOR` 단독 main scope를 main 없음으로 처리하는 것이다. 레거시 원문 `Code.js:494-496`은 `INDOOR/OUTDOOR/SUB_INDOOR`를 `hasSingleMain`에 포함하고, `Code.js:697-700`은 `hasFailedMain`에 `INDOOR/OUTDOOR`만 포함한다. 이 두 집합을 분리해야 한다.

`[DEV-SEED/단위 fixture]` 조합 표를 기존 `DailyClosingDetailServiceTest.java:437-440`의 `AC023CN1DBC1` 기대값과 대조했다. 카탈로그 mock이 비어 있을 때 현행 `kindFor`/`kindByToken`의 `ACCESSORY` fallback으로 main 자기 판정이 도달하지 않아 `verified=true`가 되었고, 기존 기대 `false`와 충돌했다. 레거시 `Code.js:192-196`상 이 token은 `INDOOR`이므로 기존 테스트 기대값은 오답이 아니며, catalog 부재 시 레거시 classifier fallback을 연결해야 한다.
