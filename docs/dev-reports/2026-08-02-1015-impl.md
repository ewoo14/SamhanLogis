# 2026-08-02 #1015 주문서 접근권한 — 판정 기준 교정 구현 보고서

## 검증 방법 (구현 전 확정)

- 공유 실 DB는 `READ ONLY` 조회로 현재 대상 수만 확인한다. 현재 레거시 30일 대상이 0건이므로 이를 기능 성공 증거로 사용하지 않는다.
- RED-first 단위 테스트에서 주문 시각과 출고 시각을 각각 입력한다. 두 시각이 모두 30일 이전이면 후보, 둘 중 하나라도 최근이면 비후보가 되는 경계를 검증한다. 로그인/비밀번호 시각만 오래된 후보는 주문·출고 활동이 없을 때만 후보가 되어야 한다.
- 테스트용 활동 데이터는 합성하되, 실 API가 사용하는 주문·출고 활동 계약과 동일한 DTO/클라이언트 경계를 통과시킨다. 공유 Docker·실 DB 쓰기는 하지 않는다.
- 비밀번호 재설정은 기존 `PartnerAuthService`/`PasswordReset` 관련 테스트를 별도 실행해 판정 기준 변경의 영향을 받지 않음을 확인한다.

## 구현

- `PartnerActivityReader` 경계를 추가하고 주문·출고 소유 서비스에서 각각 마지막 주문 확정 시각과 마지막 OUTBOUND 전표일을 읽도록 연결했다.
- 장기미발주 후보는 `max(lastOrderAt, lastShipmentAt) + 30일 <= now`로 판정한다. `lastLoginAt`·`passwordChangedAt`은 이 판정에 사용하지 않는다.
- `/internal/partner-activity/{partnerCode}` 응답은 거래처코드 경로와 마지막 업무 시각만 사용하며 UUID·개인정보·상세 전표/주문은 반환하지 않는다. 내부 토큰 필터 경로(`/internal/**`)를 사용한다.
- 화면은 가변 로그인 기준 입력을 제거하고 `주문·출고 활동 없음 30일`을 명시했다. 비밀번호 초기화는 기존 단건 API를 그대로 호출한다.
- 승인 복구(`LONG_UNUSED → NEED_PW_INPUT`) 및 로그인·비밀번호 변경 도메인 코드는 변경하지 않았다.
