## 3. 하네스 형태 및 기존 스펙 무훼손 근거

대상 스펙의 이동 문자열은 변경하지 않았다.

```text
929-r5: page.goto(`${APP_BASE}/#${hashRoute}`)
929-r4: page.goto(`/#${hashRoute}`)
897:   page.goto('/#/accounting/bank-transactions') 등 HashRouter 경로
928:   page.goto('/')
```

서버 형태도 유지했다.

- `vite.renderer.dev.config.ts`: `127.0.0.1:5175`, HashRouter 스펙의 `/#/...` 이동 대상
- `vite.web.config.ts`: `base: '/'`, BrowserRouter 웹 표면의 `/` 이동 대상
- 공용 설정의 `AUDIT_BASE_URL` override로 실제 실행 시 각 서버 origin을 선택할 수 있다.

즉, 스펙의 목표 화면을 `/#/...`에서 `/...`로 바꾸거나 `/`를 해시 경로로 바꾸지 않았다. 이번 변경은 상대 URL을 해석할 origin만 제공한다.

`.github/workflows/arologis-ci.yml` 원문:

```yaml

      - 'services/arologis-service/**'
      - 'clients/arologis-desktop/**'

      - 'clients/arologis-mobile/**'
      - 'shared/**'

```

따라서 예를 들어 `services/arologis-service/src/main/...`만 변경한 PR은 이 워크플로를 트리거하고, 새로 추가한 두 가드 잡도 함께 실행한다.

### 공용 CI의 PR paths-ignore

`.github/workflows/ci.yml` 원문:

```yaml
pull_request:
  branches: [main]
  paths-ignore:
    - 'services/arologis-service/**'
    - 'clients/arologis-desktop/**'
    - 'clients/arologis-mobile/**'
    - '.github/workflows/arologis-ci.yml'
    - '.github/workflows/arologis-deploy.yml'
```

따라서 `services/arologis-service/**`, `clients/arologis-desktop/**`, `clients/arologis-mobile/**`만 바꾼 PR에서는 공용 CI가 트리거되지 않고 arologis CI의 두 가드가 1회씩 실행된다. 이번 변경 자체인 `.github/workflows/arologis-ci.yml` 변경도 arologis CI PR paths에 포함되고 공용 CI paths-ignore에 포함된다.
