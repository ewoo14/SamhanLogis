# #1069 S6 SOL fix 지시서 — 판매전표 세트 전개

## 판정

**재현 가능한 결함 1건 있음 — 머지 차단.** S4의 최근단가 대기 중 수량 `1→3`과 직접 입력 단가 경로는 각각 최신 값으로 전개 1회가 수행되어 닫혔다. 그러나 S5가 최신 행을 전개 요청에 쓰더라도, 응답 반영 단계가 선택 전 행의 규격을 fallback으로 사용해 **사용자가 지운 규격을 되살린다.**

협소 재현 결과:

```text
사용자 순서  거래처 선택 → 빈 행 규격 `현장규격` 입력 → BUNDLE 선택
             → 최근단가 응답 대기 중 규격을 빈 값으로 삭제 → 가격 응답 완료
전개 요청    specification: undefined                         (최신 삭제 반영)
화면 결과    specification: `현장규격`                        (삭제 전 값 부활)
RED 원문     expected '현장규격' to be ''
```

읽기 전용 실 DB 재계수는 활성 `OUTBOUND DRAFT` 중 현재 활성 product 기준 정상 `SINGLE 2,107행 / 2,100전표`, `BUNDLE 0행`으로 지시 기준값과 일치했다. 정상 SINGLE 차단 회귀는 발견하지 않았다.

## ① 좌표

### F1. 최근단가 대기 중 지운 부모 규격이 구성품 규격으로 부활한다

- 최신 전개 입력: `clients/desktop/src/renderer/routes/SlipFormPage.tsx:787-804`
  - `:794`는 사용자가 규격을 비우면 `specification: undefined`를 전개 API에 보낸다.
  - `:797-803`은 세대와 최신 BUNDLE 여부를 확인하므로 늦은 응답 자체는 최신 요청으로 재발행된다.
- S5 가격 대기 경로: `clients/desktop/src/renderer/routes/SlipFormPage.tsx:910-938`
  - `latestBundle`은 최신 삭제 상태를 가진다.
  - 그러나 `:937`에서 전개 함수의 첫 인수 `source`는 최신 행이 아니라 `applyProductSelection` 진입 당시의 `line`이다. 이 객체에는 삭제 전 `현장규격`이 남아 있다.
- 서버 응답: `services/slip-service/src/main/java/com/samhanair/logis/slip/web/SlipLookupController.java:68-75`
  - 구성품 자체 규격이 없고 요청 규격도 `undefined/null`이면 응답 규격은 `null`이다.
- 응답 적용: `clients/desktop/src/renderer/routes/SlipFormPage.tsx:735-778`
  - `:755`, `:765`가 응답 규격 `null`을 `source.specification`으로 대체한다.
  - 이 `source`가 선택 전 스냅샷이므로 사용자의 명시적 삭제를 과거 값으로 덮는다.

## ② 불변식 — 구현 수단 지정 금지

1. 전개 결과를 화면에 반영할 때 부모 규격의 권위는 해당 전개 요청에 사용된 최신 BUNDLE 행이어야 한다.
2. 사용자가 최근단가 또는 전개 응답 대기 중 부모 규격을 빈 값으로 지웠으면, 자체 규격이 없는 구성품의 화면 규격도 빈 값이어야 한다. 선택 전 값이 부활하면 안 된다.
3. 구성품 자체 규격이 있으면 계속 최우선이어야 하고, 최신 부모 규격이 비어 있지 않으면 자체 규격이 없는 구성품에 계속 승계되어야 한다.
4. 최신 규격 보존을 위해 같은 세트를 구성품 행으로 두 번 삽입하거나 전개 실패/BUNDLE 부모 잔존을 만들면 안 된다.
5. S4에서 닫힌 최근단가 지연 + 수량 `1→3`, 직접 입력 단가, 일반 SINGLE 교체 경로와 S2·S3의 BUNDLE 영속 차단을 되돌리면 안 된다.
6. `#1063` 자동 빈행 규약과 정상 OUTBOUND DRAFT SINGLE 입력·수정 허용을 유지해야 한다.

## ③ 양방향 RED — 반대급부 필수

### RED-B — 재발 금지

- 거래처 선택 → 부모 규격 입력 → BUNDLE 선택 → 최근단가 대기 중 규격 삭제 → 응답 완료에서 전개 요청 규격과 자체 규격 없는 구성품 화면 규격이 모두 빈 값이 아니면 RED.
- 같은 순서를 가격 응답 완료 후 전개 응답 대기 중 규격 삭제로 바꿔도 삭제 전 부모 규격이 부활하면 RED.
- 삭제 후 구성품 행이 한 벌을 초과하거나 BUNDLE 부모 행이 남으면 RED.

### RED-A — 반대급부 보존

- 부모 규격을 삭제하지 않은 기존 경로에서 자체 규격 없는 구성품이 최신 부모 규격을 승계하지 않으면 RED.
- 구성품 자체 규격이 부모 규격으로 덮이면 RED.
- 최근단가 지연 중 수량 `1→3` 또는 직접 입력 단가가 최신 값으로 전개되지 않거나 전개 호출이 0회/중복 행 삽입이 되면 RED.
- 늦은 성공·실패 뒤 일반 SINGLE 교체가 덮이거나, 정상 SINGLE 전체수정·모바일 생성이 BUNDLE로 오인 차단되면 RED.
- 전개 전후 trailing 빈행이 정확히 1개가 아니거나 의미 없는 빈행이 저장 payload에 포함되면 RED.

## ④ 범위 밖

- 견적·분개·이동·INBOUND 전체수정
- 세트 마스터, 구성품 데이터, 가격 배분 정책 변경
- 다른 트랙 `#1057`, `#1066`, `#1075`
- Docker 재빌드·재배포·중지, DB 쓰기, 전체 게이트
- 모바일 실기기와 공유 Docker 배포본의 HEAD 동일성 판정

안 본 범위: 실제 DB 쓰기를 동반한 PUT/POST, 브라우저 라이브QA, 견적·분개·이동·INBOUND, 범위 밖 트랙은 검증하지 않았다. 임시 RED는 실행 직후 제거했으며 제품·테스트 파일에 S6 진단 변경을 남기지 않았다.
