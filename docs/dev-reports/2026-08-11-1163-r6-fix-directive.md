# PR #1164 / 이슈 #1163 R6 수정 지시서

## 판정

도달 결함 2건. 마지막 H-2 fix 자체는 screenshot 목적지를 `resolveQaShotsDir(...)`로 감싼 것뿐이라 R4 단언을 완화하지 않았고, H-2는 직접 `62 passed`로 재현됐다. 그러나 R4 live spec이 자동으로 증명하는 범위가 R4 보고보다 좁으며, HashRouter base에도 숨은 실행 전제가 있다. 이 상태로는 `1 passed`가 나와도 “UUID actorName 감사행이 남아 있고 화면에는 변경자 미상으로 보인다”를 회귀 게이트로 고정하지 못한다.

제품 구현의 R1~R4 불변식은 표적 테스트와 정적 대조에서 살아 있다. 본 지시서는 R4 live spec과 그 실행 계약만 대상으로 한다.

## 결함 1 — HIGH: UUID 미노출만 단언해 행 소실·빈 표시도 green

### 좌표

- `clients/desktop/playwright/1163-r4-fix-review/1163-r4-readonly-live-ui.spec.ts:66-81`
- `clients/desktop/playwright/1163-r4-fix-review/1163-r4-readonly-live-ui.spec.ts:83-100`

스펙은 감사행이 있는 창고를 찾지만, 한 건도 못 찾았을 때 `auditRows.length > 0`을 단언하지 않고 첫 창고로 계속 진행한다. 최종 단언도 패널 전체에 canonical UUID가 없다는 것 하나뿐이다. 따라서 다음 회귀가 모두 green일 수 있다.

1. 감사행이 UI에서 통째로 렌더되지 않는다.
2. 변경자 라벨이 빈 문자열 또는 임의의 비UUID 문자열로 바뀐다.
3. 조회한 창고에 감사행이 하나도 없지만 빈 패널만 열린다.
4. API에는 UUID actorName 행이 있으나 그 revision과 다른 행만 UI에 남는다.

R5 직접 실행에서는 실 gateway 응답이 아래와 같았고 새 `_local` 캡처에는 `#1 · 변경자 미상`과 필드 변경행이 보였다. 하지만 이는 실행 로그와 사람이 읽은 캡처의 결합 증거이며 현재 자동 단언의 증거가 아니다.

```text
{"evidence":"REAL_LOGIN_REAL_GATEWAY_REAL_OLD_BACKEND_READ_ONLY","warehouseCode":"2","auditRowCount":1,"actorNames":["a0000000-0000-0000-0000-000000000001"],"fieldNames":["name"]}
1 passed (2.5s)
```

### 불변식

실 gateway에서 선택한 감사행은 같은 revision의 UI 행으로 계속 존재해야 한다. 그 행의 표시명은 입력에 따라 다음과 같아야 한다.

- system sentinel actorId → `시스템`
- null/blank/canonical UUID actorName → `변경자 미상`
- 그 외 정상 actorName → 원문 그대로

UUID 전체·앞 8자는 0회 노출이어야 하고, 이름을 비우는 것과 감사행 자체를 없애는 것을 같은 성공으로 취급하지 않는다.

### 양방향 RED

#### RED-A — 현재 오염 표본의 입력→출력 연결

- 실 API에서 선택한 UUID actorName 행의 `revisionNo`, `fieldName`, `actorId`, `actorName`을 보존한다.
- `edit-warehouse-audit-revision-${revisionNo}`가 실제로 존재해야 한다.
- 그 revision 안에 정확히 `변경자 미상`과 해당 변경 필드/값이 있어야 한다.
- revision 소실, 빈 라벨, 임의 라벨, UUID 전체·부분 노출은 모두 실패해야 한다.
- 감사행을 찾지 못했을 때 첫 창고의 빈 패널로 계속 진행해 green이 되면 실패다. 최소한 명시적 “live evidence 없음” 판정으로 종료해야 한다.

#### RED-B — 시점 상태를 정상 기대값으로 굳히지 않기

- 현재 `auditRowCount === 1`, 창고 코드 `2`, 현재 UUID 문자열을 기대값으로 박지 않는다.
- 페이지 전체를 순회해 임의의 사용 가능한 감사행을 고르고, 실제 API actor 값으로 기대 표시명을 도출한다.
- 향후 새 backend 배포로 actorName이 정상 이름이 되거나 system 행만 남아도 위 매핑대로 검증해야 한다. “UUID 오염값이 반드시 있어야 성공”이라는 단언을 두지 않는다.
- UUID/blank 방어의 결정론적 계약은 기존 `EditWarehouseModal.test.tsx`를 유지해 live DB 상태와 분리한다. live 표본 부재를 제품 성공으로 위장하지 않는다.

## 결함 2 — MED: 기본 APP_BASE가 HashRouter 경로를 만들지 못함

### 좌표

- `clients/desktop/playwright/1163-r4-fix-review/1163-r4-readonly-live-ui.spec.ts:9`
- `clients/desktop/playwright/1163-r4-fix-review/1163-r4-readonly-live-ui.spec.ts:91-93`

기본값은 `http://127.0.0.1:4174`인데 이동은 `${APP_BASE}/admin/warehouses`다. desktop은 HashRouter이므로 이 URL은 warehouse 화면이 아니라 dashboard를 연다. R5에서 기본값과 동치인 plain origin으로 직접 실행하면 실 로그인·실 gateway 조회까지 성공한 뒤 다음 원문으로 실패했다.

```text
{"evidence":"REAL_LOGIN_REAL_GATEWAY_REAL_OLD_BACKEND_READ_ONLY","warehouseCode":"2","auditRowCount":1,"actorNames":["a0000000-0000-0000-0000-000000000001"],"fieldNames":["name"]}
Locator: getByTestId('admin-warehouses-edit-2')
Expected: visible
Error: element(s) not found
1 failed
```

페이지 snapshot은 `창고관리`가 아니라 `대시보드`였다. `REAL_QA_RENDERER_BASE_URL=http://127.0.0.1:4174/#`를 숨은 전제로 주었을 때만 `${APP_BASE}/admin/warehouses`가 `/#/admin/warehouses`가 되어 통과했다.

### 불변식

스펙의 기본 실행과 명시적 renderer origin 실행 모두 같은 `/#/admin/warehouses` 화면에 도달해야 한다. 호출자가 URL 문자열 끝에 `#`을 정확히 붙여야만 성공하는 숨은 계약을 두지 않는다.

### 양방향 RED

#### RED-A — 기본값 단독 실행

- `REAL_QA_RENDERER_BASE_URL`을 주지 않거나 plain origin `http://127.0.0.1:4174`를 주어도 `admin-warehouses-edit-*`가 보여야 한다.
- dashboard가 뜨면 route 단언에서 즉시 실패하고, 30초 locator timeout까지 기다리지 않는다.

#### RED-B — 명시 base 호환

- plain origin과 기존 `http://127.0.0.1:4174/#` 입력을 하나의 route builder로 정규화한다.
- `/#/#/admin/warehouses`, `//admin/warehouses` 같은 이중 조립이 생기면 실패한다.
- API origin `127.0.0.1:8080`과 renderer origin을 합치거나 mock mode로 바꾸지 않는다.

## R1~R4 종합 확인

- 화면 UUID 폴백 제거: `displayWarehouseActor`가 UUID/null을 `변경자 미상`으로 표시한다.
- inventory callerId 미저장: callerId는 actorId 전용이며 actorName 폴백에 사용하지 않는다.
- `X-User-Name` 네 경로: PATCH, audit revert, DELETE, restore 모두 수신·service 전달한다.
- decode 정확히 1회: 공통 `UserHeaderDecodingFilter`만 decode하고 controller는 재decode하지 않는다.
- system sentinel은 `system`으로 저장되고 화면은 `시스템`이다.
- 정상 이름은 저장·화면에 원문 그대로 보존된다.
- 되돌리기는 `fieldName && fieldName !== 'isDeleted'` 조건을 유지한다.
- actorName이 null/UUID여도 recorder 호출은 유지되어 감사행 자체가 남는다.

## 반대급부

- 현재 UUID 한 값·창고 코드·행 수 1을 fixture처럼 박으면 향후 정상 이름 저장이 시작될 때 하네스가 죽으므로 금지한다.
- 반대로 “상태가 바뀔 수 있다”는 이유로 감사행 존재·선택 revision 표시를 단언하지 않으면 빈 패널도 green이므로 금지한다.
- live DB의 가변성과 UUID 방어의 결정론을 한 테스트에 억지로 결합하지 않는다. 고정 입력 계약은 unit/component test, live spec은 실제 선택 행과 UI의 대응을 검증한다.
- route를 맞추기 위해 mock server로 바꾸거나 API를 intercept하면 실 로그인·실 gateway read-only 증거가 사라지므로 금지한다.
