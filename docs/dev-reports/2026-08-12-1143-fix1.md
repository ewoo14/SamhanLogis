# PR #1187 (#1143) fix1 — 적대검증 결함 수정 보고서

## 결론

F-1 무변경/부분 저장 시 기존 AUTO 배분 계약이 FIXED로 소실되는 결함과 F-2 비중 합 오류가 500으로 노출되는 결함을 수정했다. 기존 요청에서 생략된 배분 필드는 동일 구성품의 기존 행에서 병합하고, 신규 행만 FIXED/납품가 기본값을 사용한다. 정책 오류는 `BusinessException(INVALID_INPUT)`으로 400 매핑된다.

공유 Docker 스택과 공유 DB에는 쓰기를 수행하지 않았다. Git 명령도 실행하지 않았다.

## 원인

- `BundleComponentRequest`의 호환 생성자가 배분 계약 필드 누락을 `FIXED`로 채웠다.
- `BundleComponentService.replaceComponents`가 누락된 mode/weight/fixed amount를 기본값과 구성품 납품가로 검증·저장했다.
- 프런트 `BundleComponentItem`/`BundleComponentInput` 및 `ProductFormPage` 저장 매핑이 신규 배분 계약 필드를 전달하지 않았다.
- `BundleAllocationPolicy.validate`가 `IllegalArgumentException`을 직접 던져 전역 catch-all 500으로 흘렀다.

## 수정 내용

- 기존 구성품을 component code로 인덱싱하고 요청 필드별로 기존 allocation 계약을 병합한다.
- 기존 AUTO 행의 비중과 `fixedAllocationAmount=NULL`을 그대로 보존한다.
- 기존 FIXED 행의 금액이 없거나 신규 행이면 구성품 납품가를 기본값으로 사용한다.
- 데스크톱 응답/요청 타입과 저장 매핑에 `allocationMode`, `allocationWeight`, `fixedAllocationAmount`를 연결했다.
- 비중/금액 정책 오류를 `BusinessException(ErrorCode.INVALID_INPUT, ...)`으로 변환했다.

## 2026-08-12 CI typecheck fix 후속

### CI 오류 원인 확인

`BundleComponentDraft = BundleComponentItem & { localId: string }`이며 `BundleComponentItem`에 fix1이 추가한 다음 필드가 필수다.

```text
allocationMode
allocationWeight
fixedAllocationAmount
```

`ProductFormPage.tsx:add()`의 새 구성행 객체가 이 3개 필드를 빠뜨려 CI와 동일한 오류를 로컬에서 재현했다.

```text
src/renderer/routes/ProductFormPage.tsx(914,15): error TS2345:
... is missing the following properties from type 'BundleComponentItem':
allocationMode, allocationWeight, fixedAllocationAmount
```

### 수정

새 구성행에 실제 필드를 명시했다. `as` 캐스팅은 사용하지 않았다.

```tsx
allocationMode: 'FIXED',
allocationWeight: null,
fixedAllocationAmount: null,
```

V39 기본 계약과 동일한 `FIXED`로 시작하며, 신규 행의 고정금액은 서버가 구성품 deliveryPrice로 확정한다. 따라서 기존 AUTO/비중 계약의 의미를 바꾸지 않는다.
