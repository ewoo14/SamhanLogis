## 결론

- `SYSTEM_ACTOR_ID`의 사용자 표시명은 `시스템`이 옳다. 구현을 되돌리지 않고 기존 테스트의 낡은 기대값만 `시스템`으로 교정했다.
- `DispatchCollabConfigTest.java:222` NPE는 이번 PR과 연결된다. UUID 모양 이름의 기대값이 낡아 Mockito stub이 불일치했고, 그 결과 `saved=null` 뒤 `response.getData()`에서 NPE가 발생했다. 기대값을 `변경자 미상`으로 교정했다.
- `PartnerOrderRevisionRestoreIT`는 `SYSTEM` 표기 실패가 아니다. 공통 resolver가 UUID 이름을 `변경자 미상`으로 바꾼 뒤 버전이력의 기존 nullable 계약이 깨진 별도 원인이다. 버전이력 저장 경계에서 placeholder를 `null`로 되돌렸다.
- 지정된 13개 변경 모듈/필터의 단독 전량 재실행은 모두 `BUILD SUCCESSFUL`, JUnit XML의 `failures=0`, `errors=0`이다.

## 1. SYSTEM 표기 판정

`시스템`을 정본으로 판정한 근거는 다음과 같다.

1. 공통 표시 경계 [ActorDisplayName.java](../../shared/common/src/main/java/com/samhanair/logis/common/security/ActorDisplayName.java:15-16)가 `SYSTEM_ACTOR_ID`와 `SYSTEM_DISPLAY_NAME = "시스템"`을 함께 선언한다.
2. 같은 helper의 `resolve()`는 zero UUID와 `system` 토큰을 사용자 표시 경계에서 `시스템`으로 반환한다.
3. 공통 회귀 테스트 `ActorDisplayNameTest.system_display_is_localized_at_the_display_boundary()`가 `resolve(null, "system") == "시스템"`을 고정한다.
4. web design-system의 `safeActorName.test.tsx`, desktop/arologis의 `maskCreatedBy.test.ts`, mobile-staff의 `actorDisplayName.test.ts`도 `system → 시스템`을 고정한다.
5. fix5 대상 계획에도 `SYSTEM_ACTOR_ID → 시스템`이 명시되어 있고, 화면의 일반 감사/이력 resolver가 이 규약을 사용한다.

반대로 DB audit/soft-delete 내부 actor 리터럴의 `system`은 내부 키 계약이다. 이번 수정은 내부 `actorId`, `deletedBy`, route/join key를 바꾸지 않고 사용자 표시 테스트만 교정했다.
