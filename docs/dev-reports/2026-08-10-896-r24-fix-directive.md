# PR #1126 R24 fix 지시서 — 발통 규칙 target의 재귀 집계와 후속 legacy 호출 덮어쓰기

## ① 좌표

### 지금 고칠 것

- `clients/web/estimate-app/views/index.ejs:7963-7972` — `recomputeFootAll`은 이름에 `실외기`가 들어간 모든 HOME_MULTI 행을 `outQ`에 합산한다. 실제 발통 target `SI-AL600A`의 품명은 `실외기 일자발`이므로, 한 번 확정된 규칙값이 다음 계산에서 다시 source가 된다. 같은 함수는 이어서 원형발통을 그 합계로 쓰고 모든 평발 target을 0으로 만든다.
- `clients/web/estimate-app/views/index.ejs:8433-8503` — 규칙 source의 단독 legacy 기여를 차감하는 중립 병합은 한 번의 `recomputeHomeDerived` 안에서는 `SI-AL600A=1 · 발통세트=0`을 만든다. 그러나 다음 계산 진입 시 이미 남은 `SI-AL600A=1`은 `legacyHomeQuantities`를 뜨기 전에 실외기 수량으로 집계된다.
- `clients/web/estimate-app/views/index.ejs:8575-8580` — 발통 중립 계열 재수렴은 규칙 target `SI-AL600A`를 보존하지만, 비소유 `발통세트`에는 위 재귀 집계에서 남은 수량이 병합된다.
- `clients/web/estimate-app/views/index.ejs:10310-10312`, `19858-19863` — 사용자 초기화·복원 경로는 `recomputeHomeDerived(true)` 직후 `recomputeFootAll()`을 다시 직접 호출한다. 이 실 경로에서는 두 번째 함수가 규칙 target을 즉시 0으로 만들고 원형발통을 2로 만든다.
- `clients/web/estimate-app/views/index.ejs:6015-6035`, `7738-7757`, `7820-7829` — 수량 입력과 옵션 변경은 같은 재계산 경로에 도달한다. 사용자가 이후 다른 기준 품목이나 옵션을 바꾸어도 상태가 다시 달라진다.
- `clients/desktop/src/renderer/routes/EstimateItemsCatalogPage.tsx:1004-1032` — 사용자는 HOME_MULTI source `AJ060MXHNBC1`에 target `SI-AL600A`를 선택해 factor/multiplier 1 규칙을 저장할 수 있다.
- `services/product-service/src/main/java/com/samhanair/logis/product/quantitysync/QuantitySyncRuleValidator.java:280-318` — 두 품목이 같은 HOME_MULTI 노출에 있으므로 이 규칙은 현재 검증 계약에서 유효하다.
- `clients/web/estimate-app/test/legacy-quantity-golden.test.js:29-105`, `515-548` — 실 119행 카탈로그 입력·반복 실행·생산 함수 순서 mutation 장치를 재사용할 R24 RED 좌표다.

`2026-08-10 13:38:21 KST` 회사 PC DB에서 아래 세 행은 모두 `ACTIVE · BOTH · HOME_MULTI` 노출이다. DB 규칙은 0행이므로 DB write 없이 데스크톱 UI와 같은 `SUM · REPLACE · factor=1 · multiplier=1` 규칙을 경계에 주입했다.

```text
source  AJ060MXHNBC1 = 1  (실외기_6HP 단배관, HOME_MULTI display_order 1)
```

5계열 동시 소유에서도 같은 결함을 확인했다. 실제 `display_order`의 119행과 실제 품목만 사용해 `분기관=5 · 호스=4 · 판넬=3 · 리모컨=2 · 일자발=1`을 주입했다. 생산 호출 순서를 임의 순열 `PBRHF`, `HPFBR`, `RFHPB`로 실제 변경했을 때 다섯 소유 target과 전체 최종 Map은 순열 간 같았다. 그러나 모든 순열에서 `발통세트`가 1회차 0에서 2회차 1로 바뀌었다. 즉 계열 **처리 순서** 무관성은 성립하지만 사용자 재계산 **시간 순서**의 고정점은 성립하지 않는다.

### 분리할 것

- 별도로 미룰 도달 결함은 없다. 유효 UI 규칙, 현재 활성 품목, 초기화·복원에 이미 있는 연속 호출만으로 즉시 재현되므로 이번 fix에서 닫는다.
- `r23HomeMultiCatalog.js`의 모델·이름·단위 119행은 `2026-08-10 13:35:08 KST` DB와 집합 기준 119/119 일치하고 DB에 없는 모델은 0이다. 파일 배열은 모델 코드 순서이고 실제 앱 응답은 `product_estimate_exposure.display_order, model_code` 순서라 위치 116개가 다르지만, 실제 앱 순서의 119행으로도 위 값이 동일하게 재현됐다. 이것은 이번 production 결함의 원인도 별도 사용자 결함도 아니다.
- snapshot은 테스트 입력으로만 쓰이는 시점 고정 자료다. 현재 레코드가 일치하고 production이 이를 소비하지 않으므로 장래 카탈로그 변경 가능성 자체는 현재 도달 결함으로 분리하지 않는다.

## ② 불변식

1. 유효한 발통 규칙이 평발 target을 소유하고 발통 포함 옵션이 켜져 있으면, 최종 평발 수량은 evaluator 결과와 같고 같은 source의 원형발통 수량이 중복 생성되지 않아야 한다.
2. 파생 target의 품명에 source 판별 문자열이 포함되어도 그 target의 확정 수량이 다음 파생 계산의 신규 source 기여가 되어서는 안 된다.
3. 같은 입력에서 홈 파생 계산을 반복하거나 사용자 초기화·복원에 있는 후속 계산을 거쳐도 첫 유효 결과와 동일해야 한다.
4. 발통 제외 옵션과 발통 수동 잠금은 규칙보다 우선하고, 잠긴 파생 수량은 다른 자동 발통 수량을 증폭시키지 않아야 한다.
5. 규칙 0건에서는 현재 순수 legacy 발통 결과가 exact 보존되어야 하며, 다른 네 계열의 규칙값·비소유 legacy 값·옵션·수동 잠금은 바뀌지 않아야 한다.

## ③ 양방향 RED

### RED-A — 규칙 발통 target의 사용자 경로 고정점

- 실 119행 카탈로그와 `AJ060MXHNBC1=1 → SI-AL600A` 규칙에서 `recomputeHomeDerived` 1·2·3회 결과가 매번 `SI-AL600A=1 · 발통세트=0`이어야 한다.
- 실제 초기화·복원 순서인 `recomputeHomeDerived(true)` 다음 `recomputeFootAll()`을 실행해도 같은 `SI-AL600A=1 · 발통세트=0`이어야 한다.
- 같은 표본에서 `SI-AL600A`를 수동 77로 잠그면 `SI-AL600A=77`이 유지되고, 이 77이 원형발통 자동 수량에 더해지지 않아야 한다.
- 다섯 계열 동시 소유 표본을 기본 순서와 `PBRHF`, `HPFBR`, `RFHPB`로 실행하면 모든 소유 target과 비소유 결과가 순열 간 같아야 할 뿐 아니라 각 순열의 1·2·3회 결과도 같아야 한다.

### RED-B — RED-A의 반대급부

- 규칙 0건, `AJ060MXHNBC1=1`, 발통 포함에서는 순수 legacy 결과 `발통세트=1 · SI-AL600A=0`을 유지해야 한다. 규칙 source 기여를 전역에서 없애 순수 legacy 발통까지 0으로 만드는 반대급부를 허용하지 않는다.
- 같은 규칙에서 발통 제외 옵션이면 `발통세트=0 · SI-AL600A=0`이어야 한다.
- 원형발통을 수동 77로 잠그면 77을 보존하고, 평발을 수동 77로 잠근 경우에도 잠금 자체를 덮어쓰지 않아야 한다.
- 동일 계열의 서로 다른 두 source가 각각 `AWR-WE13N`, `AWR-WG00N`을 소유하는 기존 실 표본은 3회 모두 `2 · 3`, 비소유 `AR-EC05=0`을 유지해야 한다.
- 분기관·호스·판넬·리모컨의 규칙 target과 R23 교차계열 표본 `AXJ-YA1509N=5 · AXJ-YA2512N=1 · PC1NWSK3NW=1`은 유지되어야 한다.
