# #1069 S16 SOL fix 지시서 — 판매전표 세트 전개 오차단 재수렴

## 판정

**실 사용자 경로에서 재현 가능한 결함 2건. 머지 차단.**

- **F1 — 재전개 중 품목명을 다시 입력하면 사용자가 해제한 품목을 지연 응답이 되살린다.** 재현 난이도 **쉬움**. 옵션 재전개 응답이 도착하기 전에 현재 구성품의 품목 자동완성 입력을 한 글자만 편집하면 된다. 목록에서 다른 품목을 선택하는 경로는 S15 정리를 타지만, 확정 입력을 다시 타이핑하는 실제 경로는 그 배선을 우회한다.
- **F2 — 재전개 안내의 접근성 이름이 비어 있다.** 재현 난이도 **매우 쉬움**. 옵션을 변경해 재전개를 시작한 뒤 접근성 트리에서 새 `status`를 확인하면 된다. 문구는 화면에 보이고 live region도 존재하지만, 명시적으로 요구된 접근성 이름은 없다.

S14 F1의 영구 저장 잠금은 지정 성공·실패·timeout과 목록 선택 품목 교체·행 삭제 경로에서 다시 발견하지 못했다. 그러나 F1은 S2·S6에서 닫은 "사용자가 마지막에 한 행동이 이긴다" 계약을 같은 실 사용자 표면에서 다시 연다.

증거 무결성:

- HEAD `43b9c323a071df23f0a9b37caed1667b4f6fe0e7`에서 프론트 지정 3 files / 98 tests 및 백엔드 지정 테스트 `BUILD SUCCESSFUL`을 확인했다. 기존 테스트 통과는 아래 미포함 경로의 결함 판정을 바꾸지 않는다.
- 읽기 전용 실 DB에서 2026-08-06 00:00 이전 정상 `OUTBOUND DRAFT` 기준 **2,387행 / 2,171전표 / 2,902,645,781원**을 재확인했다. 이후 생성된 5전표·6행을 포함한 현재 총계는 2,393행 / 2,176전표 / 2,906,079,417원이므로 기준 수치와 섞지 않았다.

## 1. 좌표

### F1 — 자동완성 입력 해제가 세트 전개 세대·컨텍스트를 무효화하지 않음

- `clients/desktop/src/renderer/routes/SlipFormPage.tsx:1905-1914`, 모바일 동형 `:1983-1992`
  - `ProductAutocomplete.onInputCommitChange(false)`는 현재 행의 `productId`, `productName`, `productType`, `modelCode`를 `updateLine`으로만 비운다.
  - 목록에서 품목을 고르는 `applyProductSelection`과 달리 `bundleExpansionGenerationRef`를 증가시키지 않고 `expandedBundleOptions`도 정리하지 않는다.
- `clients/web/design-system/src/components/AsyncAutocomplete/AsyncAutocomplete.tsx:390-396`
  - 확정된 품목명을 사용자가 한 글자라도 편집하면 `setCommitted(false)`가 즉시 호출되므로 위 경로는 실 UI에서 도달 가능하다.
- `clients/desktop/src/renderer/routes/SlipFormPage.tsx:855-902`
  - 세대가 바뀌지 않았으므로 `retryLatestBundleGeneration`은 재시도하지 않는다.
  - 화면 행의 `productType`은 이미 `null`이지만 같은 행 ID의 옵션 컨텍스트가 남아 있어 `context.parentProductId === selected.productId`가 참이 된다.
  - 따라서 성공 응답이 `replaceWithExpandedBundleLines`로 들어가 사용자가 해제한 옛 세트의 구성품을 다시 화면에 넣는다.

재현:

1. 판매전표 입력에서 옵션이 있는 `SINGLE_SET / EXPAND` 세트를 선택하고 첫 구성품과 옵션 UI가 나타날 때까지 기다린다.
2. 옵션을 변경하고 `/slips/expand-line` 재전개 응답을 지연한다.
3. 응답 전에 현재 첫 구성품의 품목 자동완성 입력을 포커스해 기존 품목명을 한 글자 편집한다. 이 시점에 확정 품목은 저장 대상에서 해제된다.
4. 지연된 성공 응답을 도착시킨다.
5. 사용자가 해제한 옛 세트의 구성품이 다시 나타나는 것을 확인한다. 이후 저장하면 사용자의 마지막 품목 해제 행동과 다른 구성품이 payload에 들어갈 수 있다.

### F2 — 보이는 status에 접근성 이름 없음

- `clients/desktop/src/renderer/routes/SlipFormPage.tsx:2078-2091`
  - `role="status"`, `aria-live="polite"`, 가시 텍스트는 있으나 `aria-label` 또는 `aria-labelledby`가 없다.
  - 동일 마크업을 `dom-accessibility-api.computeAccessibleName`으로 계산한 결과는 `""`였다. S15 테스트는 `role`, `aria-live`, `textContent`만 확인해 접근성 이름을 검증하지 않는다.

재현:

1. 옵션이 있는 세트를 전개하고 옵션을 변경해 저장 버튼이 비활성화된 상태를 만든다.
2. 화면에서 `세트 구성품 반영 중… 저장할 수 없습니다.` 문구가 보이는지 확인한다.
3. 브라우저/테스트 접근성 트리에서 해당 `status`의 이름을 확인한다.
4. role과 live 속성은 있으나 접근성 이름은 빈 문자열이다.

## 2. 불변식

1. 재전개 중 품목 자동완성의 재입력·선택 해제·다른 품목 선택·행 삭제는 모두 기존 전개 세대를 무효화해야 하며, 지연 응답이 사용자의 마지막 행동을 되돌리면 안 된다.
2. 컨텍스트 정리는 현재 화면에서 아직 최신 옵션 반영을 기다리는 다른 행의 pending을 지우면 안 된다. 두 세트를 동시에 재전개해도 한 행의 편집·삭제가 다른 행의 옵션을 유실시키면 안 된다.
3. 재전개가 실제 진행 중일 때만 옛 구성품 저장을 차단하고 성공·실패·timeout·연속 편집·품목 교체·행 삭제 뒤에는 저장 가능 상태로 회복해야 한다.
4. 일반 SINGLE 전표와 기본 옵션 전개는 bundle pending 배선에 걸리면 안 된다.
5. 저장 차단 안내는 화면에 실제로 보이고, 접근성 트리에서 식별 가능한 이름을 가져야 하며, 재전개 종료 후 안내와 차단이 함께 해제되어야 한다.
6. S2·S4·S6·S8·S10·S12·S14의 폐쇄 계약, BUNDLE 부모 영속 차단, 최신 payload, 옵션 수렴, 규격 승계와 `#1063` 초기 5행/마지막 행 증식/trailing 빈행 제외를 유지해야 한다.
7. 정상 SINGLE 기준 **2,387행 / 2,171전표 / 2,902,645,781원**의 생성·전체수정·모바일 저장 계약을 바꾸면 안 된다.

구현 수단은 지정하지 않는다. 특히 자동완성 입력을 막거나 재전개 저장 차단을 제거해 결함을 숨기면 안 된다.

## 3. 양방향 RED

### RED-B — 결함 폐쇄

- 옵션 재전개 pending 중 구성품 품목명을 한 글자 편집해 확정을 해제한 뒤 옛 성공 응답이 품목 또는 구성품을 되살리면 RED.
- 같은 경로에서 실패·timeout 뒤 사용자가 해제한 품목이나 옵션 컨텍스트가 다시 나타나거나 저장이 계속 잠기면 RED.
- pending 중 목록에서 다른 품목 선택, 자동완성 재입력, 선택 해제, 행 삭제 각각 뒤 옛 응답이 적용되면 RED.
- 재전개 차단 안내가 보이지 않거나 `getByRole('status', { name: /세트 구성품 반영 중/ })`처럼 접근성 이름으로 식별되지 않으면 RED.

### RED-A — 반대급부 보존

- 한 행의 품목 편집·삭제 정리가 다른 행에서 아직 필요한 pending 옵션을 지우거나 그 옵션 반영을 유실시키면 RED.
- 재전개 중 저장을 허용해 옛 구성품 payload가 나가거나, 완료 뒤에도 안내·pending·저장 차단이 남으면 RED.
- BUNDLE 미선택 일반 SINGLE 전표 또는 기본 옵션 구성품 저장이 차단되면 RED.
- 연속 옵션 변경의 중간 응답이 적용되거나 구성품이 누적되면 RED.
- 옵션 확정 뒤 BUNDLE 부모가 화면 또는 payload에 남으면 RED.
- `#1063` 빈행 규약 또는 정상 SINGLE 생성·전체수정·모바일 저장이 깨지면 RED.

## 4. 범위 밖·안 본 범위

- 범위 밖: 견적·분개·이동·INBOUND 화면, 세트 마스터와 가격 배분 정책, 다른 트랙 `#1057`·`#1066`·`#1075`·`#1080`, Docker 재빌드·재배포·중지, DB 쓰기, 전체 게이트, 로컬 design-system 미빌드 `tsc`.
- 안 본 범위: DB write를 동반한 실제 전표 생성·수정, 모바일 실제 기기, Docker 배포본과 작업 트리 HEAD 동일성, 범위 밖 타 트랙 파일.
- 읽기 전용 DB 조회, 소스 상태 전이 추적, 협소 FE/BE 테스트만 수행했다.
