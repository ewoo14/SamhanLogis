# #978 D-1 S3 — lookup sync 프로세스 로컬 hash cache 제거

## 결론

PR #1139 S2에서 확인된 `DB commit 순서`와 `afterCompletion` 순서 역전 회귀를 수정했다.
`ProductLookupSheetSyncService`의 세 탭은 더 이상 프로세스 로컬 hash cache나 transaction callback을 사용하지 않고, 매 행마다 시트 hash와 현재 활성 DB 엔티티에서 계산한 hash를 비교한다.

## 전제 검증

rowHash 구성 요소는 모두 DB 엔티티에 있거나 의도적으로 null이다.

| 탭 | 시트 hash 구성 | DB 확인 |
|---|---|---|
| 싱글 자재가격 | materialKey, name, price, optionLabel, computedFormula | `MaterialPrice`의 5개 영속 필드 |
| 추천실외기 | recommendationType, indoorCapacity, indoorCount, outdoorHp | `OduRecommendationLookup`의 4개 영속 필드 |
| 분기계산 | branchCode, null, null | `BranchPipeLookup.branchCode`, 나머지는 시트 sync 계약상 null |

따라서 중단 조건인 “rowHash 구성 요소 중 영속되지 않는 파생값”은 발견되지 않았다.

## RED-first 증거

S2와 동일한 결정적 하네스 조건으로 새 테스트를 먼저 실행했다.

1. 초기 DB/cache 상태를 40,000으로 만든다.
2. T1이 45,000을 저장하고 DB commit 후 서비스 cache callback 직전에 정지한다.
3. T2가 50,000을 저장하고 commit/callback까지 완료한다.
4. T1 callback을 재개해 과거 45,000 hash가 마지막에 남게 한다.
5. 다음 시트 입력 45,000을 처리한다.

기존 구현의 RED 원문:

```text
ProductLookupSheetSyncServiceIT > concurrent_commit과_afterCompletion_순서가_엇갈려도_다음_sync는_DB를_기준으로_재처리한다() FAILED
expected: 1
 but was: 0
```

실패 지점은 다음 sync의 `updated=1` 기대였고, 기존 cache 기반 구현은 `updated=0`/`unchanged=1`로 잘못 판정했다.

## 구현

- `MaterialPrice`, `OduRecommendationLookup`, `BranchPipeLookup`의 현재 DB 행 hash를 직접 계산해 시트 hash와 비교.
- Material 가격은 `BigDecimal.stripTrailingZeros()` 기반 canonical decimal을 사용해 DB NUMERIC scale 차이를 제거.
- 문자열은 blank→null 및 trim을 시트/DB hash 양쪽에 적용.
- insert, update, soft-delete/restore 분기는 유지.
- `lastKnownRowHash`, `putHash/getHash/removeHash`, transaction synchronization buffer 제거.
- 기존 테스트 호출 호환을 위해 `clearHashCacheForTest()`는 no-op으로 유지.

## 검증

```text
RED: 1 test failed — cache 역전 후 다음 45,000 입력이 update되지 않음
GREEN: concurrent regression test 1/1 pass
GREEN: ProductLookupSheetSyncServiceIT 8/8 pass
```

세 탭 전체 IT에는 다음 조합이 포함된다.

- 3탭 insert/unchanged/update/soft-delete 및 null 정직성
- soft-delete 후 동일 row id restore
- 저장 실패 rollback 2회 후 retry
- 한 탭 rollback과 다른 두 탭 성공
- ODU natural-key 변경/restore 및 중복 row skip
- DB commit/callback 순서 역전 동시성 회귀

소형 격리 PostgreSQL fixture의 8건 실행 시간은 약 0.92초(test time), Gradle elapsed는 53초였다. 실 Google Sheet 쓰기와 공유 Docker stack 재기동은 하지 않았다.
