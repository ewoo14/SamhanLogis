## D1. 기존 상용 세트 72개가 견적·판매전표 전개에서 0건으로 소실된다

### 좌표

- `services/product-service/src/main/java/com/samhanair/logis/product/service/BundleExpander.java:98-100`
- `services/product-service/src/test/java/com/samhanair/logis/product/it/BundleExpanderIT.java:78-101`
- 실데이터 표본: `AM220AXVHHR1SY`, `AM360AXVGHC1SY`, `AM260AXVHHH1SY`

`BundleExpander`가 저장된 구성품을 `is_default=true`로만 거른다. 그러나 실데이터의 `COMMERCIAL_MULTI` 세트 72개는 활성 구성품 137건 전부가 `is_default=false`여서 전개 결과가 빈 배열이 된다. 새 규칙만 검사한 테스트에는 "활성 구성품은 있으나 기본 지정이 0건인 기존 세트" 표본이 없다.

### 실 사용자 RED

- 견적 작성에서 `AM220AXVHHR1SY`를 선택하고 저장하면 `POST /slips/estimates`가 404를 반환한다.
  - 원문: `세트 구성품 일부를 찾을 수 없습니다(미등록/단종): AM220AXVHHR1SY`
  - 화면: `01-estimate-commercial-bundle-save-404.png`
  - 원문 증거: `estimate-commercial-bundle-save-evidence.json`
- 판매전표 작성에서 같은 모델을 선택하면 `POST /slips/expand-line`은 200이지만 `data=[]`를 반환한다. 화면 라인은 0건·0원으로 지워지고 저장할 수 없다.
  - 화면 문구: `세트 구성품을 찾을 수 없습니다. 관리자에게 문의해 주세요.`
  - 화면: `02-sales-commercial-bundle-user-path.png`
  - 원문 증거: `sales-commercial-bundle-evidence.json`
- 주문 작성의 `AM260AXVHHH1SY`는 같은 실데이터상 비기본 구성품 2건을 갖지만 주문 UI가 구성품 전개를 쓰지 않고 모품과 부속 3종을 전송했다. 미리보기·최종확인 후 확정 200, 합계 24,687,200원으로 도달하여 이 경로에서는 D1이 발화하지 않았다.
  - 화면: `18-order-commercial-bundle-preview.png`, `19-order-commercial-bundle-final-confirm.png`, `20-order-commercial-bundle-success.png`
  - 원문 증거: `order-commercial-bundle-evidence.json`

### 불변식

기존 활성 세트는 `BundleExpander`를 타는 사용자 경로에서 배포 직후 조용히 빈 세트로 변하면 안 된다. 새 정책이 선택 구성품을 제외하더라도, 최소 한 개 이상의 기본 구성품을 갖도록 데이터 전환을 완료하거나 전환 전 데이터에 대한 명시적 호환 규칙을 둬야 한다. 주문처럼 모품을 직접 보내는 경로는 기존 금액과 라인 구성을 유지해야 한다.

### 양방향 RED

- **RED-A — 기존 데이터 호환:** 활성 구성품은 존재하지만 `is_default=true`가 0건인 실데이터 복제 표본 `AM220AXVHHR1SY`를 견적 및 판매전표에서 전개한다. 빈 배열·404·0원 소실 없이 전환 정책이 정한 기본 구성과 기존 수량/금액을 반환해야 한다.
- **RED-B — 새 필터의 구체적 역방향 가드:** `DEFAULT_INDOOR(is_default=true, 단가 100)`와 `OPTIONAL_OUTDOOR(is_default=false, 단가 200)`가 함께 있는 세트는 기본 전개 시 `DEFAULT_INDOOR` 한 건, 합계 100만 반환해야 한다. D1을 고친다는 이유로 단순히 필터를 제거해 선택 구성품 200까지 되살리면 실패시킨다.
- **주문 경로 회귀 가드:** `AM260AXVHHH1SY` 주문은 모품 1건과 현재 부속 3종, 합계 24,687,200원을 유지해야 한다. D1 수정이 주문에 구성품 2건을 추가하거나 모품을 제거하면 실패시킨다.

### 수정 범위와 반대급부

- 우선안은 72개 세트의 실제 기본 구성 확정 및 데이터 마이그레이션이다. 임시 fallback을 택하면 잘못 표시된 `is_default=false`와 진짜 선택 구성품을 구분하지 못해 선택품이 다시 금액에 섞일 위험이 있다.
- migration 전후 72개 전체의 구성 모델·수량·합계 diff를 산출하고, 견적/판매전표 실경로를 모두 고정한다.

## D2. 분류 정액할인이 견적 금액 경로에서 누락된다

### 좌표

- `services/product-service/src/main/java/com/samhanair/logis/product/web/EstimateCatalogInternalController.java:270`
- `clients/desktop/src/renderer/api/slip.ts:831-847`
- `clients/desktop/src/renderer/routes/EstimateFormPage.tsx:1470-1580`

product-service는 유효 분류 할인율을 응답하지만, 견적의 모델 lookup/자동단가 경로는 `sellingPrice`와 가격기억만 사용한다. 따라서 가격기억이 없는 거래처에서는 S/M/L 분류 할인율이 견적 표시·저장 금액으로 전달되지 않는다. 반면 같은 품목의 판매전표와 주문은 할인율을 적용한다.

### 실 사용자 RED

- 관리자 UI에서 실 분류 트리 `실내기 > 1-Way WIFI > 소형`의 S에 15%를 지정했다.
- 품목 `AJ012BN1PBC2`는 품목 고정값이 없고 카탈로그 출처가 `S`, 유효 할인율이 15%로 표시된다.
- 해당 품목 가격기억 0건인 실 거래처 `이앤공조-정종출`을 견적에서 선택했다.
- 판매가 495,000원의 기대값은 420,750원이지만, 화면에 495,000원이 표시됐고 `POST /slips/estimates` 201 응답도 `totalAmount=495000.00`, `unitPriceWithVat=495000.00`로 저장했다.
  - 화면: `17-class-s-estimate-clean-partner.png`
  - 원문: `classification-s-estimate-clean-partner-evidence.json`
- 같은 S=15% 표본은 판매전표 420,750원, 주문 445,995원(각 경로의 기준가격 차이 반영)으로 실제 적용됐다.
  - 화면: `15-class-s-sales-amount.png`, `16-class-s-order-amount.png`
  - 원문: `classification-s-three-path-money-evidence.json`

### 불변식

분류의 유효 정액할인율은 견적·주문·판매전표 각 경로가 정한 기준가격에 동일한 우선순위(`수동 품목 > S > M > L > 기존 품목값 > 미지정`)로 적용해야 한다. 거래처 가격기억 유무가 분류 할인 적용 여부를 우연히 바꾸면 안 된다.

### 양방향 RED

- **RED-A — 분류 할인 발화:** 가격기억 0건인 거래처 + `AJ012BN1PBC2` + S=15%에서 견적 화면과 저장 응답이 모두 420,750원이어야 한다. 응답 출처도 S여야 한다.
- **RED-B — 미지정의 구체적 역방향 가드:** 동일 거래처/품목에서 S·M·L을 모두 UI로 해제하고 품목 고정값도 null인 상태에서는 견적 화면과 저장 응답이 판매가 495,000원을 유지해야 한다. 할인율을 이중 적용하거나 직전 15%를 stale 상태로 재사용하면 실패시킨다.

### 수정 범위와 반대급부

- 견적 자동단가에 유효 할인율·출처를 전달하고 계산하되, 거래처 가격기억과 사용자 수동단가의 기존 우선순위를 명시적으로 결정해야 한다.
- 가격기억이 이미 할인 적용 최종가라면 재할인하면 안 된다. 권장 순서는 `USER > REMEMBERED > 유효 정액할인 적용 카탈로그가`로 고정하고 각각을 별도 RED로 둔다.
