- 머지 가능 여부: **불가.** 정리 전 비교와 나머지 라우트 비교를 끝내지 못해 도달 가능한 결함이 0건인지 확정할 수 없다.

## 2. 「대시보드로 되돌아감」 실행 판정

현재 QA renderer는 실제 데스크톱과 같은 HashRouter다. 해시 없이 pathname만 넣은 세 URL을 MASTER로 실행하면 세 화면 모두 같은 대시보드를 렌더했다.

| 실행 URL | 렌더 결과 | 권한 응답 | 후보 판정 |
|---|---|---|---|
| `/sales/slips` | 대시보드 | `/auth/admin/permissions/my` HTTP 200 | **③ 정리와 무관** — HashRouter가 빈 hash를 `/`로 해석한 URL 형식 불일치 |
| `/sales/estimates` | 대시보드 | `/auth/admin/permissions/my` HTTP 200 | **③ 정리와 무관** — 동일 |
| `/sales/estimates/new` | 대시보드 | `/auth/admin/permissions/my` HTTP 200 | **③ 정리와 무관** — 동일 |

실제 사용자 URL `/#/sales/slips`는 판매전표 목록에 도달했고, `/#/sales/estimates`도 견적 목록까지 도달했다. 따라서 직전의 pathname 실행에서 본 대시보드는 ① 삭제 데이터 의존, ② 권한, ④ 0건 데이터가 아니라 **라우터 형식이 다른 진단 URL** 때문이었다. 현재 브랜치와 `origin/main`의 `clients/desktop` 실행 소스 차이는 0건이므로 같은 renderer 코드 기준이다. 단, 견적 목록 도달 직후 증거 무결성 조건으로 중단했으므로 잔재 정리 인과 판정과 혼동하지 않는다.

## 3. UTF-8 격리 복제와 한글 무결성 원문

PowerShell 파이프를 사용하지 않았다. Git Bash에서 DB마다 custom-format dump를 호스트 파일로 받은 뒤 `docker cp`와 `pg_restore`로 격리 PostgreSQL에 복원했다.


복제 직후 필수 한글 확인 원문:

```text
KOREAN_CHECK
        name
--------------------
 (주)한국냉동물류
 (주)서울택배
 대한화물서비스(주)
(3 rows)
```

이 확인은 정상이라 화면 QA를 시작했다. 이후 화면에서 발견된 `?`는 복제본과 공유 원본을 같은 SELECT로 대조했을 때 모두 이미 존재했다.

```text
 estimate_no  | partner_name |              memo               | deleted_by | is_deleted
--------------+--------------+---------------------------------+------------+------------
 2026/08/08-2 | S26 ??? ???  | S26-1123-estimate-convert-probe |            | f
(1 row)

격리 복제본: 위와 동일
공유 원본:   위와 동일
```

즉 이번 중단은 PowerShell 복제 한글 파손 재발이 아니라, 공유 원본 `slip_db.estimates.partner_name` 자체에 남은 `?` 6개 때문이다. 지시된 예외 범위인 증거 무결성 사실만 기록하며 별도 품질 판정은 하지 않는다.

- 직전 정리 전 수치 `70건 · 656,909,053원 · 최근단가 78행`: **이번 라운드에서는 재현 확인을 못 했다.** 화면의 `?` 6개 발견 즉시 중단했으므로 격리 DB rollback과 정리 전 집계를 실행하지 않았다.

## 5. Playwright 실행 원문

인앱 Browser 런타임 조회 결과는 `[]`였지만 실행 불가로 판정하지 않고 저장소 Playwright Chromium을 사용했다.

```text
정리 후 MASTER /#/sales/slips
finalHash=#/sales/slips
routeMatched=true
questionMarks=0
chars=1023

정리 후 MASTER /#/sales/estimates
finalHash=#/sales/estimates
routeMatched=true
questionMarks=6
chars=3242

QUESTION_MARK_DATA_STOP route=/sales/estimates count=6
```

이미 로드된 화면에서 확인한 `?` 포함 행 원문:

```text
2026/08/08-2    0000000000    S26 ??? ???    2026-08-08    2026-08-31    ₩1,100
```

이후 다른 권한, 정리 전, 다른 데이터 키, `/sales/estimates/new`는 실행하지 않았다.
