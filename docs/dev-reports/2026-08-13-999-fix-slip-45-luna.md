# #999 slip-service 45건 fix — CODEX LUNA

## 결론

45건은 모두 브랜치의 opaque token 직렬화 계약을 기존 테스트 소비 코드가 UUID로 재사용한 회귀였다. 공개 응답 계약과 라이브QA 결과는 유지하고, 테스트 경계에서만 token을 내부 UUID로 복원하도록 공통 helper·assertion·격리 SQL 바인딩을 고쳤다.

## 유형별 묶음표

| 유형 | 건수 | 검증하던 동작 | 처리 |
|---|---:|---|---|
| 파싱 실패 (`UUID.fromString`) | 22 | 첨부/서명 저장, 내부 조회, 전표 lifecycle·revision restore·redline·BUNDLE 왕복, audit 확인 등 각 테스트의 실제 저장/상태/권한 동작 | `OpaqueUuidTestDecoder`를 공통 test helper로 추가하고 공개 응답의 `id`, `slipId`, `line.id`를 UUID로 복원. 도메인 단정과 status/권한/저장 검증은 유지 |
| SQL cast 실패 (`?::uuid`) | 5 | 삭제 라인 복원, status 필터, legacy 삭제 전표 fail-loud, 라인 삭제 상태와 행 수 확인 | SQL의 `?::uuid` 자체는 유지하고 helper가 복원한 UUID를 JDBC parameter로 전달. SQL·행 수·409 단정은 유지 |
| UUID 형식 assertion 실패 | 18 | SSE connected event, dispatcher/inspector 자동 기입, 내부 projection의 slip 식별자, revision restore 응답 등 | 외부 응답은 opaque token, 내부 projection/SSE는 내부 UUID라는 실제 endpoint 계약에 맞춰 기대값 표현만 변환. `status`, `actor`, `revision`, `partner`, `line`, 권한 단정은 삭제/완화하지 않음 |
| 합계 | **45** | 모든 테스트가 원래 검증하던 동작 유지 | `skip`, `assume`, 느슨한 `||`/다중 status 허용 없음 |

## 변경 범위와 동작 보존

- 생산 도메인/DB schema/API serializer는 변경하지 않았다.
- 테스트 전용 `OpaqueUuidTestDecoder`가 legacy UUID와 URL-safe opaque token을 모두 복원한다.
- 외부 응답은 계속 opaque token이므로 UUID 사용자 비공개 계약을 되돌리지 않았다.
- internal projection/SSE처럼 UUID를 반환하는 endpoint는 endpoint의 실제 표현을 기대하도록 assertion만 조정했다.
- SQL cast, HTTP status, lifecycle 상태, revision 복원/잠금, 권한 거부, partner/line 수·내용 단정은 그대로 유지했다.

## CI 두 건의 정체

PR #1128의 실패 로그를 읽어 분리했다.

1. `Frontend Desktop` 및 `Desktop Playwright`: `npm ci` 중 Electron 다운로드가 `RequestError: socket hang up`으로 종료됐다. Playwright가 시작되기 전 의존성 설치가 실패했고, 후속 silent-skip guard가 `playwright-json/results.json` 부재로 실패했다. 로컬 `npm run typecheck`는 exit 0이므로 이번 로그는 runner 네트워크/외부 Electron 다운로드 실패이며 제품 문제로 판정하지 않았다.
2. `하네스 거짓 green 가드`: 실제 문제였다. 세 QA 스크립트가 절대 checkout 경로와 커밋 QA 디렉터리 직접 출력(`OUT`)을 사용했다. `fileURLToPath`/`path`/`tmpdir` 기반 경로와 `resolveQaShotsDir(HERE)`로 바꿔 `_local` 격리를 적용했다. 수정 후 로컬 guard는 **62/62 pass**했다.
