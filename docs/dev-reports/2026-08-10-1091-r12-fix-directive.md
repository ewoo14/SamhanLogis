### 원인 좌표

- `services/slip-service/src/main/java/com/samhanair/logis/slip/service/SlipService.java:422`
  - 헤더 memo 변경 audit의 `actorName`을 표시명 헤더가 아니라 `callerId`에서 만든다. gateway의 `callerId`는 계정 UUID다.
- `services/slip-service/src/main/java/com/samhanair/logis/slip/service/SlipService.java:555-557`
  - overlay PATCH도 표시명이 없으면 `callerId`로 폴백하므로 같은 신규 UUID 행을 만들 수 있다.
- `services/slip-service/src/main/java/com/samhanair/logis/slip/audit/web/dto/SlipAuditLogResponse.java:38-49`
  - 과거 저장행의 UUID형 `actorName`을 아무 방어 없이 응답한다.
- `clients/desktop/src/renderer/api/createAuditApi.ts:67-75`
  - R11 정규화가 `actorName`을 그대로 UI 모델로 넘긴다.
- `clients/web/design-system/src/components/AuditOverlay/AuditOverlay.tsx:137,172`
  - 최신/과거 이력 모두 `actorName`을 사용자 텍스트로 직접 렌더한다.

즉, R11의 DTO 정규화는 3행 은폐를 올바르게 해제했지만, 기존 저장 경로가 `actorName`에 넣은 UUID까지 함께 사용자 표면에 도달시켰다.

### 불변식

`actorId`와 UUID 형태의 `actorName`은 색상 hash·내부 상관관계에만 사용할 수 있고 사용자 텍스트로 렌더하면 안 된다. 과거 오염행을 조회해도 revision 수·필드·이전값·새값은 그대로 보여야 하며, 변경자 표시만 UUID가 아닌 안전한 표시명 또는 중립적 대체문구로 수렴해야 한다.

### 양방향 RED

#### RED-A — 고칠 결함

1. `SlipService.editHeader`의 memo 변경과 `applyOverlayPatch`가 `callerId`를 `actorName`으로 폴백하지 않도록 한다. 이미 존재하는 `resolveActorName(callerName, callerId)` 계약을 재사용한다.
2. 기존 DB 오염행도 즉시 가려지도록 `SlipAuditLogResponse` 또는 공통 audit 응답 경계에서 UUID형 `actorName`을 사용자 안전값으로 정규화한다. 신규 write만 고쳐 기존 revision 1이 계속 노출되면 RED다.
3. 실 `2026/08/10-14`를 다시 열어 `수정 3회`, memo 3행, 세 이전값은 유지되고 화면 전체에서 UUID 정규식 일치 텍스트가 0건인지 확인한다.

아래 중 하나라도 나오면 RED다.

```text
메모 이력 또는 버전이력 모달에 UUID형 actorName 1건 이상
기존 오염행만 숨기면서 revision 수가 3에서 감소
memo 3행이 다시 '변경 이력 없음'으로 은폐
신규 header/overlay audit 응답 actorName이 callerId UUID와 동일
```

#### RED-B — 지킬 구체적 표적

- revision 3·2의 정상 표시명 `[DEV-SEED] 개발영업`은 그대로 보여야 한다.
- `2026/08/10-14`의 배지는 계속 `수정 3회`이고, `S33-open-overlay-ok`·`S33-open-header-ok`·`S33-open-normal-path` 세 이전값이 모두 보여야 한다.
- `2026/08/10-13`의 실 200 + `[]`에서는 메모·배송지가 계속 `변경 이력 없음`, 배지는 `수정 0회`여야 한다.
- `actorId` 기반 사용자 색상 dot의 결정성은 유지하되 UUID 텍스트만 노출하지 않아야 한다.
- 정상 비UUID `actorName`과 `changedAt`은 변경하지 않아야 한다.
- R11의 `fieldName → field`, `oldValue → beforeValue`, `newValue → afterValue` 정규화는 유지해야 한다.

### 구현 방향

write 경로는 `SlipService.resolveActorName(callerName, callerId)`로 수렴시키고, read 경로에는 과거 데이터용 최종 UUID 비공개 가드를 둔다. DB 원문을 파괴적으로 덮어쓰지 않아도 되지만, 응답/UI에는 의미를 과장하지 않는 `변경자 미상` 같은 중립 문구를 사용한다. UUID를 사용자명으로 역추정하거나 `system`으로 오표기하지 않는다.
