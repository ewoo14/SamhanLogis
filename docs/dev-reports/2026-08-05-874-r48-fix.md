# R48 fix 보고 — PR #1057 · 이슈 #874

## 결론

결함 1(실패 멱등 키 영구 고정)은 수정하고 RED를 GREEN으로 전환했다.
notification 요청 행은 외부 gateway 호출 전에 별도 transaction으로 커밋되며, `SENT`가 아닌 동일 키 행은 같은 행으로 재시도한다.

다만 결함 2의 **gateway 성공 직후, notification 완료 transaction 커밋 전 프로세스 종료** 칸은 현재 gateway 계약으로 닫을 수 없다. 이 경우 DB에는 호출 전 상태만 남으므로 재시도하면 외부 호출 중복, 재시도하지 않으면 영구 누락이다. 외부 gateway 자체의 멱등 키 처리 계약 없이는 두 결과를 구별할 관측값이 없다. 이 잔여 표면을 GREEN으로 가장하지 않는다.

## RED-first 증거

추가한 `sameIdempotencyKey_afterTransientFailure_retriesGateway`에서:

```text
1. 동일 idempotencyKey 첫 gateway 결과 = FAILURE_TRANSIENT
2. 저장 행 상태 = FAILED
3. gateway 성공으로 전환 후 같은 요청 재호출
4. 기대 = SENT, gateway 호출 2회
```

원본 구조에서는 기존 FAILED 행을 즉시 반환하여 gateway 호출 수가 1회이고 상태가 FAILED로 남았다.

```text
NotificationServiceTest > sameIdempotencyKey_afterTransientFailure_retriesGateway() FAILED
    org.opentest4j.AssertionFailedError at NotificationServiceTest.java:111
9 tests completed, 1 failed
```

## 상태 기계 조합표

| outbox/notification 상태 | 외부 gateway 결과 | 종료 시점 | 다음 재처리 | 정확히 한 번으로 수렴 |
|---|---|---|---|---|
| PENDING | 호출 전 | 호출 전 | 같은 행 재호출 | ✅ 성공까지 전달 |
| PENDING | 명시 실패 | 실패 기록 전/후 | 같은 행 재호출 | ✅ 성공까지 전달 가능 |
| PENDING | 성공 | 성공 결과 기록 후 | `SENT` dedupe | ✅ |
| PENDING | 성공 | **성공 직후 결과 커밋 전** | 같은 행 재호출 | **❌ 현재 gateway 계약상 중복 또는 누락** |
| SENDING | 호출 전 | slip worker 종료 | lease 회수 후 재claim | ✅ 호출 진입 가능 |
| SENDING | 성공 | slip lease/notification 기록 전 | 재claim 후 같은 키 재호출 | **❌ gateway 외부 멱등 계약 없이는 중복 가능** |
| SENT | 성공 | 응답 유실/프로세스 종료 | 같은 키 조회 후 즉시 반환 | ✅ gateway 재호출 없음 |
| any | lease 경합 | claim 조건부 UPDATE 패배 | 승자만 deliver | ✅ 한 worker만 진입 |

표의 두 `❌` 칸이 이번 라운드에 남은 다음 결함이다. DB 행을 먼저 커밋하는 변경은 호출 전 종료 및 응답 유실 경계를 개선하지만, 외부 부수효과와 로컬 상태 기록 사이의 원자성을 만들지는 못한다.

## 변경 사항

- `NotificationDispatchPersistence` 신규: gateway 호출 전 요청 행을 별도 transaction으로 저장하고, 호출 후 결과를 별도 transaction으로 확정.
- `NotificationRequestRepository`: 동일 멱등 키 준비 단계에 `PESSIMISTIC_WRITE` 조회 추가.
- `NotificationService`: `SENT`만 즉시 dedupe하고 `FAILED/RETRYING/PENDING`은 기존 행으로 gateway 재진입. 사용자 저장 transaction과 외부 호출을 분리.
- `NotificationServiceTest`: 최초 gateway 실패 후 동일 키 재시도 RED/GREEN 고정.

마이그레이션은 추가하지 않았다. 지정된 real QA 파일은 변경하지 않았다.
