## 10. 프로세스·데이터 안전

- DB에는 SELECT만 실행했다. INSERT/UPDATE/DELETE를 직접 실행하지 않았다.
- 복원 실패는 브라우저 네트워크에서 해당 POST만 409로 응답해 실제 DB를 변경하지 않았다.
- 공유 Docker 스택을 중지·재시작하지 않았다.
- 이 라운드가 띄운 Vite PID와 자식 `esbuild`를 종료했다. 종료 후 `5196` LISTENING 0, 대상 프로세스 0, Playwright 브라우저 프로세스 0을 확인했다.
- 커밋·push·제품 코드 수정은 하지 않았다.

## 11. 이 라운드가 보지 않은 것

- 주문서의 화면 표시 작성일 표본이 0건이라 두 계열 교차 정렬의 정상/역전 사례를 판정하지 못했다.
- 실제 복원 성공으로 DB 상태가 바뀌는 경로는 실행하지 않았다. 버튼 노출, 행 클릭 비전파, 한국어 실패 배너만 검증했다.
- 반대 방향인 견적 API 실패 시 주문서만 남는 경우는 실행하지 않았다.
- 합산 10,000건 경계와 Electron 패키징 앱은 보지 않았다. t1092 renderer 전용 Vite 실화면만 검증했다.
- 화면 상단의 전역 `업데이트 실패` 배너는 이 슬라이스의 판정 대상이 아니어서 원인을 조사하지 않았다.
