# #887 슬5 R3 잔여 3건 구현·검증 보고서

## 범위

기획서에 명시된 도달 가능 잔여 3건만 다뤘다.

1. CODEF 오류 안내 `.codef-import-hint--error`의 실제 렌더 대비 미달
2. CODEF·일마감·안전재고 전체 범위 `aria-pressed` 칩의 키보드 해제 불가
3. 세 화면 미선택 안내의 전체 경로·대안 경로 불일치

이미 해소된 MED 7건·LOW 13건·pre-existing 4건과 V64 적용 마이그레이션은 열지 않았고, V65 이후 코드·문서도 수정하지 않았다.

### 6-1. R1-1 — 저장된 전체 dirty 상태에서 가져오기 잠금 사유가 사라지고 aria-describedby 가 대상 없는 id 를 가리킴

재현(개발책임자 브리핑 그대로): ① `범위: 전체` 칩 포커스→Enter → ② 저장 → ③ 칩을 다시 눌러
해제 → ④ 계좌 목록에서 1건 체크.

원인: `scopeHint` 계산이 `savedAllScopeDirty`(저장된 전체가 아직 반영 안 됨) 사유와
`scopeMode===null`(아무것도 안 골랐음) 사유를 하나의 문자열로 합쳐 있었고, 그 문자열을 렌더하는
`<span id={SCOPE_HINT_ID}>`는 "`scopeMode===null`이면 힌트, `scopeMode==='SELECTED'`이면
선택 chip 목록"이라는 상호배타 삼항 안에 있었다. 그래서 계좌를 체크해 `scopeMode`가
`'SELECTED'`로 바뀌면(그러나 `savedAllScopeDirty`는 여전히 참이라 가져오기는 계속 잠긴 채)
힌트 `<span>`이 DOM에서 통째로 사라지고, 두 버튼의 `aria-describedby={SCOPE_HINT_ID}`만
대상 없는 참조로 남았다.

### 6-2. R1-2 — CodefImportScopeForm 저장/가져오기 오류 토스트(`.bank-transaction-toast--error`) 대비 미달

`CodefImportScopeForm`의 저장 실패·가져오기 실패·충돌은 `onToast({type:'error', …})`로
`BankTransactionPage`의 토스트 상태에 오르고, `.bank-transaction-toast bank-transaction-toast--error`
클래스로 렌더된다. 실 라운드트립(409 충돌 등)은 in-process mock 이 페이지(JS 컨텍스트) 단위로만
상태를 가져 단일 탭에서 결정적으로 재현할 수 없으므로, 실제 컴포넌트와 동일한 두 클래스 조합을
가진 노드를 만들어 실제 오류 토스트가 뜬 순간과 동일한 computed style을 측정했다(위 1-1 대비
테스트의 참조색 probe 와 동일 기법 — CSS fallback 이 아닌 실제 렌더 RGB).

**RED (Playwright, 실 브라우저·mock 렌더러, 수정 전 — 그대로 실행한 원문)**

```text
[대비 실측] .bank-transaction-toast--error 전경=rgb(239, 68, 68) 배경=rgb(254, 226, 226) 대비=3.08:1
Error: 실제 렌더 대비 미달: rgb(239, 68, 68) on rgb(254, 226, 226) = 3.08:1
Expected: >= 4.5

```

`3.08:1`은 이 PR이 R1-2 브리핑 이전에 결함으로 판정해 고친 `.codef-import-hint--error`의
수정 전 값(3.76:1)보다도 낮다.

수정(`global.css`): `.bank-transaction-toast--error`의 `color`를 `--state-danger`(rgb(239,
