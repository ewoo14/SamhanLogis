# #887 슬5 R3 잔여 3건 구현·검증 보고서

## 범위

기획서에 명시된 도달 가능 잔여 3건만 다뤘다.

1. CODEF 오류 안내 `.codef-import-hint--error`의 실제 렌더 대비 미달
2. CODEF·일마감·안전재고 전체 범위 `aria-pressed` 칩의 키보드 해제 불가
3. 세 화면 미선택 안내의 전체 경로·대안 경로 불일치

이미 해소된 MED 7건·LOW 13건·pre-existing 4건과 V64 적용 마이그레이션은 열지 않았고, V65 이후 코드·문서도 수정하지 않았다.

## 1. RED-first 원문 → 수정 → GREEN

### 1-1. 대비 미달

운영 CSS를 수정하기 전에 실제 mock renderer에서 오류 힌트를 노출하고 브라우저 계산색과 배경색을 측정했다.

실행 명령:

```powershell
cd clients/desktop
& .\node_modules\.bin\playwright.cmd test playwright/887-s5-r3-batch/887-s5-r3-batch.spec.ts --reporter=line
```

RED 원문:

```text
[대비 실측] 전경=rgb(239, 68, 68) 기준토큰=rgb(153, 27, 27) 배경=rgb(255, 255, 255) 대비=3.76:1
Error: 오류 힌트가 자매 화면 위험색 토큰과 다른 실제 색을 사용함
Expected: "rgb(153, 27, 27)"
Received: "rgb(239, 68, 68)"
```

원인은 `.codef-import-hint--error`가 정의된 `--state-danger`의 실토큰을 렌더하고, 자매 화면이 사용하는 `--color-danger-700`과 달랐기 때문이다.

수정:

```css
.codef-import-hint--error {
  color: var(--color-danger-700);
}
```

GREEN 원문:

```text
[대비 실측] 전경=rgb(153, 27, 27) 기준토큰=rgb(153, 27, 27) 배경=rgb(255, 255, 255) 대비=8.31:1
7 passed (7.7s)
```

### 1-2. 키보드 해제 불가

수정 전에 CODEF·일마감·안전재고 테스트에서 같은 pressable 요소에 Enter를 두 번 보내고, Space도 두 번 보내도록 작성했다.

Vitest RED 원문(CODEF):

```text
FAIL ... 전체 범위 칩은 Enter와 Space로 켜고 끄는 왕복 조작이 된다
AssertionError: expected 'true' to be 'false' // Object.is equality
Expected: "false"
Received: "true"
```

Playwright RED 원문(세 화면 동일 증상):

```text
Locator: getByTestId('codef-all-scope-chip').locator('[role="button"]')
Expected: "false"
Received: "true"

Locator: getByTestId('daily-closing-all-chip').locator('[role="button"]')
Expected: "false"
Received: "true"

Locator: getByTestId('safety-stock-all-chip').locator('[role="button"]')
Expected: "false"
Received: "true"
```

원인은 `TagChip`이 이미 Enter·Space를 `onClick`으로 전달하고 있었지만, 세 화면의 전체 칩 클릭 핸들러가 매번 `ALL`만 설정했기 때문이다.

수정:

- `CodefImportScopeForm.tsx`: `toggleAllScope`를 추가해 `ALL`이면 `clearScope`, 그 외에는 `selectAllScope`를 호출한다.
- `DailyClosingPage.tsx`: 전체 칩 클릭에서 `execScopeMode === 'ALL'`이면 거래처 선택·draft 오류를 정리하고 `null`로 전환한다.
- `SafetyStockAlertsPage.tsx`: `toggleAllConfigScope`를 추가해 `ALL`이면 `null`로 전환하고 mutation 상태를 초기화한다.
- 공용 `TagChip`은 수정하지 않았다. CODEF 잠금 안내도 X만 유일한 해제 수단이라고 오해하지 않도록 칩 재누르기와 X를 함께 안내한다.

GREEN 원문:

```text
Test Files  3 passed (3)
Tests       75 passed (75)

Running 7 tests using 1 worker
7 passed (7.7s)
```

### 1-3. 대안 경로 안내 불일치

수정 전에 세 화면의 대안 경로를 각각 단언했다.

CODEF RED 원문:

```text
expected '전체로 처리하려면 \'전체\' 칩을 선택하세요.' to contain '특정 항목만 처리하려면 계좌·카드·대출 항목을 선택하세요.'
```

안전재고 RED 원문:

```text
expected '전체로 처리하려면 \'전체\' 칩을 선택하세요.' to contain '특정 창고만 처리하려면 창고를 선택하세요.'
```

일마감은 기존 문구가 이미 양쪽 경로를 명시해 해당 전수 테스트에서 RED가 발생하지 않았다. 따라서 이 항목의 실제 수정 대상은 CODEF·안전재고 2곳이며, 일마감은 계약 고정 테스트로 보존했다.

수정 문구:

```text
CODEF:     전체로 처리하려면 '전체' 칩을 선택하세요. 특정 항목만 처리하려면 계좌·카드·대출 항목을 선택하세요.
일마감:    전체로 처리하려면 '전체' 칩을 선택하세요. 특정 거래처만 처리하려면 거래처를 선택하세요.
안전재고:  전체로 처리하려면 '전체' 칩을 선택하세요. 특정 창고만 처리하려면 창고를 선택하세요.
```

GREEN 원문:

```text
Test Files  3 passed (3)
Tests       4 passed (4)
```

## 2. 대비 실측값

숫자는 CSS fallback이 아니라 Chromium `getComputedStyle`의 실제 렌더 RGB와 실제 불투명 배경 RGB로 계산했다.

| 상태 | 실제 전경 | 실제 배경 | 실제 대비 |
|---|---|---|---:|
| 수정 전 | `rgb(239, 68, 68)` | `rgb(255, 255, 255)` | `3.76:1` |
| 수정 후 | `rgb(153, 27, 27)` | `rgb(255, 255, 255)` | `8.31:1` |

수정 후 오류 힌트의 실제 렌더 색은 자매 화면이 사용하는 `--color-danger-700`의 실제 렌더 색과 동일하다.

## 3. 계열 전수 sweep

| sweep 대상 | 같은 패턴 수 | 수정 수 | 결과 |
|---|---:|---:|---|
| `aria-pressed` 전체 범위 칩: CODEF·일마감·안전재고 | 3 | 3 | 세 화면 모두 키보드·마우스 왕복 토글 |
| 미선택 범위 안내 `전체로 처리하려면` | 3 | 2 | 일마감은 이미 양쪽 경로 명시, CODEF·안전재고 보강 |

| CODEF 해당 클래스 JSX 소비처 | 6 | 공통 selector 1 | 6곳에 수정 색상 적용 |

## 4. 실행 명령·결과 원문

### 의존성 및 mock renderer 준비

워크트리에 의존성이 없어 아래를 실행했다. `npm ci`는 package-lock을 수정하지 않고 로컬 의존성만 설치했다.

```text
clients/desktop: added 1010 packages, and audited 1012 packages in 26s
clients/web/design-system: added 470 packages, and audited 471 packages in 14s
```

첫 Playwright 기동에서는 file 의존성인 디자인 시스템의 `dist`가 없어 Vite가 시작되지 않았다.

```text
[WebServer] Unable to resolve `@import "@samhan/design-system/tokens.css"`
```

## 5. 변경하지 않은 범위

- 이미 해소된 MED 7건·LOW 13건·pre-existing 4건은 재검토·재수정하지 않았다.

- `clients/web/design-system`의 `TagChip` 공용 컴포넌트는 수정하지 않았다.
