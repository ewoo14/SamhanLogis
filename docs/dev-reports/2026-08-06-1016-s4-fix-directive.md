## ② 불변식 — 수단이 아니라 사용자에게 반드시 참이어야 하는 결과

1. `VIEW=true`, `UPDATE=false` 사용자는 페이지와 CSV 다운로드를 계속 이용할 수 있지만 주소록 동기화를 실행할 수 없어야 한다.
2. 실행할 수 없는 사용자에게 동기화 버튼을 누르거나 재시도하라는 안내가 노출되어서는 안 된다. 왜 실행할 수 없는지 화면에서 즉시 알 수 있어야 한다.
3. `VIEW=true`, `UPDATE=true` 사용자의 최초 정상 경로에서는 동기화 버튼이 활성화되어야 하며 실제로 수행 가능한 실행 안내가 유지되어야 한다.
4. 서버가 `403 FORBIDDEN`을 확정한 뒤에는 즉시 재시도하면 성공할 수 있다고 말해서는 안 된다. 사용자는 권한이 필요하다는 원인과 다음 행동을 즉시 알 수 있어야 한다.
5. UPDATE 권한이 있고 서버가 5xx·네트워크 오류를 반환한 경우에는 기존의 재시도 가능한 오류 경로가 유지되어야 한다. 403 처리 때문에 일시 장애까지 권한 오류로 오표시하면 안 된다.
6. 권한 안내 변경이 `NOT_DELIVERED`의 mock 안내·신규 0·변경 0, `DELIVERED`·`PARTIALLY_DELIVERED`의 실제 전달 문구와 건수 표시를 바꾸면 안 된다.
7. CSV 다운로드가 알리고 전달 완료의 증거가 아니라는 고지는 VIEW 전용·UPDATE 보유·응답 성공·응답 실패 모두에서 유지되어야 한다.
8. VIEW 전용 사용자의 클릭·키보드 조작으로 sync POST가 발생해서는 안 되며, UPDATE 보유 사용자의 클릭은 기존 POST 경로를 그대로 호출해야 한다.

## ③ 양방향 RED — 반대급부 포함

### RED-A — VIEW 전용과 UPDATE 보유

- `VIEW=true`, `UPDATE=false`로 `/admin/aligo-address-book`에 진입한다.
- `admin-aligo-sync-btn`은 disabled이고 sync POST 호출 수는 0이어야 한다.
- 같은 화면에서 “주소록 동기화 실행 버튼을 눌러” 또는 그와 동등한 실행 지시가 보이면 RED다. 동기화 권한이 없다는 원인은 보여야 한다.
- 반대급부: `VIEW=true`, `UPDATE=true`로 같은 페이지에 진입하면 버튼은 enabled이고 수행 가능한 실행 안내가 보여야 한다. 권한 안내가 정상 사용자의 실행 경로를 가리거나 클릭 후 POST를 막으면 RED다.

### RED-B — 서버 403과 재시도 가능한 5xx 반대급부

- FE 권한 캐시는 UPDATE를 허용하지만 sync POST가 403을 반환하는 상태를 주입한다.
- 권한 원인 없이 “잠시 후 다시 시도”만 보이거나 동일한 즉시 재시도를 계속 권하면 RED다. CSV 고지는 남아야 한다.
- 반대급부: UPDATE 보유 사용자의 sync POST가 HTTP 5xx 또는 네트워크 오류를 반환하면 권한 오류가 아니라 기존의 재시도 가능한 오류로 보여야 한다. 403 분기가 일반 장애 안내를 없애면 RED다.

### RED-C — 전달 상태 표시 반대급부

- `NOT_DELIVERED`, `DELIVERED`, `PARTIALLY_DELIVERED` 응답을 각각 다시 주입했을 때 S2 지시서 불변식 1~5와 화면 6개 테스트가 그대로 통과해야 한다.
- 반대급부: 권한 안내 수정 때문에 정상 UPDATE 사용자의 결과 chip·실패 목록·CSV 고지 중 하나가 사라지거나 mock 문구 모순이 돌아오면 RED다.
