### 미실시 사유 및 환경 차단

핵심 발화 데이터 생성은 실제 GUI에서 판매전표 3건을 저장하는 데까지 진행됐으나, 회계 매출전표 배분 단계에서 중단됐다.

- 실제 GUI `회계 → 매출전표 → 작성`에서 날짜 `2026-08-03`, 거래처 코드 `P0-6-C002`, 거래처 `(주)서울택배`를 입력하고 `전표 검색`을 클릭했다.
- 화면에 빨간 오류 배너 `배분 가능한 전표 라인을 불러오지 못했습니다.`와 `배분할 원천 거래처를 확인할 수 없습니다.`가 표시됐고, 배분 가능한 라인이 0건이었다. 근거 캡처: `docs/qa/874-riusage-global-dc-real-qa/06-accounting-sales-slip-form.png`.
- 브라우저 GUI의 읽기 전용 네트워크 관찰상 원천 조회 `GET /internal/slips/by-period?type=OUTBOUND&from=2026-08-03&to=2026-08-03`가 HTTP 404였다. 이 요청은 사용자 지시대로 증거에서 제외한 slip-service PR #1059 빌드 경로에 해당한다. 해당 차단 때문에 QA 생성 판매전표를 회계 매출전표로 배분·전기할 수 없었고, accounting_db의 `POSTED` 모델축 행도 계속 0건이었다.
- 판매전표 상세에서 QA 전표의 `작성 중` 상태를 확인했고, `창고 전송` 단계 클릭도 실제 GUI로 시도했으나 상태 전환 응답/변화가 없었다. 기존 실전표에는 이 절차를 시도하지 않았다.
- 종료 시 read-only 확인: `sales_accounting_slips`는 `POSTED` 2,512건이었고 `memo ILIKE '%QA-874-%'` 회계 매출전표는 0건이었다.

따라서 시나리오 2~5는 결함 없음으로 처리하지 않고 **미실시**로 남겼다. 이 QA에서 DB 직접 INSERT, 기존 실전표·마스터·설정 수정·삭제, Docker build/up/restart, git commit/push는 하지 않았다.
