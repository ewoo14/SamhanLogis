## 1. 결론

PR의 중심 방향인 `ActorDisplayName.resolve(callerId, callerName)` 도입은 맞다. 백엔드 공통 함수는 canonical UUID, raw 32hex, `{32hex}`, `urn:uuid:32hex`, zero-width wrapper를 차단하고, `actorId`는 audit row/SSE payload/collab revision에 계속 남긴다.

그러나 “빠진 곳이 없다”는 결론은 성립하지 않는다.

1. 홈택스 이력과 제외 목록이 UUID를 그대로 표 셀에 렌더한다.
2. 협업 코멘트/편집 이력 6개 컨트롤러는 canonical/raw32만 막아 brace/URN/zero-width 변형을 그대로 저장·전달한다.
3. 프런트 공통 `safeActorName`은 `{32hex}`와 `urn:uuid:32hex`를 놓친다.
4. SYSTEM actor는 공통 백엔드에서 `system`으로 내려오며 generic audit/version/redline 화면에서 한국어 `시스템`으로 변환되지 않는다.
5. auth-service는 화면 후보에 한해서만 N/A다. 권한 변경 application log에는 actor UUID가 직접 삽입되므로 “로그까지 포함한 sweep”에서는 N/A가 아니다. dashboard-service의 화면 N/A는 타당하다.
6. live QA는 shared DB read-only 계약을 위반하고, 새 변형을 검증하지 않으며, fresh 실행도 inventory HTTP 503으로 실패했다.

## 7. 구현자 수정 지시서

### 불변식

1. UUID는 화면 텍스트/tooltip/aria/엑셀/인쇄/알림 본문에 노출하지 않는다.
2. actorId/callerId/deleterUserId/processedBy는 저장·조인·route·색상 hash·SSE 상관관계 키로 보존한다.
3. UUID가 아닌 정상 이름은 문자 단위로 바꾸지 않는다.
4. unknown은 기존 표현 `변경자 미상`, SYSTEM actor의 사용자 표시만 `시스템`이다.
5. UUID 판별 정본을 backend/common과 frontend/design-system 각각 하나로 수렴시키고 별도 약한 정규식을 만들지 않는다.
6. shared DB live QA는 GET만 허용한다. 로그인처럼 상태를 바꾸는 호출은 pre-issued session을 쓰거나 datasource URL이 명시된 격리 DB에서만 실행한다.

### RED-A 표적

1. design-system `safeActorName` table test에 canonical, raw32, `{canonical}`, `{32hex}`, URN canonical, URN raw32와 각 zero-width wrapper를 넣고 전부 null인지 먼저 실패시킨다.
2. F-3의 모든 consumer에서 최소 대표 1개씩 raw UUID가 DOM/tooltip/aria에 없고 `변경자 미상`인지 실패 테스트를 만든다.
3. 협업 컨트롤러 6개 모두 같은 변형 table test를 적용한다. 응답/저장 authorName에는 UUID가 없어야 하지만 callerId/actorId/deleterUserId는 원본 그대로인지 함께 단언한다.
4. 격리 DB 홈택스 테스트에서 `processedBy`와 BaseEntity `createdBy`는 UUID로 저장된 채, history/exclusion 표시 DTO와 실제 UI에는 정상 이름 또는 `변경자 미상`만 나오는지 단언한다.
5. AuditOverlay, AuditVersionHistory, redline/version 대표 화면에 zero actorId + actorName `system` fixture를 넣어 `시스템`만 보이는지 실패시킨다.
6. auth application log는 내부 actorId 상관관계를 잃지 않으면서 사용자 노출 메시지 본문에 UUID가 섞이지 않는 구조인지 검증한다.
7. real-QA는 로그인 POST 없이 실행되도록 바꾸고, 스펙 자체가 모든 UUID 변형과 홈택스/collab/version 표면을 각각 고유 요소로 단언하게 한다. screenshot은 계속 `resolveQaShotsDir()`만 사용한다.

### 구현 중단 조건

**제 전제가 틀렸다면 고치지 말고 중단·보고**하십시오. 특히 홈택스 DTO 앞에 gateway display-name 변환이 있거나 collab 응답 앞에 별도 sanitizer가 있다는 증거가 있으면, 그 좌표와 실제 wire payload를 먼저 제시해야 한다. 내부 UUID 필드를 삭제하거나 문자열 `system`을 DB에서 한국어로 치환하는 방식도 중단·보고 대상이다.

## 8. 재검토 때 확인할 표면

이번 라운드는 정적 경로와 기존 unit/integration suite를 전수 확인했지만, 공유 서비스 503과 write 금지 때문에 홈택스/협업 6종에 공격 fixture를 실제 주입하지 않았다. 재검토는 datasource URL이 명시된 격리 DB에서 해당 wire payload와 DOM을 확인해야 한다. 운영 로그 집계 UI, 실제 생성된 XLSX/PDF 바이너리, mobile-staff의 audit wire 계약은 이번 live QA가 보지 않은 표면이다.
