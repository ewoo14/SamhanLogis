### F1 — `categoryKey` 파생 fallback이 변동DC 비대상 품목까지 전역DC 대상으로 만든다

적용 좌표:

읽기 SQL 재현 결과:

```text
품목 전체(non-deleted) 3,183 = ACTIVE 3,179 + DISCONTINUED 4

ACTIVE · product_category IS NULL 파생 대상
INDOOR_WALL    58 = AR 29 + AF 19 + AX 10  -> 전부 homemulti
INDOOR_CEILING 10 = AC 10                  -> 전부 commercialMulti
OUTDOOR        24 = AM 24                  -> 전부 commercialMulti
```

구체 표본 `AX17B17NNDB-86`은 `삼성 비스포크 큐브 17㎡` 공기청정기이고 정가가 204,000원이다. 현재 코드는 `INDOOR_WALL → homemulti`로 파생한 뒤 거래처 `4348703365`의 `home_discount_rate=0.4800`을 적용하므로 화면 단가가 **106,080원**이 된다. 변동DC 비대상인 이 품목의 기대값은 정가 **204,000원**이다. 같은 오분류 표면에 스탠드형 AF 19개와 공기청정기 AX 10개가 포함된다.

R76의 `AR09TXEAAWKNEU-04`도 현재 DB에서 `product_category=null`, `has_variable_discount=false`다. R76이 기록한 561,600원은 계산 자체는 재현되지만, 적용 자격을 확인하지 않은 결과다.

- 재현 난이도: **쉬움**. 전역DC 48% 거래처를 고른 뒤 판매전표에서 `AX17B17NNDB-86`을 선택하면 저장 전 화면에서 106,080원을 관찰할 수 있다. DB 쓰기 없이 화면 단가까지만 확인 가능하다.

### 닫힌 대조와 증거 무결성

- 화면을 거치지 않는 `POST /slips`는 `CreateSlipRequest.lines[].unitPrice`를 필수로 받고 서버가 그대로 저장한다. 정가를 보내면 정가, 할인 완료값을 보내면 그 값이며 서버 이중 적용은 없다. 모바일 판매전표는 같은 `SlipFormPage`를 사용하므로 F1·F2를 그대로 공유한다. 견적/주문 전환은 각 원천의 권위 단가를 별도 publish 경로에서 보존한다.
- 전역DC 단위는 DB `0.4800` → 외부 DTO `48%` → FE 숫자 `48` → `/100` 계산, 회계 내부 경로는 `0.4800 × 100`으로 분리되어 있다. 추가 단위 오인은 찾지 못했다.
- R63→R76의 핵심 수치 흐름(정가 미반영 → 고정DC 970,200 → 이중 적용 494,802 → 화면 권위 → R76 561,600/970,200·201)은 각 보고서와 응답 원문에서 재현된다.
- 다만 “활성 품목 3,183개”는 현재 DB에서 재현되지 않는다. **3,183은 non-deleted 전체**, ACTIVE는 **3,179**다.
- 착수 전부터 R71 증거 10개와 R76 `renderer.log`가 working tree에서 수정 상태다. R76의 POST 응답·network response·스크린샷은 수정되지 않았으며 핵심 수치는 그 원문으로 대조했다.

## 2. 불변식

1. 전역DC는 해당 품목이 변동DC 적용 대상일 때만 적용한다. 물리 보관 카테고리만으로 적용 자격을 새로 만들면 안 된다.
2. 명시적 `product_category`가 있는 기존 품목, 고정DC 품목, 변동DC 대상 품목의 현재 정상 가격을 훼손하면 안 된다.
3. DC 조회의 실패·지연·404가 품목 선택 완료나 저장 가능 상태를 장시간 막으면 안 된다. 실패 시 정가 fallback으로 수렴해야 한다.
4. 유효한 DC 응답이 제때 도착한 정상 경로에서는 화면 권위, 화면=저장, 고정DC 우선, `discountInfo`, UUID 비노출을 유지한다.
5. 서버 재계산을 되살려 화면 단가에 DC를 이중 적용하면 안 된다.

## 3. 양방향 RED

### RED-A — F1 오적용과 반대급부

- `hasVariableDiscount=false`, `product_category=null`, 물리 카테고리 `INDOOR_WALL`, 전역DC 48%, 정가 204,000인 AX 공기청정기는 화면·payload 모두 204,000이고 전역DC 문구가 없어야 한다.
- 반대급부: 동일 거래처에서 `hasVariableDiscount=true`인 정상 홈멀티 1,080,000원 품목은 화면·payload 모두 561,600이고 `거래처 전역DC 48% 적용`을 유지해야 한다.
- 반대급부: 고정DC 40% 품목은 변동DC 플래그와 무관하게 970,200원이며 전역DC로 덮이지 않아야 한다.
- 데이터 분포 회귀: 물리 카테고리 fallback 결과와 적용 자격을 별도로 집계해, AF/AX처럼 다른 상품군이 홈멀티 적용 대상으로 승격되지 않음을 고정한다.

### RED-B — F2 지연 차단과 반대급부

- DC GET이 미완료인 상태에서도 품목 선택은 확정되고, 저장 경로는 정가 fallback으로 유한 시간 안에 활성화되어야 한다.
- 반대급부: DC GET이 정상 응답하면 전역DC 대상 품목은 할인 완료 단가와 설명을 사용하고, 이후 최근단가가 이를 덮지 않아야 한다.
- 반대급부: 이전 거래처의 DC 응답이 늦게 도착해도 새 거래처 라인 가격이나 `discountInfo`를 오염시키지 않아야 한다.
- 반대급부: 저장 서버는 화면이 보낸 단가를 한 번만 저장해 494,802 같은 이중 적용값을 만들지 않아야 한다.
