# #1069 S5 fix 보고서 — 판매전표 세트 전개

## 판정

S4 지시서의 남은 결함 3을 수정했다. 거래처 최근단가 조회가 지연되는 동안 사용자가 변경한 최신 수량·단가를 세트 전개 요청에 반영하고, 직접 단가 입력으로 최근단가 적용이 무효화되어도 BUNDLE 전개가 누락되지 않도록 했다.

S2 결함 1(BUNDLE 영속 우회)·2(규격 승계)의 구현은 변경하지 않았다.

## RED-first 증거

신규 회귀 2건을 먼저 추가하고 기존 코드에서 실행했다.

```text
SlipFormPage.test.tsx (66 tests | 2 failed | 64 passed)

1. 거래처 최근단가 대기 중 바꾼 최신 수량으로 세트를 전개한다
   expected quantity: 3
   received quantity: 1

2. 거래처 최근단가 대기 중 직접 입력한 단가로 세트를 한 번 전개한다
   expected expandBundleLine: 1 call
   received: 0 calls
```

## 수정 내용

- `SlipFormPage.tsx:910-937`
  - 가격 응답 도착 시 선택 당시 `nextLine` 대신 `linesRef.current`의 최신 BUNDLE 행을 스냅샷으로 사용한다.
  - 수량·규격·옵션 등 최신 행 변경은 그대로 전개 요청에 전달한다.
  - 최신 행의 `priceSource`가 `USER`이면 직접 입력한 최신 단가를 유지한다.
  - 직접 단가 입력으로 가격기억 적용이 무효화되어도 최신 BUNDLE 행 전개를 계속 호출한다.
  - 품목 교체로 최신 행이 SINGLE이 된 경우에는 기존 stale guard에 따라 늦은 BUNDLE 전개를 적용하지 않는다.
- `SlipFormPage.test.tsx:802-861`
  - 지연 최근단가 + 수량 `1→3`에서 `quantity=3` 요청 및 1회 전개를 고정했다.
  - 지연 최근단가 + 직접 단가 입력에서 최신 단가 요청, 1회 전개, BUNDLE 부모 0행을 고정했다.
