## 1. 결함 원인과 수정

R83의 F1을 재현하는 RED 테스트를 먼저 추가했다. `SlipFormPage`는 거래처 선택 순간 non-null 거래처에 대해 공용 `partnerReprice` 세션을 즉시 무효화하지 않았고, bulk 완료 시 훅의 `isCurrent()`만 확인했다. 새 DC가 끝나 새 run을 시작하기 전 직전 거래처 bulk가 현재 거래처 라인에 적용될 수 있는 구조였다.

수정은 두 축을 함께 적용했다.

1. 거래처 선택 직후 `partnerReprice.invalidate(partner?.id ?? null)`을 호출해 직전 DC/최근단가 세션을 즉시 stale 처리했다.
2. bulk outcome 적용 직전에 `partnerRepriceSessionIsCurrent(requestSeq, dcRequestSeqRef.current, partnerId, selectedPartnerIdRef.current, isCurrent())`를 검사해 훅 세대·소비자 DC 세대·현재 거래처가 모두 일치할 때만 적용하도록 했다.

stale 결과는 이 가드에서 즉시 return하므로 라인 단가, `discountInfo`, `lookupLoading`, `priceRefreshChanged`, aria-live를 쓰지 않는다. 기존 USER 보호, 고정DC/전역DC 계산, timeout fallback, 서버 저장 계약은 변경하지 않았다.
