# #1013 CI 실패 수정 보고서

## 환경 차이

- PM 보고: `clients/desktop/node_modules` 및 `clients/web/design-system/node_modules`가 없어 직전 로컬 typecheck를 실행하지 못함.
- CI와 동일하게 design-system 선행 빌드 후 desktop 의존성을 준비한다.

## 원인

- `npm run typecheck`: 의존성 준비 후 실패 0건으로 통과. 직전 라운드의 미실행은 로컬 의존성/`dist` 부재 때문이었다.
- Playwright 실패 스펙: `clients/desktop/playwright/sp-08-3-4-dispatch-sms-history/sp-08-3-4-dispatch-sms-history.spec.ts`
- 최초 로컬 실행의 원문: `TimeoutError: locator.waitFor ... dispatch-sms-history-tab-run` — 로그인 화면이 표시되어 mock 서버가 아닌 기존 5173 서버 재사용으로 판정.
- CI 재현 방식으로 mock 서버를 새로 띄운 뒤의 원문: `Timeout ... locator.check ... <input disabled ... dispatch-sms-confirm-checkbox/>`.
- 원인: mock preview의 미매핑 항목에 `recipientPhone`이 없어 새 발송 모집단이 0건이 되었고, 확인 체크박스가 비활성화됨. 옛 동작을 단언한 스펙이 아니라 정상 경로를 막은 fixture 결함이다.

## 수정

- mock preview 미매핑 항목에 메시지와 수신번호 필드를 보완해 화면 건수와 실제 요청 대상이 일치하도록 함.
- mock send가 요청 entry를 기준으로 결과를 생성하도록 변경. `room:` 수신번호는 `BLOCKED`로 집계하고, 기존 저장내역의 placeholder `FAILED` 집계 fixture는 유지.
- 실 알리고 호출·실 DB 쓰기·Docker 작업 없음.
