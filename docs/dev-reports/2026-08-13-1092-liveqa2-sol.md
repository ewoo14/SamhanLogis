## 실행 경계와 증거 무결성

인앱 Browser 런타임은 실제로 `[]`였으므로 지시대로 Playwright Chromium을 사용했다. 첫 실행에서 공유 `api-gateway`가 2026-08-11 구이미지라 snapshot route가 404였고, `slip-service`도 UUID 제거 전 응답을 반환했다. 이는 fix 보고서에 적힌 “라이브 서비스 JAR 미교체” 상태와 일치했다. 현재 브랜치의 DB migration 없는 `api-gateway`·`slip-service` JAR만 빌드해 해당 컨테이너를 교체한 뒤 모든 시나리오를 처음부터 다시 실행했다. 최종 판정은 교체 후 실행만 사용했다.

공유 DB에는 아래 집계만 각각 `BEGIN TRANSACTION READ ONLY`로 실행했다. `INSERT`/`UPDATE`/`DELETE`/DDL은 실행하지 않았다. 로그인은 `last_login_at`을 갱신하므로 호출하지 않았고, 읽기 전용 QA JWT를 사용했다. 브라우저에서 gateway 대상 비-GET 요청을 전부 차단했으며 저장·편집·복원·발송·전환 버튼은 누르지 않았다.

```text
DB READ ONLY
estimates|45
partner_orders|4
quote_snapshots|4
partner_order_drafts|11

브라우저 gateway 허용: GET / HEAD / OPTIONS
차단: POST /logs/front 3회
차단: 주문서 collab presence join/leave 2회
차단: 견적 collab presence join/leave 2회
공유 DB 쓰기: 0건
```

## 3. 견적 목록·상세 API UUID 비노출

실행: 실 사용자 목록/상세 흐름에서 발생한 fetch/XHR 응답 본문 전체를 아래 UUID 정규식으로 전수 검사했다.

```text
[0-9a-f]{8}-[0-9a-f]{4}-[1-5][0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}

GET /slips/estimates?page=0&size=50      HTTP 200 | body 18,297 bytes | UUID 0
GET /slips/estimates?page=0&size=10000   HTTP 200 | body 18,303 bytes | UUID 0
GET /slips/estimates/{내부 식별자}       HTTP 200 | body 913 bytes    | UUID 0
상세 data.lines 1건 전체 JSON                         | UUID 0
```

**PASS.** 목록·상세·중첩 line 배열까지 UUID가 0건이었다. URL의 내부 식별자는 보고서와 화면에 전재하지 않았다.

## 5. 기존 데스크톱 견적·주문 상세 회귀

실행 원문:

```text
데스크톱 주문서 행 2026/08/07-1 클릭
→ 주문서 상세 2026/08/07-1
→ 거래처 코드 1068689215, 합계 1,576,036원, 라인 4건 표시
결과: PASS

데스크톱 견적 행 2026/08/10-9 클릭
→ /sales/estimates/2026/08/10-9
→ 404 페이지를 찾을 수 없습니다
결과: FAIL

기존 bookmark/deep-link 재확인
→ 견적서 상세 [2026/08/10-9], 삼성전자(1010120290), 총합 88,215,600원, line 1건 표시
결과: 기존 UUID deep-link route 자체는 열림
```

**FAIL.** UUID 제거 후 목록 DTO의 `id`가 문서번호로 바뀌었지만 목록 클릭 라우트는 그 값을 경로로 그대로 사용한다. `/`가 포함된 문서번호가 여러 URL segment로 해석되어 404가 된다. 기존 상세 route가 가려진 것은 아니고 **목록에서 상세로 가는 식별 계약이 끊겼다.**
