## M/N 계약과 저장 불능 조합 탐색

headless Chromium의 브라우저 타임존을 UTC로 강제하고 실 renderer를 조작했다.

1. REGION, M=`2026-08-08`에서 자동 N은 `2026-08-10`이었다.
2. 사용자가 N을 `2026-08-14`로 고친 뒤 M을 `2026-08-09`로 변경했다.
3. N은 `2026-08-14`로 **보존**됐고, `출고일(M)과 하차일(N)을 확인하세요...` 오류가 화면에 나타났다.
4. 새 M의 올바른 N=`2026-08-10`으로 고치자 오류가 사라졌다. 조용한 재계산이나 영구 저장 차단은 없었다.

증거:

- `docs/qa-shots/1074-s6-live-qa/01-n-preserved-after-m-change-error.png`
- `docs/qa-shots/1074-s6-live-qa/02-n-corrected-error-cleared.png`

실 API 저장 조합도 별도로 밟았다.

| 조합 | 결과 |
|---|---:|
| REGION 기본 N=`2026-08-10` | 201 |
| STACK 토요일 M → 일요일 N=`2026-08-09` | 201 |
| REGION 당착 N=M=`2026-08-08` | 201 |
| REGION 사용자 override N=`2026-08-14` | 201 |

따라서 **어떤 N을 선택해도 저장할 수 없는 조합은 발견되지 않았다.** 화면은 M 변경으로 기존 수동 N이 규칙과 어긋날 때 오류를 명시하고, 맞는 N으로 복구할 수 있다. 서버는 사용자 override N도 보존해 201로 저장했다.
