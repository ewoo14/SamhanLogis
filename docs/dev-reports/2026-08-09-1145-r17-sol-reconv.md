### 1.3 증거 무결성·데이터 안전

기존 R14 격리 auth DB에는 V99가 있으나 V98이 없어 HEAD auth-service가 `Detected resolved migration not applied to database: 98`로 기동을 거부했다. 제품 결함으로 세지 않고, 같은 전용 PostgreSQL 안에 빈 `auth_r17_db`를 만들어 HEAD Flyway가 V96 → V98 → V99를 순서대로 적용한 상태에서 검증했다. V99 SQL은 변경하지 않았다.

공유 `auth_db`와 `slip_db`에는 아래 모든 SQL을 `BEGIN TRANSACTION READ ONLY`로 실행했다. GUI 저장 결과는 격리 `accounting_db`에만 기록했다.

## 3. 각도 1 — 반대급부: CREATE 보유 역할

### 3.1 발화 조건 카운트

공유 `slip_db` 원문:

```sql
BEGIN TRANSACTION READ ONLY;
SELECT slip_type,
       count(*) AS confirmed_rows,
       count(*) FILTER (
         WHERE partner_id IS NOT NULL
           AND NULLIF(btrim(partner_code),'') IS NOT NULL
           AND NULLIF(btrim(partner_name),'') IS NOT NULL
       ) AS partner_complete_rows
FROM slips
WHERE status='CONFIRMED' AND is_deleted=false
GROUP BY slip_type
ORDER BY slip_type;
COMMIT;
```

```text

```

공유 실 `auth_db` SELECT 원문:

```sql
BEGIN TRANSACTION READ ONLY;
SELECT role_code, page_code,
       can_view::int::text || can_create::int::text ||
       can_update::int::text || can_delete::int::text ||
       can_restore::int::text || can_download::int::text ||
       can_print::int::text AS permission_mask
FROM role_page_permission_templates
WHERE role_code='MANAGER'
  AND page_code='inbound.inspection'
  AND is_deleted=false;
COMMIT;
```
