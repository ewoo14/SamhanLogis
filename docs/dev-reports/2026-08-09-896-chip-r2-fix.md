## 먼저 확정한 사실

### ① 리모컨 RED-A 원인 판정

원문 RED는 기준 수량 2에서 다음과 같았다.

```text
PC6NUDK1NW 판넬: 2
AWR-WE13N 리모컨: 0
FH-LFHLN 유연호스: 2
```

정적 소비 경계는 `clients/web/estimate-app/views/index.ejs:8335-8356`의
`applyServerHomeQuantitySync_()`이고, 호출자는 `:8360-8369`의
`recomputeHomeDerived()`이다. evaluator가 null이면 `:8371`부터 레거시 계산으로
fall back한다. 이 위치 자체에는 리모컨만 제외하는 분기가 없다.

제가 현재 실행 중인 product-service에 직접 측정한 값은 다음과 같다.

```text
HOME_MULTI 품목: 121건
AWR-WE13N: 1건
PC6NUDK1NW: 1건
FH-LFHLN: 1건
GET /products/internal/estimate-catalog/quantity-sync-rules?estimateCategory=HOME_MULTI
→ HTTP 500 / INTERNAL_ERROR
```

따라서 리모컨 전용 분기(`recomputeHomeRemotes`)가 원인이라고 확정할 수 없다.
현재 증거상 셋째 가능성은 **규칙 bootstrap endpoint 500 → 서버 규칙 소비 실패 →
레거시 fallback**이다. 이 상태에서 리모컨 특수 분기를 임의 수정하지 않았다.

### ② 주문서 카테고리 및 품목 표본

기존 하드코딩은 `clients/web/order-app/src/samhanApi.ts:190`의
`estimateCategory: 'SINGLE_SET'`이었다. 주문 화면 맥락에 맞춰 `HOME_MULTI`로
변경했다.

현재 product-service 직접 측정 표본은 HOME_MULTI 121건이다. 따라서 “품목 0건”은
현재 측정값과 다르며, 이 워크트리 환경에서의 라이브 RED-B는 판정 불가다.
다만 기존 adversarial 보고서의 당시 bootstrap 원문은 `homemulti: []`였으므로,
그 실행 시점의 RED-B는 **표본 0 — 판정 불가**로 기록한다.

### ③ 하드게이트 원인과 수정

두 스펙이 보호하던 것은 스펙 변경 없이 기존 추가 영역의 칩 카운트를 유일하게
조회하는 계약이다. `CategoryCell`마다 새 수량 동기화 `ProductMultiSelectAutocomplete`를
렌더하면서 공용 `data-testid="multiselect-chip-count"`가 여러 개 생겼다.

수정은 `clients/web/design-system/src/components/MultiSelectAutocomplete/MultiSelectAutocomplete.tsx:168`
에서 `inputTestId`가 있으면 `${inputTestId}-chip-count`를 사용하게 한 것이다.
기존 호출자의 기본 testid는 그대로 유지하고, 행별 수량 동기화 입력은 이미 고유한
`inputTestId`를 전달하므로 두 기존 Playwright 스펙을 수정하지 않았다.

## RED-A~D

- RED-A: 원문 재현값은 판넬 2 / 리모컨 0 / 유연호스 2. 현재는 endpoint 500이라는 셋째 가능성이 발견되어 리모컨 특수 분기 원인을 확정·수정하지 못했다.
- RED-B: 당시 live bootstrap `homemulti: []` → **표본 0 — 판정 불가**. 현재 직접 측정은 121건이나, 주문서 전체 발화는 재현하지 못했다.
- RED-C: 공용 컴포넌트 RED 테스트 1건 실패 후 고유 testid 수정으로 1건 통과. 두 Playwright 스펙은 이 환경에서 인증/서버 기동 문제로 원문 hard gate 재검증을 완료하지 못했다. 스펙 파일은 수정하지 않았다.
- RED-D: adversarial 원문 기준 `AM060BN6PBH1`은 before/after 모두 수량 공백, 납품가 `575,960`, 소계 `0`이었다. 이번 변경에서 해당 계산 경로는 건드리지 않았다.
