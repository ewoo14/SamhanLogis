# #1069 S7 fix 보고 — 판매전표 세트 전개

## 판정

S6 지시서의 결함을 재현했고, 응답 적용 시 부모 규격의 권위를 요청에 사용한 최신 BUNDLE 스냅샷으로 고쳤다. RED-A/RED-B 협소 회귀를 추가한 뒤 두 건이 모두 GREEN이 되었다.

## RED-first 원문

수정 전 협소 실행:

```text
npx vitest run src/renderer/routes/SlipFormPage.test.tsx -t "지운 부모 규격" --reporter=verbose
Test Files  1 failed (1)
Tests       2 failed | 66 skipped (68)
실패 1: expected '현장규격' to be ''
실패 2: expected '현장규격' to be ''
```

두 실패 모두 전개 요청은 `specification: undefined`였으나, 구성품 자체 규격이 `null`인 응답을 화면에 적용할 때 삭제 전 `source.specification`이 fallback으로 사용되어 `현장규격`이 부활했다.

## 경합 규칙 — 필드별 권위

세 시점의 의미는 `요청 시점 값`, `응답 도착 시점 값`, `그 사이 사용자가 바꾼 값`이다. 기본 규칙은 모든 필드에서 **사용자가 마지막에 한 행동이 이긴다**. 전개 응답은 서버가 반환한 구성품 고유값만 채우고, 부모에서 승계하는 값은 해당 요청에 실제 사용한 최신 부모 스냅샷을 쓴다. 세대가 바뀌면 이전 응답을 버리고 최신 값으로 재전개한다.

| 필드 | 요청 시점 | 응답 도착 시점 | 사이 사용자 변경 | 최종 권위/이유 |
|---|---|---|---|---|
| 수량 | 요청 스냅샷 | 응답 구성품 수량 | 최신 사용자 수량 | 사용자 변경이 있으면 최신 수량으로 재전개·적용 |
| 단가 | 요청 스냅샷 | 응답 구성품/가격 결과 | 최신 직접 입력 또는 최근단가 적용 | 사용자 마지막 단가가 이김; 가격 대기는 최신 행으로 1회 재전개 |
| 규격 | 최신 부모 스냅샷 | 구성품 자체 규격 또는 null | 최신 입력/삭제 | 구성품 자체 규격이 있으면 서버값 우선, 없으면 요청에 사용한 최신 부모값. 과거 `source`는 금지 |
| 옵션 | 요청 스냅샷 | 전개 응답의 구성 결과 | 최신 옵션 변경 | 세대 불일치 시 최신 옵션으로 재전개; 이전 응답은 폐기 |
| 품목 | 요청 스냅샷 | 전개 응답 구성품 | 최신 품목 교체 | 품목/종류/세대가 달라지면 이전 응답을 적용하지 않음 |

예외처럼 보이는 규격의 구성품 자체값 우선은 사용자 변경을 무시하는 예외가 아니다. 그것은 부모 규격을 승계하지 않는 구성품의 도메인 고유값이며, 사용자가 그 구성품 자체 규격을 직접 편집하는 경로가 있으면 동일한 세대 규칙으로 사용자값이 우선한다.

## 원인과 수정

- 원인: `replaceWithExpandedBundleLines`가 응답의 `null` 규격 fallback으로 선택 시작 시점의 `source.specification`을 사용했다.
- 수정: 함수에 `parentSpecification`을 명시적으로 전달하고, 정상 응답은 `selected.specification`, 실패 응답은 응답 적용 시점의 `latest.specification`을 사용한다.
- 세트 부모 제거, 구성품 1세트 유지, BUNDLE 부모 비노출, trailing 빈행 규약은 기존 경로를 그대로 유지했다.
