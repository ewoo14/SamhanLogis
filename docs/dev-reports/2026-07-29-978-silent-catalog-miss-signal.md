# #978 B-2 후속 — 카탈로그 누락이 조용히 끝나지 않게

- 일자: 2026-07-29 (회사PC) · 관련 #978 B-2 · PR #967
- 정찰 근거: [이슈 #978 코멘트](https://github.com/ewoo14/Samhan-Public/issues/978)

## 1. 정찰이 남긴 결론

지목된 조용한 skip 4곳(`order-app/index.html` 현재 `5660 · 5675 · 5695 · 5730`)은 **현재 로컬 실 API 기준 신규 금액 손실 0원** 입니다. 실 bootstrap 의 상업멀티 404행 전체 sweep 에서 missing 0건.

**그러나 넷째 위치는 과거 실제로 도달했습니다** — 구버전 `chooseBaseModel()` 이 `ACL-KORGHP06` 을 만들었는데 카탈로그에 없어 이 sink 로 빠졌고, `9 × 6,710,000 = 60,390,000원` 이 주문서에서 통째로 사라졌습니다. PR #967 이 `ACL-KORGHP07` 로 고쳐 그 사례는 해소됐습니다.

## 2. 남은 것 — sink 자체는 여전히 조용합니다

`requireCommCatalogRow_()` 도입으로 **`AR-EH05` 와 `방진가대S2중` 만** 별도 오류를 던집니다. 그 밖의 카탈로그 누락은 여전히 조용히 끝납니다.

⟹ B-2 의 답은 *"지금 돈이 새고 있지 않다"* 이지 *"이제 안 샌다"* 가 아닙니다. 카탈로그가 drift 하면(운영 시트 변경 · 모델 단종 · 오타) **같은 형태가 재발하고, 재발했을 때 사용자에게 아무 신호도 가지 않습니다.**

## 3. 불변식

1. **파생 품목이 카탈로그에 없어 계산에서 빠지면, 사용자가 그 사실을 안다** — 조용히 끝나지 않는다
2. 신호는 **어느 모델이 빠졌는지**를 알려준다
3. **정상 입력의 동작·금액이 이 변경으로 달라지지 않는다** — 경고가 정상 흐름을 막지 않는다
4. 인쇄물에는 이 신호가 나오지 않는다

⚠️ 수단은 지시하지 않습니다. 다만 이 저장소에서 **"작은 박스 안에 경고를 우겨넣는" 접근이 4라운드 연속 새 표면을 만든 전례**(#965/PR #968)가 있습니다 — 정보를 어디에 둘지부터 정하십시오.

## 4. 검증

- **RED-first** — 카탈로그에서 특정 모델을 뺀 상태를 **실 경로가 만들 수 있는 형태**로 재현해, 현재는 조용히 끝나는 것을 RED 로 고정
- 회귀 울타리는 합성이 아니라 **실 bootstrap 이 반환하는 404행**으로
- 라이브QA — 실 화면에서 신호가 보이는 스크린샷

## 5. 다루지 않는 것
