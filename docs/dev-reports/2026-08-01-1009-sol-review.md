## 도달 가능 결함

### SOL-01 — `VAT 별도` 견적을 저장하면 공급가·부가세·총액이 다른 금액으로 기록된다

1. **실 사용자 경로**

견적 작성 → `VAT별도 표기` 선택 → 품목 합계 100,000원 → `견적저장`. 화면 계산은 VAT 선택값을 금액에 반영하지 않고 라벨만 `VAT 별도`로 붙인다. 저장 코드는 선택값을 읽지 않은 채 화면 합계를 VAT 포함 총액으로 간주해 `floor(total/11)`을 부가세로 역산한다. 따라서 DB 계약상 `total_amount = supply_amount + vat_amount`여야 하는 VAT 별도 견적이 100,000/10,000/110,000원이 아니라 90,910/9,090/100,000원으로 저장된다. 저장 후 재오픈해도 저장 숫자는 그대로이므로 화면 의미와 DB 금액이 재현되지 않는다.

### SOL-03 — 작성자 권한을 대상자 집합이 아니라 `authorEmail` 조건절로 우회했다

1. **실 사용자 경로**

### SOL-04 — 본인 수정 API가 사용자 화면에 연결되지 않아 작성자도 저장 행을 수정할 수 없다

## 이번 라운드가 보지 않은 축

- 인앱 브라우저가 연결되지 않아 실제 화면 클릭, 시각 표시, 저장→목록→복원→발행 전체 여정은 실행하지 못했다.
- 실 DB에 기존 견적이 0건이라 실제 base64 과거 행의 V100 변환·재오픈은 실행 대상이 없었다.
- 실 DB 쓰기 금지로 실제 UI 저장 뒤 `snapshot_state`와 세 금액 컬럼을 실 DB에서 직접 대조하지 않았다. 테스트 전용 PostgreSQL의 HTTP 통합 경로만 실행했다.
- 기존 견적 작성·계산·발행의 브라우저 회귀는 실행하지 못했다. 커밋 diff상 저장·이력 화면 외 계산·발행 함수 변경 여부만 확인했다.
- 대상자 기반 알림·필터·통계 소비자는 현재 견적 스냅샷 경계에 존재하지 않아 실제 소비자 실행은 없었다.
- tracked 레거시와 live 레거시 사이 미확보 373행은 보지 않았다.
