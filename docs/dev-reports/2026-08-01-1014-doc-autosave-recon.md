# 1014 문서 자동 저장·이력 레거시 대조 조사

## 조사 범위

- `tools/legacy-gas`의 실제 디렉터리 나열로 세 번째 대상의 정확한 폴더명이 `내일자 전표 이미지 생성`임을 확인했다.
- 조사 대상은 `거래처별 원장생성 프로그램`, `거래처별 일괄 거래명세서 생성`, `내일자 전표 이미지 생성` 세 디렉터리로 한정한다.

## 1. 거래처별 원장생성 프로그램 — 레거시 확인

| 레거시 동작 (원문 인용 + `파일:행번호`) | 현행 위치 또는 **없음** | 같음 / 다름 / 확인불가 | 다르면 무엇이 |
|---|---|---|---|

| 입력은 사용자가 매출·입금·채권·계정별원장 Excel 네 영역을 올린다. 원문: `accept=".xlsx, .xls"` (`tools/legacy-gas/거래처별 원장생성 프로그램/Index.html:159-162`), `onclick="startProcessing()">처리실행</button>` (`tools/legacy-gas/거래처별 원장생성 프로그램/Index.html:178`). 따라서 예약·시간 기반 자동 생성이 아니라 파일 업로드 뒤 버튼을 누르는 수동 트리거다. | 있음: 현행은 기간·거래처 조회 후 인쇄 (§4) | 다름 | Excel 업로드 대신 현행 DB/API를 조회한다. 저장소·수단 변화이므로 계승 대상은 아니다. |
| PNG 파일 저장은 결과 행의 수동 `저장` 버튼이다. 원문: `<button ... onclick="saveCanvas('${idx}')">저장</button>` (`tools/legacy-gas/거래처별 원장생성 프로그램/Index.html:1219`), `link.download = item.filename; ... link.click();` (`tools/legacy-gas/거래처별 원장생성 프로그램/Index.html:1251-1254`). | **이 레거시에는 자동 저장·history가 있다.** 처리 완료 직후 이미지 자체(`dataUrl`)는 빼고 재생성 가능한 결과 데이터(`rows` 포함)를 Notion DB에 자동 저장한다. 원문: `let { dataUrl, ...rest } = item;` (`tools/legacy-gas/거래처별 원장생성 프로그램/Index.html:790-792`), `google.script.run.autoSaveResultToNotion(... | 날짜 범위로 내역을 조회하고 저장 당시 데이터를 복원해 PNG를 재생성한다. 원문: `sorts: [{ timestamp: 'created_time', direction: 'descending' }]` (`tools/legacy-gas/거래처별 원장생성 프로그램/Code.js:291`), `<th>작업자</th><th>저장일시</th><th>저장주제</th><th>복원여부</th>` (`tools/legacy-gas/거래처별 원장생성 프로그램/Index.html:244`), `item.dataUrl = await drawCanvas(item.name, item.rows);` (`tools/legacy-gas/거래처별 원장생성 프로그램/Index.html:1581-1583`). | **없음** (§4) | 다름 | 현행의 원본 분개/세금계산서 감사 이력은 생성 문서 스냅샷·복원이 아니다. |

## 2. 거래처별 일괄 거래명세서 생성 — 레거시 확인

| 레거시 동작 (원문 인용 + `파일:행번호`) | 현행 위치 또는 **없음** | 같음 / 다름 / 확인불가 | 다르면 무엇이 |
|---|---|---|---|
| 생성물은 거래별 PNG 거래명세서 이미지다. 원문: `filename: \`${inv.cust_name}_..._${inv.no}.png\`` (`tools/legacy-gas/거래처별 일괄 거래명세서 생성/Index.html:833`), `resolve(finalCvs.toDataURL('image/png'));` (`tools/legacy-gas/거래처별 일괄 거래명세서 생성/Index.html:1264`). | 있음: `/accounting/statement-batch`, `/print/statement-batch` (§4) | 확인불가 | 이번 각도에서는 현행 인쇄 표현의 100% 일치를 판정하지 않았다. |

| 입력은 사용자가 판매현황과 채권 Excel을 첨부한 뒤 `처리실행`을 누르는 수동 트리거다. 원문: `<input type="file" ... accept=".xlsx, .xls"` (`tools/legacy-gas/거래처별 일괄 거래명세서 생성/Index.html:142-143`), `<button ... onclick="startProcessing()">처리실행</button>` (`tools/legacy-gas/거래처별 일괄 거래명세서 생성/Index.html:151`). 생성 과정은 각 시트의 행을 읽어 거래명세 단위로 묶는다(`tools/legacy-gas/거래처별 일괄 거래명세서 생성/Index.html:634-650`, `tools/legacy-gas/거래처별 일괄 거래명세서 생성/Index.html:737-800`). | 있음: 현행은 기간 조회 후 선택/전체 인쇄 (§4) | 다름 | Excel 업로드 대신 현행 DB/API를 조회한다. 저장소·수단 변화이므로 계승 대상은 아니다. |
| PNG 파일 저장은 결과 행의 수동 `저장` 버튼과 브라우저 다운로드다. 원문: `<button ... onclick="saveCanvas('${idx}')">저장</button>` (`tools/legacy-gas/거래처별 일괄 거래명세서 생성/Index.html:1343`), `link.download = item.filename; ... link.click();` (`tools/legacy-gas/거래처별 일괄 거래명세서 생성/Index.html:1373-1379`). | **이 레거시도 자동 저장·history가 있다.** 처리 완료 직후 PNG `dataUrl`만 제외한 `inv`, `bInfo` 등 재생성 데이터를 자동으로 Notion DB에 저장한다. 원문: `let { dataUrl, ...rest } = item;` (`tools/legacy-gas/거래처별 일괄 거래명세서 생성/Index.html:857-859`), `google.script.run.autoSaveResultToNotion(... ## 3. 내일자 전표 이미지 생성 — 레거시 확인

| 레거시 동작 (원문 인용 + `파일:행번호`) | 현행 위치 또는 **없음** | 같음 / 다름 / 확인불가 | 다르면 무엇이 |
|---|---|---|---|
| 생성물은 출고전표별 PNG 안내 이미지다. 원문: `const dataUrl = canvas.toDataURL('image/png');` (`tools/legacy-gas/내일자 전표 이미지 생성/Index.html:623`), `const filename = \`${first.customer}_${safeDate}-${no}.png\`;` (`tools/legacy-gas/내일자 전표 이미지 생성/Index.html:625`). | 있음: `/sales/next-day-slip`, `/print/next-day-slip` (§4) | 확인불가 | 이번 각도에서는 현행 인쇄 표현의 완전 동등성까지 판정하지 않았다. |
| 이미지 표현은 로고, 거래처명, 주문인·출고인·검수인·결재, 전표 날짜·번호, 창고, `월/일·품목명·수량`, 총합계, 배송주소, 연락처, 특이사항, 배송 안내 멘트를 포함한다. 원문: `const headers = ['주문인','출고인','검수인','결 재'];` (`tools/legacy-gas/내일자 전표 이미지 생성/Index.html:792`), `['월/일','품목명','수량']` (`tools/legacy-gas/내일자 전표 이미지 생성/Index.html:852`), `ctx.fillText('총합계', ...)` (`tools/legacy-gas/내일자 전표 이미지 생성/Index.html:885`), `ctx.fillText('연락처:', ...)` (`tools/legacy-gas/내일자 전표 이미지 생성/Index.html:902`), `ctx.fillText('특이사항:', ...)` (`tools/legacy-gas/내일자 전표 이미지 생성/Index.html:908`). 미출고 품목과 비·눈 예보 문구도 선택적으로 합성한다(`tools/legacy-gas/내일자 전표 이미지 생성/Index.html:582-615`). | 인쇄 화면은 있음 (§4) | 확인불가 | 저장 계약 조사 범위에서는 표현 데이터의 세부 동등성을 판정하지 않았다. |
| 입력·생성 트리거는 수동 2단계다. 사용자가 출고전표 Excel을 업로드하면 첫 시트를 읽고(`tools/legacy-gas/내일자 전표 이미지 생성/Index.html:415-433`), 결과 탭의 `결과 생성` 버튼이 `generateResults()`를 호출한다(`tools/legacy-gas/내일자 전표 이미지 생성/Index.html:197`, `tools/legacy-gas/내일자 전표 이미지 생성/Index.html:684-693`). 예약 실행이나 Apps Script 시간 트리거 코드는 없다. “내일자”는 스케줄러가 아니라 업로드된 전표 날짜와 주소 유형으로 하차 예정일 문구를 계산하는 의미다(`tools/legacy-gas/내일자 전표 이미지 생성/Index.html:525-580`). | 있음: 현행은 기준일 선택 즉시 API 조회 (§4) | 다름 | Excel 업로드 대신 현행 출고전표를 조회한다. 저장소·수단 변화이므로 계승 대상은 아니다. |

### 최종 판정

- 로드맵의 **“한 계열로 묶어 공통 저장·이력 계약을 먼저 세운다”는 결론은 맞다.** 가장 가까운 현행 선례는 홈택스 일괄발행 배치 계약이다.
- 그러나 근거 문구인 **“셋 다 자동 저장·history가 없다”는 사실과 반대다.** 세 레거시 모두 Notion에 자동 스냅샷을 저장하고 날짜별 조회·복원을 제공한다. 정확한 갭은 **“레거시에 있던 생성 스냅샷·이력이 현행 세 대응 화면에 없다”**이다.
- 공통 계약 최소 필드: 사용자 노출 생성번호, 문서종류, 생성 기준기간/기준일, 생성건수, 작업자·생성시각, 상태, 사용자 제목(선택), payload schema version, 압축 구조화 payload, 양식 revision(거래명세서 필수), artifact manifest. 파일 바이너리 object key는 선택 필드로 두는 것이 레거시 완전계승 최소선과 현행 확장성을 함께 만족한다.
- 구현 기준은 홈택스식 **RDB 배치 스냅샷+이력+재생성**을 중심으로 하고, 바이너리 보관이 필요할 때 전표 첨부의 객체 저장 패턴을 결합하며, 거래명세서는 문서 양식 append-only revision을 pin하는 조합이 적합하다.
