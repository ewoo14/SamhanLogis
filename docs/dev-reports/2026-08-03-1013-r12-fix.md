## 최종 경계 보정 — RED → fix → GREEN

전체 검증 중 기존에 soft-delete된 과거 이력이 새 CHECK에 걸릴 수 있는 저장 경계가 보여 단정을 추가했다.


V7의 CHECK를 `is_deleted OR save_mode IN ('AUTO_LATEST', 'MANUAL_NAMED')`로 고쳤다. 그러면 과거 감사 행은 soft-delete 상태로 보존되어 migration을 통과하고, 복원되어 `is_deleted = FALSE`가 되는 순간에는 허용되지 않는다.

```text

BUILD SUCCESSFUL
test_suites=36 tests=220 failed=0 errors=0 skipped=0
```

이 SQL CHECK의 boolean 조건과 soft-delete 상태 전이는 PostgreSQL/Linux에서 동일하다. 새 단정은 Linux에서도 과거 삭제 이력을 훼손하지 않고 신규 SEND_AUDIT 저장·복원을 차단한다.
