### 1.2 견적 화면에서 조회 가능한 BUNDLE

`EstimateFormPage.searchEstimateProducts()`는 `/api/products?q=...&size=20`을 호출하고 `usageScope`를 전달하지 않는다. 실 DB의 활성 BUNDLE 분포 SQL 원문:

```sql

  COUNT(*) AS active_bundle_count,
  COUNT(*) FILTER (WHERE usage_scope = 'BOTH') AS both_count,
  COUNT(*) FILTER (WHERE usage_scope = 'ESTIMATE') AS estimate_count,
  COUNT(*) FILTER (WHERE usage_scope = 'NONE') AS none_count
FROM products
WHERE is_deleted = false
  AND status = 'ACTIVE'
  AND product_type = 'BUNDLE';
```


## 5. 판정 불가 / 운영 관찰

- 판매전표 비기본 옵션 왕복: 실 DB 표본 0, 신규 판매전표에서 비기본 picker를 만들 경로 없음 → 판정 불가.
- Playwright `locator.fill()`은 세트 옵션 텍스트 input이 매 입력마다 재렌더되어 locator가 분리되면서 timeout됐다. 실제 `keyboard.press()` 단일 키는 즉시 반영됐다. 앱 freeze로 오판하지 않고 단일 키로 저장까지 진행했다.
- 견적 신규 화면에서 BUNDLE 선택 직후 행 내부 공급가액/부가세/합계 input은 `0`으로 보였으나 하단 합계는 `2,939,090 / 293,910 / 3,233,000`으로 계산됐다. 저장 후 서버 계산은 `2,939,091 / 293,909 / 3,233,000`이었다. 본 라운드 핵심 결함과 별도인 표시 불일치 관찰값이다.
