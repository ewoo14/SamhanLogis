## 2. 1차 판정

- `view-only-mutation-gates` 2건: **스펙 오류**. R19가 실행 화면 권한을 `notification.dispatch-sms.display`로 분리해 route, sidebar, `DispatchSmsPage` 모두 새 page-code를 사용한다. 스펙은 폐기된 `send-audit`를 query override로 주므로 `PermissionGuard`에서 차단되어 버튼이 렌더되지 않았다.
- `permission-groups-c5-followup` 1건: **스펙 오류**. AppLayout의 실제 계약은 `dynamicCanAccess('notification.dispatch-sms.display', 'view')`이며, 스펙은 R19 이전 `send-audit`를 요구한다.
- `sp-08-3-4-dispatch-sms-history` 1건: **스펙 오류**. `DispatchSmsSaveHistoryController.PAGE_CODE`는 R19에서 표시 화면 권한 경계에 맞춰 `notification.dispatch-sms.display`로 변경되었다. SEND_AUDIT 회수와 자동 SMS 미발송 계약은 별개로 유지한다.
- `ac-868 ... DS4-C` 1건: R19 변경 파일/표면과 무관한 **독립 flaky/environmental 실패 후보**. 로고 원본 폭 `0`은 CI에서 이미지 로드가 완료되지 않은 상태이며 R19 diff에 AC-868 소스가 없다. 동일 test만 로컬 재현해 최종 판정한다.

## 4. 수정 내용

제품 코드는 수정하지 않았다. R19의 의도된 권한 분리를 반영해 mock 회귀 스펙 3곳의 stale page-code 단언을 다음처럼 갱신했다.

```text
notification.dispatch-sms.send-audit
→ notification.dispatch-sms.display
```

- view-only/create 권한 override 2건
- AppLayout C5 page-code 정적 계약 1건
- dispatch SMS history controller page-code 정적 계약 1건

자동 SMS 발송 경로, 적용된 Flyway 파일, R19 제품 구현은 건드리지 않았다.

## 6. R19 불변식 회귀 없음

- V93은 `notification.dispatch-sms.display`를 MASTER/MANAGER/DISPATCH에 별도 시드한다. V92의 `SEND_AUDIT` soft-delete/회수 상태를 복구하는 변경은 없다.
- 실행 화면·sidebar·route·preview 권한이 모두 `display`로 정렬되어 MANAGER 2명과 DISPATCH 1명의 표시 접근을 보존한다.
- `DispatchBatchPreviewServiceTest`가 배송기사 연락처 입력, 하차일별 그룹 문구, 기사번호 공란 fallback 계약을 통과했다.
- `DispatchSmsSaveHistoryServiceTest`가 과거 `SEND_AUDIT` soft-delete 보존 및 복원 차단, AUTO_LATEST 저장 계약을 통과했다.
- 자동 SMS 발송을 호출하는 코드는 이번 수정에서 변경하지 않았다.
