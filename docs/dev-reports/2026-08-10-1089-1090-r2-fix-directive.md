### 원인과 실 사용자 경로

`BundleExpander`는 활성 구성품 중 기본이 하나도 없으면 부모의 계보·분류·수기 편집 여부와 무관하게 활성 구성품 전체를 통과시킨다.

```java
boolean hasDefaultComponent = activeComponents.stream()
        .anyMatch(c -> Boolean.TRUE.equals(c.getIsDefault()));
List<BundleComponent> components = activeComponents.stream()
        .filter(c -> !hasDefaultComponent || Boolean.TRUE.equals(c.getIsDefault()))
        .toList();
```

그러나 기초품목의 세트 구성품 편집기는 새 행을 항상 `isDefault: false`로 추가하고, 행 UI에는 `isDefault`를 지정하거나 해제하는 조작이 없다. 저장 서비스는 빈 배열만 거부하고 1건 이상의 요청이 모두 `isDefault=false`인 상태는 그대로 저장한 뒤 부모를 `bundleComponentsManual=true`로 표시한다.

따라서 사용자가 신규 BUNDLE에 필수 구성품과 선택 구성품을 추가해 `구성품 저장`을 누르거나, 기존 기본 행을 삭제 후 다시 추가하면 다음 저장 상태가 정상 200으로 만들어진다.

```text
필수 구성품  is_default=false
선택 구성품  is_default=false
bundle_components_manual=true
```

그 뒤 견적·판매전표에서 세트를 선택하면 fallback이 두 행을 모두 전개한다. 운영자가 선택 구성품을 기본에서 제외하려고 기본을 비운 경우에도 반대로 선택 구성품까지 금액과 라인에 들어간다. 이 fallback은 `V36 이전 레거시 72세트`를 식별하지 않으므로 #1089의 “기본만 전개” 원 의도를 무력화한다.

실 스택 읽기 측정에서도 `기본 0건` 72세트 중 1세트(`AM220AXVHHR1SY`)가 이미 `bundle_components_manual=true`다. 이 행이 업무 의도인지 과거 검증 흔적인지는 읽기 증거만으로 단정하지 않지만, 현재 조건이 “의도한 레거시 집합”과 “수기 편집 집합”을 구분하지 못한다는 사실은 확정된다.

### 불변식

`기본 0건`은 일반적인 “활성 전체가 기본” 신호가 아니다. 호환 전개는 식별 가능한 레거시 전환 대상에만 적용되어야 하며, 신규·수기 편집 세트가 기본 0건인 상태는 저장 단계에서 명시적으로 거부하거나 별도 호환 표식 없이는 전개하지 않아야 한다. 기본이 1건 이상이면 정확히 그 기본 행만 전개해야 한다.

### 양방향 RED

- **RED-A — 레거시 호환 유지:** `bundleComponentsManual=false`, `productCategory=COMMERCIAL_MULTI`, 활성 구성품 2건·기본 0건인 전환 대상 표본은 기존 72세트 호환 정책대로 두 구성품을 전개한다. R1의 `AM220AXVHHR1SY` 0행/404 회귀를 다시 열면 실패시킨다.
- **RED-B — 구체 표적, 신규·수기 세트 차단:** 기초품목 구성품 PUT에 필수 1건과 선택 1건을 모두 `isDefault=false`로 보내면 200으로 저장 후 두 행을 전개해서는 안 된다. 권장 계약은 PUT 400과 `기본 구성품을 1건 이상 지정해 주세요` 원문이며, 기존 구성품 집합은 변경되지 않아야 한다. 다른 설계를 택하더라도 `bundleComponentsManual=true + 기본 0건`이 활성 전체 전개로 해석되면 RED다.
- **경계 1건:** 기본 1건과 비기본 1건인 세트는 기본 1건만 전개하고 비기본 행은 제외한다. 현재 `EXPAND_모드에서는_isDefault_구성품만_전개한다`를 유지한다.
- **빈 구성품 반대급부:** 구성품 PUT 빈 배열은 기존처럼 400을 유지한다. 실 스택의 활성 BUNDLE 중 활성 구성품 0건은 0세트다. 이번 fix가 빈 BUNDLE을 새로 허용하면 실패시킨다.

### 수정 범위와 반대급부

- 호환 대상을 `productCategory` 하나로만 제한하면 향후 같은 분류의 신규 세트가 다시 전체 전개된다. `bundleComponentsManual`, 명시적 migration marker, 확정된 모델 집합 등 전환 완료 후 제거 가능한 식별자가 필요하다.
- 수기 저장에 기본 1건 이상을 요구하려면 현재 ProductFormPage에 `기본` 조작을 먼저 제공해야 한다. UI 없이 서버 검증만 추가하면 사용자는 신규 세트 구성품을 저장할 수 없다.
- 이미 수기 편집된 기본 0건 행을 자동 수정하거나 데이터 변경하지 않는다. 어떤 행이 기본인지는 업무 의미이므로 별도 결정 대상이다.

## 폐쇄 확인 — #1090 견적 정액할인

호환 fallback을 넓게 유지하면 신규·수기 세트의 선택 구성품이 조용히 금액에 섞인다. 반대로 fallback을 단순 제거하면 기존 72세트가 다시 0행으로 소실된다. 따라서 “레거시 호환 대상 식별”과 “신규·수기 저장 시 기본 지정 강제 + UI 조작 제공”을 함께 닫아야 한다.
