## 0. 개발책임자 지시 (원문)

> 운임, 절삭은 비상품 품목이라서 재고로 들어가지 않아.
> 따라서 비상품 품목을 추가하는 경우에는 레거시 코드처럼 납품가에 값을 넣으면
> 자동으로 수량은 1로 설정되면서 견적서에 포함되는 시스템이 되었으면 해.
> 운임, 절삭뿐 아니라 견적품목 메뉴에서 해당 상품인지 비상품인지 여부도 정할 수 있게 했으면 좋겠어.

> 운임 절삭뿐 아니라 카드수수료, 영업수수료 등도 모두 비상품이야.

## 1. 실측 — 이미 있는 것과 없는 것

### 이미 있다 (다시 만들지 않는다)

| 있는 것 | 위치 |
|---|---|
| `ProductGoodsType.GOODS \| NON_GOODS` | `product-service/domain/ProductGoodsType.java` |
| 재고 제외 게이트 — NON_GOODS 는 재고를 **아예 안 만든다** | `inventory-service/client/ProductSummary.java:17-18` · `InventorySetExclusionIT` |
| FE 타입 | `productCatalogApi.ts:54-55` |
| 기초품목 등록 화면의 상품/비상품 셀렉트 | `[data-testid="product-form-goods-type"]` |

Javadoc 이 이미 이렇게 적고 있다 — **"운임/수수료/설치비처럼 견적·전표 라인에는 쓰되 재고를 만들지 않는 품목"**.
계약은 처음부터 있었고, **데이터와 화면이 그것을 안 쓰고 있었다.**

### 없다 (이번에 만든다)

1. 견적품목 메뉴에서 상품/비상품 지정
2. 비상품 라인의 수량 자동 1
3. 데이터 — 비상품 후보 **34건이 전부 `GOODS`**

## 2. 실 DB 실측

```
전체 품목                       3,083건 — goods_type 전부 GOODS · inventory_qty_mgmt 전부 true

비상품 후보                        34건
  설치비 계열                      22건   7평벽걸이(설치비) … 스탠드(20평이상) 설치비 · 2IN1설치비
  수수료 계열                       5건   영업 · 조달 · 카드 · 판매수수료
  운임 · 절삭                       2건
  금액조정                          2건   금액조정 · 무형상품 금액조정
  (기타 설치비 표기 변형)            3건

usage_scope    NONE 32건 · BOTH 2건 (운임·절삭만)

재고 행         stock_balances 0 · stock_lots 0 · stock_instances 0 · stock_movements 0
```

🔑 **재고 행이 0건이므로 `GOODS → NON_GOODS` 전환은 기존 재고를 훼손하지 않는다.** 이것이 이 설계의 전제다.

### 🚨 이 0건은 **후보 34건으로 필터한 값**이다 — 전체 테이블 행 수가 아니다

S1 구현자가 전체 테이블을 세어 `202 / 7 / 19 / 45` 를 보고하고 중단했다. **정직한 보고였고, 다른 모집단을 잰 것**이다. 재는 방법을 못 박는다.

```sql
-- inventory_db 는 product_code 가 없다. product_id 로만 조인된다.
-- product_db 에서 후보 id 를 먼저 뽑는다.
SELECT string_agg(quote_literal(id::text), ',') FROM products
WHERE is_deleted = false AND name ~ '운임|절삭|수수료|설치비|금액조정';   -- 34건

-- inventory_db 에서 그 id 로만 센다.
SELECT count(*) FROM stock_balances  WHERE product_id::text IN (:ids);  -- 0
SELECT count(*) FROM stock_lots      WHERE product_id::text IN (:ids);  -- 0
SELECT count(*) FROM stock_instances WHERE product_id::text IN (:ids);  -- 0
SELECT count(*) FROM stock_movements WHERE product_id::text IN (:ids);  -- 0
```

**대조군** — 필터가 동작함을 증명한다.
```
stock_balances 의 distinct product_id        102개
그중 후보 34건과 겹치는 것                     0개
```
⟹ 재고를 가진 품목은 실재하고(102개), **후보는 그중 하나도 아니다.**

측정 시각 `2026-08-08T23:07:45Z` (공유 DB라 값은 움직인다).

### `NON_GOODS 3건 존재` 도 사실이나 전부 삭제된 품목이다

```
goods_type | is_deleted | count
GOODS      | false      | 3,083     ← 활성. 전부 GOODS
GOODS      | true       |   135
NON_GOODS  | true       |     3     ← 삭제된 것뿐
```
활성 품목 중 `NON_GOODS` 는 **0건**이다.

## 3. 🚨 레거시가 틀린 지점 — 이름 정규식

레거시 GAS 는 비상품을 **품목명 정규식**으로 갈랐다.

```js
// tools/legacy-gas/거래처 발송 주문서/Code.js:681,802,899,1074,1160
if (/운임|절삭/i.test(name)) continue;

// tools/legacy-gas/일마감 프로그램/Code.js:669
if (/(운임|절삭)/.test(item['품목명'])) { item['확인'] = true; }
```

⟹ **카드수수료·영업수수료·설치비는 레거시에서도 비상품 처리가 안 됐다.** 정규식에 없으니까.

🚨 **이 방식을 옮기지 않는다.** 이 저장소가 이미 배운 규칙이다 —
*"목적을 경로에서 추론하지 마라 — 호출자가 선언하게 하라."*
비상품 여부는 **품목 마스터에 선언된 값**(`goodsType`)이고, 이름으로 추론하지 않는다.
개발책임자 지시의 *"견적품목 메뉴에서 정할 수 있게"* 가 정확히 이 방향이다.

## 4. 설계 — 3단

### 1단 · 견적품목 메뉴에 상품/비상품 지정

`EstimateItemsCatalogPage.tsx` 행에 상품/비상품 토글을 넣는다.

**불변식**
- 🚨 **기초품목 등록 화면과 같은 필드**(`goodsType`)를 쓴다. 새 필드·새 축을 만들지 않는다.
  두 화면이 다른 값을 저장하면 어느 쪽이 정본인지 알 수 없게 된다.
- 🚨 이 페이지는 `usageScope !== 'NONE'` 만 나열한다(`EstimateItemsCatalogPage.tsx:736`).
  후보 34건 중 **32건이 `NONE`** 이라 지금은 목록에 없다.
  ⟹ **견적 노출로 올린 뒤 비상품으로 지정하는 경로**가 실제로 통해야 한다. 밟아서 확인할 것.
- 🚫 `usage_scope` 를 마이그레이션으로 바꾸지 않는다. **무엇을 견적에 노출할지는 업무 판단**이고, 화면에서 사용자가 정한다.

### 2단 · 비상품 라인 — 납품가 입력 시 수량 자동 1

**불변식**
- 🚨 트리거는 **납품가 입력**이고, 효과는 **수량 1 + 견적서 포함**이다.
- 🚨 **양방향**이다. 상품(GOODS) 라인의 기존 수량 동작은 **하나도 바뀌지 않는다.**
  RED-A(비상품에 납품가 → 수량 1) · RED-B(상품 라인 수량 동작 불변) 를 **동시 GREEN** 으로 고정한다.
- 수량은 자동 **설정**이지 잠금이 아니다. 사용자가 바꿀 수 있다.
  (지시 원문 *"자동으로 수량은 1로 설정"* — 고정이라 하지 않았다)
- 🚨 비상품 라인이 **재고 차감·입출고를 일으키지 않는지** 실제로 확인한다.
  게이트는 있다고 되어 있으나 이 경로로 밟은 적이 없다.

### 3단 · 데이터 전환

34건을 `goods_type = NON_GOODS` · `inventory_qty_mgmt = false` 로.

**불변식**
- 🚨 **명시적 코드 목록**으로 마이그레이션한다. 🚫 이름 `LIKE`·정규식 금지 (3절이 그 이유다).
- 🚨 목록은 이 문서의 실측 34건이다. 그 밖의 품목은 건드리지 않는다.
- 🚨 전환 전 **재고 행이 0건임을 마이그레이션 안에서 다시 확인**한다.
  0이 아니면 실패시킨다 — 조용히 넘어가면 재고가 어긋난다.
- 🚫 기존 견적·전표 라인의 값을 소급 변경하지 않는다. 앞으로 만드는 라인에만 효력.
