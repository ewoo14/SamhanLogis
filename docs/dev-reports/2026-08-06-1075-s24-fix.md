# PR #1078 · 이슈 #1075 — S24 LUNA fix 보고서

## 판정

S23-F1을 수정했다. 구 marker(`U+2060X`)가 hydrate 과정에서 표시값 `X`로 정규화되는 경우, 구 snapshot의 marker를 제거한 canonical 규격과 현재 규격이 같고 현재 source가 기대 source `CATALOG`이면 source·문자열 차이를 라인 변경으로 세지 않는다.

정규화 예외는 다음 두 조합으로 한정했다.

- 평문 `X/null → X/USER`
- marker `U+2060X/null → X/CATALOG`

평문 `null→CATALOG`, marker `null→USER`, 명시 `CATALOG↔USER`, 명시 source→`null`은 계속 라인 변경으로 집계한다. 규격 문자열이 실제로 달라지거나 단가·수량·금액·비고 등 다른 라인 값이 달라지는 경우도 계속 집계한다. 규격 diff 전체를 제거하지 않았다.

backfill·DB 쓰기·마이그레이션 생성은 하지 않았다. `@Size(max=50)`도 변경하지 않았다. 전표 도메인에는 provenance를 이식하지 않았다.

## 수정 내용

`EstimateRevisionService#lineDiffers`에 다음을 적용했다.

1. 규격 비교를 `specificationDiffers`로 분리했다.
2. 이전 source가 null이고 현재 source가 `CATALOG`이며 이전 규격이 `U+2060`으로 시작할 때만 marker를 제거해 canonical 규격을 비교한다.
3. source 비교는 이전 규격에서 legacy 기대 source를 계산한다. 평문은 `USER`, marker는 `CATALOG`이다.
4. 기대 source와 현재 source가 일치하는 정규화만 제외하고, 나머지 source 전환은 변경으로 센다.
5. 수량·단가·공급가·VAT·합계·품목명·모델명·비고 비교는 그대로 유지했다.

실 화면 경로의 기존 `EstimateFormPage` 회귀(S16 marker 저장)는 `decodeEstimateSpecification → draft → update body`를 검증하고, S24 백엔드 RED/GREEN은 그 body가 만든 legacy/current snapshot summary에서 `~0`/`~1` 반대급부를 검증한다.
