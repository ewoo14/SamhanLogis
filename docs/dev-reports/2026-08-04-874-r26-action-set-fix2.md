## 결함별 재현 경로와 해소 내용

### 결함 1 — OUTBOUND SENT 주문전환 전표의 취소 노출 후 409

재현 경로:

1. 판매 주문서에서 판매전표로 전환·발행한다.
2. 판매관리에서 생성된 OUTBOUND `SENT` 전표 상세(`/sales/:id`)를 연다.
3. 데스크톱 footer의 `삭제` 또는 모바일 더보기의 `전표 취소`를 확인한다.
4. 기존 HEAD에서는 취소를 호출하고 백엔드 `Slip.cancel()`의 `PARTNER_ORDER` 가드가 409를 반환한다.

해소:

- 상세 API 응답에 `sourceType`을 추가하고 FE `SlipDetail`로 전달했다.
- `actionsForStatus('SENT', ..., 'PARTNER_ORDER')`는 `accept, reject`만 반환한다.
- 데스크톱 generic `삭제`와 모바일 `전표 취소` 모두 이 액션 목록을 따르므로 주문전환 전표에는 취소가 노출되지 않는다.
- `MANUAL` 등 일반 출처의 `SENT`는 계속 `accept, reject, cancel`을 반환하므로 취소가 노출되고 기존 백엔드 허용 경로를 실행한다.

### 결함 2 — OUTBOUND COMPLETED 데스크톱의 ship 소실

재현 경로:

1. 판매관리에서 OUTBOUND `COMPLETED` 전표 상세(`/sales/:id`)를 데스크톱으로 연다.
2. 기존 footer에서 `배송 시작` 대신 `수정`만 표시되어 `SHIPPING`으로 전이할 수 없다.

해소:

- `COMPLETED && canCollabEdit`가 전이 버튼 전체를 교체하던 분기를 제거했다.
- OUTBOUND `COMPLETED`에서는 `완료 (배송 시작)` 전이 버튼을 계속 렌더한다.
- `canCollabEdit` 권한이 있으면 `수정`을 별도 버튼으로 함께 렌더하므로 협업 편집 진입도 유지된다.

### 결함 3 — INBOUND COMPLETED 데스크톱의 confirm 소실

재현 경로:

1. 구매관리에서 INBOUND `COMPLETED` 전표 상세(`/purchases/:id`)를 데스크톱으로 연다.
2. 기존 footer에서 `확정` 대신 `수정`만 표시되어 `CONFIRMED`로 전이할 수 없다.

해소:

- 같은 footer 구조 수정으로 INBOUND `COMPLETED`의 `완료 (확정)` 전이 버튼을 보존했다.
- 협업 편집 권한 보유 시 `수정`도 함께 유지한다.
- 모바일은 기존 `mobilePrimaryAction` 경로를 유지하며, `INSPECTING`의 `inspect + reject`도 변경하지 않았다.

## 최종 확인

코드 재확인 결과:

- `sourceType === 'PARTNER_ORDER'` 분기가 `SENT` 액션을 제한한다.
- 데스크톱과 모바일의 취소 노출은 모두 `possibleActions.includes('cancel')`에 종속된다.
- 기존 `slip.status === 'COMPLETED' && canCollabEdit` 교체 footer 분기는 제거됐다.
- `desktopFooterActions`는 COMPLETED에서 OUTBOUND `ship` 또는 INBOUND `confirm`과 `collab-edit`를 동시에 표현한다.
