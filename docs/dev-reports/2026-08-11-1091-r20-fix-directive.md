R17은 UUID 모양이라는 이유만으로 다른 사람의 정상 이름을 가리던 과잉 은닉을 닫았다. 제품 코드를 `callerId` 폴백으로 되돌려 현재 테스트를 만족시키면 canonical UUID 은닉을 다시 깨므로 금지한다. 원인은 **R12 이전 테스트 기대값 한 곳의 갱신 누락**이다.

## 불변식

audit row의 actorName은 사용자에게 표시할 이름이다.

1. `callerName`이 비어 있지 않고 이 행의 `actorId`와 같은 UUID 표현이 아니면 원문을 보존한다.
2. `callerName`이 이 행의 `actorId`와 같은 canonical·대문자/공백·중괄호·URN·32자 무하이픈 표현이면 `변경자 미상`으로 은닉한다.
3. `1-1-1-1-1`과 `[DEV-SEED] 개발영업`은 보존한다.
4. actorId와 다른 UUID 모양 이름도 보존한다.
5. 테스트를 맞추기 위해 제품의 callerId 폴백을 복원하지 않는다.

## fix 범위

`SlipServiceAuditDiffTest.editHeader_memoChanged_recordsOverlayPatch()`의 세 번째 `recordOverlayPatch` 인자 기대값을 호출에 제공한 정상 표시명 `홍길동`으로 맞춘다. 가능하면 단언 의도를 actorName이라고 주석으로 고정한다.

제품 코드는 변경하지 않는다.

## 양방향 RED

### RED-A — 정상 표시명 보존

```text
callerId   = user-1
callerName = 홍길동
기대 audit actorName = 홍길동
```

현재 낡은 테스트는 이를 `user-1`로 기대해 실패한다. 수정 뒤에는 제품이 callerId 폴백으로 회귀하면 이 테스트가 RED여야 한다.

### RED-B — UUID 비공개 반대급부

기존 R12·R13·R15·R17 매트릭스를 함께 실행한다.

```text
actorId와 같은 canonical/대문자·공백/중괄호/URN/32자 무하이픈  -> 은닉
actorId와 다른 UUID 모양 이름                                    -> 보존
1-1-1-1-1 · [DEV-SEED] 개발영업                                 -> 보존
실 200 + []                                                       -> 변경 이력 없음
```

테스트를 통과시키려고 `SlipService`를 `callerId` 기록으로 되돌리면 RED-B가 실패해야 한다.
