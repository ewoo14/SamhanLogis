# 레거시 `없음` 항목 — 업무 행위 단위 정찰

- 정찰일: 2026-08-16
- 범위: 아래 6개 패리티 보고서에서 판정이 정확히 `없음`인 규칙만 포함했다. `다름`, `확인 불가`는 포함하지 않았다.
- 결과: 원 규칙 **24건**을 사용자가 한 화면에서 수행하는 업무 기준 **19개 행위**로 묶었다.
- 안전 조건: 정적 소스와 문서만 읽었다. 제품 코드·컨테이너·공유 DB·Git에는 쓰지 않았다.

## 이 표에서 말하는 “현재 우회”

저장소에는 2026-07-28 Drive에서 갱신한 레거시 GAS 원문이 있고, 각 원 보고서가 그 원문에서 해당 행위를 확인했다. 그러나 이 정찰은 GAS 실행 로그나 사용자 관찰을 하지 않았으므로 **“현재 실제로 GAS를 병행 사용 중”이라고 단정하지 않는다.**

- `GAS로 가능`: 현행 사용자 경로에는 없고, 확인된 동일 행위는 레거시 GAS에만 있다. GAS 런타임이 아직 열려 있다면 그것이 우회다.
- `현행 수동 우회`: 현재 화면에서 사람이 보정·삭제·재입력해 일부 또는 전부를 대신할 수 있다.
- `운영 확인 필요`: 저장소만으로 GAS가 아직 열려 있는지, 사람이 별도 Excel/수기로 처리하는지 확인할 수 없다.

따라서 아래 표는 “코드가 있으니 쓸 수 있다”가 아니라 **사용자가 도달하는 현행 경로에서 할 수 있는지**를 기준으로 썼다. 특히 영업수수료 계산 서비스처럼 호출되지 않는 코드는 우회로 세지 않았다.

## 묶음 기준과 개수

원 규칙 24건을 다음처럼 19개로 줄였다.

- 일마감 `R-09`·`R-12`: 같은 가격검증 업무의 자동 할인제외와 사용자 미적용 선택이라 1개 행위로 묶었다.
- 미배차 `U-02`·`U-03`: 같은 단일 목록을 상태별 운영 큐로 나누는 행위라 묶었다.
- 미배차 `U-04`·`U-05`: 현재 전표와 배차 원문을 양방향으로 대조해 이상을 찾는 행위라 묶었다.
- 거래처 업데이트 `P-04`·`P-05`: 같은 파일 적재 시 가격정책·메모를 병합하는 enrichment라 묶었다.
- 전표정리 `C-03`·`C-04`: snapshot 기반 상태 판정과 전표별 완료 각인이 하나의 수명주기라 묶었다.

그 밖의 규칙은 같은 화면에 있어도 사용자가 따로 채택·폐기할 수 있는 결정 단위라 분리했다. 예를 들어 미배차의 상태 큐, 이상탐지, 복사 포맷은 서로 독립적으로 판단할 수 있다.

## 정찰 한계

- 사용자·GAS 실행 로그를 조회하지 않았으므로 “누가 오늘 어떤 GAS를 실제로 썼는가”는 확인하지 않았다. 표의 GAS 우회는 **레거시 코드에 그 행위가 있고 현행 사용자 경로에는 없다는 뜻**이다.
- 공유 DB를 조회하지 않았으므로 역할별 개별 권한 override와 실제 운영 데이터는 반영하지 않았다. 역할은 route/pageCode의 기본 권한 계약을 기준으로 적었다.
- 후속 전표 변환·외부 이카운트 수동 보정처럼 원 보고서 범위를 넘어가는 경로는 존재를 추정하지 않았다. 확인되지 않은 것은 그대로 `운영 확인 필요`로 남겼다.
