# #1069 S4 SOL fix 지시서 — 판매전표 세트 전개

## 판정

**재현 가능한 결함 있음 — 머지 차단.** S2의 BUNDLE 영속 우회와 규격 승계 불일치는 닫혔으나, 최신 입력 보존은 **거래처가 선택되어 최근단가 조회가 선행하는 실 사용자 경로**에서 닫히지 않았다. 정상 세트 전개가 오래된 수량으로 수행되거나 아예 무시된다.

읽기 전용 실 DB 재계수:

- 권위 데이터: `product_estimate_exposure` 기준 `BUNDLE 344`, `SINGLE 521`; `bundle_component 1,588행/345세트`.
- 활성 전표의 권위 BUNDLE 라인: `0행 / 0전표`; 수정 가능한 `OUTBOUND DRAFT`: `0행 / 0전표`, 금액 `0`.
- 활성 전표 정상 SINGLE: `2,191행 / 2,145전표`; 그중 `OUTBOUND DRAFT`는 `2,107행 / 2,100전표`, `line_total 2,837,681,781원`.
- 따라서 S3 BUNDLE 가드가 과거 BUNDLE 잔존 전표를 막는 실 DB 오차단은 `0건`이다. 정상 SINGLE 모바일 생성과 전체수정의 협소 서비스 경로도 통과했다.

## ① 좌표

### F1. 거래처 최근단가 조회 중 바꾼 최신 세트 입력이 전개에 승계되지 않는다

- 진입점: `clients/desktop/src/renderer/routes/SlipFormPage.tsx:846-953`
- 최신 입력 세대 증가: `SlipFormPage.tsx:703-712`, `:815-830`, `:1008-1012`
- 원인 경계:
  - 세트 선택 당시 `nextLine`을 `SlipFormPage.tsx:858-872`에서 만든 뒤 `getPriceMemory`를 기다린다(`:906-907`).
  - 응답 후 `canStillApply`는 품목·거래처·`priceSource`만 확인한다(`:898-905`). 수량·규격·옵션과 전개 세대는 확인하지 않는다.
  - 정상으로 판정되면 최신 행이 아니라 대기 전 `nextLine`으로 전개를 시작한다(`:927-929`, 실패 분기 `:948-950`).
  - `expandSelectedBundle`의 세대 토큰은 이 늦은 시점에 새로 캡처된다(`:787-800`). 따라서 그 전에 발생한 사용자 입력을 stale로 판정할 수 없다.
- 재현 A — 최신 수량 소실:
  1. 거래처를 선택한다.
  2. 세트 수량 `1` 상태에서 BUNDLE을 선택하고 최근단가 응답을 지연한다.
  3. 응답 대기 중 같은 행 수량을 `3`으로 바꾼다.
  4. 최근단가 응답을 완료한다.
  5. 임시 협소 회귀 실측: `expandBundleLine` 1회 요청의 `quantity`는 최신 `3`이 아니라 선택 당시 `1`이었다.
- 재현 B — 정상 전개 자체 소실:
  1. 같은 조건에서 최근단가 응답을 지연한다.
  2. 대기 중 단가를 직접 입력한다. 이 입력은 `priceSource='USER'`로 바뀐다(`:815-827`).
  3. 최근단가 응답을 완료한다.
  4. `canStillApply`가 false가 되어 `:927-929`와 `:948-950` 모두 전개를 호출하지 않는다.
  5. 임시 협소 회귀 실측: `expandBundleLine` 호출 `0회`; BUNDLE 행이 화면에 남는다. 해당 행은 현재 생성 payload 필터·매핑(`:1205-1216`)에 포함될 수 있어, 저장 전 화면과 저장 후 서버 전개 결과도 갈린다.

## ② 불변식 — 구현 수단 지정 금지

1. 거래처 선택 여부와 최근단가 응답 순서에 관계없이 BUNDLE 선택은 최신 행 스냅샷의 수량·VAT 포함 단가·규격·세트 옵션으로 정확히 한 번 전개되어야 한다.
2. 최근단가 대기 중 사용자가 수량·단가·규격·옵션을 바꾸면 선택 당시 값이 아니라 마지막 사용자 입력이 전개 요청과 결과에 반영되어야 한다.
3. 사용자의 직접 단가 입력은 최근단가 덮어쓰기를 막아야 하지만, 정상 세트 전개 자체를 막거나 BUNDLE 부모 행을 저장 가능 상태로 남기면 안 된다.
4. 이후 일반 품목으로 교체된 행에는 늦은 가격·전개 성공·실패가 귀속되면 안 된다.
5. S3에서 닫힌 BUNDLE 전체수정·모바일 영속 차단, 구성품 자체 규격 우선/부모 규격 승계, 구성품 순서·금액 계약을 되돌리면 안 된다.
6. `#1063`의 초기 빈행, 마지막 행 1회 증식, 다음 입력행 보장, 의미 없는 빈행 저장 제외 계약을 유지해야 한다.

## ③ 양방향 RED — 반대급부 필수

### RED-B — 재발 금지

- 거래처 선택 + 최근단가 지연 + 수량 `1→3`에서 전개 요청 수량이 `3`이 아니면 RED.
- 거래처 선택 + 최근단가 지연 + 직접 단가 입력에서 전개 호출이 `0회`이거나 BUNDLE 부모 행이 화면/생성 payload에 남으면 RED.
- 같은 조건에서 규격 또는 세트 옵션을 바꿨는데 최신 값이 전개 요청·구성품 결과에 반영되지 않으면 RED.
- 가격 조회와 전개 응답 순서를 바꿨을 때 구성품이 중복 삽입되거나 선택 당시 세트 값이 최신 입력을 덮으면 RED.

### RED-A — 반대급부 보존

- 거래처 미선택 세트와 거래처 선택 후 즉시 완료되는 정상 세트가 전개되지 않으면 RED.
- 사용자가 최근단가 응답 전에 일반 SINGLE로 교체했는데 옛 BUNDLE 전개가 적용되면 RED.
- 직접 입력 단가가 최근단가로 다시 덮이거나, 최신 단가로 전개됐지만 기존 VAT 포함 금액 배분이 달라지면 RED.
- 정상 SINGLE/구성품 단독 입력·모바일 생성·기존 판매전표 전체수정이 BUNDLE으로 오인되어 차단되면 RED.
- 구성품 규격이 있으면 자체 규격이 우선하고, 없으면 부모 규격이 승계되지 않으면 RED.
- 전개 전후 `#1063` 자동 빈행·빈행 저장 제외 규약이 달라지면 RED.
