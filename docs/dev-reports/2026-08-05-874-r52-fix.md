# R52 fix report — PR #1057 · 이슈 #874

## 범위

SOL 지시서의 결함 2(멱등 키 없는 기존 PUSH 정상 경로 차단)를 우선 수정했다. 결함 1(lease 경합)과 결함 3(영구 실패·수신자 해석 실패의 terminal 수렴)은 이번 라운드에서 구현하지 않았다.

`accounting-service`와 `clients/desktop/playwright/874-riusage-real-qa.spec.ts`는 변경하지 않았다. git 명령, Docker 재빌드·재배포·중지, DB 쓰기, 실제 vendor 발송은 수행하지 않았다.

## DB 사전 조회

정본 확인 SQL:

```sql
SELECT COUNT(*) AS blank_or_null_push_idempotency_keys
FROM notification_requests
WHERE channel = 'PUSH'
  AND (idempotency_key IS NULL OR btrim(idempotency_key) = '');
```

현재 `notification_db`에는 `idempotency_key` 컬럼 자체가 없어 위 SQL은 다음 오류로 실행되지 않았다.

```text
ERROR: column "idempotency_key" does not exist
```

따라서 V9 이전 현재 스키마에서 기존 PUSH 경로의 도달 규모를 읽기 전용으로 확인했다.

```sql
SELECT COUNT(*) AS push_rows_before_idempotency_column
FROM notification_requests
WHERE channel = 'PUSH';
```

결과: **165건**. 현재 기준선에서는 이 165건이 모두 멱등 키 없는 기존 PUSH 저장 사건이다.

## 변경

- `NotificationClient.sendUserPushWithResult`는 멱등 키가 없을 때 `idempotencyKey: ""`를 보내지 않고 필드 자체를 생략한다.
- `NotificationDispatchPersistence.prepare`는 null·blank 키를 `null`로 정규화하고, nonblank 키는 trim 후 보존한다. 기존 정상 PUSH 소비자는 V9 CHECK를 위반하지 않는다.
- 회귀 테스트를 추가했다.
