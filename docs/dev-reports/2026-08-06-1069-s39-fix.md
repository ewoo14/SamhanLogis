## 판정

F1 전표 revision 복원 옵션 소실과 F2 견적 BUNDLE 선택 문맥 소실을 수정했다. EXPAND/BUNDLE 옵션은 snapshot·복원·상세 DTO·수정 계보 승계·견적→전표 변환까지 운반하도록 연결했다. 기존 null 행은 backfill하지 않았고, KEEP/SINGLE에 새 옵션 문맥을 부여하지 않는다.

## 구현 내용

- `SlipSnapshot.Line`과 `EstimateSnapshot.Line`에 `BundleSetOptions`를 nullable 필드로 추가하고 구 snapshot 생성자 오버로드는 null을 유지한다.
- `Slip.toSnapshot()`/`restoreFromSnapshot()`이 옵션 5개와 `setHead`/`parentSetModel`을 함께 캡처·복원한다.
- `EstimateLine`에 nullable JSONB `bundle_set_options`를 추가하고 생성/수정 전개 경로가 선택 옵션을 저장한다.
- 견적 상세 응답, FE 상세 normalize, 편집 hydrate가 저장된 옵션을 그대로 사용한다.
- `BundleLineageResolver`가 기존 lineId 수정 시 계보뿐 아니라 옵션 문맥도 승계한다.
- 견적→전표 변환이 견적 라인의 옵션 문맥을 전표 라인으로 전달한다.
- 기존 `SlipLine.copyOf`의 옵션 승계는 유지하고 계약 게이트가 이를 확인한다.
- 계약 게이트는 주석/문자열을 제거한 실제 코드에서 `SlipLine.create*`, `SlipLine.copyOf`, `EstimateLine.create*`, `slip.addLine` 생산 지점을 확인한다. 전표·견적 revision 복원과 옵션/계보 운반 표식도 확인한다. 정책 소유 파일과 seed/복사 호출자는 별도 분류하지만, 실제 `SlipLine.copyOf` 구현의 옵션 승계는 직접 단언한다.
- 새 마이그레이션: `V115__preserve_estimate_bundle_set_options.sql`. nullable 컬럼만 추가하며 default/backfill은 없다.

## 게이트 강화의 근거와 남은 구멍

S38의 단순 정규식/문자열 게이트는 주석 문자열, 사용하지 않은 정책 호출, 파일명 예외, 공백/명명 변형, `copyOf`, `EstimateLine.create`를 통과시켰다. S39는 주석과 문자열을 먼저 제거하고 호출 형태의 공백 변형을 포함해 생산 입구를 탐지하며, 실제 옵션/계보 운반 필드와 revision 복원 경로를 함께 단언한다. 별도 실행 테스트는 전표/견적 snapshot 왕복과 응답 DTO를 실제 도메인 객체로 검증한다.

그래도 이 게이트가 여전히 뚫리는 방법은 남아 있다. Java AST/호출 그래프 전체를 분석하지 않으므로 간접 메서드 참조·람다·상속/위임·reflection·생성자 별칭·생성 코드로 생산 입구를 숨길 수 있다. 같은 파일에 운반 표식만 두고 실제 호출 결과를 버리는 의미적 우회도 소스 게이트만으로는 완전히 증명하지 못한다. DB 실제 insert/HTTP 왕복과 미탐지 신규 factory까지는 이번 로컬 테스트가 보장하지 않는다. 따라서 현재 게이트는 S38 공격 계열과 핵심 사용자 왕복을 닫는 구조+실행 혼합 방어이며, 완전한 컴파일러 수준의 불변식은 아니다.
