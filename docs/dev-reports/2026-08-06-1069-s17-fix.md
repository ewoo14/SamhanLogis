# #1069 S17 fix 결과 — 판매전표 세트 전개 스냅샷 수렴

## 판정

S17 F1·F2를 수정했다. 지연 응답은 요청 스냅샷과 현재 스냅샷이 완전히 같을 때만 반영하며, 다르면 최신 세트 스냅샷으로 다시 전개한다. 세트가 품목 재입력으로 해제된 경우에는 재요청 대상이 아니므로 응답을 폐기한다.

## RED-first 증거

수정 전 신규 RED 2건을 먼저 실행했고 모두 실패했다.

- F1 원문: `expected 'Product B' to be ''` — 재전개 pending 중 구성품 자동완성의 `onInputCommitChange(false)`를 발화한 뒤 지연 응답을 resolve하자 옛 응답의 `Product B`가 다시 화면에 나타났다.
- F2 원문: `expected null to be '세트 구성품 반영 중'` — 저장 차단 `status`에 `aria-label`이 없어 접근성 이름 속성이 `null`이었다.

## 근본 원인과 수정

### F1

품목명 재입력 경로는 `productId`, `productName`, `productType`, `modelCode`만 지우고 전개 세대와 행별 옵션 컨텍스트를 정리하지 않았다. 따라서 지연 응답 처리기가 남아 있는 컨텍스트를 같은 세트로 오인했다.

다음 변경을 적용했다.

1. `invalidateBundleExpansionForLine`을 추가해 자동완성 확정 해제 시 해당 행의 세대를 증가시키고 해당 행 컨텍스트만 제거한다. 다른 행의 pending은 유지한다.
2. 요청 직전 스냅샷을 만들고 응답 직전에 현재 스냅샷을 다시 만든다. 두 스냅샷이 다르면 응답을 폐기한다.
3. 최신 스냅샷이 여전히 BUNDLE이면 최신 값으로 전개를 재요청한다. 품목 재입력으로 BUNDLE이 아니면 재요청하지 않고 응답을 폐기한다.
4. 성공·실패 모두 동일한 스냅샷 검증을 거치므로 오래된 성공 구성품과 오류 구성품 모두 최신 화면을 오염시키지 않는다.
5. 가격 기억 응답 직후 세트 전개를 시작하는 경계에서는 확정한 라인 배열을 `linesRef`에도 동기 반영해 내부 상태 반영 지연을 사용자 변경으로 오인하지 않게 했다.

### F2

재전개 저장 차단 `role="status"`에 `aria-label="세트 구성품 반영 중"`을 추가했다. 기존 가시 문구와 `aria-live="polite"`는 유지한다.

## 비교 대상 정의 — 단일 진실원

비교 대상은 `SlipFormPage.tsx`의 `BundleExpansionSnapshot`, `createBundleExpansionSnapshot`, `areBundleExpansionSnapshotsEqual` 세 곳에만 정의·구현했다. 스냅샷 필드는 다음과 같다.

- 품목: `productId`, `modelCode`, `modelName`, `productType`
- 수량·단가·규격: `quantity`, `unitPrice`, `specification`
- 세트 옵션: `remoteOption`, `remoteExcluded`, `panelOption`, `panelShape360`, `materialIncluded`

응답 반영 조건은 위 필드 전부의 완전 일치다. 비교 대상이 여러 처리 경로에 흩어지지 않도록 응답 성공·실패와 최신 재요청 판단 모두 이 동일 비교 함수를 사용한다.
