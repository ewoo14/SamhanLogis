# 2026-08-13 #1143 Live QA 6 — CODEX SOL

## 결론

**실 사용자 경로에서 재현되는 결함은 1건이다.** 사용자 이름 조회가 실패할 때 제품 상세는 HTTP 200을 유지하지만 2,564ms가 걸렸다. 정상 6회는 37~48ms(중앙값 42ms)였으므로 약 61배 느리다. user-service의 화면 장애 전파는 막았지만 사용자에게 보이는 상세 진입 지연은 남아 있다.

감사 정보 fix 자체는 정상이다. 제품·분류 API 6개 응답의 중첩 전체에서 UUID는 0건이고, 실제 사용자·미조회 UUID·마이그레이션 표식은 각각 사람 이름·`사용자 미상`·`시스템 작업 (원문 표식)`으로 구분됐다. 제품 수정 화면의 기존 `기본 정보` 영역에도 작성자·수정자가 보인다. Live QA 5의 회귀 경로도 모두 정상이다.

따라서 **머지 불가**다. 못 한 항목은 없다.

- 지속 QA 복제본도 custom-format `pg_dump` 파일 경유로 같은 3개 DB를 복원했다. 공유 DB 쓰기는 0건이며 공유 DB에는 `pg_dump`와 read-only SELECT만 실행했다.
- 세 경우를 실제로 걸을 수 있도록 격리 복제본의 `AM060BN6PBH1.modified_by`에 `V38__PRODUCT_CATEGORY_BACKFILL`을 주입했다. 이후 격리 GUI 저장으로 AP/AM052의 modifiedBy도 동일 시스템 표식이 됐다. 공유 DB에는 반영되지 않았다.
- 원본과 복제본의 한국어 제품·분류·사용자 이름을 대조했다. 데이터 자리 대체문자 `?`는 화면/응답에서 발견되지 않았다.
