## 결론

**판정 불가. 결함 1건. 머지 차단.**

발화 조건 ②인 관리자 API가 실 게이트웨이에서 404라 활성 기준선을 실 경로로 만들 수 없다. 지시대로 내부 서비스 포트로 mutation을 우회하거나 DB에 INSERT하지 않았다. 따라서 발화 조건은 0이며 ③~⑤를 결함 0으로 판정하지 않는다.

### 결함 S11-1 — 신규 관리자 API가 gateway 실 경로에 배선되지 않았다

동일한 `dev_manager` 실 JWT로 비교한 결과다.

| 요청 | HTTP | 결과 |
|---|---:|---|
| `GET http://127.0.0.1:8080/admin/slip-cutoffs` | 200 | 기존 slip 관리자 API 정상 도달, 6행 |
| `GET http://127.0.0.1:8080/admin/slip-closing-baselines` | **404** | 신규 API 미도달 |

배포된 slip-service 자체의 `http://127.0.0.1:18086/v3/api-docs`는 HTTP 200이며 다음 path를 모두 노출한다.

- `/admin/slip-closing-baselines`
- `/admin/slip-closing-baselines/{id}`

즉 slip/auth 미배포 문제가 아니다. 컨트롤러와 V118/V96은 배포됐지만 gateway 라우트가 빠진 세 번째 경우다. 저장소 gateway 정본의 slip 관리자 Path 목록에는 `/admin/slip-cutoffs`와 하위 path는 있으나 `slip-closing-baselines`는 없다(`services/api-gateway/src/main/resources/application.yml`의 slip-service 관리자 route).

## 1. 발화 조건

| 각도 | 실 결과 | 상태 |
|---|---|---|
| ① 활성 기준선 0 | DB SELECT로 활성 기준선 0건 확인 | 사전조건 확인 |
| ② 관리자 API로 기준선 생성 | GET부터 gateway 404; POST를 진행할 실 route 없음 | **도달 불가 · 결함** |
| ③ 만든 날짜의 생성 차단 | 발화 조건 0 | **판정 불가** |
| ④ 예외 권한자는 통과하고 비권한자는 차단 | 발화 조건 0 | **판정 불가** |

실 mutation이 한 건도 성립하지 않아 DB의 `S11-1123` 메모 전표는 0건이고 활성 기준선도 0건이다. 라운드 식별자가 없는 데이터를 QA 성공 건수로 세지 않았다.

## 2. 차단되면 안 되는 것

마감되지 않은 날짜 생성의 실 건수 비교는 수행하지 않았다. 관리자 API 404로 발화 조건이 0인 시점에 중단하라는 지시를 따랐다.

권한 코드 정본은 BE guard, auth V95/V96, FE `PageCode` union에서 모두 `slip.closed-date-exception`으로 일치하고 auth DB에도 같은 문자열로 materialize돼 있다. 다만 이 라운드에서는 발화 조건 0으로 desktop 권한 화면과 실 guard 소비를 끝까지 연결하지 않았으므로 런타임 parity 판정은 하지 않는다.

## 3. `SlipType` 정본

OUTBOUND 기준선만 생성한 뒤 INBOUND 생성, 그리고 반대 방향의 실 상호 격리는 수행하지 않았다. 두 종류 어느 쪽도 실 gateway를 통해 기준선을 만들 수 없었다. **판정 불가**다.

## 4. 두 게이트 결합

다음 세 경우 모두 날짜 마감 상태를 실 관리 경로로 만들 수 없어 실행하지 않았다.

| 경우 | HTTP 응답 | desktop 표시 | 상태 |
|---|---|---|---|
| 익일 열림 | 미실행 | 미캡처 | 판정 불가 |
| 익일 마감, 다음날 열림 | 미실행 | 미캡처 | 판정 불가 |
| 연속 마감 | 미실행 | 미캡처 | 판정 불가 |

HTTP와 desktop 캡처를 인위적으로 만들기 위해 내부 포트, route mock, DB INSERT를 사용하지 않았다.

## 5. 관리자 API 자체

관리 권한 계정의 GET이 gateway 404이므로 다음 계약은 모두 실 경로에서 도달 불가다.

- 같은 `(SlipType, 날짜)` 두 번 생성 409
- 기준선 삭제 후 날짜 재개방
- 권한 없는 계정 403
- 잘못된 SlipType·날짜 형식 400

404를 403/400/409의 대체 증거로 세지 않았다.

## 증거 무결성 및 회수

headless Playwright는 실 renderer에서 시작했으나 첫 화면의 중복 heading strict locator에서 캡처 전에 중단됐다. 이후 gateway 404와 활성 기준선 0을 확인해 발화 조건 중단 규칙을 적용했으므로 locator를 우회해 화면을 조작하지 않았다. `resolveQaShotsDir`를 우회한 캡처는 없고 생성된 S11 PNG도 0개다.

라운드 종료 시 QA용 Vite, Playwright/Chromium 및 이 작업 트리에서 시작한 node 프로세스를 종료하고 Gradle daemon을 정지했다. Docker 서비스는 건드리지 않았다.
