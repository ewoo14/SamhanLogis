### riUsage 대상의 조합 표

아래 표는 scope별로 독립 적용되는 Cartesian 조합을 행 상태별로 축약한 것이다. `완전`은 `used==total`, `부분/미소비`는 `used!=total`이다. `단가=일치/불일치`는 fallback 행에서만 결과를 나눈다.

| scope 안 main 구성 | main 소비 상태 | 대상 행 순서/kind | 대상 소비 | 레거시 결과·근거 | 현행 결과 |
|---|---|---|---|---|---|
| 없음 | 해당 없음 | 부속이 앞/뒤 모두 `PANEL/REMOTE/MATERIAL` | 완전 | `true` — `_zone`이 `UNKNOWN`, `:733-734`; `SINGLE` 불가 | `true` |
| 없음 | 해당 없음 | 그 밖 | 임의 | `true` — `:733-734` | `true` |
| `INDOOR/OUTDOOR/SUB_INDOOR` 있음 | 완전 | main 행 | 완전 | `true` — `:709-710` | `true` |
| 같은 구성 | 부분/미소비 | main 행 | 부분/미소비 | `false` — `:709-710` | `false` |
| 같은 구성 | 완전/미완전 | 부속이 첫 main보다 앞 | 완전/미완전 | `true` — 대상 `_zone=UNKNOWN`, `:733-734` | `true` |
| 같은 구성 | 완전/미완전 | 부속이 main 뒤, `PANEL/REMOTE/MATERIAL` | 완전 | `true` — `:702-703` | `true` |
| `INDOOR/OUTDOOR` 포함 | 완전/부분/미소비 | 부속이 main 뒤 | 미완전 | `false` if any `INDOOR/OUTDOOR` 미완전 — `:697-705` | `false` |
| `INDOOR/OUTDOOR`만 완전, `SUB_INDOOR`만 미완전 또는 main 상태상 failed 없음 | 완전/부분/미소비 | 부속이 main 뒤 | 미완전 | 단가 일치 `true`, 불일치 `false` — `:706-708` | `null`로 기존 단가 판정 위임 |
| 같은 scope | 어떤 상태 | main 뒤의 그 밖 | 임의 | `true` — `:709-712` | `true` |

`SUB_INDOOR`만 있는 조합은 `hasSingleMain=true`이지만 `hasFailedMain=false`인 별도 조합이다. 따라서 Q형 미완전 뒤 부속 미완전은 `null`이고, Q형 자기 행은 `false`다. 이 세 갈래를 한 분기로 평탄화하지 않았다.

### scope 교차 조합

서로 다른 scope의 main 소비 상태 조합도 각 scope의 표를 독립 적용한다. [DEV-SEED/단위 fixture] `RiUsageDecisionTest.java:164-175`는 `DOC-A`의 미완전 MATERIAL과 `DOC-B`의 완전 MATERIAL/미완전 OUTDOOR를 함께 넣고 `DOC-A` 결과가 `true`임을 확인한다. `DOC-B`의 failed main은 `DOC-A`를 거짓으로 만들지 않는다. 현행은 `scopeKey`별 `decideAccessoryScope` 호출로 동일하게 분리한다.

표에서 확인한 축 외 입력은 `_isOld`, 품명/`AXJ`, `isMultiApplied`, `할인율`, `_fixedDc`, `discInfo`, `_deliveryPrice`다(`Code.js:671-735`). 이들은 riUsage `_zone` 판정 전에 기존 분기로 소비되거나, riUsage의 fallback 단가 비교가 사용할 값이며, 이번 변경에서 새 riUsage 축으로 중복 편입하지 않았다.

## 6. 실데이터 도달성 — [실데이터/로컬 read-only]

읽기 전용 SQL로 세 라인 테이블을 합쳐 확인했다.

```text
 source | active_lines | model_rows | single_rows | scopes
--------+--------------+------------+-------------+--------
 tax    |           22 |          0 |           0 |     14
(1 row)
```

sales/purchase 활성 라인은 0행이어서 결과 행이 출력되지 않았고, tax 활성 22행/14 scope도 `model_name` 0행·`category_key='SINGLE'` 0행이다. 따라서 [실데이터/로컬 read-only]에서 이번 순서 축으로 실제 `확인`이 바뀐 행은 **0행**이다. 이는 규칙 정확성의 증거가 아니라 현재 로컬 데이터의 도달성 0이라는 뜻이다.

단위 fixture에서는 [DEV-SEED/단위 fixture] `PANEL 선행 + 미소비 INDOOR 후행` 1개 대상의 기존 `false`가 레거시 순서 적용 후 `true`로 바뀌었다. 이유는 대상 처리 시점의 `_zone=UNKNOWN`이고 `Code.js:733-734`가 `true`를 내기 때문이다. 역순 [DEV-SEED/단위 fixture]는 `SINGLE`로 들어가 `false`를 유지한다.
