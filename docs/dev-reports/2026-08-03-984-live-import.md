### 5. 중간 판정 및 미측정 항목

- 실 transform 기준 차단: XLSX 관계를 함께 보낸 HTTP 200 실행은 `totalRows=2854`, `rejectedNullName=1`, `skippedPlaceholder=0`, `skippedRelationOrphan=0`, `skippedGroupCount=0`이었다. 정상 CSV 관계를 붙인 실행은 transform 전에 `409 MIG2_ALIAS_DUPLICATE`로 중단되어 transform 건수는 0건이다.
- 품목코드 충전율: `1220 / 1120 / 100` → `3183 / 387 / 2796`.
- 세트 코드 보유: `344 / 0` → `344 / 0`.
- 관계 원본 명시 관계만 병합했는지, 이름 동일 품목이 병합되지 않았는지, 필드별 비어 있지 않은 값 우선 및 양쪽 충돌 여부는 **유효한 관계 CSV가 없어 판정 불가**.
- 발견 결함: (1) `itemFile` XLSX는 의도대로 422이나, `relationFile` XLSX는 422 없이 HTTP 200으로 무시된 것으로 보임. (2) 지원 CSV 정상 경로에서 `MIG2_ALIAS_DUPLICATE`가 여전히 발생. (3) 이번 200 실행에서도 세트 코드 보유가 0으로 유지되어 #1057 라이브 QA 차단은 해소되지 않음. (4) 보고된 파일 목록의 XLSX는 실제 데이터 행이 아닌 제목 행 1개짜리 파일로 확인됨.

## 📌 PM 정정 (2026-08-03, 집PC 세션)

위 보고의 **발견 결함 (4)** — *"보고된 파일 목록의 XLSX는 실제 데이터 행이 아닌 제목 행 1개짜리 파일로 확인됨"* — 은 **사실이 아니다.**

PM 이 `품목관계리스트-Excel다운로드.xlsx` 를 직접 풀어 확인한 결과:

```text
파일 크기        11,416 bytes
<row> 요소       160개
<c> 셀           1,424개
문자열 저장 방식  t="inlineStr" (셀 안에 직접 저장)
sharedStrings.xml <si> 0개   ← 여기만 보면 "빈 파일" 로 보인다
A1 값            회사명:(주)삼한공조시스템
```

`<dimension ref="A1"/>` 과 빈 `sharedStrings.xml` 때문에 비어 있는 것으로 오인한 것으로 보인다. **이 관계 원본은 실제 데이터를 담고 있다.**

이 정정이 중요한 이유 — (4)가 참이었다면 *"관계 원본 자체가 없으니 이 트랙은 파일 재취득 대기"* 로 잘못 결론냈을 것이다. 실제로는 **관계 파일은 있고, 임포터가 XLSX 관계 파일을 조용히 무시한 것**이 문제다.

### 그래서 아직 판정되지 않은 것

- `409 MIG2_ALIAS_DUPLICATE (aliasCode=00013)` 는 **관계 파일 없이 실행한 결과**다. 이름 축 제거가 409 를 푸는지는 **관계 원본을 실제로 넣고 돌려야** 판정된다.
- 발견 결함 (1) `relationFile` XLSX 가 `422` 없이 `200` 으로 무시되는 것은 **fail-open 이며 실 사용자 도달 가능하다**. 사용자가 이카운트에서 받은 XLSX 를 그대로 올리면 관계가 통째로 반영되지 않은 채 성공으로 표시된다.
