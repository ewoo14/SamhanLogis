# #1001 R2 적대검증 결함 수정 보고서

## 결론

R1에서 확정된 5건을 수정했다. VAT 이중가산은 R1 검증대로 변경하지 않았다.

## D1 — 출고 상태 범위

### RED

`SlipPartnerLedgerInternalControllerIT`에 `INSPECTING`·`SHIPPING` 전표를 추가하고 5건을 기대하도록 먼저 바꿨다.

```text
SlipPartnerLedgerInternalControllerIT > returnsEveryOutboundStatusAfterInventoryDispatchWithLinesAndNoUuid() FAILED
java.lang.AssertionError at SlipPartnerLedgerInternalControllerIT.java:88
3 tests completed, 1 failed
> Task :services:slip-service:test FAILED
```

### 상태 전이 근거

- `[실코드 근거]` `Slip.java:1064-1075`의 `complete()`는 `PROCESSING → INSPECTING`이며 “출고 완료” 주석과 함께 재고 차감 시점으로 사용된다.
- `[실코드 근거]` `Slip.java:1087-1103`의 `inspect()`는 `INSPECTING → COMPLETED` 검수 완료 전이다.
- `[실코드 근거]` `Slip.java:1110-1123`의 `ship()`은 `COMPLETED → SHIPPING`이고 OUTBOUND에만 허용된다.
- `[실코드 근거]` `Slip.java:1130-1144`의 `deliver()`는 `SHIPPING → DELIVERED`이고 OUTBOUND에만 허용된다.
- `[실코드 근거]` `SlipService.java:991-1019`는 OUTBOUND `complete()` 직후 `inventoryClient.deduct`/`shipInstances`를 호출한다.
- `[실코드 근거]` `Slip.java:1150-1156`의 `confirm()`은 OUTBOUND `DELIVERED → CONFIRMED` 최종 확정이다.

따라서 원장 포함 상태는 출고 완료 이후의 `INSPECTING`, `COMPLETED`, `SHIPPING`, `DELIVERED`, `CONFIRMED`다. `DRAFT`, `SAVED`, `SENT`, `ACCEPTED`, `PROCESSING`은 출고 완료 전이고 `CANCELED`, `REJECTED`는 거래가 무효화된 상태이므로 포함하지 않는다.

수정: `SlipInternalController.PARTNER_LEDGER_SALES_STATUSES`에 `SHIPPING`, `INSPECTING` 추가.

## D2 — 누적잔액

### RED

기존 adapter는 판매·수금 모든 행에 `balance: '0'`을 생성했다. 새 `[DEV-SEED/단위 fixture]` 테스트는 판매 100 → 수금 40의 순서와 잔액 `100`, `60`을 요구한다.

초기 원인 코드의 출력 계약:

```text
debit: line.lineAmount,
credit: '0',
balance: '0',
...
debit: '0',
credit: document.amount,
balance: '0',
```

### 수정

`buildPartnerLedgerLines`가 API가 반환한 문서/품목 순서를 그대로 순회하면서 `balance += debit - credit`를 계산한다. 정렬이나 기간 경계는 adapter에서 변경하지 않는다.

## D5 — 음수 빨강

`amountStyle`을 추가해 `Number(raw) < 0`인 경우에만 `#DC2626`을 설정했다. 양수와 0은 기존 `tdStyle.color`를 유지한다. `fmtKrw`는 `-X`, 0은 `—`를 유지한다.

`[DEV-SEED/단위 fixture]` adapter 테스트는 잔액 양수 경로를, 화면 구현은 음수/0 분기 코드를 검증한다. `eslint`는 해당 변경 파일 3개에서 오류 0건으로 통과했다.

## 실데이터 전후 측정

- `[실데이터/로컬 read-only]` R1 필터(`COMPLETED`,`DELIVERED`,`CONFIRMED`)는 `7+10+4 = 21전표`, `17+35+10 = 62라인`이었다. 해당 합계 금액은 `58,492,500 + 106,845,200 + 32,138,700 = 197,476,400.00`이다.
- `[실데이터/로컬 read-only]` R2 필터(`INSPECTING`,`COMPLETED`,`SHIPPING`,`DELIVERED`,`CONFIRMED`)는 `5+7+5+10+4 = 31전표`, `12+17+15+35+10 = 89라인`, 합계 `354,121,900.00`이다.
- `[실데이터/로컬 read-only]` DRAFT/CANCELED 및 SENT/PROCESSING/ACCEPTED/REJECTED/SAVED는 R2 원장 상태 집합에 포함하지 않았다.
- `[실데이터/로컬 read-only]` 금액은 `supply_amount + vat_amount` 합계로 측정했으며, 원장 API의 VAT 포함 `lineAmount` 권위값과 동일한 계산 축이다.
