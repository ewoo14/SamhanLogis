### 레거시 분기 트리의 공통 전처리(최종 branch selector)

최종 판정 앞에서 레거시는 `Code.js:483-498`의 입력 순서별 상태 사슬을 만든다. `AM...X/N → COMM_MULTI`, `AJ...X/N → HOME_MULTI`, `isTargetModelCode_(token) ∧ main kind → SINGLE`, 그 외에는 직전 zone을 유지하고 각 행에 복사한다. `Code.js:177-183`의 target predicate는 `^A[CP]\d{3}`, `^AF\d{2}`, `^AR\d{2}`다. 현재 구현은 `SetPoolLine`에 행 순서·품명·target predicate·legacy zone을 보존하지 않고, `MonthEndCloseService:615-640`에서 `axis == SINGLE` 부분수열만 `RiUsageDecision`에 보낸다. 이것이 L1~L6를 독립 패치로 고치는 대신 하나의 chain port가 필요한 근본 원인이다.

- `MonthEndCloseService`의 set pool 행에 품목명과 원천 순서를 보존해 `LegacyVerificationChain.route`를 실제 일마감 입력에 연결했다.

## R14 fix 후 레거시 분기 대응표

초기 표의 “부재/부분” 상태가 R14에서 다음처럼 chain에 편입됐다.

| 레거시 ID | 최종 대응 |
|---|---|
| L1 | `LegacyVerificationChain.Branch.FREIGHT_OR_CUTTING` → `revalidateByLegacyBranch` 무조건 true. `riUsageDecision`은 null이라 override하지 않음 |
| L2a | `oldProduct && !isMultiApplied` → `ALWAYS_TRUE` |
| L2b | `oldProduct && isMultiApplied && AM/NJ/NS/AVX` → `OLD_RATE_50` |
| L2c | `oldProduct && isMultiApplied && 그 밖` → `OLD_DELIVERY` |
| L3a | accessory/AXJ && `!isMultiApplied` → `ALWAYS_TRUE` |
| L3b | accessory/AXJ && `isMultiApplied` → `ACCESSORY_DELIVERY` |
| L4a | ordered zone `SINGLE` + main 없음 + accessory → `SINGLE_ACCESSORY`의 true 경로 |
| L4b | SINGLE accessory 자기 소비 완료 → `riUsageDecision` true |
| L4c | SINGLE accessory + failed `INDOOR/OUTDOOR` → `riUsageDecision` false |
| L4d | SINGLE accessory + 위 둘 다 아님 → `riUsageDecision`의 정수원 `unitPrice === deliveryPrice` |
| L4e | SINGLE `INDOOR/OUTDOOR/SUB_INDOOR` → `SINGLE_MAIN` + 모든 scope의 `riUsage` |
| L4f | SINGLE 기타 kind → `SINGLE_DEFAULT` true |
| L5a | ordered zone multi/품명 multi && `!isMultiApplied` → `ALWAYS_TRUE` |
| L5b | ordered zone multi/품명 multi && `isMultiApplied` → `MULTI_RATE`, fixed DC → zone 전역DC → 45% |

공통 selector는 `LegacyVerificationChain.route`가 scope별 원천 행 순서대로 전이하며, `MonthEndCloseService`가 그 routed rows를 set matcher와 최종 판정 양쪽에 전달한다. 따라서 분기표의 각 행은 독립적인 사후 patch가 아니라 같은 사슬의 한 branch다.
