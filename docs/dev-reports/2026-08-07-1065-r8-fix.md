# PR #1066 / 이슈 #1065 R8 fix 보고서

## 1. 상태·역할 조합 검증

이번 fix는 OUTBOUND `inspect`에 전표별 `canInspect`를 최종 capability로 적용하고, OUTBOUND 상세 라우트만 정적 목록 권한으로 차단하지 않도록 했다. 상세 API의 기존 서버 결재선/403 판정과 `ship`·`deliver`·`confirm`의 기존 권한 매핑은 변경하지 않았다.

| 역할 | 결재선 | INSPECTING | COMPLETED 이후 | 결과 |
|---|---|---|---|---|
| SALES | 안 | `canInspect=true`이면 상세 도달·`inspect` 활성 | `ship`은 기존 `slip.transfer.process:update` 없으면 비활성 | 검수 가능, 후속 운송 액션은 기존 권한 정책 유지 |
| SALES | 밖 | `canInspect=false`이면 `inspect` 비활성 | `ship` 비활성 | 강제 API는 기존 서버 403 |
| ACCOUNTANT | 안 | 정적 상세 라우트에서 탈락하지 않고 상세 API 도달·`inspect` 활성 | `ship`은 기존 권한상 비활성, `confirm`은 기존 `sales.slip.confirm:update` 가능 | D2 해소, 후속 확정 담당 경로 유지 |
| ACCOUNTANT | 밖 | `canInspect=false`이면 `inspect` 비활성 | `ship` 비활성 | 상세 API가 기존 서버 판정 |
| MANAGER | 안 | `canInspect=true`이면 상세 도달·`inspect` 활성 | `ship`·`deliver`는 기존 `slip.transfer.process:update`, `confirm`은 기존 권한으로 가능 | 기존 운송/확정 경로 유지 |
| MANAGER | 밖 | 정적 권한이 있어도 `canInspect=false`이면 `inspect` 비활성 | 기존 권한 범위만 활성 | D1 해소, 강제 `inspect`는 기존 403 |

상태 사슬은 기존 계약 그대로 `INSPECTING → inspect → COMPLETED → ship → SHIPPING → deliver → DELIVERED → confirm → CONFIRMED`이다. D3의 업무 권한을 새로 추측하거나 role-page 매핑을 넓히지 않고, 코드에 이미 정의된 `slip.transfer.process:update`/`sales.slip.confirm:update`를 그대로 사용했다.
