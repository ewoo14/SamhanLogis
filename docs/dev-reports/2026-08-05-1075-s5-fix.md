# PR #1078 · 이슈 #1075 — S5 fix 보고서

## 판정

BLOCK 결함을 수정했다. 견적 편집 협업 연결 후에도 모델명 `ProductAutocomplete`가 활성화되며, 라인 추가·삭제 구조 잠금은 유지된다.

## 원인과 수정

- `EstimateFormPage.tsx` 모바일·데스크톱 품목 입력의 `disabled` 조건에서 `coeditActive`를 제거했다.
- `isReadOnly`와 `estimateFormCoeditPending`은 그대로 유지했다.
- `lineStructureLocked={isReadOnly || coeditActive}` 및 데스크톱 삭제 버튼의 `disabled={isReadOnly || coeditActive}`는 변경하지 않았다.
- coedit Vitest의 `ProductAutocomplete` mock이 호출부 `disabled`를 실제 input에 반영하도록 보강했다.

## RED-first 증거

mock에 `disabled` 전달과 편집 계약 단정을 먼저 추가하고 수정 전 실행했다.

```text
Test Files 1 failed (1) | Tests 36 passed, 1 failed (37)
AssertionError: expected true to be false // Object.is equality
```

실패 위치는 `coedit 연결 후 모델명은 활성이고 라인 구조 삭제는 잠근다`의 모델명 `disabled` 단정이었다. 즉 provider 연결 후 실제 호출부가 `disabled=true`를 전달하는 결함을 관측했다.

첫 실행에서 사용한 `toBeEnabled()` matcher는 이 Vitest 설정에 `jest-dom`이 없어 다음 환경 오류를 냈고, 저장소 기존 방식인 `.disabled` 단정으로 교정한 뒤 위 제품 RED를 확보했다.

## 회귀 울타리 복구

`1062-line-input-ux.spec.ts`의 신규 견적 후보 모달 시나리오는 유지하고, 별도 편집 시나리오를 추가했다.

- 기존 확정행 0·1과 trailing 빈행 2 존재
- 협업 연결 후 모델명 combobox 활성
- 협업 중 라인 삭제 비활성
- 부분검색 후보 확정 후 다음 trailing 빈행 3 생성
- `data-price-source` 행 4개 유지
- 후보 확정 후 임시저장·발송 버튼 활성
- 규격·단가 표시와 UUID 비노출 표면 유지

편집 후보 `AJ052RXH5BC1`의 실제 mock 가격기억 값은 `2,120,000`이어서 단정도 해당 계약값으로 맞췄다.
