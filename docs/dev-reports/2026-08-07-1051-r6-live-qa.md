## 2. 시나리오 ② amount_authority 지속 (RED-A) — PRICE PASS / SUPPLY 판정 불가

## 3. 시나리오 ③ revision 복원 — PASS (새로고침 필요 현상 별도 관측)

1. PRICE 변경 저장으로 revision 6을 만들었다.
2. 직전 정상 저장 revision 5를 선택해 `이 시점으로 복원`을 클릭했다.
3. 확인 modal에서 복원 실행: `POST .../revisions/5/restore -> 200`.
4. 화면 토스트: `버전 5 시점으로 주문을 복원했습니다.`
5. 화면: 합계 `1,560,000원`; `1,560,001`은 사라짐.
6. DB: revision 7 `RESTORE`, `source_revision_no=5`; `PRICE / 1,560,000 / 1,418,181 / 141,819 / 1,560,000`으로 복원됨.

별도 관측: direct 수정 저장 직후 버전 이력 패널은 신규 revision 5·6을 표시하지 않고 기존 1~4만 유지했다. 브라우저 새로고침 뒤 `GET .../revisions -> 200` 재조회 시 1~6이 표시되어 복원할 수 있었다. 원인은 코드에서도 재현된다. `SalesPartnerOrderDetailPage`의 direct `updateMutation.onSuccess`는 `['partner-order', id]`만 invalidate하고, 버전 패널이 쓰는 `['partner-order-revisions', orderId]`는 invalidate하지 않는다. 복원 자체는 PASS지만 저장 직후 revision UI stale 결함 1건이다. 이 관측 라운드에서는 수정하지 않았다.

## 4. 시나리오 ④ V17 backfill 기존 행 — PASS

표본 `2026/06/08-1983`은 `created_at=2026-06-08 02:09:18`, V17 적용 전에 존재한 기존 주문이다. 검증 전 DB는 `amount_authority=PRICE`지만 `supply_amount/vat_amount=NULL`인 backfill 형태였다.

실 GUI에서 요청사항만 수정·저장한 결과:

- 화면 금액 `1,560,000` 불변
- 저장 PUT 200
- DB에서 `PRICE` 유지
- `supply_amount=1,418,181`, `vat_amount=141,819`, `subtotal=1,560,000`으로 정상 계산

새 행이 아닌 backfill 기존 행의 수정 호환을 확인했다.

## SQL 원문과 화면 대조

사용한 SELECT 원문:

```sql
SELECT o.order_no, o.status, o.total_amount, o.revision_count, o.memo, o.modified_at,
       l.model_name, l.quantity, l.amount_authority,
       l.price_vat AS unit_price, l.supply_amount, l.vat_amount, l.subtotal
FROM partner_orders o
JOIN partner_order_lines l
  ON l.partner_order_id=o.id AND l.is_deleted=false
WHERE o.is_deleted=false
  AND o.order_no='2026/06/08-1983';

SELECT r.revision_no, r.revision_type, r.source_revision_no,
       r.actor_name, r.created_at,
       r.snapshot->>'totalAmount' AS snapshot_total
FROM partner_order_revisions r
JOIN partner_orders o ON o.id=r.partner_order_id
WHERE o.order_no='2026/06/08-1983'
  AND r.is_deleted=false
ORDER BY r.revision_no;
```

## 판정 불가 / 새 관측

- **SUPPLY 권위 실제 입력**: 실제 GUI에 입력 control이 없어 판정 불가. DB/API 직접 변경 금지 조건을 지켰다.
- **화면의 S/V 직접 대조**: 상세·수정 GUI가 공급가·부가세를 표시하지 않아 SQL 값과 화면 값을 직접 나란히 볼 수 없다. 화면에서 가능한 납품가·소계·합계는 SQL과 일치했다.
- **revision 즉시 갱신 결함**: 수정 저장 직후 신규 revision이 보이지 않고 새로고침 후 표시됨. direct update 성공 경로의 revision query invalidation 누락을 코드에서 확인했다. 복원 기능은 새로고침 후 정상 동작했다.
