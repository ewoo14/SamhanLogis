# #1042 적대검증 UUID 응답 노출 수정

## 시작 기록

- 요청 범위: `services/inventory-service`의 재고 잔액 응답에서 UUID 비공개 계약을 복구하고 `clients/desktop` 소비처·mock·테스트를 동기화한다.
- 금지사항: git 명령, 공유 Docker 재빌드·재기동, 실 DB 쓰기.
- RED-first 대상: `id`, `productId`, `warehouseId` 응답 필드 제거를 검증하는 실패 테스트.

## RED — HTTP 응답 UUID 노출 재현

### 추가한 실패 단언

`StockBalanceQueryLazyIT.balances_productIdFilter_returns200WithWarehouseNameOutsideTestTransaction`에 다음 단언을 추가했다.

```java
.andExpect(jsonPath("$.data.content[0].id").doesNotExist())
.andExpect(jsonPath("$.data.content[0].productId").doesNotExist())
.andExpect(jsonPath("$.data.content[0].warehouseId").doesNotExist());
```

실패 원인은 응답 DTO가 `id`, `productId`, `warehouseId`를 실제 JSON에 직렬화하고 있어 `doesNotExist()` 단언을 만족하지 못한 것이다.

정규식 0건 단언의 첫 실행에서는 테스트 fixture가 `productCode`에 UUID를 조합하고 있어 실패했다. fixture도 응답 계약의 일부이므로 `MODEL-TEST` 고정 모델코드로 교체했다.

## GREEN — 응답 계약 및 소비처 수정

- `StockBalanceResponse`에서 `id`, `productId`, `warehouseId`를 제거했다. 응답에는 모델코드·품목명·창고코드·창고명·창고구분·가용/예약/실재고·version만 남긴다.
- Excel export는 응답 DTO가 아닌 원천 `StockBalance`에서 내부 product UUID를 사용해 품목 메타데이터를 조회한다. UUID는 xlsx 행에도 쓰지 않는다.
- Desktop `StockBalanceListRow`에서 응답 UUID 타입을 제거하고 `rowKey`를 `productCode-warehouseCode`로 대체했다.
- mock은 기존 UUID 요청 필터를 내부 fixture에서 계속 지원하되, 반환 직전에 `productId`/`warehouseId`를 제거한다.
- `StockBalanceQueryLazyIT`의 실제 MockMvc HTTP 본문 정규식 단언에서 UUID 매치 0건과 화면 필수 8개 필드를 함께 검증한다.

## 요구 불변식 확인

- A: `balances_httpResponseContainsNoUuidAndRetainsDisplayFields`가 MockMvc HTTP 응답 본문 전체를 UUID 정규식으로 검사해 매치 0건을 확인했다.
- B: 같은 HTTP 응답에서 품목코드·품목명·창고코드·창고명·창고구분·가용/예약/실재고를 모두 확인했다.
- C: 데스크톱 응답 타입에서 UUID를 제거하고 DataGrid 행 키를 `productCode-warehouseCode`로 대체했다. 상세 이동/선택 기능은 이 페이지에서 UUID 응답을 키로 사용하지 않는다.
- D: 요청 `productId`/`warehouseId` 파라미터와 서버 controller 시그니처는 변경하지 않았다. 기존 `productId` IT가 HTTP 200으로 통과했다. mock도 내부 필터 후 UUID를 응답에서 제거한다.
- E: 권한 어노테이션, 페이지 route, 창고 필터·페이지네이션·VIRTUAL `—` 표시·기존 화면 열은 유지했다. 전체 inventory-service 테스트와 desktop typecheck가 통과했다.
- F: 서버 IT fixture의 UUID 조합 모델코드를 고정 모델코드로 수정했고 desktop mock은 wire 응답에서 UUID 2종을 제거했다.

## 창고 수치 정정 및 전체 창고 판단

읽기 전용 정찰 수치는 **미삭제 창고 4곳**, **balance 보유 창고 2곳**이다. 따라서 “창고 2곳”은 전체 창고가 아니라 재고 행이 있는 창고 수치로 정정한다.

전체 창고 조회는 미삭제 4곳을 기준으로 해야 하며, 재고 0인 창고 2곳도 창고 목록/전체 현황의 대상에서 누락시키지 않는다. 단, 현재 `GET /inventory/balances`가 balance row 기반이라 0행 창고는 행이 생기지 않으므로, 화면의 창고 선택 목록에서 4곳을 보여주고 재고 행이 없는 창고는 “재고 없음”으로 표현하는 것이 정합적이다. VIRTUAL 창고는 그 4곳 중 포함되어 있으며, 화면 설명대로 `가상 창고(VIRTUAL): 수량 개념 없음 (— 표시)`를 적용한다.

## 최종 정적 확인

- `InventoryStockBalancePage.tsx`의 UUID 사용은 창고 필터 요청 파라미터뿐이며, DataGrid 컬럼과 행 키에는 `productCode`/`warehouseCode`만 사용한다.
- `StockBalanceResponse.java`에는 UUID 타입/필드가 없고 한국어 Javadoc으로 wire 비공개 계약을 설명한다.
- 전체 테스트 실행 결과: `BUILD SUCCESSFUL`, 실패/에러 0.
