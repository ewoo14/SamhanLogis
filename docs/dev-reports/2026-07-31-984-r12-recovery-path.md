## 변경 요지

- MIG-8 재실행 시 `idempotency_key`가 이미 존재해도 현재 품목 조회를 수행하고, 기존 native 주문의 `product_id IS NULL` 라인만 동일한 결정적 라인 ID 기준으로 갱신한다.
- 갱신 성공 시 `product_id`, `model_name`, `product_name`, `category_key`와 감사 수정 필드를 반영한다. 이미 해소된 라인과 정상 주문은 갱신하지 않는다.
- 아직 품목 조회가 실패한 라인은 `product_id IS NULL`로 남긴다. 따라서 전표 전환의 기존 미해소 품목 가드는 계속 작동한다.
- 미해소 라인의 native 보존 경로에서 `Map.of().get(null)`이 발생하던 NPE를 null-safe 조회로 보정했다.
- 마이그레이션, 선두 token 규칙, reservation 경합 창은 변경하지 않았다.

## 실측

- 회복되는 건수: `1건` — 첫 실행에서 `product_id IS NULL`로 보존된 1라인이 재실행 시 `PRODUCT_MISSING` 품목 조회 성공 후 `product_id`를 획득했다. 기존 전환 차단 조건이 해제되는 상태를 단언했다.
- 여전히 차단되는 건수: `1건` — 2라인 주문에서 1라인만 해소된 경우 나머지 1라인은 `product_id IS NULL`로 유지됐다.
- 정상 주문 영향: `0건` — 기존 정상 주문 3건/4라인의 생성·멱등 재실행·상태/금액 단언이 유지됐다. 정상 주문은 계속 정상 흐름이다.
- 라이브 R7 replay: 26,055행이 이 PC에 없어 데이터 부재로 미판정. 회귀 테스트는 Testcontainers의 throwaway PostgreSQL과 외부 client 격리 mock 데이터로 수행했다.
