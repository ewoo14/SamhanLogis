## 2. 적용한 fix

### D2 — 재기동 재생성 차단

- `SlipSeeder`, `EstimateSeeder`, `PartnerOrderSeeder`의 멱등성 조회를 삭제행 포함 조회로 변경했다. S1 actor로 삭제된 결정적 문서가 “없음”으로 판정되지 않는다.
- `docker-compose.local-all.yml`의 주문 테스트 시더를 `false`로 변경했다.
- `.env.dev-seed`의 전표·주문 테스트 시더를 `false`로 변경했다.
- `product-service`의 기존 `false` 설정은 유지했다.

### D1 — 혼합 견적 정합

V117에서 테스트 라인 삭제 직후 활성 라인의 `supply_amount`, `vat_amount`, `line_total`을 다시 합산해 견적 헤더 세 금액을 갱신한다. 정본 라인은 삭제 조건에 포함되지 않는다.

### D3 — 부분 복원 성공 차단

- V117/V16의 순수 테스트 문서 헤더 삭제시각을 actor 라인의 최대 삭제시각으로 맞춰 동일 그래프의 복원 매칭키를 보존한다.
- 견적 복원은 삭제된 전체 라인을 조회해 헤더 actor와 일치하는 라인이 모두 복원 가능한 경우에만 진행하고, 불일치하면 `CONFLICT`로 실패한다. 성공 후 라인 저장·refresh·금액 재계산을 수행한다.
- 주문 복원은 삭제 라인 수와 헤더 삭제시각 일치 라인 수를 먼저 비교한다. 하나라도 빠지면 `CONFLICT`로 실패해 헤더만 성공하는 응답을 차단한다.
- 기존 판매전표 복원의 fail-loud 동작은 유지했다.

`qa-seed`는 SOL 실측상 테스트 품목(`TEST-BUNDLE-SET-01`, 활성 문서 참조 0)으로 판정해 정리 대상에 유지했다. 정본 `created_by=000...001` 품목·라인 경계는 변경하지 않았다.
