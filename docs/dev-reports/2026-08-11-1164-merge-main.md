## 1. 합성 근거

### 함수 계약 확인

origin/main의 `displayActorName`은 `AuditOverlay.tsx:99-107`에 있으며 시그니처는 다음과 같았다.

```ts
function displayActorName(actorName: string, actorId: string): string
```

본문은 `normalizeUuid(actorName)`과 `normalizeUuid(actorId)`를 비교하고, 이름이 없거나 두 UUID가 같을 때만 `변경자 미상`을 반환하며 그 밖에는 원래 `actorName`을 반환했다. 따라서 `1-1-1-1-1`은 UUID 정규식에 맞지 않아 보존되고, UUID-shaped 이름도 `actorId`와 다르면 과잉 은닉하지 않는 계약이다.

HEAD의 `safeActorName`은 `clients/web/design-system/src/utils/actorName.ts:6-15`에 있다.

```ts
normalizeActorName(null | undefined | invisible-only) === null
safeActorName(...) === null // null 또는 canonical UUID
```

`safeActorName`은 `actorId`를 받지 않으므로 canonical UUID가 row의 `actorId`와 다른 경우에도 `null`을 반환한다. 충돌 구간에 이를 그대로 선택하면 main의 R16 보정(서로 다른 actorId일 때 과잉 은닉 금지)이 사라진다.

### 최종 합성

현재 `AuditOverlay.tsx:101-109`의 helper는 다음 순서를 사용한다.

```ts
function displayActorName(actorName: string | null | undefined, actorId: string): string {
  const normalizedActorName = normalizeActorName(actorName)
  const actorUuid = normalizeUuid(normalizedActorName)
  const rowActorUuid = normalizeUuid(actorId)
  if (!normalizedActorName || (actorUuid !== null && actorUuid === rowActorUuid)) {
    return UNKNOWN_ACTOR_NAME
  }
  return normalizedActorName
}
```

즉, 정규화를 먼저 하고 그 결과를 UUID 동일성 판정에 사용한다. `null`/invisible-only는 `normalizeActorName`이 `null`로 만들고 helper의 기존 `변경자 미상` 폴백이 이긴다. 두 폴백을 섞지 않았으므로 화면 라벨은 한 종류다.

동일 helper를 두 표시 좌표에 적용했다.

- 최신 revision: `AuditOverlay.tsx:164`
- 확장 revision 목록: `AuditOverlay.tsx:199`
