# 이슈 #1065 / PR #1066 — R4 구현 보고서

## 1. 결론

출고 검수 결재 게이트의 도달 결함 2건을 수정했다.

- 검수 결재선 허용 계정은 `slip.transfer.process:UPDATE` 정적 권한이 없어도, 해당 OUTBOUND 전표의 `INSPECTING` 검수 결재선에 실제로 허용된 경우에만 `POST /slips/{id}/inspect`를 수행한다.
- 결재선에 없는 계정은 기존 동적 권한 검사 또는 서비스 결재선 게이트에서 계속 거부된다.
- 화면 전이는 백엔드 도메인과 정합화했다: `PROCESSING → complete → INSPECTING`, `INSPECTING → inspect → COMPLETED`.
- 역할 템플릿(`role_permissions`)은 변경하지 않았다.

작성자 자동 포함 규칙은 현재 검수 결재선 authorize 정책에 구현되어 있지 않았다. R4에서 새 정책으로 만들지 않고, 기존 결재선 USER/GROUP 판정만 사용했다.

### 정적 권한 누수 방지

- 역할 템플릿 및 DB 권한 seed 변경 없음.
- 결재선 bypass 조건은 `OUTBOUND + INSPECTING + authorize(configured=true, allowed=true)`로 한정.
- `/complete`, `/process`, `/accept`, `/ship`, `/deliver`의 `@RequirePermission`은 변경하지 않음.
- 결재선 비회원 테스트 `inspect_salesRole_returns403`가 포함된 `SlipInspectControllerIT` 전체 통과.

### 전이 정합성

```text
PROCESSING  --POST /complete--> INSPECTING
INSPECTING  --POST /inspect --> COMPLETED
```

기존 `inspect_warehouseRole_setsInspectorAndCompletes`, `complete_transitionsToInspecting`, `outbound_fullLifecycle_includingInspecting`를 포함한 전체 `SlipInspectControllerIT`가 통과했다.

## 5. 실 데이터/화면 QA

이번 라운드에서 화면·API로 생성한 데이터: 없음.

R3가 확인한 현재 PC 상태가 `OUTBOUND × INSPECTING 0전표`, 목표 활성 결재자 0명, `kimgicheol`·`kimeunji` auth 계정 0행이므로, 실제 관리자 화면/API로 결재선과 전표를 만들 수 있는 표본이 없었다. DB 직접 INSERT는 하지 않았고, Docker 재빌드/재배포도 하지 않았다. 따라서 실 화면에서 SALES·ACCOUNTANT 계정의 200과 회계 배분까지는 이번 라운드에서 **판정 불가**다.

로그인 응답 원문/토큰, UUID 사용자 노출, vendor 발송은 수행하지 않았다.
