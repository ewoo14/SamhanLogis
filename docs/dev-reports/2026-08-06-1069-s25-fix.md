# #1069 S25 fix 보고 — 모바일 견적 BUNDLE 부모 영속 우회

## 결론

`POST /mobile/sales/quotations`의 BUNDLE 라인을 구성품으로 전개하도록 고쳤습니다. 견적 변환·견적 revision 복원 경계에도 BUNDLE 부모 재검증을 추가해 부모 ID가 `estimate_lines` 또는 `slip_lines`에 새로 들어가는 우회를 차단합니다. BUNDLE 전개 실패는 저장·가격기억 없이 한국어 조치 안내 오류로 원자 거부됩니다.

## RED-first 증거

- 최초 방어 테스트 실행은 기존 `EstimateToSlipConverter`에 상품 재검증 의존성이 없어 `compileTestJava`에서 실패했습니다(`required: SlipRepository, SlipNumberService, OutboundCutoffGuard, Clock / found: ... Clock, ProductClient`).
- 생산 코드 적용 후 모바일 BUNDLE 전개, 모바일 SINGLE 보존, 불완전 전개 원자 거부, 레거시 BUNDLE 견적 변환 거부 테스트가 GREEN이 되었습니다.

## 변경 사항

1. `MobileQuotationService`
   - `ProductSummary.productType == BUNDLE`이면 `ProductClient.expand()`를 호출합니다.
   - `EstimateLine`에는 구성품 ID·수량·단가와 `parentSetModel/setHead` 계보만 저장합니다.
   - 구성품 누락/부분 응답과 modelCode 누락은 `BusinessException(INVALID_INPUT/NOT_FOUND)`로 거부합니다.
   - 정상 SINGLE은 기존 1라인·가격기억 경로를 그대로 유지합니다.
2. `EstimateToSlipConverter`
   - 변환 전에 라인 product를 재조회합니다.
   - BUNDLE 부모가 발견되면 slip 채번·생성·저장 전에 `세트 품목은 구성품으로 전개된 견적만 전표로 변환할 수 있습니다`로 거부합니다.
3. `EstimateService`
   - 데스크톱 견적 생성/수정에서 BUNDLE 판정 시 modelCode가 없으면 부모를 일반 라인으로 저장하지 않고 명시 거부합니다.
   - revision 복원 후에도 동일한 BUNDLE 부모 검증을 수행해 구 스냅샷 우회를 차단합니다.

## BUNDLE 생성 입구 전수표(S25 축 확장)

| 입구 | 저장/전환 지점 | BUNDLE 처리 | 판정 |
|---|---|---|---|
| 직접 전표 생성 | `SlipService.create` → `addSlipLinesExpanded` | `expand` 후 구성품 저장, modelCode/부분 전개 거부 | 차단됨 |
| 기존 전표 라인 추가 | `SlipService.addLine` → 동일 전개 helper | 동일 전개/거부 | 차단됨 |
| 전표 전체·부분 수정 | `SlipUpdateService`, `SalesSlipUpdateService` | BUNDLE 부모 거부, 기존 계보 보존 및 lineId/a11y 규약 유지 | 차단됨 |
| 전표 발행 resolver | `SlipPublishService` 단건·병합 | 부모를 평면 `SlipLine`으로 만들기 전 사용자 안내 거부 | 차단됨 |
| 일반 견적 생성·수정 | `EstimateService.addEstimateLines` | 구성품 전개; modelCode 없는 BUNDLE도 일반 라인 저장 금지 | 차단됨 |
| 모바일 견적 생성 | `POST /mobile/sales/quotations` → `MobileQuotationService` | **S25 신규**: 구성품 전개; 부분 실패 원자 거부 | 차단됨 |
| 견적 → 전표 변환 | `EstimateService.convert` → `EstimateToSlipConverter` | **S25 신규 방어**: 레거시/우회 BUNDLE 부모를 저장 전 거부 | 차단됨 |
| 견적 revision 복원 | `EstimateRevisionService.restore` → `EstimateService.restoreToRevision` | **S25 신규 방어**: 복원 후 저장 전 부모 재검증 | 차단됨 |
| 모바일 주문 | `MobilePartnerOrderService` | BUNDLE을 전표 라인으로 저장하지 않고 구성품 전개 안내 거부 | 차단됨 |
| partner_order 단건 전환 | `PartnerOrderConvertService` → `SlipServiceClient` → slip publish resolver | 다운스트림 resolver가 부모를 거부; 허용 문구만 경계 통과 | 차단됨 |
| partner_order 병합 전환 | `PartnerOrderMergeConvertService` → 동일 resolver | 동일 거부·보상/convertedQuantity 수렴 유지 | 차단됨 |
| 임포트·배치·스케줄러 | 현행 slip/estimate 영속 생성 호출 검색 결과 사용자 라인 생성 입구 없음 | 해당 서비스 범위의 BUNDLE 부모 신규 저장 호출 없음 | 신규 미차단 입구 없음 |
| seed/fixture | `SlipSeeder`, `EstimateSeeder` | 테스트/개발 fixture 전용, 사용자 생성 경로 아님 | 운영 입구 아님 |

전수표 축은 `slip_lines` 직접 생성만이 아니라 `estimate_lines → 변환`, `partner_order → 전환`, 모바일 견적·주문·전표, revision 복원까지 포함해 재검색했습니다. S23의 단건·병합 안내, 내부 HTTP 문구 차단, 경합 수렴, 가격기억·재고 보상 동작은 변경하지 않았습니다.
