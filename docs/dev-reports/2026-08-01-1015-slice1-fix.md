# 1015 주문 앱 접근 복구 결함 수정 보고서

## 확인 1 — 검토 보고서와 작업 범위

- 검토 보고서는 `LONG_UNUSED` 복구가 상태를 `NEED_PW_INPUT`으로 저장하더라도 기존 `lastLoginAt` 또는 `passwordChangedAt` 기준 만료시각이 유지되어 다음 `checkStatus()`와 `tryLogin()`에서 다시 `LONG_UNUSED`가 된다고 기록한다.
- 이번 수정 범위는 `partner-auth-service`의 복구·판정·로그인 경로와 해당 회귀 테스트이며, 실 DB 쓰기·비밀번호 재설정·공유 Docker 스택 변경은 하지 않는다.
- 보고서와 코드 문서에는 거래처 코드·이름만 사용하고 UUID·비밀번호 값은 기록하지 않는다.

## 확인 2 — RED: 복구 후 재선별·로그인 차단 재현

복구 후 `checkStatus()` 재선별, 복구 후 `tryLogin()` 토큰 발급, 미복구 만료 거래처의 `LONG_UNUSED` 선별을 각각 테스트로 추가하고 다음 명령을 실행했다.

```text
.\gradlew.bat :services:partner-auth-service:test --tests "com.samhanair.logis.partnerauth.service.PartnerAuthServiceTest.restoreLongUnused_checkStatus_상태유지" --tests "com.samhanair.logis.partnerauth.service.PartnerAuthServiceTest.restoreLongUnused_tryLogin_토큰발급" --tests "com.samhanair.logis.partnerauth.service.PartnerAuthServiceTest.unrestoredExpired_checkStatus_LONG_UNUSED선별" --rerun-tasks
```

## 확인 3 — GREEN: 복구 기준시각 갱신

`restoreFromLongUnused()`이 상태를 `NEED_PW_INPUT`으로 바꾸면서 `lastLoginAt`을 복구 시각으로 갱신하도록 수정했다. 기존 복구 상태·만료시각·로그인 토큰 결과 테스트를 다시 실행했다.

```text
> Task :services:partner-auth-service:test

BUILD SUCCESSFUL in 10s
9 actionable tasks: 9 executed
```

복구 후 `checkStatus()`는 `NEED_PW_INPUT`, 복구 후 `tryLogin()`은 `OK`와 토큰 발급, 미복구 만료 거래처는 `LONG_UNUSED`로 확인됐다.
