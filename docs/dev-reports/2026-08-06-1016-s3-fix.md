## 1. 원인과 수정

### 결함 A

`AligoAddressBookPage.tsx:142-155`의 안내 문단이 `result`와 무관하게 항상 렌더링됐다. 그 아래
`DeliveryStatusNotice`와 `ResultChips`는 `DELIVERED`·`PARTIALLY_DELIVERED`를 실제 전달로
표시하고 있었으므로, 한 화면에 외부 미전달과 실제 전달이라는 상반된 문장이 공존했다.

수정은 표시 계층에 한정했다.

- `result.deliveryStatus`가 `DELIVERED` 또는 `PARTIALLY_DELIVERED`이면 정적 문단에는
  CSV 다운로드가 전달 완료의 증거가 아니라는 사실만 표시한다.
- 결과가 없거나 `NOT_DELIVERED`이면 기존 mock 미전달 안내와 CSV 사실을 함께 표시한다.
- 서버 상태 3종, `UploadResult` 생성자, sync 집계, API 경로·응답은 변경하지 않았다.
- 화면 테스트에 기존 양수 3상태 경계와 건수 0인 3상태 경계를 고정했다.

### 결함 B

S1 보고서의 기존 “실행 원문”은 `--rerun-tasks` 없는 첫 실행인데도 `3 executed, 15 up-to-date`를
강제 재실행 증거처럼 읽을 수 있었다. S1 보고서의 검증 절을 다음처럼 정정했다.

- 첫 실행·캐시 원문은 삭제하지 않고 참고값으로 명시했다.
- PM이 S1 후 수행한 최종 강제 재실행 원문을 `--rerun-tasks`, `BUILD SUCCESSFUL`,
  `18 actionable tasks: 18 executed`와 함께 추가했다.
- 이번 S3 라운드에서도 지시서 ⑤의 좁은 강제 재실행을 수행했고 같은 `18 executed`를 확인했다.

## 2. 지시서 ② 불변식 판정

1. **한 화면의 전달 문장 무모순** — `hasExternalDelivery`로 정적 mock 문구를 외부 전달 상태에서
   숨겼다. `DeliveryStatusNotice`는 기존 상태 문장을 유지하고, FE 테스트에서 세 상태 모두
   mock 문구와 상태 문구의 조합을 확인했다.
2. **`DELIVERED` 건수 보존** — `ResultChips`의 기존 외부 전달 경계를 보존했다. 양수 응답
   `신규 3`·`변경 1`과 0건 응답 모두 실제 전달 문구가 보이고 mock 미전달 단정은 보이지 않는다.
3. **`PARTIALLY_DELIVERED` 건수·실패 동시 표시** — 기존 chip와 `FailedList`를 유지했다. 양수
   부분 전달은 `신규 2`·`실패 1`, 0건 부분 응답도 `실패 1`과 부분 전달 문구를 보인다.
4. **`NOT_DELIVERED` 성공 건수 차단** — `ResultChips`의 `added`·`updated`를 0으로 만드는
   기존 경계를 유지했다. 양수 입력과 0건 입력 모두 `신규 0`·`변경 0`, 실제 전달 0건 문구를 보인다.
5. **CSV 사실의 전 상태 보존** — 결과가 없거나 미전달이면 기존 전체 문장에 포함하고, 실제
   전달이면 CSV 사실만 별도로 표시한다. FE 6개 테스트 케이스에서 모두 해당 문장을 확인했다.
6. **검증 증거 일치** — S1 보고서의 캐시 실행과 강제 재실행을 별도 제목으로 구분했다. PM 제공
   강제 재실행은 `--rerun-tasks`와 `18 executed`를 포함하고, S3에서 지시서 ⑤ 명령도 같은
   조건으로 exit 0을 재확인했다. 캐시 수치는 강제 재실행 원문으로 남아 있지 않다.

## 3. 상태·건수·chunk 조합 확인

페이지는 chunk 개수를 직접 받지 않고 집계된 응답만 받으므로, chunk 형태는 서버 단위 테스트의
실제 호출 경로로, 건수와 문구 공존 여부는 FE DOM 경로로 확인했다.

| 상태 | 건수 0 | 건수 양수 | chunk 경로와 확인 결과 |
|---|---|---|---|
| `NOT_DELIVERED` | FE 0건 행렬 테스트. mock 문구·CSV 문구·신규 0·변경 0. 서버 빈 source는 upload 0회와 0/0/0을 반환 | FE 응답 7/2와 서버 mock 양수 오염 응답 7건. 화면·서버 모두 신규/변경 성공 0 | 단일 chunk 7건, 원천 0건을 확인 |
| `DELIVERED` | FE 0건 행렬 테스트. 실제 전달 문구·CSV 문구만 표시 | FE 3/1, 서버 50건 단일 chunk 재시도 성공 및 120건 50/50/20 다중 chunk 성공 | 단일·다중 chunk 모두 `DELIVERED`와 건수 보존 확인 |
| `PARTIALLY_DELIVERED` | FE 0/0 + 실패 chunk 1개. 실제 부분 전달 문구와 실패 1을 함께 표시 | FE 2/0 + 실패 1, 서버 60건 50 성공 + 10 실패 | 다중 chunk 일부 실패, 전달 건수와 실패 목록 동시 확인 |

따라서 `NOT_DELIVERED`·`DELIVERED`·`PARTIALLY_DELIVERED` 각각에 대해 건수 0/양수 화면을
밟았고, 단일 chunk·다중 chunk·일부 실패 chunk의 서버 경계도 지시서 범위 안에서 확인했다.
