# #1116 S22 — 범위 제한 수정 결과

## 판정

S21에서 지적된 두 건만 수정했다.

1. 읽지 못한 untracked evidence-writer 후보는 writer 모집단에서 skip하되, 상대 경로 목록을 `console.warn`으로 출력한다. 따라서 green이어도 사람이 후보를 확인할 수 있다.
2. Python `'''...'''`/`"""..."""` triple-quoted 문자열을 writer 판정 전에 제거해 문서 예제의 `docs/qa` 경로와 `open/write` 언급을 오차단하지 않는다.

S21에서 의도적으로 남긴 네 가지 정적 분석 한계는 수정하지 않았다.

- quoted Batch 목적지는 문자열 마스킹 때문에 탐지하지 못한다.
- marker와 `write`가 같은 도움말 문자열에 있으면 실제 writer가 면제될 수 있다.
- `Path('docs') / 'qa'` 같은 Python 경로 조립은 탐지하지 못한다.
- Batch `%OUT%` 변수 목적지는 탐지하지 못한다.

현재 tracked 실측이 0건인 두 경로 조립 형태도 미래 위반을 green으로 만들 수 있다는 SOL 지적은 타당하며, 이번 범위에서는 AST/상수 전이 또는 결과 기반 검사를 추가하지 않았다. 이 한계는 코드 주석에도 남겼다.

## 구현

수정 파일:

- `clients/desktop/src/renderer/test-utils/harness-false-green-guard.test.ts`
  - `unreadEvidenceCandidates`를 discovery 후 경고 목록으로 출력
  - Python triple-quoted 문자열을 줄바꿈만 보존하며 제거하는 제한적 상태기계 추가
  - discovery fallback도 정규화된 Python source를 사용하도록 연결
  - unread 후보 보고와 discovery 경로를 포함한 triple-quoted 문서 오차단 회귀 테스트 2건 추가

Triple-quoted 처리는 완전한 Python parser가 아니다. unusual escaped delimiter, 문자열 prefix 조합, nested expression 등은 해석하지 않으며, 동적으로 조립되는 경로도 계속 이 가드의 범위 밖이다.
