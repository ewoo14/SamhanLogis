## 결함 2 — 화면의 PROCESSING/INSPECTING 액션이 백엔드 상태 전이와 서로 뒤집혀 있다

### ① 사용자가 밟는 화면 동선

첫 번째 막힘:

1. 정적 전이 권한이 있는 사용자가 PROCESSING OUTBOUND 상세를 연다.
2. 화면은 다음 액션을 `inspect`로 선택해 `POST /slips/{id}/inspect`를 보낸다.
3. 백엔드 `inspect()`는 INSPECTING만 허용하므로 PROCESSING에서 409다.
4. 따라서 화면으로 `OUTBOUND × INSPECTING` 발화 조건을 만들 수 없다.

두 번째 막힘:

1. 다른 경로/API로 만들어진 INSPECTING OUTBOUND 상세를 `dev_manager` 같은 정적 권한자가 연다.
2. 화면은 다음 액션을 `complete`로 선택해 `POST /slips/{id}/complete`를 보낸다.
3. 백엔드 `complete()`는 PROCESSING만 허용하므로 INSPECTING에서 409다.
4. 결재선 구성 여부와 관계없이 화면으로 COMPLETED에 도달하지 못한다.

### ② 재현 근거

- 화면 액션 표는 `PROCESSING → inspect`, `INSPECTING → complete`다: `clients/desktop/src/renderer/routes/SlipDetailPage.tsx:284-300`.
- 화면은 선택한 action 문자열을 그대로 `/slips/{id}/{action}` POST로 보낸다: `clients/desktop/src/renderer/api/slip.ts:955-964`.
- 도메인의 실제 전이는 반대다. `complete()`가 PROCESSING → INSPECTING이고 `inspect()`가 INSPECTING → COMPLETED다: `services/slip-service/src/main/java/com/samhanair/logis/slip/domain/Slip.java:1065-1097`.
- 버튼 클릭은 `nextPrimaryAction`을 그대로 mutation에 넘긴다: `clients/desktop/src/renderer/routes/SlipDetailPage.tsx:2057-2094`.
- r2는 `clients/desktop/**`를 보지 않았다고 명시한다: `docs/dev-reports/2026-08-04-1065-backend-approval-authz-r2.md:273-275`.

실행 중 서버는 PR 코드가 아니고 실서버 POST도 금지되어 실제 409 응답은 만들지 않았다. 상태 불일치는 도메인의 `requireStatus`로 결정되며, 관련 IT는 올바른 API 순서인 `.../complete`로 INSPECTING을 만든 뒤 `.../inspect`로 COMPLETED를 만든다.

### ③ 실데이터 해당 건수

현재 활성 OUTBOUND 상태 원문:

```text
   status   | count
------------+-------
 DRAFT      |   115
 SAVED      |     0
 SENT       |     4
 INSPECTING |     0
 CONFIRMED  |     1
 COMPLETED  |     0
(6 rows)
```

- 현재 즉시 발화하는 PROCESSING/INSPECTING OUTBOUND는 각각 **0건**이다.
- 현재 SENT **4건**은 정상 lifecycle을 따라가면 이 화면 경계에 도달하는 후보지만, 현재 화면 코드는 PROCESSING에서 잘못된 `/inspect`를 호출하므로 화면으로 발화 조건을 만들 수 없다.
- IT는 올바른 API 순서로 INSPECTING fixture를 실제 생성해 실행할 수 있음을 확인했다. 즉 상태 자체가 도달 불가능한 가상 상태는 아니고, 화면 배선이 도달을 막는다.
