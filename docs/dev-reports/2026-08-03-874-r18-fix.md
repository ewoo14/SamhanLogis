R17 원문에서 고정된 결함은 다음과 같다.

- `findFocusRoutes`는 `AxisKey(partnerCode, label, modelToken, axis, actualUnitPrice)` 기준으로 A 단가 행만 반환한다.
- 하지만 `LegacyVerificationChain.riUsageDecision` 내부 `focusRows`는 같은 거래처·token·kind·branch만 보고 B 단가 행까지 다시 모은다.

- R17 최소 재현은 **2전표 / 4원천행**, 사용자 표시상 A 집계행에 추가 오판 1건이다. 실제 공유 DB의 발화 snapshot은 0행이라 운영 총량은 0으로만 관측됐다.

R16 원문에서 보존해야 할 회귀 계약도 확인했다.

- 같은 화면 행의 여러 route는 전부 평가하고 `false 우선 → null → 모두 true일 때 true`로 결합한다.
- `M-P-M=false`, `P-M-P-P=false`, `P-P-M=true`를 유지한다.
- 값 변경 3케이스에서 `P-M-P=true→false`, `M-P-P=false 유지`, all-true `true 유지`를 유지한다.
- 레거시 행 순서와 `byModel`/DTO insertion order를 바꾸지 않으며, 전체 accounting-service는 300초대 timeout이면 성공으로 기록하지 않는다.

Linux(`ubuntu-latest`) 판정: 위 원문이 의존하는 것은 Java 17 list/map/stream 순서와 명시적 비교·결합 규칙이다. OS별 파일 순서나 locale을 전제로 하지 않으므로, 이 단정은 Linux에서도 참이다.

판정: R18의 RED는 `focusRows`에 같은 화면 행의 단가 축을 반영하지 않은 현재 HEAD에서 먼저 작성·실행한다. 수정 범위 후보는 `LegacyVerificationChain`과 그 직접 회귀 테스트로 잠그고, `MonthEndCloseService`의 R16 집계 결합은 건드리지 않는다.

## 5. 최소 fix와 원본 RED → GREEN

판정: R16이 지정한 6개 변경 표면이 모두 GREEN이다. 실행 중 `UP-TO-DATE`/`FROM-CACHE`는 없었고, `--rerun-tasks --no-build-cache`로 21개 task를 실제 실행했다.

Linux(`ubuntu-latest`) 판정: Gradle test selection, Java 17 테스트, JUnit XML은 CI Linux에서도 동일한 task/test semantics를 갖는다. OS 의존 fixture·filesystem 정렬을 사용하지 않는다.

### 7-1. JUnit XML 실측

명령 원문:

```powershell
$files=Get-ChildItem 'services/accounting-service/build/test-results/test/TEST-*.xml'; $total=0; $failed=0; $errors=0; $skipped=0; foreach($f in $files){$x=[xml](Get-Content $f -Raw -Encoding UTF8); $s=$x.testsuite; $total += [int]$s.tests; $failed += [int]$s.failures; $errors += [int]$s.errors; $skipped += [int]$s.skipped}; "XML_FILES=$($files.Count)"; "TOTAL tests=$total failures=$failed errors=$errors skipped=$skipped"; rg -n "UP-TO-DATE|FROM-CACHE" services/accounting-service/build/test-results/test -g 'TEST-*.xml' -g '*.log'
```

출력 원문:

```text
XML_FILES=6
TOTAL tests=78 failures=0 errors=0 skipped=0
```

마지막 `rg`는 일치 없음으로 종료코드 1을 반환했으며, 이는 캐시 표식이 없다는 뜻이다. R16의 기존 76개에 R18 신규 2개 테스트가 더해져 78개가 되었다.

Linux(`ubuntu-latest`) 판정: JUnit XML 합산과 문자열 검색은 결과 보고용 read-only PowerShell 명령이며 production 판정 자체는 Gradle/JUnit 결과다. CI에서 test result XML의 tests/failures/errors/skipped 속성도 동일하다.

## 8. accounting-service 전체 suite

실행 명령 원문:

```powershell

```

출력 원문:

판정: accounting-service 전체 suite는 timeout이다. `BUILD SUCCESSFUL`로 포장하지 않는다. 이는 기존 핸드오프와 R16/R17의 300초대 timeout 이력과 일치한다. 권위는 CI이며, 이번 fix의 직접 변경 표면은 §7의 캐시 배제 `78/0/0/0` 결과로 별도 판단한다.

Linux(`ubuntu-latest`) 판정: timeout 자체는 로컬 Windows 실행 환경의 관측이다. Linux CI에서 같은 timeout이 난다고 단정하지 않으며, Linux에 대한 성공/실패는 CI 결과로 판단한다.
