## 1. 판정

fix4의 세 결함을 수정했다.

1. 정상 PowerShell 5.1 refresh가 체크인 DB snapshot과 byte-for-byte 동일하다.
2. 중복/잘못된 row 실패가 읽을 수 있는 UTF-8 한 줄만 출력하고 exit 1로 끝난다. 기존 산출물은 변경하지 않는다.

## 2. 구현 변경

### 2.1 PowerShell generator

파일: `scripts/refresh-accounting-permission-db-snapshot.ps1`

- `:8-11`에서 PS 5.1 console/stdout을 UTF-8로 설정하고 전체 실행을 `try/catch`로 감쌌다.
- 소스 파일은 한글 리터럴을 PS 5.1이 올바르게 읽도록 UTF-8 BOM을 추가했다. `.gitattributes`의 `*.ps1 text eol=crlf` 규약은 유지했다: source는 CRLF 115줄, LF-only 0줄.
- `:77-85`의 7-bit·중복 cell 검증은 output 대입(`:85`)보다 앞선다.
- `:109`는 `[Environment]::NewLine` 대신 명시적 LF와 UTF-8 no BOM을 사용한다.
- `:112-115`는 예외의 `Exception.Message`만 error stream에 쓰고 exit 1을 반환한다.
- BOM 적용 직후 fresh 생성에서 기존 artifact 주석의 `×`/`횞` 바이트 차이를 발견했다. 체크인 snapshot의 기존 SHA-256을 보존하기 위해 generator 주석 literal을 기존 artifact와 동일하게 맞췄고, 최종 fresh 실행에서 hash가 다시 동일함을 확인했다. 권한 데이터에는 영향이 없다.

### 4.4 DynamicPermissionService 결론

fix3의 “V39 `uq_rppt_active`를 지나므로 안전”은 잘못된 인용이었다. 실제 데이터 흐름은 다음이다.

```text
DynamicPermissionService:47 RolePagePermissionRepository
  → :123 findAllOrderByRoleCodeAndPageCode()
  → RolePagePermission:34 role_page_permissions / :36 is_deleted=false
  → V7:34-36 uq_role_page_permissions_active(role_code, page_code)
  → :127-129 dbIndex.put(pageCode, row)
```

따라서 결론 자체는 “active runtime source에는 unique 보호가 있다”로 유지되지만, 근거는 V39가 아니라 V7이다. V39는 `AccountPermissionService.getTemplates()`의 `RolePagePermissionTemplate` 경로와 account permission 경로에만 인용한다.
