# PR #1109 / 이슈 #1108 S2 fix directive — 확인 건수와 실제 삭제 건수 결박

## 1. 판정

머지 차단 결함 1건이다. 화면은 품목 수정 진입 시 카탈로그에서 읽은 구성품 수를 확인 문구에
표시하지만, 저장 요청은 그 수가 아니라 `confirmBundleChildrenDeletion: true`만 보낸다. 서버는
저장 시점의 활성 구성품 수를 다시 세면서도 Boolean만 검사한다. 따라서 다른 사용자가 구성품을
변경한 뒤 먼저 열린 폼에서 저장하면 사용자가 본 N건과 실제 soft-delete되는 M건이 달라도 통과한다.

## 2. 실 사용자 도달 사슬

1. 사용자 A가 BUNDLE 품목 수정 화면을 연다. `ProductFormPage`의 `product-form` 쿼리가
   `componentCount=N`을 읽어 확인 문구의 수로 보관한다.
2. 사용자 B가 지원되는 견적 품목 카탈로그의 `구성품 편집` 모달에서 같은 세트의 구성품을
   N건에서 M건으로 변경해 저장한다. 빈 배열은 금지되지만 1건 이상인 다른 집합은 정상 경로다.
3. 구성품 저장은 카탈로그 변경 이벤트를 발행한다. 그러나 `ProductFormPage`는
   `ProductRealtimeClient`를 구독하지 않고, `product-form` 쿼리도 무효화하지 않으므로 A의 문구는 N건이다.
4. A가 `N건이 삭제됩니다` 문구를 보고 확인한다. 요청에는 N이 없고 Boolean `true`만 들어간다.
5. 서버는 현재 활성 행 M건을 센 뒤 Boolean이 true라는 이유로 통과시키고 `removeBundleChildren`가
   M건 전부를 soft-delete한다.

읽기 전용 실 DB에서 활성 BUNDLE 343건, 활성 구성품 1,584행을 확인했다. 343건 모두 구성품이
있어 이 경합의 실제 대상이며, 현재 구성품 0건 BUNDLE은 0건이다.

## 3. 반드시 지킬 불변식

1. 사용자가 확인한 삭제 건수와 서버가 실제 soft-delete할 활성 구성품 건수는 같아야 한다.
2. 확인 뒤 구성품 집합이나 건수가 바뀌면 전환은 전부 중단하고 구성품을 한 행도 삭제하지 않아야 한다.
3. 사용자는 갱신된 건수를 보고 다시 명시적으로 확인할 수 있어야 한다.
4. 구성품 0건인 BUNDLE의 세트→단일 전환은 확인 없이 계속 통과해야 한다.
5. 확인 필드를 생략한 API 직접 호출과 실제 건수에 결박되지 않은 단순 Boolean 호출은 구성품이 있으면
   삭제를 진행해서는 안 된다.
6. 정상 확인된 세트→단일 및 자재 전환의 기존 soft-delete와 16인자 생성자 호환은 유지한다.

## 4. 양방향 RED-first

### RED A — 정상 경로를 보존한다

- 활성 구성품이 N건이고 사용자가 N건을 확인한 뒤 집합이 바뀌지 않았으면 세트→단일 전환이 성공하고
  정확히 N건만 soft-delete된다.
- 자재 전환도 같은 계약으로 성공한다.
- 구성품 0건 BUNDLE은 확인 UI와 확인 필드 없이 정상 전환된다.

### RED B — 결함이 재발하지 않는다

- A가 N건을 본 뒤 B가 지원 UI에서 N→M으로 변경하고 A가 저장하면 서버는 충돌로 중단하며 활성
  구성품은 M건 그대로다. 화면은 M건을 다시 읽어 재확인을 요구한다.
- N→M이 증가·감소한 두 방향과, 같은 건수지만 구성품 집합이 교체된 경우를 모두 고정한다. 건수만
  결박하면 같은 N건의 다른 집합을 삭제하는 결함이 남으므로 집합 버전 또는 동등한 동시성 계약이 필요하다.
- API가 Boolean `true`만 보내거나 확인값을 생략하면 활성 구성품 삭제가 진행되지 않는다.
- 실패 응답 뒤 품목 종류·분류·구성품 어느 것도 부분 변경되지 않는다.

## 5. 범위 경계

- DB 직접 INSERT/UPDATE로 재현하거나 검증하지 않는다.
- 기초품목 화면에 구성품 편집 UI를 새로 만들지 않는다. 기존 견적 품목 카탈로그의 지원 UI가 동시 변경자다.
- 품목 자체 삭제, 구성품 replace-all의 최소 1개 불변식, 시트 sync의 독립 동작을 이 결함에서 재설계하지 않는다.
- #1097 라이브QA가 공유 `product-service`를 점유 중이므로 이번 S2에서 재빌드·재배포하지 않는다.
