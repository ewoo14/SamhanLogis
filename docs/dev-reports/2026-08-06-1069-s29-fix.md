# #1069 S29 fix — KEEP 왕복 판정 수렴

## 결론

PM의 도메인 판단을 채택했다. `KEEP`은 부모 1행 유지 계약이고, `EXPAND`(및 `bundleMode` 누락)는 구성품 전개 계약이다. 따라서 KEEP을 새 화이트리스트로 만들지 않고, 평면 전체수정 PUT의 공통 guard가 KEEP 부모를 허용하도록 판정을 정정했다.

## RED 원문

초기 RED는 새 `bundleMode` 계약이 HEAD에 없어 테스트 컴파일에서 실패했다. 원문은 [2026-08-06-1069-s29-red.log](2026-08-06-1069-s29-red.log)에 보존했다. 이후 mock을 제거한 공통 guard 테스트로 전환해 KEEP 통과/EXPAND 차단 assertion을 GREEN으로 확인했다.

- `services/slip-service/src/test/java/com/samhanair/logis/slip/service/BundleProductGuardTest.java:1-47` — KEEP 허용, EXPAND 차단, 누락 mode의 EXPAND 기본값 회귀 테스트.

## 입구별 판정 일치 근거

| 입구 | 판정/결과 |
|---|---|
| 전표 신규·라인 추가 | 기존 `SlipService.addSlipLinesExpanded`가 BUNDLE을 product-service expand로 처리한다. EXPAND는 구성품 N행, KEEP은 부모 1행이다. |
| 매출·매입 전체수정 PUT | `BundleProductGuard`가 정본 `bundleMode`를 읽어 KEEP은 통과, EXPAND/누락은 한국어 안내로 차단한다. 기존 SINGLE은 BUNDLE 조건에 걸리지 않는다. |
| 견적 신규·전체수정 | 기존 `EstimateService.addEstimateLines`의 동일 expand 엔진을 유지한다. 부모를 평면 저장하지 않고 mode 계약에 따라 전개한다. |
| 모바일 견적 | 기존 `MobileQuotationService`의 동일 BUNDLE expand 경계를 유지한다. 모바일 정상 선택을 단순 차단하지 않는다. |
| 화면 전개 응답 | 명시적 `componentKind=null`인 KEEP 부모만 BUNDLE로 보존하고, 구성품은 SINGLE로 반영한다. 지연 snapshot/옵션/수량/단가/규격 로직은 변경하지 않았다. |
| 부분수정·단일 라인 삭제·SINGLE 발행/전환/복사/revision | 이번 guard의 BUNDLE 판정 외 기존 경로를 변경하지 않았다. 지정 회귀 suite가 통과했다. |

오류 문구는 `세트 품목은 구성품으로 전개한 뒤 저장해야 합니다.`이며 UUID, 내부 HTTP 문구, 서비스명, stacktrace를 포함하지 않는다.
