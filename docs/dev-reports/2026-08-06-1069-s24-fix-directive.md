# #1069 S24 SOL fix 지시서 — 모바일 견적의 BUNDLE 부모 영속 우회

## 결론 · 재현 난이도

**재현 가능한 사용자 경로 결함 1건이 남아 있어 머지를 권고하지 않는다.** S23에서 보완한 단건·병합 안내는 코드상 닫혔고 내부 400 본문도 허용 문구 외에는 화면으로 투과하지 않는다. 그러나 S23의 “BUNDLE 전표 라인 생성 경로 전수표”는 정식 모바일 영업 진입점인 `POST /mobile/sales/quotations`를 빠뜨렸다.

**재현 난이도: 중간.** `slip.mobile-sales CREATE` 권한과 활성 BUNDLE 품목 1개가 필요하다. 실제 DB 쓰기가 금지된 S24에서는 호출을 실행하지 않았지만, 아래 호출 사슬은 입력의 `productType=BUNDLE`을 이미 조회하고도 분기 없이 부모 `productId`를 견적에 저장한 뒤 전표로 1:1 복사하므로 환경·경합에 의존하지 않는다.

재현 순서:

1. 권한 보유 사용자가 `POST /mobile/sales/quotations`에 활성 BUNDLE의 `productId`를 라인으로 제출한다.
2. 생성된 견적을 일반 견적 화면에서 전표로 변환한다.
3. 현재 코드는 BUNDLE 부모 ID를 `estimate_lines.product_id`에 저장하고, 변환 시 같은 ID를 `slip_lines.product_id`에 저장한다. 구성품 전개도 명시 거부도 없다.

## 1. 좌표

- 사용자 진입점: `services/slip-service/src/main/java/com/samhanair/logis/slip/mobile/web/MobileSalesController.java:54,110-116`
  - 정식 모바일 영업 `POST /mobile/sales/quotations`가 `MobileQuotationService.createQuotation()`으로 연결된다.
- 누락된 생성 경로: `services/slip-service/src/main/java/com/samhanair/logis/slip/mobile/service/MobileQuotationService.java:74-105,135-149`
  - `productClient.lookup()`으로 `ProductSummary.productType()`까지 확보하지만 BUNDLE을 판별하지 않는다.
  - 모든 라인을 `EstimateLine.create(... lineReq.productId() ...)`로 1:1 추가한다.
- 전표 영속 우회: `services/slip-service/src/main/java/com/samhanair/logis/slip/estimate/service/EstimateService.java:324-335` → `services/slip-service/src/main/java/com/samhanair/logis/slip/estimate/service/EstimateToSlipConverter.java:52,78-115`
  - 변환기는 견적 라인의 `productId`를 재조회·검증하지 않고 `SlipLine.create*()`로 복사해 저장한다.
- 비교할 정상 패턴: `services/slip-service/src/main/java/com/samhanair/logis/slip/estimate/service/EstimateService.java:78-151,191-207,245-278`
  - 데스크톱 견적 생성·수정은 BUNDLE을 구성품으로 전개한다.
- 증거 무결성 좌표: `docs/dev-reports/2026-08-06-1069-s23-fix.md:29-51`
  - 전수표에 모바일 전표 생성은 있으나 모바일 견적 생성은 없다. 따라서 “전수” 판정과 “견적은 이미 전개돼 있다”는 전제가 성립하지 않는다.

## 2. 불변식

1. 사용자 생성 경로 어느 곳에서도 활성 BUNDLE 부모 `productId`가 `slip_lines.product_id`에 신규 영속되면 안 된다.
2. 모바일 견적은 데스크톱 견적과 같은 BUNDLE 의미를 가져야 한다. 저장 전에 구성품으로 전개되거나, 전개할 수 없다면 사용자가 조치 가능한 한국어 오류로 원자적으로 거부돼야 한다.
3. 견적→전표 변환은 신뢰되지 않은/레거시 견적 라인 때문에 BUNDLE 부모를 새 전표에 복사하지 않아야 한다. 모바일 생성 경로만 고치고 변환 경계의 불변식을 방치하면 안 된다.
4. 정상 SINGLE 모바일 견적의 품목·수량·단가·VAT/권위 금액·가격 기억·견적 상태·전표 변환 결과는 바뀌면 안 된다.
5. S23의 단건·병합 BUNDLE 안내, 임의 400 본문 차단, 재고 예약 보상, `convertedQuantity` 성공 후 누적, 409 경합 수렴을 유지해야 한다.
6. S19 a11y, 옵션 입력, BUNDLE 전개 계보, `#1063` trailing 빈행 규약을 유지해야 한다.

수단 금지:

- 모바일 화면에서만 BUNDLE 선택을 숨겨 서버 우회를 남기지 않는다.
- 변환기에서 부모 ID를 조용히 삭제하거나 SINGLE로 취급해 금액·라인을 유실하지 않는다.
- 모든 견적 변환을 일괄 차단하거나 기존 정상 SINGLE 2,387행 기준선을 새 정책 대상으로 오인하지 않는다.
- Docker 재빌드·재배포·중지, 공유 DB 쓰기, 전체 게이트, 다른 트랙(`#1057`, `#1066`, `#1075`) 파일 변경을 하지 않는다.

## 3. 양방향 RED

### RED-B — 결함 재현

- `ProductClient.lookup()`이 요청 부모 ID에 대해 `productType=BUNDLE`, 유효한 `modelCode`를 반환할 때 `MobileQuotationService.createQuotation()` 결과의 활성 견적 라인에 그 부모 ID가 그대로 남으면 RED.
- 위 견적을 `EstimateToSlipConverter.convert()`에 전달했을 때 활성 전표 라인에 BUNDLE 부모 ID가 생성되면 RED.
- 일부 구성품이 없거나 전개가 실패했는데 견적/전표가 부분 저장되거나 사용자가 조치 방법을 알 수 없는 내부 문구만 받으면 RED.
- 전수표에서 `POST /mobile/sales/quotations` → 모바일 견적 → 일반 견적 변환 경로가 빠지면 RED.

### RED-A — 반대급부 보존

- 정상 SINGLE 모바일 견적이 기존처럼 1라인으로 생성되고 동일 품목·수량·단가로 전표 변환되지 않으면 RED.
- 데스크톱 견적 생성·수정·발행, 거래처 주문 단건 전환, 병합 발행, 일반 전표 생성·전체수정·부분수정·모바일 저장이 새 차단에 걸리면 RED.
- BUNDLE 실패 때문에 견적이나 주문 상태가 전이되거나 재고 예약·`convertedQuantity`가 남으면 RED.
- 단건·병합 화면에서 안전한 “구성품으로 전개” 안내가 사라지거나, 임의 400 본문/`400 BAD_REQUEST`/내부 서비스명이 노출되면 RED.
- 정상 `OUTBOUND DRAFT`, cutoff `created_at < 2026-08-06 00:00:00` 기준 **2,387행 / 2,171전표 / 2,902,645,781원**의 기존 데이터가 오차단 대상으로 판정되면 RED.

## 4. 범위 밖 · 안 본 범위

- 범위 밖: BUNDLE 자동 전개 정책 재설계, product master 변경, 모바일 앱 전면 개편, 배포, 실 DB 데이터 정리, 타 트랙 파일.
- S24에서 보지 않은 범위: 실제 모바일 기기 GUI, 배포본과 HEAD 바이너리 동일성, 실제 권한 계정으로 쓰기 호출, 전체 CI/전체 Gradle 게이트.
- DB 쓰기 금지 때문에 실제 모바일 견적 생성·변환은 실행하지 않았다. 대신 컨트롤러→서비스→도메인→converter→repository 호출 사슬을 코드로 전부 대조했다.
- 읽기 전용 DB 재계수 결과: cutoff 기준 `OUTBOUND DRAFT`는 **2,387행 / 2,171전표 / 2,902,645,781원**, 현재 활성 BUNDLE 344개와 교차는 **0행**이다. 현재 총계는 **2,399행 / 2,180전표 / 2,911,338,509원**이다.
- 증거 표기 주의: 2,387행 전체가 현재 활성 `SINGLE` product와 직접 교차하는 것은 아니다. S22가 밝힌 직접 교차 부분집합은 2,107행/2,100전표/2,837,681,781원이고, 280행은 현재 활성 product ID와 교차하지 않는다. 수치 자체는 재현됐지만 “현재 활성 SINGLE 전량”으로 표현하면 안 된다.
