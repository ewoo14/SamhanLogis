# 입금보고서 조회 전환 (2026-08-01)

## 확인 1 — 현재 구조

- 목록의 `신규 작성` 버튼은 `CashReceiptListPage.tsx`에서 `/accounting/admin/cash-receipts/new`로 이동한다.
- 해당 라우트는 `accounting.cash-receipts:create` 권한으로 `CashReceiptFormPage`를 연다.
- 입출금 내역의 정식 생성 흐름은 `BankTransactionPage.tsx` → `BankDepositReceiptModal.tsx` → `POST /accounting/cash-receipts/from-bank-transactions`이며 `update` 권한을 사용한다.
- 기존 조회/편집 라우트는 각각 `/:id`(view), `/:id/edit`(update)로 분리되어 있다.

## 확인 2 — 경로 처리 판단

`/accounting/admin/cash-receipts/new`는 삭제하지 않고 목록으로 명시적으로 redirect한다. 이유는 라우트를 단순 삭제하면 React Router의 뒤따르는 `/:id` 라우트가 `new`를 문서 ID로 오인하거나, 직접 URL 접근이 불명확한 fallback으로 끝날 수 있기 때문이다. 명시적 redirect는 직접 URL 사용자에게 안전한 조회 목록을 보여주며, 생성 권한 없이 새 문서 작성 화면을 차단한다.

`CashReceiptFormPage`의 비편집 제목은 `입금보고서 조회`로 바꾸고, `/:id/edit` 편집 제목과 편집 입력/분할 행 기능은 유지한다.

## 확인 3 — 정식 생성 경로

`BankTransactionPage`의 `createBankDepositReceiptMutation`은 `createBankDepositReceipt`를 호출하고, 성공 후 통장 내역과 입금보고서 목록만 무효화한다. `BankDepositReceiptModal`의 `입금보고서 생성` 버튼은 이 콜백을 호출하므로 목록의 신규 작성 제거 및 `/new` redirect와 독립적이다.

## 확인 4 — `accounting.cash-receipts:create` 전수 참조

- `clients/desktop/src/renderer/api/mock.ts:6559`: 일반 `POST /accounting/cash-receipts` mock handler의 create 권한 검사. 수기 생성 API mock 계약을 보존하기 위해 유지했다.
- `services/accounting-service/src/test/java/com/samhanair/logis/accounting/it/AccountingPermissionControllerIT.java:266`: 일반 cash receipt create endpoint의 권한 매트릭스 테스트. 백엔드 계약/테스트이므로 유지했다.

그 외 애플리케이션 화면에서 해당 create 권한으로 진입하는 참조는 확인되지 않았다. 입출금 내역의 생성 경로는 `accounting.cash-receipts:update`이므로 영향이 없다.

## 확인 9 — Playwright mock 전체 재실행

동일 명령을 600초 제한으로 재실행했다.

```text
command timed out after 604034 milliseconds
Exit code: 124
```

Playwright가 line reporter 출력 없이 webServer/테스트 집합에서 종료되지 않았다. `5173` listener도 남지 않아 공유 서버를 재기동하거나 Docker를 건드리지 않고는 이 환경에서 전체 mock 결과를 얻지 못했다. 따라서 Playwright 전체는 **미완료/환경 timeout**으로 기록하며, Vitest의 관련 A 경로 검증은 다음 확인으로 별도 수행한다.
