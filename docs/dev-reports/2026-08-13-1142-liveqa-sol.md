## 실행 격리와 증거 무결성

- 공유 DB에는 `PGOPTIONS=-c default_transaction_read_only=on`을 강제한 `pg_dump`만 수행했다.
- 고유 Docker network `sol1142-liveqa-net`과 고유 컨테이너 4개(DB/auth/inventory/slip)만 사용했다.
- 복제 직후 실행 DB와 `__expected` DB를 비교해 세 DB 모두 UTF-8 복제가 동일함을 확인했다.

```text
CLONE_UTF8_PASS=auth_db|533f19422bf856...
CLONE_UTF8_PASS=inventory_db|febd5b5e582f2...
CLONE_UTF8_PASS=slip_db|f075347c89d838...
SOURCE_DB_ACCESS=pg_dump only; PGOPTIONS default_transaction_read_only=on
```

인증 DB 복제본은 운영 Flyway V101 스키마에 현재 엔티티가 기대하는 `account_page_permissions.actor_id`가 없어 schema validation으로 기동되지 않았다. 격리 복제본에서만 Flyway를 끄고 `ddl-auto=none`으로 실행했으며, 스키마나 대상 데이터를 보정하지 않았다. 타깃 API와 UI는 모두 이 격리 서비스로 호출했다.

## 도달 가능한 결함과 머지 판정

### 결함 1 — UUID 비공개 불변식 위반

재현 경로: 로그인 → 입고전표 목록 → 완료 전표 상세.

- 브라우저 상세 URL이 `/purchases/<UUID>`이다.
- 동일 사용자 경로에서 기존 전표 목록·상세 JSON 응답에도 내부 UUID가 포함된다.
- 화면 본문과 이번 S1의 bulk/single 판정 **응답 본문**은 UUID 비노출로 통과했다.

따라서 답은 **“실 사용자 경로에서 재현되는 결함이 있다(1건)”**이다. UUID 비공개 규칙을 직접 위반하므로 PR #1189는 현재 상태로 **머지 보류** 판정한다.
