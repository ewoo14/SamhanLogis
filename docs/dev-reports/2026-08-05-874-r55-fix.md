# R55 fix 보고서 — PR #1057 · 이슈 #874

## 판정

R54 지시서의 양방향 결함을 수정했다. 협업 PUSH outbox는 다섯 번의 빠른 재시도만으로 정상 사건을 TERMINAL로 닫지 않으며, 최대 24시간 동안 재시도한다. 24시간이 지나도 gateway 실패가 계속되면 `GATEWAY_RETRY_LIMIT`으로 유한하게 종결된다. 수신자 해석 불가와 editor 자신은 기존처럼 vendor 호출 없이 즉시 TERMINAL이다.

최종 포기 사건은 `/admin/slip-collab-notifications/terminal`에서 담당자가 전표번호 스냅샷, 종결 사유, 시도 횟수로 조회할 수 있다. 응답에는 내부 UUID·수신자 UUID·event UUID를 넣지 않았다. API는 api-gateway의 JWT 보호 no-strip route로 연결했다.

## RED-first 원문

첫 RED 실행은 수정 전 production API가 없는 상태에서 다음 컴파일 실패로 중단됐다. 이는 새 회복·관측 계약이 아직 구현되지 않았음을 확인한 실패다.

```text
SlipCollabNotificationDispatchTest.java:215: error:
  method create(...) cannot be applied to given types
SlipCollabNotificationDispatchTest.java:218: error:
  cannot find symbol findTop100ByStatusOrderByCreatedAtAsc(...)
SlipCollabNotificationDispatchTest.java:224: error:
  cannot find symbol listTerminalFailures()
SlipCollabNotificationDispatchTest.java:225: error:
  cannot find symbol getSlipNo()
BUILD FAILED
```

RED가 고정한 행동은 다음과 같다.

1. 다섯 번 연속 일시 실패 후 여섯 번째 기회에서 SENT까지 수렴한다.
2. retry window가 지난 gateway 실패는 유한하게 TERMINAL이 된다.
3. TERMINAL 사건은 전표번호와 사유로 읽힌다.

## 변경 내용

- `SlipCollabNotificationOutbox`: 전표번호 스냅샷과 retry 시작 시각을 저장한다.
- `SlipCollabNotificationOutboxService`: 5회 즉시 상한을 제거하고 24시간 retry window를 적용한다. 기존 수신자 해석 실패·editor 자신 TERMINAL과 terminal 행의 scheduler 제외는 유지한다.
- `SlipCollabNotificationOutboxRepository` / `SlipCollabNotificationAdminController`: TERMINAL 조회 및 관리자 읽기 경로를 추가했다.
- `SlipCollabEditService`: 수정완료 시 `updated.slipNo()`를 outbox에 전달한다.
- api-gateway: `/admin/slip-collab-notifications/**` JWT no-strip route를 추가했다.
- slip migration `V112__retain_collab_notification_retry_window.sql`: `slip_no`, `retry_started_at`, terminal 조회 인덱스를 추가했다.
- 기존 마이그레이션과 `accounting-service`는 수정하지 않았다.
