# #1069 S3 구현 보고서 — 판매전표 세트 전개

## 범위

정본 `docs/dev-reports/2026-08-05-1069-s2-fix-directive.md`의 S3 결함 1~3과 양방향 RED를 좁은 테스트 범위에서 수정했다. Docker 재빌드·재배포·중지, DB 쓰기, git 명령은 실행하지 않았다.

## RED-first 증거

수정 전 지시된 회귀 테스트를 먼저 실행했다.

### 서버 RED

```text
SalesSlipUpdateServiceTest > 매출 전체수정은 BUNDLE 자체 라인을 영속하지 않고 거부한다 FAILED
MobilePartnerOrderServiceTest > mobilePartnerOrder_rejectsBundleBeforeCreatingSlipLine FAILED
```

원인은 매출 전체수정 서비스에 `ProductClient` 타입 검증 의존성/분기가 없었고, 모바일 서비스는 품목 요약에서 `productType=BUNDLE`을 확인하지 않은 채 `SlipLine.create`와 `save`까지 진행했기 때문이다.

### 화면 RED

```text
SlipFormPage 이카운트식 라인 입력 > 늦게 도착한 세트 전개 응답은 이후 일반 품목 선택을 덮지 않는다
expected 'Product B' to be 'Product A'
```

당시 지연 응답이 사용자가 이후 선택한 일반 품목을 구성품으로 교체했다. 규격 전달 계약 RED도 추가해 `expand-line` 요청에 부모 규격이 포함되는지 검증했다.

## 수정 내용

- `SalesSlipUpdateService`: 저장 전 제품 요약을 조회해 BUNDLE productId가 포함된 전체수정 요청을 `INVALID_INPUT`으로 거부한다. 정상 SINGLE/구성품 라인은 기존 저장 경로를 유지한다.
- `MobilePartnerOrderService`: 이미 수행하는 일괄 품목 조회 결과로 BUNDLE을 생성 전에 거부한다. 채번·전표 생성·저장 전에 종료한다.
- `ExpandSlipLineRequest`/`SlipLookupController`/desktop API: 부모 `specification`을 전개 계약에 추가했다. 구성품 규격이 비어 있을 때 부모 규격을 응답에 승계한다.
- `SlipFormPage`: 행별 전개 세대 토큰을 둬 품목·수량·단가·규격·옵션 입력 이후의 늦은 성공/실패 응답을 폐기한다. 수량/규격/옵션이 바뀐 채 세트가 남아 있으면 최신 행 스냅샷으로 한 번 재전개한다. 구성품 규격은 자체 값 우선, 없으면 부모 행 규격을 사용한다.
- `autoBlankRow`와 정상 SINGLE/구성품 저장 경로는 변경하지 않았다.
