# #1069 S9 판매전표 세트 전개 fix 보고서

## 판정

S8 지시서의 실패 응답 경합 결함을 수정했다. 같은 BUNDLE 행의 세대가 바뀐 뒤 이전 전개가 성공하거나 실패해도, 최신 BUNDLE 스냅샷을 다시 전개하도록 성공·실패 경로를 동일한 규칙으로 처리한다.

## 원인

`SlipFormPage.tsx`의 `expandSelectedBundle`은 성공 응답에서만 세대 불일치 시 최신 BUNDLE을 재귀 전개했다. 실패 응답의 `catch`는 품목·유형·세대 guard에서 즉시 반환했기 때문에, 수량 1 요청이 실패한 뒤 수량 3 최신 요청이 발행되지 않고 BUNDLE 부모가 화면에 남았다.

RED 원문:

```text
expected expandBundleLine to be called with quantity: 3
received 1st call quantity: 1
Number of calls: 1
Tests 1 failed | 68 skipped
```

## 수정

- `SlipFormPage.tsx:788-816`
  - 세대 불일치 여부와 최신 BUNDLE 여부를 판단하는 `retryLatestBundleGeneration` 규칙을 추가했다.
  - 성공 응답과 실패 응답 모두 같은 helper를 거쳐 최신 세대를 재전개한다.
  - 현재 세대의 실패만 기존 오류행·오류 안내로 처리한다.
  - 품목 교체/SINGLE 전환 시에는 최신 행이 BUNDLE이 아니므로 옛 요청이 재전개되지 않는다.
- `SlipFormPage.test.tsx:960-1030`
  - 수량·단가·규격·옵션 변경 중 이전 실패에 대한 최신 재전개 RED-B 회귀를 추가했다.
  - 기존 현재 세대 실패, 품목 교체, S2/S4/S6 및 빈행 회귀를 함께 보존했다.

## 검증

### RED-first

수량 변경 중 첫 요청 실패를 고정한 신규 테스트에서 수정 전 전개 호출은 과거 `quantity=1` 1회뿐이었고 최신 `quantity=3` 호출은 0회였다. 수정 후 동일 테스트는 최신 호출 1회를 확인했다.
