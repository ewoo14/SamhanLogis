## 2. 판정

**도달 가능한 결함: 1건**

결함은 **정상 매입 원천(INBOUND) 생성 경로가 `partner_id`는 저장하면서 `partner_code`를 저장하지 않는 것**이다. 따라서 사용자가 제시한 분류는 **ⓑ 결함**이다.

다만 거래처 코드가 정상인 원천을 격리 실 API로 마련한 뒤의 **매입 회계 저장 경로 자체는 `MASTER`·`MANAGER`·`ACCOUNTANT` 3/3 성공**했다. 즉 이번 결과는 다음 두 사실을 분리한다.

1. R17의 표본 0은 권한/매입 저장 API 결함 때문이 아니며, 정상 원천에서는 세 역할 모두 실제 저장된다.
2. 공유 DB의 유일한 `CONFIRMED` 매입 원천이 정상 거래처를 UUID로 참조하면서도 코드를 잃어버린 것은 유효성 검증이 아니라 선행 생성 경로의 도달 결함이다.

## 3. 발화 조건 카운트 — 먼저 센 값

공유 `slip_db`의 삭제되지 않은 매입 원천 전체를 먼저 셌다.

```sql
BEGIN TRANSACTION READ ONLY;
SELECT is_deleted,
       count(*) AS inbound_rows,
       count(*) FILTER (
           WHERE NULLIF(btrim(partner_code), '') IS NOT NULL
       ) AS code_filled,
       round(
           100.0 * count(*) FILTER (
               WHERE NULLIF(btrim(partner_code), '') IS NOT NULL
           ) / NULLIF(count(*), 0),
           2
       ) AS code_pct,
       count(*) FILTER (
           WHERE partner_id IS NOT NULL
             AND NULLIF(btrim(partner_code), '') IS NULL
       ) AS uuid_only
FROM slips
WHERE slip_type = 'INBOUND'
GROUP BY is_deleted
ORDER BY is_deleted;
COMMIT;
```

원문 결과:

```text
is_deleted | inbound_rows | code_filled | code_pct | uuid_only
false      |           61 |          12 |    19.67 |        47
true       |           14 |          11 |    78.57 |         1
```

활성 매입 원천은 **61건 중 12건(19.67%)만 코드 보유**, `partner_id`만 있고 코드가 빈 UUID-only 사고는 **47건**이다. R17의 발화 조건은 `CONFIRMED` 1건, 그중 코드 보유 0건, 코드 누락 1건이었다.

SELECT status,
       count(*) AS rows,

WHERE slip_type = 'INBOUND'

## 5. 질문 2 — R17 차단은 ⓐ 정당한 검증인가, ⓑ 결함인가

**ⓑ 결함이다.** R17의 유일한 공유 `CONFIRMED` 원천은 다음과 같다.

```text
slip_no=2026/04/08-1
slip_type=INBOUND
status=CONFIRMED
source_type=MANUAL
partner_name=거래처-P-2026-0048
partner_id=SET
partner_code=<EMPTY>
created_by=system
modified_by=system-internal
```

그 `partner_id`가 가리키는 공유 `partner_db` 마스터는 삭제·비활성 데이터가 아니다.

```text
partner_code=P-2026-0048
partner_name=여주에어컨테크
active=true
is_deleted=false
purchase_type=기본설정
```

생성 경로별 분포 SQL 원문:

```sql
BEGIN TRANSACTION READ ONLY;
SELECT CASE created_by
         WHEN 'system' THEN 'SYSTEM_SEED'
         WHEN 'a0000000-0000-0000-0000-000000000003' THEN 'MANAGER_API'
         WHEN 'a0000000-0000-0000-0000-000000000006' THEN 'WAREHOUSE_API'
         ELSE 'OTHER'
       END AS creation_path,
       count(*) AS rows,
       count(*) FILTER (
           WHERE NULLIF(btrim(partner_code), '') IS NOT NULL
       ) AS code_filled,
       count(*) FILTER (
           WHERE partner_id IS NOT NULL
             AND NULLIF(btrim(partner_code), '') IS NULL
       ) AS uuid_only,
       min(created_at) AS first_created,
       max(created_at) AS last_created
FROM slips
WHERE slip_type = 'INBOUND'
  AND is_deleted = false
GROUP BY 1
ORDER BY rows DESC;
COMMIT;
```

원문 결과:

```text
SYSTEM_SEED   | 30 |  0 | 30 | 2026-05-09 ... 2026-05-09
MANAGER_API   | 17 | 12 |  4 | 2026-07-17 ... 2026-08-08
WAREHOUSE_API | 14 |  0 | 13 | 2026-08-08 ... 2026-08-08
```
