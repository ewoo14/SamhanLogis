## 수정 1 — 발행과 inventory 보강 분리

일반 OUTBOUND와 모바일 주문은 원래 `@Transactional` 발행 흐름 안에서
`findWarehouseCode`를 동기 호출했지만, 이를 제거하고 저장 직후
`WarehouseCodeSnapshotService.scheduleAfterCommit(...)`만 등록한다.
실제 inventory 호출은 원 트랜잭션이 commit된 뒤 수행된다.

- inventory 성공: 별도 transaction으로 `source_warehouse_code`를 한 번 보강한다.
- inventory 404/403/5xx/timeout/network 실패: 예외를 전파하지 않고 저장된 전표는 유지하며,
  code는 비워 둔 채 `UNKNOWN`으로 표시된다. 자동 재시도는 이번 범위에서 도입하지 않는다.
- client에는 connect timeout 2초/read timeout 3초를 설정했다.

## 확인 5 — 다섯 장애 모드 GREEN
