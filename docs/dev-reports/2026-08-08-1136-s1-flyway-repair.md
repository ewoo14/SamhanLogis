# PR #1137 / 이슈 #1136 — 슬라이스 1 기존 환경 복구

## 결과

기존 DB의 Flyway 체크섬을 `flyway repair`로 재기록하고 `auth-service`를 복구했다. 마이그레이션 파일은 되돌리지 않았다.

| DB | 실행 전 불일치 | repair | 멱등 재실행 |
|---|---|---|---|
| `auth_db` | `5, 48, 49` | 성공 | 성공, 불일치 없음 |
| `arologis_db` | `9` | 성공 | 성공, 불일치 없음 |

`arologis-service`는 복구 전부터 healthy였고, `V9` 체크섬만 동일 절차로 정정했다.

## 실행 환경

- 스택 호스트 Compose 작업 디렉터리 라벨은 `t-likeesc`였으나 해당 위치의 `.env`/`.env.local`은 존재하지 않았다.
- 실제 QA 자격 파일은 `C:\dev\Samhan-Public\.claude\worktrees\t1096\infrastructure\.env.local`에 있었다. 보고서에는 자격값을 기록하지 않는다.
- DB 비밀번호는 저장소 스크립트에 넣지 않았으며, 환경 파일에 없을 때 실행 중 `samhan-postgres` 컨테이너 환경에서만 보완했다.

## 복구 검증

`-WhatIf` 출력:

```text
auth_db: checksum mismatch versions = 5, 48, 49
What if: Performing the operation "Flyway repair (checksum metadata only)" on target "auth_db".
arologis_db: checksum mismatch versions = 9
What if: Performing the operation "Flyway repair (checksum metadata only)" on target "arologis_db".
```

실행 후 스크립트를 한 번 더 실행했으며 두 DB 모두 `checksum mismatch versions = (none)`이었다. 실행 명령은 `repair`와 `validate`뿐이며 `clean`, `migrate`, `drop`, 수기 SQL update는 사용하지 않았다.

auth 단독 재기동:

```text
docker compose -f docker-compose.yml -f docker-compose.local-all.yml -f docker-compose.slip-port-override.yml up -d --no-deps --no-build auth-service
```

실제 `docker ps` 원문:

```text
samhan-auth-service|Up 52 seconds (healthy)
```

실제 로그인 API 검증:

```text
POST /auth/login status=200
자격: infrastructure/.env.local 사용 (<redacted>)
```
