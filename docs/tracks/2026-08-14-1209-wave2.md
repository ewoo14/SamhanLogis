# 🔒 정찰 후 개발책임자 결정 (2026-08-15)

## 결정 A — 헤더 제거는 **서비스 초기 sanitizing 까지**

```
wave 1 이 한 것   게이트웨이가 공개 route 에서 inbound identity 헤더를 제거한다
남은 구멍         서비스에 직접 닿는 공개 경로 (아로로지스 nginx 직결 등)
                  게이트웨이를 안 거치므로 거기서는 제거가 안 일어난다
                  지금은 "서비스가 해석하지 않는다" 로만 막고 있다

결정  서비스 초기에서 request header 를 물리적으로 제거한다
```

🔑 **"해석하지 않는다" 와 "존재하지 않는다" 는 다르다.** 해석 로직이 하나만 늘어도 그 헤더가 다시 살아난다. 물리 제거는 그 가능성을 없앤다.

🚩 이것은 **wave 1 계약의 확대**다. wave 1 이 만든 것을 깨지 않으면서 얹어야 한다.
