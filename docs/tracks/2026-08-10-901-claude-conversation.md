# 트랙 개설 — `#901` 클로드 대화 기능 (계정 권한 범위 내)

> 2026-07-22 등록. 🚨 **편의 기능이 아니라 보안 경계 기능**입니다.

## 이슈가 이미 못 박은 제약

> 🔒 **클로드는 "해당 계정에 부여된 권한에 한해서만" 내부 작업을 할 수 있다.**
> 로그인 사용자의 권한을 넘어선 조회·변경이 **단 한 경로라도** 열리면 권한 체계 전체가 우회된다.

## 정찰이 확정할 것

1. **권한 강제 위치** — 기존 BE 권한 강제가 어디서 도는가(`@RequirePermission` 등). `파일:줄`.
   🚨 클로드의 도구 호출이 **반드시 기존 BE 엔드포인트를 그대로 통과**해야 합니다. DB 직접 접근·내부 우회 경로를 주지 않습니다.
2. **감사 로그** — 사람이 한 것과 구분 가능한 기록 수단이 이미 있는가. `BaseEntity` 7 audit 과의 관계.
3. **UUID 비노출 규약** — 대화 응답에도 내부 식별자가 새지 않아야 합니다. 기존 노출 코드 체계를 표로.
4. 기존 대화·메신저 표면과의 관계 — `#894`(PR #1125) 정찰이 *"별도 채팅 도메인 신설 금지"* 를 확정했습니다. 이 기능이 그 위에 얹히는가 별개인가.

## 🚨 착수 전 개발책임자 확인 — 추측 금지

```text
행위 범위          조회 전용부터인가, 변경(생성/수정)까지인가
되돌릴 수 없는 작업 승인·발행·삭제에 별도 확인 절차를 둘 것인가
대화 이력          보존/삭제 정책
외부 전송 범위     모델 호출 시 사내 데이터가 무엇이 나가는가
```

🚨 마지막 항목은 **사내 데이터 외부 전송**이라 반드시 선확인입니다.
