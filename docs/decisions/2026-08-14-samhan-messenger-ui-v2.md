## 0. 개발책임자 원문

> *"삼한 메신저로 이름을 바꾸고 상단 탭에 '클로드'를 하나 넣고 새로운 세션을 계속 생성하는 방향으로 진행요청. 디자인 시스템을 사용해서 카카오톡 처럼 세련된 디자인으로 내부 디자인 변경 요망."*

> *"카카오톡 이미지잖아. 상단 페이지 전환은 위처럼 진행해줘. 다만 개별 페이지는 아까 말한 것처럼 직급별(개발자는 직급이 아님), 단 그룹별로 편성(그룹에도 우선순위 설정). 그 사람과 1:1 대화를 진행할 수 있음. 내 상태를 페이지 전환 버튼 바로 아래에 두는 이유는 거기서 내 상태 변경 가능하기 때문. 그룹별은 위 카카오톡 디자인을 참고, 클로드는 세션별로 열 수 있도록 진행."*

## 1. 앱 명칭

**삼한 메신저.** 사용자에게 보이는 모든 자리(창 제목 · 작업표시줄 · 설치본 표시명 · 앱 내 헤더)에 반영한다.

---

## 2. 상단 페이지 전환 — 참고 이미지 그대로

개발책임자가 카카오톡 화면을 참고로 제시했다. 그 화면의 상단은 **알약(pill) 모양 칩이 가로로 늘어선 줄**이다.

```
[ 전체 ]  ( 안읽음 ⑤ )  ( ChatGPT )  ( + )
  ▲선택          ▲미선택 · 개수 배지    ▲추가
```

관측된 형태 — **이 형태를 따른다**:

| 요소 | 관측된 모습 |
|---|---|
| 선택된 칩 | 진한 배경 + 반전 텍스트 |
| 미선택 칩 | 연한 배경 + 본문 색 텍스트 |
| 개수 배지 | 칩 안 오른쪽에 작은 원형 카운트 |
| 마지막 칩 | `+` — 추가 동작 |
| 정렬 | 가로 한 줄 · 좌측 정렬 · 넘치면 가로 스크롤 |

### 삼한 메신저의 칩 구성

```
[ 개별 ]  [ 그룹별 ]  [ 클로드 ]
```

🚩 `안읽음` 필터 칩과 `+` 칩을 둘지는 **미결정**(§6).

---

## 3. 내 상태 — 페이지 전환 줄 **바로 아래**

> *"내 상태를 페이지 전환 버튼 바로 아래에 두는 이유는 거기서 내 상태 변경 가능하기 때문."*

⟹ 위치는 장식이 아니라 **기능의 자리**다.

```
[ 개별 ] [ 그룹별 ] [ 클로드 ]
────────────────────────────
● 홍길동  차장            ← 여기서 내 상태를 바꾼다
```

- 내 상태 아이콘 + 이름 + 직급
- **클릭하면 상태 4종(접속 · 자리비움 · 부재중 · 오프라인)을 직접 변경**할 수 있어야 한다
- 상태 아이콘은 **이름 왼쪽**에 온다 (개발책임자 지목)

---

## 4. 개별(1:1) 페이지

```
그룹(조직 단위)으로 편성한다        — 그룹에도 우선순위(표시 순서)를 둔다
그룹 안에서는 직급 순서로 정렬한다   — 🚨 "개발자" 는 직급이 아니므로 직급 축에서 제외
사람을 누르면 그 사람과 1:1 대화를 시작한다
각 사람 이름 왼쪽에 상태 아이콘이 보인다
```

🔑 **개발자는 직급이 아니다.** 직급 순서표에 넣지 마라.

---

## 5. 그룹별 페이지 — 참고 이미지의 목록 형태

참고 화면의 방 목록에서 관측된 한 행의 구성:

```
[아바타]  방 이름  ⟨인원수⟩                     시각
          마지막 메시지 한 줄 (말줄임)
```

| 요소 | 관측된 모습 |
|---|---|
| 아바타 | 좌측 정사각 라운드. 다인원 방은 분할 그리드 |
| 방 이름 | 굵게. 이름 앞에 작은 뱃지 아이콘이 붙는 경우 있음 |
| 인원수 | 방 이름 오른쪽에 회색 작은 숫자 |
| 마지막 메시지 | 이름 아래 한 줄, 연한 색, 말줄임 |
| 시각 | 행 우측 상단. 당일은 `오전 8:36`, 이전은 `어제` |
| 구분선 | 없음 — 여백으로 행을 나눔 |

이 형태를 따른다.

## 6. 클로드 탭 — **세션별로 연다**

```
한 개의 대화창이 아니라 세션 목록 + 새 세션 생성
세션을 계속 만들 수 있다
세션을 골라 그 세션의 대화를 연다
```

🔑 **세션은 서버에 남아야 한다.** 화면 상태로만 존재하면 앱을 닫는 순간 사라지고, 감사 로그가 어느 세션의 대화인지 식별할 수 없다.

⚠️ 권한 축은 그대로다 — `system.claude` 가 없으면 **서버가 거부**한다. 탭을 숨기는 것은 권한이 아니다.
⚠️ 자격(API 키) 미설정 상태를 목업 응답으로 덮지 않는다. 사용자에게 그 사실을 알리고 멈춘다.

## 8. 🔴 개발책임자 결정 — 2026-08-14 추가 확정 4건

### 결정 A — 목록 축: **그룹이 바깥 · 직급이 안**

PM 해석이 맞다고 확정됐다.

```
▼ 영업1팀            ← 그룹 (우선순위 1)
   ● 김부장   부장
   ● 이차장   차장
   ● 박대리   대리
▼ 물류팀            ← 그룹 (우선순위 2)
   ● 최과장   과장
   ● 정사원   사원
```

### 결정 B — 그룹 표시 순서: **마스터가 관리 화면에서 지정**

전사 공통 순서다. 모든 사용자가 같은 순서로 본다. ⟹ **관리 화면과 그 권한이 필요하다.**

### 결정 C — 같은 그룹·같은 직급 안: **입사일 순 (오래된 사람 먼저)**

🚩 입사일 데이터가 전 직원에게 채워져 있어야 한다. **비어 있는 직원이 어떻게 정렬되는지**를 정해야 한다(§9).

### 결정 D — 상태는 **6종**으로 확장 · 자동 전환 10분 / 30분

> *"10분 자리비움, 30분 부재중, 그리고 회의중, 통화중 도 추가 요망"*

| 상태 | 전환 |
|---|---|
| **접속** | 활동 중 |
| **자리비움** | 무활동 **10분** 후 자동 |
| **부재중** | 무활동 **30분** 후 자동 |
| **회의중** | 🆕 **수동 전용** |
| **통화중** | 🆕 **수동 전용** |
| **오프라인** | 연결 끊김 |

🚨 **기존 4종에서 2종이 늘었다.** 상태를 저장하는 곳(enum · DB 제약 · 프런트 타입 · 아이콘 색)을 **전수로** 늘려야 한다. 한 군데라도 빠지면 그 경로에서 새 상태가 거부되거나 조용히 오프라인으로 떨어진다.
🔑 **수동으로 회의중·통화중을 고른 사용자를 자동 전환이 덮으면 안 된다.** 수동 선택이 자동보다 우선한다.

## 9. ⏳ 아직 결정이 필요한 것

```
① 상단 칩에 "안읽음" 필터와 "+" 를 둘 것인가 (참고 화면에는 있다)
② 개별 목록에 안읽음 표시를 둘 것인가 (선행 정본에서도 미결정)
③ 입사일이 비어 있는 직원의 정렬 위치 (결정 C 에서 파생)
④ 수동 상태(회의중·통화중)를 언제 풀 것인가 — 사용자가 직접만? 일정 시간 후 자동 해제?
```
