## 0. 개발책임자 원문

> *"삼한 메신저로 이름을 바꾸고 상단 탭에 '클로드'를 하나 넣고 새로운 세션을 계속 생성하는 방향으로 진행요청. 디자인 시스템을 사용해서 카카오톡 처럼 세련된 디자인으로 내부 디자인 변경 요망."*

> *"카카오톡 이미지잖아. 상단 페이지 전환은 위처럼 진행해줘. 다만 개별 페이지는 아까 말한 것처럼 직급별(개발자는 직급이 아님), 단 그룹별로 편성(그룹에도 우선순위 설정). 그 사람과 1:1 대화를 진행할 수 있음. 내 상태를 페이지 전환 버튼 바로 아래에 두는 이유는 거기서 내 상태 변경 가능하기 때문. 그룹별은 위 카카오톡 디자인을 참고, 클로드는 세션별로 열 수 있도록 진행."*

## 1. 앱 명칭

**삼한 메신저.** 사용자에게 보이는 모든 자리(창 제목 · 작업표시줄 · 설치본 표시명 · 앱 내 헤더)에 반영한다.

## 2. 상단 페이지 전환 — 참고 이미지 그대로

개발책임자가 카카오톡 화면을 참고로 제시했다. 그 화면의 상단은 **알약(pill) 모양 칩이 가로로 늘어선 줄**이다.

```
[ 전체 ]  ( 안읽음 ⑤ )  ( ChatGPT )  ( + )
  ▲선택          ▲미선택 · 개수 배지    ▲추가
```

관측된 형태 — **이 형태를 따른다**:

| 요소 | 관측된 모습 |
|---|---|
| 선택된 칩 | 진한 배경 + 반전 텍스트 |
| 미선택 칩 | 연한 배경 + 본문 색 텍스트 |
| 개수 배지 | 칩 안 오른쪽에 작은 원형 카운트 |
| 마지막 칩 | `+` — 추가 동작 |
| 정렬 | 가로 한 줄 · 좌측 정렬 · 넘치면 가로 스크롤 |

### 삼한 메신저의 칩 구성

```
[ 개별 ]  [ 그룹별 ]  [ 클로드 ]
```

🚩 `안읽음` 필터 칩과 `+` 칩을 둘지는 **미결정**(§6).

---

## 3. 내 상태 — 페이지 전환 줄 **바로 아래**

> *"내 상태를 페이지 전환 버튼 바로 아래에 두는 이유는 거기서 내 상태 변경 가능하기 때문."*

⟹ 위치는 장식이 아니라 **기능의 자리**다.

```
[ 개별 ] [ 그룹별 ] [ 클로드 ]
────────────────────────────
● 홍길동  차장            ← 여기서 내 상태를 바꾼다
```

- 내 상태 아이콘 + 이름 + 직급
- **클릭하면 상태 4종(접속 · 자리비움 · 부재중 · 오프라인)을 직접 변경**할 수 있어야 한다
- 상태 아이콘은 **이름 왼쪽**에 온다 (개발책임자 지목)

## 4. 개별(1:1) 페이지

```
그룹(조직 단위)으로 편성한다        — 그룹에도 우선순위(표시 순서)를 둔다
그룹 안에서는 직급 순서로 정렬한다   — 🚨 "개발자" 는 직급이 아니므로 직급 축에서 제외
사람을 누르면 그 사람과 1:1 대화를 시작한다
각 사람 이름 왼쪽에 상태 아이콘이 보인다
```

🔑 **개발자는 직급이 아니다.** 직급 순서표에 넣지 마라.

## 5. 그룹별 페이지 — 참고 이미지의 목록 형태

참고 화면의 방 목록에서 관측된 한 행의 구성:

```
[아바타]  방 이름  ⟨인원수⟩                     시각
          마지막 메시지 한 줄 (말줄임)
```

| 요소 | 관측된 모습 |
|---|---|
| 아바타 | 좌측 정사각 라운드. 다인원 방은 분할 그리드 |
| 방 이름 | 굵게. 이름 앞에 작은 뱃지 아이콘이 붙는 경우 있음 |
| 인원수 | 방 이름 오른쪽에 회색 작은 숫자 |
| 마지막 메시지 | 이름 아래 한 줄, 연한 색, 말줄임 |
| 시각 | 행 우측 상단. 당일은 `오전 8:36`, 이전은 `어제` |
| 구분선 | 없음 — 여백으로 행을 나눔 |

이 형태를 따른다.

## 4-b. 🔴 창 구조 — **목록 창 + 대화방 별도 창** (2026-08-14 개발책임자 결정)

> *"저렇게 좌측에 방목록, 우측에 대화 내용을 표시하는 것보다는 **카카오톡처럼 채팅방 리스트만 남기고, 실제 채팅방은 새로운 창을 켜도록** 하는게 나을 것 같은데? **그룹별에는 채팅방리스트만 표현**."*

```
❌ 지금        한 창을 좌우로 나눠 [방 목록 | 대화 내용]
✅ 바꿀 것     메인 창 = 목록만
              방을 누르면 그 방이 별도 창으로 열린다 (카카오톡 방식)
```

### 적용 범위

```
개별 탭    사람을 누르면 → 그 사람과의 1:1 대화가 새 창
그룹별 탭  방 목록만 표시 · 방을 누르면 → 그 방이 새 창
클로드 탭  세션 목록만 표시 · 세션을 누르면 → 그 세션이 새 창
```
🚩 PM 해석 — 세 탭 모두 같은 규칙으로 읽었다. 클로드 탭만 다르게 가야 한다면 알려 주십시오.

### 🚨 이 변경이 건드리는 것 — presence 판정

방금 `#1180` 이 **영속 presence session lease** 로 *"두 세션 중 하나만 닫아도 OFFLINE 이 되지 않는다"* 를 세웠다. **창이 여러 개가 되면 그 계산이 다시 흔들린다.**

```
🔒 창 하나 = 접속 하나가 아니다
   대화방 창을 열고 닫는 것은 접속 상태와 무관하다
🔒 오프라인은 "그 사용자의 삼한 메신저가 완전히 닫혔을 때" 다
   메인 목록 창이 살아 있으면 대화방 창을 다 닫아도 접속이다
🔒 presence 구독을 창마다 새로 만들지 마라
   창 N개 = 연결 N개가 되면 서버 부하가 창 수만큼 곱해지고
   창 하나 닫힐 때마다 OFFLINE 이 발행되는 지금의 결함이 되살아난다
```

### 🔴 모바일은 다르다 — 화면 전환 + 뒤로가기

> *"모바일버전은 해당 방으로 들어갔다가 **다시 뒤로 버튼으로 나와서 채팅방 목록으로 돌아오는** 게 나을 거 같고."*

```
데스크톱   목록 창 + 대화방 별도 창        (카카오톡 데스크톱 방식)
모바일     같은 화면에서 방으로 들어가고 뒤로 버튼으로 목록 복귀  (플랫폼 관례)
```

🔑 **대화방 화면 자체는 하나여야 한다.** 껍데기만 둘이다 —
```
데스크톱 껍데기   별도 BrowserWindow
모바일 껍데기     네비게이션 스택의 다음 화면 (하드웨어/제스처 뒤로가기 지원)
```
🚨 대화방 화면을 두 벌로 만들면 한쪽만 고쳐지는 결함이 생긴다. 오늘 이 저장소에서 *"고쳤는데 실 앱은 아니다"* 가 여러 번 나왔다.

🚩 모바일 뒤로가기는 **하드웨어 버튼·제스처·화면 내 버튼** 셋 다 같은 동작이어야 한다.

### 창 동작 — 결정 완료 (2026-08-14)

| 항목 | 결정 |
|---|---|
| 같은 방 재클릭 | **새 창을 또 열지 않고 이미 열린 창을 앞으로** |
| 창 위치·크기 | **방별로 기억** |
| 메인 창을 닫으면 | **대화방 창은 남고 접속도 유지** |
| 알림 | **그 방 창이 포커스면 알림 없음** |

```
메인 창 ✕ 닫기
  ↓
대화방 창 2개는 그대로 · 상태 = 접속 중

대화방 창도 전부 닫음
  ↓
상태 = 오프라인
```

🔑 **"메인 창 = 앱의 주인" 이 아니다.** 메인은 목록일 뿐이고, **열려 있는 창이 하나라도 있으면 접속**이다. 이것이 §4-b 의 presence 불변식과 정확히 맞물린다 — *창 하나 = 접속 하나가 아니다.*

🔑 **알림은 "지금 보고 있는가" 로 판단한다.** 그 방 창이 포커스면 알리지 않고, 닫혔거나 뒤에 있으면 알린다. 모바일은 그 방 화면이 떠 있는 상태가 포커스에 해당한다.

🚩 **파생으로 정해야 할 것** — 방별 창 위치·크기를 **어디에 저장**하는가(로컬 설정 vs 서버 계정). 로컬이면 PC 를 옮길 때 초기화되고, 서버면 계정별로 따라간다. 구현자가 정하고 근거를 남긴다.

## 5-b. 🔴 클로드 세션 목록 — 2026-08-14 개발책임자 지적

개발책임자가 실 앱 캡처를 보고 지적했다.

> *"메신저 클로드 부분은 왜 아래 '새대화'가 이상하게 나열되어 있는거야? **수직으로 카톡방처럼 세련된 디자인**으로 나열되어야지."*
> *"**대화창 제목은 클로드가 요약해서 한 줄로 간단히 표현**하면 되지."*

**당시 실제 화면** (`docs/qa/2026-08-14-1180-reconv/screenshots/05-claude-session-list-real-qa.png`)
```
[새 대화][새 대화][새 대화][새 대화][새 대화][새 대화][새 대화][새 대화][새 대화][새 대화][새 대화]
  ← 가로로 11개가 줄지어 있다
  ← 전부 같은 이름 — 어느 세션인지 구분할 정보가 0
  ← 네모 테두리 버튼 · 카카오톡 방 목록과 전혀 다르다
```

### 결정 — §5 의 그룹별 목록 형태를 그대로 쓴다

```
[아바타]  세션 제목                              시각
          마지막 대화 한 줄 (말줄임)
구분선 없이 여백으로 행을 나눈다 · 수직 목록
```

### 🔴 세션 제목 = **클로드가 요약한 한 줄**

```
🔑 사용자가 제목을 직접 짓지 않는다
🔑 대화 내용을 클로드가 한 줄로 요약해 제목으로 쓴다
🚩 자격 미설정·가상 에이전트 상태에서 요약이 어떻게 되는지도 정해야 한다
   (가상이면 요약도 가상임이 드러나야 한다 — 실제 요약으로 오인하면 안 된다)
```

### 🚩 함께 지적된 것 — 내부 용어 노출

같은 캡처의 헤더에 **`축 0 권한 보호`** 가 그대로 나와 있다. "축 0" 은 내부 설계 용어이고 사용자는 그게 무엇인지 모른다.
⟹ 사용자가 읽고 이해할 수 있는 말로 바꾸거나 지운다. 🚩 다른 화면의 내부 용어·코드·식별자 노출도 함께 훑는다.

## 6. 클로드 탭 — **세션별로 연다**

```
한 개의 대화창이 아니라 세션 목록 + 새 세션 생성
세션을 계속 만들 수 있다
세션을 골라 그 세션의 대화를 연다
```

🔑 **세션은 서버에 남아야 한다.** 화면 상태로만 존재하면 앱을 닫는 순간 사라지고, 감사 로그가 어느 세션의 대화인지 식별할 수 없다.

⚠️ 권한 축은 그대로다 — `system.claude` 가 없으면 **서버가 거부**한다. 탭을 숨기는 것은 권한이 아니다.
⚠️ 자격(API 키) 미설정 상태를 목업 응답으로 덮지 않는다. 사용자에게 그 사실을 알리고 멈춘다.

## 7. 디자인 기준 — 🔴 개발책임자: *"부디 세련된 카톡 디자인처럼"*

`"세련되게"` 만으로는 매번 다르게 나온다. **체크 가능한 기준**으로 적는다.

### 토큰 규율 (먼저 지킬 것)
- `@samhan/design-system` 의 **컬러 토큰 · 타이포 스케일 · Pretendard 9 weight** 를 쓴다.
- 🚫 색·폰트·간격·radius·shadow 를 코드에 직접 박지 않는다.
- design-system 에 있는 컴포넌트를 먼저 찾는다. 자체 컴포넌트 신규 작성은 최후 수단.

### 목록 화면 — 이렇게 보여야 한다

```
[ 아바타 ]  방 이름            ⟨N⟩              오전 8:36
            마지막 메시지 한 줄 (말줄임)
                                                 ⟨안읽음 뱃지⟩
```

| 항목 | 기준 |
|---|---|
| 행 구분 | 🚫 **구분선을 긋지 않는다.** 여백으로 나눈다 |
| 아바타 | 좌측 정사각 라운드. 다인원 방은 분할 그리드 |
| 방 이름 | 굵게(semibold 이상). 길면 말줄임 |
| 마지막 메시지 | 이름 아래 한 줄. **연한 색**(secondary 계열). 말줄임 |
| 시각 | 행 우측 상단. 당일 `오전 8:36` · 이전 `어제` · 그 전 날짜 |
| 밀도 | 한 행이 **한눈에 읽히는 높이** — 너무 빽빽하지도, 허전하지도 않게 |
| hover/선택 | 은은한 배경 변화. 🚫 테두리를 두르지 않는다 |

🚨 **네모 테두리 버튼을 나열하지 마라.** 그것이 이번에 지적받은 형태다.

### 대화 화면

```
말풍선     내 것과 상대 것이 좌우로 갈리고 색이 다르다
연속 발언  같은 사람이 이어 말하면 아바타·이름을 반복하지 않는다
시각       말풍선 옆 작게. 분 단위가 같으면 마지막 것에만
읽음 표시  카카오톡의 숫자처럼 — 있으면 표시, 없으면 자리도 없다
입력창     하단 고정. 여러 줄 입력 시 자연스럽게 늘어난다
```

### 판정 방법

🔑 **"카톡처럼" 은 스크린샷으로 판정한다.** 참고 화면(`docs/decisions/` 에 기록된 카카오톡 목록 형태)과 나란히 놓고 **행 구성·여백·색 대비·정렬**이 같은 결인지 본다.
🚩 구현자는 **실제 앱 캡처**를 제출한다. 컴포넌트 단위 렌더 캡처는 판정 근거가 아니다.

## 8. 🔴 개발책임자 결정 — 2026-08-14 추가 확정 4건

### 결정 A — 목록 축: **그룹이 바깥 · 직급이 안**

PM 해석이 맞다고 확정됐다.

```
▼ 영업1팀            ← 그룹 (우선순위 1)
   ● 김부장   부장
   ● 이차장   차장
   ● 박대리   대리
▼ 물류팀            ← 그룹 (우선순위 2)
   ● 최과장   과장
   ● 정사원   사원
```

### 결정 B — 그룹 표시 순서: **마스터가 관리 화면에서 지정**

전사 공통 순서다. 모든 사용자가 같은 순서로 본다. ⟹ **관리 화면과 그 권한이 필요하다.**

### 결정 C — 같은 그룹·같은 직급 안: **입사일 순 (오래된 사람 먼저)**

🚩 입사일 데이터가 전 직원에게 채워져 있어야 한다. **비어 있는 직원이 어떻게 정렬되는지**를 정해야 한다(§9).

### 결정 D — 상태는 **6종**으로 확장 · 자동 전환 10분 / 30분

> *"10분 자리비움, 30분 부재중, 그리고 회의중, 통화중 도 추가 요망"*

| 상태 | 전환 |
|---|---|
| **접속** | 활동 중 |
| **자리비움** | 무활동 **10분** 후 자동 |
| **부재중** | 무활동 **30분** 후 자동 |
| **회의중** | 🆕 **수동 전용** |
| **통화중** | 🆕 **수동 전용** |
| **오프라인** | 연결 끊김 |

🚨 **기존 4종에서 2종이 늘었다.** 상태를 저장하는 곳(enum · DB 제약 · 프런트 타입 · 아이콘 색)을 **전수로** 늘려야 한다. 한 군데라도 빠지면 그 경로에서 새 상태가 거부되거나 조용히 오프라인으로 떨어진다.
🔑 **수동으로 회의중·통화중을 고른 사용자를 자동 전환이 덮으면 안 된다.** 수동 선택이 자동보다 우선한다.
