# 주문서 → 출고전표 전환 흐름 (2026-08-15 개발책임자)

## 개발책임자 원문

> *"주문서는 그냥 선택한 주문들을 견적서처럼 개별단위 → 출고전표로 전환하는 방식을 기본으로 하도록 하자."*
>
> *"병합의 경우 첫번째 선택 전표 정보를 기준으로 그 안에 품목 데이터만 첫번째 전표 품목들 + 두번째 전표 품목들 + … 이런 식으로 가도록 하자."*
>
> *"버튼을 '출고전표 전환'으로 명칭을 바꾸고 선택하면 모달창에 먼저 위 아래로 2개의 큰 버튼을 생성해. '개별전환', '병합전환' 이런식으로."*
>
> *"개별전환은 그냥 바로 전환시키면서 주문서 목록에서 '완료' 상태로 변경하여 접수 상태 목록에서 사라지게 함. (기본은 '접수' 상태이며, 위 조회 목록에서 '전체', '접수', '완료' 상태로 볼 수 있음)"*
>
> *"그렇게 해서 '병합전환'의 경우 내가 말한 방식으로 품목들을 병합하여 주문서 전표상세를 보여주고 '승인' 버튼을 클릭하면 전환이되는거야. 상태는 자유롭게 변경 가능."*

## 확정 흐름

```text
① 목록에서 주문 N건을 체크박스로 고른다
② 버튼 "출고전표 전환" 을 누른다        ← 기존 "출고전표로 병합 전환" 에서 개명
③ 모달이 열리고 위아래로 큰 버튼 2개
     ┌─────────────────┐
     │    개별전환      │
     ├─────────────────┤
     │    병합전환      │
     └─────────────────┘
```

### 개별전환

```text
바로 전환한다 (중간 확인 화면 없음)
선택 N건 → 출고전표 N건
전환된 주문은 목록에서 '완료' 상태가 된다
  ⟹ 기본 필터가 '접수' 이므로 목록에서 사라진다
```

### 병합전환

```text
헤더    첫 번째 선택 전표의 정보를 기준으로 삼는다
품목    1번 전표 품목 + 2번 전표 품목 + …  순서대로 이어붙인다
화면    합쳐진 결과를 "주문서 전표상세" 형태로 보여 준다
확정    '승인' 버튼을 눌러야 전환된다
```

🔑 **개별은 즉시, 병합은 확인 후.** 병합은 헤더가 하나로 합쳐지므로 사람이 보고 승인해야 한다.

## 상태 축

```text
기본값   접수
필터     전체 · 접수 · 완료
전환 후  완료
🚩 "상태는 자유롭게 변경 가능" — 사람이 접수↔완료를 되돌릴 수 있다
```

## 🔒 불변식

```text
1  🚨 개별전환은 N건이 각각 별도 출고전표가 된다
   개별 경로에서는 "다른 거래처 섞임" 차단이 필요 없다 — 각자 자기 전표다
2  🚨 병합전환은 헤더가 하나이므로 거래처가 섞이면 안 된다
   🔑 차단은 병합 경로에만 남는다
3  🚨🚨 부분 실패를 뭉개지 마라
   N건 중 일부 실패 시 어느 건이 왜 실패했는지 보이고 성공분은 남는다
4  🚨 전환 가능 상태만 고를 수 있다 · 이미 전환된 주문은 두 번 못 고른다
5  🚨 '완료' 로 바뀐 주문이 '전체'·'완료' 필터에서는 보여야 한다
   사라지는 것은 '접수' 필터에서만이다
6  🚨 상태 변경이 자유로우므로 되돌린 주문이 다시 전환 대상이 되는지
   그 규칙을 명시해야 한다
7  🚨 권한 — sales.partner-order.convert / create
```

## 병합 규칙 (2026-08-15 개발책임자 추가 확정)

> *"품목 중복 시 모델과 가격이 같다면 뒷 순서로 수량 병합"*
> *"품목 외 다른 필드는 모두 첫 전표를 따름"*

```text
헤더·그 밖 모든 필드   전부 첫 번째 선택 전표를 따른다
                       배송지 · 납기일 · 메모 · 거래처 · 담당자 …
                       🚩 예외를 두지 않는다 — "품목 외 다른 필드는 모두"

품목                   1번 + 2번 + … 순서대로 이어붙인다
중복 판정              모델이 같고 가격이 같으면 같은 품목이다
                       🚩 둘 다 같아야 한다. 모델만 같고 가격이 다르면 별개 행이다
중복 처리              수량을 합친다 (뒷 순서로)
```

🔑 **버려지는 값이 생긴다.** 2번 이후 전표의 배송지·납기일·메모는 병합 결과에 반영되지 않는다.
사용자가 승인 전에 그 사실을 알 수 있어야 한다.
