## 🔴 추가 결정 (2026-08-13, PM 검증 중 발견)

### `is_leaf` 는 저장값이 아니라 **자식 유무로 판정**한다

이관 대상 27개 중 5개가 `is_leaf=false` 였고, 그중 **`4511 매출원가` 는 자식이 0개**였다.
더 세어 보니 **자식 0개인데 `is_leaf=false` 인 계정이 10개**다.

```
4511 매출원가
5019 재료비 · 5038 노무비(제품) · 5108 경비(제품)
6022 재료비 · 6038 노무비(용역) · 6108 경비(용역)
7022 재료비 · 7038 노무비(기타) · 7108 경비(기타)
```

자식이 없으면 정의상 leaf 다. 결정 7(상위 계정 기표 차단)을 저장된 플래그로 걸면 **재료비·노무비·경비·매출원가가 통째로 못 쓰게 된다** — 실제로 기표해야 하는 계정들이다.

⟹ **판정을 파생시킨다.** 업무 판단이 아니라 데이터 정합성 수리이고, 10개가 한 번에 풀리며 앞으로 이카운트에서 계정을 다시 받아도 어긋나지 않는다.
⟹ 이 결정으로 `501 상품매출원가` → **`4511 매출원가`** 이관이 결정 7 과 충돌하지 않는다.

🚩 `900` → `9018 영업외수익`/`9318 영업외비용` 은 **둘 다 자식이 있는 진짜 상위 계정**이지만 `900` 사용이 0건이라 기표 대상이 없다. 코드 정리만 하면 된다.

## 🔴 2026-08-13 집PC 실측 — *"사용 0건"* 전제가 반증됐다

집PC 에 계정과목 정본을 반영하며 다시 셌다. **위 "미사용이라 소급 비용 0" 표가 집PC 에서는 성립하지 않는다.**

```
                       회사PC    집PC
chart_of_accounts        354      77 → 353   (V101 seed 276행 적용 후)
journal_lines          7,275행    309행 / 23코드 (전부 3자리)

255 부가세예수금          0건       7행     ← 🔴
103 당좌예금              0건      10행     (+ cash_receipts.debit 5행)
831 지급수수료           26행       0건
```

`103` 은 `MAPPED_UNUSED` 라도 `target_code='1029'` 가 있어 이관된다. **문제는 `255` 하나다.**

```sql
('255', NULL, 'RETIRED_UNUSED'),                        -- V101:352
UPDATE journal_lines … WHERE m.target_code IS NOT NULL  -- 255 는 안 걸림
RAISE EXCEPTION 'V101 이관 후 검증 실패: 남은 3자리 코드: …'  -- V101:782
```

⟹ **`255` 사용 행이 있는 DB 에서 V101 은 잔존 3자리 가드에 걸려 통째로 롤백된다.**
조용히 깨지지 않는 것은 설계가 옳으나, 그 DB 는 이관 자체가 불가능하다. 실운영 DB 에 `255` 가 있으면 거기서도 같다.

### 🔴 개발책임자 결정 (2026-08-13)

> **`255` 7행은 `2559` 로 이관한다.**

결정 3(*"`220`·`255` 부가세예수금 중복 → `2559` 로 통일"*)을 **사용 행에도 그대로 적용**하는 것이다.
새 결정이 아니라 이미 내린 결정의 적용 범위를 확정한 것이며, `220` 과 동일하게 취급한다.
부가세예수금 잔액은 `220` 분과 합산된다.

```sql
('255', '2559', 'MAPPED'),   -- was: ('255', NULL, 'RETIRED_UNUSED')
```

🔑 `2559` 는 이미 `220` 의 target 이라 `v101_account_code_targets` 에 등재돼 있고 leaf 판정도 통과한다. 새 target 추가가 아니다.

### 🚩 이 건이 남기는 교훈

*"사용 0건이라 소급 비용 0"* 은 **그 PC 의 시드에서만 참**이었다. 코드 정리 대상과 데이터 이관 대상을 **한 PC 실측으로 가르면 안 된다.**
⟹ V101 은 `RETIRED_*` 로 분류한 코드에 대해서도 **사용 행이 발견되면 중단하고 보고**하는 편이 안전하다(현재 가드가 실제로 그 역할을 한다).
