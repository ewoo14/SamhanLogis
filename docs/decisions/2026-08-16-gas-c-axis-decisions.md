## ① 가격·상품 정본 — **우리 DB 가 정본**

> *"GAS 시트와 노션을 우리 DB로 데이터를 옮겼잖아."*

```text
확정   product_db · dc-config 등 현행 DB 가 정본이다
       GAS 시트와 Notion 은 그 데이터의 이관 원천이었지, 계속 살아 있는 권위가 아니다
```

🚩 **PM 의 질문 틀이 틀렸다.** "어느 쪽이 정본인가" 로 물었는데, 애초에 **이관이 끝난 관계**다.
시트/Notion 을 계속 참조하는 설계는 만들지 않는다.

### 🔑 오늘 아침 "CSV(Notion)가 정본" 결정과의 관계

```text
아침 결정   레거시 데이터 적재(#1234)에서 누락 92코드·drift 43코드를 채울 때
            CSV(Notion) 값을 쓴다
지금 결정   가격·상품의 운영 정본은 현행 DB 다
```

**충돌이 아니다.** CSV 는 **이관을 마저 끝내는 원천**이고, 이관이 끝나면 **DB 가 정본**이다.
⟹ 적재 후에는 CSV 를 다시 보지 않는다. 원천 추종 구조를 만들 이유도 없다.

## ② 주문/견적 '완료' 상태와 일마감 통제 — **수동 각인·예외를 다시 넣는다**

```text
확정   레거시처럼 사람이 완료를 각인할 수 있고, 검증 예외를 고를 수 있게 한다
현행   상태 전이가 규칙으로만 일어나고 예외를 고를 버튼이 없다
```

### 🚩 구현 시 반드시

```text
🚨 누가 · 언제 · 왜 예외를 줬는지 남는다
   유연성을 여는 대신 추적이 없으면 금액 검증이 무력해진다
🚨 자동 전이를 없애는 것이 아니다 — 수동 각인이 그 위에 얹히는 것이다
🚨 일마감 가격검증 예외(할인제외 정액DC 0원 · 멀티 할인율 미적용)도 이 축이다
```

## ③ 배차·DPS 원천 — **배차는 우리 출고전표 DB · DPS 자료만 엑셀**

> *"배차는 우리 출고전표 DB를 가져오는거고 DPS관련 자료만 엑셀로 받기로 했잖아."*

```text
확정   배차 대상   우리 출고전표 DB 에서 가져온다 (외부 파일 아님)
       DPS 자료    엑셀 업로드로 받는다
```

🚩 **PM 의 질문 틀이 또 틀렸다.** 배차와 DPS 를 둘 다 외부 파일 기준으로 묶어 물었는데,
**배차 원천은 이미 우리 DB 다.** 외부 파일이 필요한 것은 DPS 쪽뿐이다.
