# 상세 새창 · 작성일 열 제거 · 전표 라인 입력 정리 (2026-08-14 개발책임자)

## 개발책임자 원문

> *"이미 전표번호 혹은 문서번호에 날짜가 있는데 굳이 **작성일 열이 중복**하여 들어갈 필요가 없잖아? 클로드가 **모든 메뉴 전수조사**하여 작성일이 따로 있으면 삭제 요청.
> 그리고 **전표번호 혹은 문서번호에 하이퍼링크로 상세 들어가기가 모두 된게 맞는지** 확인요청.
> **상세는 모두 새창**(우측 상단에는 전체창, 닫기 버튼 아이콘, 단 전체창인 경우 축소창)으로 열도록 변경이 필요함.
> 또한 전표의 경우 상세에서 **품목입력칸 사이 여백**이 있어야 하며, 여백 입력칸과 배지로 인해 줄바꿈되면서 입력칸 높이가 어긋나는 일이 있어 **배지는 삭제, 가장 우측 합계열도 삭제**."*

---

## 결정 1 — 작성일 열 제거

```
번호 안에 이미 날짜가 있다        2026/08/14-3
그런데 목록에 작성일 열이 또 있다   ⟹ 같은 정보가 두 번 나온다
```

**전수조사해서 작성일 열이 따로 있으면 삭제한다.**

🚩 **판정 기준은 "그 화면의 번호가 날짜를 품고 있는가" 다.**
번호에 날짜가 없는 화면(마스터 목록 등)의 날짜 열은 중복이 아니므로 **건드리지 않는다.**

🚩 PM 1차 실측 — 라벨이 여러 갈래다. 전수조사가 `작성일` 만 세면 놓친다.

```
작성일 28 · 일자 58 · 전표일 5 · 발행일 3 · 작성일자 2 · 등록일 1 · 생성일 1  (파일 수)
```

## 결정 2 — 번호 하이퍼링크 전수 확인

**전표번호·문서번호를 누르면 상세로 들어가는 것이 모든 화면에서 되는지** 확인한다.
안 되는 곳이 있으면 목록으로 보고한다.

🚩 `design-system` 에 `SlipNumberDisplay` · `OrderNumberDisplay` 가 있다. **그것을 쓰는 곳과 안 쓰는 곳**을 갈라야 누락이 보인다.

## 결정 3 — 상세는 **새 창**으로

```
대상   번호가 있는 문서의 상세
       입고전표 · 출고전표 · 회계전표(매출·매입) · 견적서 · 주문서
       세금계산서 · 이동전표 · 실사
🚫 제외  마스터 상세 (거래처 · 품목 · 직원 · 창고) — 그대로 둔다
```

### 창 우측 상단 컨트롤

```
평상시    [전체창]  [닫기]
전체창일 때 [축소창]  [닫기]
```

### 🚩 이 결정이 오늘 앞선 결정을 덮는다

```
2026-08-14 수불부 결정  "수불부를 닫고 전표 화면으로 이동한다 (새 창 ❌)"
                        ⟹ 폐기
지금                    수불부에서 전표번호를 눌러도 새 창으로 연다
```
🔑 규칙이 하나여야 사용자가 예측한다. 화면마다 다르면 그 자체가 결함이다.

## 결정 4 — 전표 상세 품목 입력줄 정리

```
필요   품목 입력칸 사이 여백
삭제   배지
삭제   가장 우측 합계열
```

🔑 **이유가 미관이 아니다.** 여백 입력칸과 배지 때문에 **줄바꿈이 일어나면서 입력칸 높이가 어긋난다.** 입력 중에 줄이 밀리면 값을 잘못 넣는다.

🚩 대상 컴포넌트 후보(PM 실측) — `LineRow` · `EstimateLineRow` · `JournalLineRow` (design-system).
🚨 **design-system 을 건드리면 Playwright mock 회귀 hard gate 가 걸린다.** 오늘 다른 트랙에서 그 게이트가 깨진 전례가 있다.

## 🔒 이 트랙이 지켜야 할 불변식

```
1  작성일 열을 지우면서 정렬·필터가 그 열에 의존하고 있었다면 그 기능이 죽는다
   🚨 지우기 전에 그 열을 쓰는 정렬·필터·엑셀 내보내기를 확인하라
2  번호 하이퍼링크가 새 창으로 바뀌어도 기존 이동 경로가 끊기지 않는다
   (뒤로 가기·딥링크·인쇄 미리보기 등)
3  새 창이 열려 있는 동안 목록 화면이 계속 쓰인다 — 목록이 잠기면 안 된다
4  합계열을 지워도 사용자가 합계를 확인할 방법이 남아 있다
   🚩 어디서 보여줄지 구현자가 정하고 근거를 대라. 그냥 없애면 정보가 사라진다
5  배지가 담고 있던 정보가 무엇이었는지 확인하고, 필요하면 다른 자리에 남긴다
   🚨 배지를 그냥 지우면 그 정보가 통째로 사라진다
```

## ⏳ 정찰이 답해야 할 것

```
① 작성일 열이 있는 화면 전수 (라벨 변형 포함) · 각각 번호에 날짜가 있는가
② 번호 하이퍼링크가 되는 화면 / 안 되는 화면 목록
③ 현재 상세가 열리는 방식 — 페이지 이동 / 모달 / 새 창 각각 몇 개인가
④ 라인 입력줄의 배지가 무엇을 표시하는가 · 합계열이 무엇을 보여주는가
⑤ 새 창 컨트롤을 이미 가진 화면이 있는가 (메신저 방 창 등 참고 구현)
```

## 결정 5 — 인쇄 증빙의 작성일·발행일은 **그대로 둔다**

```
목록 화면 (사내용)    번호에 날짜가 있으니 작성일 열은 중복 ⟹ 지운다
인쇄 증빙 (외부 제출)  세금계산서 공급일·발행일 · 거래명세서 작성일 · 출고문서 작성일
                      ⟹ 손대지 않는다
```

🔑 **세무상 의미를 가질 수 있고, 외부로 나가는 문서라 되돌리기 어렵다.**
🚩 회계 보고서의 `작성일` 은 **문서번호가 없어 애초에 중복이 아니므로** 유지 (정찰 §①-D 와 동일).

## 결정 6 — 번호와 열의 날짜가 **같다고 보장되지 않으면 유지**

```
견적 통합/출처별 탭 — 웹 원천 행
  documentLabel 이 외부 값이라 날짜 포함이 보장되지 않는다
  🚩 자체 견적·주문과 한 열을 공유해 행별 숨김도 불가

아로로지스 배차 대조 (삼한 내 화면 포함 2개)
  열은 dispatchDate — 전표번호 날짜와 항상 같다는 확인이 안 됐다

재고수불부
  입출고·이동·실사·전일재고·합계가 한 표에 혼합
  🚩 번호 없는 합계행이 있어 열 자체는 남아야 한다
```

🔑 **중복이 아닌 것을 지우면 정보가 사라진다.** 불변식이 확인되지 않으면 유지가 안전하다.
⟹ 정찰이 분류한 **확정 삭제 16표면**만 지운다. 미결 6표면 중 인쇄 2건은 결정 5, 나머지 4건은 이 결정으로 **전부 유지**.

## 결정 7 — 디자인 미결 3건을 **이 트랙에 묶는다**

```
① 클로드 세션 목록 상단이 크고 짙은 단색 배너 — 카카오톡 기준 미달
② 본체 데스크톱 채팅 화면이 방 이름 없이 "채팅방" 만 반복되는 원시 목록
③ 업데이트 배너의 제목과 본문 첫 문장이 그대로 겹침
```

🔑 어차피 같은 화면들을 만지는 트랙이다. 상세 새창·라인 입력 정리와 함께 다룬다.
