## 결정 1 — `#901` 클로드 대화: **되돌릴 수 없는 작업까지 허용 · 별도 확인 절차**

이슈 본문이 이 기능을 *"편의 기능이 아니라 **보안 경계 기능**"* 으로 규정하고, 착수 전 정책 확정을 요구했습니다.

### 🔴 결정

> **조회 · 변경(생성/수정)에 더해 되돌릴 수 없는 작업(승인 · 발행 · 삭제)까지 허용한다.**
> **단, 되돌릴 수 없는 작업은 실행 전 사용자 확인 절차를 거친다.**

### 🚨 PM 이 올린 위험 — 개발책임자가 확인 후 선택

```
확인 절차가 뚫리는 경로가 하나라도 생기면
세금계산서 발행 · 전표 승인 · 삭제가 되돌려지지 않는다
```

⟹ 이 트랙은 **확인 절차 자체가 게이트**입니다. 기능이 되는 것보다 **우회 경로가 0인 것**이 머지 조건입니다.

### 🔴🔴 개발책임자 추가 지시 — **권한이 이 트랙의 전부다**

> *"901은 **권한에 따른 동작 허용 범위도 달라지므로** 권한에 대한 내용은 **절대 뚫리지 않도록** 주의요망"*

⟹ *"되돌릴 수 없는 작업까지 허용"* 은 **무조건 허용이 아닙니다.** 축이 둘로 겹칩니다.

```
축 1  로그인 계정의 권한          그 계정이 원래 할 수 있는 것만
축 2  작업의 되돌릴 수 있음 여부   되돌릴 수 없으면 추가로 사용자 확인

⟹ 클로드가 할 수 있는 것 = (축 1 ∩ 축 2)
   🚨 축 1 을 넘는 순간 권한 체계 전체가 우회된다 — 이건 기능 결함이 아니라 보안 사고다
```

**예**: 세금계산서 발행 권한이 없는 계정이 클로드에게 시켜서 발행되면 **안 됩니다.** 확인 절차를 통과해도 안 됩니다. 확인 절차는 축 2 의 장치이지 축 1 을 대신하지 않습니다.

### 🔴 축이 하나 더 있습니다 — **클로드 사용 자체가 권한이다**

> 개발책임자: *"클로드 사용허용도 **마스터가 권한설정 메뉴에서 토글로 설정 가능**(개인별, 그룹별 모두)"*

```
축 0  클로드를 쓸 수 있는가        마스터가 권한설정 메뉴에서 토글로 부여
                                   개인별 · 그룹별 둘 다 설정 가능
축 1  그 계정의 업무 권한           클로드는 이걸 절대 넘지 않는다
축 2  되돌릴 수 있는 작업인가        되돌릴 수 없으면 추가로 사용자 확인

⟹ 클로드가 할 수 있는 것 = 축 0 이 켜져 있고 · (축 1 ∩ 축 2)
```

🔑 **축 0 이 꺼진 계정은 대화 진입 자체가 막혀야 합니다.** 화면만 숨기는 것이 아니라 **서버가 거부**해야 합니다 — 화면 숨김은 권한이 아닙니다.

🔑 **기존 권한 체계 안에 넣습니다.** 클로드용 별도 권한 저장소·별도 토글 체계를 새로 만들지 마십시오. 지금 쓰는 권한설정 메뉴의 개인별·그룹별 축을 그대로 씁니다.

### 🚨 그래서 이 트랙의 머지 게이트는 "권한 우회 경로 0" 입니다

```
🔑 기능이 되는 것보다 우회 경로가 0 인 것이 조건이다
🔑 권한 계약 테스트는 "포함하는가" 가 아니라 정확한 비트로 단언한다
   → feedback_permission_contract_needs_exact_bits
🔑 enforcement 는 실 HTTP 로 회귀 검증한다 — mock 으로 통과시키지 않는다
   → feedback_enforcement_real_http_test
🚨 권한별 매트릭스를 전수로 밟는다 — 역할 하나가 빠지면 그 역할이 구멍이다
```

### 설계 제약 (이슈 본문 + 이 결정)

```
① 권한 강제 위치   클로드의 도구 호출은 반드시 기존 BE 엔드포인트를 그대로 통과한다
                   권한은 서버 권위(@RequirePermission 등)로 강제
                   🚫 DB 직접 접근 · 권한 우회 내부 경로를 주지 않는다
                   🚫 클로드 전용 엔드포인트를 새로 만들지 않는다
                      (새로 만드는 순간 그것이 우회 경로가 된다)
② 확인 절차        되돌릴 수 없는 작업은 실행 전 사용자 확인. 우회 경로 0
                   🚨 확인 절차는 축 1(계정 권한)을 대신하지 않는다
③ 감사 로그        모든 작업의 주체·시각·대상 기록. 🔑 사람이 한 것과 구분 가능해야 한다
④ UUID 비노출      대화 응답에도 내부 식별자가 새지 않는다
                   → docs/decisions/2026-08-13-uuid-never-exposed.md
```

### 🔴 결정

> **릴리스 바이너리를 사내 서버에 올리고 자체 서명서를 쓴다.**

```
✅ 비용 0 · 외부 의존 0
⚠️ Windows SmartScreen 경고가 뜬다 — 사내 배포라 감수
```

### 🚩 착수 전 반드시 실측할 것

```
electron-updater 가 서명 검증을 요구하는 경로가 있는지 먼저 확인한다.
자체서명으로 자동 설치가 막히면 이 결정의 전제가 무너진다.
⟹ 전제가 어긋나면 고치지 말고 중단·보고할 것
```

이 결정으로 게이트 ③ 의 마지막 구간(**실제 릴리스 감지 → 바이너리 다운로드 → 즉시 설치/다운그레이드**)을 밟을 수 있게 됩니다. 그 전까지는 `docs/decisions/2026-08-13-credential-rotation-and-1181-gate.md` 의 *"관측 상한까지 인정"* 이 유효합니다.
