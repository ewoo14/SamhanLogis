# `#999` QR 수명주기 정정 — 별도 메뉴가 아니라 업무 흐름 안으로 (2026-08-14 개발책임자)

> 앞선 결정: [`2026-08-14-qr-scan-inout-decisions.md`](2026-08-14-qr-scan-inout-decisions.md)
> 트랙: `#1210`

---

## 개발책임자 원문

> *"입출고 시 QR을 따로 생성할게 아니라 **입고를 잡으면 재고 인스턴스가 생성되면서 자동으로 일괄** 실내기, 실외기, 판넬 들은 QR이 각자 생성되고, 출고 시에는 창고에서 **출고전표 내부에서 출고 처리**(대부분 휴대폰 카메라 혹은 휴대폰과 연결된 스캐너 장치 사용) 진행할 수 있어야 하는데? **메뉴는 따로 필요없어.**"*

---

## 🚩 무엇이 뒤집혔나

```
이전 설계  독립 메뉴 "QR 스캔 입출고" 를 만든다
           그 안에서 전표를 고르고 → 스캔하고 → 확정한다
           QR 발행은 별도 화면에서 한다

정정 설계  QR 발행    입고를 잡는 순간 자동으로 일괄 생성된다 (화면 없음)
           출고 스캔  출고전표 화면 안에서 한다 (메뉴 없음)
```

🔑 **QR 은 사용자가 따로 하는 일이 아니라, 하던 일에 딸려 오는 것이다.**

---

## 결정 1 — QR 발행은 **입고 시 자동 · 일괄**

```
입고를 잡는다
  → 재고 인스턴스가 생성된다              (기존 동작)
  → 실외기 · 실내기 · 판넬 인스턴스마다 QR 이 자동 생성된다   ← 신규
  → 부자재는 생성되지 않는다 (batch 관리라 개체를 특정할 수 없다)
```

🚫 **QR 발행 화면을 만들지 않는다.** 사람이 발행 버튼을 누르는 단계가 없다.
🔑 QR 내용은 이전 결정 그대로 — **시리얼키 + 품목코드**, UUID 미포함.

## 결정 2 — 출고 스캔은 **출고전표 화면 안에서**

```
창고 담당자가 출고전표를 연다
  → 그 전표 안에서 바로 스캔한다
  → 휴대폰 카메라 또는 휴대폰에 연결된 스캐너 장치 (대부분)
  → 그 자리에서 출고 처리까지 끝낸다
```

🚫 **독립 스캔 메뉴를 만들지 않는다.** `/inventory/qr-scan` 라우트와 메뉴 항목을 제거한다.

### 🔑 이 정정이 없애 버리는 결함이 하나 있다

직전 적대검증이 찾은 **결함 3**(재고원 계정이 전표를 못 고름 · `GET /slips` 403)은 **설계가 바뀌면서 사라진다.**

```
이전  독립 화면에서 전표를 "고른다"  ⟹ 전표 목록 조회 권한이 필요했다
정정  이미 연 출고전표 "안에서" 스캔한다  ⟹ 고르는 단계 자체가 없다
```

🚩 **권한을 넓혀서 푸는 것이 아니라 넓힐 필요를 없앤 것**이라 더 안전하다. 재고원에게 매출전표 열람 권한을 주는 fix 를 하지 않아도 된다.

## 결정 3 — 입력 기기: **휴대폰 우선**

```
주    휴대폰 카메라
      휴대폰에 연결된 스캐너 장치
부    데스크톱 출고전표 화면 (연결된 USB 스캐너)
```

🔑 **서버 계약은 여전히 하나다** — 이전 결정이 세운 형태를 그대로 쓴다.

```
{ slipNo, items: [{ serialKey, productCode }] }
```

입력 경로가 늘어도 서버가 갈라지지 않는다. 이 부분은 뒤집히지 않았다.

## 살아남는 것 / 버리는 것

| 이전 결정 | 상태 |
|---|---|
| 대상 = 실외기 · 실내기 · 판넬 (부자재 제외) | ✅ 유지 |
| QR 내용 = 시리얼키 + 품목코드 · UUID 미포함 | ✅ 유지 |
| 전표 귀속 스캔만 허용 | ✅ 유지 — 오히려 더 강해졌다 (전표 밖에서 스캔할 화면 자체가 없다) |
| 서버 계약 `{ slipNo, items[] }` | ✅ 유지 |
| 전부 되거나 전부 취소 | ✅ 유지 |
| 거부 사유를 사람이 읽을 수 있게 | ✅ 유지 |
| **독립 메뉴 "QR 스캔 입출고"** | ❌ **폐기** |
| **화면 안에서 전표를 고르는 드롭다운** | ❌ **폐기** — 이미 연 전표가 문맥이다 |
| 데스크톱 USB 스캐너를 주 경로로 | 🔄 **부 경로로 강등** — 휴대폰이 주 |

## 🚩 라벨 지시 2건은 어떻게 되나

개발책임자가 지시한 `동작 → 구분` · `전표 → 전표번호` 는 **폐기되는 독립 화면의 라벨**이었다.
전표 안으로 들어가면 그 두 컨트롤은 사라진다(구분은 출고로 고정, 전표번호는 이미 그 전표다).
🔑 **그래도 용어 규칙 자체는 살아 있다** — 새로 만드는 전표 내 스캔 영역에서 전표를 지칭할 일이 있으면 `전표번호` 로 쓴다.

```

② 입고 이전에 이미 만들어진 기존 인스턴스들의 QR 은 어떻게 하는가
   (소급 생성이 필요한가, 필요하면 언제)
③ 입고 스캔 — 이번 원문은 "출고 시 전표 내부 스캔" 만 말했다
   입고 검수 단계의 스캔도 같은 방식(입고전표 내부)으로 두는가
```
