## 개발책임자 원문

> *"가입고처리는 xlsx 파일을 레거시처럼 그대로 인식하여 이를 입고전표(현재 2개의 창고만 지정)로 자동생성하는 시스템이야. 완전한 구현이 필요해."*

## 확정 3건 (2026-08-15)

정찰에서 **"확인 불가"** 로 남았던 것들이다. 레거시 코드에도 없고 업무 지식이라 추론하지 않고 확인받았다.

### ① 거래처 — 고정 `1248100998` 그대로

```text
레거시   이카운트 payload 의 CUST 를 모든 행에 "1248100998" 로 고정
확정     우리 입고전표도 이 거래처 하나를 쓴다
🚩 선행 작업 — 이 코드가 우리 거래처 마스터의 어느 곳인지 먼저 찾아 연결해야 한다
   못 찾으면 그것 자체가 보고 대상이다. 임의로 만들지 않는다
```

### ② 단가 — `0`

```text
레거시   BulkDatas 에 금액·단가 필드가 없다. QTY 만 보낸다
현재     CreateSlipRequest 의 라인은 unitPrice 가 필수 (0 이상)
확정     0 으로 넣는다
🔑 가입고는 매입가가 확정되지 않은 단계다. 레거시가 단가를 안 보낸 것과 뜻이 같다
```

### ④ 🚨 1WAY 규칙은 가입고가 아니다 (2026-08-15 개발책임자 정정)

> *"가입고는 창고대로 입고시키는거고, 너가말한 품목에 따라 창고지정되는 것은 거래처에서 주문서웹으로 주문서를 발송했을때야."*

```text
가입고        파일의 고객명(=창고 이름)대로 입고한다. 그게 전부다
              삼성창고·초월창고 → 00003 초월 / 이화·상일 → 2 상일
🚫 품목(모델)으로 창고를 바꾸지 않는다

1WAY 규칙     거래처가 주문서웹으로 주문서를 보냈을 때 쓰는 규칙이다
              🚩 가입고 트랙(#1225)의 범위가 아니다
```

🚩 **관측 사실 하나만 남깁니다.** 레거시 `가입고처리/Index.html:436` 에는
`if(rawM.toUpperCase().includes('1WAY')) { wh = '2'; … }` 가 실제로 들어 있습니다.
업무상 가입고의 규칙이 아니라는 것이 개발책임자 판단이므로 **우리 구현에서는 뺍니다.**
(레거시 프로그램이 그 규칙을 왜 갖고 있었는지는 이 트랙에서 따지지 않습니다.)

## 레거시 계약 (정찰 확정 — 원문 인용은 보고서에)

```text
파일 읽기   모든 시트 순회 · 1~5행 건너뜀 · 6·7행 2단 헤더 · 8행부터 데이터
            행 6개 미만 시트는 건너뜀
시트 채택   고객명·주문번호 헤더가 둘 다 있을 때만 (나머지 9열은 선택)
행 필터     고객명에 삼성·초월·이화·상일·신인호·삼한 중 하나가 포함될 때만
시트 상쇄   고객명|모델|주문|차량번호|기사명|주문일자|주문번호 가 같은 행은
            먼저 나온 시트 것만 남기고 이후 시트 것은 건너뜀
창고        삼성창고·초월창고 → 00003 초월 / 이화창고·상일물류·상일창고 → 2 상일
            그 외 대상 고객명 → 2 상일
수량        물류출고 → 없으면 주문 → 그래도 없으면 0 · Math.round
품목명      [...] (...) 제거 후 trim · GHP 포함 시 "가스히트펌프" 로 치환
품목 매핑   ① 정제 품목명 완전일치 또는 코드 완전일치
            ② 품목명 상호 부분포함
            ③ 원본 모델의 첫 공백 전 token 과 품목코드 일치
            ④ 모두 실패 → '검색실패' 로 표시하고 정제 모델명을 코드처럼 보존
```
