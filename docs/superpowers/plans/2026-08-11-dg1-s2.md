# D-G1 S2 요율 계약·정산 계산기 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 레거시 영업수수료 산식과 versioned 요율 계약을 accounting-service에 BigDecimal snapshot 구조로 추가한다.

**Architecture:** 불변에 가까운 요율 계약 entity가 버전별 비율을 보관하고, 순수 계산기가 계약과 입력을 받아 결과 snapshot을 만든다. 정산 aggregate는 계약 FK와 입력·결과 snapshot을 도메인 체인 메서드로 기록한다.

**Tech Stack:** Java 21, Spring Boot, Spring Data JPA, PostgreSQL, Flyway, JUnit 5, AssertJ, BigDecimal.

## Global Constraints

- 레거시 공식은 `tools/legacy-gas/영업수수료 계산/Index.html:262-340`의 원문과 동일한 순서를 사용한다.
- `xround`는 원 단위 `HALF_UP`이며 부호 대칭(tie away from zero)이다.
- 금액과 요율 계산에는 double을 사용하지 않는다.
- 요율 변경은 기존 계약 수정이 아니라 새 version row 생성으로만 표현한다.
- S1 채번·확정 동작과 기존 조달·카드·영업·판매 수수료 4행의 경로를 변경하지 않는다.
- S3 그룹웨어, S4 화면·버튼, D-G7 기준일 잠금·확정 취소는 구현하지 않는다.
- Flyway 번호는 accounting-service 최대 V97 다음인 V98이다.
- V98은 기본 계약 버전 1(0.03, 0.08, 0.033, 0.08)을 seed한다.
- 새 entity는 BaseEntity 7 audit와 soft delete를 사용한다.
- git 조작, 공유 DB write, 배포는 하지 않는다.
