# #1092 Slice 2 Owner Axis Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 견적서의 `requester_id`를 변경 가능한 담당으로 사용하고, 웹 자기범위 조회/복원과 데스크톱 전체 조회를 표면별로 분리하며, 작성 감사 기록(`created_by`)을 보존한다.

**Architecture:** `slip-service`가 견적 담당 필터와 담당 변경을 서비스 도메인에서 강제한다. 데스크톱은 기존 전체 목록 계약을 사용하고, 웹 표면은 caller identity가 주입되는 assigned-only 계약을 사용한다. 담당 변경은 견적 aggregate의 `requesterId`만 변경하는 전용 API로 제한하며 주문서 계열 endpoint를 호출하거나 교차 변경할 수 있는 입력을 제공하지 않는다.

**Tech Stack:** Spring Boot/JPA/AssertJ/MockMvc, React/TypeScript/Vitest, PowerShell 검증.

## Global Constraints

- `requester_id`를 담당으로 사용하고 새 컬럼을 만들지 않는다.
- `created_by`는 담당 변경 전후 불변이다.
- 역할(MASTER/MANAGER)로 조회 범위를 분기하지 않고 표면 계약으로 분기한다.
- 화면에는 UUID를 노출하지 않는다. 담당 라벨은 `담당`, 기존 감사 열은 `작성자`를 유지한다.
- snapshot 승격·판매전표 전환·주문서 생성·운임절삭 parity·웹 신규 화면은 범위 밖이다.
- DB 직접 INSERT/UPDATE/DELETE와 커밋/push, 공유 Docker 재기동을 하지 않는다.
