# #1068 fix4 R22 원장 정본 구현 계획

> **For agentic workers:** 이 계획은 현재 세션에서 inline으로 실행한다. 각 단계는 RED → GREEN → 회귀 검증 순서로 수행하며 git commit은 PM이 대행한다.

**Goal:** 거래처 원장의 전잔·후잔을 `PartnerLedgerContract.CANONICAL_SALE_STATUSES` 기준으로 계산하고, `Journal.journalNo == Slip.slipNo` exact match일 때만 분개와 slip projection을 한 번 세도록 fix3의 POSTED 정본을 R22로 되돌린다.

**Architecture:** slip-service의 판매 projection은 기존 공통 상태 집합을 그대로 사용한다. accounting-service는 projection의 canonical 상태만 `Effect.SALE`로 fold하고, `JournalSourceType.SLIP` 분개의 `journalNo`가 projection `slipNo`와 완전히 같을 때만 journal evidence를 제외한다. 금액·일자·거래처는 dedup 조건에 사용하지 않는다. 수작업·역분개·개시·번호가 다른 분개는 exact key가 없으므로 기존 collection contract를 통해 그대로 계산한다.

**Tech Stack:** Spring Boot/Java, JPA, shared common ledger contract, JUnit 5, Testcontainers PostgreSQL.

## Global Constraints

- 판매 상태는 새 목록을 만들지 않고 `PartnerLedgerContract.CANONICAL_SALE_STATUSES`를 직접 사용한다.
- 전잔 순서는 회계일자 + 전표번호 순이며, slip 번호가 아닌 분개는 같은 날 뒤로 정렬한다.
- dedup은 `JournalSourceType.SLIP`이고 `journalNo.equals(slipNo)`인 경우에만 허용한다.
- 금액·일자·거래처 추정 매칭과 새 컬럼/Flyway migration은 금지한다.
- public 응답에 UUID를 추가하지 않는다. 내부 partnerId는 기존 internal 조인 계약을 유지한다.
- 격리 Testcontainers PostgreSQL 실 왕복 IT를 추가하고, mock은 외부 client에만 사용한다.
- 라이브 QA 스펙 디렉터리와 파일명은 모두 `-real-qa`를 사용하며 캡처는 `resolveQaShotsDir()`를 경유한다.
- TC-V3 payload mutation RED, 자동채움/장애 fail-open/원장 fingerprint 회귀를 보존한다.
- git add/commit/push/merge는 수행하지 않는다.

- journal evidence 생성은 `Set<String> canonicalSlipKeys`에 있는 exact `journalNo`와 `JournalSourceType.SLIP`만 제외한다.

- [ ] **Step 1: projection canonical 상태 판정 구현**

  `PartnerLedgerContract.CANONICAL_SALE_STATUSES.contains(sale.status())`를 사용해 status 밖/CANCELED/DRAFT projection을 `Effect.NONE`으로 유지하고, canonical projection만 `Effect.SALE`로 만든다. 상태 목록을 service에 복제하지 않는다.

- [ ] **Step 2: exact key 집합 생성 및 journal evidence 제외 구현**

  기간 sales와 target sale에서 canonical projection의 nonblank `slipNo`만 exact key 집합으로 만든다. `journalDocumentsFromContract`와 `openingBalances`에 전달한다. `journalEvidence`는 `journal.getSourceType() == JournalSourceType.SLIP`이고 `canonicalSlipKeys.contains(journal.getJournalNo())`일 때만 해당 bundle을 제외한다. sourceRefId, amount, date, partnerId는 dedup에 사용하지 않는다.

- [ ] **Step 3: 전잔·후잔 순서와 no-slip 뒤 정렬 구현**

  기존 target 전잔 판정의 회계일자 + exact event number 규칙을 보존한다. 표시 문서 comparator는 `yyyy/MM/dd-N` suffix가 있는 slip document를 먼저 numeric order로 정렬하고, 번호 없는 journal/payment/adjustment를 당일 뒤로 보낸다. 번호가 없는 persisted Journal은 `journalNo` blank가 불가능하므로 sourceType이 SLIP이 아닌 문서를 매칭하지 않는다.
