# 전표 명칭 통일 A Implementation Plan

> **For agentic workers:** A 단계만 실행한다. B 배송태그 변경은 이 계획의 범위 밖이다.

**Goal:** 사용자에게 보이는 구매전표·판매전표 명칭을 입고전표·출고전표로 통일한다.

**Architecture:** 표시 문구만 변경하고 내부 계약은 보존한다. page-code, URL/API 경로, DB 컬럼·테이블, enum·코드 식별자는 검색 보호 목록으로 확인한다.

**Tech Stack:** TypeScript/React desktop client, Java Spring services, Markdown/HTML print templates, existing unit/integration tests.

**Spec:** `docs/decisions/2026-08-14-slip-naming-and-delivery-tag-redesign.md`

## Global Constraints

- `purchases.slip.*`, `accounting.sales-slip.*`, `accounting.purchase-slip.*` 등 page-code는 변경하지 않는다.
- URL 경로, API 경로, DB 컬럼·테이블, enum 이름, 저장 코드값은 변경하지 않는다.
- 사용자 표시 문구, 인쇄물, 엑셀 헤더, 테스트 기대 문자열은 새 명칭으로 변경한다.
- 배송태그·QR·마감시각·마이그레이션은 A 단계에서 변경하지 않는다.
- A를 완전히 검증하고 보고한 뒤에만 B를 시작한다.

### Task 1: 표시 문자열 전수 분류

**Files:**
- Inspect only: repository files returned by `rg` for `구매전표`, `판매전표`, `구매 전표`, `판매 전표`, `매입전표`, `매출전표`

- [ ] Search source, tests, print/export templates, manuals, and current operational docs.
- [ ] Exclude historical decision/QA evidence where changing recorded evidence would falsify history.
- [ ] Classify each match as user-visible text, test expectation, or protected internal identifier.
- [ ] Record protected matches for the A report.

### Task 2: Write failing protection test

**Files:**
- Test: existing permission/page-code contract tests selected from the scan

- [ ] Add or extend an assertion that protected page-code values remain unchanged.
- [ ] Run the focused test and verify the new assertion fails before the replacement is applied.

### Task 3: Apply A-only replacements

**Files:**
- Modify: classified user-visible source, test, print, export, and current documentation files

- [ ] Replace `구매전표`/`구매 전표` and visible synonyms with `입고전표`/`입고 전표`.
- [ ] Replace `판매전표`/`판매 전표` and visible synonyms with `출고전표`/`출고 전표`.
- [ ] Leave protected page-code, URLs, API paths, DB names, enum names, and code identifiers unchanged.
- [ ] Do not touch delivery-tag policy, QR behavior, cutoff rows, or migrations.

### Task 4: Verify A

**Files:**
- Inspect: all modified files and focused test reports

- [ ] Re-run the phrase scan and classify every remaining old phrase as protected or historical evidence.
- [ ] Run focused client/service tests, then relevant builds using the repository’s Windows path guidance.
- [ ] Check the changed-file boundary to ensure no B or migration files are present.
- [ ] Report A with changed/retained table, protected-key evidence, tests, and remaining unobservable checks.
