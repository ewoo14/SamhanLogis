# PR #965 SOL2 Image Decodability Fix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ensure undecodable document-template images never paint broken-image fallback content on screen or print, while every warning maps to a visible editor key, follows canvas order, and reflects the current draft after edits.

**Architecture:** Keep decode validation at the existing `RenderedImageElement` boundary. An image remains paint-suppressed until `HTMLImageElement.decode()` succeeds and becomes a non-rendering placeholder after failure; the warning reporter remains keyed by element key and the renderer sorts its state by the current template order. The editor exposes the same key in each canvas row and inspector, and re-runs the existing `findUndecodableImages` preflight whenever the current image identity/source changes.

**Tech Stack:** React 18, TypeScript, Vitest, Testing Library, Playwright, Chromium print media, xpdf 4.06, pypdf/pdfplumber.
