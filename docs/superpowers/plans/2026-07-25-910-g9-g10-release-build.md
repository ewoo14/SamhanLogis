# G9/G10 릴리스 빌드 경로 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 데스크톱과 Expo 릴리스 명령이 명시 버전 없이 `0.1.0-dev` 산출물을 만들지 않도록 릴리스 모드와 버전 주입을 실제 경로에 고정한다.

**Architecture:** 데스크톱 `build:win`은 공통 버전 resolver를 릴리스 모드로 호출하는 Node wrapper를 거쳐 모든 하위 빌드 프로세스에 `SAMHAN_RELEASE_BUILD=1`과 검증된 `VITE_APP_VERSION`을 전파한다. 개발·CI 명령은 기존 resolver의 고정 sentinel 경로를 유지한다. Expo preview/production EAS 프로파일은 `EXPO_PUBLIC_APP_VERSION`을 외부 주입값으로 요구하도록 계약과 문서를 명확히 한다.

**Tech Stack:** Node.js CommonJS build scripts, npm scripts, Expo EAS JSON profiles, Node test runner, Electron Vite, electron-builder.

## Global Constraints

- `npm run dev`, `npm run build`, `build:web`, `build:capacitor`, 개발 Expo config는 무주입으로 계속 성공해야 한다.
- 릴리스 산출물은 `YYYY/MM/DD-{번호}` 명시 주입 없이는 실패해야 하며 `0.1.0-dev`를 배포 가능한 산출물로 만들면 안 된다.
- 빌드 호스트 날짜·시계로 버전을 자동 생성하지 않는다.
- F-1~F-5, A1~A5, W-1~W-4를 회귀시키지 않는다.
- Git 쓰기, GitHub 쓰기, 공유 `dashboard_db` 쓰기, `docs/qa/**` 덮어쓰기를 하지 않는다.
- 주석은 한국어로 작성한다.
