# #913 + #890 검증품질 이월 구현 계획

> **작업자 주의:** 이 계획은 현재 워크트리에서 실행한다. Git add/commit/push/checkout/branch/stash는 금지한다. 각 단계는 RED 원문을 먼저 확보하고 수정 후 GREEN을 확인한다.

**목표:** #913-1의 실 QA 정리 오염을 run 단위로 격리하고, #913-2~4 및 #890-2~6의 테스트·mock·DB 방어선이 실제 보호 대상을 검사하도록 만든다.

**구조:** 실 QA 스펙은 공통 run scope와 exact-match 정리를 사용한다. 정상 종료·timeout·강제 종료에도 소유 run만 회수하도록 detached worker를 두고, DB pin 방어는 적용된 V13을 그대로 둔 채 신규 V14에서 APPROVED legacy 미pin도 차단한다. FE/BE/mock/IT는 각각 공개 계약과 실제 렌더·디코드 경로를 직접 통과하는 회귀 테스트로 닫는다.

**기술 스택:** TypeScript/Vitest/Playwright, Java/JUnit 5/Spring MockMvc/Testcontainers, PostgreSQL PL/pgSQL/Flyway, Node.js cleanup worker.

## 전역 제약

- 적용된 Flyway V13 파일은 수정하지 않는다. V14만 신규 추가한다.
- 모든 실 DB throwaway 이름은 프로세스·시각·UUID를 포함한 run 고유 식별자를 사용한다.
- 정리 대상은 exact name 또는 exact run token으로만 선택한다. 범용 `startsWith('DS4 실서버QA')` 삭제를 남기지 않는다.
- 공유 DB SQL은 `docker cp`+`psql -f` 또는 `psql -c`로 실행하고 정리 후 행 수를 다시 센다.
- 보고서·문서·주석은 한국어로 작성한다.
- 로컬 전체 스위트는 실행하지 않는다. 직접 관련 테스트만 실행한다.
