# #902 라운드 fix E-1·E-2 구현 계획

> **For agentic workers:** 이 세션에서는 사용자 지시에 따라 파일만 수정하며 git 쓰기(add/commit/push/checkout/stash/reset)는 수행하지 않는다.

**Goal:** 현재 금액 입력 정책과 정합하도록 E-1 회귀 스펙을 복구하고, authoritative 금액 전표의 수정 화면 단가 라벨과 무수정 재저장 왕복을 사실대로 보장한다.

**Architecture:** 금액 입력 스펙은 편집 가능한 단가·공급가액·부가세와 읽기 전용 합계를 분리해 검증한다. 수정 화면은 정상 전표의 VAT 제외 단가 계약을 유지하되, 입력 단가를 두 컬럼에 보존한 authoritative 라인은 VAT 포함 라벨을 행 단위로 표시하고 그 의미를 판정하는 순수 helper를 테스트한다. 라이브 QA는 `dev_manager`로 throwaway 전표를 생성하고 마지막에 soft-delete한다.

**Tech Stack:** React + TypeScript, Vitest, Playwright real QA, Spring Boot/Gradle slip-service, PostgreSQL Docker.

## Global Constraints

- 한국어 보고 및 한국어 주석을 사용한다.
- git 쓰기와 GitHub 쓰기를 하지 않는다.
- `EstimateFormPage.tsx`, 공용 `editLineVat`/`recalculateLineVat`는 수정하지 않는다.
- 합계는 read-only `<span>`/표시 요소이며 직접 입력 대상이 아니다.
- `2.7`, `-3`, `1e3`, `1,,2` 같은 잘못된 금액·수량 문자열은 거부하고 재조합하지 않는다.
- 정상 전표의 VAT 제외 단가 라벨/값과 견적·전표상세 기존 계약을 보존한다.
- 라이브 전표는 throwaway로 만들고 soft-delete하며 생성 전·생성 직후·정리 후 활성 건수를 기록한다.
