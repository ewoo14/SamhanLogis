**Goal:** PR #1131의 Desktop 타입/Playwright/하네스 실패와 slip-service 3개 테스트 실패를 원인에 맞게 고치고 전체 `slip-service` 테스트 결과를 문서화한다.

**Architecture:** R10의 `instanceKey` 백엔드 계약을 정본으로 유지한다. 구 리비전 복원은 저장된 구 스냅샷을 추측해 재키잉하지 않고, 후속 매출 편집 경계의 `BundleLineageResolver.materializeLegacyInstanceKeys`가 keyless legacy 데이터를 현재 편집 계약으로 승격하는 동작을 고정한다. QA 증거 쓰기는 `resolveQaShotsDir`를 통과시켜 커밋 증거와 실행 중 로컬 산출물을 분리한다.

**Tech Stack:** Java 21, Spring Boot, PostgreSQL Testcontainers, Gradle, TypeScript, React, Playwright, Vitest.

## Global Constraints

- 백엔드 `BundleSetOptions.instanceKey` 계약을 변경하지 않고 Desktop 타입을 맞춘다.
- ②-A의 빨간 테스트는 기대값을 먼저 수정하지 않고 원문·실패 지점·관련 도메인 테스트로 판정한다.

- 공유 DB에는 쓰지 않는다. 통합 테스트는 자체 Testcontainers로만 실행한다.
- fix 후 좁힌 범위가 아닌 전체 `slip-service` 테스트를 실행한다.
- git commit, branch, push, PR, deploy를 실행하지 않는다.
