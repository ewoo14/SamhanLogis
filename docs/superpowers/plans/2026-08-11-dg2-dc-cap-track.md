# D-G2 DC 상한을 주문서 48% 로 통일 — 트랙 개설

> 근거: `docs/dev-reports/2026-08-11-gas-sweep-devlead-decisions.md` (개발책임자 결정 D-G2)
> ⚠️ PM 은 A(문서별 현행 보존)를 권고했고, 개발책임자가 **B(48% 통일)** 를 선택했다.

## 결정

```text
견적서 49% / 주문서 48% 로 갈라져 있던 메인장비 부재 DC 상한을 48% 로 통일한다
효과   견적 → 주문 금액이 절대 바뀌지 않는다
대가   49% 로 이미 나간 견적과 소급 불일치
```

## 선행 측정 결과 (`2026-08-11-dg2-dg3-impact-measurement.md`)

```text
원시 48% 초과   3전표·3라인 — 전부 QA 산물
QA 제외 관측치  0건
🚩 그러나 **판정 불가** — 할인율 미보존 26라인 + 견적→주문 전환 표본 0건

후속 감사(2026-08-11-empty-key-columns-audit.md)
  26라인은 QA·LOADTEST·변환 probe 이고 금액 정합 26/26 — 할인율 유실이 아니다
```

⟹ **집PC 에서는 소급 영향 0건.** 다만 양 PC 시드가 다르므로 회사PC 재측정이 필요하다.

## 불변식

```text
1  clamp 값만 48 로 통일한다. 실외기 부재 페널티·티어 보너스 계산 자체는 건드리지 않는다
2  기존 행을 소급 변경하지 않는다 (48% 초과로 저장된 견적이 있으면 그대로 둔다)
3  견적과 주문이 같은 상한을 쓰는지 **한 곳에서** 정해야 한다 —
   두 곳에 48 을 각각 박으면 다음에 또 갈라진다
```
