## 3부 · 불변식 (구현 수단은 지시하지 않습니다)

| # | 불변식 |
|---|---|
| **C1** | **목록이 감싸는 폭 안에 들어온다.** 가로 스크롤 없이 노출 열 전부가 읽힌다 |
| **C2** | **목록에서 감춘 정보에 사용자가 도달할 수 있다.** 감춘 열의 값을 확인할 경로가 화면에 드러난다 |
| **C3** | 🚨 **좁은 폭에서 조작 버튼 컬럼이 도달 불가가 되지 않는다** — #880(PR #917 `2a1c3a076`)이 이미 고정한 불변식이다. **이 fix 가 그것을 깨면 안 된다** |
| **C4** | **인쇄·엑셀 내보내기는 전체 열을 유지한다.** 축소는 화면 표시에 한정된다 |
| **C5** | 조건부 표시가 이미 있는 열의 기존 규칙을 되돌리지 않는다 — `#918(#877)` 이 `BankTransactionPage` 의 `소스`·`매칭상태` 를 전체 탭에서만 보이도록 확정했다 |
| **C6** | 열이 줄어도 **정렬·필터·선택·일괄 조작이 그대로 동작**한다 |

### 📌 PM 결정 — 신규 모달을 만들지 않습니다
이슈는 *"상세 페이지 vs 모달 상세"* 를 착수 시 정하라고 합니다. **두 화면 모두 이미 상세 경로가 있으므로 기존 경로를 씁니다.** 신규 모달 신설은 표면을 넓히고(접근성·포커스 트랩·인쇄 경로) 수렴을 늦춥니다. 모달이 꼭 필요하다고 판단되면 **구현 전에 PR 코멘트로 근거를 올리십시오.**

### 📌 PM 제안 — "핵심 열" 선정은 업무 판단이라 개발책임자 확인 대상입니다
아래는 **PM 제안**이며, 개발책임자가 정정하시면 그대로 따릅니다. **이 확인을 기다리느라 착수를 미루지 않습니다** — 구현은 "열 집합을 한 곳에서 정의하고 바꿀 수 있게" 만들고, 실제 선정은 확인 후 조정합니다.

| 화면 | 목록에 남길 후보(제안) | 상세로 밀 후보(제안) |
|---|---|---|
| **입출금 내역** | 거래일 · 적요/거래처 · 입금 · 출금 · 잔액 · 매칭상태 | 소스 · 계좌 상세 · 원문 코드류 · 등록/수정 감사열 |
| **일일 마감** | 일자 · 구분 · 건수 · 금액 합계 · 마감상태 | 세부 분개 항목 · 계정별 소계 · 감사열 |

🔑 **"업무 사용 실태 기반"** 이 이슈의 기준입니다. PM 은 실 사용을 관측하지 못했으므로 위 제안은 **화면 의미 기반 추정**입니다. 개발책임자 정정이 진실원입니다.

## 4부 · 회귀 울타리 — 표면을 명시합니다

| 표면 | 울타리가 잡아야 하는 것 |
|---|---|
| 폭 | fix 후 `tableW ≤ wrapperW`. **숫자로 재십시오** — "좋아 보인다"는 근거가 아닙니다 |
| 도달성 | 감춘 열의 값이 상세에서 **실제로 보인다**(존재 확인이 아니라 값 대조) |
| #880 불변식 | 좁은 폭(모바일 포함)에서 **조작 버튼이 DOM 에 있고 클릭 가능**하다 |
| 인쇄·엑셀 | 전체 열 유지 — 내보낸 산출물의 열 수를 세십시오 |
| 조건부 표시 | `소스`·`매칭상태` 의 탭별 규칙 불변 |
| 목록 기능 | 정렬·필터·선택·일괄 조작 회귀 없음 |
| design-system | 🚨 공용 컴포넌트를 건드리면 **Playwright mock 스위트 필수**([feedback_design_system_playwright_mock_suite](../../../.claude/memory/feedback_design_system_playwright_mock_suite.md)) |

🚨 **RED-first**: 각 불변식을 깨는 실패 테스트를 먼저 쓰고 **RED 원문 제출 후** 고치십시오.
🚨 **QA 캡처는 `resolveQaShotsDir` 를 쓰십시오** — `clients/desktop/playwright/support/qa-screenshot-dir.ts`. 커밋된 캡처를 덮어쓰면 안 됩니다(이번 주 4회 발생).
