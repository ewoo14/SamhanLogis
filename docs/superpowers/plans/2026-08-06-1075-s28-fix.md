# S28 자동 규격 blur 저장 수정 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 품목 확정 후 blur가 자동 규격과 출처를 지우지 않도록 하고, 실제 저장·201 응답·재조회까지 규격 왕복을 보장한다.

**Architecture:** product-service의 기존 `ProductSummaryResponse.specification`을 slip-service의 `ProductSummary` wire DTO와 desktop lookup 타입에 연결한다. FE는 lookup 응답에 규격이 없더라도 기존 `CATALOG` 값을 blur로 삭제하지 않으며, 명시적 새 품목 선택 시에는 새 품목 응답을 기준으로 교체한다.

**Tech Stack:** React/TypeScript, Vitest, Spring Boot/Java, Gradle.

## Global Constraints

- `specification` 최대 길이 `@Size(max=50)` 유지.
- 자동 규격은 모델명 삭제 시에만 회수한다.
- 사용자 규격은 blur·저장·재조회·모델명 삭제 후에도 보존한다.
- `specification`과 `specificationSource`는 항상 한 쌍으로 유지한다.
- Docker 재빌드·재배포·DB 직접 쓰기·커밋은 하지 않는다.
