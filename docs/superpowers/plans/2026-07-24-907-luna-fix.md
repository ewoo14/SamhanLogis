> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 슬립 검색의 `%`·`_` 리터럴 회귀를 차단하고, Excel 다운로드 실패를 6개 다운로드 화면 모두에서 사용자에게 알린다.

**Architecture:** 검색어는 서비스 계층에서 임의로 변환하지 않고, `slip-service` native query의 조회·count 양쪽 `LIKE`에 동일한 backslash escape 계약을 적용한다. Excel 오류 표시는 공통 `ExcelDownloadError` 컴포넌트로 표준화하고, 기존 hook을 쓰지 않던 재고현황 화면도 같은 hook을 사용해 오류 상태 초기화·표시 계약을 공유한다.

**Tech Stack:** Spring Boot/JPA native PostgreSQL query, Java MockMvc + Testcontainers IT, React/TypeScript, Vitest + Testing Library, 지정 Playwright/실서버 QA.

### Task 1: 슬립 `%`·`_` literal 검색 회귀 고정

**Files:**
- Modify: `services/slip-service/src/test/java/com/samhanair/logis/slip/it/SlipQueryRedesignIT.java`
- Modify: `services/slip-service/src/main/java/com/samhanair/logis/slip/repository/SlipRepository.java`

**Interfaces:**
- Consumes: `GET /slips/query`의 `searchPartnerName` 파라미터와 기존 IT의 `createOutboundSlip` helper.
- Produces: `%`·`_`를 wildcard가 아닌 입력 문자로 해석하는 `searchIncludingDeleted` 조회·count 계약.

- [ ] **Step 1: Write the failing test**

  기존 `SlipQueryRedesignIT`에 `LUNA907R4`가 포함된 두 거래처를 만들고 `searchPartnerName=LUNA907R4%`, `searchPartnerName=LUNA907R4_`를 각각 조회한다. 각 조회는 특수문자가 포함된 행 1건만 반환해야 하며, 테스트의 `@Transactional` 격리로 테스트 종료 후 DB에 남기지 않는다.

- [ ] **Step 2: Run test to verify it fails**

  Run: `.\gradlew.bat :services:slip-service:test --tests com.samhanair.logis.slip.it.SlipQueryRedesignIT --no-daemon`
  Expected: RED — wildcard가 확장되어 각 조회가 2건 이상이고, assertion 원문을 기록한다.

- [ ] **Step 3: Write minimal implementation**

  `SlipRepository.searchIncludingDeleted`의 value/count query에서 6개 검색어 각각을 `REPLACE(REPLACE(REPLACE(CAST(:param AS varchar), '\\', '\\\\'), '%', '\\%'), '_', '\\_')`로 감싼 뒤 `LIKE ... ESCAPE '\\'`로 비교한다. 조회와 count query의 표현을 1:1로 맞춰 화면 total과 Excel export의 기반 결과가 어긋나지 않게 한다.

- [ ] **Step 4: Run test to verify it passes**

  같은 지정 Gradle 테스트를 실행하고 `%`·`_` 모두 1건 GREEN을 기록한다.

- [ ] **Step 5: Mutation RED and restoration**

  escape 계약을 구성하는 `ESCAPE` 한 줄을 임시로 되돌려 같은 테스트가 다시 RED인지 확인하고, 즉시 원복한 뒤 지정 테스트 GREEN을 재실행한다. `LUNA907R4` 잔존 여부는 SQL count 0으로 증명한다.
