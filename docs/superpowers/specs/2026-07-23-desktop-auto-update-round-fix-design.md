# PR #909 라운드 fix 설계 — 기동 자동 설치와 updater 오류 비공개

## 목표

데스크톱 앱이 로그인 화면을 렌더링하기 전에 실제 `window.samhanUpdater` 경로를 통과해 업데이트를 확인하고, 업데이트가 있으면 기동 중 자동 다운로드·설치·재시작을 수행하도록 한다. updater의 내부 오류 원문은 사용자 화면에서 제거하고 로그에만 남긴다.

## 불변식 해석

- B1: `AppRouter`를 `AppVersionGate`의 children으로 이동하고, 세션·`/app/version` 확인과 데스크톱 updater의 기동 판정이 끝날 때까지 children을 렌더링하지 않는다.
- B2: 기동 단계에서 `downloaded`를 받으면 사용자 버튼 없이 `install()`을 한 번 호출한다.
- B3: 일반 오류·오프라인·확인/다운로드 상한 초과는 로그인으로 fail-open한다. `CRITICAL`은 차단 모달을 유지한다.
- B4: 기동 gate가 열려 children이 렌더링된 뒤 도착한 `downloaded`에는 자동 설치하지 않는다.
- B5: 메인 프로세스는 원문을 로그로만 기록하고, 렌더러도 IPC 상태/예외를 단계별 고정 한국어 문구로 방어 정규화한다.
- B6: 기동 스플래시에 확인·다운로드 퍼센트·설치 위임 상태를 표시한다.
- B7: 확인은 30초, 다운로드는 180초의 유한 상한을 둔다. 상한 초과 시 진행 중인 updater 다운로드 자체는 취소하지 않고, 일반 수준은 로그인으로 전환한다.
- B8: 실 게이트웨이·실 렌더러에서 init script로 `samhanAuth`와 `samhanUpdater`를 모두 주입해 updater effect의 등록·check·status·install 경로를 관측한다.

## B7과 U1의 충돌 해소

U1을 “모든 느린 회선에서 로그인 전에 업데이트가 완료된다”로 해석하면 B7의 fail-open과 동시에 만족할 수 없다. 이번 구현은 다음의 안전 경계를 둔다.

1. 일반 수준은 상한 초과 뒤에도 메인 프로세스가 진행 중인 다운로드를 유지한다. 로그인은 허용하지만 이후 `downloaded` 상태를 표시하고, 사용 중에는 자동 재시작하지 않는다. 다음 기동에서 다시 확인한다.
2. `CRITICAL`은 상한 초과 뒤에도 로그인 children을 렌더링하지 않는다. 차단 모달은 “제한 시간 초과”, “다시 확인”, “앱 종료”, “관리자 문의”를 한국어로 제공한다. 다운로드가 늦게 완료되면 기동 자동 설치를 계속 시도한다.
3. 따라서 U1은 정상적으로 updater가 완료되는 경로와 `CRITICAL` 보호 경로에서 보장된다. B3가 명시한 일반 실패/오프라인 fail-open 경계에서는 절대 보장할 수 없으며, 이 한계를 보고서의 미해결 항목으로 남긴다.

## 시간 상한 근거

- 실제 게이트웨이 `/app/version` 8회 측정: 첫 cold 요청 2,117.9ms, 이후 6.18~10.01ms. 30초는 cold 측정의 약 14.2배다.
- 기존 실행 payload(`release/0.1.0/win-unpacked`) 실측: 301.67MiB, `resources/app.asar` 33.67MiB. 서명 설치본 생성은 범위 밖이라 NSIS 파일 자체는 생성하지 않는다.
- 동일 PC에서 Cloudflare 10MiB 스트림 3회 실측: 26.455/33.686/33.291MiB/s. 관측 최저 처리량으로 301.67MiB를 읽는 예상 시간은 약 11.4초이며, 180초는 그 15배 이상이다.
- 실제 사내 feed가 설정되지 않아 feed의 실제 installer `Content-Length`와 사내 WAN 처리량은 관측할 수 없다. 따라서 상한은 운영 성능 보장이 아니라 유한한 안전 상한이며, 실제 feed가 준비되면 재측정 대상이다.

## 사용자 문구와 로그 경계

사용자 문구에는 단계와 조치만 남긴다.

- 확인 실패: “업데이트 확인에 실패했습니다. 인터넷 연결을 확인한 뒤 다시 실행해 주세요.”
- 다운로드 실패: “업데이트를 다운로드하지 못했습니다. 인터넷 연결을 확인한 뒤 다시 실행해 주세요.”
- 확인/다운로드 상한 초과: “업데이트 확인 시간이 제한을 초과했습니다. 잠시 후 다시 확인해 주세요.” 또는 다운로드 단계 문구
- CRITICAL 차단: 위 문구와 함께 “다시 확인하거나 앱을 종료한 뒤 네트워크를 확인해 주세요. 계속되면 관리자에게 문의해 주세요.”

feed URL, `latest.yml`, HTTP headers, 응답 body, stack trace는 메인 로그의 `[auto-update]` 항목에만 기록한다.

## 테스트와 라이브 QA

RED-first로 메인 IPC 원문 노출, 렌더러 원문 노출, login 선렌더, 자동 install 누락, 상한 미해제를 각각 재현한다. 수정 후 GREEN을 확인하고, 안전 정규화·자동 gate를 임시로 되돌린 mutation RED를 다시 확보한다. 라이브 QA는 포트 5200 렌더러와 실제 8080 게이트웨이를 사용하며, throwaway DESKTOP release는 시작 잔재 회수·생성·정리·SQL 확증을 수행한다.
