# D-G1 S2 요율 계약·정산 계산기 설계

## 목표

레거시 영업수수료 계산기의 요율과 계산 결과를 accounting-service에 이식한다. 요율 계약은 버전별로 보존하고, 정산서는 사용한 계약 버전과 계산 snapshot을 함께 보유한다.

## 레거시 근거

원문은 `tools/legacy-gas/영업수수료 계산/Index.html`에 있다.

- `setPay` (`:262-270`)는 결제방식을 저장하고 카드결제 여부를 바꾼다.
- `setWht` (`:274-282`)는 원천징수 적용 여부를 저장한다.
- `setExp` (`:285-295`)는 기본 8%와 수기율 모드를 선택한다.
- `getExpenseRate` (`:297-301`)는 수기 모드에서 입력값을 100으로 나누고, 그 외에는 `0.08`을 반환한다.
- `xround` (`:318-320`)는 절대값을 `Math.round`한 뒤 원래 부호를 복원한다.
- `getValues` (`:323-340`)의 계산 순서는 카드 공제 → 영업수수료 기준액 → 제경비·원천·설치 공제 → 안전관리비 공제 → 소계 → 선지급 차감 지급액 → 공급가/VAT이다.

## 구조

`SalesCommissionRateContract`는 BaseEntity를 상속하는 append-only 계약 엔티티다. 버전 번호와 카드·제경비·원천·설치 비율을 BigDecimal로 보유한다. 새 요율은 새 계약 행으로 만들며 기존 계약 행을 수정하는 도메인 메서드는 제공하지 않는다.

`SalesCommissionSettlement`는 `rate_contract_id`로 계약 버전을 가리키고, 계산 입력과 결과를 금액 snapshot으로 저장한다. 계산을 기록하는 도메인 메서드는 계약과 계산 결과를 필수로 받아 체인 가능한 현재 정산서를 반환한다. 기존 S1의 번호 채번·확정 경로는 그대로 둔다.

`SalesCommissionSettlementCalculator`는 순수 계산기다. 입력에는 총액, 장비대, 선지급, 설치비, 안전관리비, 결제방식, 원천징수 적용 여부, 선택적 수기 제경비율이 있다. 수기율이 없으면 계약의 제경비 기본율을 사용한다.

## 계산 규칙

```text
card    = CARD결제 ? xround(-total × cardRate) : 0
sales   = total - equipment + card
expense = xround(sales × -expenseRate)
wht     = withholdingApplied ? xround(sales × -withholdingRate) : 0
install = xround(installInput × -installRate)
safety  = -safetyInput
subtotal = sales + expense + wht + install + safety
payout   = subtotal - prepaid
supply   = xround(subtotal / 1.1)
vat      = subtotal - supply
```

`xround`는 소수 0자리 원 단위, 양수·음수 모두 절대값 기준 0.5 이상 올림(tie away from zero)이다. Java BigDecimal에서는 `setScale(0, RoundingMode.HALF_UP)`으로 구현한다. 반올림은 카드·제경비·원천·설치·공급가에만 적용하며, 선지급은 소계와 계산 기준 금액을 바꾸지 않고 지급액에만 반영한다.

## 데이터베이스

Flyway 최대값은 V97이므로 V98을 사용한다. V98은 계약 테이블과 기본 계약 버전 1(카드 3%, 제경비 8%, 원천 3.3%, 설치 8%)을 생성하고 S1 정산서에 계약 FK, 적용 제경비율, 입력값, 항목별 공제액, 소계·지급액·공급가·VAT snapshot 컬럼을 추가한다. 기존 S1 draft 행을 보존하기 위해 FK는 migration에서 nullable로 추가하지만 계산 snapshot 기록 시에는 계약 버전이 필수다. 모든 새 entity 테이블은 BaseEntity 7 audit와 soft delete를 포함한다.

## 범위 밖

그룹웨어 연결, 화면·버튼, 기준일 잠금, 확정 취소, 기존 견적·전표 수수료 품목 경로 변경은 포함하지 않는다.

## 검증

계산기 단위 테스트에서 레거시 fixture, 수기율 유무, 선지급 유무, 계약 버전 변경 후 과거 snapshot 고정, 0원, 0.5 경계, 음수 지급액을 검증한다. S1 테스트를 다시 실행하고 accounting-service 전체 test를 실행한다. 새 코드의 금액 타입은 BigDecimal이며 double 사용은 금지한다.
