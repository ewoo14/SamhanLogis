# DS-3b 문서 양식 편집기 UI 개선 설계

## 목표

PR #891의 문서 양식 편집기와 목록 화면을 기존 기능 계약을 유지한 채 재배치한다. 핵심 성공 기준은 다음과 같다.

- 데스크톱에서 상단 폼과 3-pane의 정렬·높이·선택 상태가 한눈에 읽힌다.
- A4 라이브 미리보기가 미리보기 카드 경계를 넘지 않는다.
- 모바일에서 가로 스크롤 없이 요소 추가, 선택, 좌표/스타일 편집, 삭제, 저장, 목록 복귀가 가능하다.
- 모바일 편집 루프는 `밴드 캔버스 → 속성 패널 → 미리보기` 순서로 이어진다.
- real-QA가 사용하는 접근성 이름, 버튼 이름, 폼 라벨, testid는 유지한다.
- 인쇄 시 편집기 UI는 사라지고 문서 본문만 남는다.
- 공유 인쇄 표면 `.paper`는 변경하지 않고 편집기 preview wrapper 내부에서만 화면 폭을 제한한다.
- 목록은 모바일에서도 실제 table role을 유지한다.

## 레이아웃

### 데스크톱(1100px 이상)

```text
┌────────────────────────────────────────────────────────────┐
│ 제목 / 목록                                                │
├────────────────────────────────────────────────────────────┤
│ 문서 유형                         양식명                    │
├──────────────┬────────────────────────────┬───────────────┤
│ 요소 팔레트  │ 밴드 캔버스                 │ 속성 패널     │
│              │ 라이브 미리보기(A4 contain) │               │
└──────────────┴────────────────────────────┴───────────────┘
```

3-pane 트랙은 `minmax(0, ...)`를 사용하며 모든 pane과 중첩 grid에 `min-width: 0`을 둔다. 기존 H-B/M-J 유형의 max-content 확장과 중첩 grid 겹침을 방지한다.

### 모바일/좁은 화면(1100px 미만)

```text
┌──────────────────────┐
│ 요소 팔레트           │
├──────────────────────┤
│ 밴드 캔버스            │
├──────────────────────┤
│ 속성 패널(선택 요소)   │
├──────────────────────┤
│ 라이브 미리보기        │
└──────────────────────┘
```

스택에는 고정 `min-width`를 두지 않는다. 따라서 전역 `.app-main { overflow-x: hidden }` 아래에서도 수평으로 잘리지 않는다. 선택된 요소의 타입을 밴드의 선택 버튼과 속성 패널 헤더에 함께 표시해 M2를 만족시킨다.

## 영역별 처리

- 상단 폼: 동일한 2열 grid와 블록 라벨을 사용하고 640px 이하에서 1열로 전환한다.
- 팔레트: 토큰 기반 카드 표면과 버튼 wrap으로 정리한다. 기존 `요소 팔레트` region과 추가 버튼 이름은 유지한다.
- 밴드 캔버스: 밴드 헤더, 요소 수, 요소 목록을 분리하고 선택 요소는 브랜드 토큰 배경/테두리로 강조한다. 이동 버튼의 접근성 이름은 유지한다.
- 속성 패널: 기본 브라우저 fieldset/legend 대신 토큰 기반 section panel 스타일을 사용한다. 폼 라벨과 aria-label은 유지한다.
- 미리보기: 화면에서 `.document-template-preview .paper` 폭을 편집기 미리보기 컨테이너 안으로 제한한다. 공용 `.paper` 규칙은 건드리지 않으며 `@media print`에서는 기존 mm 크기를 덮어쓰지 않는다.
- 목록: 데스크톱 table spacing을 정리하고 700px 이하에서 각 row를 카드형 block으로 전환한다. 실제 `<table role="table">`와 row/cell 역할은 유지한다.

## 인쇄와 접근성

편집기 header, 안내/상태 문구, 폼, 팔레트 카드, 밴드 캔버스 카드, 속성 패널 카드, 저장 footer는 `no-print`를 유지한다. 미리보기 본문 wrapper는 `no-print`를 붙이지 않고 print 전용 layout 보정만 적용한다. real-QA 두 스펙의 셀렉터는 변경하지 않는다.

## 검증

- `npm run typecheck`
- `npx vitest run src/renderer/print src/renderer/components/documentTemplate`
- 코드 기준으로 1100px 이상과 1100px 미만에서 추가/선택/좌표·스타일 편집/삭제/저장/목록 복귀 경로가 DOM에 남아 있는지 점검
- Playwright는 개발책임자 지시에 따라 실행하지 않는다.
