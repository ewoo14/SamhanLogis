# 1068 fix4 R22 real-qa spec

## 확정 계약

- 전잔과 기간 판매의 금액 정본은 `PartnerLedgerContract.CANONICAL_SALE_STATUSES`를 참조하는 R22 전표 상태 기준이다.
- 시점 순서는 회계일자 후 `yyyy/MM/dd-N` 전표번호의 숫자 suffix이며, 번호가 없는 분개·입금·조정은 같은 날 뒤로 정렬한다.
- 중복 방지 키는 금액·일자·거래처 추정이 아닌 `Journal.journalNo == Slip.slipNo` exact match다. 실제 slip 분개인 `JournalSourceType.SLIP`만 projection과 dedup한다.

## 전제 확인

- accounting `JournalNumberService`와 slip `SlipNumberService`가 모두 `yyyy/MM/dd` + `-` + sequence를 사용한다.
- `Journal.create`와 `journal_no NOT NULL` 계약으로 번호 없는 Journal 저장은 허용되지 않는다. 수작업·역분개·개시 분개는 slip 번호가 없는 별도 journalNo/sourceType로 취급한다.
- `Journal.sourceRefId`는 tax invoice UUID 및 역분개 원분개 UUID로 재사용되므로 dedup 키로 사용하지 않는다.
- 동일 문자열을 가진 MANUAL 분개는 SLIP dedup 대상이 아니며 별도로 계상되어야 한다.

## 실왕복 시나리오

1. 격리 Testcontainers PostgreSQL에 canonical projection을 제공하고 잔액에 반영한다.
2. 같은 slipNo의 POSTED SLIP Journal을 실제 repository에 저장하고 projection과 한 번만 계상한다.
3. 같은 문자열의 MANUAL Journal 및 no-slip manual Journal을 저장해 오인 dedup 없이 보존한다.
4. CANCELED projection은 표시 전용 `Effect.NONE`이고 잔액에는 들어가지 않는다.
5. 같은 날 sequence 1/3과 target sequence 2를 저장해 sequence 1만 전잔에 반영한다.
6. dedup 조건을 끈 mutation에서는 exact 거래가 중복되어 테스트가 실패해야 한다.

## 격리 및 증거

- `PartnerLedgerBalanceFix4RealQaIT`는 독립 Testcontainers PostgreSQL과 독립 Spring accounting-service context를 사용한다.
- 공유 DB 로그인과 공유 서비스는 사용하지 않는다.
- QA 산출물은 `resolveQaShotsDir()`가 반환하는 `_local` 아래에 기록한다.
