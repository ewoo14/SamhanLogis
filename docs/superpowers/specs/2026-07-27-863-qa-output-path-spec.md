## 0. 원래 제목과 실제 잔여가 다르다

이슈 제목은 "outbox 관측 공백" 이지만, **2026-07-24 PM 전수 정찰 실측**으로 outbox 항목 8개는 **PR #876(`f3b900a36`)에서 전부 해소**됐다(게이지 3종 라이브 노출 · startup race · awslogs · 목록 UX 등).

**남은 범위는 하나** — 코멘트의 *"전체 mock 스위트가 커밋된 스크린샷을 덮어쓴다"*. 제안 ③(절차 문서화)만 메모리로 반영됐고 **제안 ①·② 는 미구현**이다.

## 1. 무엇이 문제인가

- **① 출력 경로 분리 미구현** — mock 스펙이 산출물을 `docs/qa/**` 에 **직접 기록**한다.
- **② 덮어쓰기 가드 미구현** — 명시 플래그 없이도 기존 커밋 파일을 덮어쓴다.

실측:

```
grep -rl "docs/qa" clients/desktop/playwright/ | grep -v -- "-real-qa"   →  41
```

즉 `-real-qa` 가 아닌 **mock 스펙 41개**가 커밋된 QA 증거 디렉터리에 직접 쓴다. 이 저장소에서는 이 경로로 **커밋된 스크린샷 53장이 통째로 덮어써진 사고**가 실제로 있었다.

## 2. 불변식 (수단은 구현자가 정한다)

1. **mock 스위트를 전부 돌려도 커밋된 QA 증거가 변경되지 않는다** — 실행 후 `git status` 가 `docs/qa/**` 에 대해 **0 변경**임을 원문으로 제시할 것.
2. **덮어쓰기는 명시적 의사표시가 있을 때만** — 기본 실행은 기존 파일을 보존한다.
3. **real-QA 증거 경로는 계속 살아 있어야 한다** — `-real-qa` 스펙이 만드는 실캡처는 여전히 커밋 대상이다. 두 경로를 같은 규칙으로 묶어 실 증거까지 임시 디렉터리로 보내지 말 것.
4. **41개 전수** — 일부만 고치고 나머지를 두지 말 것. 남은 수를 숫자로 제시.
5. **가드가 진짜로 잡는다** — 덮어쓰기를 실제로 시도해 차단되는 것을 확인하고 **원문 제출**.
