# 제품구분 카테고리 백필 설계

**목표:** 품목명 보수 규칙으로 제품구분을 채우고, 새 시트 품목과 기존 활성 품목이 동일한 카테고리 분류기를 사용하게 한다.

## 범위와 불변식

- `UNREGISTERED`(`미등록`)는 `parent_id=NULL`인 루트 카테고리이며, 기존 루트의 마지막 다음 순서를 사용한다.
- `products.category_id`의 NOT NULL 계약은 유지한다. 새 시트 품목은 품목명 자동분류 성공 시 해당 카테고리, 실패 시 `UNREGISTERED`를 갖는다.
- 품목명 자동분류는 독립된 단일 Java 컴포넌트가 수행한다. 시트 동기화와 Flyway V38은 이 컴포넌트의 규칙과 동일한 순서·키워드를 사용한다.
- V38은 활성 행 중 `classification_manual=false`인 행만 변경한다. 기존값과 적용값, 사유를 감사 테이블에 남긴다.
- 기존 견적 노출, 정액DC S/M/L 분류, 전표, 세트 전개는 변경하지 않는다.
- 시트에서 soft-delete된 품목이 같은 모델 코드로 다시 나타나면 기존 행을 복원하여 기존 카테고리를 보존한다.

## 분류 규칙

공백을 제거하고 소문자로 정규화한 품목명에 다음 순서로 적용한다. 순서는 충돌 방지 계약이다.

1. 받침대 계열 부자재 → `PIPING`
2. 실외기
3. 실내기
4. 서비스/요금
5. 계장/제어
6. 일반 배관/부속
7. 전열교환기(ERV) → `HVAC`
8. 벽걸이형
9. 시스템 천장형
10. 구성품 역할 역산
11. 미일치 → `UNREGISTERED`

정확한 키워드 원문과 실측 분포는 최종 개발 보고서에 기록한다.

## 데이터 변경과 rollback

V38은 `product_category_backfill_audit` 테이블을 생성한다. 감사행은 migration key, 제품 식별자, 이전/적용 카테고리 ID·코드, 사유와 BaseEntity 7 audit 필드를 보존한다. 마이그레이션은 감사행을 먼저 멱등 삽입하고, rollback되지 않은 감사행만 이용해 제품 카테고리를 변경한다.

rollback은 해당 migration key의 rollback되지 않은 감사행을 기준으로 이전 카테고리로 되돌린 뒤 `rolled_back_at/by`를 기록한다. rollback SQL은 운영 실행물이 아니라 개발 보고서의 명시 절차로 제공한다.

## 검증

- 단위 테스트: 각 우선순위, 벽걸이, 미등록을 분류기 자체에서 검증한다.
- 통합 테스트: 시트 신규 자동분류 성공/실패, 기존 수동분류 보존, soft-delete 후 재등장 카테고리 보존을 검증한다.
- 격리 PostgreSQL 복제본에서 V38을 실행하여 감사·rollback SQL을 검증한다.
