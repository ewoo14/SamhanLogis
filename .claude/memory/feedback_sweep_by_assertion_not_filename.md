2026-08-13 하루에 **네 번** 같은 방식으로 놓쳤다. 전부 "이름"으로 훑고 "역할"로 안 훑은 것이다.

| 트랙 | 이름으로 훑어서 놓친 것 | 역할로 훑었더니 |
|---|---|---|
| `#1196` | `UUID.fromString` 함수명 sweep | `jsonPath("$.data.slipId")` 로 raw UUID 를 **단정**하던 2곳이 남아 CI 재실패 |
| `#1189` | PM 이 준 좌표 9개(파일 목록) | **"창고 id 를 요청에 싣거나 응답에서 읽어 비교하는 곳"** 으로 훑자 6계열 추가 발견 — 모바일 주문서·재고 mutation DTO 8종·DPS 조회·응답 필드 13종 |
| `#1072` | 이관 대상 테이블·컬럼 | **"3자리 코드를 값으로 갖는 위치"** 로 훑자 `column_default` 2건 발견 — 이관은 정확했는데 **새로 만드는 행**이 죽은 계정을 갖고 있었다 |
| `#1072` | DB 만 | DB DEFAULT 를 고쳐도 **애플리케이션 상수**(`CashReceipt.DEFAULT_DEBIT_ACCOUNT_CODE="102"`)가 같은 값을 직접 주입하고 있었다 |

**Why**: 결함은 이름을 공유하지 않는다. `UUID.fromString` 과 `jsonPath(...).value(uuid)` 는 같은 일(“raw UUID 를 정답으로 취급”)을 하지만 텍스트가 겹치지 않는다. 파일 목록으로 좌표를 주면 구현자가 **그 목록이 전수라고 믿는다**.

**How to apply** — 브리핑에 sweep 축을 **문장으로** 적는다.
```
🚫 "이 파일들을 고쳐라"          → 목록 밖은 안 본다
🚫 "getFoo 를 grep 해라"        → 같은 일을 하는 다른 이름을 놓친다
✅ "X 를 요청에 싣거나 응답에서 읽어 비교하는 곳 전부"
✅ "3자리 코드를 값으로 갖는 DEFAULT·CHECK·트리거·뷰·함수 전부"
✅ "raw UUID 를 정답으로 단정하는 곳 전부"
```
그리고 **"좌표 밖에 더 있으면 그것도 이번에 닫고 목록으로 보고하라"** 를 함께 적는다. `#1189` 는 이 문장 덕에 6계열을 더 찾았다.

🔑 **DB 를 고쳤으면 애플리케이션도 세라. 반대도 마찬가지다.** 같은 값이 양쪽에 박혀 있는 것이 기본값·상수·시드의 속성이다.
🔑 전수 단정은 **모집단을 먼저 만들고 전부 분류**하는 형태여야 한다([[feedback_declare_intent_do_not_infer_from_path]] 의 "git 으로 모집단을 계산" 과 같은 요령).
