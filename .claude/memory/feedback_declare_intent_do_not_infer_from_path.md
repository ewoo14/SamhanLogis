# 🚨 목적을 데이터 모양에서 추론하지 마라 — 호출자가 선언하게 하라 (2026-08-08 #1116 · 네 번 연속 실패)

## 무슨 일이 있었나

QA 증거 덮어쓰기 가드가 **어느 디렉터리를 보호할지** 를 경로에서 판정하려 했다. 네 번 고쳤고 **네 번 다 SOL 이 뚫었다.**

```text
① docs/qa 만            →  docs/qa-shots 커밋 452장이 무방비
② docs 전체             →  docs/manual 매뉴얼 도구 3개 과차단
③ docs/qa* 이름 패턴    →  docs/dev-reports 커밋 23장이 무방비
④ 위치 기반(docs 바로 아래)  →  다시 docs/manual 과차단
```

①③은 **뚫림**, ②④는 **과차단**. 진자운동이다.

## 🔑 왜 경로로는 안 되는가

```text
보호해야 함    docs/qa · docs/qa-shots · docs/dev-reports
보호하면 안 됨  docs/manual
```

넷 다 `docs/` 아래고, 넷 다 커밋된 이미지를 담는다. **위치도 이름도 이 둘을 가르지 못한다.**
가르는 것은 **호출자의 목적**이다.

```text
QA spec              재실행이 확정 증거를 덮으면 안 된다
manual-capture 도구   자기 산출물을 의도적으로 재생성한다
```

목적은 데이터에 없다. 그러니 데이터에서 추론하려는 시도는 **원리적으로** 실패한다.

## 규칙

```text
✅ 호출자가 선언한다        resolveQaShotsDir(dir, { protect })
✅ 기본값은 안전한 쪽        protect = true — 선언을 잊으면 보호된다
✅ 예외만 명시적으로 opt-out  manual-capture 3곳만 protect:false
🚫 경로·이름·확장자로 목적을 추론하지 않는다
```

🔑 **기본값이 안전한 쪽이어야** 다음 사람이 선언을 잊어도 안 뚫린다. 이것이 ①③이 반복된 진짜 이유다 — 새 호출자가 생길 때마다 가드가 몰랐다.

## 판별문

> 이 가드가 가르려는 두 집단이 **데이터 모양으로 구분되는가, 사용 의도로 구분되는가?**
> 의도면 → **선언하게 한다.** 모양이면 → 축으로 판정해도 된다.

## 함께 — 울타리도 모양이 아니라 행위로

반열거 울타리가 **소스 정규식**(모든 구현이 같은 함수를 쓰는지)이었더니 ①③을 못 잡았다. 구조는 맞는데 모집단이 틀린 경우를 못 본다.

```text
🚫 소스에 특정 식별자가 있는지 검사
✅ 레포에서 모집단을 계산하고, 그 전부가 분류돼 있는지 단정
   git ls-files 로 docs 하위 캡처 루트를 뽑아
   각각이 "보호" 또는 "재생성" 중 하나인지 확인 — 어느 쪽도 아니면 RED
```

이러면 새 루트가 생겼을 때 **분류를 강제**당한다.

## 🚨 PM 자신에 대한 교훈 — "직접 확인" 이 두 번 부족했다

```text
1회차  "QA_SHOTS_DIR 를 설정하는 지점 0" 으로 과차단 없다고 단정
       → 추적 파일 안의 리터럴 대입만 셌다. 문서·런타임 사용처를 못 봤다
2회차  docs/dev-reports 이미지를 "문서 자산" 으로 분류
       → 실제로는 라이브QA 증거였다
```

둘 다 **측정 가능한 사실을 셌지만 세는 범위가 틀렸다.** 릴레이하지 않고 직접 센 것은 옳았고, **무엇을 세야 하는지**가 틀렸다.

⟹ 카운트로 결론을 낼 때는 *"이 카운트가 놓치는 경로가 있나"* 를 한 번 더 묻는다.
   특히 **"0건이니 안전하다"** 는 형태는 위험하다 — 0이 나오는 이유가 "없어서" 가 아니라
   "안 보여서" 일 수 있다. → [[feedback_unverified_scope_is_not_zero_defects]]
