# 리뷰 fix = 현재 PR 내 처리 (분리 금지)

2026-07-04 개발책임자 지시(PR #724 진행 중): *"fix의 경우 PR을 따로 열지 말고 현재 슬라이스(PR) 안에서 진행해."*

**Why:** 리뷰가 적발한 결함을 후속 이슈/별도 PR 로 미루면 0수렴의 의미가 약해지고 부채가 쌓인다. 같은 서비스·같은 슬라이스 범위의 fix 는 지금 PR 에서 해소하는 것이 리뷰 체인의 목적이다.

**How to apply**
- 리뷰 findings 중 현재 PR 의 서비스/도메인 범위 안에 있는 것은 **심각도 무관** 현재 PR fix 라운드에서 해소한다(예: #724 에서 IllegalState 승격 + 영문 메시지 한국어화를 accounting 3곳 전부 회수).
- 분리가 허용되는 경우 = **타 서비스·타 슬라이스 범위**, 또는 개발책임자가 명시적으로 미룬 것.
- 선례: #723(이미 머지된 타 슬라이스 유입분)은 분리 유지, #725 accounting 몫은 회수.

# 🚨🚨 범위 외 결함 — **새 이슈 등록은 개발책임자 사전 허락 필수** (2026-07-23 절대규칙)

> 개발책임자: *"앞으로 내 허락 없이는 새로운 이슈로 등록 금지야."*

**PM 자율 이슈 등록은 없다.** (2026-07-15 의 "PM 자율 등록" 조항은 폐기)

1. **현 PR 내 흡수가 디폴트** — 판단 기준은 파일 소유가 아니라 **흡수 비용**이다. 같은 클라이언트·한두 줄이면 무조건 흡수.
2. 흡수가 곤란하면 **PR 코멘트/보고에 결함을 적고 등록 가부를 개발책임자께 묻는다.**
3. 🚫 **묻지 않고 등록 금지.** 🚫 **숨기는 것도 금지** — 은폐 방지라는 원래 목적은 그대로다. 바뀐 것은 **저장 위치**뿐(새 이슈 → PR 코멘트 + 질의).
4. 발견 기록에는 **① 실측 증거**(로그/run URL/쿼리 결과) **② 근본원인** **③ 왜 그 PR 범위 밖인지**를 적는다. 추측·"~일 수 있음"은 적지 말 것(노이즈).

**실측 위반 사례(2026-07-23)** — PM 이 CI vitest 간헐 실패(`getByTestId`→`findByTestId` **한 줄**)를 이슈 #915 로 등록 → 개발책임자 제동 → 철회·#907 흡수.
🔑 **머지 게이트를 간헐적으로 막는 결함을 이슈로 미루는 것은 자기 발등을 계속 찍는 것이다.**

⚠️ **흡수로 범위가 점증하면** [[feedback_expanded_scope_reinstate_review]] 발동 — 자체 검증(grep/probe/CI)으로 갈음하지 말고 정식 라운드가 점증분까지 재검한다.
