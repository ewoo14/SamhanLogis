# 🚨🚨 **트랙 전에 항시 정찰** — 예외 없다

> 2026-08-17 개발책임자: *"앞으로는 **트랙 전에 항시 정찰이 필요해**"*
> 같은 날 앞서: *"웹에서 전표생성은 **정찰 후 시행**"* · *"자세한 것은 레거시를 다시 확인해봐 **정찰**"*

## 규칙

```text
worktree add
  → .env.local 복사
  → npm ci
  → PR 개설
  → 🚨 정찰 라운드          ← 여기가 빠지면 위반
  → 구현 라운드
```

🚫 **"작은 변경이라 정찰 없이" 는 없다.** 오늘 그렇게 판단한 것이 두 번 다 틀렸다.

## 왜 — 2026-08-17 실측 2건

### ① 정찰 없이 착수 → 통째로 되돌림

```text
PR #1260  옵션 목록만 구성품에서 읽게 바꿨다
          수량 연결이 옛 하드코딩 그대로여서 도달 결함 3건
          fix 5라운드에도 결함 수가 3→3
          ⟹ PR 을 닫고 수량동기화와 함께 다시 하기로

정찰했다면 알았을 것
  "옵션 ↔ 수량" 이 한 몸이고
  quantity_sync_rule 이 활성 1건·condition_json={} 로 비어 있다
```

### ② 정찰하니 대상 자체가 틀렸다

```text
DPS 입고비교
  이름은 입고비교인데 OUTBOUND 출고전표를 보고 있었다
  실제 DPS 엑셀 헤더를 못 읽고 자체 템플릿만 읽었다
  매칭 키·중복 처리·비교값 전부 레거시와 달랐다

⟹ "금액 대조만 추가" 로 착수했으면 틀린 대상에 금액을 붙일 뻔했다
```

## 정찰이 반드시 답해야 할 것

```text
① 레거시는 무엇을 하는가        tools/legacy-gas 원문 · 파일:줄 인용
                                🚨 인용 없이 "레거시는 ~한다" 고 적지 마라
② 현행은 무엇을 하는가          파일:줄 인용
③ 무엇이 다른가                 한 문장
④ 실제 영향이 몇 건인가          실 DB read-only · "이론상" 과 "실데이터" 구분
⑤ 우리 스키마가 무엇을 담는가    컬럼 전수 · 채움률
⑥ 이미 만들어진 것이 있는가      gh issue list --state all --search
                                🚨 CLOSED 가 곧 구현이다
⑦ 고칠 때 깨질 수 있는 것        목록
```

🔑 ④가 없으면 개발책임자가 결정할 수 없고, ⑥이 없으면 중복을 만든다.

## 라운드 크기

```text
🚨 정찰 한 라운드에 8건을 넣었더니 2시간 타임아웃으로 실패했다
   4건으로 좁히니 성공했다
⟹ 정찰은 4건 이하로 쪼갠다
   한 항목에 30~40분을 넘기지 않게 브리핑에 못박는다
```

**Why:** 코드에 무언가 있다는 것이 그것이 맞다는 뜻은 아니다. 이름이 맞다는 뜻도 아니다. 정찰 없이 고치면 틀린 대상을 정교하게 고치게 된다.

**How to apply:** 트랙 브리핑을 쓰기 전에 정찰 보고서 경로를 먼저 확보하라. 보고서가 없으면 구현 라운드를 발주하지 마라. 관련 [[feedback_verify_existing_before_proposing]] · [[feedback_canonical_workflow]] · [[feedback_open_pr_before_dispatch]]
