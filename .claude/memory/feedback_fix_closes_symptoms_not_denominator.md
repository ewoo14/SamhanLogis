# 🚨🚨 fix 가 새 표면을 만드는 진짜 원인 = **증상을 닫고 분모를 안 센다** (2026-08-10 개발책임자 지시)

## 개발책임자 지시

> *"fix가 새 표면을 만든다면 문제가 있다. 원인을 분석하고 다시 돌아가서 라운드 내에서 fix를 진행할지, 아니면 그 이후로 fix를 진행할지는 **라운드마다 PM이 검증하여 판단**요망."*

---

## 1. 원인 — 커밋으로 확정한 사슬 (`#896` PR `#1126`)

`git log -S` 로 도입 시점을 특정해 재구성했다. 추정이 아니다.

```text
R11  "사용자 옵션이 규칙보다 우선 (한 원인 · 세 증상)"
     → ownsHomeFamily 재수렴 블록 신설. 닫은 계열 = 호스 · 리모컨 · 판넬  (3)
     🔑 그 원인이 지배하는 계열은 실제로 5개였다 (분기관 · 발통이 남음)

R14  SOL 이 남은 2계열을 찾는다                      ← R11 이 만든 표면

R15  그 2계열을 닫는다. 그러나
       · 의미론이 반대다        R11 = 무조건 재수렴 / R15 = 옵션 켜졌을 때만
       · 판별 축이 다르다       R11 = 이름 정규식·isPanelRow / R15 = 모델 상수 열거

R16  SOL 이 둘 다 찾는다                             ← R15 가 만든 표면
       (a) R11 의 3계열은 규칙 소비가 죽어 있다 (규칙값을 레거시가 덮는다)
       (b) 열거 축이 실 카탈로그 SI-AL600A 를 빠뜨린다

R17  분모를 세고 닫는다 — 계열 5 × 옵션 2 × 규칙 3 = **30칸 전수**
```

**정리하면 원인은 둘이다.**

```text
원인 A  진단이 "한 원인 · N 증상" 으로 오면 fix 가 N 증상만 닫는다.
        그 원인이 지배하는 표면의 분모를 아무도 세지 않는다.
        (R11 은 3을 받아 3을 닫았다. 분모는 5였다.)

원인 B  fix 가 새 판별 축(조건 · 집합 · 상수 열거 · 정규식)을 도입하면
        기존 축과 의미론·범위가 어긋나고, 그 불일치가 다음 라운드 결함이 된다.
        (R15 의 상수 열거는 실 카탈로그를 덮지 못했고, 의미론도 R11 과 반대였다.)
```

🔑 **증상 목록은 리뷰어가 본 것의 목록이지 원인이 지배하는 표면이 아니다.** 리뷰어는 정직했다. 분모를 세는 것은 **PM 몫**이다.

## 2. PM 게이트 — 라운드마다 fix 산출물에 세 가지를 묻는다

```text
① 분모를 세었나
   이 원인이 지배하는 표면 전체를 무엇으로 나눴는가.
   보통 (계열 · 화면 · 엔티티) × (상태 · 옵션) × (데이터 축) 의 곱이다.
   fix 보고에 그 표가 없으면 아직 안 센 것이다. 표를 요구한다.

② 새 판별 축을 도입했나
   조건문 · Set · 상수 열거 · 정규식 · 매핑 테이블은 전부 판별 축이다.
   도입했으면 그 축이 **실 데이터 전수를 덮는지 SQL 로 세게** 한다.
   (SI-AL600A 는 이 질문 하나로 잡혔을 것이다.)

③ 기존 축과 의미론이 같나
   같은 표면을 무조건 처리하는 곳과 조건부로 처리하는 곳이 공존하면
   그 자체가 다음 라운드 결함이다. 하나로 통일하거나 왜 다른지 근거를 남긴다.
```

셋 중 하나라도 "아니오" 면 **커밋하지 말고 그 라운드 안에서 되돌려 보완**시킨다. 이것이 라운드를 줄이는 유일한 지점이다.

## 3. 라운드 내에서 고칠까, 이후로 분리할까 — 판단 기준

| | 라운드 **안**에서 고친다 | **이후**로 분리한다 |
|---|---|---|
| 출처 | **우리 fix 가 만들었거나 도달 가능하게 만든 것** | 선재 결함이고 우리 fix 가 도달성을 바꾸지 않았다 |
| 범위 | 같은 **분모** 안에 있다 | 분모가 이 PR 의 범위를 넘는다 |
| 수단 | 좌표가 특정돼 있고 기존 축으로 닫힌다 | 닫으려면 **새 축**(스키마 · 계약 · 데이터 모델)을 도입해야 한다 |
| 게이트 | 도달 가능하므로 게이트 ① 에 센다 | 이슈로 등록하고 근거를 PR 에 남긴다 |

🔑 **"선재 결함이냐" 가 아니라 "우리 fix 가 도달성을 만들었느냐"** 로 가른다.
`SI-AL600A` 누락은 레거시 선재였지만 R15 가 그것을 결과를 바꾸는 자리로 만들었으므로 **라운드 안**이 맞았다.
반대로 `FOOT_FLAT_MODELS` 가 여전히 하드코딩 열거라는 **잔여 취약성**은 새 축(카탈로그 조회)을 요구하므로 **분리** 후보다.

## 4. 브리핑에 넣을 문장 (PM 이 fix 지시서에 항상 덧붙인다)

```text
· 이 결함의 원인이 지배하는 표면의 **분모를 먼저 세고, 표로 제출**하십시오.
  증상 목록만 닫지 마십시오 — 리뷰어가 본 것이 전부가 아닙니다.
· 새 조건 · 집합 · 상수 열거 · 정규식을 도입하면 그것이 **새 판별 축**입니다.
  그 축이 실 데이터 전수를 덮는지 **SQL 로 세어** 보고하십시오.
· 같은 표면을 다루는 기존 코드와 **의미론이 같은지** 확인하십시오.
  무조건/조건부가 공존하면 그 불일치를 보고하십시오.
```
