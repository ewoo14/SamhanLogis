# 🚨 PM 이 라운드마다 점검하고 fix 지시를 구체화한다 — 단 "무엇"까지만

**2026-08-05 개발책임자 지시**

> *"머지 가능성을 높이기 위해 PM이 권장하는 방향이 있을까? 라운드마다 PM이 모두 점검하고 이를 fix 지시안으로 구체화 시키는거지? 구현자에게 모두 떠맡기면 안되고, 최대한 자세하게 지시해줘야해."*

[[feedback_pm_verifies_round_and_directs_next_fix]] 의 강화이고, [[feedback_pm_means_instruction_creates_defect]] 와 충돌하지 않도록 **선을 문장 하나로 가른다**.

## 판별문 (이것만 기억하면 된다)

> 이 문장을 지우면 구현자가 **무엇을** 고쳐야 할지 모르게 되는가 → **줘야 한다**
> 아니면 **어떻게** 고칠지 모르게 되는가 → **주면 안 된다**

| PM 이 반드시 주는 것 | PM 이 주지 않는 것 |
|---|---|
| 불변식 (무엇이 참이어야 하는가) | 구조·API·알고리즘 선택 |
| **적용 좌표 전수** — grep 으로 센 파일:줄 목록 | 어느 줄을 어떻게 바꿀지 |
| **재현 데이터 지목** — "실 DB 전표 2026/08/04-7 로" | 쿼리·자료구조 |
| RED-A / RED-B 문장 | 테스트 작성 방식 |
| **이 fix 가 열 새 조합 목록** | 그 조합을 막는 방법 |
| 범위 밖 · "전제가 틀리면 중단·보고" | — |

🔑 **좌표 목록은 선택지를 하나로 좁히지 않으므로 수단 지시가 아니다.**

## 왜 좌표가 핵심인가 — 2026-08-05 실측

`#1057` R33 에 *"불변식: 버튼 라벨이 실제 동작과 일치한다"* 만 주고 **같은 계열이 존재하는 모든 지점을 세어 주지 않았다.** 구현자는 삭제/취소만 고치고 **수정/수정 충돌을 새로 만들었다**(R34 결함 1 · CI red · OUTBOUND DRAFT 115건 memo 덮어쓰기).

불변식은 옳았고 **적용 범위를 구현자가 정하게 둔 것**이 라운드를 하나 더 만들었다.

## 즉시 적용 5가지

```
① fix 브리핑 전에 PM 이 grep 으로 계열 전수를 세어 좌표 목록을 붙인다
② 재현 데이터를 PM 이 실측으로 지목한다 (#1061 수수료 4건 지목이 효과)
③ 구현자에게 "커밋 전 이 게이트를 돌려 원문 제출" 을 의무화한다
   ← PM 토큰을 안 쓰면서 라운드를 줄이는 유일한 레버. 가장 효율이 좋다
④ SOL 의 "이 라운드가 보지 않은 것" 절을 읽고 다음 각도로 직접 만든다
⑤ 묶음 규칙 — 서로 다른 파일이면 묶고, 같은 파일이면 나눈다
   R32(1건·단일 파일) 깨끗 / R33(3건·SlipDetailPage 한 파일) 서로 간섭
```

## 🔑 그러나 지시 구체화가 듣지 않는 쪽이 있다

2026-08-05 회사PC 16라운드의 결함 출처:

```
자기 유발 (오늘 fix 가 만든 것)     3건   ← 지시 구체화가 직접 듣는다
PM 브리핑 오류                      1건   ← 전제 실측으로 막는다
선재 결함 발견                     10건   ← 지시로는 안 줄어든다
```

**선재 결함 쪽은 "얼마나 잘 지시했나" 가 아니라 "이 PR 이 어디까지 떠안나" 의 문제다.**

```
#874 주제        세트 riUsage · 거래처 전역DC
실제 하는 일      SlipDetailPage(4,700줄 lifecycle 허브) 선재 결함 흡수 (R21 이후 전부)

#1001 도 같은 모양이었으나 계정과목 체계 전환을 #1072 로 분리하자 범위가 닫혔다
```

⟹ 라운드가 안 끝날 때 **먼저 물을 것은 "지시가 부실했나" 가 아니라 "이 결함이 이 PR 이 만든 것인가"** 다. 선재면 분리 가능성을 개발책임자께 올린다(🚫 PM 자율로 미루지 말 것 — [[feedback_fix_in_current_pr_no_split]]).
