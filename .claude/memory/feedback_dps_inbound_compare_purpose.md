# 🚨 DPS 입고비교 = **외부 엑셀 ↔ 우리 입고내역 대조**

> 2026-08-17 개발책임자: *"DPS 입고비교는 **DPS 입고엑셀을 업로드하고 날짜범위의 우리 입고내역과 일치 여부를 확인**하게 위한거야"*

## 목적

```text
입력   DPS 에서 받은 입고 엑셀
대상   지정한 날짜 범위의 우리 입고내역
동작   두 쪽이 일치하는지 확인한다
```

🚩 **PM 정정 (2026-08-17)** — 앞서 *"즉석 대조라 저장 안 한다"* 고 적었으나 **틀렸다.**

```text
레거시   Notion 에 자동·수동 저장하고 복원한다
현행     DB 이력을 저장한다
```

⟹ 저장은 양쪽 다 한다. *"저장된 비교 이력 0건"* 은 **아직 안 쓴 것**이지 도구의 성격이 아니다.

## 개발책임자 확정 (2026-08-17) — 금액도 대조한다

```text
레거시   같은 납품번호+모델 안에서 수량과 합계금액을 1:1 대조
         r._qty = parseNum(r['수량_1'] || r['수량'])
         r._sum = parseNum(r['합 계'] || r['합계'])
         tools/legacy-gas/DPS 입고기록 비교/Index.html:398-402

현행     거래처+품번+일자 bucket 의 수량합만 대조

결정     레거시대로 — 금액도 대조한다
```

🔑 **수량만 맞고 금액이 다르면 단가 오류를 못 잡는다.** 외부에서 받은 자료와 대조하는 도구이므로 금액이 핵심이다.

## 실측 (2026-08-17)

```text
공유 DB   활성 전표 235건 · 라인 4,044건
          DPS 업로드 원문·저장 비교 이력 0건
비교기    읽기 전용 — 세금계산서·회계마감·대외 문서를 고치지 않는다
⟹ 되돌릴 수 없는 것 없음
```

## 🚨 정찰이 밝힌 것 — 현행이 거의 모든 축에서 다르다 (2026-08-17)

`docs/dev-reports/2026-08-17-dps-inbound-compare-recon/report.md`

| 축 | 레거시 | 현행 |
|---|---|---|
| 우리 쪽 원천 | 이카운트 엑셀 업로드 | **OUTBOUND 출고전표** 자동 조회 |
| DPS 헤더 | 납품일자·납품번호·모델·수량·매입단가·공급가·인도처명·부가세·합계 | 품번·입고일자·수량·거래처코드·거래처명 |
| 헤더 행 | 표지 3개가 있는 임의 행 탐색 | 첫 행 고정 |
| 매칭 키 | 납품번호(적요) + 정규화 모델 | 거래처코드+품번+일자 |
| 중복 키 | 행별 1:1 소비 | 버킷 수량 합산 |
| 비교값 | 수량 + 합계금액 | 수량만 |

### 개발책임자 결정 (2026-08-17)

```text
비교 대상    입고전표(INBOUND)      ← 현행이 출고를 보고 있었다
엑셀 헤더    실제 DPS 파일을 읽게    ← 현행은 자체 템플릿만 읽는다
금액         레거시대로 대조
```

🔑 **현행은 실제 DPS 파일로는 아예 안 된다.** 자기가 정의한 템플릿(시트명 `DPS 입고`)만 읽는다.

**Why:** 외부 업체가 보낸 입고 자료와 우리 기록이 어긋나면 재고와 매입이 틀어진다. 수량만 대조하면 "몇 개 왔는가"는 맞아도 "얼마에 왔는가"는 못 본다.

**How to apply:** 이 도구를 만질 때 **비교 대상이 입고인지 먼저 확인하라.** 이름은 입고비교인데 출고를 보고 있던 사례가 있다. 관련 [[feedback_no_fake_data_ever]] · [[feedback_verify_existing_before_proposing]]
