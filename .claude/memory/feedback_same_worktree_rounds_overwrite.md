# 🚨 같은 워크트리에 라운드를 겹쳐 돌리지 마라

## 무슨 일이 있었나 (2026-08-17 · wd03)

같은 스레드에 두 지시를 연달아 보냈고, 워크트리가 하나였다.

```text
kgiq7wnpr   "인피니트 판넬 4종을 품목명에서 도출해 적용하라"
            → 구현 완료. PANEL 250건 판정 불변 68/68/57/57 확인. V44 추가

khccwvvlt   "360판넬 하드코딩이 남았다. 어디서 와야 하는지 밝혀라.
             못 하면 근거와 함께 그대로 두어라"
            → "인피니트 분류기·마이그레이션·레거시 추론 코드 제거"
              품목명 추론 자체를 폐기 대상으로 해석했다
```

⟹ **개발책임자가 "해당 옵션을 적용해줘야해" 라고 명시한 것이 지워졌다.**

## 왜 그렇게 됐나

두 번째 지시에 *"품목명에서 도출되는가 밝혀라 … 못 하면 그대로 두어라"* 가 있었다.
구현자는 그것을 **품목명 추론 전반에 대한 판정 요청**으로 읽었고, 앞 라운드가 이미 넣은
인피니트 추론까지 "근거 약함" 으로 걷어냈다.

🔑 지시는 **그 라운드가 만든 것**만 대상으로 읽히지 않는다. 워크트리에 있는 전부가 대상이다.

## 규칙

```text
① 한 워크트리에 한 라운드
   앞 라운드가 완료·커밋되기 전에 같은 워크트리로 다음 라운드를 보내지 마라

② 이어서 지시할 때는 "직전 커밋이 확정한 것 — 건드리지 마라" 절을 반드시 넣는다
   무엇이 이미 확정됐는지 명시하지 않으면 재판정 대상이 된다

③ 방향 전환 지시는 특히 위험하다
   "A 가 아니라 B 다" 는 A 계열 전부를 지우라는 뜻으로 읽힐 수 있다
   지울 것과 남길 것을 각각 이름으로 적어라

④ 라운드 결과가 돌아오면 diff 를 확인하고 커밋한 뒤 다음을 보낸다
   커밋이 방어선이다 — 커밋돼 있으면 되돌려도 복구가 싸다
```

## 비용

이 실수로 라운드 하나(인피니트 4종 도출 + 250건 불변 검증 + V44)를 통째로 다시 돌렸다.
검증까지 끝난 작업이었다.

**Why:** 구현자는 워크트리 상태 전체를 보고 판단한다. PM 이 "이번 라운드에서 만든 것" 과
"이미 있던 것" 을 구분해 주지 않으면 구별할 방법이 없다.

**How to apply:** 발주 전에 `git -C <워크트리> status --porcelain` 으로 다른 라운드가
남긴 미커밋 변경이 있는지 확인하라. 있으면 먼저 커밋하거나, 그 라운드가 끝날 때까지 기다려라.
