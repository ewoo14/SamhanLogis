🚨 **2026-07-20 개발책임자 결정.** 계기 = "이렇게 진행해서 언제 모든 ISSUE와 남은 슬라이스를 진행하나". 실측 근거: **#854 한 건이 8시간 21분 · 커밋 14 · 69파일/+3,866줄 · 적대검증 5라운드** 를 쓰고도 미머지였고, 잔여는 슬라이스 11~12개였다(산술 90시간+).

## 🚫 채택하지 않은 것 — 위험 등급제
"dormant 경로·내부 chore 는 라운드/차원 축소" 안은 **미채택**. **캐논은 전 슬라이스 동일 강도로 유지**한다. 처리량은 검증 깊이를 깎아서가 아니라 아래 3레버로 확보한다. → [[feedback_canonical_workflow]] 무변경.

## ① 슬라이스 병렬화 (기본 운영 방식으로 전환)
캐논이 **명시적으로 허용**한다 — "병렬 다중 PR이어도 각 슬라이스는 전 단계 순차 완주(PM이 매번 전 슬라이스 점검)". 금지되는 것은 **한 슬라이스 안의 단계·라운드 병렬**이지 슬라이스 간 병렬이 아니다.
- 2~3개 슬라이스를 **별도 브랜치/PR** 로 동시 진행. 각 PR 은 기획→구현→R1→R2→0수렴→머지를 **각자 순차** 완주.
- **간섭 없는 조합으로 묶을 것** — 같은 서비스/같은 파일군을 건드리는 슬라이스는 동시에 돌리지 않는다(작업 트리 오염·리베이스 지옥). 예: BE 회계 / FE design-system / 인프라 chore 는 안전한 조합.
- PM 컨텍스트가 분산되므로 **슬라이스마다 PR 게시가 상태 저장소** 역할을 한다(실행=게시 1:1 이 더 중요해짐).

### 🚨 2026-07-23 개발책임자 재지시 — "가급적이면 트랙 3개 모두 병렬로 **꼭** 진행"
병렬은 여유가 있을 때 하는 선택이 아니라 **기본 운영 상태**다. **트랙이 비면 채운다** — 한 트랙이 스테이지를 끝내면 회수·검증·게시 직후 **곧바로** 다음 스테이지를 디스패치하고, 트랙이 완전히 끝나면 새 슬라이스를 개설한다(2026-07-23 오후 #908 머지 직후 #914 개설이 그 예).

**기획서에 적힌 "자원 경합 회피를 위한 순차"는 조건부다.** 실측상 아래를 분리하면 3트랙 동시 가동이 실제로 문제없이 돈다:
- **포트** — 트랙마다 렌더러 dev 포트를 다르게 배정하고 `--strictPort` 유지(예 5190/5195/5200). mock 하네스 `5173` 은 `reuseExistingServer` 라 **소유 트랙을 하나로 정할 것**(다른 트랙은 `PLAYWRIGHT_SKIP_WEB_SERVER=1`). 조용한 폴백은 고아 vite stale 서빙 사고가 된다.
- **DB/서비스** — 트랙마다 다른 서비스 DB 를 쓰게 배정(예 `partner_order_db`/`groupware_db`/`dashboard_db`). 라이브 **쓰기**가 겹치면 직렬화. → [[feedback_parallel_agent_gradle_shared_tree_contention]]
- **워크트리** — 트랙당 전용 워크트리. 신규 워크트리는 `npm install` + **design-system `dist` 재빌드**가 필요하다(`file:` 링크라 워크트리마다 별도, stale dist = 유령 typecheck 오류).
- **gradle** — 워크트리별 `build/` 는 분리되나 `~/.gradle` 은 공유. 서로 다른 모듈이면 실측상 무해.
- **Flyway** — 🚨 병렬 트랙이 같은 서비스에 마이그레이션을 추가하면 **번호 경합**(V12 중복으로 CI 전면 실패 실측). 구현자에게 "번호를 임의로 잡지 말고 먼저 보고"를 지시할 것.

## ② 슬라이스 중 범위 동결 (가장 큰 단일 레버)
[[feedback_fix_in_current_pr_no_split]] 를 **정밀화**한다. 두 가지를 구분한다.
- **슬라이스 자체 코드의 결함** = 현 PR 에서 fix (**기존 규칙 그대로 유지**). 별도 PR/후속 이슈 분리 금지.
- **새 기능·새 표면 추가 제안**(리뷰가 "이것도 있으면 좋겠다"로 발견한 것) = **기본값이 이슈 등록 + 다음 슬라이스**. 현 PR 에 넣으려면 개발책임자 명시 결정 + **비용(라운드 1회 추가 ≈ 3~4시간) 선제시** 필요.
- 🚩 실증(#854): R4 "전건 fix" 결정으로 관측 인프라 + FE 표시 면 + 타서비스 계약 변경이 붙어 **신규 코드 ~1,400줄**이 생겼고, **R5 가 찾은 HIGH 5건은 거의 전부 그 신규 코드 안**이었다 — 즉 **자초한 라운드**. Track 2 없이 R3/R4 에서 머지 가능했다.
- ⚠️ PM 의무: 범위 점증 결정을 올릴 때 **"라운드 1회 추가 = 3~4시간"** 비용을 반드시 함께 제시할 것. #854 에서 PM 이 이를 누락했다.
