# 🚨 **"어느 쪽이 맞나" 를 묻기 전에 "고를 게 있긴 한가" 를 세라** (2026-08-03 #984)

## 무슨 일이 있었나

`#984` 는 열 라운드 동안 **진자운동**했다.

```text
R2  이름만으로 병합    → 33품목 값 소실
R5  fingerprint 도입   → 우회 2곳
R7  gate 전수 적용     → 같은 물건이 갈림
R9  관계 우선축 도입   → 21품목 값 소실
```

R10 은 이것을 **데이터 권위 문제**로 정리하고 개발책임자께 양자택일을 올렸다.

> 관계 원본은 두 코드를 같은 물건이라 하는데 **업무값이 다른 그룹이 25개** 있다. 관계가 맞나, 업무값이 맞나?
>
> A 업무값 우선(분리) — 같은 물건이 갈림 / B 관계 우선(병합) — **21품목 37필드 값 소실** / C 25그룹 개별 판정 / D 원본 재취득

**진단은 옳았다. 그런데 25그룹을 실제로 열어 본 사람이 없었다.**

재취득 후 같은 fingerprint 정의로 26그룹을 열자:

```text
① 한쪽만 값 있음 (다른 쪽 공백/0)   23   ← 충돌 아님. 값이 하나뿐
② 공백 문자 차이만                   2   ← 'T 분기관' ↔ 'T분기관'
③ 실제 값 충돌                       1   ← 여기만 사람이 판정
```

**26개 중 25개는 고를 것이 없었다.** 개발책임자 판정은 1건으로 끝났다.

## 🔑 핵심 — 대가는 문제의 성질이 아니라 **규칙**에서 나왔다

B안의 *"21품목/37필드 값 소실"* 은 병합의 대가가 **아니었다.** 병합 규칙이 *"대표품목 값을 그대로 쓴다"* 였기 때문이다. ①에서 대표품목 쪽이 비어 있는 경우가 다수였으므로, 규칙을 **필드별 "비어 있지 않은 쪽이 이긴다"** 로 바꾸는 순간 소실이 0 이 된다.

즉 **선택지 자체가 잘못 만들어져 있었다.** A/B 는 서로 배타적인 것처럼 보였지만, 실은 "규칙을 어떻게 쓰느냐" 라는 세 번째 축이 있었다.

## 어떻게 할 것인가

- 🚨 **"N건이 충돌한다" 를 개발책임자께 올리기 전에 N건을 열어 성격별로 세라.** `한쪽 공백` / `표기 차이` / `실제 충돌` 최소 3분류. 분류 없이 올린 양자택일은 **없는 결정을 만들어 낸다.**
- 판별 정규화 주의 — 빈칸과 `0` 을 같은 값으로 정규화하면 `680,000 ↔ 0` 이 "충돌" 로 잡힌다. 그게 fingerprint 로는 맞지만 **사람이 고를 문제인지 가르는 데는 틀린 기준**이다. fingerprint 용 비교와 판정용 비교를 나눌 것.
- 반대 실수도 있다 — 빈 값을 비교에서 **제외**하면 이번엔 진짜 결손을 놓친다(첫 계수에서 26이 3으로 줄어 보였다). **두 기준을 다 돌리고 차이를 설명할 것.**
- 진자운동이 3회 이상이면 fix 를 더 하지 말고 **데이터를 열어 보는 라운드**를 넣을 것.
