# 🚨 행 입력 화면은 전부 **자동 빈행** 방식

**2026-08-01 개발책임자:**

> 판매전표처럼 아래에 빈행을 넣고 해당 행에 값을 넣으면 아래에 또 빈행이 들어가도록 진행요청
>
> 1004번뿐 아니라 **다른 전표(행이 들어가야 하는 경우)도 이런 방식 채택**

```text
초기            [ 빈행 ]
빈행에 값 입력  →  [ 행1 ] [ 빈행 ]
또 입력         →  [ 행1 ] [ 행2 ] [ 빈행 ]
```

**"행 추가" 버튼을 누르지 않습니다.** 맨 아래에 입력 가능한 빈행이 항상 하나 대기합니다.

## 적용 범위

**행을 입력하는 모든 화면** — 판매전표 · 매입전표 · 입금보고서 · 견적 · 주문서 등 라인을 넣는 곳 전부.

**Why:** 이카운트를 쓰던 실무자에게 익숙한 입력 방식이고, 화면마다 입력 방식이 다르면 같은 일을 하는데 조작을 새로 배워야 한다. **두 화면이 다르게 동작하면 그 자체가 결함**이다.

## How to apply

- 🔑 **판매전표의 기존 구현을 재사용하라.** 새로 설계하지 말고 같은 컴포넌트·같은 훅을 쓴다. 중복 구현하면 두 곳이 서서히 갈라진다.
- 🚨 **빈행이 저장 대상에 들어가면 안 된다.** 값 없는 행이 라인으로 등록되는지 반드시 실행으로 확인하라.
- **마지막 빈행을 지우려 할 때의 동작**도 판매전표에 맞춘다.
- 기존 행 **편집·삭제가 막히지 않는지** 확인하라([[feedback_fix_blocks_normal_path]]).
- 새 화면을 만들 때 "행 추가 버튼" 을 넣으려 하면 이 규칙을 먼저 떠올릴 것.
