# 🚨 결정이 필요하면 **항상 선택지를 제시**한다 (2026-08-10 개발책임자 지시)

> *"항상 결정이 필요하면 선택지를 제시"*

## 무엇이 잘못이었나

D11(세트 구성품 전제 부분충족)을 올리면서 **실측 + PM 권고 한 줄**만 적고 *"판단 요청"* 으로 끝냈다.
개발책임자는 그 상태에서 **답을 직접 작문해야** 했다. 근거는 충분했으나 **고를 것이 없었다.**

🔑 판별문 = **"내 메시지를 읽고 개발책임자가 한 단어로 답할 수 있는가?"**
아니면 선택지가 없는 것이다.

## 형식

- **AskUserQuestion 도구로 낸다** — 서술형 문단에 섞지 않는다. 고르는 자리가 화면에 있어야 한다.
- **2~4개** · 각 안은 **서로 배타적**이고 **실행 가능한 것**만. "더 조사한다" 도 결과가 달라지면 유효한 안이다.
- **PM 권장안을 맨 앞에 두고 `(권장)` 을 붙인다** — [[feedback_pm_autonomous_recommended_direction]] 의 *"권장 방향으로 자율진행"* 과 충돌하지 않는다.
  자율진행은 **권장안을 쓸 수 있을 때** 적용되고, 이 규칙은 **어차피 올려야 하는 건**의 형식을 정한다.
- 각 안에 **대가(무엇을 잃는가)** 를 함께 적는다. 장점만 적힌 선택지는 선택지가 아니다.
- 선택 결과는 **PR 에 결정 기록으로 누적**한다 → [[feedback_post_devlead_decisions_to_pr]]

## 언제 올리는가 (변하지 않음)

올릴 대상 자체는 기존 기준 그대로다 — **신규 업무규칙/정책 · 무결성 도메인 · P0 · 되돌리기 어려운 것 ·
기록된 계획과 실측이 어긋난 것**([[feedback_recorded_plan_conflict_needs_escalation]]).
🚫 이 규칙이 *"애매하면 물어라"* 로 확장되면 안 된다 — **묻는 횟수는 그대로, 묻는 형식만 바뀐다.**
[[feedback_pm_autonomous_recommended_direction]] 의 *"선택지 나열하며 기다리는 것 자체가 병목"* 은
**안 물어도 될 것을 묻는 경우**를 가리킨 것이다.

## 함께 지킬 것

- 🚨 **선택지를 잘못 만들 수 있다** → [[feedback_conflict_is_mostly_one_sided_blank]]
  *"어느 쪽이 맞나"* 를 올리기 전에 **"고를 게 있긴 한가"** 를 먼저 센다.
  실측 사례 — 26그룹 양자택일로 올렸으나 23은 한쪽이 공백, 2는 표기 차이, **실제 충돌 1건**이었다.
- 🚨 **이지선다를 주면 진짜 답이 밖에 있어도 두 칸에 욱여넣는다** → [[feedback_mock_gate_leaks_to_real_api]]
  선택지에 **"셋째 가능성이 있으면 그것을 내라"** 에 해당하는 여지를 남긴다(도구의 '기타' 로 충족).
