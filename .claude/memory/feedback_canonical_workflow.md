# 🚨 머지 게이트 = **도달성 축** (현행 정본)

| # | 게이트 |
|---|---|
| ① | **실 사용자 경로로 재현 가능한 결함 0** (심각도 무관) |
| ② | **CI green (exact SHA)** |
| ③ | **라이브QA — 실서버 실제 실행** |

## PM 재량 (2026-07-22 개발책임자 명문화)
게이트는 **사용자가 겪는 오류 / 보안 이슈** 뿐이다. 그 외(UX·디자인 일관성·표기·편의기능)는 **PM 판단으로 머지 가능**.
판정 질문은 *"사용자가 겪는가"* 가 아니라 **"그것 때문에 오류를 겪는가·보안이 뚫리는가"**.
- 후속 분리 지양 — 가능하면 현 PR 에서 처리하되 **못 고쳐도 머지를 막지 않는다.**
- 재량 남용 금지 — 판정 근거를 PR 에 명시하고, **애매하면 오류 쪽**으로.
- 🚫 MED/LOW 무시가 아니다 — **도달 가능한 MED/LOW 는 여전히 게이트다.** 축이 심각도에서 도달성으로 바뀐 것이다.

# 🚨🚨 적대리뷰는 **오직 도달성만** 본다 (2026-07-23 개발책임자 지시)

> *"라운드마다 도달 가능한 증상들만 fix 되었는지 여부만 확인하며, 적대리뷰는 검증 품질을 볼 것이 아니라 오직 도달 가능한 증상이 있는지 여부만 확인하도록 한다."*

- 리뷰어 브리프의 질문은 **하나**다 — **"실 사용자 경로로 재현 가능한 결함이 있는가?"**
- 🚫 **검증 품질(테스트가 약하다·문서가 과장됐다·mock 미비·가드에 구멍이 있으나 실 경로로 못 닿는다)은 찾지도, 보고하지도 않는다.** 종전의 `검증품질` 분류·이월 이슈 제도는 **폐지**한다.
- **도달가능 = 재현 절차를 실행해 증거(출력·스크린샷)를 첨부한 것**만 인정한다. *"이론상 가능"* 은 도달가능이 아니다.
- 라운드마다 **직전 라운드의 도달가능 항목이 실제로 닫혔는지**를 함께 확인한다.
- 검증 하네스의 약점은 **그것이 실 결함을 가렸다는 것이 드러났을 때만** 다룬다(그 경우 결함 쪽이 본체다).

**왜** — 전면 감사를 반복하면 검증 품질 발견이 매 라운드 7건씩 나와 **종료 조건이 사라진다**(2026-07-21~22 실측: 밤새 3트랙 머지 0, MED 만 7 근처 평평, 그 과반이 검증 품질). 도달 가능한 결함은 **유한하고 실제로 줄어든다.**

## 🆕 유일한 예외 — **증거 무결성은 도달성과 무관하게 항상 보고한다** (2026-07-27 개발책임자 승인 · A안)

검증품질 폐지는 *"테스트가 약하다 · 가드에 구멍이 있다"* 류에 적용된다. **인용 원문·수치의 위조·불일치는 성격이 다르므로 예외로 둔다.**

- **대상** — 보고서·PR 코멘트가 "원문"·"실측" 으로 제시한 출력이 **재현되지 않는 것**, 수치가 실제와 다른 것, **실행하지 않은 것을 실행한 것처럼 읽히게 쓴 것**.
- **대조 각도(SONNET5)의 기본 임무**로 배정한다 — 별도 지시가 없어도 매 라운드 수행한다.
- 도달성 0 이어도 **항상 보고**하고, **이월하지 않고 그 라운드에서 정정**한다.
- 🔑 **왜 종료 조건을 흐리지 않는가** — 정정이 **검증 장치를 늘리지 않는다**(위조 인용을 실제 출력으로 갈아끼울 뿐이라 다음 라운드의 감사면이 되지 않는다). 반대로 방치하면 **도달성 판정 자체가 구현자 보고 위에 서 있으므로** 그 보고서의 나머지 주장 전부가 무의미해진다.

# 🚨🚨 궁극 목적 = **결함 0** · 하네스는 그 수단이다 (2026-07-23)

> *"어쨌든 가장 궁극적인 목적은 결함을 0으로 만드는 것이기 때문이야."*

- **설계 목표는 수렴비 `c < 0.45`** (`c` = 이번 라운드 도달가능 ÷ 직전 라운드 도달가능). 매 라운드 `c`·`r` 을 계산해 **PR 에 기록**한다.
- **3턴은 권고**다(1턴 = OPUS 라운드 + CODEX 라운드). 넘겨도 임의로 끌지 말고 **남은 목록 + 흡수 난이도 + PM 권고**를 개발책임자께 올린다. 3턴 초과 자체는 위반이 아니며, **c 를 기록하지 않고 원인 없이 라운드를 반복하는 것**이 위반이다.
- **새 이슈 등록 금지** — 개발책임자 사전 허락 없이는 만들지 않는다. → [[feedback_backlog_burndown_issue_bar]]
- **PM 이 fix 를 기획한다** — ①진단을 **실행으로 확증**한 뒤 불변식을 쓴다 ②증상이 아니라 **근본원인으로 묶는다** ③**회귀 울타리**를 명문화한다 ④닫을 것/남길 것을 미리 판정한다.
- **PM 은 c·r 에 따라 하네스를 바꿀 권한을 위임받았다.**

# 표준 파이프라인 (슬라이스/PR 1건 · 단계는 순차 · 모든 단계 산출물을 그 즉시 PR 게시)

1. **기획 = OPUS 4.8** — spec/plan 수립(기존 결정 교차검증 [[feedback_spec_cross_check_prior_decisions]] · 경계/권한/계약/무결성 점검 포함). **기획 단계에서 브랜치 + PR 즉시 개설**(OPEN, draft 금지 [[feedback_pr_open_not_draft]]) 후 기획 리뷰를 PR 게시. 🚫 PR 없이 다음 단계 진행 = 위반.
   - 🚨 **진단 확증 의무** — 불변식을 쓰기 전에 **원인을 실행으로 확증**한다. 코드 읽기 추정으로 단정하지 않는다. 확증 못 하면 **"원인 미확정"** 이라 적고 규명을 구현자에게 맡긴다.
   - 🚨 **U-gate 1문장** — *"이 슬라이스가 끝나면 사용자가 **실데이터로** 무엇을 할 수 있게 되는가"* + 구체 시나리오 1개를 기획서에 명시한다.
2. **구현 = CODEX LUNA 5.6** — 파일 수정만(git 금지 · PM commit 대행 [[feedback_codex_sandbox_git]]). PM 직접 구현 금지([[feedback_pm_no_direct_implementation]]). 완료 시 구현 리뷰 PR 게시.
3. **1차 적대검증 = OPUS 4.8 표면 분할 서브에이전트 + PM 직접 라이브QA** → **fix = SONNET5** → 검증 → 라운드 리뷰 PR 게시.
4. **2차 적대검증 = CODEX SOL 5.6 자기완결 사이클** (🆕 2026-08-05 개발책임자 개편 — 아래 전용 절 참조)
   `SOL 검증 → SOL 이 fix 지시서 작성 → LUNA fix → SOL 재검증 → 결함 0` 까지 **PM 을 거치지 않고** 돈다.
   결함 0 이 확인된 뒤에만 PM 에게 보고한다.
5. **3~4 를 도달가능 0 까지 반복** (3턴 권고 · 매 라운드 `c`·`r` 기록).
6. **PM 재검증 → PM 자율 머지** — PM 이 산출물을 직접 대조(릴레이 금지)하고, **이상하면 다음 라운드로 돌린다.**
   이상 없으면 종합 리뷰 PR 게시, dev-report/docs 동기화([[feedback_continuous_docs_sync]]),
   CI green(exact SHA), **U-gate 실데이터 실행 1회** 확인 후 **PM 이 자율 머지**한다([[feedback_pm_auto_merge_authority]]).

## 🚨🚨 2차 적대검증은 **SOL 자기완결 사이클** (2026-08-05 개발책임자 개편)

> *"SOL이 적대검증으로 결함을 찾은 것을 보고만 하지 말고 바로 LUNA로 fix하고 결함 없는 것을 확인한 후에 PM에게 보고."*
> *"SOL이 발견한 결함이면 LUNA에게 직접 fix를 지시하고 SOL이 재검증하여 결함이 0인 경우 PM에게 보고하라는 거지. PM도 그러면 검증 완료 후 머지 판단을 받는 것으로."*
> *"PM 재검증 때 이상하면 다시 다음 라운드를 진행하는거지."*
> 🚨 *"**머지는 PM에게 권한 위임**"* (같은 날 확정 — PM 이 "머지 판단을 개발책임자께 올린다" 로 잘못 적었다가 정정받음)

### 사이클

```text
SOL 적대검증
  └ 결함 0 ─────────────────────────────────→ PM 보고
  └ 결함 발견
      └ SOL 이 fix 지시서를 파일로 작성        ← 지시 주체는 SOL 이다 (PM 이 아니다)
          └ LUNA fix (지시서를 브리핑으로)
              └ SOL 재검증
                  └ 결함 0 ─────────────────→ PM 보고
                  └ 결함 남음 ───────────────→ 다시 SOL 이 지시서 작성 (루프)

PM 보고 후
  PM 재검증(직접 대조 · 릴레이 금지)
    └ 이상 없음 → PM 자율 머지                   ← 머지 권한은 PM 위임 (개발책임자 확정)
    └ 이상 있음 → 다음 라운드로 되돌린다          ← PM 재검증은 도장이 아니라 게이트다
```

🔑 **PM 재검증이 이 사이클의 유일한 외부 게이트다.** SOL 이 "결함 0" 을 냈어도 PM 이 직접 대조해 이상을 찾으면 되돌린다. 실측(2026-08-05 `#1063` R26) — SOL 3건을 다 고쳤다는 보고를 PM 이 대조하다 **R22 발견 1 이 되살아난 것**을 찾아 R27 로 되돌렸다.

### 왜 바뀌었나

종전에는 `SOL → PM 검증·커밋·게시·보고 → LUNA → PM 검증·커밋·게시·보고 → SOL` 로 **PM 이 매 홉마다 끼어** 라운드 왕복이 배로 늘었다. 병목은 토큰이 아니라 **라운드 개수**다([[feedback_throughput_parallel_scope_freeze_batch]]).

### 구현 방법 — codex MCP 는 세션당 모델이 하나다

SOL 이 LUNA 를 직접 spawn 할 수 없으므로 **지시서를 파일로 넘긴다.**

```text
1  SOL 브리핑에 명시 — "결함을 찾으면 fix 지시서를
     docs/dev-reports/<날짜>-<슬라이스>-r<N>-fix-directive.md 로 작성하라.
     좌표(파일:줄) · 불변식 · 양방향 RED · 범위 밖 · 반대급부를 포함하라"
2  PM 은 그 파일을 **그대로** LUNA 브리핑으로 전달한다 (내용을 다시 쓰지 않는다 = 전달자 역할)
     환경·가드레일(재배포 금지·커밋 금지·돌릴 명령)만 PM 이 덧붙인다
3  SOL 재검증 브리핑에 "직전 지시서의 각 항목이 실제로 닫혔는지" 를 명시한다
```

🔑 **PM 이 지시 내용을 저술하지 않는다.** 좌표를 뽑아 주는 것([[feedback_pm_gives_coordinates_not_means]])은 **1차 검증(OPUS/PM 라운드)** 의 몫이고, 2차(SOL) 사이클에서는 SOL 이 자기가 찾은 결함의 지시서를 쓴다.

### 유지되는 것

- **리뷰어(SOL) / 구현자(LUNA) 분리** — 한 세션이 찾고 고치지 않는다
- **커밋은 라운드마다** — 산출물이 워크트리에만 있으면 codex 타임아웃·세션 사고로 0 이 된다(실측 다수). **게시·보고만 사이클 끝으로 묶는다**
- **PM 산출물 직접 검증** — [[feedback_pm_delegate_to_codex_conserve_tokens]] 의 *"위임해도 검증은 PM 몫(릴레이 금지)"* 은 그대로다
- 1차 적대검증(OPUS + PM 라이브QA + SONNET5 fix)의 구성은 변경 없음

✅ **머지 자율권은 그대로다** — [[feedback_pm_auto_merge_authority]] 유지. 2026-08-05 개편은 **검증 사이클**을 바꾼 것이지 머지 권한을 회수한 것이 아니다. *"머지는 PM에게 권한 위임"*(개발책임자 확정). 바뀐 것은 **PM 이 머지를 판단하는 시점** — SOL 재검증 결함 0 + PM 재검증 통과 이후다.

## 리뷰 라운드의 에이전트 구성 — **5차원 고정 폐기, 표면 분할 3~4**
차원(역할)이 아니라 **표면(파일군)** 으로 나눈다. 각 에이전트에게 주는 질문은 **도달성 단일 질문** 하나뿐이다.
- 실측 근거 — #914 5차원에서 도달가능 5건이 나왔는데 **같은 결함이 3~4개 차원에서 중복 발견**됐다(중복 = 비용). #907 마감 라운드는 **3차원으로 10건**을 찾았다.
- **도달성 판정 + 종합 + 라이브QA 는 루트.** 🔑 **도달성 = "실 사용자 경로로 재현되는가" = 라이브QA 그 자체**이므로 루트가 겸하는 것이 옳다(2026-07-23 개발책임자 정정). 떼어내면 라이브 서버 없이 도달성을 논하는 리뷰어가 되거나 라이브QA 가 중복된다.
- 회수 후 rollout 의 `/root/<name>` 으로 **실제 에이전트 구성을 확인**하라 — 주문한 수와 실제 생긴 수는 다를 수 있다.
※ **구현·fix 스테이지는 단일 에이전트가 정상.** 다중 에이전트를 요구하는 것은 **리뷰 스테이지뿐**이다.

## 🆕 1차 리뷰 각도의 모델 분리 — **발견 = OPUS · 대조 = SONNET5** (2026-07-27 개발책임자 승인)

같은 "리뷰" 라도 두 종류의 일이 섞여 있고, 요구 등급이 다르다.

| 각도 | 하는 일 | 모델 |
|---|---|---|
| **발견 각도** | 기준 자체를 만들어야 하는 일 — 설계 전제가 무엇인가, 이 경로가 실제로 열려 있는가, 어느 표면이 서로 충돌하는가 | **OPUS** |
| **대조 각도** | 기준이 이미 주어진 일 — 문서 수치 대조, **인용 원문 재현·대조**, 계열 sweep 카운팅, 무훼손 수집 전/후 비교, 트리거·YAML 정합 | **SONNET5** (`model:"sonnet"`) |

**왜** — 병목은 토큰이 아니라 **라운드 개수**다([[feedback_throughput_parallel_scope_freeze_batch]]). 발견 각도를 낮추면 라운드가 늘고, 라운드 1회가 리뷰어 등급 차이보다 훨씬 비싸다. 반대로 대조 각도는 **정답이 이미 정해져 있어** 등급 차이가 작다.

**실측 (2026-07-27 #949 R1)** — 발견 각도가 잡은 것 = `AUDIT_BASE_URL` 이 이미 **148개 스펙의 자기 오리진 변수**라 세팅 시 **106개가 한 오리진으로 끌려간다**(단일 값으로 표현 불가) · `use.baseURL` 부재가 사고가 아니라 **주석에 명시된 설계 결정**이었음. 대조 각도가 잡은 것 = dev-report 의 "실행 원문" 이 **변경 후 Error 줄 + 변경 전 Call log 줄의 스플라이스**라 어떤 실행에서도 나올 수 없음(재현해서 대조). 후자는 기계적 재현이면 충분하다.

🚫 **분리의 오용 금지** — "대조" 라는 이름으로 도달성 판정을 SONNET5 에 넘기지 않는다. 도달성 판정·종합·라이브QA 는 여전히 **루트(PM)** 몫이다.

# fix 품질 규율 (라운드 폭증을 fix 쪽에서 끊는 장치)

## 🔴 최소 변경 원칙 — **가장 강한 레버**
> **불변식을 만족시키는 최소 변경만 한다. "온 김에" 금지.**

fix 부피가 곧 **다음 라운드의 감사면**이다(실측 — #854 R4 신규 1,400줄 → R5 HIGH 5건이 거의 전부 그 안). 구현자는 **변경 줄 수를 보고**하고 늘어난 이유를 설명한다.
실측 위반 — #914 에서 진짜 원인(모델이 `key` 를 안 실음)을 고치면서 **불필요하게 정규식까지 넓혀** FE/BE 계약 불일치를 새로 만들었다.

## 🚨 PM 은 **불변식만** 말하고 구현 수단을 지시하지 않는다
수단을 지정하면 그 수단의 결함까지 PM 이 떠안고 구현자·리뷰어의 독립 판단이 사라진다. 실측 3건 — ①`COALESCE(modified_at, created_at)` 사용을 PM 이 지시해 감사 위조를 만듦 ②PM 이 "설계 정합"으로 수용 처분해 BLOCKING 이 남음 ③PM 이 FE 만 읽고 "fix 가 진짜"라 판정해 BE 분기가 남음.
⟹ PM 은 **"무엇이 참이어야 하는가"**(불변식·수용 기준·검증 게이트)를 쓰고 **"어떻게"** 는 구현자가 고른다. 수단을 제안해야 하면 **제안임을 명시**하고 반박 여지를 남긴다. **PM 이 지시한 fix 일수록 검증을 더 엄격히** 본다([[feedback_pm_verify_what_measurement_proves]]).
⟹ 구현자가 **수단 승인을 받으려 멈추면 승인하지 말고** 조건(실측 근거 요구 등)만 달아 되돌린다.

## 🚨 RED-first — 결함 재현 테스트를 먼저 쓰고 RED 를 보인 뒤 고친다
뮤테이션 검사를 fix **이후**에 하면 **"구현자가 고른 fix"만 검증**하고 결함의 전체 표면은 미검증이다. 순서를 뒤집으면 코드를 쓰기 전에 **결함이 어느 층·어느 파일까지 사는지 열거**해야 한다.
- 각 도달가능 발견마다 **재현 실패 테스트를 먼저 작성하고 RED 원문(터미널 출력 그대로)을 제출**한 뒤 고친다. 되돌리면 다시 RED 가 되는지(**뮤테이션 RED**)도 제출한다.
- 실측: FE 만 고쳐지고 BE 분기가 남은 사고 — BE 를 지나는 RED 를 먼저 썼다면 구조적으로 불가능했다.
- **RED 를 못 만들면 결함을 이해하지 못했다는 신호다. 고치지 말고 보고한다.**

## 🚨 계열 전수 sweep
한 곳을 고치면 **같은 패턴이 있는 곳 전부**를 grep 으로 확인하고 목록을 보고한다. "고친 곳"이 아니라 "같은 패턴이 있는 곳 전부"가 보고 단위다.
실측(#907) — 신선도·무효화·escape fix 가 각각 **한 경로만** 고쳐 나머지 계열이 다음 라운드에 도달가능으로 돌아왔다. → [[feedback_defect_family_sweep_fix]]

## 🚨 회귀 울타리
이 레포에서 fix 가 새 결함을 만든 전형은 **fix 가 기존 고지·기존 경로를 조용히 죽인 것**이다.
- #907 — `partnerIdExact` 필터가 legacy 행을 SQL 단계에서 제외하자 *"왜 병합 못 하는지"* 안내가 **구조적으로 렌더 불가**가 됐다. 제외는 옳았고 고지가 죽었다.
- #914 — 빈 값 fallback 을 진단 문구로 바꾸자 **실 결재문서 인쇄면**에 오류 문구가 찍혔다.
⟹ fix 지시마다 **"이것은 계속 보여야/동작해야 한다"** 목록을 함께 준다.

# 🚨 라이브QA = 실서버 실제 실행

> *"REAL QA로 실서버 검증을 하지 않는다면 추후 사용자가 사용할때 나타나는 버그를 잡을 수가 없잖아."*

- `--list`·typecheck·lint 류 **정적 검사는 하네스가 부서진 것만** 잡는다. 사용자가 겪을 버그는 **실행해야** 나온다. 🚫 정적 게이트를 라이브QA 의 **대체물로 제안 금지**(보조 조기경보로만).
- ⚠️ repo 의 `*-real-qa.spec.ts` 는 `playwright.config.ts` 가 명시 제외하고 워크플로에 `real-qa` 참조가 없어 **CI 가 실행하지 않는다.** 라운드마다 **실서버로 직접 실행**하고 원문을 제출해야 하는 이유다([[feedback_live_qa_penetrates_it_masking]]).
- **스크린샷 다수 필수** — 단계별 여러 장(요약 1컷 금지). SendUserFile + PR SHA-pinned 인라인 **둘 다**([[feedback_live_qa_every_round_screenshots]] · [[feedback_pr_screenshot_sha_pinned_urls]] · [[feedback_qa_screenshots_inline_to_user]]). 실캡처만([[feedback_no_fake_data_ever]]). **파일명이 실제 내용과 일치**해야 한다.

## OPUS 라운드의 라이브QA = **PM 이 직접 수행**
> *"라이브 QA는 따로 서브에이전트를 돌리지 말고 PM이 직접 검증… 전체 흐름을 알고 있는 PM이 전체적인 관점에서 더 넓게 확인이 가능하니까. 다만 PM이 세부적인 QA를 모두 진행하기 어려운 경우 자율판단 하에 QA 에이전트를 따로 두고 함께 검증도 가능."*

- 리뷰 차원은 서브에이전트로 디스패치하되 **라이브QA 만은 PM 이 손으로** 돌린다. 병렬 트랙에서는 서브에이전트가 자기 트랙만 보므로 QA 품질이 어긋나고, PM 만이 트랙 간 상호작용·공유자원 회귀를 넓게 본다.
- 예외 — 세부가 과다하면 QA 에이전트 **병행 가능하나 대체 아님**. PM 확인분과 에이전트 확인분을 **구분해 게시**한다.
- ⚠️ "직접 한다"는 **"돌렸다"가 아니라 "봤다"** 를 뜻한다 — 배포 증명·실 GUI 스크린샷·실패 원문을 PM 이 직접 확인한다.

## CODEX SOL 라운드의 라이브QA = **SOL 이 직접 수행**
> *"코덱스 리뷰라운드에서는 SOL이 직접 라이브 QA를 진행해야 한다."*

PM 라이브QA 와 **별개의 독립 실행**이며 서로 대체하지 않는다. 이종 검증의 가치는 **같은 것을 다른 눈으로 "실행"해 볼 때** 나온다 — 정적 리뷰를 두 번 하는 것은 이종 검증이 아니다.
**PM 디스패치 의무** — SOL 프롬프트에 ①실서버 접속 정보와 FE 하네스 기동 방법 ②라이브QA 수행 지시 + 원문·스크린샷 제출 의무 ③**쓰기 허용 범위**(throwaway 전용·공유 실데이터 write 금지·종료 시 정리 [[feedback_qa_live_shared_data_readonly]])를 반드시 명시한다.
🚫 **"파일 수정·DB 쓰기 금지"를 통째로 걸어 라이브QA 를 막지 않는다.** 금지 대상은 **git 조작**과 **공유 실데이터 오염**이지 라이브 실행이 아니다. 흐리면 SOL 은 정적 분석으로 후퇴한다(실측).
🚫 SOL 이 라이브QA 를 못 했으면 **그 라운드는 미완**이다.

| **1차 적대검증 리뷰의 대조 각도** (문서 수치·인용 원문 재현·sweep 카운팅·무훼손 비교·트리거/YAML 정합) | **SONNET5** | Agent `model:"sonnet"` **명시** |
| 1차 라운드 fix | **SONNET5** | Agent `model:"sonnet"` **명시** |
| 2차 적대검증 리뷰 | **CODEX SOL 5.6** | `mcp__codex__codex` `model:"gpt-5.6-sol"` |
| 구현 · 2차 라운드 fix | **CODEX LUNA 5.6** | `mcp__codex__codex` `model:"gpt-5.6-luna"` |

- OPUS 는 **라운드 fix 직접 수행만 금지**(리뷰어/구현자 분리 유지). 리뷰는 서브에이전트로 디스패치 — PM 세션이 혼자 대신하지 않는다.
- 🆕 **각도 배정은 디스패치 시점에 PM 이 판단**한다 — 그 각도가 *기준을 만들어야 하는가(발견)* 아니면 *주어진 기준에 맞춰보는가(대조)* 로 가른다. 애매하면 **발견 쪽(OPUS)** 으로 붙인다(라운드 1회가 더 비싸다).
- Codex 호출 표준 = sandbox `danger-full-access` · approval-policy `never` · **git 금지**(PM commit 대행) · effort 기본 high. 디스패치마다 **스테이지 모델 명시 의무**(config 기본값은 폴백일 뿐). `codex-rescue` 금지 — `mcp__codex__codex` 직접 호출([[feedback_codex_rescue_unreliable_use_mcp]]).
- 🚫 **모델 대체 금지** — 지정 모델 사용 불가 시 임의 대체 금지, **개발책임자 선확인 후에만**. 부재 단정 전 실제 호출부터 시도.

# 절대 규칙

- 🚫 **한 슬라이스 안에서 단계·라운드 병렬 금지.** 한 PR 의 두 검증 스테이지 동시 실행 금지. **슬라이스 간 병렬은 허용이자 기본**(3트랙 상시) → [[feedback_throughput_parallel_scope_freeze_batch]]
- 🚫 **단축 금지** — 트리비얼/1줄/인프라/chore PR 도 동일 워크플로우([[feedback_infra_chore_not_canon_exempt]]). 범위 점증 시 리뷰 재가동([[feedback_expanded_scope_reinstate_review]]).
- 🚫 **실행 = 게시 1:1** — 모든 단계·라운드는 완료 즉시, **다음 행동보다 먼저** `gh pr comment`(UTF-8 body-file [[feedback_gh_comment_utf8_pipe_mojibake]])로 게시. 채팅 보고 ≠ PR 게시. 머지 직전 "실행 라운드 수 = 게시 라운드 수" 대조 의무.
- 🚫 **통과 아닌 것**: `test.skip` · false-green · 미실행 · 캐시 히트를 실행 증거로 인용.
- 🚫 **어떤 fix 든(1줄이라도) 후에 재수렴 없이 머지 금지**([[feedback_reconvergence_before_merge]]).
- ✅ 무중단 자율(슬라이스 끝마다 묻지 않고 연속 진행) · 한국어 커밋/PR([[feedback_korean_commits]]) · `[FEAT]`/`[FIX]` 대괄호 prefix · Role 풀네임 · 개발책임자 결정은 PR 에 누적 기록([[feedback_post_devlead_decisions_to_pr]]) · Issue 자동 close([[feedback_issue_close_after_pr]]).

## 근본원인 자각 (반복위반 방지)
① 속도가 충실도를 이기게 두지 말 것 — **속도 < 충실도**. ② 워크플로우는 결과를 맞추는 가이드가 아니라 **내 판단이 틀릴 때를 잡는 장치** — 물음은 *"결과가 맞나"* 가 아니라 **"모든 단계를 밟았나"**. ③ 행동 전 결정 시점마다 본 파일 재대조(관성 금지). ④ 긴 세션·병렬 부하가 규율을 침식하면 짧게 끊고 재자각.

# 머지 게이트 체크리스트 (PM 머지 직전 · 전부 ✓ 후에만 merge)

① 기획 리뷰 게시(PR 본문만으로 갈음 불가·별도 코멘트 필수) ② 구현 리뷰 게시 ③ OPUS 라운드 전부 게시 + 도달가능 전건 disposition ④ CODEX SOL 라운드 전부 게시 ⑤ **fix 주체 준수**(OPUS 라운드=SONNET5 · SOL 라운드=LUNA) ⑥ **도달가능 0 수렴**(양측 + 재수렴 라운드) ⑦ 라이브QA 스샷 다수(SendUserFile + PR SHA-pinned) 매 라운드 ⑧ **🚨 U-gate — 기획서의 실데이터 시나리오를 실제로 1회 실행**(못 하면 왜 못 하는지 명시하고 개발책임자 판단. 조용히 머지 금지) ⑨ **매 라운드 `c`·`r` 기록** ⑩ PM 종합 게시 + dev-report/docs 동기화 ⑪ **CI green(exact SHA)** + 실행=게시 1:1 대조 + 메모리 가드(한국어·UUID 비노출·풀네임 Role) 위반 0.

⑫ 🆕 **2차 사이클이 SOL 재검증 결함 0 으로 끝났는가** (2026-08-05) — SOL 이 결함을 낸 채 PM 에게 넘어온 상태로 머지 체크리스트에 들어가지 않는다.
⑬ 🆕 **PM 재검증이 게이트로 동작했는가** — PM 이 산출물을 직접 대조했고(릴레이 금지), 이상이 있었다면 **다음 라운드로 되돌렸다는 기록**이 PR 에 있어야 한다.

**멈춤(개발책임자 확인 대기)** = 신규 업무규칙/정책 결정 · 데이터손실/보안/운영중단급 P0 · 무결성도메인 편집정책([[feedback_integrity_domain_policy_preconfirm]]) · 스테이지 모델 부재 시 대체 여부. 그 외는 자율 판단·정직 기록 후 진행. `--admin` 강행 머지는 개발책임자 명시 시만.
🚫 **머지 자체는 멈춤 대상이 아니다** — 게이트 충족 시 **PM 자율 머지**(2026-08-05 개발책임자 확정 *"머지는 PM에게 권한 위임"*). 새 이슈 등록도 PM 위임([[feedback_issue_registration_delegated_to_pm]]).
