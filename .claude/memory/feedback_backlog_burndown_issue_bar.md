**발단**: PM 이 3트랙 기획 정찰에서 나온 범위 외 결함 3건을 **반사적으로 새 이슈로 등록**(#898 쪽지 markRead 엔드포인트 부재 · #899 세금계산서 절사↔도메인 HALF_UP 불일치 · #900 주문 라인 공급/부가세)했고, 개발책임자가 제동을 걸었다.

**⟹ 기본값 전환: 발견된 결함은 `현 PR 내 처리`가 디폴트다.** 이슈 분리는 예외이며, 예외 사유는 **흡수가 물리적으로 곤란**(타 서비스 스키마 신설 등)하거나 **정책·세무 판단이 선행**돼야 할 때로 한정한다.

🔑 **그리고 그 예외조차 PM 이 단독 판정하지 말 것.** 흡수 **난이도를 명시한 선택지**(쉬움/중간/큼 + 각각의 대가)를 개발책임자에게 제시하고 고르게 한다.
- **실측 교훈**: PM 권장안은 "2건 흡수 / #900 은 마이그 신설이라 유지" 였으나, 개발책임자는 **3건 전부 흡수**를 선택했다. **PM 이 개발책임자보다 보수적이었다** — 즉 PM 의 "이건 범위 밖" 감각은 실제 기준보다 낮게 잡혀 있으니, 애매하면 **흡수 쪽으로 기울여 제안**하라.

⚠️ **흡수로 범위가 점증하면** [[feedback_expanded_scope_reinstate_review]] 대로 **적대검증을 확대된 범위 전체로 가동**한다(흡수는 범위 확대를 감춰도 된다는 뜻이 아니다). 흡수 결정·불변식은 **그 PR 에 결정 기록으로 게시**한다([[feedback_post_devlead_decisions_to_pr]]).

🚫 혼동 금지 — 이것은 [[feedback_fix_in_current_pr_no_split]](리뷰 fix 는 현 PR 내 처리)와 **같은 방향**이며, 그 예외였던 "범위 외 결함 = 이슈 등록" 을 **더 좁힌** 것이다. 도달성 축 캐논의 "검증 품질 = 슬라이스당 1이슈 이월"([[feedback_canonical_workflow]])은 존속하되, **이월을 기본 탈출구로 쓰지 말 것**.

**2026-07-19 심야 개발책임자 지시** (B1 배치 착수 중): "자꾸 issue가 늘어가는데 이러면 잔여 해결 issue가 많아질뿐" + "issue 먼저 해결하고 다음 슬라이스 진행" + "워크플로우 임의 단축은 금지하며 반드시 엄수".

**Why:** 슬라이스마다 적대검증이 범위 외 pre-existing 결함을 발견 → [[feedback_fix_in_current_pr_no_split]] 대로 매번 새 이슈 등록 → **닫는 것보다 여는 게 빨라 백로그 순증**. "잔여 해결"이 무한후퇴.

**How to apply:**
1. **이슈 바 상향**: 범위 외 결함은 (a) 저비용이면 **현 PR 내 in-round fix**, (b) marginal·재현불가는 **dev-report/PR 노트**로만, (c) **실질·재현 가능·물질적 영향** 결함만 이슈 등록. marginal(1회 관측·CI green·단독 통과 류) 이슈는 등록 말 것(등록됐으면 close 재검토).
2. **배치 번다운**: 파생 chore 다수를 **성격별 그룹 배치 PR**로 묶어 한 캐논 사이클로 다수 close(오버헤드 amortize·순감 전환). 예: DS/a11y 클러스터·회계 데이터 클러스터·실버그.
3. **feature보다 백로그 우선**: 개발책임자가 "이슈 먼저" 지시 시 잔여 이슈를 순감시킨 뒤 다음 feature 슬라이스.
4. **워크플로우 임의 단축 절대 금지**: chore·배치도 풀 캐논 엄수([[feedback_infra_chore_not_canon_exempt]]·[[feedback_canonical_workflow]]). 배칭 자체가 효율이지 워크플로우 축약이 효율 아님.
