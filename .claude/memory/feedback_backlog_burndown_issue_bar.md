# 🚨🚨 절대규칙 — **새 이슈 등록에 PM 자율은 없다** (2026-07-23)

> 개발책임자: *"또 새로운 이슈로 자꾸 생성하지마. 그러면 안 끝난다고"*
> 개발책임자: *"앞으로 내 허락 없이는 새로운 이슈로 등록 금지야."*

**등록하고 싶어지면 대신 이렇게 한다**
1. **현 PR 에 흡수**(디폴트)
2. 흡수가 곤란하면 **PR 코멘트/보고에 결함을 적고 등록 가부를 개발책임자께 묻는다**
3. 🚫 묻지 않고 등록 금지 · 🚫 숨기는 것도 금지(**발견은 반드시 보고**)

## 등록 전 자문 3개 — 하나라도 "예" 면 등록하지 말고 흡수하라
1. 수정이 **한 파일 몇 줄**로 끝나는가?
2. **이미 열려 있는 PR 이 같은 표면**(같은 클라이언트/서비스)을 건드리는가?
3. 그 결함이 **머지 게이트를 간헐적으로 막는가**(flaky CI 등)? — 막는다면 이슈로 미루는 것은 **자기 발등을 계속 찍는 것**이다

🔑 **PM 이 반복해서 빠지는 함정**: *"이 PR 이 건드리지 않은 파일 = 범위 밖 = 이슈"* 라는 자동 연상. **파일 소유가 아니라 흡수 비용이 기준이다.**

⟹ 등록이 정당한 경우는 사실상 **타 서비스 스키마 신설** · **정책/세무 판단 선행** · **설계 슬라이스급 크기** 뿐이고, 그마저 **허락을 받은 뒤**에 한다.

# 백로그 순감 — 배치 번다운

**2026-07-19 개발책임자 지시**: *"자꾸 issue가 늘어가는데 이러면 잔여 해결 issue가 많아질뿐"* + *"issue 먼저 해결하고 다음 슬라이스 진행"* + *"워크플로우 임의 단축은 금지하며 반드시 엄수"*.

**Why:** 슬라이스마다 적대검증이 범위 외 pre-existing 결함을 발견 → 매번 새 이슈 등록 → **닫는 것보다 여는 게 빨라 백로그 순증**. "잔여 해결"이 무한후퇴한다.

**How to apply**
1. **배치 번다운** — 파생 chore 다수를 **성격별 그룹 배치 PR** 로 묶어 한 캐논 사이클로 다수 close(오버헤드 amortize·순감 전환). 예: DS/a11y 클러스터 · 회계 데이터 클러스터 · 실버그.
2. **feature 보다 백로그 우선** — 개발책임자가 "이슈 먼저" 지시 시 잔여를 순감시킨 뒤 다음 feature 슬라이스.
3. **워크플로우 임의 단축 절대 금지** — chore·배치도 풀 캐논 엄수([[feedback_infra_chore_not_canon_exempt]]). **배칭 자체가 효율이지 워크플로우 축약이 효율이 아니다.**
