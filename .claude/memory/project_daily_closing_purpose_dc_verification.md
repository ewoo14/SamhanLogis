# 일마감은 집계 화면이 아니라 **계산서 발행 전 DC 검증 절차** (2026-07-30 개발책임자)

## 결정·설명

> *"판매전표에서 매출전표를 생성하면 일마감에서는 **회계반영일자**가 생겨. 다만, **거래처에 따라 회계반영일자를 나중에 생성하는 경우**가 있잖아?"*
>
> *"**일마감은 영업자(판매전표 생성한 사람)가 정확한 DC율과 싱글중대형의 경우 DC액을 넣었는지 확인하기 위한 절차**야. 품목마다 DC율을 잘못 설정하여 납품가를 넣었을 수 있기 때문에 **계산서를 발행하기 전 마지막으로 확인하는 절차**인거지."*
>
> *"회계반영일자 즉, 매출전표가 생성된 판매전표 데이터들을 **일괄 계산서 발행 탭에서 엑셀(국세청 업로드 양식)로 받도록** 하면 되는거지."*
>
> *"GAS에서는 **품목명이 아니라 모델명**으로 구분하게 되어있을거야."*

## 흐름

```text
판매전표 작성 (영업자가 DC율·DC액 입력)
      ↓
일마감 = 계산서 발행 전 마지막 검증
         "영업자가 DC율을 정확히 넣었는가" · "싱글중대형은 DC액을 넣었는가"
      ↓
매출전표 생성 → 회계반영일자 생김
      ↓
일괄 계산서 발행 탭 → 국세청 업로드 양식 엑셀
```

⟹ **일마감은 계산서보다 앞 단계다.** 사후 집계로 오해하면 설계가 틀어진다.

## GAS 실제 동작 (정찰 실측)

- 입력은 **이카운트 하루치 판매전표 엑셀 업로드** (`Index.html` `accept=".xlsx,.xls"`). 시트가 아니다
- 스프레드시트(`1RJqO3jT…`)는 **가격표·구성품 카탈로그**용 (`loadPriceMap_`·`loadSingleSetCatalog`). 탭 27개에 **매출 raw 탭은 없다**
- 카테고리 판별 = **고정 행 번호나 구분 행이 아니다**. `일자_번호` 그룹 내 **원본 행 순서**를 보존한 채 **품목명의 모델 토큰**을 위에서부터 읽어 `currentZone` 전환
  - `AM` → 상업멀티 · `AJ` → 홈멀티 · 대상 모델·구성품 판정 통과 → 싱글
  - **종료 토큰 없음** — 다음 전환까지 유지된다(= 위에서부터 범위)
  - 구형은 zone 전환이 아니라 **구형 가격표 모델 우선 조회**라는 별도 규칙
- `'매출전표X - '`(`Code.js:465-467`)는 **탭 이름이 아니라** 회계반영일자 미생성 거래처를 표시하는 **셀 값**

## 🚨 현대 구현과의 격차 (실측)

| 항목 | 현대 |
|---|---|
| 일마감 상세 원천 | **`tax_invoice_lines`**(기본) / 선택적으로 회계전표 라인 — **GAS 입력보다 한 단계 뒤** |
| 카테고리 전달 | 어느 경로도 전달하지 않음. 주문 라인 `category_key` 는 **전표 발행 payload 에서 복사되지 않음** |
| 집계 키 | `getItemName()`·`getProductName()` = **품목명**. GAS 는 모델명 → **잘못된 축** |
| GAS 규칙 적용 결과 | `tax_invoice_lines` 22행 **전부 `UNKNOWN`** — 하나도 분류되지 않음 |
| **싱글중대형 DC액 검증** | 🔴 **없음.** `DiscountRevalidator:123-126` 이 싱글 본체·부속 prefix(`AC|AP|AR|AF|PC|AWR|ARR`)를 `OUT_OF_SCOPE` 로 반환. `DailyClosingDetailResponse:48-80` 에 **DC액 필드 자체가 없다** |
| 유실 사슬 | 주문(`category_key` 있음) → 전표(`source_order_line_id` nullable·일부) → 회계전표(`SlipLineSnapshot` 에 그 값조차 없음) → 세금계산서(아무것도 없음) |

## 설계 함의

- 집계 키는 **`(정규화된 모델 토큰, 판매 시점 확정 categoryKey)`** 축이어야 한다. 품목명 단일 key 는 서로 다른 모델을 한 줄로 합치고 같은 모델을 두 줄로 쪼갠다
- 카탈로그의 **다중 zone 모델 토큰 76개** · `product_estimate_exposure` **복수 노출 68건** — 도메인 표현이며 배제 사유가 아니다
- 🚫 `product_estimate_exposure` 를 판매 카테고리 빈자리에 **대입하면 안 된다**. 그건 카탈로그 M:N 노출이지 *"이 라인이 어느 범위에서 팔렸는지"* 의 이력이 아니다
- **싱글중대형 DC액 검증 신설**은 #991 의 price-history variant 와 구분되는 **범위 확장 후보**
