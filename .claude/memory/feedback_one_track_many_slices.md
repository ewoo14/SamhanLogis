# 🚨 슬라이스별로 트랙을 열지 않는다

> 개발책임자 (2026-08-13): *"슬라이스별로 트랙을 개설하지 말고 **한 트랙 안에서 관련 슬라이스들을 단계별로 처리** 바람"*

## 무엇이 문제였나 — 그날 실측

PM 이 하루에 PR 을 **6건** 열었고, 그중 **4건이 같은 이슈의 다른 슬라이스**를 별도 트랙으로 만든 것이었다.

```
머지 5건       #1189 · #1197 · #1181 · #1200 · #1199
이슈 종료 1건   #1142
열린 이슈       13건 → 13건    ✅ 변화 없음
```

🔑 **머지 개수와 이슈 소진이 따로 놀았다.** 이유는 단순하다 —

```
#1200 → 이슈 #1161 의 S2a 계약 마감만 닫음 (S1.5 · S2b 남음)
#1199 → 이슈 #999 의 축 ① 시리얼만 닫음 (축 ② 재고이동 · 축 ③ QR 남음)
```

**슬라이스마다 PR 을 열면 PR 수만 늘고 이슈는 안 준다.** 개발책임자가 보는 지표는 **열린 이슈 수**다.

## How to apply

```
✅ 한 이슈 = 한 트랙(브랜치·PR) = 여러 슬라이스를 단계별로
   슬라이스 1 커밋 → 검증 → 게시
   슬라이스 2 커밋 → 검증 → 게시   ← 같은 PR 안에서
   마지막에 한 번 머지 → 이슈 종료

🚫 슬라이스마다 새 브랜치·새 PR
```

### 그래도 나눠야 할 때

```
· 이슈가 정말 서로 다른 도메인 둘을 담고 있을 때 (그러면 이슈부터 나눈다)
· 앞 슬라이스가 개발책임자 결정 대기로 멈췄는데 뒤 슬라이스는 진행 가능할 때
  → 이 경우에도 먼저 "나눠도 되는지" 를 물을 것
```

### 보고도 바꾼다

```
🚫 "오늘 머지 5건"
✅ "오늘 이슈 종료 1건 (머지 5건 — 4건은 슬라이스라 이슈가 안 닫힘)"
```

🔑 머지는 수단이고 **이슈 종료가 결과**다. 보고 단위를 결과로 맞춘다.

**Why:** 트랙이 늘면 각각에 적대검증·라이브QA·CI 게이트가 붙는다. 같은 이슈의 슬라이스 넷을 넷으로 나누면 **게이트를 네 번 통과**해야 하고, 그동안 이슈는 하나도 안 닫힌다. 한 트랙 안에서 단계별로 처리하면 게이트를 한 번만 통과하면서도 슬라이스별 검증은 그대로 남는다.
