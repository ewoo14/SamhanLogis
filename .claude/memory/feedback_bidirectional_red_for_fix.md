# 🚨 fix 는 양방향 RED 로 — 한쪽만 보면 반대 방향이 깨진다 (2026-08-04 · 하루 6회)

## 무슨 일이 있었나

fix 가 지적된 증상은 없앴는데 **그 반대 방향**이 깨졌다. 하루에 여섯 번이다.

```text
#984  R7   오차단 160건을 막으려다  →  정상 주문 3,489건 전부 거부
#1061 R14  공란 전표를 매칭        →  모든 거래처에 197,476,400원 오염
#1061 R15  오염을 차단             →  정상 금액도 0 (필터 집계 "—")
#1059 R22  날짜 변경 후 입력 반영   →  다른 날짜 연락처가 섞임
#1061 R18  세 경로 통합            →  무필터 정상 거래처 13곳 차단 + UUID 노출
#1061 R24  GET 자동저장 제거        →  저장 기능이 전면 도달 불가
#1057 R22  전이 매핑 전수 sweep     →  INSPECTING 반려 버튼 소실
```

## 🔑 브리핑에 불변식을 걸어도 부족하다

PM 이 *"기존 스냅샷 기능이 사라지면 안 된다"* 를 명시했고 구현자는 *"POST 명시 트리거로 보존"* 이라고 보고했다. **API 는 만들었지만 화면 연결이 0곳**이었다. 문장으로 건 반대급부는 **검증되지 않으면 지켜졌는지 알 수 없다.**

## 규칙 — 두 개를 각각 테스트로 고정하고 **동시 GREEN** 을 요구한다

```text
RED-A   기능이 동작한다        (fix 가 없애면 안 되는 것)
RED-B   결함이 재발하지 않는다  (fix 가 없애야 하는 것)
```

실제로 통한 예:

```text
#1059 R30  RED-A 날짜 바꾼 뒤 입력이 반영된다
           RED-B 다른 날짜로 새지 않는다              → 한 번에 닫힘
#1061 R16  RED-A 정상 금액 26,000,000 이 도달한다
           RED-B 오염 0                              → 한 번에 닫힘
#1061 R26  RED-A 사용자 조작으로 snapshot 이 생성된다
           RED-B 조회를 반복해도 늘지 않는다          → 한 번에 닫힘
```

## 함께 요구할 것

- **실 데이터로 건수를 세게 하라.** *"차단되는 건수 0"*, *"오부착 0건"* 처럼 수치로 받는다.
- 전수 sweep 을 시킬 때는 **축을 명시**하라. `#1057` R22 에 *"상태 → 다음 전이"* 만 물어 **상태마다 액션이 여러 개**라는 축이 빠졌고 반려 버튼이 통째로 사라졌다. *"도메인이 허용하는 액션 전부 vs 화면이 노출하는 액션 전부"* 로 물어야 했다.
