# 🚨 fix 는 양방향 RED 로 — 한쪽만 보면 반대 방향이 깨진다 (2026-08-04 · 하루 6회)

## 무슨 일이 있었나

fix 가 지적된 증상은 없앴는데 **그 반대 방향**이 깨졌다. 하루에 여섯 번이다.

```text
#984  R7   오차단 160건을 막으려다  →  정상 주문 3,489건 전부 거부
#1061 R14  공란 전표를 매칭        →  모든 거래처에 197,476,400원 오염
#1061 R15  오염을 차단             →  정상 금액도 0 (필터 집계 "—")
#1059 R22  날짜 변경 후 입력 반영   →  다른 날짜 연락처가 섞임
#1061 R18  세 경로 통합            →  무필터 정상 거래처 13곳 차단 + UUID 노출
#1061 R24  GET 자동저장 제거        →  저장 기능이 전면 도달 불가
#1057 R22  전이 매핑 전수 sweep     →  INSPECTING 반려 버튼 소실
```

## 🔑 브리핑에 불변식을 걸어도 부족하다

PM 이 *"기존 스냅샷 기능이 사라지면 안 된다"* 를 명시했고 구현자는 *"POST 명시 트리거로 보존"* 이라고 보고했다. **API 는 만들었지만 화면 연결이 0곳**이었다. 문장으로 건 반대급부는 **검증되지 않으면 지켜졌는지 알 수 없다.**

## 규칙 — 두 개를 각각 테스트로 고정하고 **동시 GREEN** 을 요구한다

```text
RED-A   기능이 동작한다        (fix 가 없애면 안 되는 것)
RED-B   결함이 재발하지 않는다  (fix 가 없애야 하는 것)
```

실제로 통한 예:

```text
#1059 R30  RED-A 날짜 바꾼 뒤 입력이 반영된다
           RED-B 다른 날짜로 새지 않는다              → 한 번에 닫힘
#1061 R16  RED-A 정상 금액 26,000,000 이 도달한다
           RED-B 오염 0                              → 한 번에 닫힘
#1061 R26  RED-A 사용자 조작으로 snapshot 이 생성된다
           RED-B 조회를 반복해도 늘지 않는다          → 한 번에 닫힘
```

## 함께 요구할 것

- **실 데이터로 건수를 세게 하라.** *"차단되는 건수 0"*, *"오부착 0건"* 처럼 수치로 받는다.
- 전수 sweep 을 시킬 때는 **축을 명시**하라. `#1057` R22 에 *"상태 → 다음 전이"* 만 물어 **상태마다 액션이 여러 개**라는 축이 빠졌고 반려 버튼이 통째로 사라졌다. *"도메인이 허용하는 액션 전부 vs 화면이 노출하는 액션 전부"* 로 물어야 했다.

## 🆕 2026-08-08 — **fix 뿐 아니라 "추가" 브리핑에도 반대급부를 걸어라**

`#1092` 슬라이스 1 에서 PM 이 *"슬라이스 1 의 범위 = 통합 조회, 읽기 전용"* 이라 적고
**하지 말 것 목록만** 길게 붙였다. 구현자는 통합 목록을 **더하지 않고 화면을 재작성**했다.

```text
EstimateListPage.tsx        -618 / +149
EstimateListPage.test.tsx   테스트 6건 삭제
사라진 것  복원 버튼 · 삭제 배지·취소선 · 삭제행 토글 · 기간·거래처명 필터 ·
           신규 견적 버튼 · 서버 페이지네이션 · SSE realtime invalidate
```

🔑 **RED-A/RED-B 를 걸긴 했는데 둘 다 새 기능만 지켰다**(병합 목록 · 한쪽 API 실패).
   기존 기능은 **아무도 지키지 않았다.** 구현자는 PM 이 검증하겠다고 말한 것만 지킨 것이고
   그건 정확한 행동이다. → [[feedback_pm_gives_coordinates_not_means]]

### 🔑 조기 신호 = **순증이 음수**

*"더하라"* 고 시킨 슬라이스인데 `git diff --stat` 순증이 음수면 그 자체가 위반 신호다.
보고서 파괴에 쓰던 판별을 **코드에도** 쓴다 → [[feedback_briefing_title_only_truncates_existing_report]]

### 고친 브리핑 (같은 슬라이스, 한 라운드 만에 닫힘)

```text
최우선 불변식  "통합 목록은 더해지는 것이지 대체하는 것이 아니다"
좌표 전수      잃으면 안 되는 기능 10가지 + 통과해야 할 기존 테스트 6건의 이름 그대로
RED-B 재정의   새 기능이 아니라 **기존 테스트 전건 통과**
🚫 조항        빨개진 기존 테스트를 새 동작에 맞춰 고치지 마라(고칠 신호가 아니라 읽을 신호)
보고 의무      git diff --stat 의 삭제 줄 수를 보고서에 적어라
```
결과: **+234 / -9 · 삭제된 테스트 0건 · 8/8 통과**

⟹ 가산 작업 브리핑의 RED-B 기본값은 **"기존 것이 하나도 죽지 않는다"** 이고,
   좌표를 전수로 주지 않으면 구현자가 범위를 스스로 정한다.
