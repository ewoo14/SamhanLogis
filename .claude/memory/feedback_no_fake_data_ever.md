# 가짜 데이터·목업·시뮬레이션 영구 배제 (2026-05-30 개발책임자 강력 지시)

> 원문: "앞으로 가짜 데이터, 목업, 시뮬레이션은 모든 진행에서 영구적으로 배제할 것"

## 절대 규칙
**모든 진행에서 가짜 데이터·목업·시뮬레이션을 영구 배제한다.** 실 데이터·실 서버·실 화면·실 측정만 사용·보고한다.

## 구체 금지 (위반 사례 = PR #324 Phase 2.5 PIL 합성 스크린샷)
- ❌ **PIL/그림 라이브러리로 생성한 합성 "스크린샷"** — QA 증빙은 반드시 실 화면 헤드리스/실 브라우저 캡처.
- ❌ desktop renderer 를 `VITE_MOCK_MODE=1` fixture 로 띄워 찍은 화면을 "실 QA"로 보고 (FE 가 mock 응답 렌더 → 실 적중 아님).
- ❌ 시뮬레이션/가정값으로 결과 보고 ("~일 것이다", 추정 수치).
- ❌ 가짜 seed/더미 데이터로 화면 채우고 실데이터처럼 제시.

## 의무
- **QA 스크린샷**: 실 백엔드(실 서버) + 실 DB 연동 상태의 desktop/web 실 화면을 헤드리스 chromium 또는 실 브라우저로 캡처. 실 연동이 안 되면 "캡처 불가 + 사유" 정직 보고 (가짜 생성 절대 금지).
- **실 적중 증빙**: 실 API 호출 + DB(psql) 결과로 증명 (실측이므로 OK).
- Playwright route() mock 은 **FE 단위 동작 테스트**용으로만 한정. "실 QA 증빙"으로 포장 금지. PR 에 mock 테스트와 실 QA 명확히 구분 표기.
- 실 연동 캡처가 시간/환경상 불가하면 그 사실을 그대로 보고하고 개발책임자 판단 요청 ([[always-mouse-choices]]).

## Why
가짜 증빙은 "검증됐다"는 거짓 신뢰를 만들어 운영 결함을 숨긴다. 개발책임자가 PR 캡처 누락·합성 이미지를 지적. 신뢰 파괴 행위.
