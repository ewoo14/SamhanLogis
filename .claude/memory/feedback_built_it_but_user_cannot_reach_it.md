# 🚨🚨 "만든 것" 과 "사용자가 닿는 것" 은 다르다

2026-08-15 밤. **세 트랙이 각각 다른 얼굴로 같은 실패를 했다.** 셋 다 단위 테스트는 GREEN 이었다.

| 트랙 | 단위 테스트가 본 것 | 사용자가 겪는 것 |
|---|---|---|
| `#1214` | `DetailWindowRoute` 배선 · 레지스트리 반환 | 견적서·주문서 번호를 눌러도 창이 안 열림 (`Invalid detail window route`) |
| `#1214` | 링크 목적지가 맞다 | 판매/구매조회는 **새 창이 아니라 현재 창**이 상세로 바뀜 → 목록을 못 씀 |
| `#1218` | 채팅방 신설·편집 API·컴포넌트 테스트 통과 | 그 화면이 **catalog 에서 폐기된 숨은 `#/chat`** 에만 있음. 실제 V2 화면엔 입력란도 안내도 없음 |
| `#1218` | 세 역할(MANAGER·SALES·DISPATCH) catalog 대조 "정확히 일치" | **실제 아로로지스 계정**은 그 셋에 없었고 catalog 가 `data=[]` → 배차 메뉴 전멸 |
| `#1217` | 메인이 env→query 주입을 막는다 | 패키지 앱 URL 에 `?certificateFixture=none` → **만료된 인증서가 "31일 남음"** |

🔑 **다섯 건 전부 "코드는 맞는데 그 코드에 도달하지 않는다" 이다.**
배선을 테스트하면 배선이 있다는 것만 확인된다. **그 배선을 사용자가 타는지는 다른 질문이다.**

## 왜 반복되는가

```text
① 단위 테스트는 우리가 아는 진입점으로 들어간다
   사용자는 우리가 잊은 진입점으로 들어간다
② 대조 집합을 우리가 고른다
   #1218 은 dev_* 계정 셋으로 "정확히 일치" 를 확인했다
   실제 운영 계정은 인증 체계가 달랐다 — 대조 집합 밖이었다
③ 방어를 한 겹만 본다
   #1217 은 메인을 막고 renderer 는 안 막았다
   "막았다" 가 "모든 경로에서 막았다" 는 아니다
```

## How to apply

### PM 브리핑에 넣어라

```text
🚨 "만들었다" 의 증거는 테스트가 아니라 화면이다
   그 기능에 사용자가 실제로 어떤 경로로 닿는지 먼저 적고, 그 경로로 밟아라
🚨 대조 집합을 네가 고르지 마라 — 실제 사용자 집합을 세라
   dev_* 계정으로만 확인하면 인증 체계가 다른 계정을 통째로 놓친다
🚨 "막았다" 를 주장하려면 경로를 전수로 세라
   env · query · IPC · 직접 호출 — 한 곳만 막으면 나머지로 들어온다
```

### 판정 기준

```text
✅ 화면에서 그 동작이 일어나는 것을 봤다
❌ 그 동작을 하는 함수의 테스트가 통과했다
❌ 그 화면의 컴포넌트가 렌더된다
❌ 그 route 가 등록돼 있다
```

🚩 **캡처를 찍었다고 안심하지 마라.** `#1218` 은 캡처 5장을 냈고, 그게 **사용자가 닿지 않는 숨은 화면**이었다.
캡처마다 *"사용자는 여기에 어떻게 오는가"* 를 한 줄 적게 하라. 못 적으면 그 캡처는 증거가 아니다.

🔑 **이 다섯 건은 전부 SOL 라이브QA 가 잡았다.** 라이브QA 를 안 돌렸으면 다섯 개가 전부 머지됐다.
