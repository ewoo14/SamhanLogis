> 라이브QA·스크린샷을 요구하는 모든 브리핑(SOL·LUNA 무관)에 넣는다. 없으면 그 브리핑은 미완성이다.
>
> 왜 파일로 뺐나 — 같은 항목을 메모리에 세 번 박제했는데 세 번 다 재발했다.

> 기억에 의존하는 한 또 난다. 그래서 손으로 쓰지 않고 이 파일을 붙인다.

## 🚨 브라우저 — 인앱 런타임이 아니라 로컬 Playwright

```
❌  agent.browsers.list() → []          ← 인앱 Browser 런타임. 비어 있는 게 정상이다
❌  "No browser is available"           ← 이걸 근거로 "관측 불가" 를 쓰지 마라
✅  로컬 Playwright chromium 을 직접 launch
    C:\Users\user\AppData\Local\ms-playwright\chromium-1217\chrome-win64\chrome.exe
    Version 1.59.1 · CHROMIUM_1217_COUNT=1
```

- **패키지 안에서 실행하라** — 밖에서 import 하면 `ERR_MODULE_NOT_FOUND` 가 난다.
- `headless: true` 가 기본이다. headless 캡처도 실 앱·실 서버라 가짜데이터 위반이 아니다.
- 정말 못 띄웠다면 **launch 실패 원문 그대로**를 붙여라. 🚨 인앱 런타임의 출력은 근거가 아니다.

## 🚨 해시라우터 — 해시 없으면 조용히 홈으로 떨어진다

```
❌  await page.goto(`${BASE_URL}/warehouse/...`)
✅  await page.goto(`${BASE_URL}/#/warehouse/...`)
```

에러도 안 나고 스크린샷도 찍히므로 **목표 화면을 봤다고 믿고 보고하게 된다.**

🔑 **캡처 전에 그 화면에만 있는 요소를 하나 단정**해 도달을 증명하라. 경로 규약은 또 틀릴 수 있지만 이건 그 자리에서 드러난다.

## 🚨 스펙 파일명은 `-real-qa`

`playwright.config.ts` 의 `testIgnore` 가 `**/*-real-qa.spec.ts` · `**/*-real-qa/**` 만 제외한다. 접미사가 없으면 **mock 스위트가 라이브 스펙을 집어 CI 가 깨진다.**

## 🚨 `docs/qa` 안에 캡처 스크립트를 남기지 마라

CI 의 *하네스 거짓 green 가드* 가 잡는다.

```
G3a  커밋 QA 증거로 직접 쓰는 경로 상수 — _local 격리 필수
H2b  docs/qa 안의 스크립트가 자기 커밋 디렉토리(__dirname)에 직접 쓴다
     — resolveQaShotsDir() 경유 필수
```

가드의 취지가 옳다 — **커밋된 하네스가 커밋된 증거를 덮어쓰면 거짓 green 이 된다.** 스크립트가 필요하면 `docs/qa` 밖에 두거나 실행 후 지워라.

## 🚨 환경 확인을 1절에 원문으로

```
① 띄운 스택이 어느 커밋 빌드인가   docker inspect --format '{{.Name}}|{{.Created}}'
   🚩 스택은 혼합 이미지일 수 있다. 낡은 배포본은 "없는 기능" 처럼 보인다.
      백엔드 의존 항목을 억지로 판정하지 말고 관측 불가로 남겨라
② 컨테이너 — 있는 것만 읽지 말고 **없는 것을 세라**
③ 여유 RAM. 🚨 1.0GB 아래로 가면 즉시 중단·보고 (이 PC 의 크래시 조건)
```

### 🚨 PM 에게 — 여기에 **구체적 값을 적지 마라**

브리핑에 *"스택은 08-12T17:53 빌드"* 같은 **수치를 단정하면**, 그것이 실측과 다를 때 검증자가 *전제 불일치*로 정당하게 멈춘다. **2026-08-13 `#1201` 이 그렇게 멈췄다** — PM 이 적은 시각과 실제(`gateway 08-12T15:39` · `auth 08-12T00:03` · `groupware 07-31T15:47`)가 달랐다.

```
❌  "스택은 2026-08-12T17:53 빌드입니다"           ← 검증자를 멈추게 한다
✅  "docker inspect 로 직접 재고 원문을 1절에 남기십시오.
     혼합 이미지일 수 있으니 낡은 이미지에 의존하는 항목은 관측 불가로 남기십시오"
```

🔑 **브리핑에는 "무엇을 확인하라" 만 쓰고, "그 값이 얼마다" 는 쓰지 마라.** 값은 검증자가 재는 것이다. 같은 실수를 `#1189`(스택 빌드 시각) · `#1161`(이슈 제목 수치) · `#1201`(이미지 시각)에서 **하루에 세 번** 했다.

## 🚨 미머지 마이그레이션을 공유 스택에 올리지 마라

다른 트랙이 `main` 기준으로 빌드할 때 Flyway validate 가 `applied migration not resolved locally` 로 깨진다. 격리 DB 를 써라. 🚩 격리 복제가 한글을 죽인 사례가 있으니 **인코딩을 먼저 확인**하라.

## 🚨 공유 데이터 규율

- 다른 트랙이 같은 스택에서 돈다. **남의 라운드가 만든 행을 결함으로 세지 마라.**
- **만든·바꾼 것을 전부 기록**하라 (문서번호·코드·계정).
- 끝나면 띄운 프로세스(node/electron/vite/chromium)를 **정리**하라. 안 죽고 쌓인다.

## 판정 축 — 도달성 단일

**실 사용자 경로로 재현 가능한 결함만** 보고한다. 심각도 무관.

🚫 **검증 품질은 찾지도 보고하지도 않는다** — 테스트가 약하다 / 문서가 과장됐다 / 가드에 구멍이 있다 / mock 이 미비하다.

🆕 **유일한 예외 = 증거 무결성.** 보고서·코멘트가 *"원문"·"실측"* 으로 제시한 출력이 **재현되지 않거나** 수치가 실제와 다르면, 도달 결함 0이어도 **반드시 보고하고 그 라운드에서 정정**한다.

🔑 **미실행은 검증 안 된 것이다.** 못 밟았으면 "관측 불가" 이지 "결함 0" 이 아니다. 단, *"관측 불가"* 에는 **실패 명령과 원문 출력**이 반드시 붙어야 한다.
